**Code:** `i18n/{en,ru,conformance}.json`, `crates/voicen-core/src/i18n.rs`, `src/lib/i18n/` (alias `$i18n` in `svelte.config.js`) · **Tests that pin it:** core `i18n::tests` (`conformance_fixture`, `resolve_ui_language_table`, `catalog_parity_*`, `message_ids_exist_in_both_catalogs`, `every_error_code_has_catalog_text`, `every_field_id_has_label_text`, `settings_window_message_ids_exist`), `src/lib/i18n/i18n.test.ts`, `src/lib/i18n/ids.test.ts` (type-level, run by svelte-check)

Task: T-005; UI message ids T-004, T-039, T-015, T-045. Contract: `specs/004-settings-and-first-run/contracts/core-traits.md` (i18n). Catalog location: decisions #13. `Warning.message` on the wire: decision #52. The local-model wire and the `needed` size: decision #58.

## Invariants

### Rust `Catalog::text` / `render` and the UI's `lookup + render` follow one rule, pinned by `i18n/conformance.json`

- **Scope:** what the fixture pins is lookup and placeholder rendering. Rust `text()` adds nested-id resolution on top (section "A message argument that is a nested id …" below); the UI does not resolve nested ids, and the fixture has no case for them, so that step is outside this invariant until T-006 decides whether the UI mirrors it.
- **Defect that produced it:** none yet (found in analysis, T-005). JS `String.replace` expands `$&` and `$'` in the replacement: `'Using {device}'` with device `Mic $& 1` renders `Using Mic {device} 1`; Rust `str::replace` does not. Per-argument sequential replacement re-expands a value that itself contains `{other}`.
- **What breaks if you violate it:** the same id and params show different text in the shell and the UI for user content such as device names (FR-15).
- **Where it is enforced:** the fixture, run by both suites through their `Catalog` / `lookup + render` only (not through Rust `text()`). The UI's `lookup + render` is `text` in `src/lib/i18n/render.ts`, internal to the module (see the `t` invariant below).
- **Don't:** render with `replace`/`replaceAll` and a string replacement, or substitute argument by argument. Render in one left-to-right scan; use a replacer function in TS.

### Both catalogs have the same ids, non-empty texts and placeholder names; a stray brace is an error

- **Defect that produced it:** none yet; prevents a missing or empty `ru` text showing as the id or as English.
- **What breaks if you violate it:** untranslated or broken text at runtime; there is no escaping, so a literal brace cannot be rendered.
- **Where it is enforced:** `Catalog::parity_problems` on the real files (core) and the UI parity test; both name the offending id.
- **Don't:** add an id to one file only, or a brace that is not `{[a-z][a-z0-9_]*}`. Do not add a second catalog, completeness test or parity test in another feature.

### Every Rust-originated id is a `MessageId` declared with `messages!`

- **Defect that produced it:** none yet; a hand-kept `MESSAGE_IDS` is an allowlist (P-002): a literal id missing from it passes every check.
- **What breaks if you violate it:** a Rust id absent from the catalogs renders as the raw id.
- **Where it is enforced:** `text` accepts only `MessageId`; `MESSAGE_IDS` is generated from the same declaration; `message_ids_exist_in_both_catalogs`.
- **Don't:** pass a `&str` id to the embedded `text`, or keep a separate id list. The `&str` bypass is closed by structure, not by convention: `embedded()` is private to the module, and `Catalog` (with its `from_json` and `&str` `text`) is `pub(crate)`, so another crate can neither reach the embedded catalog nor rebuild one from `i18n/*.json` (T-031). `MessageId` serializes as its id string (added by T-030 for the IPC wire form).

### A message argument that is a nested id renders as that message's text, in Rust only, one level deep

- **Defect that produced it:** none yet (T-042). `FailureReason::message_params` has no language, so it cannot render a `mic_reason.*` text itself; it returns the id as the argument value and `text()` resolves it.
- **What it is:** the `nested:` group of `messages!` (the four `mic_reason.*` ids) generates `NESTED_IDS`; the ids are also in `MESSAGE_IDS`. Rust `text()` replaces an argument whose value equals a nested id with that message's text in the same language, one level deep, inserted literally (no further placeholder expansion). Nothing else resolves: no `&str` id outside `MESSAGE_IDS` is looked up, and `Catalog::text` is unchanged.
- **What breaks if you violate it:** a nested id shows raw, or in another language than the message around it.
- **Where it is enforced:** `nested_id_arguments_render_in_the_same_language_and_nothing_else_resolves` (core `i18n::tests`).
- **Known limitation:** a user-content argument exactly equal to a `mic_reason.*` id (for example a device name) renders as that text.
- **Don't:** assume the UI does this. `t(id, params)` in `src/lib/i18n` does not resolve nested ids. Anything that sends such params over IPC must render in the shell, or mirror the rule in `src/lib/i18n` with conformance cases in `i18n/conformance.json` (T-006). Do not widen resolution to arbitrary `&str` ids.

### The UI renders a catalog id only through `t(id: MessageId)`; there is no `string`-typed renderer

- **Defect that produced it:** T-004 review round 1 #1. `tWire(id: string)` rendered ids that arrive over IPC. Any component could call it with a typo and get the raw id on screen, with no type error. This is the UI-side twin of the `&str` bypass that T-005 r1/r2 and T-031 closed on the Rust side.
- **What breaks if you violate it:** an id with no catalog text renders as the raw id, and svelte-check cannot see it.
- **Where it is enforced:** `MessageId = keyof typeof en`, so svelte-check refuses an id without an `en` text, and the parity tests refuse one without an `ru` text. The wire inputs that carry an id are typed `MessageId` at the IPC boundary: in `settingsApi.ts`, `FormError.message` and `Warning.message` (T-015, decision #52; core takes it from `WarningCode::message_id()`, so the UI builds no id from the warning code); in `src/lib/local-models/localModelsApi.ts`, `FailureReason.messageKey` and `LocalModelView.nameKey` (T-045; `download.*` and `local_model.name.<id>`, from `local_models::service`). All are Rust ids declared with `messages!`, guaranteed by `message_ids_exist_in_both_catalogs`. Two ids are built by rule from a wire string, each by one documented cast in `src/lib/settings/draft.ts` and each backed by a core test over a list kept complete by hand, next to its enum: a field error's id `errorMessageId(code)` → `` `error.${code}` as MessageId `` (`every_error_code_has_catalog_text` over `ErrorCode::ALL`), and a field's label `fieldLabelId(field)` → `` `settings.field_label.${field}` as MessageId `` (`every_field_id_has_label_text` over the `cfg(test)` `FieldId::ALL`; T-039, owner default Q1). The shared lookup + render rule `text(catalog, lang, id: string)` lives in `src/lib/i18n/render.ts` and is not exported from `index.ts`; its callers are `t` and the conformance test (`catalogProblems` uses its `nonEmpty`). A UI-only id (`error.ipc_unavailable`, `settings.field.not_restored`, `settings.saved_with_warnings`, the `local_models.*` labels of T-045) is a `MessageId` literal in TS and needs no Rust declaration; the parity tests keep its en/ru texts. `src/lib/i18n/ids.test.ts` pins this: `@ts-expect-error` on `t("settings.typo")`, on a `tWire` call, on an `i18n.text` call, on a `FormError` with a non-id message, on a `Warning` with a non-id message (T-015), and on a `FailureReason` / `LocalModelView` with a non-id `messageKey` / `nameKey` (T-045).
- **Don't:** export a renderer that takes `string` (or `` `error.${string}` ``) from `index.ts`, or add an `as MessageId` cast outside `errorMessageId` and `fieldLabelId`; a third rule-built id needs its own core completeness test. To render an id that arrives over IPC, type it `MessageId` where it enters the UI.

### A byte count in a message is a param the UI formats; the text carries no unit

- **Defect that produced it:** T-016 review round 1 (folded into T-045): `download.not_enough_disk_space` said "{needed} bytes" / "{needed} байт" with a raw byte count, against spec 002 FR-007 ("(<size> needed)").
- **What it is:** core sends `needed` as a byte count (a string, like every wire param). The UI shows it, and every other byte count (`sizeBytes`, `received`, `total`), only through `formatSize(bytes, lang)` in `src/lib/local-models/models.ts`: binary units as Windows Explorer shows them (1 kB = 1024 B, 1 MB = 1 048 576 B; whole kB below 1 MB, whole MB below 1 GB, GB with one decimal), the unit labelled by `Intl.NumberFormat` in the UI language (OQ-08 default). `reasonArgs(reason, lang)` applies it to `needed` and passes every other param unchanged. The texts carry no unit: en "Not enough free disk space: {needed} needed.", ru "Недостаточно места на диске: нужно {needed}.".
- **UI-only, like the nested-id rule is Rust-only:** Rust `text()` would print the bare number for `needed`; no Rust path shows a `download.*` text to a user (the settings window renders them), and only the core test `message_ids_per_download_failure` renders it, with `66256`.
- **What breaks if you violate it:** a raw byte count on screen, or two size rules (the list, the progress and `needed`) that disagree (P-010).
- **Where it is enforced:** `models.test.ts` (`formatSize`, `reasonArgs` literals in en and ru); `e2e/local-models.spec.ts` (the disk-space refusal in en and ru, never "66256"); core `message_ids_per_download_failure` (`expected()` texts).
- **Don't:** put a byte unit in a catalog text, send a formatted size from core, or format a size outside `formatSize`. A Rust path that ever shows a `download.*` text with `needed` must format it first.

### An OS tag becomes a UI language in exactly one place, `resolve_ui_language`; the UI never derives it

- **Defect that produced it:** none yet; a second resolver (for example `navigator.language`) would override the user's saved choice.
- **What breaks if you violate it:** a saved `ui_language` loses to the OS language.
- **Where it is enforced:** `resolve_ui_language_table`; the UI starts with `en` and takes `settings.ui_language` (T-004).
- **Don't:** read `navigator.language` or any OS locale in the UI.
