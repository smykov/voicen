# IPC ACL (app commands)

**Code:** `src-tauri/build.rs` (`APP_COMMANDS`), `src-tauri/capabilities/*.json`, `src-tauri/src/lib.rs::commands` (`generate_handler!`) · **Tests that pin it:** `src-tauri/tests/app_acl.rs` (Windows CI), `src-tauri/tests/overlay_ipc.rs`, `src-tauri/tests/local_models.rs::local_model_commands_pass_the_real_acl_from_the_settings_window`, `scripts/ci/app-acl.sh` + `app-acl.test.sh` (`make check-app-acl`)

## Invariants

### Only the window whose page uses an app command may invoke it (T-049, decisions #45, #57)

- **Defect that produced it:** none; a finding of T-044 (decision #57). tauri 2.12.1 checks a local-origin `#[tauri::command]` against the capabilities only when the app has an `__app__` ACL manifest (tauri webview/mod.rs `on_message`; tauri-build 2.7.1 acl.rs adds `__app__` only from `AppManifest::commands` or `permissions/**`). Voicen had none, so every app command resolved from a webview of any label; decision #45's per-label limit covered plugin commands only. Since T-057 there are two local webviews (`settings`, `overlay`).
- **The rule:** every command in `generate_handler!` is listed in `build.rs` `APP_COMMANDS`, which `tauri_build::try_build(Attributes::new().app_manifest(AppManifest::new().commands(&APP_COMMANDS)))` turns into `allow-<command>` / `deny-<command>` permissions (`_` → `-`). Each `allow-<command>` is granted in `src-tauri/capabilities/` to exactly the labels whose page invokes it: `default.json` (label `settings`) gets `get_build_info`, the five `settings_*` and the four `local_model*` commands; `overlay.json` (label `overlay`) gets only `overlay_ready`. Any other (command, label) pair is refused by tauri before the handler runs ("not allowed" in a debug build, "Command X not allowed by ACL" in release).
- **What breaks if you violate it:**
  - a command missing from `APP_COMMANDS` or from every capability is refused from every window, on Windows only (the build does not fail: `generate_handler!` does not consult the ACL);
  - a grant to the wrong label, a `*` window pattern or a `remote` context lets another window (the overlay page, a future window) change settings or download and delete models;
  - a `deny-*` ignores window labels (tauri ipc/authority.rs), so it refuses the command for the window that needs it too.
- **Where it is enforced:**
  - Windows CI `src-tauri/tests/app_acl.rs` over `generate_context!(test = true)` (the same OUT_DIR ACL the release `run()` embeds): the 10 settings commands pass from the `settings_window::open` window and are refused from `other` and `overlay`; `overlay_ready` is refused from `settings` and `other`; a refused `settings_save` changes nothing; a test-only command with no permission is refused even from `settings`. `overlay_ipc.rs` pins the `overlay_ready` pass from `overlay`.
  - Linux `make check-app-acl` (`scripts/ci/app-acl.sh`): the `#[tauri::command]` set, the `generate_handler!` set, `APP_COMMANDS` and the capability `allow-*` set are equal; no app `deny-*`, no non-`allow-` app permission, no `*` window/webview or `remote` on an app grant, no inline capability in `tauri.conf.json`, no hand-written file under `src-tauri/permissions/` outside `autogenerated/`. It cannot see which label gets which command; that is the Windows test.
  - tauri-build fails the build when a capability names a permission that does not exist (a typo'd `allow-*`); Linux `make check-shell-windows` runs `build.rs`, so this shows locally.
  - Tests built on `mock_context` have no app ACL (`Resolved::default()`) and stay unchecked; only `generate_context!(test = true)` tests prove the ACL.
- **Generated files:** tauri-build writes `src-tauri/permissions/autogenerated/<command>.toml` on every build (build-script cwd is `src-tauri`). The directory is gitignored like `src-tauri/gen/schemas`; a stale file for a removed command stays local only.
- **Don't:** add a command without its `APP_COMMANDS` entry and grant; grant app commands with `deny-*`, `*` or `remote`; hand-write permission sets under `src-tauri/permissions/` (option B) without changing this record and the tripwire; assume a `mock_context` test proves the ACL.

## Rejected approaches

| Approach | Why rejected | Ref |
|---|---|---|
| Hand-written `src-tauri/permissions/*.toml` (one per command or per-window sets) | same runtime effect, more hand-kept files; worth it only if scopes are ever needed | T-049 Investigation option B |
| Keep tauri's default (app commands unchecked from local origins) | two local webviews since T-057; the overlay page could change settings | T-049 option C, decision #57 |
| `deny-*` entries to close a command for a window | a deny ignores window labels and refuses the command everywhere | T-049 analysis |
