# Call indicator window (shell)

**Code:** `src-tauri/src/call_indicator.rs` (`IndicatorPart`, `start`, the "call-indicator" thread, `show_without_activation`, `moved`, the four `call_indicator_*` commands, the `IndicatorControl` slot), `src-tauri/capabilities/call-indicator.json`, core `crates/voicen-core/src/overlay.rs` (`OverlayLifecycle::on_visibility`, `on_wake_visibility`), `call/indicator.rs` (`clamp_to_monitors`, `MonitorRect`), `call/session.rs` (`CallSession::dismiss_warning`), `settings/service.rs` (`remember_indicator_position`) · **Tests that pin it:** `src-tauri/tests/call_indicator.rs` and `app_acl.rs` (real Wry runtime / generated ACL, Windows CI only), core `overlay::visibility_tests`, `call::indicator::clamp_tests`, `tests/call_session.rs`

Task: T-130. Class `overlay`. Spec: `specs/007-call-mode-record` (FR-005, FR-006; research R12; `contracts/ipc.md`); ADR-007 (decisions #235). It is the second window of the shell that must not take the focus, so it follows `docs/decisions/overlay.md` and this record adds only what differs. Status of the proof: the focus, click and drag behaviour (variant N, below) is tested only in Windows CI and was not yet seen green when this was written (to verify: the `wip/T-130` run); topmost above a full-screen app is the owner's check (T-159).

## Invariants

1. **The overlay's rules apply unchanged** (`overlay.md` invariants 1-4): `IndicatorPart::set_state` / `set_tick` run under the session lock, only store the newest value in the mailbox and wake the thread; every window operation (build, show, position, emit, destroy) runs on the one `call-indicator` thread, never under the session lock; the window is built hidden, shown once by a raw `ShowWindow(SW_SHOWNOACTIVATE)` after its style bits are written, and no tao setter (`show`, `set_focus`, `set_always_on_top`, `set_position`, `set_skip_taskbar`) touches it afterwards; `call_indicator_state` and every emit carry the mailbox's newest state.
2. **One reducer.** The thread uses core's `OverlayLifecycle` through the shown/hidden input (`on_visibility`, `on_wake_visibility`; hidden = `recording == false`); the dictation overlay's `on_state` / `on_wake` give the same answers. The window therefore exists exactly while the newest state records: built at the first recording state (never at app start), destroyed at stop and rebuilt at the next start (NFR-03). Hiding between calls was rejected: it keeps a WebView2 alive after the first call.
3. **Style (ADR-007 variant N).** Built with `focusable(false)` (`WS_EX_NOACTIVATE`), `always_on_top`, no decorations, not resizable, no shadow; then `WS_EX_TOOLWINDOW` set and `WS_EX_APPWINDOW` cleared (tao adds the latter to every unowned window), `SetWindowPos(SWP_FRAMECHANGED | SWP_NOACTIVATE)`, one `SW_SHOWNOACTIVATE`. No click-through bits: the page takes clicks (Stop, Dismiss) and drags through `data-tauri-drag-region`. Variant F (focusable, the shell returns the foreground after a click) is not implemented; it is the fallback if the Windows CI tests of click and drag fail. A native Win32 window would need a new owner decision (#235).
4. **Not a helper window.** The indicator is a product window; `scripts/ci/helper-windows.txt` is unchanged. The test `the_indicator_adds_exactly_one_top_level_window_to_the_process` pins that its show adds no other top-level window.
5. **Position.** The saved `calls.indicator_position` (physical pixels, the top-left) is clamped at each build to the present monitor work areas by core's pure `clamp_to_monitors` (a window not fully inside one work area moves fully onto the monitor it overlaps most); with none saved it is the top-right of the primary work area, 24 px inside. The one writer is `SettingsService::remember_indicator_position`, called by `moved` after the same clamp. `call_indicator_moved` saves the position; it does not move a live window (the drag already did).
6. **Size.** 320 x 72 logical pixels, scaled by the DPI of the monitor at the position.
7. **Events.** `indicator://state` at each build and each newer recording state; `indicator://tick` coalesced to the newest, at most every 100 ms; a tick with no live window is dropped.
8. **Failures.** A failed build, emit, show, destroy, position write or thread start writes one `warning kind=overlay_failed` (OS code only, no payload or text; `docs/decisions/diagnostics-log.md`). The window then stays hidden or in place; the call is not affected.
9. **Commands.** Granted to the label `call-indicator` alone (`docs/decisions/ipc-acl.md`). Stop and Dismiss go to the `IndicatorControl` slot that the call wiring fills (T-128); empty, they resolve `null` and do nothing.

## Open

- The window size (320 x 72) and the default position (top-right, 24 px in) were chosen by the developer, not by a spec: OQ-80.
