## Proposals

Ordered by expected effect.

### 1. Environment: headless worktree sessions may push `wip/<ID>` (task)

- **Evidence:** 11 of 11 parallel worktrees stopped `BLOCKED` on the P-016 push (W). Some sessions escalated up to seven times on the same question (T-160 has seven `escalate` commits). After the orchestrator pushed, all 11 runs were green.
- **Change:** a `type: chore` task:
  - add `Bash(git push -f origin HEAD:wip/*)` to the project `.claude/settings.json` allow list, so headless worktree sessions get it (today it is only in the gitignored local file, which worktrees do not have);
  - reword the `CLAUDE.md` rule "never push from a DEV session, except the orchestrator's CI-only push" so that a worktree's own stage session may make that push (decision #202 already allows it for the orchestrator).
- **Cost:** a CI run per wip push, which P-016 requires anyway. The deny list for `main` stays.
- **Measure:** worktree outcomes `escalate` on a P-016 push (now 11 / 11).

### 2. Rule: task records are edited with Edit/Write only (project rule)

- **Evidence:** 48 + 29 analysis-gate denials after 10-09, all one reason: a status edited through the shell (G). The 10-09 feedback did not change the kit's message.
- **Change:** one line under `CLAUDE.md` › Rules: "Edit task records (`docs/tasks/*.md`, status and front matter) only with the Edit/Write tools; the analysis gate refuses shell edits."
- **Cost:** one line in a file every agent reads.
- **Measure:** analysis-gate shell-edit denials (now 77 after 10-09).

### 3. teamwright: stage cost charges the whole orchestrator session to one stage (feedback)

- **Evidence:** red-tests shows 120 M tokens, 20 M per task. One long main session, which ran every stage, is charged to the stage of its last task.
- **Change:** a feedback draft. Split a session's tokens by the stage of each turn (or of each spawned role), or report the orchestrator session as its own row.
- **Cost:** none to the project.
- **Measure:** per-stage token rows after the kit changes.

### 4. Settings: no change; re-measure the 2026-10-24 settings (setting)

- **Evidence:** 5 tasks reached review after `review.blocking: high`, `batch.max_tasks: 5`, `batch.parallel: 10`.
- **Change:** none now. At the next improve, split at 2026-10-24: send-back share, follow-ups opened, docs-drift returns (high lets Medium docs drift through as follow-ups).
- **Cost:** none.
- **Measure:** as above.

### 5. Recurrence: keep watching (no change)

- **Evidence:** 0.86 after; the hotspots are the CI guard files that T-085 and T-113 settled. No fix since 2026-10-21.
- **Change:** none. If a fix lands in `ci.yml`, `Makefile` or `release-guard.sh` again, it is a recurrence: an rca task, as the rules already say.
- **Measure:** recurrence rate over the window after 2026-10-21.

### Feedback draft (not sent)

- **Problem:** the per-stage cost (`journal.stages`) charges every token of a session to one stage. A long main session that runs the flow through every stage is charged to the stage of its last task, so one stage shows tokens it never spent.

- **Proposed change:** split a session's tokens by the stage of each turn, or of each spawned role agent. Otherwise, report orchestrator sessions as their own row and leave them out of the per-stage figures.
