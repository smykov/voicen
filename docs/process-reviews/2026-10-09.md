## Diagnosis

| Signal | Reading |
|---|---|
| Send-back share 0.39, 2.16 rounds | After the threshold moved to medium, rework fell (0.85 → 0.69), but rounds barely moved (2.22 → 2.14). The returns are driven by medium+ findings in two categories, not by low noise. |
| docs-drift 62 / 20 returned | The largest category. Docs are corrected by the reviewer instead of by a writer step before review: technical-writer runs only "when the change touched a contract", and the author decides that. |
| toothless-test 26 / 14 returned | Bite is proven late: by the reviewer or by the validator's mutations (T-023 went DEPLOYED→IN_PROGRESS on 2026-10-09 for a missing test). Test-writers hand back without a mutation record. |
| Verify failures 1 → 7 | Grows with throughput. Most are owner-environment checks (NEEDS_OWNER) or missing tests, which the toothless-test fix above addresses. |
| Analysis-gate denials 37 after | Pure waste: agents edit status through `sed`. The harness advertises shell edits as fine and the gate refuses them, so each denial costs a retry. |
| Context tool 8 % | Subagents do not use Serena at all. Either the MCP server is not available to them or their role files do not mention it. Svelte has no language server. |
| Recurrence 0.56 → 0.79 | Concentrated in CI plumbing (`ci.yml`, `Makefile`, `shell-test-layout.sh`). The T-066 / T-080 work already targets it. Watch it; no new proposal. |
| Bookkeeping 0.64 | Fine for CI cost (see Data). It inflates `git log` but does not cost runs. |
| Records 133 KB | One-off tasks with long owner-validation histories. Every role re-reads them. Moderate cost. |
| Follow-ups 109 | Open but bounded, and the medium threshold is what keeps the pace. Fine as long as T-060 drains each sprint. |
| Ratified 12 | Fine: all deliberate, each with a decision row. |

## Proposals

Ordered by expected effect.

### 1. Rule: the test-writer hands back a bite record (project rule)

- **Evidence:** toothless-test 26 findings, 14 tasks returned; one task re-opened after DEPLOYED.
- **Change:** a `PRINCIPLES.md` amendment. A test-writer's handback lists, for each new test, the one-line mutation of the seam that turns it red, run on a throwaway copy. Without the list, the orchestrator does not start the developer.
- **Cost:** about one extra gate-sized run per task at test time.
- **Measure:** toothless-test returns per task at the next improve (now 14 / 66).

### 2. Rule: a writer pass before NEEDS_REVIEW whenever `docs/**` or a contract is named (project rule)

- **Evidence:** docs-drift 62 findings, 20 tasks returned. It is the largest category.
- **Change:** a `PRINCIPLES.md` amendment. The technical-writer step runs on every task whose diff touches code that `docs/architecture.md`, `contracts/` or `docs/decisions/<area>.md` names, not only on the author's judgement. Docs cite symbols and sections, never line numbers.
- **Cost:** one writer agent per qualifying task.
- **Measure:** docs-drift returns (now 20).

### 3. Environment: Serena for subagents and Svelte indexing (task)

- **Evidence:** subagent roles use the context tool 0 % of the time (78 built-in reads); Svelte is not indexed.
- **Change:** a `type: chore` task in sprint 1:
  - check that the Serena MCP server is exposed to subagent sessions;
  - name it in the role files' tool lists and first step;
  - add a Svelte language server, or record why not.
- **Cost:** small.
- **Measure:** `tw-context` share by role (now 0 % for every subagent).

### 4. teamwright: the analysis gate's shell-edit refusal (feedback)

- **Evidence:** 37 of 37 analysis-gate denials after 2026-10-05 have the same reason: a status edited through the shell.
- **Change:** a feedback draft. Either the gate accepts a shell edit that changes only the status line, or the role instructions and the gate message say "use Edit" in the first line every agent reads.
- **Cost:** none to the project.
- **Measure:** analysis-gate denials (now 37).

### 5. teamwright: test-writer agents cannot commit (feedback)

- **Evidence:** this session, the test-writer's `git commit` was refused by permissions, and the orchestrator committed the red tests on its behalf.
- **Change:** a feedback draft. The role is told to commit red tests, but the permission profile blocks it. Align the two: either let the role commit, or tell it to hand back with the files staged.
- **Cost:** none.
- **Measure:** permission denials for subagents.

### 6. Rule: move the validation history out of the task file past 40 KB (project rule)

- **Evidence:** T-006 132.8 KB, T-057 80.6 KB, T-061 73.1 KB; analysis is only 4–7 KB of each.
- **Change:** a `PRINCIPLES.md` amendment. Once a task file passes 40 KB, the Investigation and Validation histories move to `docs/tasks/<ID>.history.md`, and the task keeps a summary and a link.
- **Cost:** one move commit per large task.
- **Measure:** the largest record size.

### Feedback sent (2026-10-09)

**A — sent** as a bug report: https://github.com/smykov/teamwright/issues/2 ("analysis-gate: shell status check matches the whole compound command — denies commands that never write a task record").

The draft above was narrowed after checking the journal (`gates.jsonl` joined with `tools.jsonl`). Of the 37 denials:
- 23 were `sed -i` edits, which are true positives;
- 14 were commands that write no task record: `cat`, `grep -n`, `mkdir -p`, `sed -n`, `git status`.

The gate tests the whole command string, not the write target.
