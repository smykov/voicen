## Overview

A Tauri 2 desktop app for Windows. A Rust shell (`src-tauri`) owns everything Windows-specific (tray, global hotkey, audio capture, clipboard, SendInput paste, Credential Manager, notifications) and calls a platform-independent core library (`voicen-core`) that owns the dictation pipeline: VAD gate → engine → optional post-processing → delivery decision. The web UI (Svelte) renders settings, first run, history and the overlay, and talks to Rust only through Tauri IPC commands.

```mermaid
flowchart LR
    HK[Global hotkey] --> SH[src-tauri shell]
    MIC[Microphone] --> SH
    SH --> CORE[voicen-core pipeline]
    CORE --> VAD[VAD gate]
    CORE --> ENG{Engine}
    ENG --> API[OpenAI-compatible API]
    ENG --> LOCAL[whisper.cpp in-process]
    ENG --> SRV[Local OpenAI-compatible server]
    CORE --> LLM[Chat API post-processing]
    CORE --> SH
    SH --> CLIP[Clipboard + Ctrl+V into start window]
    UI[Svelte UI] <-->|Tauri IPC| SH
```

## Seams

| Seam | Concern | Guard / invariant |
|---|---|---|
| `Engine` trait in `voicen-core` | adding a provider | recording and delivery code do not change (NFR-11); the one total factory `voicen_core::engine::engine_for(&Settings, &dyn CredentialStore)` (per job; `Api` and `LocalServer` (T-018; the endpoint role picks the 30 s / 60 s deadline and `kind()`, an empty model is omitted, the local-server key is optional) build the one client; `BuiltinLocal` (shell, T-017), `None` or a stored base URL failing `check_base_url` → `EngineNotConfigured` without a key read, a key-store error → `KeyStoreUnavailable`; decision #44); every OpenAI-compatible request is built and sent only by `engine::openai::OpenAiCompatibleEngine::transcribe` (blocking reqwest, URL joined on the parsed base URL keeping its query, body capped at 1 MiB) and every transport failure goes through `failure::classify` to a `FailureReason` that never holds a URL, body or key (T-040) |
| `SpeechDetector` trait / `SpeechGate` in `voicen-core` `vad/` | is this recording speech (FR-12) | every speech decision is `vad::SpeechGate::decide` (infallible, `&self`, shared by workers): the primary's `Ok` answer, else `vad::energy::EnergyDetector` (R-5 rule with the [−70, −40] dBFS floor clamp and the 3-frame minimum run); a primary `Err` at construction or at run time latches the fallback for the gate's lifetime and never counts as speech; exactly one `GateDecision` per gate has `fallback_warning`; the gate emits no events, the pipeline does (T-041; Silero is T-043) |
| `RecordingController` in `voicen-core` `recording/` | is a recording on; what the tray and overlay show | the only place that starts or ends a recording and the only constructor of a `FinishedRecording` (a non-`Clone` `StopTicket` consumed by `finish`: at most one per press, none under 300 ms, on a capture error or for a stale id); the only owner of `IndicatorState` (changes only inside controller methods; `IndicatorState::derive` holds the two priority orders); sans-IO, no clock: every `Instant` comes from the caller's event; a capture error becomes `MicrophoneUnavailable{cause}` with a closed `MicCause`, never OS text; the engine = none check stays in `settings::gate::dictation_gate` (T-042) |
| `Pipeline::run_job` in `voicen-core` `pipeline.rs` | what happens to a finished recording | the only path a `FinishedRecording<PressContext>` takes (`PressContext { start_window, settings: Arc<Settings> }`, the snapshot taken at press; no `SettingsSource`, decision #47); blocking, on a plain std thread, never in a tokio runtime; two private halves, `process` (gate → engine from the one factory, default `engine_for`, with the job's snapshot and the pipeline's one `Timeouts` → `PostProcessor`) and `release` (`delivery::deliver` → pending slot → events), so T-011's queue goes between them; no factory call, credential read or request unless the gate says speech; the clipboard is written only for a non-blank text and Ctrl+V only after that write, per data-model "DeliveryDecision" (`MODIFIER_WAIT` 1 s, a `send_ctrl_v` error is copy-manual); one pending slot: a retryable failure stores its audio under a new `PendingId`, replaces the slot (none if the store failed) and deletes the older audio, `Text`/`NoSpeech` leave it; reported only as `JobReport { end: JobEnd, pending }` and `Copy` `DictationEvent`s on the one `PipelineObserver` (`[Warning]`, `SpeechGate`, `JobFinished` after the clipboard write, `[Delivered]`); `Instant::now()` only for event durations (T-001) |
| `DictationSession` in `voicen-core` `dictation.rs` | turning hotkey events into a delivered dictation (T-051, decision #64) | the only path from a hotkey press to the microphone, the pipeline, the clipboard and Ctrl+V; the shell's adapters stamp instants and carry out requests, they decide nothing. One lock over the `RecordingController<PressContext>` and the live capture; capture opens only from idle, after `dictation_gate(snapshot)` passed and `press` returned `Start` (snapshot and start window taken once, at that press); the device is stopped before `hotkey_released` returns (NFR-02); one FIFO worker owns the `Pipeline` and is the only caller of `run_job` and `job_finished`, `run_job` never under the lock (decision #48); jobs are queued in the critical section of their `finish`, releases are serialised, so delivery follows recording order; `retry_available` = the pending slot read on the worker after each job; indicator changes reach the `Indicator` port only from inside the lock, once per change, none at start, none between a stop's release and its finish, none in a recording state for a capture that failed; a timer thread ticks at `next_deadline`; events `RecordingStarted` / `RecordingEnded` / `CaptureFailed` on the pipeline's one observer. Why: `docs/decisions/dictation-session.md` |
| `overlay_payload` in `voicen-core` `overlay.rs` | what the overlay page shows (T-053) | the only producer of the overlay wire payload `{seq, lang, state}` (the `overlay://state` event and the `overlay_ready` reply, spec 001 contracts/ipc.md). It is pure: one `OverlayState` plus the caller's `lang`, `seq` and `elapsed`. A message's text is rendered here by `i18n::text` in `lang`, nested `mic_reason.*` ids included, so no message id, params, severity or expiry reach the UI, and the page has no expiry timer (every expiry is the session's). The wire form is serde impls in core, pinned by `e2e/fixtures/overlay-wire.json`. The overlay window is the shell's (T-057): `src-tauri/src/overlay.rs` keeps the newest published state in a mailbox (`ShellIndicator::set_overlay` only records it and wakes the thread) and runs every build, emit and destroy on the one "overlay" thread, following core's `OverlayLifecycle` (a window is built only when none exists and none is being destroyed, learned from the window's own `Destroyed`); `capabilities/overlay.json` grants label `overlay` listen / unlisten only; `overlay_ready` returns the mailbox state's payload. Why: `docs/decisions/overlay.md` |
| `Downloader` / `ModelStore` in `voicen-core` `local_models/` | is a built-in model on disk, and how it gets there (FR-08) | a file appears under a catalog model's final name only through `download::Downloader`, which renames `<file>.part` after the byte count equals the catalog size and the streamed SHA-256 (`sha2`) equals the pinned value; every other end (status, transport error, no data for `Timeouts::download_no_data`, disk error, size or hash mismatch, cancel) closes `<file>.part`, tries to remove it (best effort: a failed removal is ignored; the leftover is never read as a model, the next start truncates it and `ModelStore::cleanup_at_start` removes it) and clears the one active slot before the end event; blocking reqwest on its own std thread, no tokio; the no-data timeout is `ClientBuilder::timeout` (per read and per header wait), never a total one; failures are `download::DownloadFailure` (contracts/ipc.md codes; never the URL; reqwest errors reduced through `engine::openai`'s `send_error`/`body_error` facts), separate from `FailureReason`; `store::ModelStore` derives "downloaded" only from the disk (final file with the catalog size) and is the one `DownloadedModels` (T-016, decision #49) |
| `LocalModels` in `voicen-core` `local_models/service.rs`; shell adapter `src-tauri/src/local_models.rs` | which models the UI lists, and starting / cancelling a download over IPC (FR-08) | one `LocalModels` per process, made only by `LocalModels::open(models_dir, disk, timeouts, catalog)`, which runs `ModelStore::cleanup_at_start` before it returns (`run()` writes one `warning kind=models_cleanup_failed` log line with the OS code only, and runs on; T-008); its one `Arc<ModelStore>` (`store()`) is `SettingsDeps.local_models` and the store behind every command; it holds the in-memory `Downloading` / `Failed` states (lost on restart) over the disk state; only `Downloader::start` begins a download; every `LocalModelEvent` reaches the caller's `emit` only from the download thread, after the in-memory state is updated and with no lock held; a refusal changes no state, emits nothing and maps through the one `From<&DownloadError> for ReasonView` (`download_busy`, `already_downloaded`, `not_enough_disk_space{needed}`, `not_in_catalog`, `download_cannot_start`), a failure through `DownloadFailure`'s own code / message / params; the wire form is serde impls in core, pinned by `e2e/fixtures/local-models-wire.json`. The shell only delegates: commands `local_models_list`, `local_model_download {id}`, `local_model_cancel_download {id}` (no reqwest on a command thread), `emit_to(EventTarget::webview_window("settings"))`, and `WinDiskSpace` (`GetDiskFreeSpaceExW` on the nearest existing ancestor of the models dir) (T-044, decision #57) |
| Platform traits (audio source, clipboard, input, credentials) | Windows vs tests | core tests run on Linux with fakes; Windows impls only in `src-tauri` (`win/capture.rs` `CpalSource`, `win/clipboard.rs` `WinClipboard`, `win/paste.rs` `WinPaster`, `dictation.rs` `ShellIndicator` and `SettingsRequests`; T-006); `voicen_core::platform` holds `Clipboard`, `Paster`, `TempAudioStore`, `StartWindow`, `PendingId` (T-001) and `AudioSource` / `FrameSink` / `CaptureHandle`, `Indicator`, `ShellRequests` (T-051, called only by the dictation session) with public fakes (feature `test-fakes`; `test_support::realtime::RealtimeSource` paces WAV or buffer frames in real time), errors carry no OS text; `events::PipelineObserver` with `RecordingObserver` (test fakes) and `diag::LogObserver` (release, T-008); `post_process::PostProcessor` with `PassThrough` until T-020 |
| `diag::Log` in `voicen-core` `diag/` (shell: `src-tauri` `diag::start`) | what reaches `%LOCALAPPDATA%\Voicen\logs` (FR-20, NFR-04, P-009) | every byte under `logs/` comes from the one `Log` of the process (opened only by `diag::start(paths::log_dir(), on_unwritable)`, which writes `Started` first; only the primary instance opens it, after tauri's `build()`, T-052) through `Log::write(LogEvent)`: one mutex, whole lines; `LogEvent` holds only integers, closed enums and `BuildInfo` (no `String`, `&str`, path, `io::Error`, `FailureReason`), an outside `&'static str` (engine kind, detector, failure code) passes through `EngineTag::from_kind` / `DetectorTag::from_name` / `FailureTag::from_code` (unknown → `other`); `format_line` is total over a closed output; active `voicen.log` ≤ 2 MiB (rolled before a line would cross it or at the local date change), rolled `voicen-*.log` ≤ 10 MiB − 2 MiB, older than 7 days deleted, at open and after each roll, nothing else touched; `write` never panics, an unwritable folder degrades with `on_unwritable` at most once per `Log`, a reopen at most every 60 s, `LogsRecovered` first; the pipeline's events reach it only through `diag::LogObserver` (one dictation line per recording, joined by `RecordingId` / `seq`, exhaustive matches); the shell's diagnostics are typed `Warning` lines, no `eprintln!` and no `log` / `tracing` logger.
