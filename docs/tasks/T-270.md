## Context

From the T-267 analysis (decisions #374). In CI runs 45431956259 and 45596682657 the call indicator's window was still white on screen after `PageLoadEvent::Finished` and its show (receipt after 163 ms and 617 ms), while `docs/decisions/overlay.md` and the doc of `IndicatorThread::build_window` (src-tauri) say the indicator waits for the page load "so it never shows blank". The receipt proves "shown", not "painted". Not proven for the real Svelte page (the test page's background and timing differ). Outside sprint 2's goal (decisions #370): P3.

## Acceptance

- [ ] On Windows, the first show of the call indicator with the real page is checked for a white frame (screen samples from the show on), and the result is recorded
- [ ] If a white frame is seen: the indicator window is shown only after the page reports its first paint (or is painted in the page's background colour before it), and `docs/decisions/overlay.md` says which
- [ ] If none is seen: the docs say "shown after load; the first frame may lag" where they now say "never shows blank", and the check stays as a test
- [ ] Failure branch: a page that never reports its paint still shows the indicator after a bounded wait, with a log line; the indicator is never left hidden
- [ ] Test that fails without the change: a shell test in `src-tauri/tests/` sampling the indicator's pixel from the show on (positive wait, `timing_support`)
