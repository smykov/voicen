**Frame.**
- Observed: the energy detector makes every speech decision. `dictation.rs` passes `Err(VadError::Unavailable)`, the installer has no model, and `voicen.exe` does not link `voicen-whisper`.
- Expected: FR-12 / #175. The installed app decides with the bundled, pin-verified Silero model before the end of 1a. A model that cannot be loaded falls back to energy with one warning.
- Scope: `deploys: true`; proof only in Windows CI (install smoke, `cargo test -p voicen`).

**Hypotheses.**
1. *The install smoke can show `detector=silero` on a hold (the acceptance as written).* Refuted: the runner has no capture endpoint. The loaded hold step (ci.yml "A hotkey hold on a loaded launch…") logs `WARN dictation rec=0 outcome=capture_failed mic=no_device` (T-006 Verification), and the gate never runs. The same holds for the failure branch: `vad_fallback` is written at the first gate decision (`GateDecision::fallback_warning`), which never comes. So the installed exe needs a start-time observable (**D1**). The hold-level line can be proven through `dictation_e2e.rs`, which already drives the real wiring with injected audio and the real log.
2. *T-102 can wait for T-017 to link whisper.cpp into `voicen.exe`.* Refuted by #175: T-102 is decoupled and goes first. T-102 therefore owns the first link of whisper.cpp into `voicen.exe`. Its consequences are below (Linux gate switch, CRT list, AVX2). The task's Context still says "Needs T-017": that is stale against #175 (orchestrator).
3. *Adding `voicen-whisper` to the shell keeps the Linux gate green as is.* Refuted, from evidence rather than a run: the image has `gcc-mingw-w64-x86-64-win32` but no mingw g++, and the T-017 probe saw the gnu check of whisper-rs-sys fail at cmake. `check-shell-windows` needs `DOCS_RS=1`. That is a Makefile change, so a guard change: `checker: true` and `decides_on` (pre-commit guard trigger). **Orchestrator: set `checker: true` in the front matter** (outside my edit scope). Only whisper-rs and whisper-rs-sys read `DOCS_RS`, so the switch hides no other crate's gnu build (opus and aws-lc stay checked). The developer confirms it with a red gate before the switch.
4. *The model can be listed in `tauri.conf.json`.* Refuted (unchanged): tauri-build canonicalizes every resource source on each shell build, so the Linux gate and `cargo test -p voicen` would need the file. With the `--config` overlay, the merge patch adds one key to the existing map, so NOTICES stays. The CLI hands the merged config to the build script (`TAURI_CONFIG`) only for `tauri build`.
5. *The same concern is handled on a second path.* Gate builders: `release_ports`/`start_dictation` (production), `dictation_e2e.rs`, `diag.rs` and `hotkey_registrar.rs` (shell tests), and core's `pipeline.rs` and `tests/vad*.rs`. Only production changes; the tests pass their detector explicitly. A second Silero load is coming: T-135 (spans) must load "through T-102's loader, shared with dictation", and T-139 wires it. Hence invariant (1): one shell loader. T-135 will likely widen it from `Box` to a shared `Arc`. I do not build that now.
6. *This class was fixed before.* No: `docs/failures.md` has no VAD or `transcription-pipeline` entry, so `recurrence_of: []` holds. Classes this task touches:
   - F-001/F-002 (`ci-toolchain`: each exe kind gets a different subset of build-script link outputs). tauri-build's `static_vcruntime` uses plain `rustc-link-arg`, so shell test exes get it too. Still, any shell test exe that now links whisper.cpp through the lib should be in the crt-imports list (T-099 invariant 4: every exe that links whisper.cpp).
   - F-008 (`smoke-window-predicate`): the helper-window tripwire walks the new normal edges. whisper-rs and whisper-rs-sys have no `CreateWindowEx` in `src/`, so it should stay green.
   - `ci-premise-unchecked-before-main`: everything is proven on `wip/T-102` (P-016).

**Findings beyond the acceptance.**
- `panic = "abort"` in `[profile.release]`: `SileroDetector`'s `catch_unwind` guards work only in debug test exes. In `voicen.exe`, invariant (2) rests on the pre-checks (verify, UTF-8/NUL, AVX2) and on whisper-rs returning `Err`. This is acceptable because T-043's hostile-header and NUL tests cover the known panic and abort paths, but say so in `decisions/dictation-session.md`.
- Install dir = data dir by default (`%LOCALAPPDATA%\Voicen`), but the interactive directory page can move the install. Resolve the model from `resource_dir` (exe dir), never `paths::data_dir()`. Never put it under `models/`, which `LocalModels` owns (`.part` cleanup, listing). Recommended destination: `vad/<SILERO_MODEL.file_name>`, from a directory-source map entry (`"<fetch dir>/": "vad/"`), so neither the overlay nor ci.yml repeats the file name (T-043 invariant 3). The install smoke is the cross-check that the overlay's `vad/` and the shell's path agree.
- The NSIS fork's resource loops (`installer.nsi` "Copy resources" / "Delete resources") install and remove the file. `/KEEPDATA` removes it with the program files; `/S` removes the whole folder. No hook change.
- Load at start costs one 885 KB SHA-256 plus the whisper.cpp VAD init (ms range; T-043 measured ~15-20 ms per decision). It runs once in `run()`; no lazy load needed.
- AVX2: with whisper.cpp statically in `voicen.exe`, every user's exe contains `/arch:AVX2` ggml-cpu code (ARCH_FLAGS are private to the `ggml-cpu` target, ggml-cpu/CMakeLists.txt:678). `SileroDetector::load` refuses a non-AVX2 CPU before any native call. A text grep of `ggml-cpu/*.cpp` found no global dynamic initializer, but that is not proof. No runner lacks AVX2, so a non-AVX2 start of `voicen.exe` cannot be shown in CI. #142 accepted the illegal-instruction failure only for the built-in engine (**D3**).
- NFR-09: the last measured install is 9.3 MB. whisper.cpp static adds a few MB and the model 0.9 MB, leaving wide headroom; the existing smoke check stays the proof.
- The `manual.json` note ("Downloaded in CI for tests; bundled by T-102") becomes "bundled in the installer", which needs `make licenses` and the NOTICES regenerated.
- The ci.yml crt-imports comment ("voicen.exe from T-017 on") and `decisions/dictation-session.md:98` both name the old owner; update both.
- design_ref should cite #175 next to #60 and #136 (orchestrator).
- Size: medium. Four places (core diag line, shell port and loader, CI overlay and smoke, Makefile switch), all fixed by #136 and #175, and they prove only together. I recommend keeping one task. If review wants it smaller, the core log line can be a separate small task.
