- [ ] T-034 v1 Low test-gap: the e2e failure branch (`e2e/settings-autostart.spec.ts:128`) checks Save is enabled but not that the draft stays dirty after a refusal; only `draft.test.ts` holds it (mutation M1 survived the e2e)
- [ ] T-021 r1 Low #3: a Refused field error whose control is on another settings tab is shown nowhere (`src/routes/settings/+page.svelte` lists only `not_restored` and warnings at form level); T-021 makes it common (post-processing on with an empty field, Save from another tab) — settings-ui follow-up: form-level error list or jump to the tab. - [ ] T-023 review 2 Low: `opening++` in About's `onDestroy` (`src/lib/about/About.svelte`) drops a still-pending build-info answer of a destroyed instance; no test bites it and it has no visible effect. Remove it or mark it defensive in `docs/decisions/settings-ui.md` § A
- [ ] T-023 v2 Low docs-drift: the teardown rationale ("without this the new instance would showModal() unasked") holds only if the open state outlives General; since T-019 `aboutOpen` is local to General.svelte. Reword it (src/lib/settings/About.svelte:61-65; docs/decisions/settings-ui.md:140)

A future modal that skips it, or is mounted outside the settings page (the call is then a no-op), brings back the T-023/T-019 bug. - [ ] T-013 review 2 Low #1 (maintainability): the core pin test `e2e_settings_wire_fixture_test_connection_invalid_off_tab_matches_core` and the `testConnectionInvalidOffTab` doc comment say the errors are "in validate's order", but the value is built by hand, so the pin proves the wire shape, not the order.
