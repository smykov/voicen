## Context

Decision #271 (OQ-85, option c). T-062 moved the WebView2 user data of every Voicen window to `%LOCALAPPDATA%\Voicen\webview`. A machine upgraded from a build before T-062 keeps `%LOCALAPPDATA%\dev.voicen.app` (a rebuildable WebView2 profile; settings live in `settings.json`), and neither the app nor the uninstaller removes it (`docs/decisions/installer.md` › WebView2 data). The owner chose: the installer (on upgrade) or the uninstaller removes that folder; no app code. Refined by decisions #345: every install removes it, an uninstall only when it removes the data (`$VoicenPurgeData = 1`), and a locked remainder is left silently for the next install or uninstall. The NSIS hooks live in `src-tauri/windows/installer-hooks.nsh`.

## Acceptance

- [ ] Windows CI: a planted `%LOCALAPPDATA%\dev.voicen.app` (with a file inside) is gone after the installer runs over it, on every install path (upgrade `/P` and silent reinstall; decisions #345 Q1)
- [ ] Windows CI: a planted `%LOCALAPPDATA%\dev.voicen.app` is gone after an uninstall that removes the data (`$VoicenPurgeData = 1`), also when kept calls stay (default uninstall without `/PURGECALLS`), and still present after `uninstall.exe /S /KEEPDATA` (decisions #345 Q2)
- [ ] A part of the folder that cannot be removed (locked) is left without a message or a failed install/uninstall; the next install or uninstall retries it (decisions #345 Q3)
- [ ] Failure branch: nothing outside `%LOCALAPPDATA%\dev.voicen.app` is removed — a sibling folder (e.g. `%LOCALAPPDATA%\dev.voicen.app.keep`) planted next to it survives both paths
- [ ] Test that fails without the change: the Windows CI step named by the analysis
- [ ] `docs/decisions/installer.md` › WebView2 data updated (OQ-85 → #271)

## Investigation

**Frame.** Observed (by reading; nothing run): no code in the installer package names `dev.voicen.app`; the only folder deletions are in `NSIS_HOOK_POSTUNINSTALL`, rooted at `$LOCALAPPDATA\Voicen`. Expected (#271): the folder is gone after an install over an older build and after an uninstall, and nothing beside it is touched. Tools: Serena indexes Rust only, so the NSIS hooks, the fork, `ci.yml` and `scripts/ci` were read with grep and file reads; NSIS semantics from context7 `/websites/nsis_sourceforge_io`.

**Hypotheses.**
1. *The uninstaller alone can do it* — refuted for the upgrade: `PageLeaveReinstall` (fork edit 1) runs the **previously installed** uninstaller, so a user upgrading from a pre-T-207 build never runs new uninstaller code; silent installs run no uninstaller at all (installer.md, Rejected approaches). The upgrade removal must be installer-side: `NSIS_HOOK_POSTINSTALL`, which runs on every install after `CheckIfAppIsRunning` (`installer.nsi:623`, `:711`).
2. *The existing walker can be called from the installer* — refuted: `un.` functions are uninstaller-only (NSIS 4.7.1.1). The NSIS-documented shape is one macro body inserted with `""` and `"un."`, which keeps one walker text and the owned rmdir line unchanged.
3. *A second path already handles it* — checked: the T-062 CI step removes a leftover `dev.voicen.app` as its own premise (`ci.yml:1130`); no product path does. Earlier `cargo test -p voicen` may create one on the runner (T-062 hypothesis); with T-207 the first silent install removes it, and the T-062 step's "existed before" log line turns False. Harmless.
4. *This class was fixed before* — no: `docs/failures.md` has no WebView2, installer or uninstall entry of this class. Related precedents that constrain the shape: T-156 (no `RMDir /r`, one walker, owned rmdir lines) and T-025 (one decision point; do not key deletions on `$UpdateMode` alone).
5. *`$LOCALAPPDATA` in the installer section may be the all-users folder* — a risk, not a finding: the macro sets `SetShellVarContext current` itself (as `VoicenNoteInstallerEnded` does, `installer-hooks.nsh:205`) and skips on an empty `$LOCALAPPDATA`.

**Why the walker and not a literal delete.** `dev.voicen.app` may itself be a junction (or hold one); the walker removes a link without entering it, a file with `Delete`, a real folder bottom-up with a plain non-recursive removal that fails on a non-empty folder. The sibling `dev.voicen.app.keep` can't be matched: the walker takes one literal path and enumerates only inside it.

**Red test.** W2 and W4 of the windows job, extended (see `analysis.approach`). On today's hooks both "is gone" asserts throw; the sibling assert stays green and is the failure branch (it goes red on a pattern delete such as `dev.voicen.app*`). Windows CI is sufficient for acceptance: a planted folder is the same as a real pre-T-062 profile for a file-level delete. The owner's machine is not needed (an owner spot-check after the next upgrade is optional).

**Overlap.** The hooks file is shared with other installer work; T-210 (DONE) set the same rule: no new line with the token `rmdir`.

**Owner answers (decisions #345, 2026-11-23):** Q1 (a) the installer removes the folder on every install (`NSIS_HOOK_POSTINSTALL`); Q2 (a) the uninstall removes it only when it removes the data (`$VoicenPurgeData = 1`); Q3 (a) what can be removed is removed silently, and the next install or uninstall retries the rest.
