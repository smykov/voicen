**Hypotheses checked.**
1. *A dependency already built part of this.* T-128 built the call part, `start_calls`, the managed `Arc<CallStore>` and the tray route. T-141 built the wire. Nothing else is built. Confirmed by grep for `calls_`/`calls://` in `src-tauri/src` (only the counter and comments).
2. *The concern is handled on a second path.* Clipboard: the only `Clipboard` impl is `WinClipboard` (grep `impl Clipboard`). The invariant is about sharing its one instance, not a second writer. Folder opening: `logs_folder::FolderOpener` + `ShellOpener` exist; reuse them, do not add a second opener. Window creation: only `settings_window` and `overlay` build windows; the calls window copies the opener-thread pattern rather than calling `WebviewWindowBuilder` from a command.
3. *T-007 provides "Open from a toast".* Refuted: T-007 is the core Notifier only (#274). T-210's toast carries no action (toast.rs:12). Toast activation is T-213 (TODO), and the "Transcript ready → Open emits `calls://open`" line is T-139's Acceptance (TODO). So T-142 delivers `open_calls(app, Some(ref))` as the entry those tasks call. Its test drives that entry directly. **This is missing evidence against the task's Context line "Needs T-007 (Open from a toast)".** The toast button cannot be proven here.
4. *`calls://changed` can be emitted from the shell alone.* Refuted: `Toggled` has no call id (session.rs:180-192), and max-length / low-disk / storage stops happen on the `call-tick` thread (call.rs:249-301), not on the worker. A `{root,id}` payload needs a core hook (`CallShell::changed`) at the one stop-notice path (`notice_stopped`) and at Started. Pass progress, rename and delete emits belong to T-139/T-146/T-147/T-153. They reuse the same emitter.
5. *Open folder can reuse `CallStore`'s private `open_call`.* Refuted: it returns `ioFailed` for a damaged call (no meta), but D3 / FR-033 offer Open folder on damaged rows. `resolve_call` is public but needs the default root, which `CallStore` does not expose. Hence `CallStore::folder`.

**Open design points (developer-level, no owner question):**
- *Cold-window `calls://open` race.* An event emitted right after creating the window can arrive before the page's `listen`. Recommended: hold the pending target in the call part and emit it once after the window's first `calls_list`, which the page sends only after registering its listeners (+page.svelte:155-176). Alternatives: a URL query (needs a UI change and percent-encoding of root text) or a ready command (a contract change). Record the choice in the window's decision record.
- *Threading.* The commands touch the filesystem and the export shows a modal dialog. Use `#[tauri::command(async)]` (local_models.rs precedent), and run the dialog on its own COM STA thread, never on the main thread.
- *App without a call part* (`build_app` only): commands use `try_state` and return an empty `CallList` / `notFound`. `State<Arc<CallStore>>` would refuse every invoke in tests that never call `start_calls`.

**Contract drift found (fix in the same commit):** contracts/ipc.md "Settings commands are unchanged: … (`get_settings` / `save_settings`)". The commands are `settings_get` / `settings_save` (lib.rs:56-57, settingsApi.ts:146/151).

**Size.** One task, at the upper bound. One shell seam (`call.rs` plus its window, capability and dialog adapter) and two small core additions behind it (`CallStore::folder`, `CallShell::changed`), both Linux-testable. The behaviour is settled by the spec and contract. If the orchestrator wants it smaller, the clean cut is `calls://changed` + `CallShell::changed` into its own task, ahead of T-139. Not recommended: the page already listens to it.

**Recurrence check.** `docs/failures.md` has no entry of class `call-ipc` (grep of the class and of "ACL", "capabilit", "clipboard"). The only other task of the class is T-153 (TODO, builds on this). Two adjacent entries shape the tests, not the design:
- F-018: an event from a background thread heard by a listener subscribed after the action. Subscribe first and match on `{root,id}`.
- F-031: call-session timing under load. Wait on state, not on time, through `timing_support`.

`recurrence_of: []` stays.
