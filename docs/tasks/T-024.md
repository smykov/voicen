**Pinned API (step 1, core)**, re-exported from `voicen_core::diag`. The analysis's `fill` became `record`, and its syscalls are behind a port so core can prove the whole path:
- `NativeFaultSetup { build, os, session_started, pid, seconds_east }`, with pub fields, fixed at install.
- `trait FaultFiles { create_new(&mut self, tmp, bytes) -> io::Result<()>; hard_link(&mut self, tmp, name) -> io::Result<()>; remove(&mut self, tmp) }`. Names are bare file names in the logs dir. The shell implements it with `CreateFileW CREATE_NEW` + `WriteFile`, `CreateHardLinkW` and `DeleteFileW`.
- `NativeFaultWriter: Send + Sync`, built with `new(NativeFaultSetup)` (may allocate). `record(&self, now, exception_code: u32, fault_address: usize, module: Option<(&[u16], usize)>, &mut dyn FaultFiles) -> Option<CrashFileName>` never allocates and is first-wins. Its bytes are `render_crash_file` of `kind: native_fault`, where `time` and `session_started` are both at `seconds_east`, and `fault_address` is `Frame::new(&String::from_utf16_lossy(path), off)`, or `Frame::new("", fault_address)` when the module is unresolved. The tmp is `<first stem>-native_fault.tmp`. On `create_new` AlreadyExists: no link and no remove. On any other create error: remove. Links step up to 60 names, the pid kept; AlreadyExists goes to the next name, any other link error stops. The tmp is always removed after linking.

**Pinned API (step 2, shell):** `voicen_lib::diag::begin_session(PathBuf, &Arc<Log>) -> voicen_lib::diag::SessionEnd` (managed by the app; `on_run_event`'s `RunEvent::Exit` arm ends it once) and `voicen_lib::diag::os_version() -> OsVersion`.
