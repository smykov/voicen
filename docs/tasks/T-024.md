## Investigation

Tools: Serena and Context7 were not used (not connected in this session); context came from grep and file reads, the locked crate sources in `.teamwright/cache/core/` (tao 0.37.1, tauri-runtime-wry 2.12.1, tauri 2.12.1, windows 0.62.2), and two throwaway `rustc` probes in `voicen-rust:1.99` (container `/tmp`, outside the repo).

**What exists vs what is left.** T-008 is done and reused: the one `Log` (`src-tauri` `diag::start` writes `Started` first), the `Clock` + `LocalOffset` ports, `OsLocalOffset`, `BuildInfo`, the closed `LogEvent`, and log retention that touches only `voicen-*.log`. That retention is already pinned by `tests/diag_log.rs` `plant_foreign` (a 20-day-old `crash-*.txt`, the marker and the note survive). So the "20 days old survives rotation" half of Acceptance line 3 already holds for the log side; T-024 adds the 30-day / 20-file crash retention. Missing: `diag::session`, `diag::crash`, the `PreviousSession` / `Exited` events, `OsVersion`, the hook, the filter, the shell wiring, the NSIS note, and the CI crash checks. T-025 handed the `installer-ended` note and the crash smoke to T-024 (T-025 Investigation item 5), and T-026 handed over the symbols zip.

**Detection, per kind.**
- *Panic*: a `std::panic::set_hook` hook installed by the shell after `diag::start`. Release keeps `panic = "abort"`, and the hook runs before the abort. It reads `PanicHookInfo::location()` and `thread::current().name()`, never the payload. The hook must not call `Log::write`: `log.rs:155-158` takes `Mutex::lock()`, so a panic inside the writer would relock the same mutex on the same thread. R5's `crash_file_written` line is therefore dropped. The next start's "previous session crashed" line is the trace (FR-013(a)).
- *Backtrace*: R5's `std::backtrace::Backtrace` cannot produce `<module>+0x<offset>` on stable Rust. The probe showed `frames()` is E0658, and stripped output has no addresses. Replacement: a core `FrameSource` port, filled on Windows by `RtlCaptureStackBackTrace`, and resolved by `GetModuleHandleExW(FROM_ADDRESS)` + `GetModuleFileNameW`. These are `windows` 0.62.2 feature flags (`Win32_System_Diagnostics_Debug`, `Win32_System_LibraryLoader`), so no new crate is needed. The `backtrace` crate would need consent (not in #9) and is not proposed.
- *Native fault*: `SetUnhandledExceptionFilter` in `win/crash.rs`. It writes a `native_fault` file from a buffer and wide path built at install time. It uses `RtlPcToFileHeader` / a fixed-size `GetModuleFileNameW` for the module and offset, and makes no allocation. It returns `EXCEPTION_CONTINUE_SEARCH`. Stack overflow, `__fastfail` and OOM aborts never reach the filter; the marker covers them at the next start. Rust's panic abort on Windows is expected to be a fail-fast that bypasses the filter, so a panic gives exactly one file. Not proven: the Windows child-panic test must assert exactly one file. Also not proven on the installed app: that no in-process library replaces the filter later. Install it last, after tauri `build()`; this is a residual risk with no shipped trigger to test it.
- *Abnormal end*: `logs/session.marker` (pid, started, version, commit), written atomically (tmp + rename) by `Session::begin` in `release_parts`. Only a primary reaches that point: the single-instance plugin exits a second instance inside `build()` (T-052 invariant 1). Classification follows R7. One change: the installer note is judged by its file mtime against the marker's `started`, so NSIS does not have to write an offset timestamp. Order at start: `begin` (which may add an `abnormal_end` file), then `retain_crash_files`, so the 20-file cap holds after start.
- *Clean exits (NFR-07 v4)*: tao 0.37.1 handles `WM_ENDSESSION(TRUE)` in its event-target window. It synchronously emits `LoopDestroyed`, which tauri-runtime-wry maps to `RunEvent::Exit`, and then calls `process::exit(0)`. Tray Exit (`app.exit(0)`) ends in the same `RunEvent::Exit`. So one call in `on_run_event` covers both clean exits (P-011). No subclassed 001 window is needed, contrary to R7 and T026's "tray Exit and WM_ENDSESSION handlers". The installer close goes through the `installer-ended` note: the PRE hooks run before `CheckIfAppIsRunning` (`installer.nsi:619-623`, `756-760`). Whether that macro kills the process or closes it is not visible in the repo (`utils.nsh` ships with tauri-bundler). The note works either way. Proposed: write the note only when `voicen.exe` is running, so an install after an unrelated kill does not hide that crash.

**Linux core vs Windows CI.** Linux gate (core, fakes, temp dir, `FakeClock`): marker classification (all R7 cases plus a corrupt marker), crash rendering per kind (allowlist and order), payload never written, hook re-entry, unwritable dir, crash retention. Windows CI only: the real hook with Win32 frames, the exception filter (access violation → `0xC0000005`), `RunEvent::Exit` deleting the marker, a second instance leaving the marker alone, the NSIS note, and the installed-app smoke. For a real shutdown, send `WM_QUERYENDSESSION` / `WM_ENDSESSION(TRUE)` to the app's `Tao Thread Event Target` window (the class is listed in `scripts/ci/helper-windows.txt`). Proposed proof technique: the shell test re-runs its own test exe as a child (env var + `--exact … --ignored`) instead of R6's `crash_probe` bin behind a feature. A new bin target would change `scripts/ci/shell-targets.txt` and its `make check-shell-layout` pins. The smoke already kills every launch (`installer-ci.md` note, T-014/T-037), so each kill now leaves an `abnormal_end` file. Crash checks must count new files per step, not the total.

**Dependencies.** No new crate: only `windows` 0.62 feature flags (`Win32_System_Diagnostics_Debug`, `Win32_System_LibraryLoader`, `Wdk_System_SystemServices` + `Win32_System_SystemInformation` for `RtlGetVersion`). Precedent: #9 and the Cargo.toml comment "feature flags only, no new crate". No owner consent needed. No minidumps (R5, FR-014: a dump holds memory, audio and keys).

**Owner question (proposed OQ).** Symbols for panic backtraces. FR-014 says "the matching symbol files are kept by CI with each build", but #119 allows only the tag-run installer artifact, and the release job and upload step are byte-pinned fragments (`release-job.yml`, `release-upload.yml`, `make check-release-guard`). Options:
- (a) Build the PDB on every ref; attach `voicen-<version>-symbols.zip` to the GitHub Release on `v*` tags only. Requires editing the pinned fragments and `release.sh`. **Proposal.**
- (b) Per-commit symbols artifact. Reopens #119's quota risk.
- (c) Keep no symbols in release 2. Crash files then carry module + offset only, and FR-014's symbols sentence is amended.

Separately, the release-profile change (`debug = "line-tables-only"`, `split-debuginfo = "packed"` with `strip = true`) must be confirmed on the runner to still produce a PDB and keep the installer size (R5 "confirm on Windows").
