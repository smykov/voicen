**Order at start (T-060 T-100 r2#2, decided here).** `diag::start` → `RtlGetVersion` → `Session::begin` → `install_panic_hook` → filter → `retain_crash_files`. Three facts force `begin` before the hook:
- `CrashContext.session_started` is `Session::started()`. A hook built before `begin` cannot carry the link that makes the next start say `Crashed` instead of writing a second record.
- `begin` deletes every `crash-*.tmp` (`crash.rs:439-452`), so a hook already writing during `begin` would lose its file.
- `begin` is panic-free by construction, and T-100 tests it.

Cost: a panic before `begin` returns (tauri `build()`, `diag::start`, `begin`) leaves no record of this session. The previous marker is left untouched, so the previous session's verdict is not lost. The single-instance decision happens inside `build()`, so `begin` cannot move earlier anyway (T-052 invariant 1).

**The native-fault filter (T-060 T-100 r2#3).** Spec T026 says no allocation in the filter. A fault with the heap lock held, or with a corrupt heap, would otherwise hang or re-fault instead of ending. So the filter cannot call `write_crash_file`. Proposal: core gains a `NativeFaultWriter`, built at install from `CrashContext`-like inputs. It holds:
- the rendered head (`kind: native_fault` … `session_started:`);
- a fixed-capacity tail buffer;
- the offset fixed at install (`OsLocalOffset` calls `SystemTimeToTzSpecificLocalTime`, which is not safe to call from a filter);
- a first-wins `AtomicU8`.

`fill(now, code, fault: Option<(&[u16] module path, offset)>)` writes the tail without allocating (no `String` growth past capacity) and yields the bytes and the candidate names: the same 60-second stepping and the same pid as `write_crash_file`. The shell filter (`unsafe extern "system" fn(*const EXCEPTION_POINTERS) -> i32`) keeps its state in a `static`, not on the faulting thread's stack, which may be nearly exhausted. It reads `ExceptionCode` and `ExceptionAddress`. It finds the module with `RtlPcToFileHeader` (`Debug/mod.rs:774`) and `GetModuleFileNameW` into the static `[u16]`. It does `CreateFileW(tmp, CREATE_NEW)`, `WriteFile`, `CreateHardLinkW` per candidate (`FileSystem/mod.rs:401`; fails on an existing name, the T-100 no-replace rule) and `DeleteFileW(tmp)`. It returns `EXCEPTION_CONTINUE_SEARCH`, so WER and the exit code stay Windows'. Core proves byte-equality with `render_crash_file` and zero allocations (counting allocator, own test binary). `contracts/core-diag.md` "Crash files" names it as the second writer.

**Locks.** The contract says the hook's ports "must not lock either" (`contracts/core-diag.md` "Crash files" guarantees). No Win32 unwinder or module lookup meets that literally: `RtlCaptureStackBackTrace`, `GetModuleHandleExW` and `GetModuleFileNameW` take OS loader / function-table locks, and the hook already allocates (heap lock). Proposal: reword it to "no Voicen lock" and record the residual: a crash while another thread holds the loader lock and is itself stuck waits on it. This is agent-decidable, with the reviewer.

**Clean exits.** Facts unchanged from the pre-split analysis and re-read: tao `event_loop.rs:2332-2343` calls `loop_destroyed()` then `process::exit(0)` on `WM_ENDSESSION(TRUE)`, and `tauri-runtime-wry` `lib.rs:4131` gives `RunEvent::Exit`. `tray.rs:418` `app.exit(0)` passes `on_run_event`'s `ExitRequested { code: Some(_) }` and also ends in `RunEvent::Exit`. Design:
- `wire` manages a `SessionEnd` holding `Mutex<Option<(Session, Arc<Log>)>>`. A lock is fine here: this is not the crash path.
- `on_run_event` gets a `RunEvent::Exit` arm: `app.try_state::<SessionEnd>()`, then `take()`, then `end_clean`.
- Its signature is unchanged, so `tests/lifecycle.rs:208` and `tests/overlay.rs:269` compile as they are. In tests that do not manage it, nothing happens.

**Installer note.**
- Today `installer-hooks.nsh` has no `NSIS_HOOK_PREINSTALL`, and `NSIS_HOOK_PREUNINSTALL` (`:39-72`) writes nothing. The PRE hooks run before `CheckIfAppIsRunning` (`installer.nsi:619-623`, `756-760`).
- A reinstall (`/P`, decision #76 `PageLeaveReinstall`) runs the installed uninstaller first. Its `CheckIfAppIsRunning` closes the app before the new installer's PREINSTALL runs, so the note must also be written by PREUNINSTALL, in every mode, before the purge block.
- Rule (invariant 5): write `$LOCALAPPDATA\Voicen\logs\installer-ended` only when the logs dir exists and `voicen.exe` is running (`nsis_tauri_utils::FindProcess`, the plugin the fork already loads at `installer.nsi:246/434`; confirm its return convention). The note's content is not read; this also fixes the T-060 T-100 r1#5 drift (the old text said "the marker's `started`").
- The first upgrade from a pre-T-024 build has no marker, so it is `Clean`. The old uninstaller lacking the hook does not matter.
- Residual: an install cancelled after the note was written, followed by a kill, reads as `EndedByInstaller`.
