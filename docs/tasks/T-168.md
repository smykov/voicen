## Investigation

Tools: Serena `get_symbols_overview` on `failure.rs` and `post_process/mod.rs`. `find_referencing_symbols` on `SkipReason::from_failure` returned nothing (index miss), so callers and the rename blast radius come from grep over the whole repo, excluding `target/`, `node_modules/` and `.serena/`.

- **What `classify` produces** (`failure::classify`): `InvalidApiKey`, `ServerError`, `NetworkUnavailable`, `CannotReach`, `Timeout { origin: Server }`, `UnexpectedResponse`. `post_process::chat::ChatPostProcessor::process` is the only production caller of `SkipReason::from_failure`, so on this path `KeyStoreUnavailable` (the chat reads the key as "no key", research R5), `EngineNotConfigured` (that case returns `SkipReason::NotConfigured` directly), `ClipboardUnavailable`, `MicrophoneUnavailable`, `NoLocalModel`, `LocalEngineFailed` and `Timeout { origin: Builtin }` cannot reach it.
- **Keep the arms or remove them:** keep them. Rust needs a total match, and the only ways to drop the arms are a `_ =>` wildcard (a new variant would get a silent default, which is the gap this task closes), `unreachable!()` (a panic in the product), or a narrower return type from `classify`. The last one is a real fix but crosses seams: `classify` is also used by `engine::openai`, the local server and `connection_test`. The sibling `connection_test::from_failure` already keeps the same arms with "kept total" comments, so (A) keeps the two mappings alike.
- **Coverage check:** `failure::tests::every_reason` already lists each variant once, with both origins, and an exhaustive-match guard. Exposing it as `#[cfg(test)] pub(crate)` (in `failure.rs`, outside the private test module) lets the post-processing table iterate it. A new variant then fails to compile in `every_reason` until it is listed, and once listed the table test fails until it has a row.
- **Display wording:** "did not finish in time" (the T-106 review's suggestion) names no subject, so it fits the API, local server, post-processing, connection test and built-in origins. The text reaches no user and no log: overlay and IPC render `message_id()`, the log writes `code()`, and `diag` takes no `FailureReason` (`diag/mod.rs` header).
- **Wire and serde check for the rename:** neither `TimeoutSource` nor `FailureReason` derives `Serialize`. `Debug` prints variant names only (`Timeout { origin: Server }`), so the redaction tests' `{r:?}` output does not change. There are no occurrences in `src/`, `e2e/`, `src-tauri/` or `crates/voicen-whisper/`.
- **Recurrence:** `docs/failures.md` has no failure-taxonomy, Display-text or exhaustive-mapping class (F-005, F-013 and F-021 mention `Timeout` only as a timing outcome). `git log` on `failure.rs` and `post_process/mod.rs` shows no earlier patch of this kind. Not a recurrence.
- **Size:** small. There is one seam (the core failure taxonomy in `failure.rs` plus its consumer's table test), no behaviour change and no product question. No spec is needed.
