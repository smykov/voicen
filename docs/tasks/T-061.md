## Context

Cut from T-025 by decision #76. The uninstall hook (T-025) removes the user's keys by running `voicen.exe --purge-credentials`. Today the targets are built in `voicen_core::secrets::KeySlot::target_name` (`Voicen/transcription-api|local-server|post-processing`, secrets.rs:50-56) with no shared prefix constant, and `main.rs` only calls `voicen_lib::run()`. Add `CREDENTIAL_TARGET_PREFIX` beside `KeySlot::target_name` (every slot's target starts with it), and handle `--purge-credentials` in `main.rs` before `run()`: enumerate `Voicen/*` (`CredEnumerateW`) and delete each (`CredDeleteW`), exit 0 on success / 2 on failure, no window, no log of key material (FR-20, NFR-04). `WinCredentialStore` (src-tauri/src/credentials.rs) already takes a test prefix.

## Acceptance

- [ ] Core: every `KeySlot` target starts with `CREDENTIAL_TARGET_PREFIX` (Linux gate)
- [ ] Windows CI: with test entries under the prefix and one outside it, `--purge-credentials` removes exactly the prefixed ones, exits 0 and opens no window
- [ ] Failure branch: no entries → exit 0; a delete that fails → exit 2, the remaining entries untouched, nothing logged with key text — Windows CI
- [ ] Test that fails without the change: the core prefix test and `src-tauri/tests/purge_credentials.rs` (Windows CI)

## Investigation

**Frame.** Expected (spec 006 FR-021, FR-022; contracts/installer-ci.md "`voicen.exe --purge-credentials`: exit 0 = all entries with the prefix removed (or none existed); 2 = at least one failed. No window, no log, no marker"; contracts/ipc.md `main()` row: before Tauri and single-instance): the uninstaller hook (T-025) runs the installed exe with `--purge-credentials` and every `Voicen/*` Credential Manager entry is gone. Observed: `main()` is `voicen_lib::run()` only, which builds tauri (single-instance plugin, log, settings, tray, possibly the first-run settings window); the three targets are bare literals in `KeySlot::target_name`; nothing in the tree calls `CredEnumerateW` (grep over `src-tauri/` and `crates/`). This is a feature gap; nothing is broken today.

**How I looked.** Serena tools were not callable in this session; facts come from grep and reads of `crates/voicen-core/src/secrets.rs`, `src-tauri/src/{main,lib,credentials,autostart}.rs`, `src-tauri/tests/credentials.rs`, `src-tauri/Cargo.toml`, `docs/decisions/windows-shell.md`, spec 006 (spec.md FR-021/022, contracts, research R10, plan), T-025 Investigation. The Win32 signatures were read from the pinned `windows-0.62.2` source in a worktree's cargo cache (`src/Windows/Win32/Security/Credentials/mod.rs`): `CredEnumerateW(filter, Option<CRED_ENUMERATE_FLAGS>, *mut u32, *mut *mut *mut CREDENTIALW) -> Result<()>`, `CredDeleteW(target, CRED_TYPE, Option<u32>)`. context7 was not used (the pinned crate source is the authority).

**Hypotheses.**
1. *A prefix already exists somewhere* - refuted: grep `Voicen/` finds only the three literals in `target_name` and test copies.
2. *A second path writes or deletes credentials* - checked: `WinCredentialStore` is the only writer (`target = prefix + slot.target_name()`); tests use `voicen-test-<pid>-<n>-<nanos>/` prepended, so their targets are `voicen-test-.../Voicen/...`. The purge must use the same composition (store prefix + `CREDENTIAL_TARGET_PREFIX`), which also makes it testable without touching the user's real entries.
3. *Purge through the normal start path (`run()`)* - rejected: it would hit the single-instance plugin (a running app would swallow the call and exit 0 = false green), open the log and possibly a window. `docs/decisions/windows-shell.md` "No process touches the log, the data dir, the Run value or a window before tauri's build()" is respected only if the branch returns before `run()` and touches nothing but Credential Manager.
4. *This class was fixed before* - no: `docs/failures.md` F-001..F-005 are CI link / test-port classes; the only `class: installer` tasks are T-025, T-061, T-062 (siblings from decision #76). F-002 matters indirectly: spawning the test-profile bin from an integration test is avoided below for a different reason (it would purge the developer's real keys), not for linking.

**Design facts the developer needs.**
- `CredEnumerateW` with filter `<prefix>*` (flags `None`; `CRED_ENUMERATE_ALL_CREDENTIALS` requires a null filter, so never set it). No match fails with `ERROR_NOT_FOUND` -> empty list, exit 0. The returned array holds the blobs too: copy only `TargetName` and `Type`, wipe each blob (the `wipe` helper pattern of `credentials.rs`) and `CredFree` the array once. Delete with each entry's own `Type`. `ERROR_NOT_FOUND` on delete (raced away) counts as removed.
- Defence in depth: the policy re-checks `target.starts_with(prefix)` before deleting, so filter semantics (wildcards, case) can never widen the scope. **Confirm on Windows** whether the filter is case-insensitive; harmless either way, since the app writes only the exact `Voicen/` case.
- No new crate or feature: `Win32_Security_Credentials` is already enabled for `windows 0.62`.
- Arg detection: mirror `autostart::launched_by_autostart` (any arg equals the constant), as a pure fn `purge_requested(args)`.
- Exit: `std::process::exit(code)` from `main()`. The release exe is `windows_subsystem = "windows"`, so no console either; the path writes nothing to stdout/stderr and never calls `diag::start`.

**How the test reaches the purge without an installed exe.** `voicen_lib::win::purge::from_args(args, store_prefix) -> Option<i32>` (None = not a purge call) is the one entry; `main()` is `if let Some(code) = from_args(std::env::args_os(), "") { std::process::exit(code) } voicen_lib::run()`. `src-tauri/tests/purge_credentials.rs` calls `from_args(["voicen.exe", "--purge-credentials"], <unique test prefix>)` against real Credential Manager: plants two entries under `<test>Voicen/...` and one outside (e.g. `<test>VoicenOther/x`, plus one under a second unique prefix), asserts exit 0, the two gone, the outsiders intact (raw `CredReadW`, guard deletes leftovers, as `tests/credentials.rs` does); then a second call with nothing left -> 0. Spawning `CARGO_BIN_EXE_voicen` is rejected: the bin has no prefix override (an env override would be a production switch able to widen the scope), so it would purge the developer's real `Voicen/*` keys on any Windows machine.

**How "opens no window" is proven.** (1) Structurally: the branch is in `main()` before `run()`, so no `tauri::Builder` exists; the lib tests run without a tauri runtime. (2) On the deployed exe, one step in the `windows` job (P-006: the installed commit): with no Voicen process running (`Stop-Process` the smoke instances first, else a missing branch would hit single-instance and exit 0 = false green), `cmdkey /generic:Voicen/ci-purge-a`, `.../ci-purge-b` with fake values and `cmdkey /generic:VoicenOther/ci-keep`; `Start-Process "$env:LOCALAPPDATA\Voicen\voicen.exe" --purge-credentials -PassThru -RedirectStandardOutput/-Error`, `Wait-Process -Timeout 15`: must have exited with 0 (without the branch the app starts, stays in the tray and never exits -> red), the two gone, `VoicenOther/ci-keep` present (then removed), both output files empty and free of the fake values, the log file unchanged (size/mtime). A second run -> exit 0. Optionally sample `scripts/ci/visible-windows.ps1` for the pid while it runs; the exit-in-time check is the decisive one.

**Failure branch.** A real `CredDeleteW` cannot be made to fail on demand, so the policy lives in core over a small trait (list(prefix) -> entries {target, kind}; remove(entry) -> Result<(), CredentialError>), no blob in the trait. Linux tests with a fake: one remove fails -> exit 2, every other entry still removed, the failed one kept; list fails with anything but not-found -> 2; empty -> 0; an entry outside the prefix returned by list -> not removed; the fake's call log shows remove only for prefixed targets. The Windows test wraps the real adapter with a remove that fails for one planted target -> 2, that entry present, the other gone. **Reading of the Acceptance line:** "the remaining entries untouched" is taken as "the entry whose delete failed stays, entries outside the prefix stay"; the purge continues after a failure (contracts: "2 = at least one failed"; FR-022: the user then removes the listed entries by hand, so fewer is better). Orchestrator can settle the wording; no owner question.

**Options.**
- **A (recommended): core constant + core policy + shell adapter + main branch + one CI step.** Removes the gap at the one seam the app and the uninstaller share (FR-022, P-010); the failure branch is red/green on the Linux gate. Risk: a new core trait (small). Rollback: revert; T-025 hook then has nothing to call.
- **B: everything in the shell** (constant in core only; policy and fault injection in `src-tauri`). Fewer types, but the failure branch is proven only on Windows CI and the policy is untestable locally.
- **C: purge per `KeySlot::all()` via `WinCredentialStore::delete`** (no enumeration). Rejected: misses entries of removed or renamed slots and older versions (FR-021 "every Voicen entry"); contradicts the contract's `CredEnumerateW(prefix*)`.

**Red tests first.** Core: `every_slot_target_starts_with_prefix` (compile-red without `CREDENTIAL_TARGET_PREFIX`; also asserts the prefix is `Voicen/`, so a rename is caught), `purge_*` policy tests (compile-red without the policy). Shell: `src-tauri/tests/purge_credentials.rs` (compile-red without `voicen_lib::win::purge`; `#![cfg(windows)]`, no `#[cfg(test)]` in `src-tauri/src`). CI: the installed-exe step (red: the exe never exits, entries stay).

**Doc drift to fix in the same commit.** specs/006 tasks.md T028 and contracts/core-diag.md place the constant in `voicen_core::diag::credentials`; the task and decision #76 place it beside `KeySlot::target_name` in `voicen_core::secrets` (the slots own the naming; recommended). Update core-diag.md:152 and the T028 line. Add to `docs/decisions/windows-shell.md` (invariant "nothing before build()") that `main()`'s `--purge-credentials` branch exits before `run()` and touches only Credential Manager. Note for T-025: PREUNINSTALL runs before the stock code closes the app, so a running app could re-write a key after the purge only on a settings save; T-025 should close the app before the hook runs the purge, or accept that.

**Size.** One concern (Voicen's credential namespace and its removal): core `secrets`, one shell file plus `main()`, one test file, one CI step. Not large, no owner decision. The CI step edits the same `windows` job T-025 will extend; T-025 depends on T-061, so land T-061 first.

**Recurrence:** none (F-001..F-005 are other classes; no earlier `class: installer` fix). **Recommended exit:** n/a (feature).
