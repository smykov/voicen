## Investigation

Tools: Serena (`get_symbols_overview` on diag/format.rs, event.rs, observer.rs; `find_symbol` with bodies for `DictationLine`, `write_dictation`; `find_referencing_symbols DictationLine` returned nothing, so constructors were found with grep over crates/, src-tauri/, src/, e2e/). Grep for the ci.yml matchers, docs/failures.md and docs/decisions/diagnostics-log.md.

**Frame.** Seen: a recording ended by microphone loss (T-012) or by sleep (T-010) writes the same dictation line as a normal release; nothing in the line says how the recording ended. Wanted: one closed `end=` value per way a recording hands its audio to a job. T-118 (the precondition) is DONE.

**Hypotheses.**
1. The observer drops `RecordingEnded.end` after using it to pick the closing event. Confirmed: in `Open::apply` the RecordingEnded arm stores only `duration_ms`; `Record` has no end field.
2. The end is lost before the observer (emitters send `Released` for every end). Refuted: `dictation.rs` `esc_pressed` sends `Cancelled`, and the stop path sends `ticket.end()` / `Ended::Dropped.end`; recording/mod.rs test `release_end_is_too_short_for_a_discard_and_released_for_a_stop` pins the controller's ends.
3. A second path writes dictation lines. Refuted: `LogEvent::Dictation` is built only in `Record::line` (observer.rs) in production; the other constructors are tests and doctests (diag/mod.rs, tests/diag_log.rs, tests/diag_format.rs).
4. Fixed before. No: docs/failures.md has no diag-grammar entry; diagnostics-log.md line 55 records leaving out `end=` as deliberate (T-012, T-010), and #201 reverses that.

**Scope note, set `Suspended`.** T-012 r1#1 and #201 list four values (released / toggled / max_length / device_lost) "for every way a recording ends in a job". `Suspended` (T-010) came later and also ends in a job (observer.rs groups it with `DeviceLost`). Without it a sleep-ended recording would look like a release again, the same gap. I recommend `suspended` as a fifth value under #201's "every way" wording. The reviewer should confirm that. It is not a blocker. If the owner reads #201 as only the four values, `Suspended` would map to no key, and that would need a new decisions row. `TooShort` and `Cancelled` close their record themselves and already appear as `outcome=too_short` / `outcome=cancelled`, so they write no `end`. That keeps the closed set to job ends only, which the Acceptance failure branch asks for ("a value outside the closed set cannot be written").

**Key position.** The key goes after the outcome-specific keys (`result` / `failure` / `http_status` / `mic`) and before `detector=`. Never between `dictation` and `rec=`: the install smoke's matcher `$recLine = 'dictation rec='` (ci.yml lines 886 and 958) relies on that, and `dictation outcome=blocked` lines have no record. On a capture failure at stop (`RecordingEnded{Released}` and then `CaptureFailed`), the line gets `end=released`. That is true: the hold was released. It works the same way as `duration_ms`, which travels in the record whatever closes it.

**FR-20 / NFR-04.** `EndTag` is a `Copy` enum written through a `&'static str` table. It carries no text, audio or key. `diag_pipeline.rs` `log_holds_no_key_query_or_transcript_on_any_path` keeps covering this.

**Options.**
- A (recommended): `diag::event::EndTag` (5 variants, no `Other`, no `from_str`). The observer maps it from `RecordingEnd` with an exhaustive match: a new `RecordingEnd` variant does not compile until it has a mapping, as diagnostics-log.md already requires. Red tests are listed in `approach`. Risk: tests that compare exact lines for job-closed records must gain `end=`. That is intended churn. Rollback: revert the one commit.
- B: put `recording::RecordingEnd` itself into `DictationLine`. Rejected: `too_short` and `cancelled` would become writable `end` values, the type would not stop a value outside the set, and diag would depend on the controller's enum shape.
- C: write `end=` only for ends other than Released. Rejected: a missing key would mean both "released" and "no RecordingEnded came" (a job with no recording events), which breaks the "None means the event did not come" rule of the data model.

**Docs drift in the same commit.** format.rs module doc: the start sample becomes `... started pid=4242 os=10.0.26100` (T-105 r1#1), and one dictation sample shows `end=`. Also update docs/decisions/diagnostics-log.md (line 55's "with no `end=` pair of its own", for both T-012 and T-010), specs/006 data-model.md DictationLine table, contracts/core-diag.md Pipeline observer paragraph, and a decisions.md row (#201 asks for one on implement).

**Size / blocker.** One seam in core (diag grammar). Linux gate only, no Windows-only code, not large. No blocker. Only open point: the reviewer confirms `suspended` under #201.
