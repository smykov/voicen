## Context

Second half of T-210, split off by the owner (decision #279). T-210 ships the shell toast notifier (toast thread, sink port, toasts without a Retry button), the core `PendingId` toast-argument codec, the tray Retry arm and the logs-folder notice. This task adds what makes a Retry button on the toast work. A desktop toast button with no activator does nothing, so the button lands only here.

The T-210 analysis is the starting point: `## Investigation` › Size ("New (toast Retry)"), "Seam details and residual risks" (NSIS COM write through `System::Call`, upgrade path in `NSIS_HOOK_POSTINSTALL`, test isolation of the per-process CLSID registration), and its invariants I6 (every Retry input reaches core only as `DictationSession::retry`; the toast argument is `retry:<id>` only, parsed by the one core codec) and I7 (every install leaves the shortcut's `ToastActivatorCLSID` and `HKCU\Software\Classes\CLSID\{C}\LocalServer32` pointing at this `voicen.exe`; every uninstall that removes the program removes both).

- COM activator: `INotificationActivationCallback` registered with `CoRegisterClassObject(CLSCTX_LOCAL_SERVER, REGCLS_MULTIPLEUSE)` on T-210's toast thread; `Activate` copies the args, stamps the instant and hands off with `spawn_blocking` to `session.retry(at, Some(id))`. A stale or malformed id runs nothing.
- The toast gets the `action.retry` button only when the offer carries `retry = Some(id)`.
- `LaunchArgs` reads `-Embedding` as a no-window second launch (TrayOnly). A cold activation (app not running) only starts the app: the pending audio is gone by FR-032.
- Installer: `installer-hooks.nsh` only (the fork diff stays unchanged; no line with the token `rmdir`). One CLSID: a Rust const and one `!define` in the hooks, pinned equal by a shell test.
- FR-20 / NFR-04: the toast argument is `retry:<id>` only; no OS text in logs.
