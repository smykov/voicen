## Context

Split out of the T-086 audit (decision #124). `scripts/ci/shell-test-layout.sh` with its `.awk` makes sure every Windows test exe of `voicen` gets the Common-Controls manifest (F-002). Half of it conforms: the switch `doctest = false` and the tokens `--doc`/`rustdoc`. The other half is an awk Rust lexer and a TOML header tracker, and it leaks:
- R1: a `macro_rules!` that builds `#[cfg(test)]` / `#[test]` from an ident fragment. The guard exits 0, and `rustc --test` built and ran it.
- L1: `cargo test --d"oc"` in a `run:` line. bash joins the quoted word into `--doc`.

The proposal names two ways and leaves the choice to the investigation:
- `test = false` on the lib and bin targets. Whether `--lib` / `--all-targets` override it must be read from the cargo 1.99 source.
- Comparing cargo's own unit list (`--message-format=json` for `x86_64-pc-windows-gnu`) with an owned set.

The workflow half needs a pinned literal test invocation, not a token search. This is the largest of the rewrites, so it gets its own investigation.

## Investigation

Context tools: Serena MCP tools were not available in this session; grep and file reads were used. cargo 1.99 source read through `gh api repos/rust-lang/cargo/contents/...?ref=rust-1.99.0` (copies in `/tmp/t092src`). ### 1. Frame

- **Protects:** F-002. Only `kind: test` targets get `cargo:rustc-link-arg-tests` (the Common-Controls manifest); the bin gets tauri-build's `-bins` args in any mode (`custom_build.rs:266-277`, `LinkArgTarget::Bin => target.is_bin()`). The exes left uncovered are the lib unit-test exe, lib doctests, examples and benches.
- **Observed:** the guard passes R1 and L1. Re-run at 198db1c on copies of `fixtures/shell-test-layout/ok-current-shape`: R1 appended to `src/lib.rs` gives exit 0, and L1 `cargo test --d"oc" -p voicen` in `workflows/ci.yml` gives exit 0. In T-086 §2, `rustc --test` built and ran R1.
- **Today's shell:** `cargo metadata --no-deps` reports `voicen_lib test=true doctest=false` and `voicen (bin) test=true`. So `cargo test -p voicen` (`ci.yml` windows job) builds the lib unit-test exe on every run. Only the lexer stands between a macro-built test and that exe.

### 2. Hypotheses

1. **Grammar model (confirmed).** The pass comes from awk's reading of Rust before expansion and grep's reading of bash before quote removal (the F-003/F-015 mechanism). Confirmed by R1 and L1.
2. **`test = false` alone closes it (refuted).** cargo 1.99 `unit_generator.rs`:
   - `:431`: `--lib` takes every `Target::is_lib`, with no `tested()` check;
   - `:483-488`: `--bins`/`--bin` take every `Target::is_bin`;
   - `:467-470`: only `--tests` (`FilterRule::All`) filters on `Target::tested`;
   - `compile_filter.rs:159-168`: `--all-targets` is `lib: Default, bins: All`.

   Probe `p`: with `test = false`, `cargo test --lib`, `--bins` and `--all-targets` still build both unit-test exes. Plain `cargo test` and `--tests` do not.
3. **A cargo unit list closes it (refuted as the deciding signal).** `--unit-graph` is unstable (`command_prelude.rs:824-826`, `fail_if_stable_opt`). `--message-format=json` describes one invocation (the gate's, not the workflow's), and R1 is about what an exe holds, not which units exist. `cargo metadata --no-deps` (stable, offline, no build) gives the target switches and is enough.
4. **Second path.** The workflow is a second path to the same exes (any selector, any spelling: L1). A literal pin of the workflow's test invocation cannot stop another step spelling `--lib` through bash quoting. That is YAML/bash text, the exposure T-088 is blocked on. The path is closed only if the compiler makes every selector harmless.
5. **Fixed before.** This guard is F-003's guard. Its doc half was replaced by switches in T-038. This task applies the same exit to the remaining half.

### 3. Evidence: the compiler switch

Probe `c` sets line 1 of `lib.rs` to `#![cfg(not(any(test, doctest)))]` and line 1 of `main.rs` to `#![cfg(not(test))]`, with `[lib] test = false, doctest = false` and `[[bin]] name = "c" test = false` (no path; metadata still reports `src/main.rs`). Planted in the crate: R1, a plain `#[test]`, a crate doctest, an item doctest, and a `#[macro_use]` dependency.

| Command | Result |
|---|---|
| `cargo test` | `tests/it.rs` only, 1 passed |
| `cargo test --lib` / `--bins` / `--all-targets` | unit-test exes run **0 tests**; no planted panic |
| `cargo test --doc`, `cargo rustdoc --lib -- --test`, L1 `cargo test --d"oc"` | **0 doctests** |
| `cargo check`, `check --tests`, `build`, `doc --no-deps`, run the bin | unchanged (the bin prints its value) |

`harness = false` still passes `--cfg test` (`compiler/mod.rs:1434-1449`), so the pin covers it too (probe `h`). `cfg` is a builtin attribute applied before name resolution, so user code cannot shadow it. Line 1 has nothing before it. No later attribute can turn a false crate cfg true, because cfgs are ANDed.

**Rejected loud variant (`compile_error!` under `cfg(test)`):** five probes pass silently:
- `s`: `use m::nop as compile_error;`;
- `ma`: `#[macro_use] extern crate fake;`, even with the pin inside its own `mod pin { }`;
- `s2` and `mc`: `extern crate fake as core;` hijacks `::core::compile_error!`;
- `s3`: Cargo `core = { package = "fake", ... }`.

A macro name resolves through user code, so this variant is another model.

### 4. Root cause, invariant, seam

See the `analysis` block. Root cause in short: the deciding question (does any non-integration test exe hold shell code) is answered by rustc after expansion and by bash after quoting, while the guard answers it from raw text, and the crate leaves the lib and bin testable by every explicit selector.

What the rewrite must contain:
- **Owned files.** `scripts/ci/shell-targets.txt` holds the projection of cargo metadata's voicen targets without `kind: test` rows: custom-build `src-tauri/build.rs`, lib `voicen_lib` `src-tauri/src/lib.rs` test=false doctest=false, bin `voicen` `src-tauri/src/main.rs` test=false doctest=false. Plus two owned pin lines (or one file each).
- **Guard steps.** `tw-run core` runs `cargo metadata --no-deps --offline --format-version 1 --manifest-path src-tauri/Cargo.toml`. Host `python3 -I` with `json` prints the projection. The guard `cmp`s it with the owned file and `cmp`s `head -n1` of each crate root with its pin. A docker, cargo or python error is exit 3. The JSON is read with a real parser, not a grammar model (the same standard as `helper-windows.sh` and `nsis-fork.sh`).
- **Shell edits.** In `src-tauri/Cargo.toml`, add `test = false` in `[lib]` and a new `[[bin]]` with `name = "voicen"` and `test = false` (no `path`). Make each pin line 1 of `src/lib.rs` and `src/main.rs`; the explanatory comments go on the lines after it, and the existing "DO NOT REMOVE" comment and `windows_subsystem` attribute move to lines 2-3.
- **Removed.** `shell-test-layout.awk`; steps 1-4 of the current script; every fixture whose guarantee is now carried by the pin (see §5); the `--doc`/`rustdoc` workflow rule (`ci.yml` stays byte-identical).

| Old guarantee | Now |
|---|---|

### CI red at dd292f4

**Verdict: outside the diff.** A pre-existing race in the test `local_models.rs::deleting_the_selected_model_through_ipc_resets_the_engine_and_the_window_hears_it`. The product path is fine.

**What failed (run 38161876395 attempt 1, `cargo test -p voicen --no-fail-fast`).** The panic is at `src-tauri\tests\local_models.rs:679:5`, the assertion on `heard`, the first `settings://changed` payload the test received. It is **not** the `settings_get` view. Every earlier assertion passed: the delete result (`engineReset: true`), the empty models dir, `state_of`, `view["settings"]["engine"] == "none"` and `builtin_local.model_id == null` (lines 669–674), and `service.snapshot().engine == None` (675). So the reset was persisted and is in force. The payload the test heard was a view with `engine: "builtin_local"`, `model_id: "small"`, the state left by the test's own `w.save`. The other shell test binaries were all `ok`, 14/15 in `local_models`.

**Mechanism.** The test calls `w.save(&builtin_local("small"))` first and only then `w.changed_events()` (`listen_any`). `settings_ipc::spawn_change_bridge` emits asynchronously: `swap_and_publish` sends the snapshot to an mpsc channel, and the `settings-changed` thread later calls `app.emit(SETTINGS_CHANGED, service.view())`. `settings_save` can therefore return before the save's emit has run. If the bridge thread is scheduled after the listener is registered and before `forget_model` swaps the snapshot, the save's event (view still `builtin_local`) is the first one on the channel. `recv_timeout` takes it and line 679 fails. The bridge emits `service.view()` at emit time, not the snapshot it received. So a late save event shows `builtin_local` only if it runs before the delete's swap, and the payload fits that window exactly. The sibling tests in `settings_ipc.rs` (`changed_events()` at lines 334, 400, 486, 801) subscribe **before** any save and do not have this window. This test is the only `changed_events()` caller in `local_models.rs` (grep of `src-tauri/tests`).

**Why the T-092 diff cannot cause it.**
- `[lib] test = false` and `[[bin]] test = false` only remove the lib's and the bin's own unit-test executables. The integration test `tests/local_models.rs` is a separate crate. It links `voicen_lib` built as a normal dependency, without `--cfg test` (cargo sets `cfg(test)` only on the crate compiled as the harness). So line 1 `#![cfg(not(any(test, doctest)))]` is true there and the lib is complete. It is the same build as before the diff. If it were empty, `tests/local_models.rs` would not compile (it calls `voicen_lib::build_app`), and the reset assertions at 669–675 would not pass.
