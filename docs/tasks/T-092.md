## Context

Split out of the T-086 audit (decision #124). `scripts/ci/shell-test-layout.sh` with its `.awk` makes sure every Windows test exe of `voicen` gets the Common-Controls manifest (F-002). Half of it conforms: the switch `doctest = false` and the tokens `--doc`/`rustdoc`. The other half is an awk Rust lexer and a TOML header tracker, and it leaks:
- R1: a `macro_rules!` that builds `#[cfg(test)]` / `#[test]` from an ident fragment. The guard exits 0, and `rustc --test` built and ran it.
- L1: `cargo test --d"oc"` in a `run:` line. bash joins the quoted word into `--doc`.

The proposal names two ways and leaves the choice to the investigation:
- `test = false` on the lib and bin targets. Whether `--lib` / `--all-targets` override it must be read from the cargo 1.99 source.
- Comparing cargo's own unit list (`--message-format=json` for `x86_64-pc-windows-gnu`) with an owned set.

The workflow half needs a pinned literal test invocation, not a token search. This is the largest of the rewrites, so it gets its own investigation.

## Acceptance

- [ ] The rule decides on cargo switches pinned as literal text or on cargo's own output compared with an owned set. No Rust lexer or TOML reader is left, and its `decides_on` is named.
- [ ] Failure branch: R1 and L1 are refused, and each fixture is red against the old guard. The existing shell-layout fixtures' guarantees still hold.
- [ ] `docs/decisions/ci-toolchain.md` (shell tests, the guard table) and the CLAUDE.md "Shell tests" bullet are updated. `make check` and the Windows CI job are green.
