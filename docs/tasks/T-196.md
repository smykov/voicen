## Context

A new parallel worktree needs `.serena/project.yml` and `.serena/memories` copied from the main tree by hand before `tw-parallel.py prepare`; without them the worktree's stage sessions cannot use the context tool. `tw-parallel.py` belongs to the plugin, so the fix sits on the project side, or becomes a teamwright feedback line if the project has no seam for it. Check first whether the files should simply be tracked.

Orchestrator, at analysis (2026-11-19): option A taken. `--prepare` overwrites a worktree `project.yml` that differs from the main tree's and says so (a worktree copy is only ever autogenerated; Q2, a tooling call). The contour runner's own autogenerated config (the preflight in `teamwright-agent.yml`) is not in this task: OQ-88 asks the owner.

## Acceptance

- [ ] A worktree started with `tw-parallel.py start` passes `tw-parallel.py prepare` with no manual copy
- [ ] Failure branch: when the config is missing, `prepare` or the project's own step says so by name and the worktree is not launched
- [ ] Test that fails without the change: named under `## Tests`, or the seam is recorded as the plugin's and the feedback line drafted

## Investigation

**Tools used.** Serena and context7 were loaded but not needed. The code is in Python scripts outside the indexed languages (the kit's `tw-parallel.py`, the installed serena-agent package), so I read it with grep, sed and file reads. Serena's own behaviour was read from its installed source (serena-agent 2.1.1.dev0 under `~/.local/share/uv/tools/serena-agent`), not from memory or context7.

**Frame.** Observed: a new worktree's stage sessions get a Serena whose project config was generated in the worktree, not the main tree's config. The task's Context calls this "cannot use the context tool". More precisely, the tool works but serves the wrong language set. The workaround so far is copying `.serena/project.yml` and `.serena/memories` by hand. Expected: `start` → `prepare` → launch gives the worktree the main tree's config, or stops by name.

**Hypotheses.**
1. The untracked config never reaches the worktree, and Serena autogenerates a different one. Confirmed (below).
2. The files should simply be tracked. `.serena/project.yml` was untracked on purpose (#16: Serena rewrites it each version, which dirties the tree), so tracking it is an owner reversal. Tracking `project.local.yml` as an override is refuted, because `ProjectConfig.autogenerate` copies the template over `project.local.yml` unconditionally whenever project.yml is missing.
3. A second path handles the same concern. Confirmed: the contour runner's preflight (`teamwright-agent.yml`, `serena project index .` on a fresh checkout) autogenerates the same way. The MCP server (`--project-from-cwd`) autogenerates too, if no index step ran first.
4. This class was fixed before: no. No F-entry or task covers it. #16, #72 and #146 set the language list but say "Where it is enforced: nowhere" (context-tools.md).
5. The kit fixed it upstream: no. The marketplace `teamwright` and `teamwright-next` copies of `tw-parallel.py` have the same `INDEX` (cache only).

**Evidence.**
- Reproduction with no repo change: `git archive HEAD | tar -x -C $tmp` gives `$tmp/.serena` = `{.gitignore}`. Running serena-agent's python `ProjectConfig.autogenerate($tmp, SerenaConfig.from_config_file(), save_to_disk=False)` prints `name t196.hRxK` and `langs ['rust']`. The main tree's `language_servers` are `typescript, rust, markdown, svelte` (decisions/context-tools.md, order matters).
- Serena `cli.py::ProjectCommands.index` (the command `prepare` runs) → `get_registered_project(..., autoregister=True)` → `ProjectConfig.load`, which autogenerates when the yaml is missing (`config/serena_config.py`). `autogenerate` saves project.yml and then `shutil.copy(PROJECT_LOCAL_TEMPLATE_FILE, project_local_yml_path)`.
- Kit 0.16.2 (`.teamwright/installed.json` `@kit`) `tw-parallel.py::prepare`: copies `INDEX["serena"][0]` = `.serena/cache` only, then runs the index. `start`'s own hint is `tw-parallel.py prepare X && tw-parallel.py launch X`.
- Live worktrees T-130, T-132, T-152 and T-155: project.yml is byte-equal to the main tree's (`diff -q` silent), mode 600. These are the manual copies.

**Root cause.** See `analysis.root_cause`. It explains all the symptoms: why nothing fails visibly (autogenerate succeeds), and why only TypeScript, Svelte and specs lose symbols. It also explains why the manual copy fixed it.

**Seam and second path.** The project's seam is `scripts/tw-launch`. It is the only project entry that already wraps the kit's `tw-parallel.py` (it loads the kit module and execs `launch`), and the kit manifest does not render it, so decisions #330 does not apply. The kit's `prepare` and `start` belong to the plugin and are not edited. The contour runner (teamwright-agent.yml preflight) is a second path for the same concern. It has no main tree to copy from, so this seam cannot fix it. A closed fix there needs a committed source for the language list, which again touches #16 (Option B), and it would edit the workflow T-230, T-236 and T-237 are pinning. I recommend recording it as a follow-up task or an owner question rather than widening T-196.

**Guard paths.** The red tests belong in `scripts/ci/` (tw-launch is already tested in `scripts/ci/tw-wip-push.test.sh` section D, `make check-wip-push`). A new target would also touch the `Makefile`. So `checker: true` is needed, with `decides_on: literal` as drafted. tw-launch itself is not a guard path.

**Overlaps.**
- T-230: none. It edits ci.yml, teamwright-agent.yml, release-guard and the Makefile comment of check-release-guard. T-196 touches neither workflow.
- T-183: none. It edits ci.yml, hotkey-hold.ps1 and windows-shell.md.
- T-237: indirect only. It pins `.mcp.json` and the Serena allowlist and edits context-tools.md (its 'Not caught' line). T-196 edits a different paragraph of context-tools.md ('Serena language servers', Where it is enforced) and, if a new target is added, the Makefile `check:` line. Rebase on whichever lands first.
- Shared with T-192/T-199 history: `tw-wip-push.test.sh` section D and the gates.md 'Launch' paragraph.

**Feedback draft (teamwright, for the owner to send).** `tw-parallel.py prepare` copies only the provider's cache (`.serena/cache`) and then runs `serena project index .`. When the provider's project config is untracked (as Serena's own docs suggest for project.yml, which each Serena version rewrites), a new worktree has none. Serena then autogenerates one (name = directory, languages detected, `project.local.yml` overwritten with the template), and the worktree's sessions silently serve a different language set. Proposal: give each `INDEX` entry a list of untracked config files to copy from the main tree when absent (`.serena/project.yml`, `.serena/project.local.yml`, `.serena/memories/`). Also, `prepare` should report an error (not run the index) when the main tree has none, since the index would only autogenerate.

**Open questions (owner).**

- Q2: Should `--prepare` overwrite a worktree project.yml that differs from main's? Recommended: yes, and report it. A worktree's file is generated, never owner-tuned. The alternative is to refuse and ask.

**Recommended:** Option A (analysis.approach).
