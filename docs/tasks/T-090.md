## Context

Split out of the T-086 audit (decision #124). `scripts/ci/ci-credentials.sh` refuses raw Credential Manager tokens (`Cred*`, `cmdkey`, `vaultcmd`, ...) outside `scripts/ci/credentials.ps1`. But it passes any line whose first non-blank character is `#`.

Probe C1 leaks: `run: "echo a` / `  #\n cmdkey /list"`. YAML reads that as `echo a #\n cmdkey /list`, so bash runs `cmdkey` on the second line. The proposal is to drop the comment skip so any occurrence refuses, and to reword the comments in the scanned files.

## Acceptance

- [ ] The guard refuses each token on any line of the scanned files, comments included. It keeps no comment reader, and its `decides_on` is named.
- [ ] Failure branch: C1 is refused, and so is a token in a plain `#` comment. Each fixture is red against the old guard.
- [ ] `docs/decisions/windows-ci-runner.md` and the guard table in `docs/decisions/ci-toolchain.md` are updated. `make check` is green.

### 1. What the guard scans (cbbd337)
- Workflows: top-level `.github/workflows/*.yml` and `*.yaml`. Today that is only `ci.yml`. `.github/` has no other dir, and a local action would be an unlisted `uses` line, which release-guard R11 refuses.

- **The helper is exempt as a whole** and is the seam. It must still hold the four call names (rule 2, unchanged). It stays exempt after T-090. The two tripwire files stay exempt because they must spell the tokens (patterns, fixtures).

### 2. Old guard leaks (red baseline)
The only pass besides "no hit" is line 60: `[[ "$text" =~ ^[[:space:]]*# ]] && continue`. That line is a comment reader (P-020).

| Probe | Shape | YAML / shell | old | no skip |
|---|---|---|---|---|
| C1 (`c1/`) | `      - run: "echo a` / `          #\n cmdkey /list"` | PyYAML: `'echo a #\n cmdkey /list'`; bash on that value runs a stub `cmdkey`: `CMDKEY-RAN /list` | exit 0 | exit 1 (`ci.yml:5`) |
| c2 (`c2/`) | `run: \|` block with `# cmdkey /list` | a real comment, not executed | exit 0 | exit 1 |
| c3 (`c3/`) | `scripts/ci` `notes.sh`: `# CredWriteW in a plain comment ...` | a real comment | exit 0 | exit 1 |

My first C1 attempt (a plain `#` line, then `cmdkey /list"` on its own line) was refused by the old guard too, because the token sat on a non-`#` line. The leak needs the escaped `\n` inside a double-quoted scalar on a line that starts with `#`. c2 and c3 do not execute. They are in the table because P-020 is fail-closed: the guard cannot tell c2 from C1 without reading YAML.

### 3. Current lines that would be refused (to reword)

Rewording constraints:
- These lines are not inside any owned fragment that release-guard compares byte for byte (step 18 is not one).
- The new text must still avoid release-guard R11's tokens: the word `uses` in any case, `actions/cache`, `setup-node`, `rust-cache`, `cache/save`, `pnpm/action-setup`. Example: "through the product's own Win32 write/read/enumerate/delete calls (GENERIC) in scripts/ci/credentials.ps1" and "The purge enumerates `Voicen/*`".
- Dropping the `Cred[A-Z]` left boundary `(^|[^A-Za-z0-9_])` adds 0 hits on the real files (checked). Keeping or dropping it is optional. It is a token boundary, not a grammar reader.

**Self-test impact** (`test-new.sh`, the no-skip guard on today's cases): 14 pass, 3 fail.

### 4. Hypotheses checked
- **H1, comment skip (confirmed):** see §2.
- **H2, a second path reaches Credential Manager in CI:**
  - The windows job also runs `pnpm install`, `pnpm tauri build` (NSIS hooks in `src-tauri/windows/`) and the `src-tauri/tests` exes. The test exes call `CredWriteW` legitimately: that is product code.
  - `ci.yml` calls no script outside `scripts/ci/` (grep of script paths in `ci.yml`).

- **H3, case-sensitive `Cred[A-Z]` is a model:** not a grammar reader. Win32 export lookup is case-sensitive, so a lower-case entry point does not resolve. This is from Win32 behaviour and was not probed here (no Windows host). The rule is unchanged by T-090.
- **H4, this class was fixed before:** yes, see §6.
