## Context

Owner decision #292 (2026-11-16): the teamwright contour runs up to 5 tasks at once. Today it runs one: `.github/workflows/teamwright-agent.yml` has the repository-wide `concurrency: group: teamwright-agent` ("One stage at a time in the repository (one runner)"), `.github/workflows/teamwright-next.yml` has `group: teamwright-next` and its "Next stage" step stops a chain when "a stage of another task runs (one task at a time)". The runner pool (`[self-hosted, Linux, X64, claude]`, VM 105) is raised by the owner's infra, outside this repository.

The contour workflows' headers are byte-pinned (`scripts/ci/contour-heads/<name>`, R14 in `scripts/ci/release-guard.test.sh`), so this is a guard change (`checker: true`, `analysis.decides_on`). Overlaps with T-215 (same files): one after the other.

## Acceptance

- [ ] Stages of different tasks run at the same time, at most 5 tasks with an unfinished stage; a 6th task's dispatch waits or stops with a comment naming the limit (not "one task at a time")
- [ ] One task never has two stages at once (per-task concurrency group or the existing own-run wait)
- [ ] The limit 5 is one value in one place, named in the workflow comment and `docs/decisions/ci-toolchain.md`
- [ ] `scripts/ci/contour-heads/` and the R14 checker stay in step with the new headers; `make check` green
- [ ] Failure branch: a dispatch while 5 other tasks have unfinished stages starts no stage and says why on the Issue (a test of the dispatcher's count, e.g. on a faked `gh run list` output)
- [ ] Test that fails without the change: the count test above fails on the current "one task at a time" check
- [ ] CLAUDE.md and docs that say "one task at a time" / "one runner" for the contour are updated in the same commit
