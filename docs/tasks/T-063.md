## Investigation

**Frame.** Not a defect in shipped behaviour: three non-blocking Lows/notes from T-027 (reviews/2.md findings 1 and 2, validation/1.md closing note), cut out of T-025 by decision #76. Expected: each license guarantee is either checked by a test that can go red or stated as a bounded assumption. Observed: (1) `docs/decisions/licenses.md:31` and `vite.config.js:18-19` state as fact that an asset with no original file "carries no third-party code"; the plugin cannot know this (`vite.config.js:39` drops such assets before `classifyBundle`, `scripts/licenses/bundle.mjs` `classifyBundle` asset loop sees only original files). (2) `about.hbs:15-17` leaves out every crate without `source`; the rule "never vendor third-party code as a path crate or `[patch]`" (`licenses.md:40`) has no test (P-004). (3) `Makefile` `licenses-stale` (lines 181-183) is the only staleness check and nothing checks the step; `licenses-fixture` does exactly that for the Rust check.

**Hypotheses.**
1. Prose-only rules with no check (P-004) -- confirmed for (2) and (3): `notices.test.mjs` "the committed notices do not list the project's own workspace crates" checks the opposite direction only (members not listed), not sourceless => member; no target in `make check` runs `licenses-stale` on known-bad input (`grep -n licenses Makefile`).
2. A second path past the notices: `[patch]` with a path also yields a sourceless Cargo.lock entry, so the same template branch hides it -- confirmed by Cargo's lock format (path and patched-path packages carry no `source`); covered by the same invariant (a).
3. Class fixed before -- T-027 rounds 1-2 closed the bundle's fail-closed path for modules and file-backed assets; this is the residual at its edge, not a recurrence (`docs/failures.md` has no license entry; no other `class: licenses` task).
4. The plugin's blind spots ship third-party code today -- refuted per reviews/2.md real-build listing (143 module ids, assets: CSS chunk and `_app/version.json` only); no plugin uses `writeBundle`/`closeBundle`/`renderChunk`/`banner`, `static/` holds only project files. Stays a documented boundary.

**Evidence searched.** grep/Read only (Makefile, .mjs, .hbs, Handlebars and TOML are not symbols for Serena; Serena not used). Cargo.lock sourceless packages today: `voicen`, `voicen-core` (awk over `[[package]]`), equal to `Cargo.toml` members. No `[patch]` in any Cargo.toml. The validator's M2/M3 in T-027 validation/1.md ran `make -o licenses-rust -o licenses-bundle licenses-stale` in a copy, so the recipe can be run without regenerating; I did not re-run it (no heavy run; a probe was not permitted in this session) -- the developer confirms `-o licenses-generate` runs no `scripts/tw-run` (the guard asserts the output has no tw-run/docker line).

**Option chosen (B, guard the real recipe).**
- (c) docs: reword `licenses.md:31` and `vite.config.js:18-19` as an assumption that holds for the current plugin set; name what `generateBundle` of `voicen-bundled-packages` cannot see: files written in `writeBundle`/`closeBundle` (e.g. a workbox service worker), assets emitted by plugins whose `generateBundle` runs after ours (post plugins), code added in `renderChunk`/`banner`/`intro`/`footer`, `static/` copies; adopting a Vite plugin that emits files or injects code is a license-review point. Qualify "fail closed" in the decision heading area and the `docs/architecture.md` row ("fail closed for the modules and file-backed assets the plugin sees").
- (a) path crates: export `workspaceMemberNames(root)` (move the parse out of `notices.test.mjs`; fail on a glob member rather than guess) and `pathCratesOutsideWorkspace(lockText, names)` (each `[[package]]` without `source = ` whose name is not a member). Tests in `notices.test.mjs`: fixture lock text with `vendored-zlib` (no source) and members `voicen`, `voicen-core` -> `["vendored-zlib"]`; a `[patch]`-style sourceless entry likewise; registry/git packages ignored; real repo `Cargo.lock` -> `[]`. Runs in `licenses-unit` (offline). Update `licenses.md:39-40` (the Don't becomes "enforced by"), `about.hbs` comment.
- (b) stale guard: `Makefile` `NOTICES := THIRD-PARTY-NOTICES.txt` used by `licenses-stale` (test -f, diff, both messages) and `licenses` (cp). `scripts/licenses/stale-check.sh` runs `make -s -o licenses-generate licenses-stale LICENSES_DIR=<tmp copy of case>/fresh NOTICES=<case>/committed` on `licenses/fixtures/stale/{equal,stale,missing}/` (every case dir listed in the script, as `shell-test-layout.test.sh` does): equal -> exit 0; stale (one changed line) -> non-zero, stderr "is stale" and the changed line from `diff -u`; missing -> non-zero, "is not committed". It also checks that `licenses-check` has `licenses-stale` as a prerequisite (from `make -pRrqn` database, not Makefile text). Exit 1 = guard broken, 3 = cannot run (make/diff missing). New target `licenses-stale-guard` in `licenses-check` before `licenses-stale`; offline and docker-free. Update `licenses.md` invariant "byte-equal" (Where enforced + Tests that pin it, Code line), Makefile comment.
