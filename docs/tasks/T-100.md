## Investigation

See `docs/tasks/T-024.md` (analysis and Investigation): this task is its core part, moved here by decision #134.

**Refresh 2026-10-17 (main d24b606, after T-054, T-089, T-098, T-103).** Tools: Serena and Context7 were not used (not connected); context from grep and file reads, plus one throwaway `rustc` probe in `voicen-rust:1.99` (container `/tmp`, outside the repo; the image has no `rust-src`, so std was probed, not read).

*Drift fixed.* `diag/mod.rs` now also has `notice` (T-054). `Log::write`'s lock moved to `log.rs` `Log::write` (lines 170-176). T-098's `DictationLine.local` and T-076's `post_processing` do not touch crash/session. T-089/T-103 added the call bans: `clippy.toml` denies `Instant::now/elapsed` (src exemptions only `clock::instant` / `clock::since`) and `SystemTime::elapsed`. Crash and session code needs no monotonic time: wall time comes from the `Clock` port, and ages are `now.duration_since(mtime)`, as `log.rs` `retain` already does. `SystemTime::now` is not banned. That crash/session read the passed-in `Clock` and do not call it directly is checked by review only.

*New facts that change the approach.*
- A panic inside the hook is not re-entry: std aborts the process (probe: `thread panicked while processing panic. aborting.`, exit 134). So spec T024's "a panic inside the hook's own file write does not recurse or panic" cannot run in-process. It becomes two tests. First: an unwritable logs path writes no file, and the hook returns normally. Use a regular file at the path, because the core container runs as uid 0 (`tests/diag_log.rs` header) and mode bits do not work on Windows. Second: two threads panic at once and exactly one file is written. The guard is a first-wins atomic owned by each installed hook, so a test that reinstalls the hook starts fresh.
- Core tests also run on the Windows job (`ci.yml` `cargo test --workspace --exclude voicen`). The location assertion therefore compares with `file!()`, not a `/` literal, and every fixture must be portable.
- `ModuleResolver` returns adapter text. A full module path on a user machine holds the user name (`C:\Users\<name>\...`). Core reduces it to a bounded base name without separators before rendering, and a test pins it. This is invariant (3).
- A `LogEvent` field must stay an integer, a literal or `BuildInfo` (`diag/mod.rs` invariant, T-008). So `PreviousSession`'s file name is a `CrashFileName` held as its parts (local time fields + pid), rendered by diag, not a `String`/`FileName` newtype.
- Installer note vs marker: R7 says "a time ≥ the marker's started", and the marker's `started` is local text (the identity matched against `session_started`). Parsing that text back would add a second parser. Proposed: compare the note's mtime with the old marker's file mtime. Both are file-system times on the same wall clock, and tests plant both with `set_modified`. Alternative: add an integer `started_unix_ms` key to the marker. Either is agent-decidable; record it in `contracts/core-diag.md`.
- `Exited`: data-model gives it `reason: TrayExit | SessionEnd`. T-024 showed that both reach the shell as the one `RunEvent::Exit`, so the shell cannot tell them apart. Proposed: `Exited` without a field. A contract edit in the implementing commit.
- `OsVersion` on `Started`: needs `RtlGetVersion` in the shell, so it goes to T-024. T-100 defines `OsVersion` (three `u32`, rendered `major.minor.build`) for crash files.
- A partial crash file (process killed mid-write) has no `session_started`. The next start would then write a second record. Proposed: write `crash-*.tmp`, then rename. `Session::begin` deletes stale tmp files, and `retain_crash_files` counts only `crash-*.txt`.
- The hook does not chain the previous (default) hook: that hook prints the payload to stderr. Tests restore the previous hook themselves.

**Still one seam.** All code is in `voicen_core::diag` (area `core`, Linux gate, plus the same core tests on the Windows job). No `src-tauri`, installer or CI change. The design already lives in spec 006 (`design_ref`), so no new Spec Kit work is needed. The contract and decision-doc updates go in the implementing commit.

**make check tripwires touched.**
- `check-core`: fmt; clippy `--all-targets -D warnings` with the clock bans; `#![deny(unwrap/expect/indexing)]` from `diag/mod.rs` covers the new submodules.
- `check-clippy-lines`: a new line containing the token `clippy` must match a `*` entry, or needs a reviewed owned entry. Avoid it: `Session::begin` is at 7 parameters, the `too_many_arguments` limit.
- `check-core-test-os-answer`: scans the two new test files; they contain no `.invalid`, `127.0.0.1:1` or `192.0.2.1`.
- `check-ban-canary`: probes and `clippy.toml` unchanged, so `ban-canary.expected.txt` is unchanged.
- `licenses-check`: no new crate (std only).
- `check-shell-layout`, release guards: untouched.
- The diff is outside `docs/**`, so a green `wip/T-100` run is needed (P-016).

**Questions (not decided here).**
- (Q1, product, non-blocking) Version and commit in an `abnormal_end` file. FR-014 says "version, commit" without saying whose. The crashed session's values are in the marker as text read from disk. Proposal: render the current `BuildInfo` (typed), and do not render the marker's text. If the owner wants the previous build, it needs a validated parse (digits/dots, hex ≤ 40), and that becomes an OQ.
- (agent-decidable) Note-vs-marker comparison (above), `Exited` shape, whether `Clean` writes a line (proposal: no line), and how a panic `location` inside a dependency is shown. That path holds the CI runner's cargo home, not the user's, because release builds are made by CI; FR-014 allows the location, so it is written as-is. The reviewer should confirm.
