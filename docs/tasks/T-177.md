## Investigation

Investigator, 2026-11-10, main at 5d4f1fed. Serena was not used: the seam is shell, Makefile, YAML, config and two TS specs, and the context tool does not index them. Evidence comes from grep (tree without node_modules/target/.git), file reads, the installed Playwright 1.63.0 sources and types, Context7 `/microsoft/playwright` (main-branch docs, checked against the 1.63.0 types), the host cron and journalctl.

**1. Own-context pages (T-050 r2#1).** The structural test in `e2e/boot-failure.spec.ts` flags a spec only when it destructures `page`/`context` and does not import `test` from `./support/boot`. A spec with `async ({ browser }) => { const c = await browser.newContext(); ... }` passes, and so does `browser.newPage()`, which also makes a new context. E2's Don't line says this is not covered. No e2e file uses those tokens today, so the new scan starts green, and its proof that it works is a characterization test over string fixtures, the way the T-195 navigation scan does it.

**2. E1 only opt-in (T-050 r2#2).** `scripts/ci/e2e-build-race.sh` runs only by hand. Both tests of `e2e/build-race.spec.ts` skip without `VOICEN_E2E_BUILD_RACE`. Playwright exposes the resolved `webServer` to a test (`FullConfig.webServer`, present in the 1.63.0 types), so one in-run test can assert `reuseExistingServer: false`, `--port <VOICEN_E2E_PORT> --strictPort`, url = baseURL and the run-private outDir at no extra cost. Running `foreign-port` in the gate was rejected: it needs a second full Playwright run with its own build, plus port 4173 free.

**3. Shared `npm-bundled.json` (T-050 r2#4).** `vite.config.js` `bundledPackages` uses a plain `writeFileSync` to write `<root>/target/licenses/npm-bundled.json` for every client build. That includes e2e webServer builds, which move only `kit.outDir`. Beyond the torn-file risk, a concurrent e2e build can write the list between `licenses-bundle`'s `rm -f` and its own `pnpm build`. That defeats the stale-list guard (docs/decisions/licenses.md). Fix: an e2e build (VOICEN_E2E_OUT_DIR set) writes under its run dir, and every write is temp file + rename in the target dir.

**4. Gate workers (T-055 v1).** `check-ui` runs `scripts/e2e.sh` with no arguments, and `playwright.config.ts` has no `workers`, so the default applies: half the logical cores. That is 3 on the 6-core host (the task line says "all CPUs", which is not right, but it is still above the owner's 2). e2e.sh already forwards `$@` in both branches, so the change is in the Makefile alone: `WORKERS ?= 2` and `--workers=$(WORKERS)`. CI's ubuntu-24.04 runner has 4 vCPUs, where the default is already 2, so CI does not change.

**5. Vanished image (T-055 v1).** What the gate does: `check-ui` starts with `scripts/tw-run ui -- pnpm lint`. tw-run (kit-managed) runs a plain `docker run`, which for a missing local tag tries an implicit pull and fails with `Unable to find image ... locally`, exit 125. e2e.sh's preflight (`image inspect`, exit 3, `make ui-image`) is only the third line. What removed the image (most likely, not proven): the host cron `/etc/cron.d/disk-cleanup` (2026-10-05) runs `/usr/local/sbin/docker-image-cleanup.sh` at hh:37 every 6 h. It removes every image older than 24 h that no container references and whose ref is not in KEEP_RE, and tw-run's `--rm` containers leave no reference. voicen-ui:1.63.0 has Created 2026-10-06T16:45, so it was over 24 h old from 2026-10-07. The T-055 validation was committed at 13:02 on 2026-10-09, just after the 12:37 run. The image came back minutes later with the same Created, which fits a fully cached rebuild (same image ID). The oldest version on disk (`docker-image-cleanup.sh.bak`, mtime 2026-10-09 15:35) already keeps `voicen-(rust|ui):`, so the host was likely fixed that afternoon. The earlier version and the journal (it starts 2026-10-30) are gone, which is why this stays unproven. Host note for the owner, outside the repo: the keep pattern `mcr\.microsoft\.com/playwright/` does not match `mcr.microsoft.com/playwright:v1.63.0-noble` (no slash after `playwright`), so the base image is still removed. That costs a pull at the next uncached build, not a gate failure. The repo fix: an image-presence preflight before the first container of `check-ui` (core too, same script).

**6. Exit code through pnpm (T-064 v1 note 1).** The host branch of `scripts/e2e.sh` ends with `exec scripts/tw-run ui -- pnpm e2e "$@"`. The validation record shows real pnpm turning the in-image exit 3 into 1. The fixture's fake pnpm `exec`s the script, so `scripts/ci/e2e-entry.test.sh` passes with 3 and cannot see this. A direct check with host pnpm was denied by the sandbox, so the pnpm behaviour rests on the validation record. Fix: re-enter with `scripts/e2e.sh` directly and make the fake pnpm faithful (a non-zero script exit becomes 1). An outermost `pnpm e2e` typed on the host still reports 1, and that cannot be fixed in the repo. The gate calls `scripts/e2e.sh` directly.

**7. One image tag (T-064 r1#5 / r2#10).** Literal copies: `docker/ui.Dockerfile` (FROM `v1.63.0-noble`, ENV `VOICEN_UI_IMAGE`), Makefile `ui-image` (and `core-image`), `.teamwright/config.yml` areas[].image, and a fifth one the review missed: `.github/workflows/teamwright-agent.yml` preflight `for pair in core=voicen-rust:1.99 ui=voicen-ui:1.63.0`. So a new reader, `scripts/ci/area-image.sh`, feeds the Makefile (tag, `--build-arg PLAYWRIGHT_VERSION`, `VOICEN_UI_IMAGE`) and the contour loop. A check pins the ui tag's version to the installed `@playwright/test`.
