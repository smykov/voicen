## Context

Split out of the T-086 audit (decision #124). Two guards share the same YAML skeleton: indent and step tracking, a scalar reader and a comment cutter. Both leak.
- `scripts/ci/ci-wip.sh`: the workflow runs on `main` and `wip/**`, and no step saves a cache off `main`.
- `scripts/ci/setup-node-cache.sh`: no setup-node step needs host pnpm.

The probes, all of which PyYAML reads as the violating step:
- W1: a flow-mapping step `- {name: "cache #1", uses: actions/cache@v4, ...}`.
- W2: an explicit key `? uses` / `: actions/cache@v4`.
- S1: `"cache": pnpm`.
- S2: `? cache` / `: pnpm`.

release-guard R7 already pins the trigger inside `scripts/ci/release-header.yml`. ci-wip's setup-node clause is stricter than setup-node-cache's. The proposal:
- the trigger is asserted as lines of the owned header literal;
- the raw tokens `uses`, `actions/cache`, `setup-node`, `rust-cache`, `cache/save` and `pnpm/action-setup` occur only on owned lines or blocks;
- an unlisted action stays refused.

## Acceptance

- [ ] One guard, or two that share no grammar reader, decides only on owned literals and raw tokens. It keeps no YAML key, scalar or comment reader, and its `decides_on` is named.
- [ ] Failure branch: W1, W2, S1 and S2 are refused, and each fixture is red against the old guards. The existing ci-wip and setup-node-cache guarantees still hold: a cache saved off `main`, a trigger change, setup-node with pnpm cache, an unlisted action.
- [ ] `docs/decisions/ci-toolchain.md` (the guard table from T-086) is updated. `make check` is green.
