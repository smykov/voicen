## Investigation

How: Serena `get_symbols_overview` on `src-tauri/src/win/hotkey.rs` and `src-tauri/src/call.rs`; the full reads were hotkey.rs and the relevant ranges of `settings/service.rs`, `dictation.rs` (core and shell), `lib.rs::run` and `call.rs`. I did not run any Rust (that needs Docker/Windows), so every claim below comes from reading the code.

- **Prerequisites exist.** T-126: `CallSession::toggle_record` with `CallSource::Hotkey` / `StopReason::Hotkey` is in core. T-128 added `call::request` / `serve`. T-007/T-210: the `Notifier` port and the shared `ShellNotifier`. T-119: `notice.call_hotkey_conflict` is in the catalog. T-120: `CallSettings::hotkey` is stored and validated, including equality refused from either side.
- **What is missing.** Three pieces:
  - The second registration slot on the hotkey thread.
  - The startup wiring in `start_dictation_with`.
  - Re-registration on save. Core `SettingsService::save` prepares only `settings.hotkey`, and `docs/decisions/settings.md` forbids registering outside prepare/commit/abort. So this task touches core as well as the shell: one more step in `save` and one trait method.
- **One seam.** Both halves sit on the two-step registrar, the same split T-055 used. No new behaviour has to be invented, except the open question below.
- **Esc premise (hotkey.rs module doc, T-009/T-174).** It holds as long as a call press never calls `hotkey_pressed`. The call press only posts a `CallRequest`.
- **Recurrence.** None. `docs/failures.md` has no `call-hotkey` entry and no defect in hotkey registration. The test-side rules from F-020 (probe only after a synchronous answer) and F-014 (synthetic input timing) apply to `call_hotkey.rs`.
- **Open question (for the owner or spec, not blocking the shell tests).** US9 #3 / FR-33 say "the Calls settings tab marks the call hotkey" after a conflict at startup, but no wire carries that mark. `contracts/ipc.md` says the settings commands are unchanged, and T-155 marks the field only from a save error. This task keeps the mark as shell state that the tests can read. The UI wire needs a decision before T-155 (for example a `SettingsView` field or an event).
- **Guard change:** none. No path under `scripts/ci/`, no `Makefile` or `*.mk`, so `decides_on` stays empty.

**Recommended exit:** n/a (feature task).
