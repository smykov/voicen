## Context

Owner report, 2026-10-12, installed build 0.1.143 (main CI run 143, commit 23143c0): on the recording hotkey the overlay flickers from the recording state to "Речь не распознана" (`notice.no_speech`). FR-01..FR-03 (hold mode, default `Ctrl+Alt+Space`), FR-12 (speech gate).

What the code says so far (not yet the root cause):
- `notice.no_speech` comes only from a finished job: the speech gate said no speech (`pipeline.rs` `process`, no `engine=` on the log line) or the engine / post-processing returned blank text (`engine=` present). A hold under `MIN_HOLD` (300 ms) is `too_short` and shows nothing, so the recording ran at least 300 ms, or it was a toggle stop.
- The hold ends when the 10 ms `GetAsyncKeyState` poll (`src-tauri/src/win/hotkey.rs` `run`, `win32_data::released`) sees any poll group with no key down. A false "released" while the key is still held would give exactly this picture: a short recording, then the energy detector's "no speech".
- The recording path did not change between build 0.1.116 (d328c72) and 0.1.143 except T-054's logs notice (`dictation.rs` `notice_with`, `LogsNoticeSink`), so a regression is not established.

Owner, same day: build 0.1.70 (main CI run 70, commit 62d5d35) works with hotkey `Ctrl+Space` (hold, speak, release, the text is pasted); reinstalling it now still works. In the new builds, holding `Ctrl+Space` gives a repeating cycle "recording starts → «Речь не распознана» → recording starts → …", and no real recording happens. So it is a regression between 62d5d35 and 23143c0. Candidate: T-009 (f77a2e7: toggle mode, Esc claim registered on every recording start, `press_while_live`). Hypotheses to test: (H1) the mode is `toggle` and keyboard auto-repeat delivers repeated `WM_HOTKEY` despite `MOD_NOREPEAT` (the menu-mask key injected on each `WM_HOTKEY` may reset the repeat detection), so each repeat toggles a recording of a few tens of ms (toggle has no `MIN_HOLD`), which the gate calls no speech; (H2) the mode is `hold` and something since T-009 ends the hold while the keys are down, and repeated `WM_HOTKEY` restarts it.

Evidence to collect: the owner's `dictation` lines from `%LOCALAPPDATA%\Voicen\logs\voicen-*.log` (fields `outcome`, `engine`, `detector`, `duration_ms`; no transcript text is logged), the recording mode and hotkey in settings, whether the key is held or tapped, and the focused application.
