## Investigation

Checked at HEAD b4fec295 (branch `task/T-182`). Serena: `get_symbols_overview` on call/codec.rs. `find_referencing_symbols` for `ReadEnd` came back empty, so the consumers were found with grep across `crates/**` and `src-tauri/**`. Dependency source came from the crates.io archives, and each checksum matches Cargo.lock: ogg 0.9.2 `fdab8dcd…`, opus 0.4.0 `33718946…`. context7 has only the C libogg, not these crates. Line numbers are from HEAD and have moved since T-060.

**Frame.** This is test hardening and one ssot cleanup. No user-visible symptom: production propagates every error today (codec.rs:184-185, :237-243, :277-279), and every reader end yields the same recoverable audio.

**Per Acceptance line**

1. **r1#1 (holds).** codec.rs:41 `RATE = 16_000` and :445 `saturating_mul(16)` in `next_window` repeat audio/mod.rs:16. FRAME (:43, 320), GRANULE_PER_SAMPLE (:47, 3) and MAX_DECODED (:58, 1920) also encode 16 kHz. Approach: `RATE = crate::audio::SAMPLE_RATE`, plus a `SAMPLES_PER_MS` derived from it, as final_pass.rs:95 already does. Derive the other three from RATE, with a compile-time assert that 48 kHz is a multiple of RATE. Tests keep their literals (`RATE: usize = 16_000` at :477, the OpusHead bytes at :873): they are the independent oracle for the contract's "input rate 16000" (core-call.md, page-1 table). No red test, since behaviour does not change. Sibling outside the seam: call/session.rs:85 `SAMPLES_PER_MS: u64 = 16` (the orchestrator may file a follow-up).
2. **r1#2 (holds; approach = contract statement, not a rescan).** Mechanism: a flip that grows byte 26 (segment count) or a lacing value makes `read_ogg_page` `read_exact` past EOF (ogg reading.rs:871, :876). That is `OggReadError::ReadError(UnexpectedEof)`, not `HashMismatch`, so codec.rs:359 (first bad page) or :372 (inside `after_bad_page`) returns Truncated, even when a CRC-valid page sat after the bad one and was swallowed by the overrun. A page can grow by up to 255×255 B, and audio pages are about 3 KB, so this can hit any of roughly the last 20 pages. The prefix read is the same either way; only the label differs. Why a statement is enough: no production consumer branches on the label. storage.rs `recovered_duration_ms` (:524-537) reads only `duration_48k`. final_pass.rs:889 ends a track the same way on `Ok(None)` and `Err(Damaged)` (call-final-pass.md D5). Tests elsewhere (tests/call_session.rs, tests/call_recovery.rs) assert Complete/Truncated only on their own undamaged or cut files. So the AC's own condition ("before storage relies on the difference") is not met. A rescan from bad-page-start + 1 would need byte offsets that `Pages` does not track today (`get_mut().stream_position()` around each page read, then `seek_bytes`). It would add a resync path and its tests and change nothing observable. The wording to add, in the `ReadEnd::Damaged` / `Pages::after_bad_page` docs and core-call.md "Damaged": "Damaged iff the reader's forward walk reaches a CRC-valid page after a bad one. A bad page whose segment count or lacing runs past the end of the file reads as Truncated, with the same recoverable prefix." This matches research R7, which already treats `UnexpectedEof` as end of recoverable data. Pin it with one test (segment count of page last-1 grown past EOF → Truncated, prefix last-2). **Not an unsettled product decision today.** It becomes one only if a future consumer (UI badge, storage choice) shows Truncated and Damaged differently. At that point a rescan is required, and that consumer's task must decide it.
3. **r1#3 (holds).** `encoder_uses_the_r5_settings` (:1156-1206) pins packet duration, frame count, mono, bandwidth ≤ wideband, DTX (no ≤2 B packets in silence), VBR (silence < speech/2), the bitrate band, and Voip only as "no CELT packets", which also depends on VBR/DTX. Complexity 9 (:54, :138) and FEC off (:140) are never asserted. Neither is observable in the bitstream with certainty: FEC only shows under packet loss, and complexity changes bytes without a property to assert. So pin the configuration: a new test reads the encoder's getters after `OpusOgg::create` on a `Sink`. opus 0.4.0 has `get_complexity`, `get_inband_fec`, `get_application` (Application is PartialEq), `get_vbr`, `get_dtx`, `get_bitrate`, and `mod tests` is a child module, so it sees the private `encoder` field. Mutants `set_complexity(10)`, `set_inband_fec(true)`, `Application::Audio` and `set_vbr(false)` each fail one assertion. Deleting a setter line is equivalent only where libopus's default equals the R5 value. Not checked here (libopus 1.6.1 defaults not looked up); the getter test still kills it where the default differs.
4. **r2#1 + failure branch (holds as a test gap; the code is correct).** :237 is `self.write(packet, end, granule)?;`. The only push-time write-error test, `a_write_error_maps_to_storage_error_write` (:1591-1608), uses `fail_write_at` (:525, :558-562), which fails that write **and every later one**. Under the mutant `let _ = self.write(..)`, ogg's `write_page` returns before its page reset (writing.rs:280-284), so `segment_cnt` keeps growing across pages. At 255 the next packet indexes `cur_pg_lacing[255]` at writing.rs:161 and panics. That panic is the only thing that kills the mutant. How to fail exactly one write: `SinkState::fail_write_once_at` (:528, :563-568) fails the first write that would store past `at`, stores nothing, and clears itself. Set `at = pages(&encode(&speech(n)))[2 + k].start`: identical bytes, since the signal is the same `Speech::new(140.0, 0.01, 7)` and chunking is pinned by `push_in_any_chunking_writes_the_same_bytes`. The header `write_all` of audio page k+1 is then the one that fails, during push index `(k + 1) * 50 - 1` (one 320-sample push per packet in `first_failing_push`, :1652-1663). Assert `(at, e.op, e.kind) == ((k + 1) * 50 - 1, StorageOp::Write, kind)` for k ∈ {0, 2} with distinct kinds (e.g. StorageFull, PermissionDenied). Also assert that `fail_write_once_at` is `None` afterwards (the fake fired) and that the events end at or before `pages[2 + k].start`, with no Flush/Sync after it. Under the mutant the ogg page state merely carries over (no overflow within 8 s with one failure), every push returns Ok, and `first_failing_push` panics with its own "failure was swallowed" message. That is a test-owned assertion, not an ogg panic. This is the red test to write first. It is red only against the mutant (the code already propagates), so the test-writer shows red with the mutant applied: `scripts/tw-mutants core T-182` or a copy build.
5. **r3#1 (holds).** `consecutive_bad_pages_up_to_the_end_of_the_file_end_recoverable_data` (:1395-1405) expects Truncated. A cut, an EOF overrun or a CRC run all give that result. That its run is a CRC run is shown only indirectly, by the sibling (:1380-1393) getting Damaged, which only the HashMismatch path at :358 reaches. Approach: assert it in the tail test. Either walk the corrupted bytes with `ogg::PacketReader` and require the first error at page k to be `OggReadError::HashMismatch` (the dependency as oracle, not the code under test), or, with the test parser, check that each page in the run keeps its capture pattern, segment count and lacing while its CRC no longer matches. Add one line at `corrupt_run` stating the length-preserving property.
6. **r4#1 (holds).** `opus_head_pre_skip` (:313-320) accepts version 0-15 (`version >> 4 == 0`) and channels 1-2. Its test (:1483-1517) has only reject rows, so `*version == 1` and `*channels == 1` survive because the fixture is version 1, mono. The test's own comment already defines the boundary as RFC 7845 5.1 ("version of 16 or more", "0 or 3 channels"), and the contract only says "no valid OpusHead". So the reader stays RFC-tolerant, which needs no owner decision. Add accept rows to the same table shape: version 2, version 15, channels 2 (CRC fixed with `fix_crc`). Each must give `scan_of` Ok with end Complete and the fixture's duration, and `OpusOggReader::open` Ok. A 2-channel head over mono packets still decodes through the mono decoder, but assert only open/scan, not samples.
