## Context

Split from T-001 by decision #43 (T-001 analysis, option A). Synchronous engines with blocking reqwest (OQ-05 (a), decision #42). From the T-001 Investigation: reqwest 0.13.5 `default-features = false` with `blocking`, `multipart`, `json`, `rustls` (spec T002's `rustls-tls` does not exist; keep `system-proxy` — confirm); the request URL is built on the parsed base URL so a #27(2) query string survives; reqwest errors carry the URL and must never reach a `FailureReason`, event or log (P-009, #30); the blocking client panics inside a tokio runtime (tests run wiremock in a runtime and call the engine on a plain thread); FR-24 timeouts = connect 5 s + per-request 30 s (`Timeouts`, one constructor, ms in tests); `AudioBuffer` 16 kHz mono i16 only via `from_frames` (mix-down + rubato) or 16 kHz samples; WAV writer by hand (`hound` not consented); error classification as in the Investigation (401/403 → InvalidApiKey, refused/connect-timeout → CannotReach{host[:port]}, DNS/unreachable → NetworkUnavailable, total timeout → Timeout, other status → ServerError, bad/oversized body → UnexpectedResponse, empty text → Ok("")). Open contract gap to settle in the analysis (not owner-level): a `CredentialStore::read` error gives a retryable failure and sends no request; the factory must not panic for engines not built yet (T-017/T-018). New dependencies are within decision #9 (reqwest, rubato, thiserror; dev: wiremock, tokio) — `aws-lc-sys` (via rustls) is the first C library in core: the first Windows CI run proves it links (watch for a ci-toolchain instance).

## Acceptance

- [ ] A WAV of a 16 kHz mono buffer sent to a wiremock `/v1/audio/transcriptions` is multipart with `file`, `model`, `language` (omitted for auto) and `Authorization: Bearer <key>`; a base URL with a query string keeps the query and gets the path
- [ ] `AudioBuffer::from_frames` mixes down and resamples 44.1/48 kHz stereo to 16 kHz mono (length and a tone's frequency preserved within tolerance)
- [ ] Failure branch: 401 → `InvalidApiKey`; a delay past a ms-scale timeout → `Timeout`; a refused 127.0.0.1 port → `CannotReach(host:port)`; an oversized or malformed body → `UnexpectedResponse`; no `FailureReason`, event or `Display` contains the URL query or the key
- [ ] Test that fails without the change: `crates/voicen-core/tests/openai_client.rs` and unit tests in `audio`/`engine`

**New evidence (probe in voicen-rust:1.99, temporary copy of the workspace, reqwest 0.13.5 with the features below).**
- Error flags:
  - refused `127.0.0.1:9` → `is_connect`, not `is_timeout`, io `ConnectionRefused`;
  - `nohost.invalid` → `is_connect` **and** `is_dns`;
  - `192.0.2.1:80` with `connect_timeout(300 ms)` → `is_connect` and `is_timeout`;
  - a silent listener with `.timeout(300 ms)` → `is_timeout` only.
- So the order is fixed. This sharpens T-001's table, which did not say that DNS errors are also `is_connect`:
  1. status
  2. `is_dns`, or io `NetworkUnreachable`/`HostUnreachable` in the source chain → `NetworkUnavailable`
  3. `is_connect` → `CannotReach{host[:port]}`
  4. `is_timeout` → `Timeout`
  5. body errors → `UnexpectedResponse`

  A TLS handshake failure is also `is_connect`, so it gives `CannotReach`. That is accepted.
- Body read through `Read::take`. A stall mid-body gives `io::Error(Other)` wrapping a `reqwest::Error` with `is_timeout=true`, which must map to `Timeout` (FR-24: the whole request). A reset mid-body gives the same wrapper with `is_timeout=false` → `UnexpectedResponse`. The adapter downcasts `io::Error::get_ref()` to `reqwest::Error`.
- Every send error's `Display` contained the URL query (T-001 (d) confirmed). The body-read wrapper's did not.
- URL join: `path_segments_mut().pop_if_empty().extend(["audio","transcriptions"])` gives `https://api.example.com/v1/audio/transcriptions?api-version=2024` and `https://api.example.com/audio/transcriptions`.
- aws-lc-sys 0.45.0 compiles in the image with the cc builder (core cold build ≈ 70 s). The build also works without reqwest's `json` feature.

**(1) `CredentialStore::read` error.**
- `secrets.rs:217` returns `Err(CredentialError{os_code})`. `data-model.md:131-145` and `contracts/messages.md` have no row for it, and `i18n/en.json` has no `failure.*` id.
- `error.key.store_failed` exists, but it is the settings-save text ("could not be stored"), so it is not reusable.
- Settled (contract gap, not owner-level, like #25): new retryable `FailureReason::KeyStoreUnavailable`, message id `failure.key_store_unavailable`. Proposed texts:
  - en "The API key could not be read from Windows Credential Manager."
  - ru "Не удалось прочитать API-ключ из диспетчера учётных данных Windows."
- `engine_for` returns it before any engine exists, so no request can be sent. That is structural, not a check. `os_code` is not carried; it is not needed and it is not secret.
- `Ok(None)` for the API slot follows the contract unchanged: no `Authorization` header, and the server's 401 → `InvalidApiKey`.

**(2) Engines not built yet.** One new retryable reason, `FailureReason::EngineNotConfigured`, id `failure.engine_not_configured`. Proposed texts:
- en "The transcription engine is not set up. Check the Engine settings."
- ru "Движок распознавания не настроен. Проверьте настройки движка."

It covers every settings state `engine_for` cannot build, which makes the function total:
- `BuiltinLocal` (core never builds it, #12; T-017 wraps `engine_for` in the shell);
- `LocalServer` until T-018 adds its arm;
- `None` (normally stopped earlier by `settings::gate::dictation_gate`);
- a stored `api.base_url` that fails `check_base_url`. `load_or_init` accepts any string (`service.rs:215-216`); the rule runs only at save (`validate.rs:102`), so a hand-edited file reaches dictation.

Order inside `engine_for` (Api): `check_base_url` (the one URL rule, P-010) → `creds.read(KeySlot::TranscriptionApi)` → `OpenAiCompatibleEngine::new`. A bad URL or a non-API kind never reads the key. Both reasons are retryable: the audio is kept, and a retry after fixing the settings uses the current settings (Clarification 4, NFR-06). 002's `NoLocalModel` (spec 002 T008) replaces `EngineNotConfigured` for BuiltinLocal when T-017 lands. The orchestrator records (1) and (2) as one `docs/decisions.md` row. The T-040 commit adds both rows to `data-model.md` and `contracts/messages.md` (P-014).
