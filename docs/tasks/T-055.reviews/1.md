## Verdict rationale

The core part is correct and tests bite, judged by reading.
- Prepare comes after validation and before autostart, and only for a changed canonical text. The grammar accepts canonical text only, so comparing text is sound.
- Every later refusal aborts after its undo. Commit comes after `write_atomic` and before the swap and the publish.
- `hotkey_registration(false)` asks for settings outside the lock. The reentrant test bites on that.

The shell part follows the analysis seam: a request channel into the one hotkey thread, a spare id, a fail-closed handle. Reasoning on the developer's points:
- No deadlock: the thread never takes the save lock, and `settings_save` is `async`.
- Ten-second wait: a hold keeps the message loop pumping, so a save waits only during the at most 3 s device open, not for the 10 s.
- A timed-out prepare is released by the failed `reply.send`.
- Drop frees committed ids (tested).
- Every commit calls `hotkey_registration(true)`, but `publish` dedups, so a commit with no error publishes nothing.
- The fail-closed `load_settings` is used only by tests. `run()` uses `load_settings_with` with the shared handle. Acceptable.
- Q1 as implemented (report before ready, `startup_action_after_hotkey`) matches the orchestrator's decision. It is pure and tested on every outcome.

The Q2 rule and the toast half deferred to T-007 are recorded decisions.
