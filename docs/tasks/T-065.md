## Context

Opened by the code review of T-057, round 4 (`docs/tasks/T-057.reviews/4.md`, verdict `REJECT_RECURRENCE`). T-057 is `DEFERRED` with `absorbed_by: T-065`.

The install-smoke predicate (`scripts/ci/visible-windows.ps1` `VoicenWindows.Shown`, behind every window check of the install smoke in `.github/workflows/ci.yml` and behind `src-tauri/tests/smoke_predicate.rs`) has been fixed three times for the same class: **which framework helper windows a tauri process has, and which of them the predicate must not count**. Each fix took that premise from reading one library, and each was first checked against the real window set by a Windows CI run:

1. T-037 review round 1 #1 (fix 2a3d417): `Process.MainWindowHandle` returned tao's event-target window (`Tao Thread Event Target`, visible-styled, layered). Fix: skip `WS_EX_TOOLWINDOW` windows and tao's class. Not logged in `docs/failures.md`.
2. T-057 (1545ecf): the `WS_EX_TOOLWINDOW` clause was removed for F-003 (a tool-window overlay at start must count), leaving "exclude only tao's class" on the premise that tao's window is the only always-visible helper.
3. T-057 VERIFY_FAIL 3 (run 37419266451, job 112127101411): that premise was false since T-052 registered tauri-plugin-single-instance 2.5.2, whose helper (`dev.voicen.app-sic`) has the same shape. Every launch of the installed app failed. Fix 2093e5c (kept as a temporary workaround, see below): a pinned helper-class list (tao, plugin) AND all four helper ex-style bits.

The current rule (2093e5c) is correct for today's dependency set and is well tested at the rule level, but by its own analysis ("What A cannot close: a third helper added by a future dependency") the next dependency, feature or version bump that creates a visible-styled helper window brings the same defect back: the smoke fails on every launch, and the fix is one more list entry. That is the P-002 pattern (an allowlist of known cases instead of an invariant).

**Temporary workaround in place:** 2093e5c (class list + four helper bits) stays in the tree, marked temporary with an `RCA: T-065` reference, so that T-057's feature and T-061's purge step can be proven in CI meanwhile. This task either ratifies it (with the rule/guard that closes the class) or replaces it.

Signals for the exit (the investigator recommends; (b) and (c) are owner decisions):
- One seam today (`VoicenWindows.Shown`), but the knowledge it depends on lives elsewhere: the dependency set (`src-tauri/Cargo.toml`, plugins registered in `src-tauri/src/lib.rs` `run()`), and no test process can host the real set (the plugin's second-instance path calls `process::exit(0)`, T-052).
- Hotspot: T-057 has three VERIFY_FAILs; the predicate file was changed by 2a3d417, 1545ecf, 2093e5c (plus the VF2 harness work in the test).
- Process side: the same shape as the proposed class `windows-premise-unchecked-on-host` (F-007, related F-002, F-005; owner decision pending) — a Windows premise taken from reading and first checked by a CI push.
- `src-tauri/tests/overlay.rs` `shown_windows` (:312-341) keeps its own copy of the predicate (tao class only, no bit check): a second source of truth for the same rule.

## Acceptance

- [ ] Invariant (to be confirmed or replaced by the analysis): the smoke counts every window of the installed app that a user could see, and excludes a window only on raw facts that do not depend on knowing in advance which dependencies create helper windows — or, if a list is kept, a check that is not the install smoke itself fails when the real window set of `voicen.exe` gains an unlisted helper (so a new dependency cannot first surface as a red smoke on every launch).
- [ ] Failure branch: a new visible-styled, non-rendering helper window (a third class) → either excluded by the invariant with no list edit, or caught by the guard named above before/independently of the install smoke; a click-through overlay (class `Tauri Window`, LAYERED|TRANSPARENT|NOACTIVATE|TOPMOST|TOOLWINDOW) and a tool window shown at start still count (F-003; `smoke_predicate.rs::a_click_through_overlay_window_counts`, `a_visible_unowned_tool_window_counts_as_shown`).
- [ ] One source of the predicate: `overlay.rs` `shown_windows` uses the same rule as the script or states why it differs.
