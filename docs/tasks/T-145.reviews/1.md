## Verdict rationale

The change follows the analysis seam point by point:
- (a) The worker's first job is the one `CallStore::recover`, with `Recovery.queue` enqueued.
- (b) `CallRequest` gains `Exit`, `ExitConfirmed`, `Sleep` and `Resumed`, served on the worker.
- (c) One `DeliveryGate` (Normal / Held / Exiting) behind `ShellCallShell::{notice, call_ready}`.
- (d) The `ExitConfirm` port, with `WinExitConfirm` = `MessageBoxW(MB_YESNO|MB_ICONQUESTION|MB_DEFBUTTON2|MB_SETFOREGROUND)` on a one-at-a-time `call-exit-question` thread.
- (e) `finalize_on_exit` runs first in the `RunEvent::Exit` arm.

The tray, hotkey and core D1 edits match too.

I checked the invariants by reading:
- I1: `ExitConfirmed` stops with `Exit` before `end_loop`, so the later `finalize_on_exit` stop is a no-op. Concurrent stops serialize on the session lock.
- I2: `exiting()` is set before each exit stop.
- I3: the main thread only posts, and No changes nothing.
- I4: hold before `stop(Sleep)`; release on resume or on any other request; the unlock arm is split from resume.
- I5: one recover, before the first request.

The main-thread lock exception at exit is sound. Inside the session lock, the indicator only does `TrayPart::set_call_recording` (store and post). Shell callbacks run after the lock and go to the gate, whose `deliver` calls `offer` and `PassQueue::enqueue` (push and notify). None of them waits on the main thread.

Tests assert state: meta, track scans, log order and the notifier. The bite claims hold by reading. For example: dropping `gate.exiting()` in `ExitConfirmed` puts `CallSavedTranscribing` into the notifier, which the Yes test asserts empty. Showing the box on the worker hangs the tray Stop in the open-question test. Mapping unlock to `on_resume` releases the hold inside `SETTLE` in the new unlock-after-suspend test.

No test was weakened. The core row changes only its expected value for `sleep`, and `call_hotkey.rs` only gains the new port field. Docs match the code. The Windows CI run at the reviewed head is green, including `cargo test -p voicen`, so every shell guarantee has executed. Both local gates pass on a clean tree.

What remains is below the High threshold and none of it is in a blocking category: recording the measured finalize time in R14 (#1), the orchestrator's `CI:` line (#2), one doc sentence on the asynchronous sleep stop (#3), and a pre-existing coupling noted as a follow-up (#4).
