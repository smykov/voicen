## Round-3 change, read

- **`end_of_process`** (`src-tauri/src/lib.rs`) is the old Exit-arm body, in the same order: `finalize_on_exit`, then `SessionEnd::end`, then `PendingAudio`. Each step is idempotent:
  - `finalize_on_exit`: `exiting` is final, and a `stop` on a stopped call does nothing.
  - `SessionEnd::end`: it `take`s the session under its mutex.
  - `PendingAudio`: `delete_all` on an empty set.
  So in the plain case, the hook running first and then the `Exit` arm gives exactly one `call_stopped` and one `exited`. Both `wm_endsession` tests assert one of each.
- **`win::end_session`**:
  - It sets a thread hook, `WH_CALLWNDPROC`, on `GetCurrentThreadId()`, installed from `Ready` on the loop thread. The hook proc is called on that thread before the window procedure, which also holds inside a nested pump.
  - `take_end` makes it run once. The proc wraps its body in `catch_unwind`, so no panic crosses the FFI.
  - `CallNextHookEx` runs on every path.
  - `uninstall` at `Exit` runs from the window procedure, after the hook proc has returned. The thread-local `Drop` unhooks.
- **Deadlock check** (the loop thread blocks in `join` while `end-session` runs the end). Nothing in the end waits on the loop thread:
  - `TrayPart::set_call_recording` is `shared.want(..)`.
  - The indicator is driven through its mailbox. The `call-indicator` thread that builds the window holds no session lock, and the hook does not join it.
  - The gate is `Exiting` before the stop, so no notifier call happens.
  - `SessionEnd::end` writes the log.
  - The session lock is not taken on the loop thread on this path. Worker paths inside the lock only post (round 1 and round 2 analysis, unchanged).
