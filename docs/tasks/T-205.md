## Investigation

Context tools: Serena loaded but not used (it indexes Rust only; the seam is bash and workflow YAML), so grep and file reads; context7 `/github/docs` for `GITHUB_TOKEN` permission levels; read-only `gh run view` for runs 45102866589 and 45129205331.

**Frame.** Observed: a contour stage (review, and as of 2026-11-23 also implement) cannot read the `ci.yml` run of `wip/<ID>`. T-145 implement round 3 (run 45129205331) needed the failing test of red run 45102866589 (@ 47ecf23a, `wip/T-145`, `workflow_dispatch`), got REST 403 on `actions/jobs/<id>/logs` without a token, and escalated; the owner read `gh run view --log-failed` in the main tree and pushed the answer into the record (bc3b5c9a, decisions #342). Expected (#259): the contour reads its own run through `scripts/tw-wip-run`, with an `actions: read` token, and no session holds a write token.

**Hypotheses and evidence.**
1. *tw-wip-run refuses the contour branch* — confirmed: the branch regex accepts only `refs/heads/tw/<ID>`; the contour checks out `task/<ID>` ('Task branch, git hooks, the kit').
2. *The session has no token* — confirmed, by design (T-202 review 1 finding 1): `persist-credentials: false`, the stage step's env holds only `CLAUDE_CODE_OAUTH_TOKEN`, `MCP_TIMEOUT`, `SYSTEM_PROMPT`; the job token reaches only the push and chain steps. A public repo's run list is readable anonymously, but `gh` needs a login and job logs need auth (the 403).
3. *An actions-read token for one step is possible* — refuted: GitHub sets `GITHUB_TOKEN` permissions at workflow or `jobs.<job_id>` level only (context7 `/github/docs`, `authenticate-with-github_token.md`, `section-assigning-permissions-to-jobs-specific.md`); the agent job needs contents, issues and actions write. So an `actions: read` token is either a PAT secret (refused today by release-guard R4: only `secrets.CLAUDE_CODE_OAUTH_TOKEN` in `teamwright-agent.yml`) or a separate job's token (refused today by R3: `permissions` only in the owned head). A separate job's token ends with that job and cannot reach the session.
4. *"Usable only by that program" can hold for a token in the session* — refuted by the contour's own named limits (`docs/decisions/ci-toolchain.md`, contour exception): the session runs as the runner's OS user, so any env value or file it can pass to `tw-wip-run` it can read itself, and `curl` is not denied (only `Bash(gh:*)`). Acceptance 2 cannot be met with a token inside the session; acceptance 5's "a token with more than actions: read is refused" has no runtime check for a fine-grained PAT, only a static one for a job's `permissions:` block.
5. *tw-wip-run would have answered T-145* — refuted: on a red run it prints `FAILED JOB: <name>` from `run view --json jobs`; here that is "Windows build, install and smoke test", one job holding every shell test. The fix needed the failed step's log (`--log-failed`), which no owned template reads.
6. *Second path* — the main-tree workaround (`gates.md` › Contour review and the `CI:` line) and #342's one-time `task/<ID>` push are the two hand paths; the worktree path (`tw/<ID>`, owner's `gh` login) works and stays unchanged.
7. *Fixed before* — no F-entry covers the contour CI read (checked `docs/failures.md` F-001..F-033); OQ-83/#259 is the planned close, #342 its first sighting in the implement stage. Not a recurrence.

**Timing fact.** `teamwright-next.yml` dispatches the `wip/<ID>` `ci.yml` run and the next stage in the same step, so review starts while the run is pending (Windows job up to 120 min); `tw-wip-run`'s 90-minute ceiling (exit 6) may end a wait before a slow run completes.

**Options.**
- **A (chosen, #350; built by T-249): a read-only job `ci-read` before `agent`.** `permissions: actions: read` at job level (an owned fragment under `scripts/ci/`, R9 per name; R3 allows that one block), checks out `github.sha` (the code that holds the token comes from main, not from `task/<ID>`, as the push step's hooks do), runs `tw-wip-run` for `task/<ID>` at the stage's start commit, waits there, and hands the answer (the `CI:` line, or RED + failed jobs + a bounded failed-step excerpt) to the agent job, which writes it into `$OUT/ci-read.md` before the session. No session holds any token, and the scope is checked statically. Removes the cause: the reader runs where an actions-read token can exist. Red first: the `tw-wip-run.test.sh` and `release-guard.test.sh` cases in `approach`. Risk: the answer is a snapshot at stage start (a re-run during the stage is not seen); the wait moves before the session (on `ubuntu-latest` it uses no self-hosted slot; Q4). It changes #259's "the review reads CI itself"; the owner chose it (#350). Rollback: revert the job and the fragment; the main-tree workaround still works.
- **B (#259 as written): a fine-grained PAT secret (this repository, Actions: read)** in the stage step's env for the stages that read CI; `tw-wip-run` hands it to `gh` as `GH_TOKEN` with a fresh `GH_CONFIG_DIR`; R4 allows that one secret name in `teamwright-agent.yml`; the upload scan's pass 1 gets its value. Keeps the live wait inside the session. Named limits: the whole session can read and `curl` it (actions read on a public repo: run logs and artifacts, which are public to any logged-in user already); its scope and expiry are the owner's settings, not checkable from the repository; it is a user token (rotation, rate limit on the owner's account).
- **C: a pre-session step in the agent job with the job token.** Simplest, no guard widening for the token, but the token reading CI is write-scoped (contents, actions). Not recommended.

Contour-mode detection (both A and B): `task/<ID>` is accepted only with a marker the workflow sets and an `<ID>` equal to the job's `TASK_ID`; on the dev host the marker can be forged, which is harmless (a read, with the owner's own `gh` login). Named limit, best effort, as T-199's other checks.

**Size.** Medium to large for one record: `tw-wip-run` (+ contour mode, + a third template), its self-test, `teamwright-agent.yml` (new job or env), `release-guard.sh` R3 or R4 + self-test, an owned fragment (A), docs (`gates.md`, `ci-toolchain.md`, CLAUDE.md row, decisions). Not a Spec Kit item; split by the owner (#350 Q5) into this task ("tw-wip-run contour mode + failed-step log") and T-249 ("the `ci-read` job + guard + docs").
