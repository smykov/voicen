### 2. Config format (clippy 1.99)
- Clippy reads `clippy.toml` from `CARGO_MANIFEST_DIR` upward, so a file in `crates/voicen-core/` applies to that package only (src-tauri is unaffected).
- Each entry is a string or `{ path, reason, replacement, allow-invalid }`.
- Proposed:
  ```toml
  disallowed-methods = [
    { path = "reqwest::blocking::get", reason = "T-079: every reqwest client is built by engine::http" },
    { path = "reqwest::get", reason = "T-079: every reqwest client is built by engine::http" },
    { path = "std::time::Instant::now", reason = "T-080 I2: read the clock through crate::clock / tests/common::timing" },
    { path = "std::time::Instant::elapsed", reason = "T-080 I2: read the clock through crate::clock / tests/common::timing" },
  ]
  disallowed-types = [
    { path = "reqwest::blocking::Client", reason = "T-079: build clients in engine::http" },
    { path = "reqwest::blocking::ClientBuilder", reason = "T-079: build clients in engine::http" },
    { path = "reqwest::Client", reason = "T-079: build clients in engine::http" },
    { path = "reqwest::ClientBuilder", reason = "T-079: build clients in engine::http" },
  ]
  ```
- **Trait-impl methods cannot be named.** `reqwest::blocking::Client::default` gives the config warning "does not refer to a reachable function", and `-D warnings` does not turn that warning into an error. A mistyped path is therefore silent, and only a canary proves each entry bites (see §6).
- **Why disallowed-types is needed.** Methods alone leave the Default class open: H3 `Client::default()`, H6 `ClientBuilder::default()`, H7 `let c: Client = Default::default()`, H8 `mk::<Client>()`, H9 a `#[derive(Default)]` field, H13 `<Client as Default>::default()`, H15 async `ClientBuilder::default()`.
- **Methods plus types, probe2.** Every probe H1–H20 is refused:
  - H1 whitespace, H2 split path, H4 `use … as`;
  - H5 `reqwest::blocking::get`, H17 `reqwest::get`;
  - H10 fn reference, H11 local macro, H12 async builder, H16 `ClientBuilder::new()`;
  - H18 `use reqwest::blocking as rb`, H19 glob import;
  - a `type Alias =` definition.

  Other reqwest items (`RequestBuilder`, `header`, `multipart`, `Error`) are not flagged, so engine/openai.rs and post_process/chat.rs need no allow.
- **K probes, tests/k.rs.** All refused:
  - k1 `Instant :: now()`, k2 `.elapsed ()`, k3 `use Instant as I`, k4 UFCS;
  - k5 `map(Instant::elapsed)`, k10 a fn pointer;
  - k6 and k11 inside `#[tokio::test]` (that macro does not inject an allow), k7 inside `assert!`, k8 a local macro, k12 inside `format!`;
  - k13 the full path.
- The tokio dev-dependency has no `time` feature, so `tokio::time::Instant` is unreachable today. If the feature is ever added, put it in the config.

### 3. Exemptions, and the 72 src clock reads
- **Clippy lints the lib under the same config even when only a test target is requested** (`cargo clippy --test k` relints the lib, p2.testonly). Neither a per-invocation `CLIPPY_CONF_DIR` nor a "tests-only" config can keep the clock ban out of src. One package config applies to src too.
- **The real crate copy under the proposed config** (log `real`):
  - non-test lib: 18 clock hits — pipeline 4 now + 2 elapsed, connection_test 1+1, dictation 2, local_models/download 1, engine/lookup 2, platform 2, test_support/realtime 3;
  - lib unit tests: 53 more (71 total) — recording/mod.rs 42, overlay 3, recording/indicator 2, pipeline 5, download 1;
  - http: 0 hits once engine/http.rs carries `#![allow(clippy::disallowed_types)]`;
  - integration tests: 0 hits once tests/common/mod.rs line 23 becomes `#![allow(dead_code, clippy::disallowed_methods)]`.
- **So the src reads are affected.** Decision: add `pub(crate) fn instant() -> Instant` and `pub(crate) fn since(t: Instant) -> Duration` to `crate::clock` (already "the one wall-clock port of the core", P-011). They carry the only src `#[allow(clippy::disallowed_methods)]`, and the 71 sites call them.
  - The change is behaviour-neutral: same std calls, one indirection.
  - `pub(crate)` keeps integration tests on tests/common::timing, as I2 wants.
  - Alternative for the 53 unit-test sites only: one owned lib.rs line `#![cfg_attr(test, allow(clippy::disallowed_methods))]`. It relaxes only the cfg(test) lib build (lib test 20 vs lib 22 errors in p3).
  - Caution: integration test crates are also `cfg(test)`, so this line is safe only in lib.rs. That is one more reason the token guard must own it.
- **How the allows are expressed.** Decision: as `#[allow]` attributes, not a second clippy.toml.
  - A per-directory clippy.toml does not exist: config is per package.
  - A second package would move 23 test files and break src-tauri's `#[path]` include of tests/common/mod.rs (Option D, rejected).

### 4. Lint level and escapes
- `check-core` runs `-D warnings`. Under that alone, these silence the lint:
  - `#[allow(warnings)]` and `#[expect(...)]`;
  - `allow(clippy::all)` and `allow(clippy::style)`, also spelled `clippy :: style`;
  - `cfg_attr(all(), allow(...))`;
  - a macro-generated `allow(warnings)`, and `allow(r#warnings)`;
  - the renamed `clippy::disallowed_method` together with `allow(renamed_and_removed_lints)`.
- Lint names are case-sensitive: `clippy::Disallowed_Methods`, `WARNINGS` and `clippy::ALL` are unknown lints and do not apply. `warn(clippy::disallowed_methods)` still errors.
- **Pinning deny explicitly** (CLI `-D clippy::disallowed_methods -D clippy::disallowed_types`, probed) closes every `warnings` escape, multi-line `allow(\n warnings\n)` and `expect(warnings)` included. Recommended form: `crates/voicen-core/Cargo.toml` `[lints.clippy] disallowed_methods = "deny"`, `disallowed_types = "deny"`. The package `[lints]` level was probed: `"allow"` there silences the lint, so the level set there is the one that applies. Adding the CLI `-D` too in check-core is harmless.
  - **Gap:** the `"deny"` value itself was not probed. It needs a canary run in the implementation (§6).
- **Every remaining escape spells the token `clippy`:** the lint name, `clippy::all`, `clippy::style`, a renamed lint. `warnings` cannot be a refused token because it is a product word (settings save warnings), and with the pinned deny it no longer matters.
- **`-F` (forbid) was rejected.** It turns every legitimate exemption allow into E0453. `-F warnings` is useless: it only nominally overrules allows and breaks `allow(dead_code)`.
- **Environment.** There is no `RUSTFLAGS`, `CLIPPY_CONF_DIR`, `--cap-lints` or `all-features` in the Makefile, ci.yml, `.cargo/config.toml` (only `[env] AWS_LC_SYS_PREBUILT_NASM`) or docker/rust.Dockerfile (only `CARGO_HOME`). The canary covers future drift there.

### 5. Token guard (replaces both scripts' path parts)
- **Rule:** every line in tracked `*.rs`, `Cargo.toml` and `.cargo/config.toml` that holds `clippy` (any case, comments included, no `//` skip) is an owned line.
  - Exemption lines are file-bound: http.rs, clock.rs, tests/common/mod.rs, and the optional lib.rs cfg_attr line.
  - General owned lines: the 23 existing `#![deny(clippy::unwrap_used, clippy::expect_used, clippy::indexing_slicing)]` lines, tests/diag_observer.rs `#[allow(clippy::too_many_arguments)]`, src/settings/service.rs `#[allow(clippy::large_enum_variant)]`, and the new `[lints.clippy]` lines.
- **Today:** `clippy` occurs only in crates/voicen-core: those 25 lines and no comment. No other tracked .rs file has it.
- Allowing general lines anywhere is safe, because none of them names the two lints.

### 6. Canary (proves the switch, not the spelling)
- A feature `ban-canary` (or a cfg set only by the canary make target) compiles one lib module and one tests file that hold the H and K probes. Each probe exits 0 on the old guards.
- `cargo clippy --message-format=json` on it must yield exactly an owned expected list of (file, lint, path) diagnostics.
- This catches a mistyped or unreachable config path (silent, see §2), a lost deny level, a `CLIPPY_CONF_DIR` or `--cap-lints` drift, and a clippy upgrade that changes resolution.
- Without the canary, the switch would be trusted rather than proven.
