## Context

T-111 extends F-021's invariant to server-side deadlines and adds `in_time()` and margin M = 5 s in `tests/common`. This is the third one-off grep fix of this class (T-080, T-110, T-111). A token tripwire turns the review-only rule (T1) into a checked one (T3): it refuses `Timeouts {` and `Timeouts::default()` in `crates/voicen-core/tests/**` outside `tests/common`. This is a guard change: `checker: true`, and `analysis.decides_on` is required.

## Acceptance

- [ ] `make check` refuses a `Timeouts {` literal or `Timeouts::default()` in a core test file outside `tests/common`
- [ ] The allowed constructors live only in `tests/common`; the current tree passes
- [ ] The tripwire also refuses, outside `tests/common`, the shapes the `Timeouts` token misses (T-111 review 1 #3): a duration passed to an in-time fixture (`fixture(&server, Duration::from_secs(2))`), a `Serve::Stall`, a short `Serve::Trickle`; or those sites take their value from `tests/common`; its self-test has a fixture for each
- [ ] Failure branch: the tripwire's self-test goes red when it misses a literal in a test file

## Investigation

Written 2026-11-08 (analyze), main at 2bf6e415. T-111 is DONE.

**How I looked.** Serena `get_symbols_overview` of `tests/common/download.rs` (`timeouts`, `fixture_with`, `fixture_with_timeouts`, `fixture` are its deadline-taking functions). grep over `crates/voicen-core/tests/**/*.rs` outside `common/` for `Timeouts {`, `Timeouts::`, `Timeouts as`, `= Timeouts`, `Default::default`, `Stall`, `Trickle`, `SilentHeaders`, `fixture(`, `fixture_with(`, `timeouts(Duration`, `TimeoutSettings`, `_s =`, `.<field> =`. Read: `scripts/ci/core-test-os-answer.sh` and its self-test, the Makefile targets, `crates/voicen-core/src/timeouts.rs::Timeouts` (all fields `pub`), `src/test_support/local_models.rs::Serve`, T-111's Investigation, catalog follow-ups and reviews 1-4, decisions #112, #200, #224, P-020. A text search does not see a deadline built at run time from other parts; that is a named residual below, not a claim of absence.

**Hypotheses.**
1. *A tripwire on `Timeouts {` and `Timeouts::default()` alone closes the rule.* Refuted: the in-time shapes T-111 r1#3 and r2#2 named (`fixture(&server, Duration::from_secs(2))`, `timeouts(Duration::from_secs(5))` in `silero_model.rs`, a `Serve::Stall`, a short `Serve::Trickle`) contain no `Timeouts` token. Also, `-> Timeouts {` (a local constructor) matches `Timeouts {`, so local helpers must move to `common` for the tree to pass, which matches Acceptance 2.
2. *"Short" can be decided by the tripwire.* Refuted by P-020: judging a duration's value or a call's argument means reading Rust. So the timed plans are refused as words (`Stall`, `Trickle`, `SilentHeaders`), whatever their values, and the duration argument is taken away at the type level.
3. *The same concern on a second path.* Confirmed, in three places. (a) Field mutation after construction: `openai_client::req_with_total` writes `r.timeouts.api_transcription = total`. This is #112's "editing a case's `pub` deadline fields", already T1. A token on the field names would hit `Settings` fields with the same names (`s.post_processing = PostProcessingSettings {..}` in `post_process_timeout.rs` and `diag_pipeline.rs`), so it stays T1, and the move gives `req_with_total` a named common value. (b) The settings route: `TimeoutSettings { .. }` and `s.timeouts.<role>_s = ..` in `api_pipeline`, `local_server`, `post_process_timeout`, `connection_test` and `settings_apply` (about 50 lines). Product code turns these into `Timeouts::from_settings`. Most of them have the setting itself as the subject (forms, clamping, apply). The configured-timeout legs are pinned by `*_keep_the_in_time_margin_m`. Not in the Acceptance, so it is an owner question below. (c) `crates/voicen-core/examples`, the `#[cfg(test)]` units under `src`, and `src-tauri/tests` fall outside the scanned dir, as they do for I1.
4. *This class was fixed before.* Yes, three times by a one-off grep (T-080, T-110, T-111), and each pass found sites the previous one missed. The I1 half of the class has been T3 since T-080/T-089 (`core-test-os-answer.sh`), and that guard is the model here.

**Why the fixture shape goes to the compiler and not to the token.** Once `common::download::fixture(&Server)` and `fixture_with(entries, disk)` take no `Duration` and `common::download::timeouts(no_data)` is gone, `fixture(&server, Duration::from_secs(2))` does not compile. The other ways to supply a short no-data value are `fixture_with_timeouts(.., Timeouts { .. })` (token), `Default::default()` (token) and `let mut t = in_time(); t.download_no_data = ..` (mutation, #112, T1). A fn-pointer type check in a common test (`let _: fn(&Server) -> Fixture = fixture;`) pins the signatures, so putting a Duration parameter back is a compile error. The guard's self-test still carries one fixture for each Acceptance-3 shape: a `Serve::Stall {`, a short `Serve::Trickle {`, a `Stall {` after `use Serve::*`, a `Trickle as` alias. A fixture of `fixture(&server, Duration::from_secs(2))` would pass the tripwire (exit 0 expected), and it stays in the self-test with a comment that says rustc refuses it. That keeps the self-test honest about where the decision is made.

**Proposed token list (decides_on).** Case-sensitive, because Rust identifiers are. Comments are included. Self-test fixtures: one violation dir per token; a comment hit; `-> Timeouts {`; `impl X for Timeouts {`; a `type T = Timeouts;` alias; `use ..::{Timeouts as T}`; `Default::default()`; `Serve::SilentHeaders {`; a nested `diag_support/` file; a `common_extra.rs` (only the top-level `common/` dir is exempt); `diag_support/common/` (not exempt). Allowed dirs: `Timeouts` only in type positions (`t: Timeouts`, `Option<Timeouts>`); `timeouts` in lower case (a field and variable name); `Serve::Full`/`Status`/`Redirect`; `TimeoutSettings` (outside this rule, see 3b); a `Stalled` / `Trickled` word, which the identifier boundary does not match. Cannot-run cases as in I1. The real tree is expected to exit 0. The bite run removes each token in turn from a copy of the tripwire and confirms the self-test goes red (Acceptance 4).

**Scope of the move.** 71 lines in 13 files plus 7 calls in `silero_model.rs` (listed in `evidence`). 13 of the 71 are comments (bite notes naming `Timeouts::default()`), which get reworded to say "the production defaults", as T-089 §7 did for I1. Values do not change. The existing per-file pins (`*_keep_the_in_time_margin_m`, `in_time_deadlines_of_this_file_*`, `download_limits_keep_the_in_time_margin_m`) read the moved constructors. The `silero_model.rs` fix is T-197's T-111 r2#2 item. It has to land here, because without it the tree does not build once `timeouts(no_data)` is gone. Overlap: T-175 (TODO, `depends_on: [T-111]`) touches `src-tauri/tests/dictation_e2e.rs` and `common::os_answer`, so whichever lands second rebases. T-149, T-166 and T-202 (analysing now) do not name core test files in their titles. I did not check their diffs.

**Residuals after T-165 (T1, review), to be listed in core-tests.md:** field mutation of a `Timeouts` after construction (#112); the settings route `TimeoutSettings` / `*_s` (unless the owner widens, see the question); `<_>::default()` or a generic `T::default()` inferred into `Timeouts`; a deadline built at run time from other parts; a wiremock `set_delay` / `common::Server` answer time on an in-time leg (that is an answer time, not a deadline: `late_answer` covers timeout legs); the units under `src`, `examples/`, `src-tauri/tests`; a new common function that takes a `Duration` into an in-time deadline (review of `tests/common`).

**Owner question (scope, a residual of the class):** should the settings route (`TimeoutSettings { .. }` and `s.timeouts.<role>_s = ..` outside `tests/common`, about 50 lines in 5 files) be (A) a named T1 residual in `core-tests.md`, which is the recommendation (its in-time legs are already pinned by `*_keep_the_in_time_margin_m`, and most sites have the setting as the subject), or (B) refused by this tripwire too (tokens `TimeoutSettings {`, `TimeoutSettings::`, `_s =`), with all those sites moved into `tests/common`, which roughly doubles the move?

**For the orchestrator (no owner decision needed):** the Acceptance still lacks the `timeouts(<duration>)` shape that T-111 r2#2 asked for under #224 (r3#4 and r4#3 say so). Suggested line: "- [ ] The `common::download::timeouts(<duration>)` call shape (T-111 r2#2, #224) does not compile outside `tests/common`; the seven `silero_model.rs` fetch legs take `in_time()`". Mark T-197's T-111 r2#2 item absorbed by T-165.
