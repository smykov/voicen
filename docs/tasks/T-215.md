## Context

Owner decision #288 (2026-11-15, "Только переменная"): the teamwright contour's pause is the same for every project on the runner pool — the repository variable `TEAMWRIGHT_CONTOUR_PAUSE`, which the owner sets with `gh variable set`. The runner-host file `/etc/teamwright/voicen.pause` (T-202, `TEAMWRIGHT_PAUSE_FILE` in the push step of `.github/workflows/teamwright-agent.yml`) is dropped: the runner pool is not changed and has no `/etc/teamwright` mount. No `TEAMWRIGHT_PAUSE` file in the base branch is added for the contour (the owner chose the variable only); the local `TEAMWRIGHT_PAUSE` at the repository root keeps its meaning for local sessions.

Reference implementation in sibling projects on the same pool (ecosystem-bots, elektrik-calc, spisok-pokupok): `.github/teamwright-agent/task_push.py`, `paused()`.

The contour workflows' headers and tails are byte-pinned (`scripts/ci/contour-heads/`, `scripts/ci/contour-upload.yml`, `scripts/ci/release-guard.test.sh`), so this is a guard change (`checker: true`, `analysis.decides_on`).

## Investigation

Tools: Serena was loaded but not used. The change touches only YAML, bash and markdown, which the language server does not index. I used grep and file reads: `grep -rn "TEAMWRIGHT_PAUSE_FILE\|/etc/teamwright\|CONTOUR_PAUSE"` over the tree except node_modules/target, plus `.github/workflows/teamwright-{agent,next}.yml`, `scripts/ci/release-guard.test.sh`, `scripts/hooks/pre-push`, `docs/process/gates.md`, `docs/decisions/ci-toolchain.md` and decisions #261/#288. Docs: context7 `/websites/github_en_actions` (contexts, workflow permissions).

**Frame.** Observed: the contour has a pause that can never fire. Its push step sets `TEAMWRIGHT_PAUSE_FILE: /etc/teamwright/voicen.pause` (teamwright-agent.yml push step env), and `pre-push` (lines 51-55) refuses only when that path exists. The JIT runner container has no `/etc/teamwright` mount: #261 never created it and #288 drops it. `teamwright-next.yml` reads no pause, so a paused contour keeps starting stages, ci.yml runs on `wip/<ID>` and PRs. Expected (#288 (b)): `vars.TEAMWRIGHT_CONTOUR_PAUSE` non-empty → no push, no dispatch, and one report line naming the pause.

**Hypotheses.**
1. *The pause reads a path the runner cannot see.* Confirmed: line 215 together with pre-push:51, #261 ("`/etc/teamwright` not created for now") and #288 ("no mount").
2. *A second path dispatches without a pause check.* Confirmed: next.yml 'Next stage' goes from input validation to `contour-busy.sh`, `gh workflow run ci.yml`, `gh pr create` and `gh workflow run teamwright-agent.yml` without reading any pause. The agent's chain step only reacts to a push that did not happen.
3. *This class was fixed before.* T-202 review 1 #2 found that the contour pause could not fire (the checkout never holds `TEAMWRIGHT_PAUSE`). It was fixed with the host file, which is the same defect one level down: a path outside the job's reach. #288 moves the control to where the job can read it, the run's own `vars` context. That is the root, not another patch.
4. *The pause should stay in pre-push (one gate).* Refuted as the seam: pre-push and `_hookio.py` are kit-owned (`.teamwright/installed.json`), and pre-push reads files, not variables. Bridging the variable into a temp `TEAMWRIGHT_PAUSE_FILE` in the step would keep the name in the workflow, which Acceptance 3 forbids.

**When the variable is read (limit).** GitHub interpolates `${{ }}` contexts "before the job is sent to a runner" (context7, use-variables), so a job sees the value from its own start. The `GITHUB_TOKEN` permission list has no variables scope (workflow-syntax `permissions`), so a running step cannot re-read the variable with the job token. Consequence: a pause set *during* a stage does not stop that stage's push. It stops the next `teamwright-next.yml`, which starts after the push and dispatches nothing. The sibling projects (`/projects/ecosystem-bots` workflows, lines 69/103 and 68/90) have the same limit. Document it under Not caught in ci-toolchain.md. A live read would need a PAT secret, which is out of scope for #288.

**Root cause.** See `analysis.root_cause`. It covers both symptoms: the push is not refused, and the dispatcher keeps going.

**Invariant / seam.** See the analysis block. The pushing step and the dispatching step check the pause themselves, before their first push/dispatch line. Nothing else pushes or dispatches in the contour: the stage session holds no token, and the chain step only starts next.yml.

**Options.**
- **A (recommended): variable in both workflows, checked in the acting step.**
  - Push step: `TEAMWRIGHT_CONTOUR_PAUSE: ${{ vars.TEAMWRIGHT_CONTOUR_PAUSE }}` replaces the `TEAMWRIGHT_PAUSE_FILE` line. Its first line after `set -euo pipefail` is `if [ -n "${TEAMWRIGHT_CONTOUR_PAUSE:-}" ]; then echo "paused=1" >> "$GITHUB_OUTPUT"; echo "::notice::..."; exit 0; fi`.
  - Chain step: gets `PAUSED: ${{ steps.push.outputs.paused }}`. When it is 1, it reports one line, "**T-NNN**: chain stopped: the contour is paused (repository variable TEAMWRIGHT_CONTOUR_PAUSE); task/T-NNN was not pushed. <run>", and exits 0 (a pause is not a failure). The existing not-pushed line (exit 1) stays for a pre-push refusal.
  - next.yml 'Next stage': the same env line. The check comes right after input validation: one `say` line, exit 0.
  - Economy: 'The task fits this stage' also refuses when paused, writing the sentence to `$OUT/preflight.md` (`mkdir -p "$OUT"` first), so the failure step's one line names the pause and no 4-hour session runs for a push that cannot happen.
  - Red test: the release-guard.test.sh expects in `decides_on` fail on today's files (no env line, no check, and the host-file line is present) and pass after. The mutation case covers Acceptance 4.
  - Risk: a mid-stage pause is not seen (above). Rollback: revert the commit.
- **B: only next.yml checks** (no push-step check). Smaller, but a stage dispatched before the pause, or started by hand, still pushes. Acceptance 1 and 4 fail. Rejected.
- **C: the step writes a temp pause file and sets `TEAMWRIGHT_PAUSE_FILE` to it** (pre-push stays the one gate). The name stays in the workflow against Acceptance 3, and the check gets an indirection the guard test must model. Rejected.

**Scope of Acceptance 3 (for the orchestrator, not an owner question).** `TEAMWRIGHT_PAUSE_FILE` is also the generic local override: pre-push and `_hookio.py` (kit-owned), `scripts/tw-wip-push`, `scripts/tw-wip-run`, their tests `scripts/ci/tw-wip-{push,run}.test.sh`, and the gates.md lines for the "What it blocks" list and the env table. #288 concerns only the contour, so those stay. The removal covers `.github/workflows/`, the release-guard.test.sh pin and the contour text in gates.md ('Pausing the contour') and ci-toolchain.md. CLAUDE.md has no occurrence today (grep). Recommended: read Acceptance 3 as "no contour use", and say so in the review. This also closes T-202 follow-ups v2#2 and r2#11.

**Guard change.** release-guard.test.sh is under `scripts/ci/`, so `checker: true` stays and `decides_on` is filled. Copy it into the `check-release-guard` row of the guard table in `docs/decisions/ci-toolchain.md` in the same commit. T-216 (same files) is DONE, so there is no overlap left.

**Owner questions:** none. #288 settles the mechanism. The mid-stage limit follows from GitHub's context semantics, and it gets documented, not decided.
