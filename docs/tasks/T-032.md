## Context

Split from T-003 by decision #23. It builds on T-003's types (`Settings`, `defaults()`, `validate`, `secrets`, the `HotkeyRegistrar` / `DownloadedModels` traits with fakes behind `test-fakes`) and adds:
- `settings::file`: `SettingsFile` trait plus the std-fs implementation over a given directory, with an atomic write (tmp + sync + rename, a leftover `.tmp` deleted and never parsed) and `move_aside` that never overwrites a backup.
- `settings::service`: `SettingsService` with `load_or_init` (FirstRun / Loaded / Reset / Unavailable), `snapshot`, `view`, `save` (validate → keys → file → commit, reverse undo on failure; the hotkey step stays a no-op until T-010, and there is no autostart step until T-014), and `subscribe` on std `mpsc` (decision #22).

The test plan is in T-003's analysis approach, AC2/AC4 file and service parts and the live-apply part (T034): `first_run_writes_defaults`, `write_atomic_*`, `failed_write_keeps_previous_file`, `save_round_trips_through_a_new_service`, `save_never_writes_key_bytes`, `refused_save_changes_nothing`, `file_write_failure_restores_keys`, `key_store_failure_refuses_with_key_store_failed`, `undo_failure_reports_partially_restored`, `unreadable_file_reset`, `move_aside_never_overwrites_existing_backup`, `move_aside_failure_is_unavailable`, `read_io_error_is_unavailable`, `save_refused_while_unavailable`, `subscriber_receives_snapshot_after_saved`, `refused_save_sends_nothing`, `earlier_snapshot_unchanged`, `dropped_receiver_does_not_fail_save`. Decision #23 N5: defaults that cannot be written at FirstRun/Reset keep the outcome, and the next save retries. `save` stores the normalized values (base URLs through `check_base_url`, spec 004 data-model "normalize before store") — from T-003 review round 1 #9.

## Acceptance

- [ ] A fresh data folder yields the FR-21 v4 defaults, which are written to `settings.json`
- [ ] A valid save persists atomically (tmp + rename) and a new `SettingsService` over the same folder returns the same values; key bytes never appear in `settings.json`
- [ ] After `Saved`, every subscriber receives the new snapshot; a refused save sends nothing; a snapshot already handed out never changes
- [ ] A key `Replace` that is empty after Unicode trim is never written in any slot: it is treated as `Untouched`, so the stored key stays (decision #30); only `Clear` deletes
- [ ] Failure branch: a refused save (validation, key store failure, file write failure) leaves the file bytes, `snapshot()` and every key slot as before (reverse undo); an unreadable file is kept as `settings.json.bad-<UTC>` (never overwriting a backup), and defaults are loaded with a reset notice; the file cannot be moved aside, or a read fails with an I/O error other than not-found → `Unavailable`: defaults in memory, the file neither written nor moved, every save refused with `notice.settings_unavailable`, the credential store never called (decision #19) — verified by core tests on a temp dir
- [ ] Test that fails without the change: `crates/voicen-core settings::file / settings::service tests and tests/settings_apply.rs`

## Investigation

Investigator, 2026-10-03.

**Tools.** Serena and context7 were not connected in this session (no `mcp__*` tools), and Serena indexes TypeScript only anyway (decision #3). I used grep and file reads for Rust. Library facts come from the std 1.99.0 docs fetched from doc.rust-lang.org (`fs::rename`, `OpenOptions::create_new`). The image has no `rust-src`. Baseline: `scripts/tw-run core -- cargo test -p voicen-core` gives 73 unit + 7 integration + 2 doc tests, all green.

### Frame

- **Observed:** core has `Settings`, `defaults()`, `validate`, `check_base_url`, the gate, `secrets` and the fakes (T-003). Nothing reads or writes `settings.json`, produces a `LoadOutcome`, runs a save or publishes a snapshot. `settings/{file,service}.rs` and a clock are absent.
- **Expected:** the Acceptance of this task, i.e. spec 004 FR-003 and FR-008 to FR-010, R-2, R-3 and R-4, decisions #19, #22, #23 N5 and #30, and data-model "normalize before store". All of it must be provable on the Linux gate with fakes and a real temp dir.
- **Where:** everywhere. This is a new capability.

### Hypotheses

1. **Part of the file or service already exists.** Refuted: `ls` and grep (above) found nothing.
2. **The same concern is handled on a second path.** Refuted in code. grep for `settings.json`, `CredWrite`, `CredRead` and `credential` in `src-tauri/src` and `src` finds nothing. Spec 001's own loader and key port were removed by #21. The paths that will need this seam are listed in `seam`. An empty grep is not proof for future code, so the reviewer of T-030, T-006 and T-001 checks that none of them opens `settings.json` or calls `write`/`delete` on `CredentialStore`.
3. **This class was fixed before.** Refuted. See the Recurrence check.
4. **T-003's rules are enough for the save.** Refuted in two places.
   - `validate` treats a blank `Replace` as "not entered" (`validate.rs:29-35`) but cannot stop the save step from writing it. #30 makes that rule T-032's.
   - The trim and one-`/` rule lives only inside `check_base_url` (`url.rs:32-37`), which returns nothing for an invalid URL. An unselected engine's URL, which is never validated (Q2), therefore has no normalizer.
5. **std gives a no-clobber move.** Refuted. `fs::rename` "replac[es] the original file if `to` already exists" on Unix and on Windows (1.99 docs), so a plain rename into a backup name could destroy an earlier backup. `OpenOptions::create_new` is atomic and fails with `AlreadyExists`, which is the primitive used below.

### Settled design (not left to the developer)

**1. `SettingsFile`: the contract shape, unchanged.**
- The trait is `read() -> io::Result<Option<Vec<u8>>>`, `write_atomic(&[u8]) -> io::Result<()>` and `move_aside(suffix: &str) -> io::Result<String>`, with `Send + Sync`.
- `FsSettingsFile::new(dir: PathBuf)` owns `pub const SETTINGS_FILE: &str = "settings.json"`. The tmp name is `settings.json.tmp`. The backup prefix is `settings.json.bad-`.
- `read`: first a best-effort `remove_file` of a leftover `.tmp`, with any error ignored. The `.tmp` is never opened for reading. Then `fs::read`. `NotFound` → `Ok(None)`; any other error → `Err`, which includes a directory at `settings.json`.
- `write_atomic`: `create_dir_all(dir)`, `File::create(tmp)`, `write_all`, `sync_all`, then `rename(tmp, settings.json)`. On any error, best-effort `remove_file(tmp)`, then return the error.
  - Creating the directory removes the "directory missing" failure instead of reporting it. The shell still resolves the path (P-010).
  - There is no directory fsync: R-2 does not ask for one, and std cannot open a directory on Windows.
- `move_aside(suffix)`, for each candidate in `settings.json.bad-<suffix>`, then `-1` … `-9`:
  - `OpenOptions::new().write(true).create_new(true).open(candidate)` reserves the name. `AlreadyExists` → next candidate; any other error → `Err`.
  - Then `rename(settings.json, candidate)`. That overwrites only the empty file just reserved.
  - If the rename fails, best-effort `remove_file(candidate)` and return `Err`; `settings.json` stays in place. If all 10 names are taken, return `Err(AlreadyExists)`.
  - The result is a real move: no copy, and no hard links (which would depend on the file system). It relies on the same rename-over-existing primitive that `write_atomic` needs, which T-030 Acceptance 2 proves on Windows.
- `FakeSettingsFile` (behind `test-fakes`) holds bytes in memory, keeps a call log (`Read`, `WriteAtomic`, `MoveAside(suffix)`), lets a test inject `read` errors of any `io::ErrorKind`, `write_atomic` failures and `move_aside` failures, and lets a test see the bytes stored and the backups made.

**2. `load_or_init(deps, os_language) -> (Self, LoadOutcome)`.**
- `read` returns `Err` → `Unavailable(defaults(os))`. The service is marked unavailable for life, with no further file call.
- `Ok(None)` → `FirstRun(defaults(os))`, and the defaults are written.
- `Ok(Some(bytes))` and `serde_json::from_slice::<Settings>` succeeds → `Loaded(s)`. Settings are not validated or rewritten at load: only a parse failure makes a file unreadable (R-2). A hand-edited invalid value is caught at the next save.
- The parse fails:
  - `move_aside(utc_compact(clock.now()))` returns `Err` → `Unavailable(defaults)`.
  - It returns `Ok(name)` → `Reset { defaults, backup_file_name: name }`, and the defaults are written.
- A failed defaults write keeps `FirstRun`/`Reset` (#23 N5). Every save writes the whole file, so the next save is the retry without any extra state.
- No branch calls the credential store.

**3. `save(req) -> SaveOutcome`: order and reverse undo.** One `Mutex<()>` serializes saves for the whole call (R-3). Steps:
- (0) Unavailable → `Refused { errors: [], form_error: Some(FormError::SettingsUnavailable) }`. No dependency is called.
- (1) `normalize` the settings (point 6).
- (2) Read the three slots in `KeySlot::all()` order. These values are kept for undo and give the `KeyPresence` for `validate`. A read error → `Refused { [FieldError { <slot key field>, KeyStoreFailed }], None }`; nothing has been written.
- (3) `validate(&normalized, &KeyEditsWithPresence { edits: &req.keys, presence }, local_models)`. Errors → `Refused { errors, None }`.
  - `validate` sees the raw edits, so a blank API `Replace` with engine `api` is still `key.required` (#27(1), #28(b)).
- (4) Hotkey step: a no-op. `hotkeys` is held and never called; T-010 inserts prepare/abort/commit here.
- (5) Keys, in `KeySlot::all()` order, with the effective edit:
  - A `Replace` that is empty after `trim()` becomes `Untouched` (#30). It is never written, in any slot.
  - A non-empty `Replace` → `write(slot, secret)`, with the secret stored as entered. `Clear` → `delete(slot)`. `Untouched` → no call.
  - Each completed step is pushed as `(slot, old_value)`.
  - On a failure at slot *k*: undo, then `Refused { [FieldError { key field of k, KeyStoreFailed }], form_error }`.
- (6) `write_atomic(serde_json::to_vec_pretty(&normalized))`. On failure: undo, then `Refused { [], Some(FormError::WriteFailed) }`.
- (7) Commit:
  - Swap `RwLock<Arc<Settings>>` to the new `Arc`.
  - `subscribers.retain(|tx| tx.send(arc.clone()).is_ok())`, which prunes dropped receivers without failing.
  - Return `Saved { view, warnings: vec![] }`.
  - `view` presence is computed from the reads plus the effective edits, with no extra credential call.
- **Undo** walks the completed steps in reverse. `old Some(v)` → `write(slot, v)`; `old None` → `delete(slot)`. It continues after an undo error and collects the slots whose undo failed.
  - If any undo failed, `form_error` becomes `Some(FormError::PartiallyRestored { not_restored: Vec<FieldId> })`, holding the key field ids of exactly those slots. It replaces `WriteFailed` and is added beside a `key.store_failed` field error.
  - The file and `snapshot()` are still unchanged: the file was never written, or `write_atomic` failed, which leaves the old file by (I3). The slots named in `not_restored` are the only state that differs, as R-3 documents.

**4. `FormError` instead of data-model's `MessageRef`.**
- `enum FormError { WriteFailed, SettingsUnavailable, PartiallyRestored { not_restored: Vec<FieldId> } }` with `message_id()` → `SETTINGS_WRITE_FAILED`, `NOTICE_SETTINGS_UNAVAILABLE` or `SETTINGS_PARTIALLY_RESTORED`.
- The step is named structurally, by field ids, which are safe to show and log (R-11) and which the UI can highlight. The catalog texts have no placeholders.
- data-model.md (`SaveOutcome`) is updated in the same commit (P-014).

**5. Clock and the `<UTC>` suffix: std only, no new dependency.**
- `crates/voicen-core/src/clock.rs`: `pub trait Clock: Send + Sync { fn now(&self) -> SystemTime; }`, `SystemClock`, and `FakeClock::at(SystemTime)` behind `test-fakes`.
- `pub fn utc_compact(t: SystemTime) -> String` gives `yyyyMMdd-HHmmss`. It takes `duration_since(UNIX_EPOCH)` (a time before the epoch clamps to 0), then converts days to a civil date with the standard days-from-civil inverse, about 15 lines.
- It lives at the crate root rather than in `service.rs`, so history (005) and the connection tester (R-9) reuse one wall-clock port (P-011). core-traits.md is updated.
- Correction to the brief: chrono **is** consented by #9 (decisions.md:19). It is only absent from `voicen-core/Cargo.toml`, so using it would need no owner question. I recommend std anyway: one format, no new crate in the core build, and no `make licenses` churn. If the reviewer prefers chrono, `chrono = { version = "0.4", default-features = false, features = ["std"] }` is allowed without asking.

**6. Normalize before validate and store** (data-model; T-003 review 1 #9).
- In `url.rs`, extract `pub fn normalize_base_url(raw: &str) -> &str` (trim, then strip one trailing `/`). `check_base_url` calls it, so there is one rule.
- `normalize` applies it to `api.base_url`, `local_server.base_url` and `post_processing.base_url`, whether or not the engine is selected or the URL is valid. It trims `api.model`, `local_server.model` and `post_processing.model`, and sets `schema_version = SCHEMA_VERSION`, since a loaded `0` is written back as `1`.
- Not touched: the hotkey (strict canonical text, #26), `speech_language` (exact match), the prompt and the microphone.

**7. `view()` and flags.**
- `SettingsView { settings, keys: KeyPresence, first_run, reset_notice }` derives `Serialize`, which the no-key-bytes test needs.
- `keys` comes from three `read`s, and a read error counts as `false`. While Unavailable, `view()` makes **no** credential call and reports all `false`. That is the literal reading of #19 and of the Acceptance "the credential store never called".
- `first_run` and `reset_notice` reflect the load outcome for the life of the service, and a save does not clear them. How the UI shows them is T-004's.

**8. `subscribe` and live apply: core vs shell.**
- Core (this task, spec T015 and the core part of T034):
  - `subscribe() -> mpsc::Receiver<Arc<Settings>>` over an unbounded std channel. It sends no initial value; a consumer calls `subscribe()` then `snapshot()`, so no save is missed.
  - Publishing happens only in the commit, under the save lock.
  - `SettingsService: Send + Sync` (a compile-time assertion).
  - The tests in `tests/settings_apply.rs`.
- T-030 (shell): the `settings://changed` event with `view()` after `Saved`, the tray rebuild and notifier language, the data-dir → `FsSettingsFile::new` wiring, and the serde wire form of `SaveRequest` (`KeyEdit`/`Secret` deserialize), `SaveOutcome`, `FieldError` and `MessageId` per ipc.md. It may add core unit tests for the wire form, which run on the Linux gate.
- 001, 002 and 005 wire their own subscribers (spec T042). T-015 fills `warnings` (`Warning { field, code: EndpointInsecure }` is declared here and always empty). T-008 adds the R-11 log lines.

**9. Message ids (#23 N3).** `SETTINGS_WRITE_FAILED`, `SETTINGS_PARTIALLY_RESTORED` and `NOTICE_SETTINGS_UNAVAILABLE` go into `messages!` (`i18n.rs:61`) and into both `i18n/en.json` and `i18n/ru.json`. `message_ids_exist_in_both_catalogs` is the gate. `notice.settings_reset` stays with T-004 (spec T025/T027, shell executor).
