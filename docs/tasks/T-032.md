## Context

Split from T-003 by decision #23. It builds on T-003's types (`Settings`, `defaults()`, `validate`, `secrets`, the `HotkeyRegistrar` / `DownloadedModels` traits with fakes behind `test-fakes`) and adds:
- `settings::file`: `SettingsFile` trait plus the std-fs implementation over a given directory, with an atomic write (tmp + sync + rename, a leftover `.tmp` deleted and never parsed) and `move_aside` that never overwrites a backup.
- `settings::service`: `SettingsService` with `load_or_init` (FirstRun / Loaded / Reset / Unavailable), `snapshot`, `view`, `save` (validate → keys → file → commit, reverse undo on failure; the hotkey step stays a no-op until T-010, and there is no autostart step until T-014), and `subscribe` on std `mpsc` (decision #22).

The test plan is in T-003's analysis approach, AC2/AC4 file and service parts and the live-apply part (T034): `first_run_writes_defaults`, `write_atomic_*`, `failed_write_keeps_previous_file`, `save_round_trips_through_a_new_service`, `save_never_writes_key_bytes`, `refused_save_changes_nothing`, `file_write_failure_restores_keys`, `key_store_failure_refuses_with_key_store_failed`, `undo_failure_reports_partially_restored`, `unreadable_file_reset`, `move_aside_never_overwrites_existing_backup`, `move_aside_failure_is_unavailable`, `read_io_error_is_unavailable`, `save_refused_while_unavailable`, `subscriber_receives_snapshot_after_saved`, `refused_save_sends_nothing`, `earlier_snapshot_unchanged`, `dropped_receiver_does_not_fail_save`. Decision #23 N5: defaults that cannot be written at FirstRun/Reset keep the outcome, and the next save retries. `save` stores the normalized values (base URLs through `check_base_url`, spec 004 data-model "normalize before store") — from T-003 review round 1 #9.

## Acceptance

- [ ] A fresh data folder yields the FR-21 v4 defaults, which are written to `settings.json`
- [ ] A valid save persists atomically (tmp + rename) and a new `SettingsService` over the same folder returns the same values; key bytes never appear in `settings.json`
- [ ] After `Saved`, every subscriber receives the new snapshot; a refused save sends nothing; a snapshot already handed out never changes
- [ ] A key `Replace` that is empty after Unicode trim is never written in any slot: it is treated as `Untouched`, so the stored key stays (decision #30); only `Clear` deletes
- [ ] Failure branch: a refused save (validation, key store failure, file write failure) leaves the file bytes, `snapshot()` and every key slot as before (reverse undo); an unreadable file is kept as `settings.json.bad-<UTC>` (never overwriting a backup), and defaults are loaded with a reset notice; the file cannot be moved aside, or a read fails with an I/O error other than not-found → `Unavailable`: defaults in memory, the file neither written nor moved, every save refused with `notice.settings_unavailable`, the credential store never called (decision #19) — verified by core tests on a temp dir
- [ ] Test that fails without the change: `crates/voicen-core settings::file / settings::service tests and tests/settings_apply.rs`
