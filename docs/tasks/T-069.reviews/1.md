The new check accepts only Win32 1168, so the "gone" assertions (`:226-227`, `:286-290`, `:368-373`) are stricter. The "present" assertions (`r.is_ok()`) mean the same as `raw_exists == true`. No assert was removed, and no skip or ignore was added. The `Planted::add` premise still panics with no retry.
4. **Every test takes `serial()` first.** Checked by reading. In `purge_credentials.rs` all 9 `#[test]` fns do (`:202`, `:250`, `:263`, `:295`, `:347`, `:399`, `:427`, `:452`). In `credentials.rs` all 5 do (`:146`, `:195`, `:210`, `:232`, `:249`). In every test `_serial` is declared before `Planted` / `_cleanup`, so cleanup deletes run under the lock, also during a panic unwind. `Planted::add` panics with `premise_failure` (`:181-183`). I checked that call site, since no test covers it.
