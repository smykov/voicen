## Context

Routed by decision #40 (T-004 review round 1 #6). The page side of T-037's `settings_window::open(tab, field)` and the rest of spec 004 T036 that T-004 left out: the `/settings` page focuses the control with `data-field=<field>` (switching to its tab) from `?field=` on load and on a `settings://focus {tab, field}` event; closing the window with a dirty draft asks whether to discard (needs T-037's capability for `core:window:allow-destroy` and the close request); and every field of the `SettingsView` the release-1 tabs own is rendered and round-trips through `settings_save` (spec T036). Verified with Playwright on the built UI over `e2e/support/tauriMock.ts`.

Also routed here from T-004 review round 2 (Lows): (1) `not_restored` fields that are not rendered on the current page (e.g. `engine.api.key` while another engine is selected, `general.start_with_windows` until T-034) are listed by label in the form-level message — the Open item in `docs/decisions/settings-ui.md`; (2) `docs/decisions/i18n.md` says there is no string-typed renderer, but `text(catalog, lang, id: string)` is still exported from `src/lib/i18n/index.ts` — narrow it to the module or make the wording true; and update the stale red-phase header of `src/lib/i18n/ids.test.ts` (it still allows `` `error.${string}` ``, which i18n.md forbids).

## Acceptance

- [ ] `/settings?tab=recording&field=recording.hotkey` opens the Recording tab with the hotkey control focused; a `settings://focus {tab, field}` event does the same on an open page
- [ ] Closing the window with a dirty draft asks to discard; "keep editing" keeps the window and the draft, "discard" closes it; a clean draft closes without asking
- [ ] Every field the release-1 tabs own (Engine, Recording, Output, History, General) is rendered from the view and sent unchanged in `settings_save` when untouched (one Playwright case over the core-synced fixture)
- [ ] Failure branch: a `field` that names no control on the page focuses nothing and shows no error; the page still opens on the requested tab (or Engine)
- [ ] Test that fails without the change: a new Playwright spec for focus, discard and the field round-trip

## Investigation

Tools: no `mcp__serena__*` or `mcp__context7__*` tools were exposed in this session. I used grep and file reads over `src/`, `e2e/`, `src-tauri/`, `crates/voicen-core/src/` and `i18n/`. For the Tauri API I read the pinned sources: `node_modules/@tauri-apps/api` 2.12.1 (`window.js`, `event.js`) and the tauri 2.12.1 crate in `.teamwright/cache/core/.../tauri-2.12.1`.

- **Focus.** The shell always sends `tab` together with `field`, in the URL and in the event (`settings_window.rs:39-41,60-63`). The page shows only the active tab, so the order is: set the tab, wait for the render (and for `draft`, since the controls appear only after `settings_get`), then match `[data-field]` by `dataset.field === field`. Do not use `controlId`: it maps `-` and `.` to the same id. Do not build a selector: an arbitrary `?field=` would make it throw. Taking the tab from the FieldId prefix would be a second rule beside the shell's (U1), so the requested tab is used. A field on another tab focuses nothing.
- **Close.** tauri prevents the native close whenever a JS `tauri://close-requested` listener exists (`manager/window.rs:177-181`). Then `onCloseRequested` calls `destroy()` unless `preventDefault()` ran before the handler resolved (`window.js:2028-2036`). So: call `preventDefault()` synchronously when dirty, then call `destroyWindow()` from the dialog's "discard" button. Never call `close()`: it emits close-requested again, and `core:window:allow-close` is not granted. A handler that throws leaves the window impossible to close, so it must not throw. A clean close also goes through `plugin:window|destroy`, so the mock needs that command for both paths. Its listen already ignores `target`, and `metadata.currentWindow.label` is already `settings`.
- **Round trip.** Today `saveRequest` copies `draft.settings` whole (`draft.ts:116-118`). The test catches a control that rewrites a value when it mounts or when the user switches tabs (History `$effect.pre`, the speech-language select before `settings_speech_languages` answers). That works only if every value differs from core's defaults, hence the non-default literal, whose keys are checked against the core-synced fixture.
- **Labels.** The existing label ids cannot serve: they are shared across fields (`settings.field.base_url`, `settings.field.key`) and depend on context. A hand-kept TS FieldId → label table would be a second copy of the enum (P-010). A rule-built id, `settings.field_label.<FieldId>`, backed by a core completeness test, is the same pattern as `error.<code>`. It shares that pattern's documented weakness: the list in the test is kept complete by hand.
- **Size.** Parts 1–3 and 5 are one seam (`settingsApi.ts` plus the page; the i18n module for 5). Part 4 also touches core (the test, a `cfg(test)` `FieldId::ALL`) and both catalogs.
- **Owner questions (none blocking):**
  - (Q1) Part 4 relaxes the i18n.md rule of "one cast" to two casts, each backed by a core test, and adds core work to a `surface: ui` task. Default: do it here. Alternative: split it into its own task and point the settings-ui.md Open item at that task.
  - (Q2) The discard dialog is in-page (`role="alertdialog"`, en/ru ids), not tauri's dialog plugin, which is neither a dependency nor granted. Default: in-page.
- **Recurrence:** none. `docs/failures.md` has F-001…F-003 (classes `ci-toolchain`, `guard-model`) and no entry in class `settings-ui`.
