## Context

Decision #272. The contour review of T-188 (run 43148171046) ran without Serena. The session's init line shows `serena` `connected`, but its only Serena tools were `mcp__serena__initial_instructions` and `mcp__serena__serena_repl`: the runner image `gha-runner:2.338.1-e-claude` has no `/root/.serena/serena_config.yml`, so Serena 2.1.1 starts with its default REPL interface. The role files (`.claude/agents/**`, pinned by `scripts/ci/role-heads/`) allow `mcp__serena__find_symbol`, `find_referencing_symbols`, `get_symbols_overview`, … — tools that exist only with `agent_interface: tools`, which the VPS sets in `~/.serena/serena_config.yml`. So every role agent spawned in the contour had no Serena tool at all and fell back to grep.

Possible seams (the analysis decides): the runner image (`/opt/gha-pool/Dockerfile.voicen`, the owner's infrastructure on VM 105: a `serena_config.yml` with `agent_interface: tools`), the `serena` entry of `.mcp.json` or the contour workflow's MCP step (`.github/workflows/teamwright-agent.yml` › `MCP servers and toolchain images`; header pinned by `scripts/ci/contour-heads/`, `.github/` closed to contour sessions), or the project's `.serena/project.yml` (untracked today, so absent in a contour checkout).

## Acceptance

- [ ] A contour stage session's init line lists `mcp__serena__find_symbol` (and the other Serena tools the role files allow), not only `serena_repl`
- [ ] A role agent spawned in a contour session (e.g. `code-reviewer`) calls a Serena tool successfully; its record does not say "Serena not reachable"
- [ ] Failure branch: when `serena` is missing on the runner, the MCP step still takes its grep fallback with the `no serena on the runner` warning (unchanged)
- [ ] Local sessions on the VPS keep the classic tools (their behaviour unchanged)
- [ ] `docs/decisions/context-tools.md` names the interface requirement
