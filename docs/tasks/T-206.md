## Investigation

context_tool: builtin. The change is YAML, shell and docs, and the configured Serena (Rust-only) does not index them. I used grep and file reads over .github/workflows, scripts/ci, scripts/hooks, the Makefile and docs. docs_tool: context7 /actions/upload-artifact/v4.

**Frame.** Observed: run 42871509840 failed in "The stage" and no transcript is kept anywhere. Expected: every run leaves its session readable for a short time. It reproduces on every run in the ephemeral container, success or failure: the keep step cannot store anything there.

**Hypotheses.**
1. The keep step writes to a host dir that is not there and exits 0. Confirmed: teamwright-agent.yml job env `RUNS_DIR`, keep step `[ -d "$RUNS_DIR" ] || exit 0`, every `cp` ending in `2>/dev/null`, then `exit 0`.
2. A second path keeps the session. Refuted: no other step reads `$OUT`, except "Chain: the stage failed", which reads only `preflight.md` and `questions.md` into the step summary. There is no other upload, because R9 allows only one in the dir.
3. The session left no file. Refuted by the workflow text: the stage step redirects stream-json to `$OUT/session.jsonl` before claude starts, so a partial stream exists even on exit 1. The content of this run's file is unknown because it is gone.
4. Fixed before. T-202 review 1 finding 5 (Low) changed only what is copied (the whole `~/.claude/projects`), not where it goes. Not a recurrence class.

**What the session leaves** (workspace, gitignored or excluded):
- `.teamwright-agent/`: `session.jsonl` (the main session's stream-json with `--verbose`), `preflight.md`, `image-<area>.log`, `pnpm.log`, `questions.md`.
- `.teamwright/logs/`: the hook journal (`tools.jsonl`, `perms.jsonl`, `outcomes.jsonl`, `gates.jsonl`) and the gate and test logs.
- `$HOME/.claude/projects/<slug>/`: the CLI's own transcripts, subagents included. I did not check whether stream-json carries subagent turns.

**Guard constraints found.**
- R9 (raw `upload-artifact` exactly once dir-wide = `release-upload.yml`) refuses any contour upload. This is the guard change, and the reason for `checker: true`.
- R11 is already satisfied: the owned line `      - uses: actions/upload-artifact@v4` is in `action-lines.txt`.
- R4: `secrets.` is allowed in teamwright-agent.yml only as `secrets.CLAUDE_CODE_OAUTH_TOKEN`. The scan step may name it, and nothing forbids it. `secrets.TELEGRAM_` stays only in `telegram-send-step.yml`, which is R10 and untouched.
- release-guard.test.sh real pin: `github.token` only after "Did the stage commit?". The new steps are at the end, so it holds.
- ci-toolchain.md "Don't … upload any other artifact" must be amended in the same commit; decision #265 is the owner's basis.

**Scan without printing.**
- The values come only through the step's own `env:` (GitHub masks them in the log anyway).
- `grep -a -r -l -F -f <(printf '%s\n' ...)`: printf is a builtin, so no argv carries the value. The step prints only the number of matching files, never names or lines, because names are chosen by the session.
- A second grep runs over the `find` output of the file names.
- Empty values are dropped: an empty pattern line matches everything. The step refuses when the job token value is empty.
- No `set -x`.
- The scan runs on the staged copy, and the upload takes exactly that copy, so what is uploaded is what was scanned.
- `ACTIONS_RUNTIME_TOKEN` is given to actions, not to run steps. I did not verify this against GitHub's docs, so it is not scanned.

**Residual risk (public repo).** Anyone can download the artifact for 3 days. The transcript holds what the session read or ran: repo files (public anyway), command output, host paths, `docker info`, and anything the session printed from the runner host. The OAuth value is the one secret the session holds, and the exact-value scan covers it. Not covered: other host secrets the session could read as the runner's OS user (runner registration files, `~/.ssh`, files under `~/.claude`). How to bound it:
- copy regular files only, never follow symlinks;
- never copy `~/.claude` beyond this checkout's project dir (owner question 2);
- an optional format belt (owner question 1);
- a size cap on staging (e.g. 200 MB, refuse above it).
A leftover session process can rewrite the staging copy between scan and upload. That is the same limit as R14's "process the session leaves running", closed only by a separate OS user.

**Recommended exit**: not an rca task. The fix is code in one seam: the owned tail of teamwright-agent.yml plus R9 per name.

**Questions for the owner.**
1. Should the scan also refuse on known secret formats (private-key header, `ghp_`/`ghs_`/`github_pat_`, `sk-ant-` long runs), not only the job's own values? Recommended: yes. Cost: a fake token read from a fixture refuses that run's upload.
2. Should the artifact also carry this checkout's `~/.claude/projects/<slug>/` (subagent transcripts)? Recommended: yes, only that dir, scanned the same way. If no, only `.teamwright-agent/` and `.teamwright/logs/` go up, as Acceptance says.
3. Retention: 3 days (the Acceptance maximum)? Recommended: 3.
