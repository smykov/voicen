- [ ] `make check` stays green, including the mingw build of `check-shell-windows` (T001)

The diff changes comments and docs only (the `docker/rust.Dockerfile` comment plus a cmake bullet in `docs/decisions/ci-toolchain.md`). The apt line is unchanged.
- **Acceptance 1:** `make core-image` (exit 0, image rebuilt with the new comment), then `scripts/tw-run core -- cmake --version` → `cmake version 3.25.1`.
- **Acceptance 2:** `make check` on base b4cc5c2 plus the uncommitted diff → exit 0. That covers 884 cargo tests passed, 0 failed, 0 ignored, the 238 Playwright e2e tests passed, and `check-shell-windows` (both `cargo check -p voicen --target x86_64-pc-windows-gnu` invocations, without and with `--tests`). `git status --porcelain` was the same before and after the gate, so the gate changed no tracked files.
- CI: pending (P-016 `wip/T-115` run, orchestrator).

## Investigation

**Frame.** Expected per T001/R5: the core image lacks `cmake` and must gain it. Observed: it already has it.

**Evidence.**
- `docker/rust.Dockerfile` line 13 installs `cmake` together with `clang libclang-dev gcc-mingw-w64-x86-64-win32` in one `apt-get install --no-install-recommends`, then removes the apt lists. `git log -S cmake -- docker/rust.Dockerfile` shows it was added in the walking skeleton 0afeaf3, and T-056 (c544f08) kept it.
- How versions are pinned: the base image tag `rust:1.99-bookworm` fixes the Rust toolchain and the Debian suite. No apt package carries a version. `cargo-about` is the only tool with an explicit pin (`--version 0.9.2` plus a version check).
- The local image `voicen-rust:1.99` was created 2026-10-08, after the last Dockerfile commit (2026-10-05). Its `docker history` has the same RUN line. `docker run --rm voicen-rust:1.99 sh -c 'cmake --version; dpkg-query -W cmake'` printed `cmake version 3.25.1` / `cmake 3.25.1-1`. This was one light container run, not a build.
- Drift: the Dockerfile comment (lines 5-11) and `docs/decisions/ci-toolchain.md` (check-shell-windows decision, "The `voicen-rust:1.99` image carries" bullets) name only mingw gcc/windres and the `x86_64-pc-windows-gnu` target. CLAUDE.md and `docs/architecture.md` name only the image. None of them says that cmake is there or why, which is how R5 and decision #186 came to treat it as missing.
- cmake-rs (Cargo.lock `cmake` 0.1.58) already has two consumers, aws-lc-sys and whisper-rs-sys. On the Linux gate whisper-rs-sys skips cmake (`DOCS_RS=1`).

**mingw path.** `check-shell-windows` runs `cargo check -p voicen --target x86_64-pc-windows-gnu` (with and without `--tests`), and `src-tauri` depends on `voicen-core`. Once T-116 adds `opus` (bundled), its build script will run cmake with mingw gcc under `cargo check` as well, so the same apt `cmake` serves both paths (R5 confirmed). A risk for T-116, not this task, is unproven here: `.cargo/config.toml` `[env]` forces MSVC `CMAKE_*` values with `force = true` for every build script, on Linux too. Whether opusic-sys or CMake picks them up for the native or gnu build must be checked in T-116. Separately, libopus 1.6.1's `cmake_minimum_required` was not read (the crate is not in any local cache) and must be checked against 3.25.1 in T-116.

**Hypotheses.**
1. cmake is absent and needed. Refuted by line 13 and the image run.
2. cmake is installed but the built image is stale. Refuted: the image is newer than the last Dockerfile change and has the RUN line.
3. A second path installs tools (CI builds its own image). The CI gate runs the same `make core-image` (ci-toolchain.md), so there is a single seam.
4. This class was fixed before. See Recurrence.

**Guard path.** None. Only `docker/rust.Dockerfile` (comment) and `docs/decisions/ci-toolchain.md` change. Neither is under `scripts/ci/**`, `scripts/licenses/**`, `Makefile` or `*.mk` (tasks.md Markers; contracts/installer-ci.md "Guard and owned files"). `checker: false` is correct and `decides_on` is not required.

**Recurrence.** `docs/failures.md` has no entry on the core image, cmake or a missing toolchain package (searched `cmake`, `Dockerfile`, `core image`, `core-image`, `image`; the only image hits are F-010/F-011, both in the ui/CI area). This is not a recurrence. The mechanism is close to docs drift (an undocumented image component), but no F-entry exists for it.

**Approach.** See `analysis.approach`. The task is effectively docs-only, plus one cited `scripts/tw-run core -- cmake --version` run. Because the diff stays outside code but touches `docker/`, P-016 still asks for a `CI:` line (the diff is outside `docs/**`). The orchestrator may instead close the task as already satisfied and move the comment and doc line into T-116 (option C).
