## Verdict rationale

The design follows the analysis seam and invariants. `set_overlay` only writes to a mutex mailbox and notifies a condvar. Every build, emit and destroy runs on one "overlay" thread that holds no lock, driven by a pure core reducer. A rebuild waits for the window's own `Destroyed`. The window is built visible with `focused(false)`/`focusable(false)`, and no setter is called on it afterwards. `overlay_ready` and the emits read the same mailbox through the one `overlay_payload`. The capability allows only listen and unlisten. The smoke predicate now counts tool windows (F-003). Warnings write only the kind and the OS code. The docs moved in the same commit. The deviations are reasoned and recorded.

One Medium finding blocks at this project's threshold (`review.blocking: medium`). Finding 1: the unrequested-Destroyed branch the developer added has no test, and removing it would go unnoticed while the overlay disappears for the rest of the run. The fix is a few core tests plus one property-test extension (optionally one shell test). Findings 2–5 are non-blocking follow-ups. Finding 2 sits next to finding 1 and is cheap to fix in the same round.
