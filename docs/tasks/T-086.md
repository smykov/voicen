### 3. Root cause and class

All seven leaking guards fail the same way. The pass comes from the guard's own reading of a grammar finding nothing: YAML keys and scalars, which line is a comment, a GitHub expression, how a Rust path or a macro is spelled, or how bash joins a word. The probes need no exotic input. An explicit key, a flow mapping, a `#` line inside a scalar, a quote, a space in a path, a trait impl or a `const` is enough. This is class `guard-model` (F-003, F-015). None of these guards has a recorded leak in CI, because no one probed them. P-020 already closes the class at design time for new guards (decisions #120), so this is a code exit for the existing ones: the rule is in place, and the remaining work is applying it.

### 4. Size: large, recommend a split

Six rewrites over five seams need a separate review each. History shows each guard design costs review rounds: three patches in one file for F-015, four rounds for F-003. One diff holding all of them would repeat that. Recommended plan, for the owner to confirm:

1. **T-086 (this task, docs only):** the guard table above, moved into `docs/decisions/ci-toolchain.md` (protects, `decides_on`, the switch, literal or token named, or the rewrite task). Also: update the `guard-model` row of `docs/failures.md`, close the T-060 items (http-client-builder, app-acl → T-049), and amend this task's Acceptance. Bullets 2–3 move to the rewrite tasks.
2. **Telegram secret steps** (P1, it guards a secret): the raw token `secrets.TELEGRAM_` (any case, comments included) may occur only inside one owned step literal, byte-exact the way R9 is, either in `telegram-guard.sh` or as R10 of `release-guard.sh` (that task decides). R4 already refuses every other `secrets` spelling. Red: T1.
3. **Workflow cache and setup-node steps** (ci-wip + setup-node-cache merged): the trigger is asserted as lines inside the owned header literal. The raw tokens `uses`, `actions/cache`, `setup-node`, `rust-cache`, `cache/save` and `pnpm/action-setup` may occur only on owned lines or blocks; an unlisted action stays refused. Red: W1, W2, S1, S2.
4. **voicen-core call bans** (http-client-builder + core-test-clocks): clippy `disallowed-methods` (compiler-resolved paths, so whitespace, `Default` and `use … as` cannot escape it), denied by check-core's `-D warnings`, allowed only in `engine::http` and `tests/common`. `src` has 72 `Instant::now`/`.elapsed(` uses, so the allow sits at the lib root. The config format must be checked against clippy 1.99 docs. Red: H, K.
5. **ci-credentials:** drop the `#` comment skip so any occurrence refuses, and reword comments in the scanned files. Red: C1.
6. **helper-windows product-class rule:** a raw-token rule, so a visible-helper class must not occur as raw text in a product-window crate. Red: the const probe.
7. **shell-test-layout:** pin cargo switches instead of lexing Rust. Either `test = false` on the lib and bin targets next to `doctest = false` (whether `--lib` / `--all-targets` override it must be read from the cargo 1.99 source, as was done for `--doc`), or compare cargo's own unit list (`cargo check --tests --message-format=json` for `x86_64-pc-windows-gnu`, which check-shell-windows already resolves) with an owned set. The workflow half needs a pinned literal test invocation, not a token search. Red: R1, L1. This is the largest task and needs its own investigation.

Each new task carries `checker: true`, `class: guard-model` and its `decides_on`, and its first commit is the probe fixture red against the old guard.
