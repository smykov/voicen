**Frame.** Expected (SC-009, FR-042): after a session with a call, a device change and a failed pass, 0 occurrences of transcript text, keys or device friendly names in logs and crash files. Expected (SC-006, FR-032): 100 % survival and unchanged audio across capture loss, storage failure, engine errors and timeouts. Observed: no test checks either end to end; each part is pinned on its own.

**Hypotheses.**
1. A planted value reaches `voicen.log` through a call line. Refuted by the types: `LogEvent` holds only closed enums, integers and `EndpointId` (`diagnostics-log.md` invariant 1, `diag_format.rs` grammar, `compile_fail` doctests). The sweep pins this for composed use.
2. A second writer under `logs/` (the same concern on a second path). The only writers are `Log`, `Session::begin` and `diag::crash` (`diagnostics-log.md` Don't list). The shell's `ShellPassEvents::log` is a plain `Log::write`. The sweep asserts the closed file set.
3. A friendly name enters as an id. `TrackSource::open` returns an `EndpointId`, and `EndpointId::new` turns non-id text into `invalid`. `settings::Microphone.name` is never put on a line. `DeviceEvent` carries ids only. The sweep plants the name in both places.
4. Crash files echo a panic payload. Refuted by `install_panic_hook`, which never reads the payload (`diag_crash.rs` UTF-8 / UTF-16LE). The sweep re-checks it with the call's transcript as the payload.
5. This class was fixed before. `docs/failures.md` has no privacy-log or diagnostics-log entry, and no other task carries `class: privacy-log`. Re-checked at 0be819c8: the only new entry, F-034 (T-145), is the Windows `WM_ENDSESSION` process end in the shell, not a log leak. **Recurrence: none.**

**Root cause / size.** This is coverage work, not a defect. It needs one new test binary and one rig constructor, with no product seam. Size: medium, one seam (tests). No spec work is needed. Surface `none`. The owner's machine is not needed: everything runs in the core container through `scripts/tw-test core call_privacy`.

**Dependency.** T-138, T-144, T-149 and T-152 are DONE. T-145 is merged and DEPLOYED (fe747940, 1f81926d; decisions #355). In core it changed only `CallSession::notice_stopped`: a Sleep stop now reports `CallNotice::Stopped{Sleep}` to the shell instead of `CallSavedTranscribing`. That is a `CallShell::notice`, not a `LogEvent`. It also changed one assertion in `tests/call_session.rs`. It added no log line or storage path and did not touch `tests/call_support/mod.rs`. Its shell changes (a start-up `CallStore::recover` on the call worker, `CallSwitchRefused` lines, `end_of_process`) write through existing core types. The shell is outside this task's area (#346 Q1). The invariant and the seam are unchanged. A Sleep stop is a stop reason, not an FR-032 fault. It may end one matrix row (asserting `Stopped{Sleep}` on the `FakeShell`), but it is not a required row.
