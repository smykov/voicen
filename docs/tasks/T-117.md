## Investigation

Investigator, 2026-10-24. Serena loaded but not used for code: the evidence is shell, YAML, TOML, CMake and third-party build scripts, read from the core image's cargo registry cache (`.teamwright/cache/core/_usr_local_cargo_registry/src/index.crates.io-*/`). Docs: Context7 `/rust-lang/cargo` (`[env]` `relative`/`force`, build-script rerun rules) and `/websites/cmake_cmake_help` (CMP0091, `CMAKE_MSVC_RUNTIME_LIBRARY`).

**Frame.** Feature: R5 wants a `/MT` libopus in every Windows build, proven by the CI build itself (the T-099 pattern). Today libopus is `/MD` everywhere (`OPUS_STATIC_RUNTIME` defaults to OFF), and no step looks.

**Findings that change the planned design** (spec 007 R5, contracts/installer-ci.md, tasks.md G03):
1. **`CMAKE_TOOLCHAIN_FILE` must be target-scoped.** cmake-rs `Config::build` reads it through `getenv_target_os`, which tries `CMAKE_TOOLCHAIN_FILE_<target>` and `_<target with _>` first. Once the toolchain file is defined, cmake-rs stops setting `CMAKE_SYSTEM_NAME` for cross builds and stops passing `CMAKE_C_COMPILER`. With the plain name, the mingw opus build of `make check-shell-windows` would lose both `CMAKE_SYSTEM_NAME=Windows` and the mingw compiler, and it would probably still pass, because it is a `cargo check` with no link. Use `CMAKE_TOOLCHAIN_FILE_x86_64_pc_windows_msvc` with `relative = true` (cargo makes the path absolute) and `force = true`.
2. **`CMAKE_MSVC_RUNTIME_LIBRARY` is never in opus's cache.** opus sets it as a normal variable from `OPUS_STATIC_RUNTIME` and `CMAKE_BUILD_TYPE` (`CMakeLists.txt:282-294`). The acceptance line "a cache with `CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded` passes" can only hold if the toolchain file writes that entry as well, and then the entry only echoes the toolchain file, because the normal variable shadows it. The effective configuration is `OPUS_STATIC_RUNTIME:BOOL=ON` plus `CMAKE_BUILD_TYPE:STRING=Release`: opusic-sys always uses Release, and `MATCHES DEBUG` then picks `MultiThreaded`. -> **D1**.
3. **The cache shows the configuration, not the compile line.** cc-rs 1.5.1 adds `-MD` (`lib.rs:2339-2347`; the repo sets no `crt-static`), and cmake-rs writes it into opus's `CMAKE_C_FLAGS`, because opusic-sys does not define that variable. With CMP0091 NEW, CMake also adds `-MT`, so cl sees both: the later flag wins, with warning D9025. Which one comes later is not proven from the docs, and the import table cannot tell (finding 5). The effect is visible in the objects: `dumpbin -directives opus.lib` shows `/DEFAULTLIB:LIBCMT` for `/MT` and `/DEFAULTLIB:MSVCRT` for `/MD`. -> **D2**.
4. **A restored build cache hides the change.** opusic-sys's build script declares only `rerun-if-env-changed=ANDROID_NDK_HOME`. Probe in the core image: `CMAKE_TOOLCHAIN_FILE_x86_64_unknown_linux_gnu=/nonexistent/x.cmake cargo build -p opusic-sys -j2 -v` printed `Fresh opusic-sys v0.7.5`, so the build script did not rerun. The windows job restores rust-cache through its restore-key (run 40030080179: `full match: false`), and T-116 is on `main`. The next `main` cache will therefore hold a `/MD` opusic-sys OUT_DIR, and the `wip/T-117` run and every later `main` run would keep it. The checker fails closed, so those runs would be red for a cause outside the diff. The same latent hole exists for whisper-rs-sys: ci-toolchain.md already says the cache "can restore an older OUT_DIR". -> **D3**.
5. **`crt-imports.sh` cannot tell `/MD` from `/MT` for libopus.** libopus is C only, so it never imports MSVCP140. Shell exes link with tauri's `static_vcruntime` arguments (`/NODEFAULTLIB:msvcrt.lib`, `/DEFAULTLIB:libcmt.lib`, `libvcruntime.lib`), so `/MD` C objects still link without a VCRUNTIME140 import. T-116's analysis records that `voicen.exe` already links `/MD` aws-lc and passes. `voicen.exe` does not call the codec yet, so the linker very likely pulls no opus object at all (inferred, not proven). The "call test exes" do not exist: `src-tauri/tests` has no `call_*.rs`; the first ones are T-127 `call_capture.rs` and T-139 `call_chain.rs`. `crt-imports.sh` refuses an unmatched glob, so adding them now would make the windows job red. -> **D4**.
6. **Mixed CRT in the core test exe** (a premise only the wip run can test). The voicen-core lib test exe links with Rust's default `/MD` CRT and will now contain `/MT` opus objects. Expect warning LNK4098; LNK2005 errors are possible, and only Windows can show which. The whisper precedent avoided this case: voicen-whisper has no lib test, and its integration tests get static_vcruntime `rustc-link-arg-tests`. -> **D5**, only if the run goes red.
7. **A second path through the same variable.** whisper-rs-sys forwards every `CMAKE_*` env var as `-D` (`build.rs:278-287`), and cmake-rs then loads the toolchain file for whisper.cpp as well. The toolchain file must therefore set nothing whisper.cpp reads: only `OPUS_STATIC_RUNTIME` (unused by whisper.cpp) and the CMP0091 default (already forced for whisper). `whisper-cmake-cache.sh` has no token for either, so it stays green, which the first acceptance item requires. aws-lc-sys uses its cc builder today; it would see the file only if it fell back to its cmake builder, and that would be harmless for the same reason.
8. CMP0091 NEW is already in effect through opus's `cmake_minimum_required(3.16)`. Keep it in the toolchain file anyway: the acceptance names it, and it costs nothing.
