## Context

Split from T-001 by decision #43. FR-12: silence, a cough or keyboard noise must not reach the engine. Core gets the `SpeechDetector` port and an `EnergyDetector` (the fallback on Linux and when Silero is unavailable); `SileroDetector` lives in `crates/voicen-whisper` (decision #12, spec 002 R-1) — that is T-043. From the T-001 Investigation: the energy rule as R-5 words it counts keyboard clicks as speech, so the gate must require a minimum run (~90 ms) of loud frames; an energy detector cannot reliably tell a long cough from speech — real-audio FR-12 is proven only by Silero on real clips plus the owner. Fixtures are generated in test code with a fixed-seed generator (`rand` not consented): harmonic "speech", a −60 dBFS noise floor, a 150 ms noise burst for the cough, 10–20 ms clicks for the keyboard. Depends on T-040 for `AudioBuffer`.

## Acceptance

- [ ] The 3 s synthetic speech fixture is speech; silence, the 1 s cough burst and keyboard clicks are not (energy detector with the minimum run)
- [ ] The gate uses the given detector and falls back to the energy detector when it is unavailable, emitting a `vad_fallback` warning once
- [ ] Failure branch: a detector error never panics and never lets audio through as speech by accident — the gate falls back (unit test with a failing fake detector)
- [ ] Test that fails without the change: unit tests in `crates/voicen-core/src/vad/`

## Investigation

Background, Silero placement (#12) and the fixture model are in the T-001 Investigation ("Speech gate", "Fixtures"). Here: the shapes and constants that T-001 left to this task.

**Recurrence check.** `docs/failures.md` lists F-001, F-002 (`ci-toolchain`) and F-003 (`guard-model`). This task is class `transcription-pipeline`, which has no entries, so there is no recurrence and `recurrence_of: []` stands.

**Hypotheses.**
1. *A second path already decides speech.* Refuted. A grep over `crates/voicen-core/src` for `vad`, `speech`, `Speech` and `energy` finds nothing outside i18n/settings strings. Serena indexes TypeScript only. T-040 added no VAD.
2. *The class was fixed before.* No; this is the first gate code.
3. *R-5 as written is enough.* Refuted by simulation (table): keyboard passes R-5's total rule. A pause-free utterance gets floor = speech level and is rejected.
4. *The gate should emit the warning itself through an observer.* Rejected. `PipelineObserver` and `events.rs` belong to T-001 and do not exist yet. A gate that emits would be a second emitter beside `run_job` (P-011). Returning the fact keeps one emit path.

**Trait and gate shape (contract kept, return value added).**
- `pub trait SpeechDetector: Send + Sync { fn name(&self) -> &'static str; fn contains_speech(&self, audio: &AudioBuffer) -> Result<bool, VadError>; }`. Synchronous (#42).
- The trait returns `bool`, not a score: each detector owns its thresholds (Silero's probability and minimum duration in T-043), so the gate needs no common scale.
- `#[non_exhaustive] pub enum VadError { Unavailable, Failed }`, with static `Display` texts only (no path, no audio).
- `EnergyDetector` has an infallible inherent `detect(&AudioBuffer) -> bool` and also implements the trait (always `Ok`).
- `SpeechGate::new(primary: Result<Box<dyn SpeechDetector>, VadError>, fallback: EnergyDetector)`.
- `decide(&self, &AudioBuffer) -> GateDecision { speech: bool, detector: &'static str, fallback_warning: bool }`. It takes `&self` and is `Send + Sync`, because R-10 runs jobs on several workers through one shared gate.
- State: `primary_failed: AtomicBool`, which starts at `primary.is_err()` and latches on the first runtime `Err`, after which the primary is not called again. `warned: AtomicBool` is set with `swap(true)`, so exactly one decision carries the warning even under concurrency.
- Why latch instead of retrying every recording: R-5 says "for that and later recordings"; one warning per session (FR-016) then means one state; and a whisper.cpp VAD error is not expected to be transient.
- Before T-043 the shell passes `Err(Unavailable)`, so each session logs one `vad_fallback`. That is honest: no model is loaded.
- A panic inside a primary cannot be caught (`panic = "abort"`, Cargo.toml:16). Not panicking is T-043's job. `vad/` gets the `deny(unwrap_used, expect_used, indexing_slicing)` header (spec T038), with `chunks_exact` and `.get()` instead of indexing.

**Energy rule (pinned constants, R-5 extended).**
- Frames: 30 ms = 480 samples, not overlapping. A trailing partial frame is dropped.
- Level: RMS of i16/32768 in dBFS. An all-zero frame is `-inf`; that is not NaN, and the sort uses `total_cmp`.
- Floor: the 10th percentile of the frame levels, clamped to [-70, -40] dBFS.
  - -70 handles digital zero (the floor would otherwise be -inf).
  - -40 handles an utterance without pauses. The cost: a steady noise louder than about -28 dBFS counts as speech. That is acceptable for a fallback.
- A frame is loud when its level is at least floor + 12 dB.
- Only runs of 3 or more consecutive loud frames (90 ms) count. A click of 20 ms or less spans at most 2 frames.
- Speech means the counted frames total 10 or more (300 ms). A buffer shorter than 300 ms is never speech.

**Fixtures.** All are generated in `test_support` (cfg test/test-fakes) at 16 kHz i16, so T-001 reuses the same generator. The generator is a 64-bit LCG in test code (a = 6364136223846793005, c = 1442695040888963407, top 53 bits), with a fixed seed per fixture. Host simulation (`python3`, the same rule and generators, 2026-10-04):

| Fixture | Recipe | Result | Why it bites |
|---|---|---|---|
| speech 3 s | f0 110→220 Hz, 7 harmonics, 4 Hz raised-cosine envelope, peak -12 dBFS, over a -60 floor | 68 loud, longest run 6 → **speech** | positive control: an always-false detector fails |
| silence 3 s | uniform noise, -60 dBFS RMS | floor -60.3, 0 loud → no | a floor-relative threshold, not a "nonzero" test |
| zeros 3 s | digital zero | floor clamped to -70 → no | -inf/NaN and panic path |
| cough 1 s | burst at -6 dBFS, 10 ms attack, -50 dB over 150 ms | 5 loud, run of 5 counted, total < 10 → no | **total minimum** (the run rule alone would pass it) |
| keyboard 3 s | 10–20 ms decaying clicks at -10 dBFS, gap 125–167 ms (6–8/s) | 27 loud (R-5's total rule says speech), longest run 2 → no | **minimum run** |
| continuous speech 1 s | speech envelope never below 0.6, peak -20 dBFS | raw floor about -26; clamped to -40 → **speech** (without the cap: no) | **floor cap** |

Each fixture test also asserts its own premise (for example keyboard: at least 10 loud frames and longest run at most 2), through a `pub(crate)` `analyse()` that returns `{floor_db, loud, longest_run, counted}`. So a later change to the recipe cannot silently stop the fixture from biting (P-005). The click gap of at least 125 ms is a fixture assumption; fast typing bursts are a known limit of the model.
