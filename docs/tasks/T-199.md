## Context

T-192 review 1, finding 3. A stage session started by `scripts/tw-launch` can push `wip/<ID>`, but cannot read the run (the kit's deny on `Bash(gh:*)`, kept by #219). Nothing makes it stop after the push: each stage session repeats "CI unread" and commits a note until the loop ends. On 2026-10-31 T-102 ended `outcome: limit` at 12 stages and T-122 ended `stuck`.

**Question for the owner.** (a, recommended) Allow `gh run list` and `gh run view` for stage sessions: read-only, and the session finishes its own stage. (b) Keep the deny: the loop has to stop after a push, and the orchestrator writes the `CI:` line each time.

## Acceptance

- [ ] After its `wip/<ID>` push a worktree task spends no further stage session until the run's result is available to it
- [ ] The result reaches the task's `## Tests` as `CI: <run> @ <sha>` by the path the owner chose
- [ ] Failure branch: a red run returns the task to its stage with the failed job named, not to a repeated wait
