## Context

FR-13, FR-21, NFR-10. Svelte settings window over IPC `settings_get` / `settings_save`, first launch opens it on the Engine tab with engine none. Verified with Playwright against the built UI with mocked IPC.

## Acceptance

- [ ] First run (mocked `settings_get` returns first-run) opens on the Engine tab with engine = none and the v4 defaults shown
- [ ] Choosing API, entering URL, model and key, then Save calls `settings_save` once with those values; the key field is masked
- [ ] A saved change is reflected without reload (event `settings://changed`); changing `ui_language` re-renders visible text in the new language without reload — Playwright (T-005 review round 1 #2: the `$state` language store has no unit test, vitest loads Svelte's server build)
- [ ] Failure branch: Save with an empty base URL → the field is highlighted with the validation message and `settings_save` is not called; a backend `hotkey_unavailable` result → the hotkey field shows "hotkey unavailable" and the old value stays — verified by Playwright
- [ ] Test that fails without the change: `e2e/settings-first-run.spec.ts`
