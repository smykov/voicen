## Investigation

Tools: Serena (`get_symbols_overview` win/capture.rs, `find_symbol` WinDiskSpace); cpal 0.18.2 and windows 0.62.2 read from the registry cache `.teamwright/cache/core/_usr_local_cargo_registry/` (the pinned versions in Cargo.lock), not context7. Grep was used for docs and spec text.

**Frame.** Feature task, US1 G13. The core session needs a Windows `TrackSource`. The disk part shrank to reuse (T-125 Notes 2026-11-05): `local_models::WinDiskSpace` already implements core's `DiskSpace` with `GetDiskFreeSpaceExW`, so no `win/disk.rs` is created and only the `%TEMP%` acceptance test is added.

**Hypotheses checked.**
- *A second path already handles it.* `win::capture::CpalSource` is dictation-only: `FrameSink`, an `Instant` stamped at callback entry, and `device_loss_callback`, which reports nothing for `DeviceChanged` and is reused by nothing else. Not reusable without editing it, and the task forbids that (FR-009).
- *The class was handled before.* F-016 / T-104: the dictation loss map treated `Xrun` as a loss. The lesson carries over: the call-track map is taken from cpal's emit sites (`process_input` Xrun keeps capturing; the default-device monitor's `StreamInvalidated`/`DeviceNotAvailable` keep the stream running on the old device; every other `emit_error` + `break` ends the thread).
- *`now()` = `Stream::now()`.* Refuted as a design: `CallSession::open_tracks` calls `source.now()` before opening any stream. The shell reads QPC itself with cpal's formula (counter x 10^7 / freq, x 100), which puts it on the same clock and the same 100 ns grid as `capture` stamps.
- *Loopback uses `default_input_config()`.* That would be wrong: on an eRender device cpal returns `UnsupportedOperation`. Use `default_output_config()`. CI cannot see this on a device-less runner (open fails earlier with NoDevice), so it is a review point and part of the owner's manual check.

**Areas.** shell (src-tauri), plus spec/docs text. Core is not changed.

**Risks.**
1. The runner's audio endpoints were never probed (windows-ci-runner.md, T-059 Q1). If it has a render or capture endpoint, test 1 takes its "device present" branch, and its R1/R2 stamp facts become CI-observed facts. If it has none (expected), the real-endpoint R1/R2 confirmation stays the owner's manual check, already decided (OQ-62 (b), decisions #178), so this is not a new question. Either way the fact goes into research.md R1/R2 and windows-ci-runner.md.
2. A default-device change emits `StreamInvalidated` while the old stream keeps delivering. Reporting the loss once and then staying silent is correct for 1a. Reopening is R4's later task (G35/G36), not here.
3. Loopback delivers no callbacks while nothing plays (R1). Core's `Timeline` fills that from stamps; the shell must not synthesize blocks.
4. The callback must stay allocation-light and non-blocking: `ChannelSink::block` is `try_send`. One reused f32 buffer per stream, as in dictation's `build`.
5. Adding the `Win32_System_Performance` feature changes neither Cargo.lock nor THIRD-PARTY-NOTICES (feature unification; cpal already enables it).

**Windows CI.** `src-tauri/tests/call_capture.rs` runs in the windows job's `cargo test -p voicen --no-fail-fast` step on `wip/T-127` (pushed by the orchestrator, P-016). `make check` on Linux does not build the shell. Evidence: `CI: <run> @ <sha>` under ## Tests.

**Owner questions.** None. A real-device check of loopback, stamps and loss on a default-output switch falls under the existing manual-check decision (#178).
