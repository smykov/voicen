## Context

T-019 returns `{ engineReset, resetFailed: true }` when the model file is deleted but the settings write that resets the selection fails (decision #110). The settings window then shows the shared `settings.write_failed`, which ends "Nothing was changed." — untrue, because the file is gone. The owner chose a dedicated text (decision #111, OQ-27 (b)): the model was deleted, but the settings could not be updated.

## Acceptance

- [ ] A delete answered with `resetFailed: true` shows a dedicated message (new i18n key, en and ru) saying the model was deleted but the settings could not be updated; `settings.write_failed` is not shown for it
- [ ] Failure branch: a delete that fails (`delete_failed`) and a plain settings save that fails still show their existing texts
- [ ] Test that fails without the change: e2e over the mocked `local_model_delete` answering `resetFailed: true`, plus the i18n key in both locales

## Investigation

**Where it is handled.** Only `src/lib/local-models/BuiltinLocal.svelte` handles `local_model_delete` results (grep over `src/` and `e2e/` for `local_model_delete|resetFailed|engineReset`; Serena not used, not connected in this session). `confirmDelete` sets `refusal = { kind: "reset_failed" }` on `outcome.resetFailed`; the alert renders that kind as `t("settings.write_failed")`. `localModelsApi.ts::deleteLocalModel` passes `DeleteOutcome` through unchanged (pinned by `localModelsApi.test.ts`), so the render branch is the only seam.

**Catalog.** The settings window reads the shared root catalog `i18n/{en,ru}.json` (`src/lib/i18n/index.ts` imports `$i18n/en.json`, `MessageId = keyof typeof en`), the same files embedded by `voicen_core::i18n`. A UI-only id needs no Rust declaration (`docs/decisions/i18n.md`, UI-only list); core's `message_ids_exist_in_both_catalogs` checks Rust ids against the catalog only, and parity tests (core `catalog_parity_*`, UI `i18n.test.ts`) require the en/ru pair and equal placeholder sets. No core test enumerates `delete.*` ids (grep for `delete.` and `en.json` across `crates/`, `src/`), so no core change. Note: existing `delete.*` ids are wire messageKeys from `local_models::service`; `delete.reset_failed` would be the first UI-only id in that namespace — record it in `docs/decisions/i18n.md` (or name it `local_models.delete_reset_failed` instead; either is agent-decidable, #111 names `delete.reset_failed`).

**Tests today.** `e2e/local-models.spec.ts` "failure branch: resetFailed (OQ-26 a) ..." asserts `en("settings.write_failed")` — it becomes the red test. Mock support exists: `queueDeleteOutcome(page, deleteOutcome("reset_failed"))` over core-checked `e2e/fixtures/local-models-wire.json` (no fixture change). Failure branch already covered: the `delete_failed` refusal loop in the same spec and `e2e/settings-first-run.spec.ts` (`settings.write_failed` on a failed save).

**Recurrence check.** `docs/failures.md` (F-001..F-015 and the Classes table) has no entry on local-model delete, i18n texts or a message contradicting the outcome; `recurrence_of: []` stands. This is the follow-up decided in #111, not a defect recurrence.

**Size.** Small: one component branch, two catalog lines, one e2e test edited plus a ru case, three doc updates (component header comment, `docs/decisions/settings-ui.md`, `docs/decisions/i18n.md`). Wording proposed in `analysis.approach`, non-blocking.
