SPEECH gives exactly one closed timed chunk per 120 s window for windows 1-3 (spans end 20 s, 10 s and 20 s before the window edge). `drive` stops refilling once 3 requests are in flight. So on correct code at most 3 `next_window` calls can happen before any answer, whatever the thread interleaving. The hook value is read before that request's answer, and the first hook comes before every answer. Under the mutant, refill reads all 5 calls (4 windows and the end) before the first dispatch, so the first value is 5. Deterministic both ways.
