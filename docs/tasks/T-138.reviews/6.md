## Determinism, oracle, bite

Code read: `Lane::refill`, `Run::drive`, `Run::pick` (`call/final_pass.rs:773-958`), `ChunkPlanner` / `RangePlanner::feed` (`:180-208`, `:354-385`), and the fakes `GenDecoder` and `FakeEngine::transcribe_timed` (`pass_tests.rs:228-400`). I located them with Serena and grep, then read the line ranges.

- **Count is stable, no race.** `Req::n` is the arrival number, assigned under the log lock. So the third arrival (`n == 2`) can only happen after all three `scope.spawn` calls. In `drive`, every `refill` runs at the top of the `while in_flight.len() < MAX_IN_FLIGHT` loop, before the `pop_front` and spawn of that chunk. Once the third worker is spawned, the loop exits to `rx.recv()` and makes no further `next_window` call until an answer arrives. Arrivals 0 and 1 block in the answer closure (not in the `on_request` hook, which the fake runs under its lock) until `n == 2` has stored the count. Arrival 2 stores the count before it returns its own answer. So the count is read while the dispatcher is idle in `recv`, and the result does not depend on how the threads interleave. The 30 s `wait_timeout_while` only bounds a broken pass. On correct code it never expires, because arrival 2 always comes.
- **Oracle is not tautological.** `windows_to_cut` drives a lone `ChunkPlanner` over a separate `GenDecoder` and never touches `Lane` or `drive`, so a mutation of `refill` cannot move it. It copies only the ask formula (`TIMED_MAX_MS - carry_ms()`), which is the documented window contract. It would follow a planner change, which is the right behaviour for a test of read-ahead. With `PAUSE_MS` = 300 and a 30 s pause before each window edge, every `EIGHT` window closes its own chunk, so the oracle gives 3.
- **Kills 101 deterministically.** Under `while self.queue.len() < 2`, each `refill` reads until two chunks are queued, and it does so before the pop and spawn. So before the third spawn the mic decoder has been called 4 times, not 3, and those calls happen before arrival 2 can exist. `4 != 3` fails the test every time. That matches the author's 6 of 6 red runs.
- No weakened tests: the diff only adds code. The data is fake (marked tones). No clock reads were added.
