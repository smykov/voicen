## Investigation

Analysis 2026-11-05 (investigator, main tree at a0413f75).

**How I looked**
- Serena tools were loaded, but most of the reading was done with grep and file reads in the main tree:
  - `crates/voicen-whisper/src/{silero,lib}.rs`, `tests/silero_clips.rs`, `tests/clips/`, and `Cargo.toml`;
  - core `vad/mod.rs` and `energy.rs`, `call/codec.rs`;
  - `src-tauri/src/{vad,lib,dictation}.rs`;
  - the `ci.yml` test and fetch steps, and `licenses/manual.json`.
- I checked the whisper-rs 0.16.0 API and whisper.cpp's VAD defaults and padding in the crate sources, in the cargo registry cache of the T-136 worktree (the same version as `Cargo.lock`). I did not use context7: the source of the pinned version settles the question.
- The callers of `SileroDetector::load` (grep) are `src-tauri/src/vad.rs::load_bundled`, `src-tauri/tests/dictation_e2e.rs` and `crates/voicen-whisper/tests/silero_clips.rs`.
- The callers of `load_bundled` are `src-tauri/src/lib.rs::release_ports` only.

**Hypotheses**
1. *The spans exist and are only discarded.* Confirmed: `contains_speech` sums the segments and drops them. Nothing implements `SpeechSpans` for Silero.
2. *Sharing one load needs a type change.* Confirmed: `load` returns a `Box` that owns the only native context. Under the orphan rule, voicen-whisper cannot add an impl of core's traits for `Arc<SileroDetector>`. So either the detector becomes `Clone` over `Arc<Mutex<_>>` (option A), or core grows blanket `Arc<T>` impls (option B).
3. *The same concern is handled on a second path.* The energy spans (T-134) are the fallback path and stay as they are. The planned risk is a second, pass-only Silero load in T-139. Option A makes that unnecessary, and the "one load" test pins it at the crate level.
4. *This class was fixed before.* No. `docs/failures.md` has no VAD entry, and the history of `silero.rs` is only T-043.

**Deviation from the design reference.** tasks.md T040 puts the red tests "in `silero.rs`". The crate has `[lib] test = false`: a lib test exe would link the dynamic CRT, against T-099 invariant 4. So the tests go into `tests/silero_clips.rs`. That exe is already in the CI test run and in the crt-imports list. A new `tests/*.rs` file would also need a crt-imports line in `ci.yml`, so avoid one. The Acceptance line "the `silero.rs` span tests" means these tests.

**Why the native `Err` is pinned by the core helper.**
- whisper-rs returns `Err` only on a NULL result, and nothing in a test can make whisper.cpp return NULL.
- The `c_int` overflow branch needs at least 2^31 samples (4 GiB).
- The lock cannot be poisoned from outside, because every native call runs inside `catch_unwind` under the lock.

So acceptance line 1 is proven in two parts:
- the Linux-gate tests of `vad::segments::spans_from_centiseconds` (an `Err` passes through unchanged, a malformed segment is `Err(Failed)`, never `Ok(empty)`);
- a single error funnel in `silero.rs`, which the reviewer reads.

Malformed segments become `Err` rather than being dropped, as `contains_speech` does today. With the energy fallback, that means "send audio" instead of "drop audio", which is the safe direction for FR-023. Dictation is affected only in this case, which whisper.cpp does not produce.

**Not touched, and why**
- `src-tauri/src/vad.rs` and `src-tauri/src/lib.rs`: `load` keeps its signature. Exactly one `vad::open_bundled`/`load_bundled` call that feeds both `DictationPorts.detector` and the pass worker is T-139's wiring. **Follow-up for T-139 Acceptance:** "one bundled load feeds dictation and the pass (`SileroDetector::open` + clone)".
- `src-tauri/tests/dictation_e2e.rs`, `crates/voicen-core/src/call/final_pass.rs` (T-137; it imports only `SpeechSpan`), `engine/openai.rs` (T-136), `call/storage.rs` / `call/mod.rs` (T-125), `.github/workflows/ci.yml`, `scripts/ci/**`, `Makefile`.
- `docs/decisions/builtin-engine.md`: `VAD_THREADS` stays 1, and the spans add no new thread or parameter.
- No new dependency.

**Fixture notes.**
- **Speech.** The three CC0 speech clips are already in `licenses/manual.json`. The composed buffer is about 12 s. The labels are hand-set from each clip's waveform and committed as constants. The energy premise keeps them independent of Silero.
- **Silence.**
  - Generated digital zero, 1 920 000 samples.
  - `room-tone-ac-unit` tiled 40 times. The joins are a harder case, not a premise.
- **Music.** This is the only new bytes. It must be CC0-1.0, because the accepted licence list has no public-domain id (decision #59 / about.toml).
  - Check that the Commons description says instrumental, without vocals.
  - Encode it mono, so `OpusOggReader` accepts it (mapping 0, 1 channel).
  - If the reader refuses it, commit raw s16le (3.84 MB) instead, and say so in review.
- **Runtime.** 120 s is about 3 750 Silero graphs. That is under 1 s by the T-043 measurement (3 s took about 15-20 ms).

**Risk (no open question yet).** Silero v6.2 may give spans on some instrumental music with whisper.cpp's defaults (threshold 0.5). Tuning the thresholds for the fixture would change dictation's rule as well (P-011) and break "never tuned per clip". If it happens, the developer stops and the orchestrator raises an OQ for the owner. Choosing a different piece only to pass is not allowed.

No open question was added: FR-023, SC-008, R8 and #175 settle the behaviour.
