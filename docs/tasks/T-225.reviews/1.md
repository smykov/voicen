What I verified by reading:
- **Seam and invariant.** For each track, `advance` now calls `drain_track(track)` first and skips the decision if it handled anything (or if the recording ended). `now`, `stalled` and `both` are then computed after that read. So a track is zero-filled only right after an empty read of its own channel, with no handle in between. Both tracks are drained, so catalog survivor 04 (Mic-only drain) is not the code. The change sits in the seam the analysis named and follows option A.
- **Side effects of handling events in `advance`.** `handle` runs `apply`, `maybe_tick` and `settle` here, as it already does in `round()`. A track skipped this round also skips the gap `landed_ms` check. That costs at most one round, because the next round reaches it with an empty read (and `handle` itself calls `settle`). On the stopping path, `round()` read both channels empty after `stopping` was read, so `advance`'s reads are empty too and the break is unchanged.
- **Hypothesis-3 path.** Take a slow `write_meta` between `round()` and `advance`. The Mic is decided with System's `last_event` still stale, so `both` may hold and the Mic follows `TrackSource::now` − 200 ms. That can only happen when the Mic's own channel read empty, i.e. it really delivered nothing. It is the I9 behaviour for a silent track and no real block is covered. Then System is drained before it is decided. No defect.
