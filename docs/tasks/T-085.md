## Context

Opened by T-026 review round 4 (`REJECT_RECURRENCE`). The trigger was set by T-026 review 3: "If another YAML-model gap turns up in this guard after that, it should go to an rca under class `guard-model`."

`scripts/ci/release-guard.sh` is a host-side awk reader. It re-implements three foreign parsers: the YAML of the workflow (scalar styles, comments, flow mappings), bash word and command splitting, and gh's argument parsing. It decides "pass" whenever its model does not see a violation. Each round found shapes the model passed silently (fail-open):

- T-026 validation 1 M6 (fixed in 2fe375a): `|| true`, `; true`, `if`, `set +e`, pipe around the check call.
- T-026 review 2 (fixed in 2e90f89): `#` line closing a quote opened on the call line; `\n` escapes in a quoted scalar.
- T-026 review 3 #1 (logged as a Low in T-060): folded `run: >` with a `#` line before the call.
- T-026 validation 2 (fixed in 6e7e7a8): `gh --repo R release upload`, `gh release --repo R upload`; `env: # GH_TOKEN: ...` (a YAML comment); `NOT_GH_TOKEN`.
- T-026 review 4 (open, reproduced on a copy of 6e7e7a8):
  - `run: >` folded scalar `gh release` / `upload ...` in the windows job;
  - a plain multi-line scalar `run: gh release` / `upload ...` in the windows job;
  - `${GH:-gh} release upload` and `GH=gh; $GH release upload`;
  - `env: { NOTE: "x, GH_TOKEN: none" }` with no real token.
  Each gives exit 0 (`ok: 1 step(s) publish a release`). PyYAML reads the first two as one `gh release upload ...` command, so a release is written from a job with no tag `if:`, no `needs` and no release-check.

F-003 (class `guard-model`, rca T-038) already holds the rule: "a guard decides on a switch or on raw text the tool cannot reinterpret, never on a model of another tool's parser". The release guard was built as such a model, and each fix extends the model. Smaller siblings in other guards are in T-060 (T-049 r1 #4 `app-acl.sh` block comments, T-079 r1 #1 `http-client-builder.sh` missed constructors).

## Acceptance

### Red tests round 2 (T-085)

Test-writer, 2026-10-10, for review 1 (`T-085.reviews/1.md`). Serena and context7 were not connected, so I used grep and file reads. I ran the host suite only, not `make check`. **Contract changes the tests pin:**
- **R2 (finding 1):** the release block runs from `  release:` to the end of its file and must equal the owned copy byte for byte. Any text after the owned copy is a difference, and that includes a comment at any indentation and a following job. The release job is therefore its file's last job. The listed line is the first line after the owned copy. The test helper `block()` now reads to EOF.
- **R1 (finding 2):** the word `jobs` (any case, bounded as for gh) occurs on exactly one line per file, and that line is exactly `jobs:`. The reviewer's suggested rule ("exactly one line `jobs:`") is not enough. `v-r1-jobs-key-quoted` puts the only exact `jobs:` line inside the scalar and spells the real key `"jobs":`. **The developer must reword the comment on line 23 of `.github/workflows/ci.yml`** ("right before jobs:"), or the `real` case goes red under this rule. The bite run shows that with "right before the job map" the full suite passes.
- **R4 (finding 3, vars):** the word `vars` (any case, bounded) occurs nowhere. The real workflows contain none (`grep -i vars .github/workflows/*`: nothing). I folded this into R4 because it is the same capability: a token from outside `permissions:`.
- **New R6 (finding 3, escapes). This is my choice: a raw rule, fail-closed, not a "Not caught" entry.** These raw texts must occur nowhere, comments included:
  - `\x` followed by 2 hex digits;
  - `\u` or `\U` followed by 4 hex digits;
  - a backslash directly before a line break: LF/EOL, CR, NEL `\302\205`, LS `\342\200\250` or PS `\342\200\251`.

  Why this rule and not the plain `\x`/`\u`/`\U` token the caller proposed:
  - The real `ci.yml` contains `\u` and `\U` in PowerShell paths: line 147 `Voicen\uninstall.exe`, lines 903/961 `...\Uninstall\Voicen`. A bare `\u`/`\U` token rule would refuse it.
  - Requiring hex digits does not refuse those paths. The real files have no `\x`+hex, no `\u`/`\U`+4 hex and no backslash at the end of a line.
  - These are the only YAML escapes that can spell a letter or join two lines. `\N`, `\_`, `\L` and `\P` give separators, not letters.
  - No scalar reader is needed: the raw bytes decide in any scalar style, so P-020 holds.
  - R6 also catches an escaped key (`"permi\x73sions"`), which the round-1 header listed as Not caught.
