## Investigation

**Frame.** Expected: a `/calls` page (window label `calls`, T-142) that shows FR-033/034/036 from the T-141 wire, EN and RU (FR-046). Observed: no route, no `src/lib/calls/`, no mock handlers for `calls_*`. Context gathered with plain reads and grep (file listings, `contracts/ipc.md`, `calls-wire.json`, `i18n/en.json`, `settingsApi.ts`, `language.svelte.ts`, `storage.rs` `CallStore::list` / `newest_first`, `docs/decisions/call-storage.md`); no Serena symbol lookup was needed for the UI tree, which has no calls code to look up.

**Hypotheses checked.**
- *A second path already renders calls* (e.g. a settings tab): refuted. `grep calls_list|calls_get` in `src/` and `src-tauri/` finds nothing; `src/routes` has `+page`, `overlay`, `settings` only.
- *Core already settles order and titles*: confirmed. `CallStore::list` sorts with `newest_first` (stamp, numeric suffix; call-storage.md "Don't: sort by CallId"). The damaged title is rendered by Rust in the UI language (`damagedRu`). So the UI must not re-sort or re-title (D1).
- *The catalog is complete*: partly refuted. Every `calls.*` / `speaker.*` id of the contract exists in EN and RU, but "an export failure shows the reason" has no text per `ioFailed.reason` word (D4).
- *The fixture covers every Acceptance line*: partly refuted. `detail.lines` contain no "contract"; `list` has 12 entries, not 3. The fixture is core-generated ("never edit by hand"); regenerating it means editing `storage.rs` test inputs, which is T-138's seam. The spec derives its inputs from the fixture (D7).
- *The page has what it needs for the empty-list hotkey and the language*: no command of the calls contract returns them. `settings_get` (`SettingsView.settings.ui_language`, `.calls.hotkey`) and `settings://changed` are the existing sources (the settings page does the same). This needs T-142 to grant `allow-settings-get` (and event listen) to the `calls` label (ipc-acl.md: grant to exactly the labels whose page invokes it). This is a handoff, not a blocker for T-143's mocked tests.

**Decisions for the developer** (record them in `docs/decisions/calls-ui.md`):
- D1 Order: render `calls_list` order verbatim; no client sort.
- D2 Date and time: take `YYYY-MM-DD` and `HH:MM` from the `startedAt` text as written (with or without offset), shown as `DD.MM.YYYY HH:MM` in both languages, matching the `calls.title_default` digits; no `Date`/`Intl` conversion. The wall clock of the recording is the local time FR-033 means, and the result does not depend on the test host's timezone. Duration `H:MM:SS` (`MM:SS` under 1 h); `durationMs: null` shows `—`. Line time from `startMs` in the same form.
- D3 Action set, one pure `actionsFor(state)`: ready → copy, export md, export json, open folder, delete; recording → open folder; queued, transcribing, failed, recovered → open folder, delete; damaged → open folder, delete only, and not opened to detail (`calls_get` is `ioFailed` for it, D2 of T-141). T-148 adds Transcribe / Transcribe again, T-154 adds the behaviour of Delete (confirmation, `recordingCall`, `inUse`). T-143 renders the Delete button from the action set because Acceptance 2 requires it on the damaged row. Its click handler is T-154's, so T-154's red tests stay red. Say this in Notes when implementing.
- D4 Failure text: new ids `calls.error.io.{missing,not_a_folder,access_denied,disk_full,other}` (EN + RU, full sentences such as "Could not export: access denied", modelled on `notice.call_refused.root.*`). An unknown or absent reason maps to `.other`, and `notFound` maps to `calls.error.io` for now. The same mapper serves copy and export failures. A cancelled export (`saved: false`) shows nothing. Add the rows to the contracts/ipc.md catalog table.
- D5 Search: case-insensitive substring over `line.text` (`toLowerCase`, covers Cyrillic). All lines stay visible and matches are wrapped in `<mark>` built from text segments, never `{@html}` (transcript text is untrusted). Zero matches over a non-empty query shows `calls.no_matches`.
- D6 Speaker: the label is `speakers[].name` for `line.speaker`. A fixed colour per speaker id (`me`, `s1`) is shown next to the label text (colour never alone). The test asserts a distinct colour per speaker plus the label.
- D7 Test data: `tauriMock` helpers derive every case from `calls-wire.json`: `callsList(n)` slices `list.calls` (3 newest), `callsDetailWithTexts([...])` replaces only `text` of fixture lines, an empty list `{calls: [], unavailableRoots: list.unavailableRoots}`, errors from `errors.*`. No hand-written wire object.
- D8 Events: `calls://changed` refetches the list (and the open detail if its `{root,id}` matches); `calls://open` selects that call; `settings://changed` updates the language and hotkey and refetches the list, because titles are rendered in the UI language. One unit test per listener in `callsApi.test.ts` / `view.test.ts`.
