## Context

Seen repeatedly on 2026-10-04 in local Playwright runs (never in the CI Gate job so far): a test's first `page.goto` gets SvelteKit's "500 Internal Error", chunk fetches under `/_app/immutable` abort with `net::ERR_NETWORK_CHANGED` then "Failed to fetch dynamically imported module", `page.goto: Page crashed`, or a 30 s navigation timeout. It hits different, unrelated tests each run and blocks gates at random. Known contributing causes so far: (1) two `make check` runs in one working tree share `build/` — `licenses-bundle` runs `pnpm build` under the preview server, so the preview serves a half-written `build/` (T-039 developer, round 1); (2) host load (load average 22–40 on 6 cores, ~0 GB free memory) and Docker network connect/disconnect events from other projects while the browser runs (T-015, T-039 validators). Find the causes that are ours to fix (e.g. the gate rebuilding `build/` while a preview serves it; `reuseExistingServer` reusing a preview over a changing `build/`; Playwright workers vs host capacity) and make the gate robust against them, without retries that hide real failures.

## Acceptance

- [ ] The gate's e2e step never serves a `build/` that another step of the same or a concurrent gate is rewriting (e.g. licenses-bundle builds elsewhere, or the e2e build is private to the run)
- [ ] Failure branch: a page that fails to boot is reported with its cause (status, failed chunk), not as an unrelated assertion timeout; no blanket retry added
- [ ] Test that fails without the change: a reproduction script or test that rewrites `build/` during an e2e run and shows the 500 before, not after (evidence in the task)
