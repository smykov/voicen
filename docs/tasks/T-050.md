## Context

Seen repeatedly on 2026-10-04 in local Playwright runs (never in the CI Gate job so far): a test's first `page.goto` gets SvelteKit's "500 Internal Error", chunk fetches under `/_app/immutable` abort with `net::ERR_NETWORK_CHANGED` then "Failed to fetch dynamically imported module", `page.goto: Page crashed`, or a 30 s navigation timeout. It hits different, unrelated tests each run and blocks gates at random. Known contributing causes so far: (1) two `make check` runs in one working tree share `build/` — `licenses-bundle` runs `pnpm build` under the preview server, so the preview serves a half-written `build/` (T-039 developer, round 1); (2) host load (load average 22–40 on 6 cores, ~0 GB free memory) and Docker network connect/disconnect events from other projects while the browser runs (T-015, T-039 validators). Find the causes that are ours to fix (e.g. the gate rebuilding `build/` while a preview serves it; `reuseExistingServer` reusing a preview over a changing `build/`; Playwright workers vs host capacity) and make the gate robust against them, without retries that hide real failures.

## Acceptance

- [ ] The gate's e2e step never serves a `build/` that another step of the same or a concurrent gate is rewriting (e.g. licenses-bundle builds elsewhere, or the e2e build is private to the run)
- [ ] Failure branch: a page that fails to boot is reported with its cause (status, failed chunk), not as an unrelated assertion timeout; no blanket retry added
- [ ] Test that fails without the change: a reproduction script or test that rewrites `build/` during an e2e run and shows the 500 before, not after (evidence in the task)

## Investigation

Investigator, 2026-10-05. Serena was not used; I read files directly and grepped. The Playwright API comes from the installed package (`playwright@1.63.0` `types/test.d.ts`, `TestConfigWebServer`). The SvelteKit behaviour comes from installed `@sveltejs/kit@2.70.3` `src/exports/vite/preview/index.js` and `src/exports/vite/index.js` (`buildStart` → `rimraf(out)`). Experiments ran in a throwaway worktree (`/tmp/t050-inv-wt`, since removed) with its own preview on port 4373/4374. /projects/voicen was not touched apart from this file.

**Frame.** Observed: local e2e tests fail at page boot. The failing tests vary from run to run and are unrelated to each other. The page shows "500 / Internal Error", or `page.goto: Page crashed`, or a 30 s goto timeout. Expected: a boot either works or fails with its cause. CI Gate: never seen there.

**Correction to the task's premise.** `pnpm preview` (SvelteKit's preview plugin) does not serve `build/`. It serves `.svelte-kit/output/client` through sirv, which caches the file list once at start. It renders pages through `.svelte-kit/output/server` (manifest imported at start, route nodes imported lazily on first use). Every `vite build` starts with `rimraf(.svelte-kit/output)`. SvelteKit's version timestamp changes the hashed names on every build.

**Hypotheses.**
1. *M1: a concurrent build rewrites the served output.* **Confirmed as a mechanism (reproduced).** It is not seen in any trace yet. Possible writers in one tree:
   - another gate's `licenses-bundle`;
   - another gate's Playwright webServer `pnpm build`.

   Within a single serial `make check`, e2e finishes before `licenses-bundle` starts, so one gate alone cannot hit this.
2. *Second path: port 4173 is shared across trees.* **Confirmed by config reading** (not run). `reuseExistingServer: !CI` with a fixed port means a gate in a worktree reuses whatever preview listens on 4173. That preview may come from another tree with other code, which is a silent correctness hole. Playwright stops the webServer it started when its own run ends, so the reusing gate loses its server mid-run.
3. *M2: host network change.* **Confirmed (reproduced, and matches every trace).** Chromium runs in the host netns. Docker user-network or interface events from other jobs abort in-flight requests to localhost with `net::ERR_NETWORK_CHANGED`. SvelteKit's client router then fails `import(nodes/N.js)` and renders its own error page, "500 / Internal Error". That is a client-side 500; the server answered 200.
4. *M3: renderer crash or timeouts under memory and CPU pressure* (load 22–40, ~0 GB free per T-015/T-039). **Hypothesis, not reproduced.** Host load was ~1.4 and there were 8 GB available during this investigation. Crashes left no trace. What is missing: a crash reproduction under a memory cap, for example a cgroup or `systemd-run -p MemoryMax=`.
5. *Fixed before.* No `docs/failures.md` entry of this class. F-004 is a related pattern (a shared, released resource reused by a sibling) but a different class, in core tests. `recurrence_of: []` is right.

**Evidence: M1, server side.**
- Fresh preview, then `mv .svelte-kit/output` away, which simulates the rimraf window of a concurrent build. `GET /settings` returns `HTTP 500 {"message":"Internal Error"}`. The preview log shows `Error [ERR_MODULE_NOT_FOUND]: Cannot find module '.../.svelte-kit/output/server/nodes/0.js' imported from .../manifest.js`.
- After the directory is restored, `/settings` and `/` are still 500. `manifest.js` `__memo` caches the rejected import, so one hit poisons the preview for its whole life.
- Real race (`pnpm build` while the preview serves; GET of the manifest's entry chunk every 50 ms): 31 × 200, then the preview process dies with `Error: ENOENT: no such file or directory, open '.../output/client/_app/immutable/entry/start.DuKo9wwT.js'` (an unhandled ReadStream `error` event). After that every request is refused (curl 000). The rebuilt chunk names differ from the served ones (`start.Cr_kodhy.js` vs `start.DuKo9wwT.js`).

**Evidence: M2, client side.** I ran `BASE_URL=http://localhost:4373 npx --no playwright test e2e/{tauri-mock,build-info,overlay,settings-warning}.spec.ts --repeat-each=2` (100 tests) under three kinds of background Docker activity:

| Run | Background Docker activity | Result |
|---|---|---|
| Host netns | `docker network create t050-probe-N && docker run --rm --network t050-probe-N voicen-rust:1.99 true && docker network rm …` | 3, 1 and 5 failed of 100 (three runs) |
| Private netns (`unshare -n`, `ip link set lo up`, preview and Playwright inside) | same churn | 100/100 passed, twice |
| Host netns | `docker run --rm voicen-rust:1.99 true` ×30, default bridge (what `tw-run core` does) | 50/50 passed |
| Host netns | `docker network create/rm` with no container | 40/40 passed |

The one kept trace (`overlay.spec.ts:406`) shows:
- `ERR_NETWORK_CHANGED` ×4;
- `Failed to fetch dynamically imported module: http://localhost:4373/_app/immutable/nodes/3.BbH1yG47.js` ×2;
- page snapshot: heading "500", paragraph "Internal Error";
- reported as `expect.poll … the overlay page listens to overlay://state … Received: 0`, an unrelated assertion.

This is exactly the T-015 verify/1 and T-039 verify/1 signature.

**Root cause.** There are two mechanisms, not one:
- **M1 (ours).** The e2e preview is neither run-private nor tree-private: its served directory `.svelte-kit/output` and its port are shared. A concurrent build crashes or poisons it.
- **M2 (environment).** The host-namespace browser takes Docker network events from other jobs as network changes and aborts boot chunk fetches.

All observed traces fit M2. M1 is a real, reproducible hazard. The T-039 developer report and the T-045 note fit M1 or M2; their failures left no server log that could tell the two apart. Contradicting evidence: none. M3 (crashes) is still unproven.

**Invariant.** An e2e run serves only a build it made itself, into a directory and on a port no other process writes or binds. A page that fails to boot fails the test with the boot cause, never as an unrelated assertion.

**Seams.**
- **M1:** `playwright.config.ts` `webServer` together with `svelte.config.js` `kit.outDir`, which can be set from an env var such as `VOICEN_E2E_OUT_DIR` (default `.svelte-kit`, so lint, `tauri build` and `licenses-bundle` are unchanged). The flow:
  - the config creates or reads one run-private dir (in the runner process, before workers start; workers inherit env);
  - the command runs `pnpm build && pnpm preview` with that env;
  - the preview uses a run-private port;
  - `reuseExistingServer` is false unless `BASE_URL` is set explicitly. With false, Playwright throws if the port is taken, a loud failure instead of a silent reuse.

  The port can come from a free-port probe with `--strictPort`, which turns a rare collision into a loud failure. Alternatively, Playwright 1.63 `webServer.wait.stdout` with a named group captures the port vite printed into env (see `TestConfigWebServer.wait` in the installed types), and the developer verifies how tests read it.

  Every caller goes through this: `make check-ui`, `pnpm e2e`, and validators' worktrees.
- **Failure branch:** one boot fixture in `e2e/support/` that every spec's `page` goes through, for example `test.extend` overriding `page`, with specs importing `test`/`expect` from it. There are 25 `goto` sites in 8 spec files. The fixture records:
  - `requestfailed` (URL + `failure().errorText`);
  - responses with status >= 500;
  - `crash`;
  - `pageerror`.

  When the test fails, or the SvelteKit error page is shown, it fails with that list.
- **M2:** a second seam: the network namespace of the ui e2e run, configured in `.teamwright/config.yml` area `ui` (runner host) and `make check-ui`. Options: the Playwright image as a docker runner for e2e (a `mcr.microsoft.com/playwright` image of another version is already on the host; 1.63 would need a download), or `unshare -n` around the e2e step (needs root or user namespaces; Linux only). Either changes the toolchain and is an **owner decision**. CI is not affected.

**Approach (options).**
- **(A) M1: private build dir + private port + no implicit reuse.** Recommended, do it now.
  - Red first: a committed reproduction that runs the e2e webServer, then `pnpm build` in the same tree while it serves, and asserts `/` and the manifest's entry chunk still return 200. Before the fix: 500 or connection refused. After the fix: 200, because the preview serves the private dir.
  - Then the boot fixture, with a spec that aborts one `/_app/immutable/nodes/*` route (`page.route(..., r => r.abort('internetdisconnected'))`) and expects the error to name the URL and errorText.
  - Risk: kit `outDir` drives generated tsconfig paths, so only the e2e build may set it. The private dir must be cleaned up (a mktemp dir under `target/`, removed in `globalTeardown`).
  - Rollback: revert the config.
- **(B) M2: private network namespace for the e2e browser.** Owner decision.
  - Evidence: 0/200 vs 9/300 under the same churn.
  - Red test: the churn loop above with the e2e step fails before and passes after. It needs a host with Docker.
  - Risk: needs root or user namespaces, or an image download; the setup differs from CI.
  - Rollback: config.
- **(C) Lock instead of privacy:** `flock` on a per-tree lock around `make check`. It serialises gates in one tree but does not fix cross-tree port reuse or M2. Not recommended alone.
- **Not acceptable:** retries. `retries: process.env.CI ? 1 : 0` stays as is.
- **Related shared state, not part of this bug:** `target/licenses/npm-bundled.json` is shared by concurrent gates in one tree (`licenses-bundle` runs `rm -f` and then builds). Same class of shared output, flagged for the orchestrator.

**Scope.** The work spans more than one seam: M1 (e2e config plus support fixture) is ours, and M2 is a toolchain or environment decision for the owner. Suggestion: T-050 does (A) plus the boot fixture. M2 goes to `docs/open-questions.md` or a follow-up task with the evidence above. M3 stays a hypothesis until a crash is reproduced. After (A), the Acceptance's "never serves a build/ another step is rewriting" holds. Boots aborted by host network changes will still fail, but with their cause named.

## Tests

Test-writer, 2026-10-05 (M1 only, decision #77). Serena and context7 were not used; the Playwright API was checked against the installed `playwright@1.63.0` (`types/test.d.ts`: `JsonReporterOptions.outputFile`) and by probes.

- `scripts/ci/e2e-build-race.sh` runs `e2e/build-race.spec.ts` through the gate's own `playwright.config.ts` webServer (BASE_URL unset, `--retries=0`), one scenario per run:
  - `build`: a `pnpm build` with a plain shell env runs in the tree while the preview serves; `/`, the entry chunk served at the start and `/settings` must answer 200 during and after it. Red today: 183 × `ECONNREFUSED ::1:4173` and 1 × `socket hang up` (the preview died on ENOENT).
  - `foreign-port`: a foreign HTTP server holds 4173; `/` must be this run's build. Red today: body `t050-foreign-server` (`reuseExistingServer` reused it).
  - Without `VOICEN_E2E_BUILD_RACE` both tests are skipped, so `pnpm e2e` runs no second build.
- `e2e/boot-failure.spec.ts` runs `e2e/fixtures/boot-failure/boot-failure.inner.ts` (ordinary specs on `e2e/support/boot.ts`) in a child Playwright run against this run's preview and reads its JSON report. Code frames are stripped from the messages, so only runtime text counts. Tests: healthy boot passes; aborted page chunk → message has the URL and `net::ERR_INTERNET_DISCONNECTED`; chunk 500 → URL and `500`; boot failure with assertions that pass → still fails with the cause; renderer crash (CDP `Page.crash`; `chrome://crash` is refused as a navigation) → `crash`; every spec that uses `page` imports `test` from `./support/boot`. Red today: the inner run cannot load (`Cannot find module e2e/support/boot`); 7 specs import `test` from `@playwright/test`.

Bite check (throwaway worktree, removed afterwards):
- No fixture (`boot.ts` re-exports `@playwright/test` = today's reporting) → aborted-chunk, 500, assertions-pass and crash tests red (message only the unrelated assertion); healthy passes.
- Fixture fails only when the test already failed → "fails the test even when its own assertions pass" red.
- Fixture fails with a generic "page failed to boot" (no URL/status/errorText) → aborted-chunk, 500, assertions-pass, crash red.
- Fixture records only `requestfailed` (no status >= 500, no crash) → 500 and crash red.
- Reference fixture (requestfailed + response >= 500 + crash, throw in teardown) → all 5 green; after migrating the 7 specs' imports the structural test is green.
- M1 port-only (random port + strictPort, outDir unchanged) → `build` red (ECONNREFUSED; WebServer ENOENT `.svelte-kit/output/.../start.*.js`), `foreign-port` green.
- M1 dir-only (`kit.outDir` from env in a mkdtemp dir, port 4173 + reuse) → `foreign-port` red, `build` green.
- Reference M1 (both, `reuseExistingServer: false`) → both scenarios PASS.
