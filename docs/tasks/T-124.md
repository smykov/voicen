## Context

Area core, seams `crates/voicen-core/src/call/capture.rs` and `call/wav_source.rs`, fake clock only. Needs T-116 and T-118. Dictation's `FrameSink` / `AudioSource` stay unchanged (FR-009).

## Acceptance

- [ ] Blocks are placed at `(stamp − call_start) × 16 kHz`, with downmix and resampling (T020, T021)
- [ ] Fake sources at +50 ppm and −50 ppm stay within 20 ms of each other at minute 60; `ratio_adj` is clamped to ±500 ppm (T020)
- [ ] An offset above 40 ms re-anchors at once (ahead → zeros, behind → overlap dropped); a gap of 200 ms or more is reported (T020)
- [ ] Failure branch: a lost track keeps advancing with zeros from the other track's stamps or the session tick (T020)
- [ ] Failure branch: a full callback channel drops blocks, fills the time with silence and reports the drop (T020)
- [ ] `WavTrackSource` reads 16-bit PCM and f32 RIFF with synthetic stamps at an accelerated pace, a drift factor and scripted gaps (T020, T021)
- [ ] Levels are RMS over 100 ms blocks, at most 10 Hz (T020)
- [ ] Test that fails without the change: the `call/capture.rs` and `call/wav_source.rs` tests

## Investigation

2026-11-04, problem-investigator (main tree, at f2d84ad3). Tools: Serena (`get_symbols_overview`, `find_symbol` on `call/events.rs`, `audio/mod.rs`, `clock.rs`, `diag/event.rs`), grep for the spec docs, and the rubato 5.0.1 source in `.teamwright/cache/core/_usr_local_cargo_registry/` (I did not query context7, because the pinned source is on disk).

**Frame.** This is a feature with nothing in place yet. The spec asks for two tracks on one clock (FR-011, at most 100 ms at minute 60 under 50 ppm drift; the test target is 20 ms). Every gap must be silence (FR-012), and each source must be replaceable by a WAV file (FR-014). Today core has none of this. Dependencies: T-116 (codec, `TrackEncoder::push(&[f32])` at 16 kHz) and T-118 (`Track`, `EndpointId`, the call `LogEvent`s) are both DONE.

**What exists and why it cannot be reused as is.**
- `platform::FrameSink` / `AudioSource`: an `Instant` taken at callback entry, which carries several ms of scheduling jitter (R2). FR-009 says these stay unchanged, so the call ports are new.
- `audio::resample::mono_to_16k`: `rubato::Fft` with `process_all` over a whole clip at a fixed ratio. It cannot stream or change its ratio. rubato 5.0.1 `Async::new_sinc` / `new_poly` take `max_resample_ratio_relative` and implement `Adjustable::set_resample_ratio_relative(rel, ramp)` (`src/asynchro.rs`, `src/lib.rs`). No new crate is needed, and `THIRD-PARTY-NOTICES.txt` does not change.
- `audio::mix_to_mono`: the one downmix rule. Reuse it.
- `test_support::realtime::read_wav`: PCM16 only, and `RealtimeSource` is paced by `clock::instant()`. That is dictation's test source (FR-009), so leave it alone. `wav_source.rs` gets its own RIFF reader (tag 1 with 16 bit, tag 3 with 32 bit float; anything else gives `WavError`, never a panic). The chunk walk is duplicated on purpose; merging the two readers can be a follow-up.
- `platform::DeviceId` and `platform::CaptureHandle` fit `TrackDevice::Selected` and the `open` return value of the contract. Reuse them.

**Design points for the developer (inside the contract, no owner needed).**
1. **Placement.** `Timeline::new(track, call_start: CaptureStamp)`. For each block, expected = (stamp − call_start) × 16000 / 1e9, the position of the block's first 16 kHz sample.
   - The first block zero-fills from 0, so the file starts at the call start (in 1a both tracks are open before `call_start`, and `start_offset_ms` stays 0).
   - Samples stamped before `call_start` are dropped.
2. **Drift loop.** error = expected − (written + resampler `output_delay` and buffered input).
   - `ratio_adj` = clamp(Kp·e + Ki·∫e, ±500 ppm), applied with `set_resample_ratio_relative(1 + ratio_adj, true)`. The resampler is built with `max_resample_ratio_relative` ≥ 1.0005.
   - The integrator stops growing while the output is clamped (anti-windup).
   - Keep 16 kHz input on the same path (ratio 1 ± adj), so drift is trimmed there too.
3. **Re-anchor.** If |error| > 40 ms, act at once: ahead → push zeros, behind → drop the overlapping head of the resampled block. Then reset the loop state.
   - Report `Gap { at_ms, gap_ms }` when an insert or drop is ≥ 200 ms.
   - The Timeline only returns reports. It never logs and never writes `meta.json`.
4. **Callback channel.** `ChannelSink` implements `TrackSink` over `sync_channel(N)` with `try_send`.
   - On `Full` it adds the block's frame count and stamp span to a per-track `AtomicU64` drop counter.
   - The consumer reads the counter before the next block, zero-fills that span exactly (even below 40 ms, so a short drop is not left for the slow loop to absorb over tens of seconds) and returns `Dropped { blocks, ms }`.
   - `lost()` goes through the same channel. When the channel is full, a `lost` flag is set instead, so a loss is never itself dropped.
5. **Lost or silent track.** `Timeline::advance_to(stamp)` is called with the other track's stamps or the session tick (`TrackSource::now()`).
   - For a track marked lost, it fills zeros up to expected(stamp).
   - For a live track, it fills only past a hold-off (200 ms), so a block that arrives late is never clipped. A red test: a block 30 ms behind the other track keeps all its samples.
   - WASAPI loopback sends no packets while nothing plays. The hold-off covers that, and the next block re-anchors.
6. **Levels.** RMS of each full 1600-sample (100 ms) window of the Timeline's output, zeros included, so a lost track reads 0. That gives at most 10 Hz by construction. The output is linear `f32` 0..1; the indicator mapping is T-126's.
7. **`WavTrackSource`** (`#[cfg(any(test, feature = "test-fakes"))]`, like `RealtimeSource`; `src-tauri` dev-depends on `test-fakes`):
   - No thread and no wall clock (core-tests: no wall-clock ceilings, `clock` ban). `open` stores the sink. `pump(until: CaptureStamp)` pushes every block whose synthetic stamp is ≤ `until` on the caller's thread, and `now()` returns the source's current stamp. "Accelerated" means the test pumps as fast as it likes.
   - Drift factor d: stamp_k = start + k·N / (rate·(1 + d)).
   - Scripted gaps: `Stall { at_ms, len_ms }` (no blocks, then a later stamp) and `Lost { at_ms }` (calls `sink.lost`).
   - Past the end of the file it pushes silence, as a live device would.
8. **`OpenError`** is `no_device | access_denied | busy | other` and maps one-to-one onto the matching `RefusedReason` variants. **`LossCause`** is `invalidated | not_available | other` (R4: call tracks treat `StreamInvalidated` and `DeviceNotAvailable` as losses). What to do on a loss is T-149's.

**Risk: test runtime.** Sixty minutes × 16 kHz × 2 tracks is about 115 M samples through a sinc resampler in the debug profile. Use 100 ms blocks and 16 kHz mono input for the 60-minute drift test, and measure it. If it takes minutes, add `[profile.dev.package.rubato] opt-level = 3` to the root `Cargo.toml` (not a guard path) rather than shortening the test. The 48 kHz stereo placement test can be short.

**Guard paths.** None (no `scripts/ci/`, `scripts/licenses/`, `Makefile` or `*.mk`), so `decides_on` is empty and `checker: false` stays.

**Overlap.** Not with `call/final_pass.rs` (T-137) or `call/storage.rs` (T-125). The only shared file is `call/mod.rs`: each of the three tasks adds its own `pub mod` line and re-export line, so expect a trivial merge.

**Points for T-126, not blocking T-124 (spec gaps for the orchestrator to note).**
- **Q1.** R3 and the contract say a non-device gap (missing callbacks) and a channel drop are logged. The closed grammar (`diag::event`, T-118) has only `call_device ... cause=<DeviceCause> gap_ms` for gaps, and no line for a drop. T-124 returns typed reports only. T-126 needs either a new event (for example `call_track_gap track=<..> cause=<stall|dropped> gap_ms=<n>`) or an explicit decision that they go only into `meta.json`.
- **Q2.** With WASAPI loopback silent during playback pauses, "every re-anchor ≥ 200 ms is a gap in `meta.json`" may record a gap at every pause in the far-end audio. T-126/T-149 should decide whether stall gaps without a device change are persisted. The Timeline reports them either way.
- **Q3.** `WavTrackSource` is pump-driven (design point 7). T-126's session tests and T-127's shell tests must call `pump` rather than expect a background thread.

**Recurrence.** None. This is a new area (`class: call-capture`); `docs/failures.md` has no capture or timeline entry.
