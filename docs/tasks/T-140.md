## Investigation

**Tools.** Serena was loaded. I used `get_symbols_overview` on `engine/openai.rs` and `test_support/realtime.rs`. The rest was read directly: lib.rs, audio/mod.rs, engine/mod.rs, timeouts.rs, secrets.rs, Cargo.toml, clippy.toml and the Makefile. I searched specs and docs with grep and `scripts/tw-req FR-047`. FR-047 is a spec 007 id, so it does not appear in requirements.md. No library API is new: the example uses only std, sha2 0.10 (already used for model SHA-256) and existing core APIs, so I did not query Context7.

**Framing.** This is a feature, not a defect. Acceptance needs four things: normalization, word-level WER on fixtures, an empty reference handled without a panic, and an owner-run example. The example reads WAV only, documents the FLAC conversion, uses a committed manifest of at least 30 min with the MD5 and SHA-256 pinned, and takes the key from the environment.

**Recurrence check.** docs/failures.md F-001..F-022 has no scoring, harness, WER or transcript-measurement class. The nearest rule is the privacy one: no transcript text or key in logs (FR-20, NFR-04, docs/decisions/diagnostics-log.md). The example is not the app log, but the Russian set is the owner's customer data. So the invariant makes the example print counts and ids only, never text or the key.

**Normalization choices.** These are within R23 and need no owner decision. I recommend the developer adopt them as written:
- **Rule:** std only, with no Unicode-category crate (#186). A char is a word char iff `char::is_alphanumeric`. Apostrophes `'` and `’` are deleted, so LibriSpeech `DON'T` and Whisper `don't` both become `dont`. Every other non-alphanumeric char separates words, so `twenty-five` becomes `twenty five`, which matches LibriSpeech's form.
- **Numbers as written:** `25` stays `25` and counts as an error against `TWENTY FIVE`. R23 accepts this cost. `3.5` becomes `3 5`.
- **`ё` → `е`:** applied after lowercasing, which also covers `Ё`.
- **Empty reference:** `rate()` returns `None`. The example reports it as "n/a" and still adds the insertions to the set totals.

**Plan gaps found (decision points).**
- **D1: what the example transcribes through.** This is the main point. The orchestrator can settle the task split; the owner settles what SC-004 measures.
  - **The conflict:** R23 says the utterances are concatenated per speaker group "so the chunker and VAD are exercised", and FR-047 says "the final's WER". But tasks.md marks G26 as independent and T-140 has `depends_on: []`. The final-pass runner (T-138), the chunker (T-137) and SpeechSpans (T-134) do not exist yet.
  - **Two more constraints:**

  - **Recommendation:**
    - T-140 ships the scorer and a per-utterance harness. LibriSpeech utterances are at most about 35 s, so each is one `Engine::transcribe`. That meets every Acceptance line as written.
    - The orchestrator opens a follow-up task. It depends on T-138 and switches the example to concatenation plus the pass runner, which is where R23's speaker-group concatenation belongs.
    - That follow-up goes into T-159's `depends_on`. Today T-159 does not list T-140 either, which is a gap of its own.

- **D2: who pins the SHA-256 and builds the manifest.** Picking at least 30 min of ids needs the per-utterance durations, and they are only in the archive (FLAC STREAMINFO). Recommendation: the developer downloads `test-clean.tar.gz` (346,663,984 bytes) once on the dev host and checks MD5 `32fa31d27d2e1cad72775fee3f4849a9` with `md5sum`. They pin the `sha256sum` result in the manifest header and as the example's constant. They pick whole chapters totalling 32 min or more, for margin, with durations taken from the STREAMINFO headers. No decoder or new tool is needed. The download needs network access and 346 MB on the host; if downloads need owner consent, ask first. The fallback is that the owner sends the SHA-256 and the id list. The MD5 is checked with the external `md5sum` (documented in the usage), because there is no md5 crate (#186).

Update quickstart.md step 8 in the same commit. The env names VOICEN_WER_KEY, VOICEN_WER_BASE_URL (default `https://api.openai.com/v1`, passed through `check_base_url`) and VOICEN_WER_MODEL (default `whisper-1`; Groq through base URL and model) are a proposal.
