## Context

Owner decision #63: try a Linux-side type check of the Windows shell so compile errors are caught before a push (each Windows CI round costs ~25 min). Spike: can `src-tauri` (tauri 2.12.1, windows 0.62, aws-lc-rs via rustls) pass `cargo check --target x86_64-pc-windows-gnu` in the voicen-rust image with mingw-w64 and the target installed (image change in docker/rust.Dockerfile, `make core-image`)? It needs a built frontend (`pnpm build`) for tauri's context macro. If it works, add a `check-shell-windows` target to `make check`; if not, record why (docs/decisions/ci-toolchain.md) and close. Follow F-001/F-002 rules (shell tests and doctests).

## Acceptance

- [ ] `make check` runs a Windows-target type check of src-tauri on Linux and it passes on the current code, or the task records with evidence why it cannot (and the gate is unchanged)
- [ ] Failure branch: a deliberate type error in src-tauri/src makes the new step fail locally (shown once, reverted)
- [ ] Test that fails without the change: the new make target (or the recorded spike result)
