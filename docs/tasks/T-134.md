## Investigation

**Frame.** This is a feature and nothing is broken. Dictation needs one bool per recording (FR-12), so `vad` was built as a yes/no seam (T-041, T-043). The call final pass (spec 007 FR-023, R8) needs to know where the speech is. It cuts chunks of at most 120 s at pauses and sends nothing for silence or music (SC-008). Three things are missing: a span port, a span type, and spans from the energy detector (the #188 fallback).

**Current code.** Read with Serena `get_symbols_overview` on `vad/mod.rs`, `vad/energy.rs` and `voicen-whisper/src/silero.rs`. Serena `find_referencing_symbols` on `SpeechDetector` returned nothing, so callers were found with grep over `crates/` and `src-tauri/`.
- `vad::SpeechDetector` (mod.rs:23-28) returns `Result<bool, VadError>`. `vad::VadError` (mod.rs:33-38) already has the two causes that `vad_fallback cause=<unavailable|error>` needs.
- `vad::SpeechGate` (mod.rs:63-113) is dictation's fallback. It is infallible and latches the primary off for the gate's lifetime. The pass's fallback is per track with a logged cause (contracts/core-call.md `VadFallback`), so the gate does not fit. It stays as is.
- `vad::energy::analyse` (energy.rs:100-135) already finds every loud run, then drops it after counting. The spans are those runs (at least `MIN_RUN_FRAMES` long) as `[i*30, (i+run)*30)` ms. To keep one energy rule, spans are empty when `counted < MIN_SPEECH_FRAMES`, which is exactly when `detect` is false. Gaps are not merged here: merging gaps under 300 ms and the 200 ms pad belong to the chunker (R9, T-137).
- `voicen_whisper::SileroDetector::contains_speech` (silero.rs:101-108) computes whisper.cpp segments (in centiseconds) and sums them. Returning them, converting cs to ms and sharing the model load with dictation are T-135's work. Note for T-135: `SileroDetector::load` returns `Box<dyn SpeechDetector>` (silero.rs:62). To serve both traits from one VAD context, it must return the concrete type or an `Arc`.
- Callers of `SpeechDetector` / `SpeechGate` outside `vad/` are `silero.rs` and 6 core integration tests: `tests/api_pipeline.rs`, `local_engine.rs`, `local_server.rs`, `local_no_network.rs`, `diag_pipeline.rs`, `diag_format.rs`. A separate trait leaves all of them unchanged.

**Hypotheses considered.**
1. Add a span method to `SpeechDetector`. Rejected as the shape: every implementer and fake would change, and per-recording use would mix with per-window use. R8 says "next to".
2. Give the pass its own energy code. Rejected by P-011 and R8 ("one VAD stack"): energy spans must come from `analyse`.
3. Was this class fixed before? No. `docs/failures.md` has no VAD, energy or Silero entry. Only T-135 shares `class: call-vad`. `git log` on `vad/` shows only T-041 and T-043, both feature work.

**Port shape (recommended).**
```rust
pub struct SpeechSpan { pub start_ms: u64, pub end_ms: u64 } // [start, end), relative to the buffer
pub trait SpeechSpans: Send + Sync {
    fn name(&self) -> &'static str; // "silero" | "energy", as SpeechDetector
    fn speech_spans(&self, audio: &AudioBuffer) -> Result<Vec<SpeechSpan>, VadError>;
}
```
Times are relative to the buffer; the pass adds the window offset. The scripted fake returns spans or a `VadError` from a queue and counts its calls, like `FakeDetector` in the mod.rs tests. It lives in `crate::test_support` behind `test-fakes`, so T-137 and T-138 can use it too.

**Consumers of the port.**
- T-135: the Silero implementation; it already depends on T-134.
- T-137: the chunker takes spans, so it needs `SpeechSpan`, but its `depends_on` is only `[T-116]` (see Q2).
- T-138: the pass runner (Silero first, energy fallback, `vad_fallback`); it already depends on T-134.
- T-139: the shell wiring, through T-135 and T-138.

**Owner / orchestrator decision points.**
- **Q1: where the #188 fallback selection lives.**
  - (A) In T-138's pass runner, where tasks.md T046 puts it. T-134 delivers only the port, the type, energy spans and the fake. Its failure branch is: an `Err` passes through the port unchanged and never becomes an empty Vec.
  - (B) A small selector in `vad` (Silero spans, or energy spans plus the cause), tested in T-134.
  - **Recommendation: (A).** It keeps the spec's task split, and T-138 already has the acceptance line "Silero unavailable → energy spans and `vad_fallback`". T-138's review should check that an `Err` never becomes empty spans.
- **Q2: T-137's dependency on the span type.**
  - **Recommendation:** add `T-134` to T-137's `depends_on`, so the chunker takes `vad::SpeechSpan` and there is one span type (P-011).
  - The alternative is for T-137 to define its own span type and for T-138 to convert between the two.
  - Not edited here: T-137 belongs to a concurrent investigator.
- **Q3 (developer level, written down so it is not chosen silently).**
  - Energy spans keep the `MIN_SPEECH_FRAMES` total threshold, so they are empty exactly when `detect` is false.
  - The noise floor is computed per window, because the pass calls the port once per decoded window (at most 120 s plus carry, FR-018).
  - No new constants.

**Size.** Small: one seam (`vad/`), only additions, testable on Linux. No spec-tool work needed.
