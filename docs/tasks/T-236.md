## Context

On 2026-11-18 five contour `implement` stages ended with `The action 'The stage' has timed out after 240 minutes` (`teamwright-agent.yml`): T-217 (run 44277742977), T-171 (44282080254), T-165 (44307768381), T-130 (44314973273), T-145 (44333153525). Each time the branch `task/<ID>` kept only the red-tests commit: the implementation was not committed before the gate, so the whole stage was lost and has to be re-run from scratch. T-171's re-run (44323668743) then succeeded once host load dropped.

Observed while it happened: a core gate took about 38-46 minutes (`scripts/tw-gate core`; locally 46m15s for T-213), sessions re-ran it after a red step, host load average reached 46-62 with up to 4 contour stages plus 2 local worktree pipelines and a local top gate at once (decision #316 then capped the contour at 3).

Owner decision (2026-11-18, this session): open this rca task rather than only lowering the limit. Exits the orchestrator proposed: commit the work in progress before the gate (so a timeout keeps it), a longer stage timeout, fewer parallel gates on the host (one heavy gate at a time across contour and local work). Per CLAUDE.md the investigator recommends; exits (b) `/arch-review` and (c) a `PRINCIPLES.md` amendment are the owner's.

Note: `.github/` edits are not done in the contour (decision #315); this task runs in the attended session.
