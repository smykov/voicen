## Context

On 2026-11-18 five contour `implement` stages ended with `The action 'The stage' has timed out after 240 minutes` (`teamwright-agent.yml`): T-217 (run 44277742977), T-171 (44282080254), T-165 (44307768381), T-130 (44314973273), T-145 (44333153525). Each time the branch `task/<ID>` kept only the red-tests commit: the implementation was not committed before the gate, so the whole stage was lost and has to be re-run from scratch. T-171's re-run (44323668743) then succeeded once host load dropped.

Observed while it happened: a core gate took about 38-46 minutes (`scripts/tw-gate core`; locally 46m15s for T-213), sessions re-ran it after a red step, host load average reached 46-62 with up to 4 contour stages plus 2 local worktree pipelines and a local top gate at once (decision #316 then capped the contour at 3).

Owner decision (2026-11-18, this session): open this rca task rather than only lowering the limit. Exits the orchestrator proposed: commit the work in progress before the gate (so a timeout keeps it), a longer stage timeout, fewer parallel gates on the host (one heavy gate at a time across contour and local work). Per CLAUDE.md the investigator recommends; exits (b) `/arch-review` and (c) a `PRINCIPLES.md` amendment are the owner's.

Note: `.github/` edits are not done in the contour (decision #315); this task runs in the attended session.

### Root cause

The contour job pushes a stage's commits only when the session step succeeded (`steps.claude.outcome == 'success'` on the count and push steps), so a stage that runs out of time loses everything it made. Stages ran out of time because the implement stage runs 2-4 whole-repo `make check` gates. Each takes 25-100 min depending on host load. One of them is often a byte-identical repeat (`--top` after `core` on the same key), and load failures force full reruns. Contradicting evidence: none found. T-171's loss also needs the patch part of the invariant, because its tree was never committed.

Root or symptom: the loss on timeout is the root of the class "a stage loses its work". The long gates are the trigger, and their cost can always outgrow a fixed budget. On this one host, the same work took 25 min in one run and 99 min in another. Raising the timeout or lowering the cap (#316) only moves the threshold.

### Earlier patches of the class and why they did not hold

- **#316 (2026-11-18), cap the contour at 3 tasks, held by the orchestrator.** It lowers load but bounds neither the gate count nor the gate duration, and it does not cover local worktree pipelines or the main tree's gates on the same host. Three of the five timeouts (T-165, T-130, T-145) happened with 3 contour stages running.
- **#296 / #292 (MAX_PARALLEL 5).** This is the setting that produced the load. The monitoring note in #296 already said 5 is safe "only if builds do not coincide".
- **F-027 (2026-11-06)** recorded that `core` and `--top` run two `make check` of one tree as "teamwright feedback". It was never filed in `docs/kit-feedback.md`, so the repeat stayed.

### Approach

- **Option 1, recommended.** Exit (a); see `analysis.approach`.
  - Red test: `contour: a timed-out stage still pushes its commits and keeps its uncommitted diff`, in `scripts/ci/release-guard.test.sh` next to the upload-tail checks (`cu_expect ... no condition names steps.claude`). It goes green when the owned fragment `scripts/ci/contour-push.yml` matches the workflow and its `if:` lines hold no `steps.claude`. A mutant that puts `&& steps.claude.outcome == 'success'` back into the push step turns it red.
  - Risk: an incomplete implementation lands on `task/<ID>`. That is not a delivery (#253), the chain stops on failure, and the next implement session starts from it instead of from scratch.
  - Rollback: revert the commit.
  - Process: needs `checker: true` (guard paths under `scripts/ci/`) and the attended session (#315: `.github/`).
- **Option 2, workaround.** Raise `timeout-minutes` of the stage. No test can show it removes the cause, because gate duration is unbounded under load.
- **Option 3, exit (b), owner's decision.** Make the stage fit its budget. Inputs for `/arch-review`:
