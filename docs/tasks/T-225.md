## Context

From follow-up T-203 impl#1 (Medium, product-hypothesis, not demonstrated), owner's grouping 2026-11-17: `Writer::drain` empties one track's channel before it reads the other, so under sustained writer overload the track drained second can starve; its `Seen.last_event` then ages past `STALL` (500 ms) and, when drain returns, `Writer::advance` may zero-fill that track up to the other track's `last_end` − 200 ms while its real blocks still wait in the channel, to be placed late and head-dropped. A red test on a starved lane comes first; if the hypothesis does not reproduce, the task closes with that evidence. Fix option: bounded batches or round-robin per track in `Writer::drain` (crates/voicen-core/src/call/session.rs: Writer::drain, Writer::advance).

## Investigation

Problem investigator, 2026-11-27, worktree `tw/T-225` at 5ab6b13f. Serena: `get_symbols_overview` of `session.rs`; bodies read with sed by line range (the overview gave the names). Text search covered `capture.rs`, `tests/call_support/mod.rs`, `tests/call_session.rs`, `src-tauri/src/call.rs` (`CHANNEL_CAPACITY` 512), `docs/failures.md`, `docs/decisions/call-session.md`, T-203, T-239. Context7 was not used: rubato's error conditions (r1-4) were judged from the in-tree call sites, not from its docs (see below).

**Frame.** Filed hypothesis (T-203 impl#1): under writer overload the track drained second starves, its `Seen.last_event` ages past `STALL`, and when drain returns `Writer::advance` zero-fills it over blocks still queued. Expected: no real block is ever replaced by zeros; drops caused by full channels are counted (`Dropped`, I7) and nothing else is lost.

**Hypotheses.**
1. *The second-drained track (System) is zero-filled on drain return* (as filed). **Refuted** by code and by test. `Writer::run` calls `round()` (→ `drain()`) and only then `advance()`. `drain()` leaves the System loop only on an empty `try_recv`, and every handled event stamps `last_event = mono.now()` in `Writer::handle`. So at `advance()` the System track either had an event a moment ago or truly had nothing queued. While the Mic loop runs, `advance()` cannot run at all (T-203 already noted this), so starvation of the System lane gives full-channel drops (counted, I7), never a zero fill over real blocks. Repro mirror: park inside a Mic handle, feed System during the park, mono +600 ms → GREEN, no zero span on either track.
2. *The first-drained track (Mic) is zero-filled* — the mirror. **Confirmed.** The Mic loop ends on an empty read, then the System loop runs. Everything the writer spends from there to `advance()` ages the Mic's `last_event`, while the Mic producer keeps queueing in real time. At 500 ms of that, `advance()` takes the Mic as stalled and calls `advance_track(Mic, system.last_end)`. `Timeline::advance_to` fills zeros up to that stamp minus 200 ms. The next round's Mic blocks land behind the written position: `Timeline::place` drops their heads and re-anchors.
3. *A second path to the same zero fill.* **Confirmed by code, not run.** `round()` handles device outcomes after `drain()`, and `handle()` calls `settle()`. Both can call `device_change` → `write_meta`, a disk write, before `advance()`. If that write stalls for 500 ms or more, both tracks age with blocks queued. `advance()` then sees both stalled and moves both to `TrackSource::now` minus 200 ms, over their queued blocks. Reordering the drain (round-robin) does not close this path. The check has to sit at `advance()`.
4. *Sustained overload where the writer is slower than real time on one track.* Not the defect. The Mic loop never ends, and `advance()`, commands and `flush_warnings` wait. System overflows into counted drops. A fair drain would only spread the drops over both tracks. T-239 measured the same thing: fairness does not change when the backlog ends. Liveness of commands under that overload is a separate concern (see the question below).
5. *This class was fixed before.* F-037 (T-266) is the same zero fill (a lane held past `STALL`, filled to the other track's `last_end` − 200 ms, then head-dropped and 40 ms long). It was set off by a shell test feed and fixed in the feed (`WavSource::pump_for`), with the note "No product defect: real capture delivers both tracks in real time". Capture does deliver in real time, but the writer's stall clock measures when the writer reads, not when capture delivers. So this repro is the first product instance of F-037's mechanism, not a recurrence of a product fix. F-031 and F-033 are test-side relatives (drain order and budgets). No earlier product patch of this class exists, so no rca task is needed.

**Root cause.** The stall rule I9 means "a live track that delivered nothing for 500 ms", but the code measures "the writer took nothing of it for 500 ms". `Writer::advance` acts on that measure right after a drain that read the first track's channel before spending unbounded time elsewhere. This explains everything seen: only the first-drained track is hit, the hole starts where its loop ended and ends at the other track's `last_end` − 200 ms, the queued blocks are head-dropped with the F-037 40 ms drift, and nothing is reported. Nothing found contradicts it. Not measured: how often a 500 ms writer stall happens on real Windows hosts (the calls root can be a user-chosen folder: a slow USB or redirected drive, AV scanning). This is P3 by impact on a real call, not a test artefact.

**Invariant.** `Writer::advance` zero-fills a track (live or lost) only after a read of that track's channel found it empty, and that read came after the writer's last handle of any event. A track with a queued event is never stalled.

**Seam.** `session.rs` `Writer::advance`. Factor the inner loop of `Writer::drain` into one per-track helper (`drain_track(track) -> bool`). `drain()` calls it for both tracks. `advance()` calls it for each track just before deciding that track: if it handled anything, the track is not stalled this round (and a lost track is not filled past blocks it just received). Other callers of `advance_track`: `end_recording`, reached from `Command::Detach` after `command()`'s `while self.drain() {}`, and from `run()` after the stopping round found both channels empty. Both already meet the invariant. Sibling read paths: `Writer::command` (full drain), `Writer::round`; no other `try_recv` on the track receivers in the writer.

**Approach options.**
- **A (recommended): drain-before-advance in `Writer::advance`.** It removes the cause on every path (drain order, slow handle, slow `write_meta` in `outcome` or `settle`), because the decision is made right after an empty read of that track.
  - Red first: `call_session` test "a slow handle of one track does not zero-fill the other track's queued blocks". It is the repro above on a committed park-once hook in `tests/call_support` (`FakeSubtitles`); it asserts no 100 ms window under 0.05 RMS in 400..1300 ms of `mic.opus` and mic length equal to system length within one block (20 ms). It is red today, as shown.
  - Keep the mirror (park in Mic) as a guard. Optionally add a both-tracks case that parks inside `write_meta` (a slow-meta opener) for hypothesis 3.
  - The I9 tests (`a_silent_loopback_still_advances_the_system_track` and others) must stay green: a track that truly delivers nothing still reads empty and is still advanced.
  - Risk: low. `advance()` may now handle events, so `apply`, `maybe_tick` and `settle` run from it, as they do in `round()`. Rollback: revert the commit.
- **B: round-robin `Writer::drain` (one event per track per pass, until a pass handles nothing).** It closes the drain-order path and spreads overload drops over both tracks. It does not close hypothesis 3 (`write_meta` between `drain` and `advance`). Take it only on top of A if fairness of drops is wanted.
- **C: bounded batches per track plus A.** Also lets commands and `flush_warnings` run under overload where the writer is slower than real time. That is a different property (liveness), not this defect.

**Folded Low lines, checked against the current code.**
- **T-124 r1-3 (`capture.rs` `Lane::flush_dropped`, now line 209; the cited :176 is stale): still present.** `take_dropped` swaps the packed counter out, and `unpack_dropped` rounds its µs to whole ms (`(us + 500) / 1000`). On `TrySendError::Full`, `flush_dropped` adds back `ms * 1000`, not the original µs. So each failed retry loses or gains up to 0.5 ms (round to nearest: short or long, not only short). It is reachable only when a dropped block's duration is not a whole ms. 20 ms at 16 kHz and 10 ms periods at 48 kHz or 44.1 kHz are exact; odd WASAPI buffer sizes are not.
  - Fix: keep the raw packed value from the swap and `fetch_add` it back on `Full`.
  - Red test (capture.rs unit): capacity 1, a full queue, blocks of e.g. 100 frames at 44.1 kHz (2268 µs each), several `block` calls while still full. Then drain: the `Dropped.ms` equals `round(n * 2.268)`. Today it comes out short.
- **T-124 r1-4 (`Timeline::advance_to`, now line 698; `Timeline::retire`, now 819; the cited :688 / :787 are stale): still present.**
  - `advance_to`: a `drain` error sets `conv = None` and fills zeros directly.
  - `retire`: a `conv.run` error breaks the flush loop, and `fill_direct` pads to the end.
  - In both, the length is kept, but the error reaches neither the caller nor the log (`place` does propagate its error).
  - Reachability, judged from the in-tree code only: `Converter` feeds exactly `chunk` frames (`FixedAsync::Input`) into an output buffer of `output_frames_max()`. `set_rel` is clamped to 1 ± `MAX_ADJ` (500 ppm), inside `MAX_RELATIVE` 1.001. So no error is reachable today. Rubato's error list was not checked in its docs. Owner question below.
