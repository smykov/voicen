## Context

Testing tech debt (decision #150). The owner's manual Windows checks of six tasks run once, on the release-candidate build, before the first `v*` release tag. Those tasks close on their CI evidence; their owner parts of Acceptance point here. The T-012 step waits for T-007's toast (decision #152).

Report each step as pass or fail with the matching `%LOCALAPPDATA%\Voicen\logs\voicen.log` lines. Never include transcript text, audio or keys. The log's `voicen <version> (<commit>) started` line identifies the build.

## Acceptance

- [ ] T-034 (autostart): turn on "Start with Windows" in Settings › General and save. HKCU `...\CurrentVersion\Run\Voicen` = `"<exe>" --autostart`. After a sign-out and sign-in, or a reboot: the tray icon is present, no window opens, and voicen.log has a new `started` line
- [ ] T-010 (SC-006): the hotkey records and pastes 3 of 3 presses after each of these:
  - sleep and wake;
  - Win+L and unlock;
  - an Explorer restart (the tray icon comes back);
  - an autostart at logon followed by lock and unlock.
  Optional: going to sleep while a recording is held gives one result after wake
- [ ] T-006: in Notepad run as administrator, a 2–5 s Ctrl+Alt+Space hold pastes nothing, the text is in the clipboard, and the log has `dictation rec=… outcome=delivered result=copy_manual`. With microphone access for desktop apps turned off, a press records nothing and the log has `outcome=capture_failed mic=access_denied` (or `other`). Turn access back on afterwards
- [ ] T-024:
  - End voicen.exe in Task Manager and start it again. `%LOCALAPPDATA%\Voicen\logs` gets one new `crash-*.txt` with `kind: abnormal_end`, and voicen.log has `previous session outcome=ended_abnormally crash_file=<name>`.
  - Shut Windows down with the app running. After logon there is no new crash file
- [ ] T-025, in Windows Sandbox with two earlier builds (one of them a pre-T-025 build, ≤ 0.1.66, whose upgrade runs the stock uninstaller) and the candidate:
  - The per-user install shows no UAC prompt.
  - A double-click upgrade with the default choice asks nothing and keeps settings.json, the `Voicen/` credential, the Run value and the shortcut.
  - An interactive uninstall asks one question, in EN or RU by display language, with Yes as the default. No keeps the data folder and the credential and removes the Run value and the shortcut. Yes removes `%LOCALAPPDATA%\Voicen` and every `Voicen/` credential, and keeps other credentials.
  - Optional: with voicen.exe deleted, an uninstall answered Yes shows "Saved keys could not be removed…"
- [ ] T-012 (after T-007, decision #152), with a USB microphone selected:
  - Unplugged: a short dictation uses the default device and shows one notice "Using <device>"; a second press shows none.
  - Plugged back in: the USB microphone is used and no notice appears.
  - Unplugged at about second 5 of a toggle recording: the recording stops and the text is pasted.
  - No input device at all: nothing is recorded and the notice says "microphone unavailable: no input device".
  - Settings shows "<name> (not connected)" and keeps it selected
- [ ] Failure branch: a step that fails is recorded with its log lines as a bug task, not as a pass
- [ ] Test that fails without the change: `n/a (manual pre-release pass; evidence = the owner's check record)`
