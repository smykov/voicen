## Acceptance

- [ ] Silent install + uninstall with default removes the data folder and Credential Manager entries
- [ ] `/KEEPDATA` keeps them
- [ ] Installed size ≤ 100 MB
- [ ] Failure branch: upgrade install over an existing one → no question, no data removed — verified by the Windows CI job's same-version `/P` reinstall (it runs the old uninstaller; silent installs never do) and by the owner's interactive two-build upgrade in Windows Sandbox (decision #76)
- [ ] The NSIS template is a minimal-diff fork of the pinned tauri-cli version (`PageLeaveReinstall` always passes `/UPDATE /P`, stock data checkbox removed); `@tauri-apps/cli` is pinned exactly and the gate fails when the fork's recorded upstream version differs from the lockfile (decision #76)
- [ ] Test that fails without the change: `the windows job's install/uninstall steps`

## Investigation

**Frame.** Expected (FR-28 v4, spec 006 FR-018..FR-025 and FR-034, US4 scenarios 1-8, contracts/installer-ci.md): a per-user install of ≤ 100 MB with notices and a Start-menu shortcut. Uninstall asks once, default Yes (EN/RU); Yes, or `/S`, removes `%LOCALAPPDATA%\Voicen` and the `Voicen/*` credentials; No, or `/S /KEEPDATA`, keeps both; autostart is always removed on uninstall. An upgrade asks nothing and removes nothing. Observed today: `tauri.conf.json` has only `installMode: currentUser` + `compression: zlib`. There is no hook, no `resources` and no `languages`, and `ci.yml:69` installs but never uninstalls. The app creates windows without `data_directory`.

**How the template was read.** The NSIS template is not in the cargo cache: tauri-bundler is compiled into the CLI. It was extracted from the pinned CLI binary `node_modules/.pnpm/@tauri-apps+cli-linux-x64-gnu@2.12.1/node_modules/@tauri-apps/cli-linux-x64-gnu/cli.linux-x64-gnu.node`, at the byte offset of the first `Unicode true` (2699412). Line numbers below refer to that extracted text. Upstream it is `crates/tauri-bundler/src/bundle/windows/nsis/installer.nsi` at tauri-cli v2.12.1. The config schema is `node_modules/@tauri-apps/cli/config.schema.json`; `installerHooks` at :3236-3237 names exactly the four hooks. context7 and Serena were not used; facts come from grep/read of these pinned files.

**Facts about tauri-cli 2.12.1 NSIS (pinned):**
- Per-user: `currentUser` → `RequestExecutionLevel user` (110-112), `INSTDIR = $LOCALAPPDATA\${PRODUCTNAME}` = `%LOCALAPPDATA%\Voicen` (514-515), `SetShellVarContext current` (SetContext 1116-1120). Program files and data share one folder (research R9, decisions #10).
- Hooks: `!include "{{installer_hooks}}"` comes at line 36, before every page and before `MUI_LANGUAGE` (471). PREINSTALL (642-644) runs before `CheckIfAppIsRunning`. PREUNINSTALL (778-781) runs before the app is closed and before files are deleted. POSTUNINSTALL (887-889) runs after the stock removal. `LangString … ${LANG_RUSSIAN}` in the hooks file would be undefined at line 36. Use the numeric LANGID 1049 (to confirm when the installer compiles).
- Switches: `/P` passive, `/NS`, `/UPDATE` parsed with `${GetOptions} $CMDLINE` in `.onInit` (478-492) and in `un.onInit` (766-774). That shows `${GetOptions}` works in the uninstaller, so a hook can read `/KEEPDATA` the same way. `/S` is NSIS's own silent flag; `MessageBox … /SD IDYES` gives silent Yes.
- Stock data removal: a checkbox drawn on the uninstaller confirm page (`un.ConfirmShow` 428-458, state read in `un.ConfirmLeave` 460-462). The page is skipped when passive (463-464) and, in NSIS silent mode, all pages are skipped, so its state stays 0 under `/S`. It deletes only when checked and not updating (871-885), and only `$APPDATA\${BUNDLEID}` and `$LOCALAPPDATA\${BUNDLEID}` (`dev.voicen.app`) plus `HKCU\Software\<manufacturer>\Voicen`. That is never `%LOCALAPPDATA%\Voicen`, and never Credential Manager. Without our hook, `/S` therefore removes no user data.
- Autostart: `DeleteRegValue HKCU …\Run "${PRODUCTNAME}"` unless `$UpdateMode = 1` (865-867). `PRODUCTNAME` = `Voicen` = `src-tauri` `autostart::RUN_VALUE_NAME` (autostart.rs:28), so the stock uninstaller already removes it on a real uninstall.
- **Upgrade detection (the key finding).** `PageReinstall` (189-302) runs only when a previous install's uninstall key exists. On an upgrade the default radio is "uninstall before installing" (243-244, 291-295). `PageLeaveReinstall` then runs the old uninstaller via `ExecWait '"…uninstall.exe" _?=<dir>'`, appending `/UPDATE` only if this installer itself got `/UPDATE` (355-361). Only the updater plugin passes that, and Voicen has none (`src-tauri/Cargo.toml`). Research R10's premise, "Tauri passes /UPDATE to the old uninstaller during an upgrade", is therefore false for a manual upgrade. A hook keyed on `$UpdateMode` would show the question during an interactive upgrade, and the default Yes would purge settings, models and keys (FR-024 violated). Passive (`/P`): `$R2` holds a string, not a control, so `NSD_GetState` gives 0. A same-version reinstall therefore goes to `reinst_uninstall` with `/P` (268-269, 324-329): the old uninstaller runs passive and the hook's MessageBox shows, because `/SD` applies only to silent. A passive upgrade (R0=1) skips uninstalling. Silent installs skip pages, so `PageReinstall` never runs and files are overwritten. That makes the "two versions in a row" CI check unable to go red. **confirm on Windows**: the silent page skip and the `_?=` in-place run.
- Even with the data invariant held, the stock confirm page with the "Delete the application data" checkbox is shown during an interactive upgrade, because the old uninstaller is GUI. That is a visible data question, against US4 scenario 7. Only a template change, passing `/P` (and `/UPDATE`) from `PageLeaveReinstall`, removes it.
- WebView2 data: `tauri-2.12.1/src/manager/webview.rs:559-564` sets `data_directory = app_local_data_dir()` (`%LOCALAPPDATA%\dev.voicen.app`) when a window sets none. `settings_window::open` (settings_window.rs:83) and the overlay `build` (overlay.rs:347) set none, which breaks FR-034 today.
- Shortcut identity: `SetLnkAppUserModelId` writes `PKEY_AppUserModel_ID = ${BUNDLEID}` on the Start-menu/desktop links (1191-1215, called at CreateOrUpdateStartMenuShortcut). Toast AUMID = `dev.voicen.app` is stock, so nothing to add.
- Resources: `File /a "/oname={{this.[1]}}"` (654-656) and the matching `Delete` on uninstall honour the map form `{"../THIRD-PARTY-NOTICES.txt": "THIRD-PARTY-NOTICES.txt"}`.
- Credentials: targets are `Voicen/transcription-api|local-server|post-processing` (`voicen_core::secrets::KeySlot::target_name`, secrets.rs:50-56). `WinCredentialStore` in `src-tauri/src/credentials.rs` already takes a test prefix. No `--purge-credentials` and no prefix constant exist (`main.rs` is `voicen_lib::run()` only).

**Hypotheses.**
1. *The stock uninstaller already meets FR-28 if configured.* Refuted: 871-885 (wrong folders, checkbox default off, skipped in silent mode, no credentials).
2. *Hooks keyed on `$UpdateMode` handle upgrades (R10).* Refuted: 355-361 (`/UPDATE` is only propagated), plus no updater plugin.
3. *A second path deletes or keeps data.* Confirmed. The stock checkbox (871-885) is a second deletion path outside `%LOCALAPPDATA%\Voicen` (FR-023 "MUST NOT delete anything outside"). WebView2 data (webview.rs:559-564) is a second data location the folder removal misses.
4. *This class was fixed before.* No: `docs/failures.md` has F-001/F-002 only (CI link), no task has `class: installer`, and `git log -- src-tauri/tauri.conf.json` shows no installer change since the skeleton.

**Options.**
- **(A) Hooks only + installer marker.** The hooks file `!define`s `MUI_CUSTOMFUNCTION_GUIINIT` (unused by the 2.12.1 template; grep finds no GUIINIT) to a function that sets an env var (System `kernel32::SetEnvironmentVariable`). The uninstaller started by `ExecWait` inherits it, and PREUNINSTALL reads it (`ReadEnvStr`) → treated as an update: no question, keep data and keys. POSTUNINSTALL must also re-create the Run value, because the stock code deletes it when `$UpdateMode <> 1`. It removes the purge-on-upgrade cause with no fork. The stock confirm page and checkbox remain (visible on an interactive upgrade; scenario 7 not met literally; a non-Voicen deletion path, FR-023). Risk: relies on MUI2 GUIINIT and env inheritance, unverified on Linux. Rollback: drop the hook file.
- **(B) Forked template, minimal diff + hooks (recommended; decisions #10 reads "custom NSIS template").** `bundle.windows.nsis.template = "windows/installer.nsi"`, copied from tauri-cli 2.12.1 with two edits. `PageLeaveReinstall` always appends `/UPDATE /P` to the old uninstaller, so no page shows, the hook skips on `$UpdateMode`, and the stock code keeps the Run value and shortcuts. The stock checkbox is removed. Voicen logic stays in `installer-hooks.nsh`, so research R10 holds once `$UpdateMode` is reliable. Cost: the fork must follow tauri-cli bumps. Mitigation: pin `@tauri-apps/cli` exactly (now `^2`), record the upstream version in the fork's header, and add a gate check that it equals the lockfile version. Rollback: remove `template`.
- **(C) Change the install dir to `%LOCALAPPDATA%\Programs\Voicen`.** Does not address upgrade detection; already rejected (decisions #10, R9).

**Red tests first (windows job, contract installer-ci.md).** (1) After the silent install: installed size ≤ 100 MB printed; `THIRD-PARTY-NOTICES.txt` in the install dir; `Voicen.lnk` present. (2) `cmdkey /generic:Voicen/ci-test …` + a log file present; same-version `setup.exe /P` → completes within a timeout, log + credential still there (red under A/B without the marker: the MessageBox blocks). (3) `uninstall.exe /S /KEEPDATA` → folder + credential present; reinstall. (4) `uninstall.exe /S` → `%LOCALAPPDATA%\Voicen` absent, `cmdkey /list:Voicen/*` empty, Run value absent (red on today's stock uninstaller). The uninstaller re-launches itself from %TEMP% unless `_?=` is passed, so the step must wait for that child (poll with a timeout) before asserting. **confirm on Windows** that `Start-Process -Wait` does not cover it. Interactive Yes/No, EN/RU text and an interactive upgrade between two builds stay with the owner in Windows Sandbox (verify_exception).

**Fully specified?** Yes for the behaviour: question text EN/RU, default, `/S`, `/KEEPDATA`, scope (folder + prefix credentials), failure messages, autostart. Not settled: the mechanism fork (#10 literal "custom template" vs plan "Owner decisions needed" #4 / tasks T029 "installerHooks") and what CI proves for an upgrade. These are owner questions Q1-Q2 below. Contract drift to fix in the same commit: `contracts/installer-ci.md` says the hook deletes the Run value "unconditionally (FR-023)", but its own table and FR-28 v4 say an upgrade keeps it. R10's `/UPDATE` premise also needs correcting.

**Size verdict: too large — five seams, two blocked on unfinished tasks.** Proposed cut:
1. **T-025 (keep): installer and uninstaller.** `tauri.conf.json` bundle (resources = notices map, languages EN/RU, `displayLanguageSelector: false`, hooks/template), `installer-hooks.nsh`, the fork if B, and CI steps (1)-(4). Depends on the purge task below.
2. **New (core + shell): credential prefix and `--purge-credentials`.** Add `CREDENTIAL_TARGET_PREFIX` next to `KeySlot::target_name`, with a core test that every slot's target starts with it (P-010). `main.rs` handles `--purge-credentials` before `run()` via `CredEnumerateW("Voicen/*")` + `CredDeleteW` (exit 0/2, no log), with a Windows test in `src-tauri/tests/` (spec T028).
3. **New (shell): WebView2 data under `%LOCALAPPDATA%\Voicen\webview`.** One helper used by `settings_window` and `overlay` (`paths.rs` gains `webview_dir()`), plus a CI check that `%LOCALAPPDATA%\dev.voicen.app` is absent after a window is opened (spec T027). It touches `overlay.rs`, so it waits for T-057 (CODE_COMPLETE) to land.
4. **New (licenses): the three T-027 follow-ups.** Reword `docs/decisions/licenses.md:31` / `vite.config.js:18-19` as an assumption naming the blind spots; add a test that every `Cargo.lock` package without `source` is a workspace member; add a guard on `licenses-stale` like `licenses-fixture`. Different seam (`scripts/licenses`, `Makefile`); shares only the notices topic.
5. **Leave to their owners:** the PREINSTALL/PREUNINSTALL `logs\installer-ended` note and the crash/abnormal-end CI checks go to T-024 (session marker TODO). The Silero VAD resource goes to T-043 (TODO). The symbols zip upload goes to T-024/T-026.
