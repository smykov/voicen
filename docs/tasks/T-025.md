## Acceptance

- [ ] Silent install + uninstall with default removes the data folder and Credential Manager entries
- [ ] `/KEEPDATA` keeps them
- [ ] Installed size ≤ 100 MB
- [ ] A same-version `/P` reinstall keeps the Run value written by the Start-with-Windows toggle (T-034); a user-started uninstall removes it
- [ ] Failure branch: upgrade install over an existing one → no question, no data removed — verified by the Windows CI job's same-version `/P` reinstall (it runs the old uninstaller; silent installs never do) and by the owner's interactive two-build upgrade in Windows Sandbox (decision #76)
- [ ] The NSIS template is a minimal-diff fork of the pinned tauri-cli version (`PageLeaveReinstall` always passes `/UPDATE /P`, stock data checkbox removed); `@tauri-apps/cli` is pinned exactly and the gate fails when the fork's recorded upstream version differs from the lockfile (decision #76)
- [ ] Test that fails without the change: `the windows job's install/uninstall steps`

**New facts from the re-read (not in the 2026-10-05 analysis).**
- The dropped checkbox block (:871-885) also removed the installer's bookkeeping key `HKCU\${MANUPRODUCTKEY}` (install location, "Installer Language"). With the block gone, POSTUNINSTALL removes that key on Yes, using the template's own define inside the hook macro, so the fork diff stays a pure deletion. It is installer state, not a folder, so FR-023 is not touched. `MUI_UNGETLANGUAGE` reads "Installer Language" in `un.onInit` (:764), before the hook runs, so the uninstaller's own language is unaffected.
- A same-version reinstall chosen interactively as "Uninstall" (`uninstallApp`, :240) also goes through `reinst_uninstall` and then on to `reinst_done`, so the install continues. With the fork it keeps data, which is right: every installer-started uninstall is followed by an install.
- Downgrades: `allowDowngrades` defaults to true. A forked installer of a lower version also passes `/UPDATE /P`, so there is no question. Installing a **pre-T-025 build over a T-025 build** (an older Telegram build) runs our uninstaller without `/UPDATE`, so the question shows with default Yes. That is the old installer's code and cannot be fixed. Residual risk, recorded for `docs/decisions/installer.md`; the owner can answer No.
- `uninstall.exe` without `_?=` copies itself to `%TEMP%` and returns at once. CI must poll for the effect, with a timeout. The reinstall's `ExecWait … _?=<dir>` runs in place, so `setup.exe /P` with `-Wait` covers it. In-place runs cannot delete `uninstall.exe` itself, which is one more reason `RMDir /r` runs only on a user-started (never `_?=`) uninstall. Still **confirm on Windows** (first wip run).
- `paths::data_dir()` is `%LOCALAPPDATA%\Voicen` from the env var, independent of INSTDIR (the interactive directory page allows another install dir). The hook therefore removes the literal `$LOCALAPPDATA\Voicen`, not `$INSTDIR`, and refuses when `$LOCALAPPDATA` is empty. NSIS takes `$LOCALAPPDATA` from the shell folder and the app from the env var; they are equal on a normal profile (assumption, stated in the decisions file).
