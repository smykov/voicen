## Context

Split from T-016 by decision #49 (T-016 analysis, option A). The UI half of the local-model download: `src/lib/local-models/` (reads only `local_models_list` and the `local-model://` events through one IPC module, like `settingsApi.ts`), the `builtin_local.model_id` picker replacing the T-004 placeholder `settings.builtin_local.pending` in `src/lib/settings/tabs/Engine.svelte`, the new commands and events in `e2e/support/tauriMock.ts`, and `e2e/local-models.spec.ts`. Depends on T-039 (it changes the Engine tab's page and the i18n catalogs). Message texts for `DownloadFailure` come from T-016's catalog ids. Note from T-016 review round 1: `NotEnoughDiskSpace{needed}` carries raw bytes and the core texts say "{needed} bytes"; spec 002 FR-007 wants a size the user can read — format it (MB/GB) and adjust the en/ru texts here. Notes from T-039 review round 2 (Lows, fold in here): (1) settings-ui.md › D overclaims "no draft is ever editable without the close guard" — a `settings://changed` arriving while the focus/close `listen` is pending creates a draft before the guard exists; register `onCloseRequested` first or reword D; (2) `e2e/support/tauriMock.ts` header (lines 28-29) says `holdSettingsGet` holds "the first" `settings_get`, the code holds every one until release; (3) settings-ui.md › R and › L say "the case" but each has two cases.

## Acceptance

- [ ] Picking `base` shows progress and the model becomes selectable; while one download runs, the other Download buttons are disabled
- [ ] Failure branch: an interrupted download or checksum mismatch shows the reason and Retry, and Retry starts the download again; Cancel returns the model to "not downloaded" without a retry offer; a model that is not downloaded cannot be selected — Playwright over the mocked IPC

## Investigation

**Frame.** Expected (spec 002 US1 AS1-AS7, FR-001/002/006/007, edge cases "Two downloads requested" and "No model selected"; research.md:76): with engine `builtin_local` the Engine tab lists the five models with sizes, a `small` badge, progress, Cancel, Retry with the reason, and a select offering only downloaded models. Observed: a placeholder text (see `analysis.root_cause`). This is a need, so there is nothing to reproduce. Tools: Serena was not connected in this session (no `mcp__serena__*` tools), so code was read with grep and file reads over `src/`, `e2e/`, `crates/voicen-core/src/{local_models,settings,i18n.rs}`, `src-tauri/src/local_models.rs`, `i18n/`, `docs/`. context7 was not used: Svelte's select binding was read in `node_modules/svelte` 5.57.1 (the installed version, `^5.56.3`), and Intl output was checked with Node 20.

**Hypotheses checked.**
1. *A second path already handles models in the UI.* Refuted. `@tauri-apps/api` is imported only by `settingsApi.ts` and `buildInfo.ts`. There is no `local_model` string in `src/` and no `builtin_local` use beyond the placeholder.
2. *The class was fixed before.* No. Class `model-download` has T-016 and T-044 (planned splits of decision #49). `docs/failures.md` has no model-download or UI entry.
3. *A select whose options arrive late rewrites the draft (the R hazard).* Refuted for Svelte 5.57.1 (`select.js:109-110, 209-215`): the value is written back only on mount with `undefined`. `model_id` is `string | null`. The R round trip for `builtin_local` pins it anyway; it does not exist today.
4. *Applying events in arrival order over one list is enough.* Not enough. `local_models_list` and `local_model_download` are async commands, so responses can overtake each other and events. After `download` resolves there is no event until the first progress, up to 30 s on a stall. A fast failure can end before the command returns. Hence I2: re-list after a download resolves, keep only the newest list response, and replay the events buffered since it was requested. No optimistic `downloading` in the UI: a local `downloading` set after a fast `failed` event would stick.
5. *The D overclaim is only wording.* No, the gap is real (+page.svelte:219-221). Registering `onCloseRequested` first closes it with no other change: the handler prevents nothing while the draft is null. Red test: hold the close-requested listen, emit `settings://changed`; today a control renders with no guard.

**6. Who formats `{needed}`.** The wire form keeps param values as strings (contracts/ipc.md › Wire form; `MessageArgs = Record<string,string>`, src/lib/i18n/index.ts:28).
- **(a) Core sends bytes, the UI formats (recommended).** The UI must format sizes anyway: `sizeBytes` per row (US1 AS1) and `received`/`total` (AS2). `formatSize(bytes, lang)` is then the only size rule (P-010), and `needed` is one more input. It follows the existing precedent: core sends raw values and the UI localizes their display with Intl (speech-language names, Engine.svelte:20-25; U1). It re-renders on a language switch, as W requires of `t`. Cost: the UI needs one typed fact from the contract, "`needed` is a byte count". It is stated in ipc.md and applied in one function, `reasonArgs`; it is not a table of codes, which U2 forbids. Rust `text()` would print the bare number, but no Rust path renders `download.*` to a user (only the core test does). i18n.md records this as UI-only, the mirror of the nested-id "Rust only" rule. New texts, for example: en "Not enough free disk space: {needed} needed.", ru "Недостаточно места на диске: нужно {needed}." `expected()` in `message_ids_per_download_failure` changes to them with `66256`; that test still bites a wrong id or param name.
- **(b) Core sends a formatted size.** It cannot be language-neutral (decimal separator, unit). Integer MB plus a unit in the catalog would work in both renderers, but it is a second size rule beside the UI's list and progress sizes, and the two could disagree. Decision #52's pattern (core decides which value warns) is about a rule, not presentation, so it does not argue for (b).

**7. Recurrence.** None. Binding rules: U1 (no UI rule; the mock never validates, #38), U2 (refusals on the field; `error.ipc_unavailable` for a rejection), R (no write-back), L/W (the new control joins `renderedFields`), i18n.md (only `t(MessageId)`; no new `as MessageId` cast is needed, because `nameKey` and `messageKey` are Rust `MessageId`s, service.rs:43, 56).

**Design points for the developer.**
- The section mounts only while engine is `builtin_local` on the Engine tab, so other tests never call the list. A remount re-lists.
- The fieldset is disabled during a save, which also disables Download/Cancel briefly. Acceptable; saves are short.
- `loaded` is not rendered (always false until T-017).
- No auto-select after a download (spec: "becomes selectable").
- A select placeholder for `null`: `<option value={null} disabled>`.
- The reason is not `role="alert"` (it is async); use a polite live region.
- Optional, cheap enforcement of I1: ESLint `no-restricted-imports` for `@tauri-apps/api/*` outside `*Api.ts` and `buildInfo.ts`.

**Size.** One task, one seam (the settings window UI and its mock), plus catalog texts and one core test text. Roughly 11 e2e, 2 settings-focus-close, about 6 mock self-tests, about 8 vitest tests and one type test, plus docs. The T-039 folds are small and touch files already in scope. No split. Suggested commit order: red tests → mock → `localModelsApi`/`models` → `BuiltinLocal.svelte` + Engine → D order → texts and docs.

**Questions.**
- **Q1 (owner, non-blocking; default proposed): size units.**
  - Default: the Windows Explorer convention. 1 MB = 1 048 576 bytes, labelled MB/МБ through Intl. Whole MB below 1 GB, one decimal for GB, kB below 1 MB. `base` shows "141 MB", and `needed` matches the free space Windows shows.
  - Alternative: decimal SI, as Hugging Face shows ("148 MB"). Plan.md's "75–550 MB" matches binary.
  - Only `formatSize` and the e2e literals depend on this choice.
- **Q2 (owner, non-blocking; default: continues):** closing the settings window during a download leaves it running in the shell; reopening shows its progress from the list. The spec says nothing either way.
- **Q3 (orchestrator):** a new `localModelsApi.ts` (one IPC module per contract), with settingsApi.ts:4-5 and settings-ui.md D reworded to match. Recommended.
- **Q4 (orchestrator):** D fixed in code (listener order plus a red test), not only reworded. Recommended.
- Not an owner question: the recommended badge. It is required by the approved spec (FR-001 MUST, US1 AS1) and carried on the wire (`recommended`). Its text is a new UI-only id; the agent writes the en/ru wording.

**Recommended:** option A. First red tests: `src/lib/local-models/models.test.ts` (sequencer and `formatSize`), then `e2e/local-models.spec.ts` › "download base shows progress, disables the other Download buttons, and makes base selectable", then the failure-branch cases (3)-(8).
