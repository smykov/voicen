## Investigation

Tools: Serena (`get_symbols_overview`, `find_symbol` with bodies) for src-tauri/src/call.rs, core `final_pass.rs` (`PassQueue`, `transcribe_transition`) and `storage.rs` (`CallStore`). grep for the strings `calls_transcribe`/`callsTranscribe` (code, UI, e2e, contracts), for `recover` in src-tauri/src, for the capability JSON, for build.rs and for the test outlines. `git` for T-145's remote branch. Context7 was not needed: no new library API (a tauri command of the same kind as the five existing ones).

**Frame.** Expected (FR-027, FR-028, contracts/ipc.md): `calls_transcribe {root, id}` queues the call and answers its summary as `queued`. A pass cut by an exit runs again at the next start. Observed on main ca20b1de: the command does not exist, and nothing in the shell calls `PassQueue::transcribe`. The start-up restart depends on `CallStore::recover` being called at start, which is T-145's part (D4) and not on main yet.

**Hypotheses.**
1. *The command is just missing.* Confirmed. There is no handler, no APP_COMMANDS entry, no grant and no UI call.
2. *A second path already queues on request.* Refuted. The only enqueue in src-tauri is `ShellCallShell::call_ready` (the stop path). Core's `transcribe` has no caller outside core tests.
3. *This class was fixed before.* No. docs/failures.md has no entry for `call-final-pass` and no PassQueue or final-pass entry. The earlier tasks of the class (T-136, T-137, T-138, T-139, T-146 DONE; T-221 CODE_COMPLETE) built the feature; none was a defect fix. **Recurrence: none.**
4. *The restart needs new code in T-147.* Refuted. `CallStore::recover` already maps `transcribing` to `ready-to-transcribe` plus the queue, and T-145 owns the one start-up caller. T-147 only proves the end-to-end restart with the mock server. T-145's red tests cover the `recording` and `ready-to-transcribe` leftovers but not `transcribing`, so T-147's relaunch case is not a duplicate.

**What blocks.** Acceptance 2 cannot go green until T-145's start-up recover is merged. T-145 is IN_PROGRESS (stage implement), and origin/task/T-145 holds only red tests (1f335924), which also edit `src-tauri/tests/call_shell_support/mod.rs` (`CallPorts.exit_confirm`, `FakeExit`). T-145 is not in this task's `depends_on`. The `calls_transcribe` half (acceptance 1) does not depend on T-145.

**UI.** Out of scope. src/ and e2e/ never invoke `calls_transcribe`. The buttons, the Queued row and the `recordingCall` error are T-148 (G34, depends on T-147).

**Size.** Small: one shell seam plus a single-line core helper, and settled behaviour (contract and Q2-Q4). It does not need the spec tool.

**Open question for the orchestrator (process, not product).** Add T-145 to `depends_on` (or set `blocked_on: T-145` before the relaunch test is written), or move the `transcribing` relaunch case into T-145. Recommended: add the dependency. The `calls_transcribe` tests and code can be written now.

**Recommended exit**: n/a (feature, not rca).
