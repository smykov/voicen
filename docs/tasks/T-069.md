## Context

Opened from the T-066 review, round 1, finding #3 (`docs/tasks/T-066.reviews/1.md`).

In CI run https://github.com/smykov/voicen/actions/runs/37569806425 (attempt 1, `wip/T-066` @ 1741e43, the first `wip/` run under P-016), `cargo test -p voicen` failed in `src-tauri/tests/purge_credentials.rs:105`, `adapter_lists_exactly_the_prefixed_entries_with_their_types`, with `premise: voicen-test-7824-0-931433800/Voicen/a planted`. `CredWriteW` returned Ok, and the `CredReadW` right after it did not find the entry. Attempt 2 at the same sha was green, and the test was green on main in 37465516406, 37502781812 and 37530828511. `raw_exists` throws away the Win32 error, so the failure does not say why.

Second occurrence: https://github.com/smykov/voicen/actions/runs/37588730139 attempt 1 (`wip/T-070` @ c3a8342), another test in the same file, `failed_delete_exits_2_keeps_that_entry_and_removes_the_rest`, same line 105, `premise: voicen-test-7276-1-888677500/Voicen/a planted`. That makes 2 red attempts in 4 `wip/` runs, so it is not rare.

Under P-016 every non-docs task needs a green full-CI run on `wip/<ID>`, so an intermittent red here turns unrelated tasks red at random.
