## Context

Logged by the orchestrator (P-016: a red attempt whose failure is outside the diff is logged as its own task before a re-run counts). `ci.yml` run https://github.com/smykov/voicen/actions/runs/45465360769 on `wip/T-197` @ d124277e (a diff of docs, specs and README.md only) failed in `Test the shell`: `call_dictation::a_dictation_during_a_call_pastes_and_leaves_the_call_tracks_unbroken` panicked at `src-tauri/tests/call_dictation.rs:412` — "the call's tracks after a dictation differ from the call recorded alone": left `Tracks { mic: 98874, system: 96960, drops: 0, device_changes: 0 }`, right `Tracks { mic: 96960, system: 96960, ... }`. The mic track had 1914 more samples than the call recorded alone. The same test passed on main runs 45452515249 (f7e85ab2, T-151's merge) and 45529997012 (54744418). The test came with T-151; the sample counts look tied to wall-clock pumping (`pump_for`, `thread::sleep(HOLD)`) rather than to a fixed number of frames.

## Acceptance

- [ ] The test's guarantee (a dictation during a call leaves the call's tracks unbroken: no drop, no gap, no device change, mic and system aligned) is checked without depending on how many samples the wall clock let through
- [ ] Failure branch: a dictation that does break the call track (a drop, a gap or a device change) still fails the test
- [ ] Test that fails without the change: the existing case, made deterministic (or a repeat run that reproduces the flake before the change)
