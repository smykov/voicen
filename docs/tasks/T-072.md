## Context

Owner, 2026-10-07: the URL settings were copied from another client, which takes the full endpoint (`http://10.10.10.110:8000/v1/audio/transcriptions`). Voicen appends `/audio/transcriptions` to a base URL (FR-06, FR-17; `crates/voicen-core/src/engine/openai.rs`), so the request went to `…/audio/transcriptions/audio/transcriptions`: `dictation rec=4 engine=local_server outcome=failed failure=server_error http_status=404`. Decision #96: accept both forms.

## Acceptance

- [ ] For the API and Local server engines, a URL ending in `/audio/transcriptions` (with or without a trailing `/`) is requested as is; any other URL gets `/audio/transcriptions` appended. One function in core decides this for both engines and for "Test connection".
- [ ] The URL fields show an example hint (e.g. `http://10.0.0.5:8000/v1`) in en/ru.
- [ ] Failure branch: a URL with a doubled path or any other wrong path still reports the server's 404 as today (`failure=server_error http_status=404` and the existing notice); verified by a core test against the mock server.
- [ ] Test that fails without the change: named in `## Tests`.

## Investigation

Tools: Serena and Context7 were not callable in this session. I used grep and file reads instead. No library API changes: the fix uses the `url` crate's `path_segments` / `path_segments_mut`, which `transcription_url` already calls.

**Frame.** The owner pasted `http://10.10.10.110:8000/v1/audio/transcriptions` as the local server URL. The request went to `…/v1/audio/transcriptions/audio/transcriptions`, and the job failed with `failure=server_error http_status=404`. Expected: per decision #96, a URL that already names the endpoint is used as is.

**Hypotheses.**
1. *The join always appends.* Confirmed. `engine::openai::transcription_url` runs `pop_if_empty().extend(["audio","transcriptions"])` with no check of the existing path. `openai_client.rs::trailing_slash_base_url_gives_same_path` and the unit tests `join_*` pin append-only.
2. *A second path builds the URL.* Refuted. Grep over `crates/` and `src-tauri/src` for `audio/transcriptions`, `transcription_url` and `OpenAiCompatibleEngine::{new,local_server}`: the only caller is `OpenAiCompatibleEngine::transcribe`, and the only constructors are in `engine::mod::engine_for` (api and local_server arms). Test connection (T-046, TODO) is designed to go through `engine_for` → `transcribe` (T-046 Context), so it picks up the fix with no change. Post-processing (T-020, TODO) uses another endpoint and is out of scope for #96. `local_models::download` imports only `host_port`, `send_error` and `body_error`.
3. *Validation or normalization rewrites the URL.* Refuted. `settings::url::check_base_url` / `normalize_base_url` only trim and strip one `/`. `is_insecure_remote` decides by scheme and host only, so a full endpoint URL gets the same `endpoint.insecure` warning as its base.
4. *This class was fixed before.* No. `docs/failures.md` has no URL or path entry (grep `url`, `path`, `endpoint`), and no other task has `class: settings-url`.

**Design points, settled.**
- **One decision function:** `transcription_url(base: &url::Url)`. Take the path segments. If the last one is empty, drop it (the same as today's `pop_if_empty`). If the last two segments then equal `audio`, `transcriptions`, return the URL with that path. Otherwise append them. The query is kept in both branches, so Azure-style `…/audio/transcriptions?api-version=…` works.
- **Trailing slash:** `check_base_url` already strips one `/`. The leftover empty segment is dropped, so `…/audio/transcriptions/` posts to `…/audio/transcriptions`. Sending the slash would invite a 307 redirect of a multipart POST. Read "requested as is" in the Acceptance as "nothing appended".
- **Case:** compare segments with `eq_ignore_ascii_case`, and send the path in the case the user typed. If `/Audio/Transcriptions` were not matched, we would send a doubled path that no server serves. If the reviewer wants the decision text literally, an exact match is the alternative; pin it in the unit table either way.
- **Near misses append** (unit table): `/v1/audio`, `/v1/transcriptions`, `/v1/audio/transcriptions2`, `/v1/audio%2Ftranscriptions` (one segment), `/audio/transcriptions/x`.
- **Saved value:** store it as typed (only `normalize_base_url`). Do not rewrite it to a base URL. `docs/decisions/settings.md` says the file, the snapshot and the UI carry the same value, and a query is stored as typed. A silent rewrite would surprise the user and add a second normalization rule. No new validation code, no new warning. `error.url.malformed` keeps its example.
- **Hint:** `settings::defaults` fills both URLs (`https://api.openai.com/v1`, `http://localhost:8000/v1`), so a placeholder would never show. Use a visible `<p class="hint" id={hintId(field)}>` under each URL input, the same pattern as `HotkeyField.svelte` › `settings.hotkey.hint`. Add the hint id to the input's `aria-describedby` through `fields.ts::describedBy` (an optional hint argument), so `describedBy` stays the one rule. One new catalog id, `settings.base_url.hint`:
  - en: "For example http://10.0.0.5:8000/v1. A full address ending in /audio/transcriptions also works."
  - ru: "Например, http://10.0.0.5:8000/v1. Подойдёт и полный адрес, оканчивающийся на /audio/transcriptions."

  Parity is covered by `i18n.test.ts` ("en and ru have the same ids…") and core `i18n::tests`. A literal `t("settings.base_url.hint")` type-checks against `MessageId`.

**Root cause.** `transcription_url` encodes "the stored URL is a base" as an unconditional append, so every full-endpoint URL doubles the path. This explains the 404 and that it hit only `local_server` (the owner's engine; `api` has the same flaw). No contradicting evidence.

**Options.**
- **A (recommended).** Decide inside `transcription_url` as above; keep the stored value as typed; add the hint. It removes the cause at the only URL builder, so it covers the api, local_server and Test connection paths. Risk: a server whose real base path ends in `/audio/transcriptions` would now get no append, which is implausible. Rollback: revert one function.
- **B.** Normalize on save: strip a trailing `/audio/transcriptions` in `service::normalize`. Rejected: it rewrites what the user typed, the stored value differs from what was pasted, and it touches `settings/service.rs`.
- **C.** A UI-only rule or rewrite. Rejected: a second URL rule outside the `url` crate (the P-010 / F-003 class, `docs/decisions/settings.md` Don't list).

**Red tests (before the fix).**
- Core, mock server:
  - `openai_client.rs::full_endpoint_url_is_requested_as_is`: a table of suffixes, each giving exactly one request at that path, with the query kept.
  - `local_server.rs::full_endpoint_local_server_url_is_requested_as_is`: the owner's form through `engine_for`.
- Unit: `engine::openai::tests::join_full_endpoint_kept` plus the near-miss table.
- Failure branch: `local_server.rs::wrong_path_reports_server_404`. Mount the mock with `path("/v1/audio/transcriptions")` only. Base `…/v1/audio/transcriptions/audio/transcriptions` and base `…/v2` must each give `ServerError{status:404}`, one request, audio kept. Use the existing `harness` / `JobReport` pattern. Do not touch the diag tests, which other tasks are editing now; the `http_status=404` log rendering is already pinned by diag tests.
- UI: new `e2e/settings-engine-url.spec.ts`. For api and local_server, the hint text is visible under the URL input and is part of its accessible description, in en and after switching to ru.
