## Context

Follow-up of T-145 review 4 #1 (Medium, correctness; decisions #355). After T-145 the `win::end_session` hook runs `lib.rs::end_of_process` on the first `WM_ENDSESSION(TRUE)`, so the call, `SessionEnd` and the pending audio are finalized. tao 0.37.1 then answers the message with its own `loop_destroyed()`; inside a nested message pump (wry's WebView2 creation, e.g. the call indicator window) that call is re-entrant and panics, which in release (`panic = "abort"`) aborts the process: the user gets a crash record at shutdown where a clean `exited` was expected. Documented as the **Open residual** in `docs/decisions/windows-shell.md` and in F-034. Area shell (`src-tauri`), Windows CI only.

## Acceptance

- [ ] A release build that gets `WM_ENDSESSION(TRUE)` while its loop thread is inside a nested pump ends with exit 0, an `exited` line and no crash record (Windows CI smoke)
- [ ] Failure branch: the same message outside a nested pump, and a hook that cannot be installed, still end through `RunEvent::Exit` exactly once (no double `SessionEnd`)
- [ ] Test that fails without the change: the nested-pump release smoke shows the crash record on current main
