## Context

T-192 review round 1 returned `REJECT_RECURRENCE`, class `guard-model` (P-020; F-003, F-015, F-022). `scripts/hooks/wip-push-guard.sh` splits a Bash command with its own model of shell (`shlex`, `commands`, `unwrap`, `live_text`, `substitution_end`, a list of prefix commands and keywords) and allows every shape the model does not read. Decision #219 asks for a PreToolUse hook that reads the command. It does not ask for a shell model, and it is not an exception to P-020.

Owner: `problem-investigator`. The analysis ends in one of three exits (`docs/process/lifecycle.md` §6): (a) code, (b) architecture review, (c) process amendment.

Reviewer's signals, not a choice of exit:

- **Code.** The hook is one seam. The settings deny `Bash(git -C * push*)` already refuses, under the task's own reading of `*`, the commands the model exists to let through (`git -C . stash push`, `git -C . commit -m "do not push"`). A raw-token rule may therefore cost little: compare what it would newly refuse.
- **Process.** The P-020 design step did not bite again. T-192 has `checker: true` and `decides_on: "#208, #219"`, which names no switch, literal or token, and the pre-commit trigger accepts any non-empty value. The trigger fired only because of `Makefile` and `scripts/ci/`; `scripts/hooks/` is not a guard path, so a later hook-only change does not fire it. `scripts/hooks/test-guard.sh` and `_hookio.py` (kit-owned) also use `shlex`: whether P-020 covers PreToolUse hooks at all is a question for this analysis and the owner.
- **Crossing seams.** The kit's launch allows `Bash` tool-wide, so denies and this hook are best effort whatever rule they use. `pre-push` remains the boundary for delivery refs.
