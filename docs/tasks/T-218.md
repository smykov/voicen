**What happens today on Retry with unreadable pending audio.**
- `Pipeline::retry` (`crates/voicen-core/src/pipeline.rs:283-292`): `get_pending` returns `Err`. The pipeline calls `drop_pending` (empties the slot, deletes the file), emits `Warning{PendingAudioUnreadable}` and returns `RetryOutcome::Unreadable`.
- The worker (`dictation.rs:1008-1013`) calls `retry_dropped(key)`, so the tray is left as after any dropped retry and tray Error is not set. It then calls `notice_with(NOTICE_RETRY_UNAVAILABLE)`, which shows the message on the overlay for 3 s and offers it once to the Notifier (toast).
- The user sees "The failed dictation could not be read back, so it cannot be retried" (`i18n/en.json:169`; ru at `i18n/ru.json:169`). The id is `notice.retry_unavailable` (`i18n.rs:264`), and the texts were decided in #280.

**Tests that prove it** (`crates/voicen-core/tests/dictation_session.rs`):
