## Context

Opened by T-082 review round 1 (`REJECT_RECURRENCE`, class `guard-model`). T-082 added `scripts/ci/role-tools.sh` (`make check-role-tools`), a tripwire over the YAML front matter of `.claude/agents/*.md`, which Claude Code interprets. Its R2 and R3 pass on the guard's own reading of that front matter: the first `---` pair, the first `tools:` line, and a comma split of its value. P-020 forbids this kind of pass. The review reproduced four shapes that pass the guard (exit 0, "ok: 1 role file(s)"). Under YAML semantics, each of them names a Serena tool the guard is meant to refuse:

- A: flow sequence `tools: [mcp__serena__write_memory, <manifest names>, Read]`. The first element splits to `[mcp__serena__write_memory`, which does not start with `mcp__`, so R3 lets it through.
- B: a second `tools:` key in the front matter with `mcp__serena__execute_shell_command`. The guard reads only the first key.
- C: a plain-scalar continuation line `  mcp__serena__replace_symbol_body` after `tools: ..., ToolSearch,`. YAML folds it into the value, and the guard never reads it.
- D: a quoted element `'mcp__serena__write_memory'`. It starts with a quote, so R3 lets it through.

The probe script is outside the tree. To rebuild it, take any role file's Tools block and put each front-matter variant above it.

The allowlist edits of T-082 are kept: they are the fix, and a code-reviewer subagent called `mcp__serena__get_symbols_overview` through them (`.teamwright/logs/tools.jsonl`, 2026-10-21). `role-tools.sh` stays in `make check` as a temporary workaround that points here.
