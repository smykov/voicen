**Does each new test bite, for the right reason** (checked by reading `codec.rs` and ogg 0.9.2 `writing.rs`; no mutation was run):
- ogg 0.9.2 writes each page in separate `write_all` calls: the header (`writing.rs:263`), the lacing (`:264`), then each packet (`:276`). The one-shot write fault therefore fails exactly one call, which stores nothing. Every later write, flush and sync succeeds.
- **C16**: `create_fails_when_only_a_header_page_write_fails`.
  - With `at = 0`, the 27-byte header of the OpusHead page fails.
  - With `at = head_end`, the first write that goes past page 1 fails, which is the header of the OpusTags page.
  - If `create` swallowed the error, it would return `Ok`. `assert_storage` would then panic with "swallowed".
  - The check "the fake fired" shows that the injected failure was actually reached.
- **C12**: `create_fails_when_only_a_header_page_flush_fails`.
  - Flush 0 or flush 1 fails once. These are the flushes of the head page and the tags page in `create`.
  - If the error were swallowed, `create` would succeed, because no other fault is set.
- **F6**: `finish_fails_when_only_the_eos_page_write_fails`.
  - The fault is set at `len − 1` of a reference encode. The fault is one-shot and the encode is deterministic: the same input, and a clock that never moves, so no periodic sync runs. The write that fails is therefore the last packet write of the EOS page, inside `finish` → `encode_frame(Some(..))`.
  - If the error were swallowed, `packets` is still incremented, so the loop ends. The flush and the sync then succeed and `finish` returns `Ok`, which the test rejects.
- **F4**: `finish_fails_when_only_the_final_flush_fails`.
  - In `encode_frame`, the EOS page (`EndStream`) is not flushed. So `flushes − 1` of the reference run is `finish`'s own flush.
  - If that error were swallowed, the sync would succeed and `finish` would return `Ok`.
- **H2, H3, H4**: `each_opus_head_field_check_makes_the_file_unreadable`.
  - Each case first asserts the original fixture byte, at offsets 8, 9 and 18 of the OpusHead body. It then changes that one field and recomputes the CRC with `fix_crc`.
  - `scan` does not decode, so the only thing that can make it `Unreadable` is the check in `opus_head_pre_skip` (`codec.rs:306-313`).
  - Version 0x10 and 0xFF kill `true &&` and the near variants. Channels 0 and 3 kill `true`, `0..=2` and `1..=3`. Mapping 1 and 255 kill `< 255` and `<= 1`.
- **H6**: `an_opus_head_sharing_page_1_with_opus_tags_makes_the_file_unreadable`.
  - The control rebuilds the file with the head alone on page 1 through `ogg_page`/`rebuilt` and gets the fixture back byte for byte. This shows the helpers produce valid, identical pages: CRC, flags, granule 0 on the header pages, and contiguous sequence numbers.

- **NW6**: `a_packet_libopus_rejects_ends_the_windows_with_a_codec_error`.
  - `[0x03, 0x00]` is a code-3 packet with a frame count of 0. RFC 6716 3.2.5 forbids this, and libopus's packet parser returns `OPUS_INVALID_PACKET` for it.
  - Before decoding, `pages(&bytes)` checks every CRC and the page count, and page 3's granule is restored.
  - In the reader, `DecodeEnd::Codec` can come only from `Decoder::new` or from `decode`'s `map_err`. `Decoder::new` succeeds on every other fixture, so the error is libopus rejecting the packet.
  - "No samples" shows that the rejected packet is the first one decoded.
