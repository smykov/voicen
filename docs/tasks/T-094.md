## Context

Found in T-086 review 1 (finding 2, decisions #125). `make licenses-npm` (`scripts/licenses/check.mjs`) judges the npm packages of the client bundle against the one accepted-license list, the top-level `accepted` array of `about.toml`, which cargo-about also reads (T-027). It reads that list through `scripts/licenses/accepted.mjs`, whose header says "Not a TOML parser": it understands only basic and literal strings, comments and a trailing comma before the first table header, and fails loudly on anything else.

Being fail-closed limits the risk, but P-020 still applies: a TOML shape that the reader accepts and reads differently from cargo-about would let the npm list and the Rust list drift apart without anyone noticing. Nobody has probed it.

The analysis decides between:
- (a) reading the list with a real TOML parser (the tool itself, for example a pinned npm TOML library or the cargo-about binary's own output);
- (b) moving the list into an owned literal both tools consume;
- (c) a probe-backed argument that no shape the reader accepts is read differently by cargo-about's TOML parser, recorded as out of scope.

## Acceptance

- [ ] The npm license check decides on the tool's own reading of `about.toml`, on an owned literal, or carries a recorded, probe-backed out-of-scope argument. Its `decides_on` is named.
- [ ] Failure branch: when the reader is kept or replaced, the divergence probes the analysis finds (multi-line strings, escapes, dotted keys, a duplicate key, a key after a table) are refused, and each fixture is red against the old reader. If none diverges, the probes are listed in the argument.
- [ ] The guard table in `docs/decisions/ci-toolchain.md` and `docs/decisions/licenses.md` are updated. `make check` is green.

## Investigation

2026-10-18, problem-investigator. Serena and context7 were not connected; context from file reads and grep. cargo-about 0.9.2 source is not in the core image (only the binary), so its behaviour was probed, not read.

### Frame

- Observed: `readAcceptedList` (`scripts/licenses/accepted.mjs`) reads about.toml with its own subset model: it walks top-level `key = value` lines before the first `[` header; `skipValue` skips a bracketed value by reading single-line strings (`readString` stops at a newline) and treats `"""` as an empty string plus another string.
- Expected: the npm check (`check.mjs::main`) uses the same list cargo-about uses, or fails.

### Probes

Method: fixtures in a throwaway dir; each run through (1) the current reader (node 24, `voicen-ui:1.63.0`), (2) Python 3.12 `tomllib` (same image, reference only), (3) `cargo about generate --frozen --fail --workspace -c <fixture>` (`voicen-rust:1.99`, cargo-about 0.9.2) on a one-crate path workspace licensed `GPL-3.0-only`. Offline worked: path crates only. cargo-about exit 0 means it read GPL-3.0-only as accepted; "failed to satisfy license requirements" means it read MIT.

**Leaks** (the reader returns a wider list; cargo-about accepts the file):

```
# q01                                   # q02 (literal)                         # q03
targets = ["""x86_64-pc-windows-msvc" ] targets = ['''x86_64-pc-windows-msvc' ] workarounds = ["""ring" ]
accepted = ["GPL-3.0-only"]             accepted = ["GPL-3.0-only"]             accepted = ["GPL-3.0-only"]
"""]                                    ''']                                    """]
accepted = ["MIT"]                      accepted = ["MIT"]                      accepted = ["MIT"]
```

| id | reader | tomllib | cargo-about 0.9.2 |
|---|---|---|---|
| q01 targets, `"""` | `[GPL-3.0-only]` | `[MIT]` | reads MIT; an MIT crate passes, exit 0, no warning |
| q02 targets, `'''` | `[GPL-3.0-only]` | `[MIT]` | reads MIT |
| q03 workarounds, `"""` | `[GPL-3.0-only]` | `[MIT]` | reads MIT; exit 0, one `[WARN] no workaround registered` |

**The reader diverges, but cargo-about refuses the file** (licenses-rust fails loudly): p10 (the T-094 Notes probe, `note = """`), p11 (reverse), p12 (`'''`), p80 (quoted key `"a=b" = """`), p82 (line-ending backslash in a multi-line string): "expected a table, found string", because an unknown top-level key must be a per-crate table. p74 `x = "a" # = [`: same error.

**The reader refuses (fail-closed, no leak):** p13, q04-q06, q09 (multi-line strings inside `[...]`/`{...}` values, unterminated string), p20 (`\u` escape), p24 (multi-line string inside `accepted`), p31-p33 (quoted or escaped key `"accepted"`; cargo-about reads them as `accepted`), p50, p52 (only in a table), p81.

**Both agree, or cargo-about fails loudly:** p00, p01, p25 (raw tab: cargo-about "unknown term"), p30, p34-p36, p40, p41 (a second `accepted`, dotted, quoted or `[accepted]`: cargo-about "duplicate key"), p51 (key after a table: both read the top-level list; cargo-about also applies `[probe] accepted` as a per-crate exception, see below), p60, p61 (inline table, multi-line inline table: both `[MIT]`; tomllib refuses p61, TOML 1.1), p62 (cargo-about "unexpected keys"), p70, p73 (trailing tokens: "expected newline"), p71 (BOM: both GPL), p72 (lone CR: "unexpected character"), p75, q07, q08.

So option (c) is refuted: q01-q03 are shapes the reader accepts and reads differently from cargo-about, with cargo-about exiting 0.

### Hypotheses

1. The reader's value-skipping model mis-reads a multi-line string in an earlier value: **confirmed** (q01-q03).
2. Escapes or quoted keys produce different strings: refuted as a leak; the reader refuses (p20, p31-p33).
3. Duplicate key / key after a table: refuted as a leak; cargo-about refuses duplicates, and tables cannot reach the top level.
4. A second path reads the list: no. `grep -rn readAcceptedList` finds only `check.mjs::main` and the two test files; `notices.mjs` does not judge licenses.
5. This class was fixed before: yes, class `guard-model` (F-003, F-015, P-020); T-094 is one of the planned audit rewrites (decisions #124, #125), not a new escape. No rca needed; `recurrence_of` stays empty.

### Root cause

The npm check decides on its own model of TOML (skip earlier values, then read `accepted`), and the model is wrong for multi-line strings inside an array value, which cargo-about's TOML parser accepts for the known keys `targets` and `workarounds`.

### Options

- **(a) a real TOML parser.** Node 24 has no built-in TOML parser; an npm TOML package is a new dependency (owner consent). Python 3.12 `tomllib` is in the ui image, but from the base image, not pinned by `docker/ui.Dockerfile`. It is TOML 1.0, cargo-about's parser is TOML 1.1 (p61). It agrees with cargo-about on every probe both accept, but it is still a second parser standing in for cargo-about, and check.mjs would have to spawn python. "The tool itself" (judge each npm license by running cargo-about on a synthetic crate) needs the core image in licenses-npm and maps npm SPDX strings to Cargo license fields: more than one seam. Not recommended.
- **(b) owned literal, recommended.** about.toml stays the one list (#24 D2). The reader stops parsing TOML. It requires about.toml to begin, from byte 0 (CRLF normalised to LF; any other CR, a BOM, or anything else refused), with: zero or more `# ...` lines; `accepted = [`; lines that are `    # ...` or `    "<id>",` with `<id>` = `[A-Za-z0-9.+-]+( WITH [A-Za-z0-9.+-]+)?`; `]`. It returns the ids of that block. No quote, backslash or multi-line string can occur in the block, so it has one TOML meaning, and it is the start of the document, so nothing before it can change that meaning. A later redefinition of `accepted` is a TOML duplicate key, which cargo-about 0.9.2 refuses (p30, p34-p36, p40, p41). The current about.toml already has this shape. `decides_on: literal` (the owned line shape, like `nsis-fork.sh`'s `; upstream:` line). Risk: an about.toml reformat (for example single-line array, inline comment) fails `licenses-npm` with exit 2, which is the intended fail-closed result. Rollback: revert the one file and its tests. Optional hardening: a cargo-about duplicate-key fixture in `fixture-check.sh`, which pins the "later `accepted` is refused" half on a cargo-about bump (the licenses.md rule already says to re-run guards on a bump).
- **(b2) a separate owned list file** (for example `licenses/accepted.txt`) that the npm check reads, plus a byte-exact check that about.toml begins with its rendering. This is stricter (byte-exact), but the list then lives outside about.toml, against the #24 D2 wording ("all in about.toml, the one list"), so it needs an owner decision. Not needed: (b) gives the same guarantee.
- **(c) out-of-scope argument:** refuted by q01-q03.

### Red test first

In `scripts/licenses/accepted.test.mjs`: q01, q02, q03, p10 and p12 (verbatim above and in the T-094 Notes) must throw. The old reader returns `["GPL-3.0-only"]` for each, so all five are red. Then: the committed about.toml yields `DECISION_24`. A valid head plus a later `accepted = ["GPL-3.0-only"]` returns the head's list (the file is refused by cargo-about, p40). These are refused: single-line `accepted = ["MIT"]`, a literal-string id, an inline comment after an id, a key or blank line before `accepted = [`, a BOM, a lone CR, an id with a quote or backslash. The existing test "reads a multi-line array with comments, trailing comma and both string kinds" and "only the top-level accepted is read" are rewritten to the new shape.

### Out of scope, noted

A per-crate `[crate] accepted = [...]` in about.toml widens the Rust side only (p51: cargo-about passes the GPL crate). The npm side stays stricter, so the lists cannot drift the dangerous way. Such an entry is already an owner decision (licenses.md, "an exception is an owner decision"); not this guard's concern.

**Size:** small, one seam (`accepted.mjs::readAcceptedList`). **Owner decision:** none for (b); (a) with an npm package or (b2) would need one.
