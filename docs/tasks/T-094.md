## Context

Found in T-086 review 1 (finding 2, decisions #125). `make licenses-npm` (`scripts/licenses/check.mjs`) judges the npm packages of the client bundle against the one accepted-license list, the top-level `accepted` array of `about.toml`, which cargo-about also reads (T-027). It reads that list through `scripts/licenses/accepted.mjs`, whose header says "Not a TOML parser": it understands only basic and literal strings, comments and a trailing comma before the first table header, and fails loudly on anything else.

Being fail-closed limits the risk, but P-020 still applies: a TOML shape that the reader accepts and reads differently from cargo-about would let the npm list and the Rust list drift apart without anyone noticing. Nobody has probed it.

The analysis decides between:
- (a) reading the list with a real TOML parser (the tool itself, for example a pinned npm TOML library or the cargo-about binary's own output);
- (b) moving the list into an owned literal both tools consume;
- (c) a probe-backed argument that no shape the reader accepts is read differently by cargo-about's TOML parser, recorded as out of scope.

## Acceptance

- [ ] The npm license check decides on the tool's own reading of `about.toml`, on an owned literal, or carries a recorded, probe-backed out-of-scope argument. Its `decides_on` is named.
- [ ] Failure branch: when the reader is kept or replaced, the divergence probes the analysis finds (multi-line strings, escapes, dotted keys, a duplicate key, a key after a table) are refused, and each fixture is red against the old reader. If none diverges, the probes are listed in the argument.
- [ ] The guard table in `docs/decisions/ci-toolchain.md` and `docs/decisions/licenses.md` are updated. `make check` is green.
