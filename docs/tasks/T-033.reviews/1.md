### Root cause verified independently (not taken from the analysis)

- **tauri-build 2.7.1** (`src/static_vcruntime.rs`, read from the locked crate in the core registry cache):
  - `override_msvcrt_lib()` writes a stub `msvcrt.lib` into `OUT_DIR` and prints `cargo:rustc-link-search=native={out_dir}`.
  - `build()` prints plain `cargo:rustc-link-arg=/NODEFAULTLIB:msvcrt.lib` … `/DEFAULTLIB:libcmt.lib`, `libvcruntime.lib`, `ucrt.lib`.
- **cargo at the `rust-1.99.0` branch** (fetched with `gh api`):
  - `src/ops/cargo_test.rs` passes `-L` to every rustdoc doctest for each entry of `compilation.native_dirs`.
  - `src/compiler/build_runner/mod.rs` fills `native_dirs` from the `library_paths` of every build script in the invocation, in the loop at the end of `compile`.
  - The same file pushes `link-arg=` into a doctest only from `find_build_script_metadatas(unit)`, which is the doctest's own package.
  - So the claim holds: search paths are shared across the whole invocation, link-args are per package.
- **CI log 37151218166**: `Doc-tests voicen_core` → `running 2 tests` → `...\target\debug\build\voicen-6de42dc96d3ba620\out\msvcrt.lib : warning LNK4003: invalid library format; library ignored`. This matches the analysis. `Doc-tests voicen_lib` ran 0 tests, so it says nothing either way.

### Does the change follow from the cause and hold the invariant?

- **Step 1, `cargo test --workspace --exclude voicen` (`ci.yml:60`).** The shell's build script is not in this invocation, so the stub's directory is never in `native_dirs`.
  - voicen-core's graph is serde, serde_json, url, zeroize and the self dev-dependency. It contains no CRT-shadowing build script.
  - `--workspace` picks up any future member automatically. For example, the planned `crates/voicen-whisper` (specs/002 plan:116) will have its doctests tested without the stub. This holds the "current or future crates" half of the invariant without anyone having to keep a list.
- **Step 2, `cargo test -p voicen` (`ci.yml:61`).** Only the shell's own targets are tested here. voicen-core is built as a dependency, and its tests and doctests do not run.
  - Any future `voicen_lib` doctest gets tauri's link-args (`LinkArgTarget::All` applies to doctests), so the stub is harmless there.
- **Comment (`ci.yml:57-59`).** It names the mechanism (stub, `native_dirs`), the rule ("other crates' doctests must not share a run with `voicen`") and F-001, at the exact place a future edit would happen.
- **What could break it later.** A future crate that depends on `voicen`, or that calls `tauri_build::build()` itself, would bring the stub back into step 1. That failure is loud (a link error turns the job red), not silent, and F-001 together with the comment points to the cause. This is acceptable without a mechanical guard.
- **The rest of the job is unaffected.** `pnpm tauri build` builds only the shell's targets, which get the link-args, and the release profile is unaffected.
- **Scope and secrets.** No Cargo.toml, build.rs, tauri.conf.json or code change, and no new dependency. No secrets or personal data in the diff or the commit message. `surface: "none"` is honest: the change is CI-only, with no endpoint or screen.
