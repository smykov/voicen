## Context

Session review of 2026-10-23. In the T-116 agents' transcripts, commands that should take under a second took 1–2 min between `tool_use` and `tool_result`: `sed -i '460{/^$/d}' … ; sed -n …` 2.1 min, a `python3 -` in-place edit 1.3 min, `grep -n … | head` 0.9 min, a `cat >> …/mutants.py <<'PY'` 1.6 min. No build ran at those moments in that agent. Candidates: PreToolUse hooks (`scripts/hooks/`, the teamwright gates), the permission/auto-mode check, host load from a parallel agent or gate. Unknown which; nothing is changed until the cause is measured.

## Acceptance

- [ ] The cause is measured, not guessed: per-call timings of hooks vs. the command itself (hook timing log or `time` around the hook scripts), on a reproduction with a trivial command
- [ ] Either a fix (hook made cheaper, matcher narrowed) with before/after timings, or a recorded finding that the latency is outside the repository (runtime or permission layer), with the evidence
- [ ] Failure branch: a hook that must refuse (e.g. the VERIFY GATE on a shell write to a verify record) still refuses after any change; shown by one refused call
- [ ] Any change to `scripts/hooks/` follows the guard rules if it touches a guard path; `make check` stays green
