**Facts the design rests on**
- The start order needs no change to storage.rs. `NewCall` takes the `EndpointId`s that `TrackSource::open` returns, so the order system open → mic open → `CallStore::create` (probe inside it) is the natural order. `create_with` already cleans up the folder after any failure that follows the probe.
- Stop needs no change to storage.rs or codec.rs either. The session moves `mic`/`system` out of `ActiveCallFiles` (pub fields; clone `dir()`/`meta()` first) and calls `TrackEncoder::finish`. It then writes the final meta through `storage::write_meta` (the one atomic writer) and takes `mic_bytes`/`system_bytes` from `fs::metadata` of the two files. A byte-count API on the codec was considered and not needed.
- `ProviderHost` has no `Serialize`, but `CallWarning` derives `Serialize`. A `serialize_with` in events.rs keeps `settings/url.rs` untouched. The indicator wire carries `{id, kind, text}`, with the text rendered in Rust, so the host reaches the UI only inside the rendered `warning.provider_notice` text.
- No writer for `calls.warned_hosts` exists (`keep_server_owned` blocks the draft). `forget_model` is the precedent for a narrow writer under `save_lock`; `remember_warned_host` follows it, and `docs/decisions/settings.md` gets a line for it.
- The provider host comes from the 1a final engine, which is the API engine (`settings.api.base_url` through `check_base_url` → `provider_host`). That is the same rule the Calls tab shows (T-120 I4).
- The mic fallback is core's decision, the same as in dictation (dictation-session.md). It is a retry on `NoDevice` for `Selected(id)` only, never on busy or access_denied. The other way is `microphone::choose` over `AudioSource::devices()`; I rejected it because it needs a second port in the session and T-127's `CpalTrackSource` already opens "the selected id or the default input".
- `recording::IndicatorState` (dictation) already exists. The call types live in `call::indicator`, and the crate root does not re-export them.
