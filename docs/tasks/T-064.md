## Context

Cut from T-050 by decision #77 (OQ-13, option (a)). T-050's analysis found two causes of the local e2e boot flake; T-050 fixes M1 (run-private build output and port, boot fixture that names the cause). This task takes M2: Chromium runs in the host network namespace, so Docker user-network / interface changes from other jobs abort in-flight `/_app/immutable` chunk fetches with `net::ERR_NETWORK_CHANGED` and SvelteKit renders its client "500 Internal Error" page. Evidence (T-050 Investigation): under network churn 9/300 failures in the host netns, 0/200 in a private netns (`unshare -n`). Owner's choice: run the ui e2e (webServer + test runner) in the official Playwright container image matching the pinned `@playwright/test` version, through the ui area's runner (`scripts/tw-run ui`). Changing the area runner in `.teamwright/config.yml` goes through `config.next.yml` + `apply --config` with the owner (the orchestrator does not edit the config). Every e2e entry point (`make check`, `pnpm e2e`, validators' worktrees) must keep working; CI Gate behaviour stays the same or moves to the same image.

## Acceptance

- [ ] `make check`'s e2e step and `pnpm e2e` run Playwright and its webServer inside the Playwright image pinned to the lockfile's `@playwright/test` version, in a network namespace of their own (no `--network host`)
- [ ] Failure branch: the T-050 churn reproduction (Docker user network create / attach / remove in a loop) during an e2e run → no `ERR_NETWORK_CHANGED` abort, the suite passes; a missing image or a version mismatch fails the gate with a message naming the image, not as a test failure
- [ ] Test that fails without the change: the churn reproduction committed as a script (evidence: failures in the host netns before, none after, recorded in the task)
