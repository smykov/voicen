## Context

Cut from T-050 by decision #77 (OQ-13, option (a)). This task takes M2: Chromium runs in the host network namespace, so Docker user-network / interface changes from other jobs abort in-flight `/_app/immutable` chunk fetches with `net::ERR_NETWORK_CHANGED` and SvelteKit renders its client "500 Internal Error" page. Evidence (T-050 Investigation): under network churn 9/300 failures in the host netns, 0/200 in a private netns (`unshare -n`). Every e2e entry point (`make check`, `pnpm e2e`, validators' worktrees) must keep working; CI Gate behaviour stays the same or moves to the same image.

## Investigation

Investigator, 2026-10-06. **Tools:** Serena and context7 were not connected in this session, so I used file reads and grep. I did not use context7 for Playwright's Docker docs. Playwright's behaviour comes from the installed `playwright-core@1.63.0` (`lib/coreBundle.js`): the Docker marker file `/ms-playwright/.docker-info`, the "Please update docker image as well" path in `executablePathOrDie`, and the default `--no-sandbox` and `--disable-dev-shm-usage` switches. Image facts come from registry metadata only (`docker manifest inspect`, `docker buildx imagetools inspect`). **No layers were pulled**, and I ran no e2e run in a container. I edited nothing except this file.

**Frame.** Observed: local gates and validators fail at random at page boot with `net::ERR_NETWORK_CHANGED` on chunk fetches while other jobs churn Docker networks. T-050's boot fixture now names the cause (T-061.validation/2, T-065.validation/1), but the failures still happen. Expected: the e2e browser is immune to host network events. Never seen in CI: its runner has no concurrent Docker jobs.

**Hypotheses.**
1. *The browser shares the host netns on every entry point.* **Confirmed by code reading.**
   - `package.json` `scripts.e2e` = `playwright test`.
   - `.teamwright/config.yml` gives area `ui` `runner: host`, so `scripts/tw-run`'s `host` branch is `sh -c` in the tree.
   - `Makefile` `check-ui` calls `scripts/tw-run ui -- pnpm e2e`.
   - The rendered agent commands (`.claude/agents/test-writer-ui.md`, `task-validator.md`) use the same `scripts/tw-run ui -- pnpm e2e`.
   - No entry point gets its own netns.
2. *A private netns removes M2.* **Confirmed for `unshare -n`** (T-050: 0/200 vs 9/300 under the same churn). **Not yet measured for a container.** A Docker container also has its own netns, but with an `eth0` on a bridge, not lo only. Churn on *other* user networks moves host-side veths and bridges, which are outside the container's netns. That is why I recommend `--network none` for the e2e run: it is exactly the measured lo-only condition, and the suite needs no outside network (IPC is mocked; the `example.com` and `192.0.2.10` URLs in e2e are mock data, not fetched). The after-measurement is the task's evidence.
3. *A second path keeps a host-netns browser.* Today every path is host. After the change, three paths have to land in the container:
   - Makefile `check-ui`;
   - `pnpm e2e` typed on the host;
   - `scripts/tw-run ui -- pnpm e2e`.

   `BASE_URL` mode also changes meaning. Inside the container, `localhost` is the container's own, so a server on the host is unreachable without `--add-host`. Today it is used only by investigators against a preview in the same netns.
4. *Same class fixed before.* T-050 fixed M1 of class `e2e-boot-flake` (DONE) and deliberately left M2 to this task (decision #77). M2 has not been patched before, so this is not a recurrence. `docs/failures.md` has no entry and no Classes row for `e2e-boot-flake`. `recurrence_of: []` is right. - run on the **host**, because it needs Docker and must not run inside the ui container;
- churn with an image already present (the ui image itself, or `voicen-rust:1.99`);
- count the churn cycles, so a run without churn cannot pass;
- run the e2e entry point with `--retries=0` and enough `--repeat-each` to make the before-run red with high probability (T-050: ~3 % of 100 tests per run, and the suite now has 116);
- assert deterministically that the runner's `/proc/self/ns/net` differs from the host's.

**Root cause.** The ui area runs Playwright, and with it Chromium, in the host network namespace on every entry point. Host Docker network churn therefore reaches the browser as network changes and aborts boot chunk fetches. Contradicting evidence: none. It is consistent that CI never flakes, because nothing churns there.

**Invariant.** No e2e browser shares the host's network namespace. Every entry point runs runner, webServer and Chromium in a run-private netns inside the Playwright image at the lockfile's version. A missing image or a mismatched one stops the run before any test, naming the image, and never falls back to the host.

**Seam.** One seam: the ui area's runner (config) as executed by `scripts/tw-run`'s docker branch, plus one project-owned e2e entry wrapper (`package.json` `e2e` → wrapper) that does the preflight and adds `--network none --init -e CI`. Paths routed through it:
- Makefile `check-ui`;
- `pnpm e2e` on the host (the wrapper re-enters via `TW_DOCKER_ARGS=… scripts/tw-run ui -- …`);
- `scripts/tw-run ui -- pnpm e2e` (already inside; detected via `/ms-playwright/.docker-info` or a marker env, runs directly, with the version preflight still applied);
- `scripts/ci/e2e-build-race.sh` (runs inside, unchanged);
- CI Gate.

It must change together with `playwright.config.ts` `sweepStaleRunDirs` (pid namespaces). **Size:** one concern with settled behaviour (decision #77). It is not large, so no spec tool is needed, but it touches config, wrapper, Makefile, `playwright.config.ts`, the CI workflow, docs and possibly a Dockerfile.

**Approach.**
- **(A) Recommended: ui area `runner: docker`, image = official Playwright 1.63.0 image + pnpm 8.15.0.** Because the official image has no pnpm and every `tw-run ui` command calls `pnpm`, the image is a thin project image: `docker/ui.Dockerfile` `FROM mcr.microsoft.com/playwright:v1.63.0-noble`, installing pnpm at `packageManager`'s version, tag e.g. `voicen-ui:1.63.0`, with `make ui-image` like `make core-image`. CI builds or pulls the same image.
  - Lint, unit tests and licenses then also run on the image's Node 24 instead of 20.19 (allowed by `engines`, and N-API binaries are unaffected). This is a toolchain change the owner should accept knowingly.
  - Red first: the churn script fails on the host-netns run (record the counts) and passes in the container (record the counts), plus the deterministic netns assertion.
  - Wrapper fixture tests (fake `TW_DOCKER`, or a fake `.docker-info`): a missing image → exit before any test with a message naming the image; `driverVersion` ≠ lockfile → a message naming both. CI env passthrough: `CI=1` reaches `playwright.config.ts` (`forbidOnly`).
  - E1 sweep test: a `run-<pid>-` dir from another pid namespace with a pid that is free in this one is not deleted while its owner lives.
  - Docs in the same commit: `docs/decisions/ui-e2e.md` new E3 (and E1's "Where it is enforced"), `CLAUDE.md` Commands and Gotchas (`pnpm e2e` runs in the container; setup needs `make ui-image`), `docs/architecture.md` if it names the ui toolchain.
  - Risk: a ~1 GB image per CI run (the Actions cache is already over its limit, decision #81, so caching the image is no answer); the first run locally needs the download; uid 1001 in CI not yet tried.
  - Rollback: `config.next.yml` back to `runner: host` and revert the wrapper.
- **(B) Alternative: ui stays `runner: host`; only e2e runs in the unmodified official image.** Use a second area (e.g. `ui-e2e`, `runner: docker`), or the wrapper's own `docker run`, and a pnpm-free webServer (`node_modules/.bin/vite build && … preview`, `node_modules/.bin/playwright test`).
  - Keeps lint, unit tests and licenses on host Node 20.19 and needs no derived image.
  - But it departs from #77's "through the ui area's runner (`scripts/tw-run ui`)". A docker call outside tw-run duplicates its mount and uid logic, and a second area may not fit the hooks' area routing. Same red tests.
- **(C) `unshare -n` around the e2e step:** rejected in #77 (it needs root or user namespaces and differs from CI).
- **Not acceptable:** retries, or filtering `ERR_NETWORK_CHANGED` in the boot fixture (E2).

**Needs the owner.**
1. The **config change** of area `ui` (`runner: docker`, `image: …`; `e2e_ui_command` can stay `pnpm e2e`) goes through `.teamwright/config.next.yml` + `tw-install.py apply --config`. The orchestrator does it with the owner's go; no agent edits `config.yml`.
