## Investigation

Tools: Serena and context7 are not connected in this session, so I used grep and file reads. The pinned dependency sources (tauri 2.12.1, tauri-macros 2.7.1, reqwest 0.13.5) are in `.teamwright/cache/core/_usr_local_cargo_registry`. Nothing was run; the evidence comes from reading code.

**Frame.** FR-14 (v4) and spec 004 US4 require "Test connection" for the api and local_server engines. It uses the form values, unsaved ones included, and the stored key when the key field is untouched. It reports OK with latency in ms, or why it failed. It saves nothing and is disabled while it runs. A result that arrives after the window closed is discarded. Today nothing in core, the shell or the UI does any part of this.

**What exists and is reused (P-011).**
- `engine_for(&Settings, &dyn CredentialStore)` (engine/mod.rs:49-70) is the one factory. It applies `check_base_url` before any key read and reads the slot once. `OpenAiCompatibleEngine` (openai.rs) is the one client: blocking reqwest + rustls, a body buffered for correct connect classification, a 1 MiB cap, and `authorization()` (:101-109) as the one key-header rule. `classify` (failure.rs:164-191) is the one mapping, and `host_port` (openai.rs:241-247) gives `host[:port]` with no query. `Timeouts` holds connect 5 s, api 30 s, local server 60 s. The tests in tests/openai_client.rs show the patterns to copy: wiremock on its own runtime, the engine on a std thread, `refused_port()`, `.invalid` hosts.
- The request that R-9 settled is `POST {base}/audio/transcriptions` with a bundled ~1 s 16 kHz mono clip, no language and no VAD. It is not `GET /models`, because not every server has it and it proves nothing about transcription. The key comes from `KeyEdit` with the save's semantics (data-model.md:41,84).

**Hypotheses.**
1. *Parts exist; only the tester and its wiring are missing.* Confirmed (lib.rs module list, lib.rs:27-32 handler list, Engine.svelte, tauriMock.ts).
2. *A second path for the same concern.* This is a risk, not a fact. A tester that builds its own reqwest client or `bearer_auth`, or that re-implements the URL, trim or key rules, would be a second path. The reuse points are already private. `key_step` and `normalize` are private in service.rs:478-512, and `host_port` is `pub(crate)`. So the tester goes inside core and is reached only through `SettingsService`.
3. *The shared mapping already gives the required messages.* Refuted for DNS. An unresolvable host gives `NetworkUnavailable` (failure.rs:173-181, pinned by tests/openai_client.rs:485-494), but FR-017 says DNS failure means "cannot reach <host>". The Acceptance "wrong host → cannot reach <host>" therefore needs a tester-level mapping `NetworkUnavailable → CannotReach{host_port(base)}`. `classify` must stay unchanged, because dictation keeps "network unavailable".
4. *The obvious shell command works.* Refuted. The existing pattern, a sync body under `#[tauri::command(async)]` (settings_ipc.rs:98), runs inside `async_runtime::spawn` (tauri ipc/mod.rs:375). In debug builds reqwest's blocking `wait::enter()` builds and drops a runtime there and panics (wait.rs:81-90). The engine doc (engine/mod.rs:4-5) already forbids it. The command must be `async fn` + `spawn_blocking` (or a std thread + channel), returning `Result` because `State` is a reference (tauri-macros wrapper.rs:176-228).
5. *This class was fixed before.* No. docs/failures.md has F-001..F-003 (ci-toolchain, guard-model); none concerns the connection test or the settings UI. The only process link is the F-002 rule: the shell test goes only in `src-tauri/tests/*.rs`. Recurrence: none.

**Contract gaps found (no owner choice needed unless stated; fix them in the implementing commit, P-014).**
- core-traits.md:111-117 says `async fn test`. Under #42 core is synchronous, so the tester is a blocking `fn`.
- R-9, core-traits.md:55, clock.rs:1-2 and architecture.md:68 say latency comes from the wall `Clock`. Under #47(2) durations use `Instant`, and a wall clock can step backwards. Measure latency with `Instant` around `transcribe`. The test asserts `latency_ms >= mock delay` (wiremock `set_delay`), which bites a constant or missing measurement without a fake clock. Remove "connection test" from the Clock docs.
- data-model.md:85 has no result for a credential read error (`KeyStoreUnavailable`) or for the Unavailable load state (#19: no credential call). Proposal (Q3) below.
- T053 asks for messages as kinds (`OK, {ms} ms`, `cannot reach {host}`, ...). U2 (settings-ui.md) forbids a UI table of codes. So the wire result should carry a core `MessageId` + params, like `FormError.message`. Reuse `failure.cannot_reach`, `failure.invalid_api_key`, `failure.timeout`, `failure.server_error`, `failure.unexpected_response` (en.json:25-34). Add `settings.test_connection.{button,running,ok}` (`ok` = "OK, {ms} ms") to both catalogs. Pin one example of every kind in `e2e/fixtures/settings-wire.json` with a core test, as service.rs:2653 does for the view.
- `Invalid{errors}` uses the save's rules (the `UrlError` → code mapping of `validate`, API model `required`), not a copy, so T053's "a refused-form result highlights fields" goes through the same `errorsByField` path.

**Design (recommended).**
- *Core.* `SettingsService::test_connection(&self, req: ConnectionTestRequest, timeouts: &Timeouts) -> ConnectionTestResult` delegates to `connection_test`. The steps:
  1. Overlay the request's engine, base URL and model on a clone of the snapshot, then run the save's `normalize`.
  2. Form errors → `Invalid`, with no request.
  3. Wrap the credential store in a read-only view for the selected slot: `Replace` trimmed (#33(a)); blank `Replace` or `Untouched` → `read` (#30); `Clear` → `None`. `write`/`delete` → `Err`, never delegated.
  4. `engine_for(&overlaid, &view)` → `transcribe(clip, {language: None, timeouts})`, timed with `Instant`.
  5. Map the outcome: `InvalidApiKey`→`InvalidKey`, `CannotReach`/`NetworkUnavailable`→`CannotReach{host}`, `Timeout`→`Timeout`, `ServerError`→`Http`, `UnexpectedResponse`→`UnexpectedResponse`, `KeyStoreUnavailable`→(Q3), with no wildcard.

  "Nothing saved" is structural: the tester never calls `save` and holds no write path. It logs nothing (R-11's `settings test_connection` line belongs to T-008, which has no log yet).
- *Local server.* It goes through T-018's `engine_for` arm (60 s timeout, `model` omitted when empty, optional key via `authorization()`), so this task writes no local-server code. Until T-018, `engine_for` gives `EngineNotConfigured` for local_server. That would be a wrong result for US4-5, so the local-server case needs T-018 first (see size).
- *Shell.* `#[tauri::command] async fn settings_test_connection(service: State<'_, Arc<SettingsService>>, request: ConnectionTestRequest) -> Result<ConnectionTestResult, String>` clones the `Arc`, then runs `spawn_blocking(move || service.test_connection(request, &Timeouts::default()))`. A join error rejects with a fixed text (contract `ipc.unavailable`). Deserialize errors use fixed texts that never quote the key, like `SaveRequest` (T-030 J1). Register it in `commands()`. If the window is destroyed while the request is in flight, Tauri's response goes nowhere. The blocking thread ends at the latest when the request times out (≤ 35 s / 65 s, SC-006).
- *UI.*
  - `testConnection(request)` in settingsApi.ts; the request is built in draft.ts from the draft (selected engine's URL, model, `draft.keys[slot]`).
  - Engine.svelte gets the button for api/local_server only, disabled with progress while pending, and the result rendered with `t(message, params)`.
  - A generation counter discards a result that arrives after `discard()` → `destroyWindow()` or after unmount. Spec edge case 148 says a result after a draft edit refers to the values at the click and is still shown, so it is not discarded on edits (Q4).
  - tauriMock.ts gets `settings_test_connection` with scripted results, `holdTests`/`releaseTest` and call recording.

**Size.** This is not seam-sized. It spans a core module + asset + wire types + service method (~15 red tests), a shell command (Windows CI, 2-3 tests) and a UI feature (~8 Playwright cases, en/ru texts, mock). It also needs T-018 for the local-server branch. Options for the orchestrator, following #35/#38/#43/#49:
- **(A, recommended; #35 shape)** New task **T-046 "Connection test in core and shell"**: `connection_test.rs`, clip, wire serde + fixture pin, `SettingsService::test_connection`, `settings_test_connection` + its `src-tauri/tests` case. `surface: none`, `deploys: true` (Windows CI), `depends_on: [T-018]`. It takes Acceptance line 2's "core tests against a mock server", and the local-server cases (US4-5, model omitted, 60 s) are its red tests once T-018's arm exists. **T-013** keeps the UI (button, result, discard, messages, mock, `e2e/settings-test-connection.spec.ts`), `surface: ui`, `depends_on: [T-004, T-046]`. It edits Engine.svelte next to T-045 (picker); merge order only.
- (B; #49 shape) Core / shell / UI as three tasks. The shell half is about 20 lines, so a separate review costs more than it isolates.
- (C) Keep it whole and depend on T-018: three seams in one review, against the precedents.

**Owner / product questions.**
- **Q1 (blocking only for the clip commit in the core implementation, not for the red tests or the UI):** R-9 says the ~1 s speech clip is "recorded for the project" and committed under MIT. An agent cannot record a voice. Options:
  - (a) the owner records a short phrase as a 16 kHz mono WAV (default per R-9);
  - (b) the agent ships a synthetic non-silent signal; R-9 warns some servers reject or hallucinate on silence, and it has not been checked against OpenAI/Groq;
  - (c) a CC0/public-domain speech snippet, with its licence recorded in THIRD-PARTY-NOTICES.
- Q2 (orchestrator): the split, A / B / C above.
- Q3 (orchestrator, non-blocking): a credential read error during an `Untouched` test. Proposal: a new result kind `KeyStoreUnavailable`, rendered with the existing `failure.key_store_unavailable`. While settings are `Unavailable` (#19), `Untouched` means "no key" with no credential call, which matches the view's "no key saved" (#33(b)).
- Q4 (orchestrator, non-blocking): the brief said to discard on draft change, but spec edge case 148 says the result refers to the values at the click. Proposal: follow the spec. Show the result and keep it until the next click; discard only on close or unmount.
- Q5 (orchestrator, non-blocking): API engine with no key (Clear, or Untouched with nothing stored). Proposal: `Invalid[engine.api.key key.required]` from the save's rule, with no request, rather than sending without a key and showing "invalid API key".
