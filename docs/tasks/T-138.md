## Acceptance

- [ ] A primary `Err` never becomes empty spans or dropped audio (T-134 r1#1)
- [ ] Decoding is one window at a time (≤ 120 s plus carry); no temp file in the call folder or the temp dir (T046, T047)
- [ ] At most 3 requests are in flight, drawn from both tracks in start order (T046)
- [ ] Failure branch: a 400 on chunk k makes chunk k and every later chunk time-less, lines span their chunks, and `pass_mode: timeless` is recorded (T046)
- [ ] Per-segment, per-request and missing language give `en`, the request value and `null` (T046)
- [ ] Failure branch: Silero unavailable → energy spans and `vad_fallback` logged (T046)
- [ ] Failure branch: a built-in dictation engine with no API key gives `failed: engine_not_set_up` before any request (T046)
- [ ] Failure branch: a track's first failure cancels its remaining chunks, the other track finishes, per-track results are kept in `meta.json` `results` (T046)
- [ ] `transcript.json` is validated, then written with temp + rename, and so is `transcript.md`; failure branch: a failed write leaves `failed: storage` and no partial file (T046)
- [ ] `final_stage` lines per stage and track and `final_finished outcome= reason= mode= ms=` are logged; the notice is `transcript_ready{call}` or `pass_failed{reason}` (T046)
- [ ] An API engine settings change during a pass is not picked up by the running pass (T046)
- [ ] Test that fails without the change: the pass tests of `call/final_pass.rs`

**Design facts the runner rests on.**
- `Timed.segments: Some` → `ChunkInput{segments: Some, lang: timed.language}`; `merge` gives each segment `segment.lang.or(chunk.lang)`. That is FR-025's "per segment, per request, else null" with no extra code. The request's `language` setting is **not** a fallback for `lang`.
- `TimedFailure::Timeless` is decided inside the engine (T-136). The pass only matches it: re-cut the chunk with `recut_timeless` and send each piece `Plain`. `Failed(reason)` fails the track.
- Memory: per track, one `ChunkPlanner` (≤ 120 s, 3.84 MB) and at most one ready chunk, plus ≤ 3 chunks in flight (their WAV is built inside `transcribe_timed`, R11 ≈ 11.5 MB). This is bounded and independent of call length. The 30-min test pins it through the planner's `carry_ms()` and the decoder's asked `max_ms`.
- Stage times: `crate::clock::MonotonicClock`, injected (the clippy ban on `Instant::now`).

**Developer-level choices (D1–D7; written to contracts/core-call.md "Built (T-138)" and docs/decisions/call-final-pass.md in the implementing commit; none needs the owner).**
- D1 *"Every later chunk"* is strict, in dispatch order. When chunk k (pass-global dispatch order) returns `Timeless`, the pass mode flips. Chunk k and every chunk dispatched after it are sent `Plain` after `recut_timeless`. A later chunk already in flight as `Segments` has its answer dropped and is re-sent `Plain`, which costs at most 2 extra requests. Chunks before k keep their times. The planners stay `Timed`; later chunks are re-cut before dispatch, so there is one cutting rule.
- D2 *VAD fallback* is per window and sticky per track. The primary's `Err` on a window gives energy spans for **that** window (not empty, not skipped), one `vad_fallback track= cause=` (`Unavailable` → `unavailable`, `Failed` → `error`, a later `VadError` variant → `error`), and energy spans for the rest of that track. `primary: None` → `cause=unavailable` for each track at its first window.
- D3 *Engine setup*: base URL refused by `check_base_url`, or key `None` or blank after trim → `failed: engine_not_set_up`, `failure.track: None`, both results `failed{engine_not_set_up}`, no request. A credential-store read `Err` → `key` (the key slot could not be read; "Transcribe again" retries). This is not T-136's private `fail_reason` default (`KeyStoreUnavailable` → `provider`, which says nothing about the cause). The reviewer may prefer `provider`; neither is a product change, since both are existing FR-027 reasons.
- D4 *Track failure and call failure*: the first `Failed` of a track stops dispatching its chunks and decoding it; its in-flight answers are dropped. `failure = {reason: that track's reason, track: Some(track)}`. If both tracks fail, the reason is the first failure in dispatch order and `track: None`. No `transcript.*` is written unless both tracks are done (FR-027); `results` keeps `done{segments}` of the good track (call-relative `SegmentV1` from `merge` over that track alone, so T-146 can redo only the failed one).
- D5 *Decode ends*: `Ok(None)` and `Err(Damaged)` (the CRC-valid prefix was already returned, R7) both end the track. `Unreadable` and `Codec` fail the track with `storage`.
- D6 *Write order*: validate, then render, then `transcript.md`, then `transcript.json` (the commit point; T-141 D3 reads lines from it), then `meta.json` (`ready`, results, `pass_mode`). Each step goes through `write_atomic`. A failure at any step gives `CallStorageFailed{kind: transcript | meta, os}`, a best-effort `meta.json` with `failed: storage`, and `PassFailed{storage}`. Files left are whole, never partial. A `validate()` `Err` logs `TranscriptInvalid{rule, segment}` and gives `failed: storage` (contract "transcript.json").
- D7 *Log lines*: `final_stage` for decode, vad and upload per track (summed ms, `chunks` = the track's chunks); merge and write run once over both tracks and are logged once per track with the shared ms and that track's chunk count, because `FinalPassStage.track` is required. One `final_finished` per pass with `mode` = the mode the pass ended in. `meta.json` `duration_ms: None` (should not happen after stop) → the shorter decoded track's length (data-model "duration = the shorter readable track").
