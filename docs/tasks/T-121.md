## Investigation

Tools: Serena loaded (ToolSearch select). `get_symbols_overview` on `crates/voicen-core/src/settings/gate.rs` worked; `find_referencing_symbols` for `second_launch_action` returned nothing (src-tauri is Windows-only and not resolved by the Linux language server), so callers were found with grep over `crates/` and `src-tauri/` for `launched_by_autostart`, `AUTOSTART_ARG`, `on_second_instance`, `SecondLaunchAction`, `LaunchArgs`, `CallSwitch`. No new library API (the plugin callback's `Vec<String>` argv and `std::env::args_os()` are already in use), so no context7 lookup.

**Frame.** Feature. Today a second launch is classified by one bool (`--autostart` anywhere in argv, exact match). Expected (FR-003, FR-043, #184): `--call record` reaching the running instance is a distinct decision `StartCallRecord`; an unknown `--call` value is refused without action; the pre-007 rows are unchanged.

**Hypotheses checked.**
1. *A second parser of the same argument*: today core never sees argv (the shell parses, core gets a bool). After the change the risk is a second `--call` reader in T-128's first-launch path; invariant I1 closes it (T-128 calls `LaunchArgs::parse(std::env::args_os())`). `win::purge::from_args` parses `--purge-credentials` separately, runs in `main` before `run()` and exits; the contract keeps it unchanged - a different argument, not a second path of this concern.
2. *Logging inside the callback*: the contract says "the primary logs `CallSwitchRefused`", while windows-shell.md forbids any side effect in the second-instance callback beyond posting one request and `on_second_instance`'s doc says it writes no log line. The only queue in the primary today is the settings opener (`settings_window::request`), the wrong owner. The event itself is T-118's (IN_PROGRESS). Hence the decision point.
3. *Behaviour change of `launched_by_autostart` through delegation*: the shell test pins exact, case-sensitive, any-position matching (`--autostart-later`, `--other`, empty argv). `LaunchArgs::parse` keeps any-position scanning for `--autostart` (argv[0] included, as today), otherwise the delegated fn changes meaning.
4. *Exhaustive match breaks*: `StartCallRecord` makes `tray.rs::on_second_instance`'s match non-exhaustive, so the shell moves in the same commit (Acceptance says so); proven only on the Windows `wip/T-121` run.
5. *Earlier fix of this class*: none; `docs/failures.md` has no argv / launch / second-launch entry and class `call-launch` is new.

**Findings the developer needs.**
- Parse edges the spec leaves open (developer proposes per the approach, reviewer checks against I3): `--call` as last argument, `--call RECORD`, `--call --autostart`, repeated `--call`, `--call=record`. Safe direction: anything naming `--call` that is not exactly `--call record` is `Unknown` (no action), never `Record`.
- `StartCallRecord` wins over the autostart `TrayOnly` row (contract). The Run value never passes `--call`, so no logon start records.
- `startup_action` / `startup_action_after_hotkey` keep their `launched_by_autostart: bool` parameter (the contract changes only `second_launch_action`); `release_launched_by_autostart` keeps working through the delegated shell fn.
- `on_second_instance` returns `Option<Receipt>`: `StartCallRecord` (no-op) and `Unknown` both return `None` until T-128.
- docs/architecture.md (start-order row: "core `second_launch_action`: `--autostart` opens nothing, otherwise `request(Front)`") and docs/decisions/windows-shell.md describe the old table; update in the same commit.
- T-120 overlap: same file, different symbols; no ordering needed. T-128 already depends on T-121.

**Decision point (owner / orchestrator).** Who writes `call_switch_refused reason=unknown_value`. Recommended: T-128 (one writer for first and second launch, inside its posted request; no callback exception; no T-118 dependency here); T-121's Acceptance line 2 then reads "`--call <other>` gives `CallSwitch::Unknown` and `TrayOnly` with no action", and T-128 gains the log line. Alternative: `depends_on: [T-118]` plus an explicit windows-shell.md exception allowing one log write in the callback.

**Size.** Small: one core seam plus two mechanical shell call-site moves. Behaviour settled except the decision point and the parse edges above.
