## Investigation

**Refresh (2026-10-16, HEAD 562687f).** Re-checked against HEAD with grep and file reads (Serena not used). Probe: `scripts/tw-run core -- cargo test -j2 -p voicen-core --lib unbuilt_or_unset_engine_is_engine_not_configured`, which passes, so the placeholder is still live. The root cause and the scope are unchanged. Stale parts, now fixed above:
- **Clock.** T-103 added `crate::clock::instant()` / `since()` (`pub(crate)`), and T-089 bans `Instant::now` / `elapsed`, `SystemTime::elapsed` and tokio `Instant` everywhere else (clippy deny, owned `clippy` lines). The only injectable clock port, `clock::Clock`, is wall time (`SystemTime`), so it cannot drive the idle deadline. The fix is a monotonic port in `crate::clock` whose production impl calls `clock::instant()` (no new allow, no new owned line) and a `test-fakes` fake. Both the 600 s unload and the 120 s abort budget read it, so the tests are deterministic and need no wall-clock ceilings (F-005 / F-013, `docs/decisions/core-tests.md`).
- **Spec contract drift.** `specs/002-local-transcription/contracts/core-traits.md` `ModelResidency::new(.., clock: Arc<dyn Clock>, ..)`, `async fn acquire` and `EngineError` contradict data-model (`Instant`), #42 (sync engines) and `FailureReason`. Fix the contract in the implementing commit.
- **Factory seam.** The docs of pipeline / dictation still say "T-017 wraps `engine_for` in the shell". Under P-011 the `BuiltinLocal` mapping belongs in the one core factory, with the residency injected, not in a shell wrapper.
- **Wording.** `failure.timeout` says "The server did not answer in time", which reads wrong for the built-in engine. This is a product wording point to note in review; it does not block, because the reason stays `Timeout` per FR-019a.

**Size:** core only, one crate, already designed in spec 002 (`design_ref`), so not large. **Recurrence:** none of class `local-engine` in `docs/failures.md`. The related class `os-answer-deadline-race` is honoured by the fake-clock tests.
