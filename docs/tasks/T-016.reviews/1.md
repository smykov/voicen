**What holds** (checked by reading, and against the analysis and design points 1–9):
- *Invariant.* The only rename to the final name is `Job::run` → `transfer` `Ok`. `transfer` returns `Ok` only with `received == size_bytes`: it rejects `>` per chunk and `<` after EOF. The digest must equal the pinned hex, and the file must be synced and closed first. Every other end goes through `remove_part`, then `guard.release()`, then the event. The tests snapshot the directory inside the callback, so "no `.part` at the end event" is checked at the moment of the event.
- *Per-read timeout.* `Client::builder().connect_timeout(connect).timeout(download_no_data)`, with no `RequestBuilder::timeout`. I confirmed the semantics in the reqwest 0.13.5 source: `blocking/response.rs:436-444` wraps each `read` in `wait::timeout` with a fresh deadline. `trickle_longer_than_no_data_succeeds_and_stall_fails` bites a total timeout (≥ 800 ms with no_data = 150 ms).
- *Failure type.* `DownloadFailure` is separate from `FailureReason`, uses the contracts/ipc.md codes, and carries `host[:port]` only (`host_port`). `assert_no_url_in` checks every event for the query, the path mark and `http`.
- *Cancel.* A cancel during a stall maps a read timeout to `Cancelled` (`Job::failed`), and `Cancelled` comes only after the `.part` is removed.
- *Throttle.* It takes an injected `Instant`. The irregular-gap tests pin ≤ 4/s and ≥ 1/s.
- *One at a time.* The slot stays locked across the checks. `SlotGuard` clears it on panic and on a failed spawn.
- *Disk check.* The threshold is size + 1 % (`div_ceil`), `>=`. A probe error lets the download proceed.
- *Store.* "Downloaded" means the final file with the catalog size, read from disk on every call. `cleanup_at_start` removes every `*.part` and leaves other files.
- *Acceptance line 1.* `validate` accepts `builtin_local` through `ModelStore`.
- *Production catalog (Acceptance line 3).* I re-fetched the public metadata (metadata only). `/api/models/ggerganov/whisper.cpp` reports `sha` = `5359861c739e955e79d9a303bcbc70fb988958b1`. The `/tree/<commit>` `lfs.oid`/`lfs.size` of all five files equal `MODELS` exactly. So do the raw LFS pointers of `ggml-small.bin` and `ggml-large-v3-turbo-q5_0.bin`.
- *Decision #50.* `sha2 = "0.10"` adds no crate to the lock (0.10.9 was already there), and THIRD-PARTY-NOTICES already lists it.

**Declared deviations**:
1. `DownloadError::NotInCatalog` / `CannotStart`: accepted in core. `NotInCatalog` cannot happen with the production catalog. `CannotStart` is the honest result of a failed `thread::Builder::spawn`, which the old contract had no variant for. However, the claim "T-044 maps them" is recorded nowhere (#3), and `NotInCatalog` has no test (#6).
2. `send_error`/`body_error` → `pub(crate)`: accepted. It keeps one reqwest-to-facts adapter that drops the URL (P-011, P-009), instead of a second copy in `download.rs`.
3. `NotEnoughDiskSpace{needed}` in raw bytes, with "{needed} bytes" texts: acceptable for the core half. But spec FR-007 wants a size the user can read ("<size> needed"), and moving the formatting to T-045 is recorded nowhere. T-045 will have to change the en/ru texts as well as the param (#3).
4. A failed `.part` removal is ignored and the end event is still emitted. This is a sound choice: the `.part` is never read as a model (the store looks only at the final name), the next `start` truncates it (`File::create`), and `cleanup_at_start` removes it at the next start. Reporting `Failed{DiskError}` instead would turn a user's Cancel into a retry reason. However, it does **not** match the invariant and the contract as written ("every other end closes and deletes `.part` before its end event"). The wording must say best-effort (#4).
