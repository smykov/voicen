## Investigation

Tools: Serena (`get_symbols_overview`, `find_symbol` on `crates/voicen-core/src/call/session.rs`; method lookups inside `impl Writer` returned nothing, so the bodies were read with grep/sed), grep over `tests/call_session.rs`, `docs/failures.md`, the follow-ups and the contract. Nothing built or run.

**Frame.** Observed (r1#2, code read): with subtitles only, a track is lost (and maybe declared silent at 2 s), then record is turned on. The new call has no `TrackLost` warning, no `call_device ... to=none` line or entry, and the dead track is padded as a stalled live track, so `cant_hear_*` can fire for it (contradicts I10 "a lost track never gives it"). Expected: the call is marked lost as if the loss happened at its start (Acceptance 1).

**Hypotheses.**
1. The writer's device state exists only inside `Recording`, and attach does not seed it. Confirmed (code path below).
2. The device thread forgets the loss with record off. Refuted: `DeviceThread` keeps `reopen` pending and retries every 2 s (I8, `subtitles_only_reopens_a_lost_track_silently`); it simply never re-sends `Silent` (`reopen.silent` set once in `DeviceThread::deadlines`).
3. Second path: the same pre-attach device state is lost for other facts. Confirmed, sibling, see Q2: `Captures.mic_id` / `system_id` / `warnings` are set once in `CallSession::spawn` and never updated by a device-thread reopen (only `DeviceLane.endpoint` is), and `open_call` reads them for `create_files` (meta) and `begin_call` (`call_started mic= system=`); a mic reopened on the default under subtitles also drops its `MicChanged` (`Writer::outcome` returns first).
4. Fixed before. Refuted: class `call-session` has no F-entry (`docs/failures.md`, grep); T-126 (subtitles seam) and T-149 (device changes, D6 drop) introduced the code; no earlier patch of this mechanism.

**Code path that leaves the mark.**
- `Writer::handle`: with `rec == None` it returns before `step_of`, so the `TrackEvent::Lost` marks no timeline and opens no `DeviceGap`.
- `Writer::outcome`: `let Some(rec) = self.rec.as_mut() else { return; }` drops `Silent` (and `Reopened`, `MicChanged`) — D6 meant "do not log/store/show", but it also discards the state.
- `Writer::command` `Command::Attach`: installs `recording(files, start, mono_start)`, whose lanes are `Timeline::new` (lost = false), `gap: None`; then `pending.clear()`.
- `Writer::advance`: the dead track has no events for `STALL` (`seen` survives the attach), is not `is_lost()`, so it is advanced 200 ms behind the other track with zeros and `lost = false`; `Writer::apply` -> `Activity::listen(.., false)` counts those seconds; with speech on the other track `Activity::cant_hear` fires after 60 s.
- When the track later reopens, `Writer::outcome` `Reopened` with `gap: None` logs one change with gap 0 ("Record started after the loss", I9 last sentence) — the only path that considered a pre-attach loss.
- Both sub-cases are hit: declared silent before record-on (no to=none ever), and lost < 2 s before record-on (the later `Silent` is logged with `at_ms` = now, the timeline still not lost, so `cant_hear` stays possible; acceptance needs it marked lost from 0).

**Root cause.** See `analysis.root_cause`: device state kept only in the call's lanes and discarded with record off; Attach starts the call from a "both tracks live" state.

**Invariant / seam / approach.** See the front matter. Options considered:
- (A, recommended) Writer-held per-track device state, seeded into the lanes at `Command::Attach`; a silent declaration for the new call queued and emitted from the writer's next lock-taking round, so it follows `call_started` (open_call sends Attach before `begin_call` logs `call_started`). Red tests listed in `analysis.approach`. Risk: line order against `call_started`; meta write at the declaration (existing `device_change` path). Rollback: revert one commit.
- (B) Attach's reply returns the down/silent tracks to the session, and `begin_call` raises `TrackLost` and logs the lines after `call_started`. Removes the cause too, but splits device-line ownership between session and writer (I8/I9 say the writer measures and logs device changes). Not recommended.
- (C) A replay request to the device thread on record-on, which re-sends `Silent`. Needs a second channel into the device thread and races Attach. Not recommended.

**Size.** Small: one seam in `session.rs`, two or three core session tests, I9/I10 text in `docs/decisions/call-session.md` (and the "Built (T-149)" clause in the contract if Q1 changes the gap rule). Q2 is not taken in (decisions #344: follow-up T-248), so the size stays small.

**T-145 overlap.** `origin/task/T-145` changes in core only `CallSession::notice_stopped` and one assertion in `stop_closes_both_files_readable_and_reports_it`; no writer or attach code. No functional conflict; at most a textual merge in `tests/call_session.rs` (different functions).

Gap of the reopen when record started while the track was down: (a) the whole silence of this call, from position 0 to where the new audio lands (cause `reopened` after a to=none, or the trigger's cause otherwise) — consistent with the to=none entry at 0.
