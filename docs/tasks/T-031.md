## Context

Two Low findings from T-005 review round 2:
- **Second path:** `Catalog`, `Catalog::from_json` and `Catalog::text(&str)` are public. Another crate could rebuild a catalog from `i18n/*.json` and render an undeclared `&str` id, skipping `MessageId`. There is no outside user today. Either narrow them to `pub(crate)` (the conformance and parity tests live in the module), or record the case in the "Don't" line of `docs/decisions/i18n.md` and in `core-traits.md`.
- **Docs drift:** spec 004 `plan.md:111` and `research.md:57` still describe the vitest scan of literal ids that `svelte-check` replaced; `tasks.md:43` has a stray comma before "(unknown literal ids".

## Acceptance

- [ ] Outside `voicen_core::i18n` the embedded catalog can be rendered only through `text(lang, MessageId, args)`. Either `Catalog` is not reachable from other crates, or the decision record names the remaining path explicitly
- [ ] spec 004 plan, research and tasks describe `svelte-check` (`MessageId = keyof typeof en`) as the check for unknown literal UI ids
- [ ] Failure branch: if `Catalog` is narrowed, a use from outside the crate fails to compile. Verified by reading the visibility, since there is no outside caller, and by the existing in-module tests staying green
- [ ] Test that fails without the change: `none — visibility and docs; existing i18n tests stay green`

## Investigation

**Tools.** Serena indexes TypeScript only, so for Rust and Markdown I used grep and file reads over `crates/`, `src-tauri/` (src and tests), `specs/004-settings-and-first-run/` and `docs/`. There is no `benches/` directory. context7 was not needed because no library API is involved.

**Callers.** No code outside `crates/voicen-core/src/i18n.rs` uses `Catalog`, its methods or its problem types, and that includes the new T-030 shell code in `src-tauri/src`. Other crates use only `voicen_core::i18n::UiLanguage` (`crates/voicen-core/tests/settings_apply.rs:12`, `src-tauri/tests/settings_ipc.rs:20`). So narrowing changes no integration test. The only in-crate users are the module's `embedded()`/`text` and its `mod tests`.

**Narrow vs document.** I chose to narrow. "Document the path" would leave a public bypass that holds only by convention, and P-014 prefers structure to convention (the same reasoning that made `embedded()` private in T-005 round 1). Pitfall: `make check` runs `cargo clippy --all-targets -D warnings`. Once `Catalog` is crate-private, the checkers that only tests use become dead code in the non-test lib build: `parity_problems`, `missing_ids`, `CatalogProblem`, `ProblemKind`, `LANGS` and `placeholder_names`. Put them under `#[cfg(test)]`. The alternative, `#[cfg_attr(not(test), allow(dead_code))]`, keeps them compiled but hides real dead code. `tokens`, `Token::Stray` and `render` are still used by `Catalog::text`. Once `parity_problems` is under `cfg(test)`, the module doc's intra-doc link at `i18n.rs:12` would point at nothing, so change it to plain code.

**Failure branch.** A crate-private item named from another crate is a compile error (E0603). Reading the visibility proves it: no outside caller exists to compile against, and the task says no new test is needed.

**Recurrence.** None. `docs/failures.md` has only F-001 (ci-toolchain). This is the residual of T-005 review round 1 #1, closed at the type level instead of the accessor. It is not a new instance of a recorded class.

**Out of scope here.** The `## Notes` items (the spec 006 wording from T-029 and the `MESSAGE_IDS` count test and wording from T-005 validation) are not in Acceptance. The orchestrator decides whether to add them.
