## Context

Owner decision #256 (OQ-84, option a): the call-indicator page (T-131) renders its own labels (`indicator.recording`, `indicator.stop`, `indicator.dismiss`) with `t()` and must get the UI language from the state it receives, as the overlay does with `OverlayPayload.lang`. Core holds the call's language in `ActiveCall.lang` (`crates/voicen-core/src/call/session.rs`) and uses it only for Rust-rendered texts. Area core; seams named in T-131's analysis (option A): `crates/voicen-core/src/call/indicator.rs` (`IndicatorState.lang`; `idle()` and `recording()` take it), `crates/voicen-core/src/call/session.rs` (the call's language while recording, the settings language at stop/idle), `crates/voicen-core/tests/call_indicator_wire.rs` and the regenerated `e2e/fixtures/call-indicator-wire.json`, `specs/007-call-mode-record/contracts/ipc.md`. T-131 depends on this task.

## Acceptance

- [ ] `IndicatorState` serialises a `lang` key (`en` / `ru`, the `UiLanguage` wire form) in every state, idle included
- [ ] While a call records, `lang` is the call's language, the same one the Rust-rendered reminder and warnings use; a settings language change during the call does not change it
- [ ] The idle state after stop carries the current settings language
- [ ] `e2e/fixtures/call-indicator-wire.json` is regenerated by its test and holds `_en` and `_ru` states with the matching `lang`; `contracts/ipc.md` names the field
- [ ] Failure branch: a state built with a language other than the call's (e.g. the settings language read mid-call) fails a core test

## Investigation

Tools: Serena `get_symbols_overview` on `call/indicator.rs`; grep (`IndicatorState`, `call::indicator`, `set_state`, `lang`) over `crates/`, `src-tauri/`, `src/`, `e2e/`, `specs/007-call-mode-record/` for references, since this is a small, string-heavy search. An empty result is not proof of absence. It covers only the files grep reached.

**Frame.** Decision #256 (OQ-84, option a) says the call-indicator page (T-131) renders `indicator.recording` / `indicator.stop` / `indicator.dismiss` with `t()` and needs the language from the state it receives, as the overlay does. Today `IndicatorState` carries no language. This is a missing field, not a defect.

**Where the state is built and emitted.**
- `call::indicator::IndicatorState::idle()` and `IndicatorState::recording(lang, reminder_visible, warnings)` are the only constructors. `recording` already renders the reminder and headphones hint in `lang`, and the warnings come in rendered by `WarningList::items(lang)`.
- `session::Call::state()` is the only builder of a recording state, and it uses `Call.lang` for both the texts and the warnings. It has five publishers, all under the session lock (I4): `CallSession::begin_call`, `CallSession::reminder_tick`, `CallSession::dismiss_warning`, the low-disk branch of the free-space poll, and the writer-side pending-warning flush (`self.shared.indicator.set_state(&call.state())`). They all go through `Call::state()`, so adding the field there covers every one of them.
- `CallSession::finish` publishes `IndicatorState::idle()` after a stop. This is the one place that needs the settings language (`self.deps.settings.snapshot().ui_language`). The snapshot is an `Arc` clone and does not block, so it is safe inside the lock.
- Shell: no production `CallIndicator` exists yet. The window and the `call_indicator_state` reply are T-130. `src-tauri/tests/call_capture.rs` `Indicator::set_state` ignores its argument, so no shell change is needed. Handoff to T-130: `call_indicator_state` must return the last state the session sent, not build its own, or the "one producer" rule of #256 breaks.
- Not to confuse: `recording::IndicatorState` (`crates/voicen-core/src/recording/mod.rs`, the dictation tray/overlay state) is a different type and is out of scope.

**How the call's language is chosen.** The task text says `ActiveCall.lang`. In the code it is the private `session::Call.lang`. `CallSession` takes one `settings` snapshot at record-on, and that snapshot feeds both `create_files` (`NewCall.lang` -> meta) and `begin_call` (`Call.lang = settings.ui_language`). Nothing reassigns it during the call. So "the call's language" is the start snapshot's `ui_language`, the same value the Rust-rendered reminder and warnings use.

**Wire form.** `i18n::UiLanguage` derives `Serialize` with `rename_all = "lowercase"`, which gives `"en"` / `"ru"`. `overlay::OverlayPayload.lang: UiLanguage` uses this form through its own hand-written serializer. `IndicatorState` derives `Serialize` with `rename_all = "camelCase"`, so a `pub lang: UiLanguage` field serialises as `"lang": "en"` with no custom code. That is the same wire form as `OverlayPayload.lang`.

**Wire test and fixture.** `tests/call_indicator_wire.rs` `e2e_call_indicator_wire_fixture_matches_core` compares the key sets both ways and prints "copy this value" on a mismatch. To regenerate the fixture, run the test and copy the printed values into the file.
- Replace the `idle` case with `idle_en` / `idle_ru`.
- The existing `recording_*_en/_ru` and `warnings_en/_ru` cases get `lang` automatically.
- Update the fixture's `_format` text to match.
- Today no e2e spec reads the fixture (grep of `e2e/`, `src/` for `call-indicator-wire` found nothing), so renaming `idle` breaks no consumer. The module doc comment of the wire test, which lists the API, also needs updating.

**contracts/ipc.md.** The `IndicatorState` interface in the TypeScript block gains `lang: "en" | "ru"` (the UI language of the call; idle: the settings language).

**How to pin the failure-branch acceptance.** `call_support::FakePort::edit` changes the settings snapshot mid-call, and `FakeIndicator::states()` records every published state. Proposed core test in `tests/call_session.rs`:
1. Settings `ui_language = En`, a non-loopback provider so a warning is listed, reminder on.
2. Start a record and assert the first state has `lang == En`.
3. `rig.port.edit(|s| s.ui_language = UiLanguage::Ru)`.
4. Force republishes: `dismiss_warning(id)`, and advance the fake mono clock past 10 s and `tick()` to end the reminder.
5. Assert every state before the stop has `lang == En` and English texts.
6. Stop and assert `states().last() == Some(&IndicatorState::idle(UiLanguage::Ru))`.

What the test catches:
- A mutant that builds a recording state from the settings snapshot (the "settings language read mid-call" of the Acceptance) fails step 5.
- A mutant that gives `idle` a fixed or call language fails step 6.
- A unit test in `indicator.rs` pins `recording(lang, ..).lang == lang` for both languages, so the field cannot drift from the texts.

Also existing callers: `tests/call_session.rs` (`Some(&IndicatorState::idle())` in the stop test) changes to `idle(<the rig's settings language>)`.

**Hypotheses checked.**
- A second path builds the state: refuted. All recording states go through `Call::state()`, and the only idle state is in `finish` (grep of `session.rs`).
- This class was fixed before: not applicable, because this is new behaviour. The overlay precedent (`OverlayPayload.lang`) is the model to follow.
- The shell builds its own state: no shell producer exists yet (T-130).

**Options.**
- **A (recommended, #256):** add a field on `IndicatorState`, set by the constructors, as described above.
- **B:** wrap the state in `{lang, state}` the way the overlay wire is shaped. This changes every consumer's shape and gives nothing for a page with one state type. Rejected.

No guard change is needed (nothing under `scripts/ci/`, `Makefile`, `*.mk`), so `decides_on` stays empty.
