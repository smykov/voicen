## Context

Process review 2026-10-09 (`tw-context.py --json`): 7 of 90 code reads over 13 sessions went through Serena, every one of them from the main session. The subagent roles read with built-in tools only: developer-core 34, problem-investigator 20, task-validator 16, test-writer-core 8. Svelte (16 files) is not indexed, because the ui area runs in Docker and the host has no Svelte language server.

## Acceptance

- [ ] Each role file in `.claude/agents/` that reads code names the context tool in its tools and first step, and a subagent session can call it (shown by one run whose journal records a Serena call from a subagent)
- [ ] Svelte is indexed by Serena on the host, or `docs/decisions/` records why not and what the roles use instead
- [ ] Failure branch: when the context tool is unavailable in a session, the role instruction says to fall back to built-in reads, not to stop

## Investigation

2026-10-18, problem-investigator. Serena tools were not available in this session (offered: Read, Bash, Edit), which is itself a reproduction of the defect. Context gathered with grep, file reads and python over `.claude/agents/`, `.teamwright/logs/tools.jsonl`, `.teamwright/installed.json`, `.mcp.json`, `.claude/settings*.json`, `.serena/project.yml`, the teamwright 0.8.2 kit under `~/.claude/plugins/cache/teamwright/teamwright/0.8.2/` (templates, `providers/context/serena.md`, the installer's plan logic) and the installed Serena package (`solidlsp`, `serena/resources/config/contexts/claude-code.yml`). Context7 was not reachable either, so the Claude Code `tools:` semantics come from the `plugin-dev` agent-development skill in the official plugin marketplace ("If omitted, agent has access to all tools") plus the empirical journal, not from memory.

**Frame.** Observed: 0 MCP calls from any subagent over 13 sessions (journal: 14 `mcp__serena__*` events, all from the main session on 2026-10-05). Expected: roles that read code call Serena first, as their rendered Tools block says. Svelte (16 tracked `.svelte` files) is not indexed.

**Hypotheses.**
1. *The subagent allowlist excludes MCP tools* - confirmed. Every role file has `tools: Read, Grep, Glob, Bash, Edit[, Write]` (front matter), identical to the kit templates. The server is configured and approved (`.mcp.json`, `enabledMcpjsonServers`), the main session used it, and this subagent session got no `mcp__*` tool at all. The tool set offered here matches the role's `tools:` line.
2. *The role files do not mention Serena* - refuted. All 7 code-reading roles carry the rendered Tools block ("Before reading files to understand code, ask Serena") and a "Gather context with the configured tools" step.
3. *The MCP server is not approved for the project* - refuted. `.claude/settings.local.json` enables serena, context7 and playwright, and the main session called Serena.
4. *A second path: other MCP providers have the same gap* - confirmed. context7 and Playwright MCP also have 0 subagent calls, through the same allowlist. The same edit fixes them, and the invariant covers them.
5. *This class was fixed before* - no. `docs/failures.md` (F-001..F-019) has no tool, MCP or role-file entry, and no task has `class: context-tool-coverage` besides this one. The fallback did report it five times (T-019, T-021, T-076, T-078, T-092 Notes: "Serena tools were not available in this session"). Those reports landed in task Notes that nobody aggregates, so the defect stayed silent until the process review counted it. Not a recurrence: first task of the class.

**Svelte.** Decision #72 set Serena's language servers to typescript, rust and markdown. `.serena/project.yml` is host-local (decision #16) and lists exactly those, and `.serena/cache/` has no svelte index. The installed Serena (2.0.0.dev0) supports `svelte` (`solidlsp/language_servers/svelte_language_server.py`). It npm-installs `svelte-language-server` 0.18.0 with TypeScript into `~/.serena/language_servers`, and needs node and npm. The host has node 20. The task's premise "the host has no Svelte language server" is true today, but Serena can install one itself. That is a host install needing consent (requirements, "Installs needing consent" row, r2#13), so it is an owner decision. Serena gives svelte lower priority than typescript for `.ts` files, so adding it should not take `.ts` away from the TypeScript server. The developer checks this with `get_symbols_overview` on one `.svelte` file and one `.ts` file after indexing.

**Kit ownership.** The 9 role files are installed by teamwright (`.teamwright/installed.json`). The installer re-renders only the text between the `teamwright:tools` markers in a file edited since install, and keeps the rest (`op: tools`, `keep_manifest`). `code-reviewer.md` and `task-validator.md` already differ from their install hashes (decisions #32, #70). So a front-matter edit survives kit upgrades. Its cost: kit changes to the body of those files stop arriving automatically, as for the two files already edited. Precedent says local edits to role files go through an owner decision row plus "carry into teamwright". The kit defect itself (templates render the Tools text but never the allowlist the text depends on) is a teamwright feedback item for every project that uses an MCP provider.

**Conflict to keep out.** Serena's `claude-code` context prompt tells agents "Edit -> FORBIDDEN. Use replace_symbol_body". That contradicts the Tools block ("Edit with the normal Edit/Write tools ... the gates see only Edit/Write"). Listing only Serena's read and navigation tools in `tools:` makes the edit tools unavailable to subagents, so the conflict cannot bite there. This is why option B (omit `tools:`) is rejected. Risk for the developer role: Claude Code's Edit refuses a file not read with Read. A developer who navigated with Serena must Read the target range before editing. The Tools block already routes edits through Edit/Write.

**Unverified, to be settled by the red run.** (a) Whether a subagent with an explicit allowlist also needs `ToolSearch` to load deferred MCP tools. This session had neither. (b) Whether `mcp__serena__*` wildcards are accepted in `tools:`. Use explicit names unless the run proves the wildcard. The Acceptance run (one subagent session whose journal shows `agent_type=<role>` with `tool=mcp__serena__*`) is the proof for both.

**Size.** Small, not a Spec Kit item. There is one seam (the role allowlists) plus one host-local config line, with no product behaviour. It needs two owner decisions before IN_PROGRESS: (1) editing kit-managed role files locally (decision row, like #32/#70), plus the teamwright feedback draft; (2) S1/S2/S3 for Svelte (host npm install by Serena vs Docker wrapper vs recorded "why not").

**Recommended exit**: not an rca task. Exit-equivalent is (a) code/config in the role allowlists, plus the upstream kit feedback.
