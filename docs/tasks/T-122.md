**Findings beyond the acceptance.**
1. *Windows compile break that `make check` cannot see.* Adding a `TrayState` variant breaks `src-tauri/tests/tray.rs::all_states` (wildcard-free match). Adding `TrayAction` variants breaks `src-tauri/src/tray.rs::on_menu_event` (exhaustive `Option<TrayAction>` match). Changing `menu`'s signature or return type breaks `build_menu` and `tests/tray.rs::expected`. tasks.md lists G08 as core-only. T-122 must carry a shell compile follow-through and cite a green `wip/T-122` run (P-016) whatever D1 decides.
2. *The catalog has no tooltip for the new state.* `tooltip()` must map every state, and contracts/ipc.md lists only `tray.call`, `tray.call.record`, `tray.call.stop` and `tray.calls`.
3. *The input is a bool, not `CallState`.* T-118's `CallState` is the stored meta.json lifecycle (`recording`, `ready-to-transcribe`, ...). The tray reads CallSession's `record: bool` (data-model), so T-122 does not need T-118. It needs the catalog ids from T-119 (G05), unless it adds them itself.
4. *Where the two inputs meet* is T-128's: `TrayPart::set_tray` today stores the dictation session's one state. T-122 only supplies the pure `shown` function. The FR-006 Error is the dictation `Error` only: call warnings go to the indicator and toasts (FR-006 second sentence), never to the tray.
