## Context

FR-17, FR-24 (60 s), v4 FR-13 (own URL, optional model and key). Built on T-040: the `LocalServer` arm in core `engine_for` reusing `OpenAiCompatibleEngine` with `Timeouts::local_server` (no factory in src-tauri; specs/002 T031) and its `authorization()` rule for the optional key — no second `bearer_auth`.

## Acceptance

- [ ] Request to `<URL>/audio/transcriptions` without `Authorization` when no key is set
- [ ] Failure branch: server down → "cannot reach localhost:8000" and audio kept; no answer in 60 s → "timeout" — verified by core tests against a mock server
- [ ] Test that fails without the change: `crates/voicen-core local-server tests`

## Investigation

Tools: Serena was not connected in this session (no `mcp__serena__*` tools), so I used grep and file reads over `crates/voicen-core`, `src-tauri/src`, `src/`, `e2e/`, `specs/001…`, `specs/002…` and `docs/`. No library API is new here: only reqwest calls T-040 already uses (`RequestBuilder::timeout`, `multipart::Form::text`), so context7 was not needed.

**Frame.** Selecting engine = local server today gives `EngineNotConfigured` on every dictation (`engine_for`, `engine/mod.rs:66`). Expected (spec 002 US3): the request goes to `<URL>/audio/transcriptions` with `model` only when set and `Authorization` only when a key is stored in the `local-server` slot. A refused or unconnectable server gives `CannotReach{host:port}` and keeps the audio. No answer within 60 s gives `Timeout`. 401/403 gives `InvalidApiKey`.

**What already exists (no change needed):**
- Settings: `LocalServerSettings { base_url, model }`, defaults `http://localhost:8000/v1` / `""`, `FieldId::EngineLocalServer{BaseUrl,Model,Key}`, save-time normalize (URL normalized, model trimmed), http-remote warning (`service::save_warnings`).
- Key: `KeySlot::LocalServer` → `Voicen/local-server`, optional per decision #28(b) (an empty `Replace` is no error and is never stored).
- `Timeouts::local_server` = 60 s, already pinned by `timeouts::tests::defaults_are_fr24`; connect 5 s.
- Client: `OpenAiCompatibleEngine::authorization()` already omits `Authorization` for `None` or an empty key. `transcription_url` and `host_port` already give `localhost:8000`. `failure::classify` already maps refused/connect-timeout → `CannotReach`, timeout → `Timeout`, 401/403 → `InvalidApiKey`.
- Pipeline: `Pipeline` calls `engine_for` per job from the press-time `Arc<Settings>` (decision #47(1)), and retryable reasons keep the pending audio (T-001). So "audio kept" and "no restart" need no new code.
- diag: `EngineTag::from_kind("local_server")` exists.
- UI: `Engine.svelte` renders the local-server URL, model and `KeyField slot="local_server"`, and the e2e mocks carry the wire shape.
- Shell: `src-tauri` reaches engines only through core `engine_for` (`src-tauri/src/dictation.rs`, `lib.rs` docs). The Credential Manager store already serves every `KeySlot`.

**What is missing (all in `crates/voicen-core/src/engine`):**
1. `engine_for` has no `LocalServer` arm (`mod.rs:66`).
2. `model` is always sent: `OpenAiCompatibleEngine.model: String`, `multipart_body` `.text("model", …)` with no condition (`openai.rs:84`), and `body_capacity` takes `&str`. Spec 002 T030 and core-traits "Required of 001's client: optional model (omit the form field)".
3. The request deadline is always `req.timeouts.api_transcription` (`openai.rs:130`). Spec 002 needs `local_server` (60 s). The T-040 Investigation already said: "per-request `.timeout` = `api_transcription`, or `local_server` for T-018's role".
4. `kind()` is always `"api"` (`openai.rs:165`), so pipeline/diag would tag local-server jobs as `api`.

**Hypotheses.**
- H1, the client needs only configuration: refuted by gaps 2–4 above.
- H2, a second path handles the concern: none found. There is no other HTTP transcription client (grep for `reqwest`/`Client::builder` in core: `engine/openai.rs` and the model downloader only). There is no engine factory in `src-tauri` (grep for `engine_for`, `OpenAiCompatibleEngine` over `src-tauri/src`: doc references only). T-046 (connection test) will go through this arm (T-013 analysis: "LocalServer comes only through T-018"), so the role/Option-model shape must be usable from there and must not be duplicated.
- H3, this class was fixed before: no. `docs/failures.md` F-001..F-011 hold no `transcription-pipeline` class entry. Test-side rules from F-004/F-005 do apply (see below).
- H4, Windows-specific work is needed: no. The key read goes through the `CredentialStore` trait, whose Windows implementation and its CI test already cover all slots. Nothing here falls under OQ-14.

**Root cause.** See the analysis block: the factory arm is missing, and the shared client hard-codes three API-only choices (model always sent, the 30 s deadline, kind `api`).

**Invariant / seam.** See the analysis block. The deadline is chosen inside the engine from its role, not by the caller. `TranscribeRequest.timeouts` stays the single source of durations (the engine reads `timeouts.local_server` or `timeouts.api_transcription`), and the pipeline keeps passing `Timeouts` as is.

**Options.**
- **A (recommended).** In `openai.rs`, add a private `enum Endpoint { Api, LocalServer }` stored in the engine. `kind()` returns `"api"` / `"local_server"`. `fn request_timeout(&self, t: &Timeouts)` picks `api_transcription` / `local_server`. `model: Option<String>`, and `None` skips the part (and its `body_capacity` share). Keep `new(base_url, model, key)` for the API (`Some(model)`, behaviour unchanged, so the 3 call sites stay), and add `OpenAiCompatibleEngine::local_server(base_url, model: Option<String>, key)`. In `engine/mod.rs` add the arm: `check_base_url(&settings.local_server.base_url)` (Err → `EngineNotConfigured`, no key read) → `creds.read(KeySlot::LocalServer)` once (Err → `KeyStoreUnavailable`; `Ok(None)` → no header) → `model = Some(trimmed)` unless trimmed is empty. The trim is in the factory because a hand-edited file bypasses the save-time normalize, the same reason `check_base_url` sits in the factory.
  - It removes the cause: one client, three role-derived choices, one factory arm.
  - Red → green: `tests/local_server.rs` (no-key request has no `Authorization` and no `model` part; key from the `local-server` slot sent as bearer; model part only when set; a request that outlives an injected `api_transcription` but not `local_server` succeeds, and one that outlives `local_server` gives `Timeout`, so swapping the fields bites; a refused address gives `CannotReach{"127.0.0.1:1"}`; 401/403 gives `InvalidApiKey`), plus engine unit tests.
  - Risk: low, because the API path keeps `Some(model)` and its role.
  - Rollback: revert the commit, and the arm goes back to `EngineNotConfigured`.
- **B.** A `LocalServerEngine` wrapper that clones the request with `api_transcription = local_server` and delegates. It adds a second `Engine` type, makes a caller rewrite a role field (breaking "durations only from Timeouts per role"), and cannot omit `model`. Rejected.
- **C.** Spec 002 T030's `local_server_endpoint` / `Endpoint` struct in a new `engines/local_server.rs`. This predates decisions #44/T-040 (no `Endpoint` type exists, and the path is `engine/`, not `engines/`). It is a spec drift to correct, not a design to follow.

**Tests and their constraints.**
- Refused cases use `common::refused_addr()` / `common::refused_timeouts()` (F-004, F-005; `docs/decisions/core-tests.md`), never a released port or a sub-budget whole-request deadline.
- Timeout cases use a slow server (the `partial_body_server` / wiremock delay pattern in `openai_client.rs`).
- The engine runs on a plain thread outside the tokio runtime (decision #42).
- The spec T028 line "connection not accepted in time → cannot reach (injected connect timeout)" has no deterministic local fixture: a full-backlog listener needs socket2, and TEST-NET addresses may give `HostUnreachable` → `NetworkUnavailable` inside a Docker netns. The mapping connect+timeout → `CannotReach` is shared and already pinned by `failure::tests`. The test-writer should either cover it there or say why the integration case is omitted, not add a flaky one.
- T029 ("no restart") is covered by building `engine_for` from the snapshot that `SettingsService` returns after a save of URL/model/key.
- The production 5 s / 60 s values are already asserted in `timeouts::tests`; T028's last bullet needs at most one assertion that the engine reads the `local_server` field (the swap test above).

**Docs to update in the same commit:**
- `engine/mod.rs` and `engine/openai.rs` module docs ("LocalServer (until T-018)", kind "later").
- `specs/001-dictation-via-api/contracts/core-traits.md` (the `engine_for` arm list).
- `specs/001-dictation-via-api/contracts/openai-transcription.md` (`model` omitted when the local model is empty; the timeout row "> 30 s" → "30 s API / 60 s local server").
- `specs/002-local-transcription/tasks.md` T030 (path/`Endpoint` drift → this design) and `contracts/core-traits.md` "Local server" section.

**Size: small.** One seam (`crates/voicen-core/src/engine`), settled behaviour (spec 002 US3 plus contracts), about 10 red tests, no change in `src-tauri`, `src/` or CI, no new dependency. `surface: none`, `deploys: false` stay correct.

**Open product question: none blocking.** One non-owner-level choice, settled here: a whitespace-only stored local model counts as unset (trimmed in the factory), matching the save-time normalize.

**Recurrence:** none (class `transcription-pipeline` has no F-entry; `recurrence_of: []` stays).

## Tests

Written by the test-writer before the implementation. Serena was not connected, so I used grep and file reads. Every integration test gets its engine from `engine_for` with `EngineKind::LocalServer`, which is the path the pipeline and the shell take, so the tests compile against today's API and do not name the new constructor. The settings keep a valid API section and the API slot holds a different key (`sk-test-API-OTHER`), so an arm that builds from the API side shows up.

**Characterization (green now):** `engine::openai::tests::default_local_server_url_names_localhost_8000` checks that the default local URL passes the URL rule and that its `CannotReach` host is `localhost:8000`.

**Red tests: `crates/voicen-core/tests/local_server.rs`** (wiremock; engine on a std thread per decision #42; refused cases use `refused_addr()`/`refused_timeouts()`; timeout cases use a delayed mock):
- `no_key_request_goes_to_url_audio_transcriptions_without_authorization` (Acceptance 1): POST to `/v1/audio/transcriptions` with no `Authorization`. Parts are exactly `file` (the WAV) and `response_format=json`, with no `model` part for an empty model. Only the local-server slot is read, and only once.
- `whitespace_only_model_omits_model_part`: a whitespace-only model counts as unset.
- `set_model_is_sent_trimmed`: a set model is sent trimmed. The API model is never used.
- `stored_local_server_key_is_sent_as_bearer`: the bearer is `Bearer sk-test-LOCAL`, never the API slot's key.
- `empty_stored_key_sends_no_authorization`: an empty key goes through the existing `authorization()` rule.
- `request_deadline_is_local_server_not_api_transcription`: a reply after 1.5 s succeeds with api_transcription = 300 ms and local_server = 5 s.
- `no_answer_within_local_server_deadline_is_timeout` (Acceptance 2, "no answer in 60 s → timeout"): with a 5 s delay and local_server = 300 ms, the result is `Timeout` in under 3 s.
- `refused_server_is_cannot_reach_host_port` (Acceptance 2, "server down"): the result is `CannotReach{"127.0.0.1:1"}`.
- `status_401_and_403_are_invalid_api_key`: the result is `InvalidApiKey` after one request.
- `server_down_is_cannot_reach_and_audio_kept` (Acceptance 2, production pipeline): the job fails with `CannotReach`. The pending recording keeps the same audio, nothing is copied, and the `JobFinished` engine is `"local_server"`.
- `saved_local_server_settings_reach_the_next_job_without_restart` (spec 002 T029): URL, model and key are saved through the real `SettingsService`. The next job delivers the text with the saved URL, model and Bearer, tagged `"local_server"`.

**Red tests: `engine::tests` (`crates/voicen-core/src/engine/mod.rs`):**
- `local_server_engine_reads_only_local_server_slot_once`: kind is `"local_server"` and the calls are `[Read LocalServer]`.
- `local_server_default_settings_build_without_key_or_model`: the defaults (no key, empty model) build an engine.
- `local_server_key_store_error_is_key_store_unavailable`: a read `Err` gives `KeyStoreUnavailable` after one read.
- `local_server_bad_stored_base_url_is_engine_not_configured` is a guard. It passes today only because the arm is missing, and it bites once the arm exists (see W8).
- `unbuilt_or_unset_engine_is_engine_not_configured`: `LocalServer` was removed from its kinds (the contract changed with T-018). `BuiltinLocal` and `None` are still checked.

**Not covered by an integration test:** "connection not accepted in time → cannot reach". There is no deterministic local fixture for it (T-018 Investigation). The mapping connect+timeout → `CannotReach` is already covered by `failure::tests` (row "192.0.2.1 connect_timeout: connect + timeout").

**Red run:** `scripts/tw-run core -- cargo test -p voicen-core --test local_server` gave 11 failed and 4 passed. The 4 passes are the `refused_addr_tests` probes. Every failure is `EngineNotConfigured` from the missing arm. `scripts/tw-run core -- cargo test -p voicen-core engine::` gave 3 failed and 13 passed: the missing arm gives `EngineNotConfigured`, not an engine or `KeyStoreUnavailable`. fmt and clippy (`--all-targets -D warnings`) are clean.

**Bite check** (throwaway worktree). I first wrote a reference implementation with a private role, `Option` model, a `local_server` constructor and the factory arm. All 15 integration tests and all 16 `engine::` tests passed against it. Each wrong implementation below changes one thing in that reference:
- W1, deadline = `api_transcription`: `request_deadline_is_local_server_not_api_transcription` and `no_answer_within_local_server_deadline_is_timeout` went red.
- W2, deadline = `Timeouts::default().local_server` (ignores the request): `no_answer_within_local_server_deadline_is_timeout` went red.
- W3, `kind()` stays `"api"`: `server_down_is_cannot_reach_and_audio_kept`, `saved_local_server_settings_reach_the_next_job_without_restart`, `local_server_engine_reads_only_local_server_slot_once` and `local_server_default_settings_build_without_key_or_model` went red.
- W4, reads the `TranscriptionApi` slot: `no_key_request_…`, `stored_local_server_key_is_sent_as_bearer`, `empty_stored_key_…`, `saved_local_server_settings_…` and three `engine::tests` went red.
- W5, model not trimmed (only `""` counts as unset): `whitespace_only_model_omits_model_part` and `set_model_is_sent_trimmed` went red.
- W6, model always sent: `no_key_request_…` and `whitespace_only_model_omits_model_part` went red.
- W7, key-store `Err` treated as no key: `local_server_key_store_error_is_key_store_unavailable` went red.
- W8, key read before `check_base_url`: `local_server_bad_stored_base_url_is_engine_not_configured` went red.
