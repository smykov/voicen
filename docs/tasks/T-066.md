## Context

Opened by the T-061 review, round 5 (`docs/tasks/T-061.reviews/5.md`, verdict `REJECT_RECURRENCE`).

Class `windows-premise-unchecked-on-host` (`docs/failures.md`): a Windows-only premise is written on the Linux dev host, where it cannot be run (no Windows, and for pwsh/C# not even parsed). It is first checked by a push to `main` that triggers the Windows CI job. Logged entries:

- F-007: T-061 `purge_credentials.rs` DOMAIN_PASSWORD plant refused by `CredWriteW` (verify 1 and verify 2, two CI rounds).
- F-009: T-061 ci.yml step 18 `cmdkey` plant/premise failed (run 37444780779) before `voicen.exe` ran.

Related, with the same outer mechanism and listed in the class row: F-002 (shell test exes without the manifest, first run on CI), F-005 (Windows refused-connect timing), F-008 (helper-window predicate, the install smoke only).

Each entry was fixed locally, and every local fix is again Windows code first run by a CI push. The T-061 verify-3 fix (ac7a558) is new P/Invoke C# plus pwsh that was not parsed on the host. Its `make check` tripwire refuses one tool name (`cmdkey`). The class row's proposal ("a Windows-premise probe on a throwaway CI branch before a Windows fixture is committed") has been waiting for the owner since F-007 and was not applied.

T-061 is absorbed here (`absorbed_by: T-066` once the orchestrator defers it). Its ac7a558 patch stays in the tree as a **temporary workaround** that points to this task (see the review record).
