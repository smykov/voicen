## Verdict rationale

The design follows the analysis. The run lives in `+page.svelte` and survives a tab round trip. The generation advances on an unprevented close (the new `return` keeps "keep editing" alive), on discard before `destroyWindow`, and on unmount. Both the result and the rejection branches check it, and `testPending` clears only when the shell answers. Every requirement the caller asked about holds:

- **Generation guard:** tested both ways. The dirty-discard and clean-close cases go red without `dropTest`, and the keep-editing case goes red if it is called unconditionally.
- **No key or transcript in logs or the DOM:** the diff adds no `console` call. `Engine.svelte` renders only `t(...)` texts. The key goes only into `invoke`, and the e2e cases assert that the typed fake key never appears in `body` text.
- **Mapping:** `testMessage` is an exhaustive switch with a declared return type and no default arm, so svelte-check refuses a new kind (TS2366). Its completeness is also checked over the core-pinned fixture, and core's pin now uses a wildcard-free `match`.
- **i18n:** all four `settings.test_connection.*` ids exist in en and ru with matching `{ms}`, and the reused `failure.*` ids exist.
- **Docs:** architecture.md, i18n.md, settings-ui.md § T/§ C and contracts/ipc.md cite symbols, not lines, and match the code (P-018).
- **Wire:** the TS types match `connection_test.rs`: kinds, `latency_ms`, `host`, `status`, `errors`, `KeyEdit` `Clear`, and `TimeoutSettings`. The `{ request }` argument name matches the shell command.
- **Tests:** the unit and e2e tests bite on every mutant listed under ## Tests, as far as I can tell by reading.

One documented guarantee has no test that bites: the label list of an `invalid` result's fields that have no control (#1). The project's blocking threshold is Medium, and that gap needs a test change, so this is REQUEST_CHANGES. Findings #2–#4 are Low and do not block on their own.
