## Context

Found 2026-11-17 (owner's "Да" to opening this task): `/teamwright:sprint` started Issues #16–#20 with `tw-sprint.py issues … --start`, which only sets the `teamwright` label; `.github/workflows/teamwright-next.yml` triggers only on `workflow_dispatch`, so no chain ran for ~2 h until the orchestrator dispatched hop 0 by hand (`gh workflow run teamwright-next.yml --ref main -f task_id=<ID> -f issue=<N> -f hop=0`, runs 44069664481…44069687676). Earlier chains were also started by a manual dispatch from the owner's account. The kit's sprint/blockers commands assume the label starts (and, for `CODE_COMPLETE`, re-starts for verify) the chain.

Guard paths: the contour workflows and their byte-pinned heads (`scripts/ci/contour-heads/teamwright-next.yml`) change in pairs; `checker: true`, `analysis.decides_on` (P-020); release-guard rules (write token only in the named contour files) stay as they are.

Also decide here (or record as an OQ): a chain whose task is already `CODE_COMPLETE` with no new commits ends with "pull request create failed: No commits between main and task/<ID>" (T-182, Issue #16) instead of running verify; the dispatcher should route it to verify or end with a clear message.

## Acceptance

- [ ] Adding the `teamwright` label to an open Issue whose title starts with `T-NNN:` dispatches hop 0 for that task with the Issue number; a label on any other Issue, or another label, starts nothing.
- [ ] A label event and a manual dispatch for the same task do not run two chains at once (the per-task concurrency group holds).
- [ ] A `CODE_COMPLETE` task with nothing to merge goes to verify (or ends with an explicit "verify locally" message), not a GraphQL error.
- [ ] Failure branch: an Issue with a malformed title is labelled → no agent run, one comment on the Issue saying why; verified by the guard test or a fixture of the dispatcher's title parser.
