## Context

Follow-up 2 of decision #91. T-020 ends a skipped post-processing job as `JobEnd::DeliveredSkipped{reason, …}` with tray Error and the 3 s overlay message. This task makes T-007's notifier show the skip reason as a toast, without Retry, because the raw text was already delivered.

## Acceptance

- [ ] A skipped post-processing step shows one toast naming the reason (one of the six skip reasons, en/ru), with no Retry.
- [ ] Failure branch: a toast that cannot be shown is logged and changes nothing else (the delivery stays as it was).
- [ ] Test that fails without the change: named in `## Tests`.

## Tests

## Investigation

**Frame.** Expected (spec 003 FR-003, FR-006, US2-6, SC-002; #91 follow-up 2): every skipped post-processing raises one toast naming its reason (en/ru), no Retry; a toast that cannot be shown is logged and changes nothing else. Observed: the chain already exists. No code is missing on the Pasted / CopiedOnly path.

**The path, end to end (symbols, read via Serena and grep):**
1. `Pipeline::release` ends a skip as `JobEnd::DeliveredSkipped{reason, delivery}` (T-020).
2. `RecordingController::end_job` sets tray Error and calls `show(skip_message(&reason, delivery))`. `show` → `show_offer(.., retry: None)`, which pushes an `Offer` into the outbox (T-007 I1: every shown message is offered once).
3. `dictation::Locked::drop` takes the offers after the lock and calls `Notifier::notify(id, params, retry.map(ToastAction::Retry))`. A skip gets `None`, so no Retry button.
4. `src-tauri/src/lib.rs` `run()` builds `win::toast::ShellNotifier` and passes it to `start_dictation_with` (T-210). `ShellNotifier::notify` drops only `notice.logs_unwritable` (`i18n::is_toast_surface`). The toast thread renders `i18n::text(ui_language, id, params)` and builds a button only for `Some(action)`. A failed build or Show writes one `warning kind=toast_failed os_code=N` and leaves the overlay, the tray and the next toast alone.
5. The six skip ids `notice.post_processing_skipped.{timeout,unreachable,invalid_key,http,invalid_response,not_configured}` are declared in `i18n.rs`. `SkipReason::message_id` / `message_params` map them, and `post_process` unit tests check that the en/ru catalog covers them.

**What is not covered.** No test drives a `DeliveredSkipped` end to the offer list or to a Notifier:
- `dictation_session.rs` has offer tests for Failed, Notice and the Delivered notice (`job_notices_are_offered_once_each_without_a_retry_id`) but none for a skip. Its Rig hard-wires `PassThrough`.
- The controller tests `delivered_skipped_*` check only the indicator, not `take_offers`.
- `src-tauri/tests/dictation_e2e.rs` `post_processing_server_refusing_still_pastes_the_raw_transcript_with_tray_error` uses `start_dictation`, which wires `NoToasts`.
- `src-tauri/tests/feedback.rs` checks the toast mechanics and the failure branch, but only with failure and notice ids.

Searched with grep over `crates/voicen-core/{src,tests}` and `src-tauri/{src,tests}` for `DeliveredSkipped`, `SkipReason`, `post_processing_skipped`, `take_offers` and `Notifier`. Serena `find_implementations` on `Notifier` returned nothing, so grep was used for the impls.

**Unsettled product point (not guessed).** With `DeliveryResult::CopyManual`, `post_process::skip_message` returns `notice.copied_paste_manually` (#91(3), still marked "pending: owner ratifies"). That message is the one overlay message and also the only offer, so the skip reason is named nowhere. This conflicts with SC-002 ("each one raises exactly one notification naming the reason") and with Acceptance 1 here. Options for the owner:
- (a) keep #91(3) for both surfaces, so a skip after a failed paste has no reason toast;
- (b) the overlay keeps `copied_paste_manually` and the toast names the skip reason. That breaks I1 "toast = what the overlay shows" and needs a second, toast-only offer from `end_job`;
- (c) two toasts (paste-manually and the skip).

The en/ru wording of the six strings is already in the catalog, so this task decides no wording.

**Recurrence.** `docs/failures.md` (31 entries) has no entry about post-processing, skips or toasts. `docs/decisions/post-processing.md` records #91(3) as one function (`skip_message`). Class `post-processing`: no recurrence.

**Size.** Small, one seam (`RecordingController::end_job` / `post_process::skip_message`). The shell needs no change under any option except (b)/(c), and even those change only core's offer list.

**Where tests live.** On Linux, core: `crates/voicen-core/tests/dictation_session.rs`. This needs a `Custom` post-processor field on its Rig, a test-only change, and a fake `PostProcessor` returning `Skipped(..)`. Or use the controller unit test in `recording/mod.rs` with `take_offers`. Optional on Windows CI: `src-tauri/tests/feedback.rs`, a skip offer through `ShellNotifier` + `FakeSink` showing the reason text with no `<action>`. Today none of these goes red without a change. A red-first test exists only if the owner picks (b) or (c) for CopyManual.

**Recommended next step.** Ask the owner the CopyManual question (it also ratifies #91(3)). If the answer is (a), mark T-075 absorbed by T-007 + T-020 + T-210, or keep it as a test-only pin (the skip offer test above). If (b) or (c), it stays a small core change in `end_job`, with a red test that offers the skip reason for CopyManual.
