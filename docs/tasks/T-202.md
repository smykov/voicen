## Context

Owner decision #249 (option A): voicen moves to the teamwright autonomous contour on GitHub. The infrastructure exists outside the repository:
- a self-hosted runner `voicen-*` on host 105, labels `self-hosted, Linux, X64, claude`, one job at a time;
- `RUNS_DIR=/srv/gha-voicen-runs`;
- repo variable `TEAMWRIGHT_AUTH=subscription`;
- secret `CLAUDE_CODE_OAUTH_TOKEN`, set by the owner.

The kit ships no workflow (kit `docs/process/plugin.md` § tw-github, `docs/usage.md` § contour). The owner's other contour projects (smykov/spisok-pokupok, smykov/ai-resume) carry `teamwright-agent.yml` and `teamwright-next.yml` that can serve as the model; read them with `gh` (read-only).

The contour workflows need `contents: write` (and the matching issues and pull-requests scopes) to push `task/<ID>` branches and open pull requests. The project's CI guard refuses that. `make check-release-guard` (`scripts/ci/release-guard.sh`, rules R1-R10 over every file in `.github/workflows`) requires the workflow-level `permissions: contents: read` block (R1). The guard set also pins the other rules (`docs/decisions/ci-toolchain.md`, CLAUDE.md "Where things live" row for `.github/workflows/ci.yml`):
- `scripts/ci/action-lines.txt` and `scripts/ci/cache-steps/`: every line naming an action;
- `secrets.TELEGRAM_` only in the Telegram send step;
- the release job is the last job.

This is a guard change: `checker: true`, `analysis.decides_on` required, full review.

## Acceptance

- [ ] `.github/workflows/teamwright-agent.yml` and `.github/workflows/teamwright-next.yml` exist and run on `runs-on: [self-hosted, Linux, X64, claude]`. Each uses only the permissions it needs, authenticates via `CLAUDE_CODE_OAUTH_TOKEN` and `TEAMWRIGHT_AUTH`, and runs one task at a time (`concurrency`).
- [ ] The guard grants the `contents: write` exception to exactly these two paths, owned by name (literal), not by a pattern. Every other file in `.github/workflows` is still refused unless it has `contents: read` (R1).
- [ ] Every other guard rule still holds for the new files: action lines owned, no `secrets.TELEGRAM_`, no secret printed. `ci.yml` is unchanged.
- [ ] Failure branch: the guard's self-test has cases for:
  - a third workflow file with `contents: write`, which must be refused;
  - one of the two contour files carrying a permission beyond its owned set, which must be refused;
  - a renamed copy of a contour file (`teamwright-agent2.yml`), which must be refused.

  The self-test goes red if the exception is widened to a glob.
- [ ] A chain's branch gets CI: the agent chain ends with `gh workflow run ci.yml --ref task/<ID>` (with `workflow_dispatch` on `ci.yml`, if the guard allows it), or the gap is recorded as an open question. The kit notes that a `GITHUB_TOKEN` push starts no CI.
- [ ] `docs/decisions/ci-toolchain.md`, `CLAUDE.md` (the workflows row) and `docs/process/gates.md` (if a gate is affected) describe the exception in the same change.
