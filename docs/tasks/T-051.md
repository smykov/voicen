## Context

Split from T-006 by decision #64 (T-006 analysis, option A): the platform-free dictation session so the Linux gate proves every decision before the Windows adapters land. New `crates/voicen-core/src/dictation.rs`: the session over `RecordingController` (T-042) and `Pipeline` (T-001); capture opens only after `dictation_gate(snapshot)` passes and `press` returns Start; one FIFO worker is the only caller of `run_job` and `job_finished` (decision #48: one delivery at a time, in recording order); the 3 s message timer; new ports `AudioSource`/`CaptureHandle`/`FrameSink` (reporting the first-frame instant), `Indicator` and shell requests (open settings on a tab), with fakes; `retry_available` from `JobReport.pending` on the worker, never `Pipeline::pending()` on a UI thread (T-007 note). Also: the hotkey-registration input to the controller, a `Hotkey` → Win32 modifier/VK table as pure data (cross-checked against the windows crate in Windows CI by T-006), the "target is elevated" rule as a pure function, a real-time WAV test source, and a controller notice input so `notice.choose_engine` can show on the overlay (T-006 Q8). The session takes a `PipelineObserver` (T-008's `LogObserver` plugs in) and a capture failure at press emits a Copy event with `MicCause`, never OS text (T-008 shared touch points). Toggle mode behaves as hold until T-009 (owner decision #63).
