## Context

Split from T-006 by decision #64 (T-006 analysis, option A): the platform-free dictation session so the Linux gate proves every decision before the Windows adapters land. New `crates/voicen-core/src/dictation.rs`: the session over `RecordingController` (T-042) and `Pipeline` (T-001); capture opens only after `dictation_gate(snapshot)` passes and `press` returns Start; one FIFO worker is the only caller of `run_job` and `job_finished` (decision #48: one delivery at a time, in recording order); the 3 s message timer; new ports `AudioSource`/`CaptureHandle`/`FrameSink` (reporting the first-frame instant), `Indicator` and shell requests (open settings on a tab), with fakes; `retry_available` from `JobReport.pending` on the worker, never `Pipeline::pending()` on a UI thread (T-007 note). Also: the hotkey-registration input to the controller, a `Hotkey` → Win32 modifier/VK table as pure data (cross-checked against the windows crate in Windows CI by T-006), the "target is elevated" rule as a pure function, a real-time WAV test source, and a controller notice input so `notice.choose_engine` can show on the overlay (T-006 Q8). The session takes a `PipelineObserver` (T-008's `LogObserver` plugs in) and a capture failure at press emits a Copy event with `MicCause`, never OS text (T-008 shared touch points). Toggle mode behaves as hold until T-009 (owner decision #63).

**Frame.** This is a feature. Expected: one platform-free owner turns hotkey events into a delivered dictation, and the Linux gate proves every decision before T-006's Win32 adapters exist (#64). Observed: the stages exist, but nothing in production calls them, and the ports the session needs do not exist (see `analysis.evidence`).

**Recurrence.** Class `dictation-session`. `docs/failures.md` has F-001..F-005 in the classes `ci-toolchain`, `guard-model`, `test-port-race` and `windows-refused-connect-timing`. None of them is this class, so `recurrence_of: []` stands. Rules of other classes still bind T-051:
- **F-004 and F-005.**
  - The session tests need no network. Engines are faked through `Pipeline::with_engine_factory`, and no refused address or deadline is involved.
  - If a test ever uses the std mock server, it uses `common::refused_addr()` / `refused_timeouts()`.
  - The voicen-core tests also run on windows-latest (`ci.yml:61`). Every real-time assertion (timer, real-time source) therefore polls against a budget sized for Windows (timer resolution ~15.6 ms, slower thread start), never an exact Linux deadline.
- **F-001 and F-002.** They do not apply: T-051 is core only and has no shell test.
- **P-009.** `CaptureError::Other`'s OS text never reaches an event, a message or the indicator; only `MicCause` does. The session has no `eprintln!` and no file writes (T-008 touch points).

**Hypotheses.**
1. *Parts exist under other names.* True for the decisions: gate, controller, pipeline, indicator, `PressContext`, fakes for the clipboard, the paster and the store, `RecordingObserver`, `SettingsService` with fakes (`tests/api_pipeline.rs:444` builds one).
   False for:
   - the session;
   - the capture, indicator and request ports;
   - a hotkey-registration input;
   - a notice input;
   - the Win32 tables;
   - a WAV reader.
2. *The same concern on a second path.* Four risks, all closed by the invariant:
   - (a) Shell-side orchestration (gate → press → capture → finish → worker → `job_finished` → render) would be a second owner beside the controller.
   - (b) A tray that calls `Pipeline::pending()` from the event loop would block behind `put_pending` (T-007 note).
   - (c) A second observer instance (the session's and the pipeline's) would split T-008's dictation line. Building the `Pipeline` inside the session from `PipelineDeps` closes this by construction.
   - (d) The shell computing "elevated" or the key codes on its own would give a second, Windows-only source (P-010). Hence the pure tables in core, which T-006 cross-checks against `windows::…` on CI.
3. *This class was fixed before.* No.
4. *`JobReport.pending` of the last job is `retry_available`.* Refuted. `release` returns `pending: None` for `Text` and `NoSpeech` (`pipeline.rs:269-275`, `:285-299`), but data-model "PendingRecording" says those outcomes do not touch the slot. After "503 → pending", a later delivered dictation would hide the tray Retry while the audio is still pending.
   - Fix: the worker reads `pipeline.pending().is_some()` right after each `run_job`. That is the slot itself (P-010), read on the worker, the only thread that changes the slot until T-007's retry, which also runs there.
   - The alternative is to derive it from `JobReport`: `Failed(r)` with `r.retryable()` → `pending.is_some()`, otherwise unchanged. It copies `release`'s rule, so it is a second chain.
   - Test 14 below fails for the naive version.
5. *One seam.* Refuted, narrowly. See the size verdict.

**Design (option A).**
- **Session API.**
  - `DictationSession::start(SessionDeps) -> io::Result<DictationSession>`. Thread spawn can fail, and the error carries only the `io::ErrorKind`.
  - `SessionDeps { pipeline: PipelineDeps, engine_factory: Option<Box<EngineFactory>>, audio: Arc<dyn AudioSource>, indicator: Arc<dyn Indicator>, requests: Arc<dyn ShellRequests>, settings: Arc<SettingsService> }`.
  - The session keeps clones of `pipeline.observer` and `pipeline.paster` before it builds the `Pipeline`, so there is one observer and one paster.
  - Inputs, all `&self`, called by shell threads with instants stamped there: `hotkey_pressed(at)`, `hotkey_released(at)`, `tray_menu_opened(at)`, `hotkey_registration(registered: bool, at)`. `Drop` closes the queue and joins (see Q3).
- **Press.** All of this runs under the lock:
  1. If `ctrl.live_id()` is `Some`, return (no gate, no second stream).
  2. Take `snapshot = settings.snapshot()`.
  3. If `dictation_gate(&snapshot)` is `Err(b)`, carry out `blocked_actions(b)` in order:
     - `Notify(id)` → `ctrl.notice(id, at)`, then publish;
     - after unlocking, `OpenSettings(tab)` → `requests.open_settings(tab)`.
  4. Otherwise build `PressContext { start_window: paster.capture_start_window(), settings: snapshot }` and call `ctrl.press(at, ctx)`.
  5. On `Start(id)`, call `audio.start(sink)`:
     - `Ok(handle)`: keep `(id, at, handle, buffer)` in the capture slot, then publish (Recording).
     - `Err(e)`: call `ctrl.capture_failed(id, e, at)`, emit `CaptureFailed { recording: id, cause }`, then publish (tray Error plus the message).

  Publication happens only once the start result is known, so a failed capture never shows Recording (FR-009; data-model "Idle --press [device fails]--> Idle + failure (no recording state)"). `settings.mode` is not read (#63).
- **Release.**
  1. Under the lock: `ctrl.release(at)`, then take the capture slot for that id and publish.
  2. Outside the lock: `handle.stop()`. After it returns, the source calls the sink no more, and the device is closed (NFR-02).
  3. Emit `RecordingStarted { recording, hotkey_to_first_frame_ms: first_frame − press_at, device: Selected }`, only if a frame arrived (T-008 omits keys that are absent), then `RecordingEnded { duration_ms, end }`. `end` and the duration come from `Release::end()` / `held`, or from `stopped_at − started_at`.
  4. For `Stop(ticket)`: convert with `AudioBuffer::from_frames`. An `AudioError` becomes `CaptureError::Other` with a fixed literal (an adapter bug, never OS text). Then, under the lock: `ctrl.finish(ticket, audio, at)`.
     - `Ok(rec)`: push it to the FIFO under the same lock, so queue order equals finish order, then publish.
     - `Err`: emit `CaptureFailed` and publish.

  The conversion runs on the caller's thread (see Q6).
- **Worker.** One std thread loops:
  1. `recv`;
  2. `id = rec.id()`;
  3. `report = pipeline.run_job(rec)`, with no lock held;
  4. `retry = pipeline.pending().is_some()`;
  5. under the lock: `ctrl.job_finished(id, report.end, Instant::now())`, record `retry`, publish.

  The worker stamps the job-end instant: it is the caller of `job_finished` and the instant of its event, which matches core-traits.md "every `Instant` is the instant of the caller's event". `run_job` still reads `Instant::now()` only for durations (#47 (2)). T-011 later replaces the worker with its delivery thread.
- **Timer.** One std thread waits on the session `Condvar`:
  - with no deadline, it waits until notified;
  - with deadline `d`, it calls `wait_timeout(d − now)`. Once `now >= d`, it calls `ctrl.tick(now)` and publishes.

  Every session mutation notifies the `Condvar`, so a replaced or dropped message re-arms or cancels the wait. No clock port is added: tests use the real `Instant`. Deterministic tests place caller instants in the past (`t0 = Instant::now() − 10 s`), so they stay ordered against the worker's real instants. Only the expiry tests wait for real time.
- **Publication.**
  - `publish()` compares `(ctrl.indicator(), retry_available)` with the last published value and calls `set_tray` and/or `set_overlay` only on a change, always inside the session lock. So the port sees states in the controller's order, and never twice.
  - Port contract: the implementation must not block on another thread and must never call the session. T-052 and T-053 hop to the main thread with an `emit` or `run_on_main_thread` that does not wait.
- **Ports** (shapes are recommendations; the developer may rename; core-traits.md is updated to the built form).
  - `AudioSource::start(&self, sink: Arc<dyn FrameSink>) -> Result<Box<dyn CaptureHandle>, CaptureError>` uses the default device. T-012 adds `list_devices` and a device argument (#64 moved device choice there).
  - `FrameSink::frames(&self, interleaved: &[f32], rate: u32, channels: u16, at: Instant)`. `at` is stamped by the adapter in its callback, and the sink keeps the first one. The sink mixes down to mono as frames arrive (this halves memory until T-009's 10-minute cap), and a format change within one capture is an error.
  - `CaptureHandle::stop(self: Box<Self>) -> Result<(), CaptureError>`. Drop also stops.
  - `on_end(DeviceLost)` (FR-031) is T-012's.
  - `Indicator { set_tray(TrayState, retry_available: bool), set_overlay(&OverlayState) }`, as in core-traits.md.
  - `ShellRequests { open_settings(SettingsTab) }`. T-055 adds the field focus, and T-007 adds the `Notifier` (toasts) beside it.
  - Fakes with call logs:
    - `FakeAudioSource`: a scripted start result, frames, a first-frame offset, a stop error, a start-call count and an open-handle count;
    - `FakeIndicator`: the sequence of published states;
    - `FakeShellRequests`.
- **Controller additions** (`recording/mod.rs`, T-042's seam):
  - `hotkey_registration(registered, at)`: `hotkey_error = !registered`. This replaces the hard-coded `false` at `:396`. Only `true` clears it (FR-011/FR-028; data-model "HotkeyError is cleared only by a successful registration").
  - `notice(id, at)`: a message for 3 s with the tray unchanged, the same rule as `JobEnd::Notice` (T-006 Q8 → #64). It changes the `Where` column of `notice.choose_engine` in messages.md to "toast + overlay".
  - `live_id() -> Option<RecordingId>`, so the session never keeps a second "is a recording on" flag (P-010).
- **Event.** `DictationEvent::CaptureFailed { recording: RecordingId, cause: MicCause }` (still `Copy`) covers both `capture_failed` and `finish(Err)`. No `RecordingEnd` variant is added: a capture failure at press is "no recording state".
- **Pure Win32 data** (a new core module, no `windows` crate dependency):
  - `hotkey_codes(&Hotkey) -> { modifiers: u32, vk: u16, poll: [group] }`.
    - `modifiers` is the `MOD_*` bits ORed with `MOD_NOREPEAT` (R-1).
    - `vk`: A–Z 0x41–0x5A, 0–9 0x30–0x39, F1–F24 0x70–0x87, Space 0x20, PageUp 0x21, PageDown 0x22, End 0x23, Home 0x24, Left/Up/Right/Down 0x25–0x28, Insert 0x2D, Delete 0x2E, Pause 0x13, Num0–Num9 0x60–0x69.
    - `poll`: one group per pressed key, Ctrl [0x11], Alt [0x12], Shift [0x10], Win [0x5B, 0x5C] (no generic Win VK exists), plus [vk].
  - `released(&groups, is_down)` is true when any group has no key down (R-1: the first key found up counts as the release).
  - `IntegrityLevel(u32)` with the RIDs LOW 0x1000, MEDIUM 0x2000, MEDIUM_PLUS 0x2100, HIGH 0x3000, SYSTEM 0x4000, and `target_elevated(own: Option<IntegrityLevel>, target: Option<IntegrityLevel>) -> bool` = `target > own`, or either is unknown (R-12; for "own unknown", see Q4). It lives next to `StartWindow` (platform.rs), whose `elevated` doc already states the rule.
  - T-006 asserts both tables against `windows::Win32::…` constants on Windows CI.
- **RealtimeSource** (`test_support`, feature `test-fakes`, never in release):
  - It implements `AudioSource` over interleaved frames at any rate and channel count, built from an `AudioBuffer` or from PCM16 WAV bytes. The reader is the inverse of `wav::encode`, plus stereo and any rate; it is written by hand, since `hound` is not consented (#9).
  - `start` spawns a thread that pushes 10 ms chunks paced by real time, stamping `Instant::now()`. Once the data runs out it pushes silence, as a live microphone would, so the captured length follows the hold.
  - `stop` joins the thread.
  - T-006's `dictation_e2e` injects it through the wiring function. R-4's `VOICEN_TEST_AUDIO`/`test-audio` switch stays a shell question.

**Red tests (Linux gate; each must fail before the code exists).** Unless noted, they go in `crates/voicen-core/tests/dictation_session.rs`. Every test is built from the real `SettingsService` with fakes, `FakeAudioSource`, the fake engine factory, `FakeClipboard`/`FakePaster` (a non-elevated start window), `FakeIndicator`, `FakeShellRequests` and `RecordingObserver`.
