## Context

First end-to-end slice of the release-1 flow (requirements §2) on the walking skeleton, in the part the Linux host and an API test can prove: the `voicen-core` pipeline from a recorded buffer to the text that would be delivered. Requirements: FR-06, FR-12, FR-24 (connect 5 s, API 30 s), FR-11 (pending audio), NFR-06, NFR-07 (engine failure never panics). Foundations from spec 001 Phase 2: `Timeouts`, `AudioBuffer` + WAV encoding, platform traits with fakes, `DictationEvent`. Dependencies per decisions #9. Settings and keys come from T-003 (decision #21): `DictationSettings` is a projection of `SettingsService::snapshot()` (no own file, loader or defaults), the key is read with `CredentialStore::read(KeySlot::TranscriptionApi)` as a `Secret`. The API surface: add `api_test_command` for area `core` (an integration test binary that runs the pipeline against a local mock OpenAI-compatible HTTP server) through `.teamwright/config.next.yml` — the owner applies it.

## Acceptance

- [ ] A 3 s speech fixture sent through the pipeline to a mock `/v1/audio/transcriptions` returns the mock's text as the delivery text; the request is multipart with 16 kHz mono WAV, `model`, `language` (auto = omitted) and `Authorization: Bearer <key>`
- [ ] Silence, 1 s cough and keyboard-noise fixtures make no HTTP request and yield outcome `NoSpeech` (FR-12)
- [ ] `api_test_command` for area `core` exists in `.teamwright/config.yml` and runs these tests
- [ ] Failure branch: mock answers 401 → outcome `Failed(InvalidApiKey)`, nothing to paste, the audio stays as the pending recording; no answer in 30 s → `Failed(Timeout)`; unreachable host → `Failed(CannotReach(host))` within 5 s connect — verified by the API test and the absence of any paste/clipboard call on the fakes
- [ ] Test that fails without the change: `crates/voicen-core/tests/api_pipeline.rs (red before the change)`

## Investigation

### Re-analysis 2026-10-04 — narrowed scope (decisions #42, #43, #44)

**Frame.** T-001 is now the pipeline job only. It takes a finished recording through the speech gate (T-041, built), then the engine via `engine_for` (T-040, built), then post-processing (identity until T-020), then the delivery decision. It ends in a JobEnd for the controller (T-042, in review), a pending recording on retryable failure, and events on one observer. Proof: the Linux gate (`tests/api_pipeline.rs` against wiremock, unit tests with fakes), and the same binaries on `windows-latest` (`ci.yml`, `cargo test --workspace --exclude voicen`). Context and Acceptance are unchanged. Of the pre-split questions: Q1 is answered by #42 (sync), Q5 by #44, and Q2/Q3 moved to T-043. Q4 (api_test_command) remains.

**Recurrence.** The class is `transcription-pipeline`. `docs/failures.md` has F-001..F-003 (`ci-toolchain`, `guard-model`). There is no earlier defect of this class, and `recurrence_of: []` stands.

**Hypotheses checked.**
1. *Parts already exist.* Confirmed for the stages, refuted for the sequencer. The search was a grep over `crates/` and `src-tauri/src` (`*.rs`); Serena indexes only TypeScript. Built and reused as is: `engine_for(&Settings, &dyn CredentialStore)`, `SpeechGate::decide -> GateDecision`, `FinishedRecording<C>`, `JobEnd`, `Timeouts`, `FailureReason::{code, message_id, message_params}`, `classify`, and the `test_support::fixtures` generator (speech_3s, silence_3s, cough_1s, keyboard_3s; T-041 seam: "T-001's api_pipeline reuses"). Missing: pipeline, events, platform ports, delivery, `ClipboardUnavailable`, `retryable()`.
2. *A second path for the same concern.* There are three risks, and each is closed by the design below:
   - (a) A `DictationSettings` projection beside `Settings` would give two sources for engine, URL and language. `engine_for` already takes `&Settings`, and T-040 (3) found `api_base_url: Url` cannot be an infallible `From<&Settings>`. So: `Arc<Settings>`, no projection, no `SettingsSource` (P-010, P-011).
   - (b) A gate or engine that emits events itself would be a second emitter. Only `run_job` emits; the gate returns `fallback_warning`.
   - (c) A pipeline-local clock port would be a second clock. There is none; see "Time" below.
3. *The class was fixed before.* No.
4. *The input type blocks retries.* Confirmed. `FinishedRecording` is built only by the controller (`recording/mod.rs:123`), so T-007's retry can never construct one. Hence `run_job` takes `FinishedRecording<PressContext>` for fresh jobs now. Internally it works on a private `Job` view (audio ref, start window, settings, stopped_at, recording id), and T-007 adds a second constructor (from the pending slot) into the same `process` → `release` path. No change to `recording/` is needed: `audio()` and `ctx()` by reference are enough (nothing is cloned; `put_pending` takes `&AudioBuffer`).

**Settled shapes.**
- `PressContext { start_window: Option<StartWindow>, settings: Arc<Settings> }`, defined in `pipeline.rs`. It is the controller's `C`. T-006 fills it at press with `Paster::capture_start_window()` and `SettingsService::snapshot()`, so the snapshot is taken at recording start (data-model DictationSettings, Clarification 4). Changing settings mid-recording does not affect that job.
- `Pipeline::new(deps: PipelineDeps) -> Pipeline`, with `Send + Sync`. `PipelineDeps { gate: SpeechGate, credentials: Arc<dyn CredentialStore>` (the same instance as `SettingsService`'s), `clipboard, paster, temp_audio, observer, post_processor }`. The engine factory field defaults to `engine_for`; T-017 wraps it for BuiltinLocal and tests may inject a fake. The only non-test constructor uses `Timeouts::default()`; a `cfg(any(test, feature = "test-fakes"))` constructor takes ms-scale `Timeouts`. So the production pipeline cannot run with other durations, and FR-24 rests on `defaults_are_fr24` plus one pipeline test (below).
- `run_job(&self, rec: FinishedRecording<PressContext>) -> JobReport { end: JobEnd, pending: Option<PendingId> }`. The shell reads `rec.id()` first and then calls `controller.job_finished(id, report.end, at)`. The doc comment says: blocking, a plain std thread, never inside a tokio runtime (the blocking reqwest client panics there, T-040).
- Steps, in this order:
  1. `gate.decide(audio)`. On `fallback_warning`, emit `Warning{vad_fallback}`, then `SpeechGate{recording_id, detector, speech}`.
  2. Not speech: `NoSpeech`. There is no factory call, no credential read and no request.
  3. Speech: `factory(&settings, &*credentials)`, then `transcribe(audio, &TranscribeRequest{ language: settings.speech_language.clone(), timeouts })`. `Ok("")` becomes `NoSpeech`.
  4. Text: `post_processor.process(text, &settings)`. Empty after post-processing becomes `NoSpeech`; the T-020 fallback rules are not decided here.
  5. Release (below).
- Code layout: `run_job` is two private halves, `process(&Job) -> JobOutcome` (no side effects except events 1 and 3) and `release(&Job, JobOutcome) -> JobReport` (clipboard, paste, pending, JobFinished/Delivered). T-011 then puts the `DeliveryQueue` between them without rewriting either half (R-10: workers run `process`, one delivery thread runs `release`).
- Platform ports (`platform.rs`), following core-traits.md:
  - `Clipboard::set_text_excluded_from_history(&str) -> Result<(), ClipboardError>`.
  - `Paster { capture_start_window() -> Option<StartWindow>; wait_modifiers_released(Duration) -> bool; is_in_front(&StartWindow) -> bool; send_ctrl_v() -> Result<(), PasteError> }`.
  - `TempAudioStore { put_pending, get_pending, delete_pending, delete_all }`. All four are in the trait (the contract shape); T-001 calls `put_pending`/`delete_pending`, and the tests read back through the fake's `get_pending`.
  - `StartWindow { handle: WindowRef(u64, opaque), process_id: u32, elevated: bool }` (Clone).
  - `PendingId(u64)`, monotonic per pipeline.
  - `ClipboardError` and `PasteError` are unit structs (no OS text, P-009).
  - Not in T-001: `AudioSource` (T-006), `Notifier` and `Indicator` (T-006/T-007), `SettingsSource` (dropped).
- Public fakes, `cfg(any(test, feature = "test-fakes"))`, next to the traits as in secrets.rs (#23 N4):
  - `FakeClipboard`: records texts, has a fail switch.
  - `FakePaster`: scripted start window / modifiers / in-front / send result, with a call log.
  - `FakeTempAudioStore`: an in-memory map with a call log and a put-fail switch.
  - `RecordingObserver` (in events.rs).
- `PostProcessor::process(&self, text: String, settings: &Settings) -> PostProcessed { text, notice: Option<MessageId> }` plus `PassThrough`, placed in the existing `post_process/mod.rs`, not a new `postprocess.rs` (one module per concern). T-020 widens the arguments (credentials, timeouts) and decides how its notice combines with a copy notice, because `JobEnd::Delivered` has one notice slot.
- `FailureReason` additions in failure.rs: `ClipboardUnavailable` (`failure.clipboard_unavailable`, en/ru from messages.md) and `retryable()`. `retryable()` is true for every variant from `InvalidApiKey` through `ClipboardUnavailable` and false for `MicrophoneUnavailable`, written as an exhaustive match. Also new ids in `messages!` and both catalogs (#23 N3): `notice.no_speech`, `notice.copied`, `notice.copied_paste_manually`.

**Delivery (`delivery.rs`, the data-model table, first match).**
- The clipboard is written first. An error gives `Failed(ClipboardUnavailable)`: no paster call, and the recording goes pending.
- `auto_paste` off gives `CopiedOnly`, with no paster call at all.
- Otherwise `CopyManual` in each of these cases, checked in this order:
  - `start_window` is `None` or `elevated`. These are static and checked first, so nothing waits 1 s for nothing. The order does not change the result, because all of them give the same outcome.
  - `!wait_modifiers_released(MODIFIER_WAIT = 1 s)` (one constant, P-010).
  - `!is_in_front(w)`. It is checked after the wait and right before sending, so the race window stays small.
  - `send_ctrl_v` returns `Err`. This row is new (contract gap, not owner-level): the text is already in the clipboard, so the user pastes manually. It is added to data-model's table in the same commit.
- Otherwise `Pasted`.
- JobEnd mapping:
  - `Pasted` → `Delivered{notice: None}`.
  - `CopiedOnly` → `Delivered{notice: Some(notice.copied)}`.
  - `CopyManual` → `Delivered{notice: Some(notice.copied_paste_manually)}`.
  - `NoSpeech` → `Notice(notice.no_speech)`.
  - `Failed(r)` → `Failed(r)`.

**Pending slot (one, in `Pipeline`, a `Mutex<Option<PendingRecording{id, start_window, reason}>>`; lock poisoning is tolerated without `unwrap`).**
- On a retryable `Failed`:
  1. Take a new `PendingId`.
  2. Call `put_pending(new, audio)`.
  3. Under the lock, swap the slot to `Some(new)` (if the put succeeded) or `None` (if it failed).
  4. Call `delete_pending(old)` for any older entry. Errors are ignored; the start/exit `delete_all` (T-007, FR-032) catches leftovers.
- `JobReport.pending = Some(new)` only if stored.
- Recommended default (orchestrator, not blocking): a failed put still removes the older pending. Data-model says "at most one; a newer Failed replaces it", and the tray must never offer a dictation older than the last failure reported.
- `Text` and `NoSpeech` do not touch the slot. `pub fn pending(&self) -> Option<(PendingId, FailureReason)>` exists for T-006/T-007 (tray `retry_available`, toast id).
- Not here: retry, the fs store, WAV decode, `delete_all` at start/exit, the Notifier (all T-007).

**Events (`events.rs`).**
- `#[derive(Clone, Copy, Debug, PartialEq, Eq)] enum DictationEvent` holds exactly the six data-model variants. Fields are only integers, bools, `&'static str` codes and small enums (`RecordingId`, outcome, delivery result). `Copy` is the type-level guard: adding a `String`, `Vec`, `Secret` or `FailureReason` (whose `CannotReach{host: String}` is not Copy) fails to compile. A test `fn assert_copy::<DictationEvent>()` pins this.
- `JobFinished` carries:
  - `seq` (a pipeline counter at `run_job` entry; T-011 moves the assignment to stop);
  - `engine: Option<&'static str>` (`kind()`; `None` when no engine was built);
  - `stop_to_text_ms` (from `rec.stopped_at()` to the outcome);
  - `outcome` (text / no_speech / failed);
  - `failure: Option<&'static str>` (`code()`);
  - `http_status: Option<u16>` (from `ServerError` only; 401/403 are not carried by `InvalidApiKey`, a known limit).
- Per job the order is `[Warning]`, `SpeechGate`, `JobFinished`, `[Delivered]`. `JobFinished` is emitted after the clipboard write, so a clipboard failure is logged as failed/ClipboardUnavailable and there is no `Delivered`. T-001 emits these four. T-006 emits `RecordingStarted`/`RecordingEnded` on the same observer instance (T-042: the controller emits nothing).
- **Time.** No clock port (core-traits.md, T-042). Decisions never read a clock. The two event durations (`stop_to_text_ms`, `text_to_paste_ms`) need an instant inside `run_job`, so they read `std::time::Instant::now()` and are compared against the caller's `stopped_at` (both are monotonic `Instant`s). Tests assert bounds, not values. The rule "`Instant::now()` only for event durations, never for a decision" goes into core-traits.md in the same commit (orchestrator records it, not owner-level).
- Redaction test inputs: key `sk-test-SECRET`, base URL `http://127.0.0.1:<port>/v1?api-version=SECRETQ`, and `TRANSCRIPT-MARKER` in the 200 text and in the error bodies. It runs every api_pipeline path and asserts that no event `Debug`, no `JobReport` `Debug` and no `FailureReason` `Debug`/`Display` contains any of the three. Positive control: the fake clipboard did receive `TRANSCRIPT-MARKER`.

**Error classification (pure function over a small `TransportError`, then the reqwest adapter).**
- Status 401/403 → `InvalidApiKey`.
- Any other non-2xx → `ServerError{status}`.
- `is_dns()` (`error.rs:176`), or an io `NetworkUnreachable`/`HostUnreachable` in the source chain → `NetworkUnavailable`.
- `is_connect()` (`error.rs:158`) with `ConnectionRefused`, or with `is_timeout()` (connect timeout) → `CannotReach{host[:port]}`.
- `is_timeout()` and not connect → `Timeout`.
- Body not JSON, `text` missing or not a string, more than 1 MiB, invalid UTF-8, or reset mid-body → `UnexpectedResponse`.
- 2xx with empty or whitespace-only `text` → `Ok("")`, which the pipeline turns into `NoSpeech`.

Check `is_connect` before `is_timeout`. Probes in `voicen-rust:1.99`: a refused `127.0.0.1` port fails at once, so the `CannotReach` adapter test is deterministic; a `.invalid` host fails DNS at once (RFC 6761); `192.0.2.1:80` (RFC 5737) blackholes, so a connect-timeout adapter test with a ms-scale `Timeouts` works here. It is environment-dependent on `windows-latest` (a fast ENETUNREACH would give `NetworkUnavailable`), so the "within 5 s" claim rests on three things: the pure mapping test, a test that `Timeouts::default().connect == 5 s` is what the client gets, and the 192.0.2.1 test as an extra.
