## Context

First end-to-end slice of the release-1 flow (requirements §2) on the walking skeleton, in the part the Linux host and an API test can prove: the `voicen-core` pipeline from a recorded buffer to the text that would be delivered. Requirements: FR-06, FR-12, FR-24 (connect 5 s, API 30 s), FR-11 (pending audio), NFR-06, NFR-07 (engine failure never panics). Foundations from spec 001 Phase 2: `Timeouts`, `AudioBuffer` + WAV encoding, platform traits with fakes, `DictationEvent`. Dependencies per decisions #9. The API surface: add `api_test_command` for area `core` (an integration test binary that runs the pipeline against a local mock OpenAI-compatible HTTP server) through `.teamwright/config.next.yml` — the owner applies it.

## Acceptance

- [ ] A 3 s speech fixture sent through the pipeline to a mock `/v1/audio/transcriptions` returns the mock's text as the delivery text; the request is multipart with 16 kHz mono WAV, `model`, `language` (auto = omitted) and `Authorization: Bearer <key>`
- [ ] Silence, 1 s cough and keyboard-noise fixtures make no HTTP request and yield outcome `NoSpeech` (FR-12)
- [ ] `api_test_command` for area `core` exists in `.teamwright/config.yml` and runs these tests
- [ ] Failure branch: mock answers 401 → outcome `Failed(InvalidApiKey)`, nothing to paste, the audio stays as the pending recording; no answer in 30 s → `Failed(Timeout)`; unreachable host → `Failed(CannotReach(host))` within 5 s connect — verified by the API test and the absence of any paste/clipboard call on the fakes
- [ ] Test that fails without the change: `crates/voicen-core/tests/api_pipeline.rs (red before the change)`
