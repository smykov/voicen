## Context

From the T-225 analysis (2026-11-27), outside its scope; the owner chose a task of its own, P3 (decisions #378). `Writer::drain` (crates/voicen-core/src/call/session.rs) reads each track's channel until it is empty. When the writer is slower than real time on one track, that loop never ends, so `Writer::run` never reaches its command handling and a stop or pause waits for as long as the overload lasts. Core only; not queued in the contour without the owner's "запускай".

## Acceptance

- [ ] `Writer::drain` handles at most a bounded batch per track per round, so commands are read at least once per bound while a track stays full
- [ ] Failure branch: one track fed faster than the writer handles it → a stop is acted on within the bound and the recording ends cleanly, verified by a core session test
- [ ] Counted drops under true overload stay as they are (I7, docs/decisions/call-session.md); no real block is zero-filled over (T-225's invariant still holds)
