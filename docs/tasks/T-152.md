## Acceptance

- [ ] Renaming `s1` to "Colleague" re-renders `transcript.md` and `transcript.json`; the title reaches `transcript.json` `title`; duplicates are allowed (T074, T075)
- [ ] Failure branch: an empty or whitespace-only title or speaker name is refused (T074)
- [ ] Deleting a ready call removes its folder whole; deleting a transcribing call cancels the pass first (T074)

**API the tests pin** (the analysis states the seam; where it left a shape open the simplest one consistent with existing code was chosen):
- `storage.rs`: `CallStore::rename(&self, calls, root, id, title: &str) -> Result<CallSummary, CallError>`; `CallStore::rename_speaker(&self, calls, root, id, speaker: &str, name: &str) -> Result<CallDetail, CallError>` (both as in the analysis, no `lang`); `CallStore::delete_folder(&self, calls, root, id, deleter: &dyn FolderDeleter) -> Result<(), CallError>` (guard of `folder`, so a damaged call is allowed; `recordingCall` for an active call, so the store refuses on its own as well as the queue); `trait FolderDeleter: Send + Sync { fn claim(&self, file: &Path) -> Result<Box<dyn Send>, InUse> }` (`file` is a path inside the call folder, the box is the claim held until dropped, `InUse(pub String)` carries the bare file name); `struct StdFolderDeleter` (claims never refuse). The store claims every file, and only when all claims are held removes the files, drops the claims and removes the folder (analysis "commit" is done by the store, not a port method: the simplest port that can still report a locked file).
- `transcript.rs`: `enum RenameError { EmptyName, UnknownSpeaker }`, `check_name(&str) -> Result<(), RenameError>`, `rename_speaker(&mut [Speaker], id, name) -> Result<(), RenameError>`; a name is stored as given.
- `final_pass.rs`: `PassQueue::delete(&self, calls, root, id, deleter: &dyn FolderDeleter) -> Result<(), CallError>`; the pass's meta writes carry the on-disk title and speakers.
- Modules `transcript.rs` and `final_pass.rs` deny `unwrap`/`expect`/indexing, so their tests use `ok()`, `get` and helpers; `storage.rs` tests use `expect` as the existing ones do.

**Wire shapes the tests pin** (serde, camelCase, `file`/`reason` skipped when None): `{"code":"emptyName"}`, `{"code":"recordingCall"}`, `{"code":"inUse","file":"mic.opus"}`, `{"code":"notFound"}`, `{"code":"ioFailed","reason":"<snake_case>"}`. `file` is the bare file name, never a path.

**Atomicity.**
- *Rename.* Render all bytes first, with no fs call. Then `write_atomic` writes `transcript.md`, then `transcript.json` (`export_json` with the meta title and speakers), then `meta.json` last, as the commit point, in the same order as `write_ready`. Each file is replaced whole. If `meta.json` fails, the previous transcript bytes go back best effort and the call returns `ioFailed`. A test can inject the fault portably: make `meta.json.tmp` a folder, as `write_meta_failure_keeps_previous_meta_json_and_no_tmp` does. A call with no `transcript.json` writes only meta. A damaged call is `ioFailed` (`open_call`).
- *Delete.* `remove_dir_all` deletes file by file. On Windows a sharing violation on `mic.opus` would therefore leave a half-deleted folder. Renaming the folder to a tombstone first was considered and rejected. A directory rename does fail on Windows while a child is open, but that is unverified here, and the error is `ACCESS_DENIED`, which does not name the file. So the recommended design is claim-all-then-commit through a core port `FolderDeleter`:
  - claim every file in the folder. The Windows claim is `OpenOptions` with `share_mode(FILE_SHARE_DELETE)`. It fails with a sharing violation while another process holds the file for read or write, and while held it blocks new openers.
  - if any claim fails, drop all claims and return `inUse{file}`. Nothing has been removed.
  - otherwise `remove_file` each file, close the claims, and `remove_dir`.
  - The core std impl has a no-op claim (Unix has no mandatory locks). The Linux test uses a fake deleter that refuses `mic.opus` and asserts the real temp folder is byte-identical.
  - The Windows impl belongs to `src-tauri` (CLAUDE.md: Windows-only code lives in `src-tauri` or behind a core trait), and its real-lock proof is T-153's acceptance (G39 T076). It is unverified until then.
- *Transcribing delete.* `PassQueue::delete` refuses `recordingCall` for an active call. Otherwise it cancels a queued or running pass and keeps the slots lock until the folder is gone, so no stop or "Transcribe" can queue the call in between. The cancelled pass has already written its `ready-to-transcribe` meta, because `cancel` waits for the pass end. Cancel can block up to the FR-24 request timeout, so T-153 must call it off the IPC thread (T-146 Risks).

**Scope.** Core only. Per tasks.md, the shell commands `calls_rename`, `calls_rename_speaker` and `calls_delete`, the Windows `FolderDeleter`, and the real share-lock test are T-153 (G39). The UI flows are G40 (T-154). The work touches three core files of one area (`storage.rs`, `transcript.rs`, `final_pass.rs` for `PassQueue::delete` and the pass's meta writes). That is wider than the task's two named seams, but there is no new service. Medium size, no spec split.

**Hypotheses checked.**
1. *A second path writes meta.json.* Confirmed: the session (active only), the pass (4 writes), `transcribe_transition` and `recover`. This is why invariant (1) uses a lock and carries the names over.
2. *This class was fixed before.* `docs/failures.md` has no `call-storage` entry (first sighting). Nearest precedent: T-141's "never open a name we did not create".
3. *Rename of the recording call races the session.* Confirmed: `ActiveCallFiles` writes its in-memory meta on device changes and at stop. Hence refuse (Q1).

**Open decisions.**
- **Q1 — answered (decisions #317): (A), a rename of the recording call is refused with `recordingCall`; an unknown call or speaker id is `notFound`; Q2 and Q3 stand as recommended.** Original question: rename of the call this process records. The FR-035 text is silent. ipc.md lists only `emptyName`/`ioFailed` for the rename rows, and the UI already shows only "Open folder" on a recording row (calls-ui.md `actionsFor`). Recommended: **(A)** refuse `recordingCall` and add it to both rename rows of ipc.md. Alternative (B): route the rename through `CallSession` into `ActiveCallFiles`. That touches `session.rs`, a second area.
- **Q2 (developer-level, reviewer may overturn):** rename during a running pass. Recommended: a store meta lock, with the pass carrying the on-disk title and speakers into its writes and its Markdown render. Alternative: refuse while transcribing. That needs a new error code, which is a product change.
- **Q3 (developer-level):** an unknown speaker id is `notFound`, added to the `calls_rename_speaker` row. A title is stored as given, not trimmed. The Markdown already folds whitespace.
