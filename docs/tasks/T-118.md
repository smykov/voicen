## Context

Foundational for spec 007. Spec FR-042, SC-009; research R20; P-009; decisions #188. Area core, seams `crates/voicen-core/src/diag/{event,format}.rs` and `crates/voicen-core/src/call/{mod,events}.rs`. Needs the `call` module from T-116.

## Acceptance

- [ ] Every new `LogEvent` (`call_requested` … `call_switch_refused`, `vad_fallback track= cause=`, `transcript_invalid rule= segment=`) formats exactly as contracts/core-call.md "Log lines", never with segment text (T008, T009)
- [ ] Failure branch: an `EndpointId` with a character outside `{`, `}`, `.`, hex, `-` or longer than 128 characters formats as `endpoint=invalid` (T008)
- [ ] The exhaustive matches in diag/format.rs `level` / `write_message` and the `diag_format` tests (`every_event`, `seen`, `check_closed`) cover every new variant; `LogObserver` gets no call arm (T008; decision #195)
- [ ] `CallNotice` / `CallWarning` hold catalog ids and enums only; `ProviderNotice{host}` is out of scope (T-126 adds it with a typed host) (T008; decision #195)
- [ ] `Track`, `CallId` (`YYYY-MM-DD_HHMMSS[-n]`), `StopReason`, `FailReason`, `CallState` serialize with the data-model.md names (snake_case; `CallState` keeps data-model's hyphenated `ready-to-transcribe` via explicit rename) (T008, T009; decision #195)
- [ ] Test that fails without the change: `diag_format` tests and `call/events.rs` tests

## Investigation

**Frame.** This is a feature task (spec 007 G04, T008/T009). Observed: core has no call type and no call log line. Expected: the 13 line bodies of contracts/core-call.md "Log lines", and typed values for `Track`, `CallId`, `EndpointId`, `StopReason`, `FailReason`, `CallState`, `CallNotice` and `CallWarning` with the data-model names, all under the closed-output invariant of docs/decisions/diagnostics-log.md.

**How I looked.** I read `diag/event.rs`, `diag/format.rs` (`level`, `write_message`, `pair`), `diag/observer.rs`, `call/mod.rs` and `tests/diag_format.rs` (`every_event`, the `seen` match). I grepped `crates/` and `src-tauri/src` for `enum Track`, `CallId`, `EndpointId`, `StopReason`, `FailReason`, `CallState`, `CallNotice` and `CallWarning` and got no hit. This was grep, not Serena, so the empty result proves absence only for those spellings. Recurrence: `docs/failures.md` has no `diagnostics-log` row or entry, and the decision doc says the class has had no defect in this project yet.

**Hypotheses checked.**
1. *A second path writes call lines* (for example the shell formats text, or `LogObserver` gets a call arm). Refuted for now: no call producer exists yet. The seam keeps it closed, because producers only build `LogEvent` values and format.rs is the only writer of text.
2. *The class was fixed before.* No F-entry exists. The existing enforcement is the mechanism to extend here, not a patch to repeat: the compile_fail doctests in `diag/mod.rs`, the exhaustive `level` and `write_message`, and the `diag_format` grammar with planted strings.
3. *The "exhaustive LogObserver match" (acceptance 3, R20) is the enforcement point.* Refuted as worded. `LogObserver` (observer.rs:195-220) matches `DictationEvent` only, and call events never reach it. The exhaustive matches that fail to compile on a new `LogEvent` variant are format.rs `level` and `write_message`, and the test's `seen` match. Recommendation: the reviewer reads acceptance 3 as those three matches, and `LogObserver` gets no call arm, since adding one would create a second path.

**Shape of T009 (field types per line; literals from the contract or data-model).**
- `CallRequested{source: CallSource(tray|hotkey|switch)}`.
- `CallRefused{part: RefusedPart(mic|system|root), reason: RefusedReason(no_device|access_denied|busy|unwritable|missing|other)}`.
- `CallStarted{mic: EndpointId, system: EndpointId, comms_differs: bool}`. `record=1 subtitles=0` are written as constants because the 1a mode is fixed.
- `CallDeviceChanged{track, cause: DeviceCause(default_output_changed|mic_lost|mic_default_changed|track_lost|reopened|no_device), gap_ms: u64, to: Option<EndpointId>}`. The cause set is the one in data-model DeviceChange, and `None` is written `to=none`.
- `CallTrackSilent{track, rule: SilentRule(lost|cant_hear)}`.
- `CallStopped{reason: StopReason, duration_ms, mic_bytes, system_bytes: u64}`.
- `CallStorageFailed{kind, os}`.
- `CallRecovered{calls: u32}`.
- `FinalPassStage{track, stage(decode|vad|upload|merge|write), ms, chunks}`.
- `FinalPassFinished{outcome(ready|failed), reason, mode(timed|timeless), ms}`.
- `CallSwitchRefused{reason(unknown_value)}`.
- `VadFallback{track, cause(unavailable|error)}`.
- `TranscriptInvalid{rule(unsorted|out_of_range|unknown_speaker|unknown_track|bad_source|bad_lang|empty_text), segment: u32}`.

Notes on these:
- R20's field lists differ from the contract: `CallStopped` has no byte counts, and `CallStarted` has `{tracks, ...}`. R20 itself says the contract is authoritative, so the contract wins.
- `FinalPassFinished.reason` on `outcome=ready` is not defined by the contract (`reason=<…>`). Proposal: write the key only on `failed`, with a `FailReason` literal (key|network|timeout|provider|storage|engine_not_set_up), and pin that in `diag_format`.
- `EndpointId` has no public field and no `From<&str>`. `EndpointId::new(&str)` keeps the text only if it has 1..=128 chars, all in `{`,`}`,`.`,`0-9a-fA-F`,`-`. Anything else is Invalid. `Display` and the formatter write the kept text, or `invalid`.
- The serde `Deserialize` of `EndpointId` must go through the same constructor, so a hand-edited `meta.json` cannot carry free text into a later log line.
- An empty string is Invalid, because a key never has an empty value (format.rs `list`).
- The contract does not give levels. Proposal: WARN for `call_refused`, `call_track_silent`, `call_storage_failed`, `final_finished outcome=failed`, `call_switch_refused`, `vad_fallback`, `transcript_invalid`, and `call_device` with `to=none`; INFO for the rest. Pin the levels in `diag_format` so a change is visible.
- The existing `WarningKind::VadFallback` (`warning kind=vad_fallback`, dictation) stays. The call line is a separate variant with `track`/`cause` (#188). This is not a second path, because it is a different event with different fields.

**Points the spec does not settle (concerns; each needs an answer before or during T009).**
1. *`CallState` spelling.* The acceptance and tasks.md say "snake_case names of data-model.md". But data-model.md, spec.md (FR-007, FR-028), research R14 and plan.md all spell the stored state `ready-to-transcribe`, with a hyphen, and serde `snake_case` gives `ready_to_transcribe`. This value is the `meta.json` wire that T-125 and the UI read.
   - Recommendation: follow the data-model literal (`ready-to-transcribe` via an explicit rename), since the data-model is cited as the source, and fix the wording in tasks.md.
   - If the owner prefers snake_case, data-model.md and spec.md change instead.
   - Either way it is a product-wire choice, so the orchestrator or owner should confirm it.
2. *`CallWarning::provider_notice{host}`.* data-model "CallWarning and CallNotice" and ipc.md `warning.provider_notice` (with `{host}`) conflict with acceptance 4 ("catalog ids and enums only"). These values are not logged, but the acceptance is absolute. Options:
   - (a) T-118 leaves `ProviderNotice` out, and the task that owns FR-031 (T-120 provider-host rule / T-126) adds it with a typed host value from the host rule;
   - (b) T-118 adds a validated host newtype.

   Recommend (a), noted in the task, so that acceptance 4 stays literal.
3. *`call_storage_failed kind=... os=<code>`.* Two gaps:
   - `call::StorageError` (T-116, call/mod.rs:9-15) keeps only `io::ErrorKind`, which has no integer form.
   - Its `StorageOp::Encode` has no literal in the contract's `kind` set (write|flush|sync|meta|transcript|low_disk).

   T-118 should define `os: Option<i32>` (the raw OS code, key left out when unknown, like `Warning.os_code`). The `Encode` mapping can be left to T-125, or the contract can be amended to add an `encode` literal. This does not block T-118's grammar, but the contract line needs that note.
4. *`CallId`* is a validated id with the grammar `YYYY-MM-DD_HHMMSS[-n]`. No line logs it, since the log never names the call folder (R20). It is used by `CallNotice::transcript_ready{call}`, which is a closed id, not free text. Keep `CallId` out of every `LogEvent`.

**Size.** One seam (the closed log grammar plus the call value types it needs). The change is additive and changes no behaviour on existing paths, so the task is not large. The points above are naming and wire choices, not new behaviour. Point 1 should be confirmed before T009 writes the serde attributes.

**Approach options.**
- A (recommended): a closed enum per field plus the `EndpointId` newtype, as above. It closes the gap at the one seam. Red test: the extended `diag_format` (every new variant, planted endpoint strings, `seen.len()` 24) and the `call/events.rs` serde and CallId tests, which fail to compile today.
- B: one `CallLine` sub-enum inside a single `LogEvent::Call(CallLine)` variant, like `Dictation(DictationLine)`. It gives the same guarantees and a smaller `LogEvent`. Not recommended only because the `seen` match and the acceptance list name each variant, so B makes the grammar test less direct.
- Rejected: logging the endpoint through a generic string field and redacting it at write time. That puts a `String` field in `LogEvent`, which the decision doc's Don't list forbids.
