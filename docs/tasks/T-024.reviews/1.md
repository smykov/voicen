Checked and accepted (no finding):
- **First `unsafe` in voicen-core** (`diag/native_fault.rs`: `UnsafeCell<Scratch>` + `unsafe impl Sync`). There is no `unsafe_code` lint or decision against it. It is sound by reading. `taken.swap(true, SeqCst)` lets exactly one call ever reach `scratch`, and `taken` never resets. Drop needs `&mut self`. `Scratch` is `Send`, so the auto `Send` holds. The shell's `FaultState` (`win/crash.rs`) repeats the same pattern for its own buffers, with its own `entered` flag. `copy_within` and the `out.len - start` arithmetic stay in bounds, so the "never panics" claim holds.
- **No-allocation claim.** Core is proven by the counting allocator (`record_makes_zero_allocations`, plus a guard test). The shell side I checked by reading the pinned sources:
  - `full_path` writes iterators into fixed buffers;
  - `io_error` uses `from_raw_os_error` / `From<ErrorKind>` (no box);
  - `windows-result` 0.4.1 `Error::from_thread` is `from_hresult(HRESULT::from_thread())` with `ErrorInfo::empty()` (no `GetErrorInfo` call, no allocation);
  - `module_of` writes into the static buffer;
  - `SystemTime::now` does not allocate.
- **Start order.** `diag::begin_session` runs `os_version` → `Session::begin` → `install_panic_hook` → filter → `retain_crash_files`, as the analysis states. Begin-before-hook is forced at compile time (both need `started()`). Retain-after-begin is not pinned (see #1). It is called from `release_parts` only, after `diag::start`, so a second instance (T-052 marker-hash premise) and `--purge-credentials` (`main.rs` exits before `run`) never reach it.
- **The single `RunEvent::Exit` arm** (`lib.rs`). `SessionEnd::end` takes the session out under a poison-tolerant mutex, so `end_clean` runs at most once. The shell has no other `end_clean` call, no other `app.exit` (only `tray.rs` Exit) and no `process::exit` besides `main.rs` (purge). Proven by `the_tray_exit_item_ends_the_session_once` and the installed-app `WM_ENDSESSION(TRUE)` step. The test manages `SessionEnd` directly; the `Parts` → `wire` path is proven by the installed-app step.
