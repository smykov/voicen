## Investigation

**Frame.** Nine Low findings from T-060 P10b. Each reproduces by reading the named file on main 5d4f1fed. This is not a recurrence: the lines share a directory, not a mechanism. The analysis block lists the gaps one by one. Tools: the Serena symbol tools do not index bash or YAML, so I used grep and file reads over scripts/ci, .github/workflows/ci.yml, the Makefile and the T-099 validation record.

**Hypotheses checked.**
- H1, a second path already covers the ci.yml wiring: refuted. Only two make check scripts read ci.yml. release-guard.sh (R1-R14) covers tokens, actions and caches. whisper-model-key.test.sh (K1-K5) covers the restore step's key. No rule names the CMakeCache, CRT or workspace-test lines.
- H2, the opus step (T-117) needs no pin because the CRT step covers it: refuted. opus-cmake-cache.sh checks every `opus.lib` and opusic-sys CMakeCache, which crt-imports.sh does not read. It runs under `!cancelled()` like the others.
- H3, the step order cannot matter: refuted. The build cache restores `target/`, and decisions #142 and T-099 note that a restored cache can hold an older CMakeCache. A checker step moved above the build would pass on stale files. Hence the position rule in I-3. Moving it into another job is loud: no `target/`, and the checker reports none found.
- H4, `exact`'s regex already refuses a trailing newline: true, but it never sees one. Command substitution strips it before the compare. bash also drops a NUL from `$(...)`, so a print-a-terminator fix would still let `2.12.1\u0000` through. Only refusing control characters inside python closes I-2.
- H5, the YAML-escape limit (T-090 r1#2) is open for workflows: refuted from the release-guard.sh header, not by a probe (the sandbox refused the probe run). R6 refuses `\x` plus 2 hex digits, `\u`/`\U` plus 4, `\0` and a backslash before a line break, in every workflow file. So in workflows the gate as a whole catches `"\x63mdkey"` and `"cmd\`+newline+`key"`. Plain or single-quoted folding joins with a space, so it cannot spell `cmdkey`. Only ci-credentials.sh alone misses them. The Acceptance line says the limit is "shared" by R10/R11. In fact R10/R11 rely on R6 (release-guard header, R10 and R11 text). The doc note should say "outside ci-credentials, closed for workflows by release-guard R6". For scripts/ci files, which are not YAML, a PowerShell backtick or bash `$'\x63'` is already under "a name built at run time".
- H6, the class was fixed before: no F-entry or decision names these guard gaps.

**The tripwire (I-3).** Fragments run from the step's `      - ` line to its last line. The fragment for the workspace test is the one `- run:` line. The fetch-model fragment covers S-Y07 (the GITHUB_ENV echo). The Acceptance asks for all five survivors, although S-Y07 is already red in CI by design (`tiny_path` panics). The line after each fragment must have at most 6 leading spaces, as in release-guard R9/R10's 'ended by the next step', so no key such as `continue-on-error` or a second `if:` can be appended. The comment lines above each step stay free. 'libopus built as Release (T-101)' and 'Drop restored opusic-sys build outputs (T-117)' are not in the Acceptance. A developer may add them as fragments, at no extra design cost, but they are not required.

**The tw-wip-run.test.sh flake (gate log core-20261110T170316Z-585a6be): its own task, not T-180.**
- Mechanism, reproduced: `ceiling_hit` runs `all_text | grep -qF "https://example.com/runs/202"` under `set -uo pipefail`. `all_text` is a builtin printf of stdout then stderr. bash line-buffers stdout, so each line is a separate write. grep -q exits after the URL on line 1. A later write of the left subshell can get SIGPIPE (status 141), pipefail makes the pipeline fail, and the `||` branch reports "does not name the run" although stdout holds the URL, exactly as in the log. A loop of the same pipeline (bash 5.2.21, a one-line stdout and a 50-line stderr) failed 1 time in 3000.
- Why not T-180: T-180's scope is the nine T-060 lines above, and tw-wip-run (#241) is none of them. The mechanism is T-181's class (`writer | early reader` under pipefail; T-181 proved it in scripts/licenses/stale-check.sh). This is the class's second occurrence, in another directory. CLAUDE.md says: stop patching and open a `type: rca` task with `recurrence_of: [T-181]`. Its invariant would be "no guard or guard test in scripts/ci or scripts/licenses decides on the status of a pipeline whose reader can stop early". It could add a make check tripwire for the pattern.
- Known instances (grep `| *grep -q` over scripts/ci; other early readers such as `head` or `awk exit` were not searched): tw-wip-run.test.sh (6 `all_text |` sites), crt-imports.sh:57 (`tr <<< | grep -qx`, a Windows CI verdict; it fails only on large dumps), release-guard.test.sh:975, 1022 and 1053, release.test.sh:188, and telegram-failure-branch.sh:46.
- T-180 rewrites the telegram-failure-branch.sh line anyway (I-1) and will use here-strings there. That one instance goes away as a side effect. The rest stays with the rca task.
