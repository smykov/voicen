## Context

Decisions #364 lets a local worktree task (`tw/<ID>`) hand its next stage to the contour through a push of `tw/<ID>` to `task/<ID>`. The state guard refuses an agent that sets `TEAMWRIGHT_WIP_REFS_RE` ("push overrides ... are a person's, in their own terminal"), so on 2026-11-24 every hand-off (T-261, T-222, T-247, T-151) waited for the owner to run the push by hand. Wanted: a narrow entry, by the pattern of `scripts/tw-wip-push` (#219), that the main-tree orchestrator may run: it writes only `refs/heads/task/<ID>` on `origin`, `<ID>` from a worktree on branch `tw/<ID>`, with `--force-with-lease` against the remote's current `task/<ID>` (absent → plain create), and nothing else; `.claude/settings.json` allows only this script for it; the hook refuses the other push forms as today. A task that edits `.github/` is not handed off (#365).

Guard paths (`scripts/hooks/`, `.claude/settings.json`, `make check` pins) change in pairs; `checker: true`, `analysis.decides_on` (P-020).

## Acceptance

- [ ] From the main tree, `scripts/tw-task-push <ID>` pushes the worktree's `tw/<ID>` head to `origin` `refs/heads/task/<ID>` (create, or force-with-lease over the remote's current head) and the pre-push hook lets it through
- [ ] Failure branch: any other ref, a branch that is not `tw/<ID>`, a worktree whose task edits `.github/`, or a lease mismatch → refused, nothing pushed
- [ ] Test that fails without the change: a `make check` pin of the script, its settings allow line and the hook's refusal of other forms (`make check-task-push`), red on today's tree
