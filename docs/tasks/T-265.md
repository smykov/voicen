## Context

Decisions #364 lets a local worktree task (`tw/<ID>`) hand its next stage to the contour through a push of `tw/<ID>` to `task/<ID>`. The state guard refuses an agent that sets `TEAMWRIGHT_WIP_REFS_RE` ("push overrides ... are a person's, in their own terminal"), so on 2026-11-24 every hand-off (T-261, T-222, T-247, T-151) waited for the owner to run the push by hand. Wanted: a narrow entry, by the pattern of `scripts/tw-wip-push` (#219), that the main-tree orchestrator may run: it writes only `refs/heads/task/<ID>` on `origin`, `<ID>` from a worktree on branch `tw/<ID>`, with `--force-with-lease` against the remote's current `task/<ID>` (absent → plain create), and nothing else; `.claude/settings.json` allows only this script for it; the hook refuses the other push forms as today. A task that edits `.github/` is not handed off (#365).

Guard paths (`scripts/hooks/`, `.claude/settings.json`, `make check` pins) change in pairs; `checker: true`, `analysis.decides_on` (P-020).

## Investigation

**Frame.** Observed (2026-11-24): every hand-off push of decisions #364 (T-261, T-222, T-247, T-151) waited for the owner. Expected: the main-tree orchestrator hands a committed `tw/<ID>` to `task/<ID>` by itself, with no general push override for agents (#366).

**Which layer refuses today** (read, not run; Serena does not index shell or JSON, so `Read` and `grep` were used):

1. `scripts/hooks/pre-push` DRAIN: only a remote ref matching `TEAMWRIGHT_WIP_REFS_RE` (default `^refs/heads/wip/`, line 63) skips DRAIN (line 77); a `task/<ID>` push of an `IN_PROGRESS` task is refused (line 126, statuses `CODE_COMPLETE DEPLOYED VERIFIED DONE`).
2. The state guard: `_hookio.py::guard_state` → `shell_overrides_push` returns `push` for any assignment word matching `_PUSH_ENV` (line 801, `TEAMWRIGHT_WIP_REFS_RE` included), in prefix, `export`, `env` or `sh -c` form; hard deny (line 1012). This is the refusal named in the task.
3. `.claude/settings.json`: `deny` holds `Bash(git push --force-with-lease *)` (line 19); `allow` holds only the two `tw-wip-push` rules. `TEAMWRIGHT_ALLOW_PUSH` is ignored under `CLAUDECODE` (pre-push line 45).
4. `scripts/tw-wip-push` cannot do it: `<ID>` comes only from the current branch `tw/<ID>` (lines 47-49), so it refuses in the main tree, and its destination is fixed to `wip/`.

**How the script gets through without a general override.** The state guard reads only the command text, and its own docstring says a script file is not seen. `scripts/tw-task-push` sets the value inside its own process, as `contour-push.yml` does in its push step (line 23, #253): it overwrites any inherited `TEAMWRIGHT_WIP_REFS_RE` with the fixed literal `^refs/heads/(wip|task)/`, unsets `TEAMWRIGHT_ALLOW_PUSH`, `TEAMWRIGHT_PUSH_STATUSES` and `TEAMWRIGHT_DOC_PATHS_RE` (keeps `TEAMWRIGHT_PAUSE_FILE` as an extra pause place, as `tw-wip-push` does) and the `GIT_*` repository and config variables, and then pushes one fixed refspec. The agent still cannot set any override in a command (the guard is unchanged). The exemption covers only `refs/heads/task/<ID>`, which #253 already counts as not a delivery. The pause check in pre-push runs before the WIP exit and still applies. The settings allow is `Bash(scripts/tw-task-push *)` and nothing else. Nothing changes in `pre-push` or `_hookio.py`: they are kit files, outside P-020 scope (decisions #230). Option B, widening pre-push's default, would exempt every push form, not just this one.

**Run from the main tree for a worktree.** The worktrees share refs with the main tree (`git worktree list`: `/projects/voicen.worktrees/T-151` on `tw/T-151` and others), so the main tree resolves `refs/heads/tw/<ID>` directly. The script refuses unless `git rev-parse --git-dir` equals `--git-common-dir` (the main tree, not a linked worktree), and unless `git worktree list --porcelain` has a line `branch refs/heads/tw/<ID>` (compared as a literal). The `<ID>` is the one argument (`^T-[0-9]{3,}$`, the contour's own pattern, `teamwright-agent.yml` push step), never a refspec or an option. The pushed sha must descend from the fork point from `main` (as `tw-wip-push` lines 52-61). Pushing from the main tree has a side benefit. `core.hooksPath` is the relative `scripts/hooks` (`.git/config`), so git runs the main tree's `pre-push`, never the copy on the task's branch. That is the property the contour gets from `HOOKS_FROM` (T-230). This is from git's documented rule (a relative hooksPath is relative to the tree the hook runs in), not run here. A worktree stage session could still call the script by absolute path or after a `cd`. Neither command text matches the allow rule, and the headless launch has no prompt to approve it; this is a named residual. The main-tree check refuses it only when the session runs it inside its own worktree.

**Lease.** `expect="$(git ls-remote origin refs/heads/task/<ID>)"` is the sha, or empty when the ref is absent. The push is `git push --no-follow-tags --no-recurse-submodules --force-with-lease=refs/heads/task/<ID>:<expect> origin <sha>:refs/heads/task/<ID>`. Per the git-push docs (context7 `/git/htmldocs`; host git 2.43.0), an empty `<expect>` means "the named ref must not already exist", so the absent case is a guarded create, not a blind one. A `+` prefix "does the same thing as `--force`", and `--force` disables the lease checks, so the refspec must **not** carry `+`, unlike `tw-wip-push` line 65.
