## Investigation

Investigator, 2026-11-10, main 5d4f1fed. Tools: Serena loaded but not used for these files, since they are shell and small .mjs files, read whole (the index is stale). Reproductions ran on the host with GNU Make 4.3 and bash 5.2.21, the same make the gate's `licenses-stale-guard` uses (host make, offline).

**Frame.** Observed: one `make check` run failed in `licenses-stale-guard` with "NOTICES does not default to THIRD-PARTY-NOTICES.txt in the Makefile", then passed 5 of 5 alone (T-023 review 1 fix). Expected: a deterministic verdict. The other six Acceptance lines are review findings about coverage (T-063 r1, T-094 r1/r2), not observed failures.

**Hypotheses.**
1. *SIGPIPE under pipefail* (the task's guess). It is confirmed if the guard's exact pipeline fails with PIPESTATUS `141 0` on the real dump. Result: **confirmed**, 23 of 2000 (1.15 %), and 300 of 300 with 300 KB after the match.
2. *The database differs under an outer make* (MAKEFLAGS, -j, environment). This would be refuted if the dump with `env -u MAKEFLAGS ...` matches every time. `run_make` already unsets MAKEFLAGS, MFLAGS, MAKELEVEL and MAKEOVERRIDES, and the NOTICES line is in the dump on every failed iteration (only the writer died). Not the cause. The outer environment only adds `# environment` variables, which makes the dump longer and the race likelier.
3. *A second path with the same shape.* In stale-check.sh, the line `if printf '%s\n' "$out" | grep -Eq 'tw-run|docker'` has the same race. It fails open: on a match followed by more output, the `if` turns false and the docker/tw-run hit is not reported. `out` is make's output on three tiny fixtures, so the window is small, but the class is the same. `prereqs="$(printf | awk '...exit')"` races too, but its status is not read, so it is harmless. `shown="$(printf | head -n 12)"` is cosmetic.
4. *This class was fixed before.* Refuted: docs/failures.md and docs/decisions/*.md have no SIGPIPE/pipefail entry, and no task record other than T-023 names it.

**Root cause.** A pipe from a builtin writer into an early-exit reader under `pipefail` makes the verdict depend on scheduling. The fix removes the pipe (here-string), not the pipefail.

**Make database, measured.** On a scratch Makefile, `make -pRrq` prints:

| Makefile line | printed | with `NOTICES=evil` in env |
|---|---|---|
| `NOTICES := X` | `NOTICES := X` | `NOTICES := X` |
| `NOTICES ::= X` | `NOTICES := X` | `NOTICES := X` |
| `NOTICES = X` | `NOTICES = X` | `NOTICES = X` |
| `NOTICES ?= X` | `NOTICES = X` | `# environment` / `NOTICES = evil` |

So `^NOTICES :?= ...` accepts `=` and `?=`. Requiring `:=` alone closes the `=` and `?=` cases. Running the check with a sentinel in the environment tests the property itself (env-immunity), not one spelling. Both are in the approach.

**Coverage gaps, read in place.** `check.test.mjs` `project()` always writes the owned head, so no CLI test sees exit 2 from a refused head. `check.mjs` `main` maps the `readAcceptedList` throw to 2 in its catch. `accepted.mjs` and its BOM test hold a raw U+FEFF (byte check: `grep $'\xef\xbb\xbf'`). `isComment` has two branches, and only the `startsWith(indent + '# ')` one is exercised by an accepting fixture. `fixture-check.sh` never runs cargo-about on a second `accepted`. The licenses.md claim rests on T-094 probes p30, p34-p36, p40, p41.

**Seam and options.** See `analysis.seam` and `analysis.approach`. Option A is recommended: here-strings, a `db_check` function run on the real Makefile (env sentinel) and on `licenses/fixtures/stale-db/<case>/Makefile`, the extended prerequisite set, and the four test and fixture additions.

**Same class outside this seam (not proven, for a follow-up task).** `grep -l pipefail scripts/**` combined with `| grep -q`, `| head` or `| awk ... exit` lists: scripts/ci/tw-wip-run.test.sh (`all_text | grep -qF`, 5 sites), scripts/ci/release-guard.test.sh (several `| head -n 1`, `| grep -q`), scripts/ci/version-stamp.test.sh (two `grep | grep -vq`), scripts/ci/release.test.sh, scripts/ci/telegram-failure-branch.sh, scripts/hooks/commit-msg, scripts/hooks/pre-push. Each depends on the writer and the input size. Most writers are external commands with short output, so none is shown to flake. Recommend that the orchestrator open one task for them, with this task's F-entry as the rule.

**Draft F-entry for docs/failures.md** (the developer writes it in the fix commit): "A guard under `set -o pipefail` piped make's 20 KB database into `grep -q`; grep exited at the first match, `printf` died of SIGPIPE (141), and the guard reported a missing NOTICES default (T-023 gate, about 1 % of runs). Rule: a guard never decides on a pipeline whose reader can stop early; feed early-exit readers from a here-string or a file."

**Recommended exit:** not an rca task. A code fix in one seam (scripts/licenses/), with no owner question.
