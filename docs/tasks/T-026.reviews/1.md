## Deviations reported by the developer

1. **Premise and failure-branch steps skipped on `v*` tags, while the SHA-256 print runs on every ref.** Accepted. On a tag, the stamped tree carries the tag's own MAJOR.MINOR, so #102 would compare the tag with itself. A #103-refused tag would also turn the windows job red, which would skip the release job, so the job could never "fail naming both" (the Acceptance). The release job still runs the same script on every tag, and the wip run proves the pass path and the failure branch. The reason is written in ci.yml and in `ci-toolchain.md`, but the task record does not mention it (finding 1).
2. **MAJOR.MINOR read by running `version-stamp.sh` on a temp copy.** Accepted, and better for P-010: there is no second version reader, and the checkout is never written. `GITHUB_ENV` is unset for that call, otherwise the windows premise would overwrite `VOICEN_VERSION` with `X.Y.1`. No test pins that unset (finding 3).
3. **The release job sets `GH_REPO`.** Accepted. It is harmless: `gh` uses the stated repository instead of inferring it from the checkout's remote. The value is `github.repository` through `env:` and is not secret.
