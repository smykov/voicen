## Context

T-161's analysis included a dry run. `scripts/ci/clippy-lines.sh` scans only `git ls-files`, so a not-owned allow line in a new, untracked file passes a local `make check` (exit 0). It is caught only after `git add -N`, or in CI. This is a guard change: `checker: true`, and `analysis.decides_on` is required.

## Acceptance

- [ ] `scripts/ci/clippy-lines.sh` refuses a not-owned `#![allow(clippy::…)]` line in an untracked new `.rs` file under the scanned roots
- [ ] Ignored files (`.gitignore`) stay out of the scan
- [ ] Failure branch: the self-test (`make check-clippy-lines`) has a case for the untracked file and goes red when the scan drops untracked files
