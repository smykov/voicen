## Context

T-161's analysis included a dry run. `scripts/ci/clippy-lines.sh` scans only `git ls-files`, so a not-owned allow line in a new, untracked file passes a local `make check` (exit 0). It is caught only after `git add -N`, or in CI. This is a guard change: `checker: true`, and `analysis.decides_on` is required.

## Acceptance

- [ ] `scripts/ci/clippy-lines.sh` refuses a not-owned `#![allow(clippy::…)]` line in an untracked new `.rs` file under the scanned roots
- [ ] Ignored files (`.gitignore`) stay out of the scan
- [ ] Failure branch: the self-test (`make check-clippy-lines`) has a case for the untracked file and goes red when the scan drops untracked files
- [ ] The `git add -N <new files>` clause of `.claude/agents/test-writer-core.md` step 5 (T-161, needed only while the scan reads `git ls-files`) is removed in the same change (T-161 review 1, Low #2)

## Investigation

Tools: Serena does not index shell scripts or Makefiles, so I used grep and file reads (scripts/ci/clippy-lines.sh, clippy-lines.test.sh, Makefile, ci-toolchain.md row 207, test-writer-core.md step 5, T-161 record). Git behaviour comes from the local git 2.43.0 and was checked with the dry run below, not from memory. Context7 was not needed because no package API is involved.

**Frame.** Expected: a local `make check` refuses a not-owned token line in any new scanned file. Observed: such a line in an untracked file passes (exit 0) and is caught only after `git add -N` or in CI, where the file has been committed.

**Hypotheses.**
1. The file set comes from the index only. Confirmed: line 54 `git ls-files -z`, and the dry run shows exit 0 untracked and exit 1 after the listing is widened.
2. A second path handles the same concern. The self-test's `real()` helper copies `git ls-files` output, but it builds fixtures and is not the scan, so it can stay. The real-repository case runs the guard itself, so it inherits the fix. No other guard under scripts/ci uses `git ls-files` (checked with grep). core-test-os-answer.sh uses `find`.
3. This class was fixed before. No. T-161 worked around it in role text with `git add -N` (Option B was deferred to this task, decision #200). recurrence_of stays empty.
4. Ignored files would flood the scan once untracked files are read. They do not with `--exclude-standard`: the ignored target/x/ignored.rs was not read (dry run).
5. An intent-to-added file is listed twice. It is not: `--cached` and `--others` do not overlap, and the count was 1.

**Dry run (2026-11-06, throwaway clone /tmp/t164-dry of 7bb02272).**
- Untracked probe, current guard: `clippy-lines: ok: 47 line(s) owned`, exit 0.
- Same probe with the widened guard: `crates/voicen-core/src/t164_probe.rs:2: clippy: ... not owned`, exit 1.
- Ignored `target/x/ignored.rs` with `#![allow(clippy::all)]` only: exit 0.
- After `git add -N` of the probe: refused, listed once.
- `clippy-lines.test.sh` with the widened guard copied in: `ok: 45 cases as expected`.

**Root cause, invariant, seam, approach:** see `analysis`. Exit to the existing contract: the `cannot run` branch for a listed file that is not readable stays as it is. With `--others`, an untracked file that vanishes between listing and reading also lands there, which is correct.

**Recommended exit:** not an rca task; this is a code change at one seam (the ls-files call in clippy-lines.sh), with `checker: true` and `decides_on` as above.
