## Context

Split from T-016 by decision #49 (T-016 analysis, option A). The shell half of the local-model download: `src-tauri/src/local_models.rs` with the commands and `local-model://` events from specs/002 contracts/ipc.md over T-016's core `ModelStore` / `Downloader`; the models dir `paths::data_dir().join("models")` in `paths.rs` (one resolver, P-010); one `Arc<ModelStore>` shared by `SettingsDeps.local_models` (replacing `NoDownloadedModels`, settings_ipc.rs) and the IPC commands; `ModelStore::cleanup_at_start` at startup; the Windows free-space probe behind core's `DiskSpace` trait (a `windows` crate feature flag such as `Win32_Storage_FileSystem`, no new crate). Shell tests only in `src-tauri/tests/*.rs` (decisions #36/#37), built and run in Windows CI. Logging of download outcomes waits for T-008. Note from T-016 review round 1: core's `DownloadError` also has `NotInCatalog` (an id missing from the catalog) and `CannotStart` (the OS refused the worker thread), which have no wire code in specs/002 contracts/ipc.md yet — map both here (and add them to ipc.md).

## Acceptance

- [ ] Windows CI: `local_models_list` reports the catalog with each model's state from disk; a download started through the command emits progress events and ends with the model listed as downloaded; settings validation accepts `builtin_local` with that model (same store)
- [ ] Failure branch: a failed or cancelled download leaves no `.part` file and the model not downloaded; a `.part` left from a previous run is deleted at start — Windows CI tests over a local mock server and a TempDir
- [ ] Test that fails without the change: `src-tauri/tests/local_models.rs` (Windows CI)
