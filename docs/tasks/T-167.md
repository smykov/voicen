## Investigation

**Frame.** Five review lines on the shell's two Credential Manager callers (`credentials::WinCredentialStore`, `win::purge::WinCredentialNamespace`) and their tests. Nothing has failed on CI; three lines are latent correctness or maintainability gaps, two are a toothless test and a missing decisions entry. Everything Windows-side is proven only on `wip/T-167` (P-016).

**How I looked.** Read at HEAD 543ab2a8 with grep and sed (the Serena tools were loaded; these reads were whole small files, so I read them directly). Win32 docs through context7 `/websites/learn_microsoft_en-us_windows_win32_api` (CredEnumerateW, CREDENTIALW). Searched `src-tauri/src` for `fn wide|fn wipe|fn os_code|fn credential_error|encode_utf16().chain`; `src-tauri/tests` for `Cred*W|WinCredentialStore|WinCredentialNamespace|cred_support|SERIAL`; `*.md` for `CredentialNamespace`.

**Hypotheses.**
1. *r1#2 is a plain copy.* Confirmed: `credentials.rs` holds `wide`, `os_code`, `credential_error`, `wipe`; `win/purge.rs` holds `wide`, `credential_error`, `wipe` and imports `super::os_code`. The cause is module placement: `credentials` is `crate::credentials`, and `win::os_code` is private. `autostart.rs::wide` and the inline `encode_utf16` lines in `win/clipboard.rs` are the same kind of copy outside the Credential Manager seam: out of scope, mentioned only.
2. *r1#4: filter and policy disagree on case.* The docs say CREDENTIALW `TargetName` "is case-insensitive"; the CredEnumerateW filter is "a name prefix followed by an asterisk", case not stated. `purge_credentials` filters the listing with case-sensitive `starts_with`. So an entry `voicen/transcription-api`, which `CredReadW("Voicen/transcription-api")` would return to the app (names are case-insensitive), is not removed. Either the filter lists it and the policy skips it (exit 0, key left), or the filter does not list it. Both break FR-021 ("every Voicen entry"). Which one happens is unproven until the Windows test runs. The fix differs only in the adapter (see approach).
3. *r1#3: one bad name fails everything.* Confirmed in code: `WinCredentialNamespace::list` sets `bad_name` and returns `Err(ERROR_INVALID_DATA)` after the loop, and the core trait `list -> Result<Vec<CredentialEntry>, _>` cannot express "these entries, plus N I could not name". Nothing is removed and the exit code is 2. Whether Windows accepts a target with an unpaired surrogate at all is unknown. The red test's premise decides it, and settings.md records the result either way.
4. *r4#10: type pass-through.* `remove` passes `CRED_TYPE(entry.kind)`; correct in code. No test would catch a hard-coded `CRED_TYPE_GENERIC`. Test gap only.
5. *Second path: another place touches Credential Manager.* Found one. `src-tauri/tests/settings_ipc.rs::canary_key_never_in_data_dir_or_log` writes and reads real entries through `WinCredentialStore::with_target_prefix`, with no `mod cred_support;` and no `serial()`. It is the only Credential Manager test in its binary, so nothing races it today (the lock is per binary, and cargo runs test binaries one after another), but the "one home of the lock" rule T-069 r2#4 asks for is already not closed. Product paths: `main.rs` calls only `win::purge::from_args`; the CI step goes through `scripts/ci/credentials.ps1` (its own `CredEnumerateW "<prefix>*"`), which this task does not change.
6. *Fixed before.* T-069 (3ef76c61, 70fc358b) made `cred_support` the shared lock for `credentials.rs` and `purge_credentials.rs`. It did not record the rule in a decisions file or reach `settings_ipc.rs`. No earlier fix of hypotheses 2-4 (git log of the three files: 0dbac71f, 985dcb1a, 77219462, 70fc358b, 3ef76c61). Not a recurrence.

**Recommended (Option A), in order.**
1. Red tests (analysis.approach lists them by name). Core: case rule and unreadable count (Linux gate). Windows: case variant purged, filter case behaviour pinned, a type-2 remove keeps the generic entry, an unreadable name leaves the rest removable with exit 2.
2. `secrets.rs`: `CredentialNamespace::list` returns `Listing { entries: Vec<CredentialEntry>, unreadable: usize }` (name to the developer). `purge_credentials` keeps the policy filter (it is what stops a widening filter, `purge_never_removes_an_entry_outside_the_prefix_even_if_listed`), but compares the prefix bytes with `eq_ignore_ascii_case` (byte-safe: ASCII case changes keep byte length; non-ASCII bytes compare exactly), removes every match, and returns 2 when `unreadable > 0` or a remove failed. The doc comment changes in the same commit.
3. `win/purge.rs`: `list` counts unreadable (null or non-UTF-16) targets instead of failing; blobs are still zeroed for every entry. If test 3b shows the filter case-sensitive, list with a filter that cannot miss a case variant (the store prefix alone when it is non-empty, else NULL) and leave the scope to the policy. Record which one in settings.md.
4. `win/mod.rs`: `pub(crate) fn wide`, `wipe`, `os_code`, `credential_error`. Both callers drop their copies. `is_not_found` stays in `credentials.rs` (its only user).
5. `settings_ipc.rs`: `mod cred_support;` and `let _serial = cred_support::serial();` first in the canary test. The lock tests then run in that binary too. `cred_support/mod.rs` doc: three binaries.
6. Docs in the same commits. settings.md J1 shell paragraph: the case rule, the unreadable rule. windows-shell.md: new section "A shell test that touches Credential Manager takes `cred_support::serial()` first" (invariant I5, defect F-012, what breaks: two tests deleting or reading each other's entries in one logon session, Don't: a binary-local lock or Mutex). failures.md class row `parallel-tests-share-session-state`: replace "No decisions-file statement" with the pointer to that section and to `src-tauri/tests/cred_support/`. contracts/installer-ci.md exit 2: "at least one failed or could not be named".

**Not chosen.** B (document today's bad-name behaviour): smaller, but one foreign bad name blocks the whole purge, against FR-021 and FR-022 "continue". C (raw UTF-16 targets in `CredentialEntry`, so the bad entry is removed too): the widest core change, for an entry no Voicen build writes. It can follow if test 5 shows such names are writable and the owner wants them gone.

**Owner.** None needed. The case rule follows from FR-021 and the documented name semantics. The bad-name rule follows FR-022 and the acceptance's own "remove the rest". `checker: false` stays: no `scripts/ci/**`, `Makefile` or `*.mk` change.

**Residuals.** The ASCII-only case fold (Windows' upcase table also folds non-ASCII; the prefix is ASCII). An unreadable entry under the prefix stays in Credential Manager (exit 2 tells the uninstaller to name it per FR-022).

**Overlap.** None with T-130: T-167 does not touch `lib.rs`, `build.rs`, capabilities, `call_indicator`, `app_acl.rs`, or core `call/`, `settings/service.rs`, `overlay.rs`.
