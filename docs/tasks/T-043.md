## Context

Owner answers (decisions #59, #60): Q2 — the Silero model is downloaded in CI with a pinned SHA-256 (no binary in the repository); Q3 — real voice clips are public-domain recordings (CC0 or an explicit PD dedication), recorded in licenses/manual.json. Split from T-001 by decision #43. Decision #12 and spec 002 R-1 keep native/model code out of voicen-core, so `SileroDetector` lives in `crates/voicen-whisper` and implements core's `SpeechDetector` (T-041). The energy detector cannot reliably tell a long cough from speech; FR-12 on real audio is proven only by Silero on real clips (Windows CI) plus the owner.

Owner decisions 2026-10-12. #136 (OQ-34, option A): this task keeps the detector proven on real clips (the pin and `verify` in core, `SileroDetector` in `voicen-whisper`, the CI fetch and cache, the CC0/PD clips, `silero_clips.rs`, the notices entry) and ships nothing (`deploys: false`). T-102 ships it (the `--config` overlay bundle for `tauri build`, the `dictation.rs` wiring, the install smoke `detector=silero`). #130 (OQ-29): the `voicen-whisper` crate is created by T-099, which this task depends on.

## Acceptance

- [ ] On Windows CI, the Silero detector classifies the real speech clips as speech and the real silence / cough / keyboard clips as not speech
- [ ] The model file's integrity is checked (pinned SHA-256) and its license is listed in the notices
- [ ] Failure branch: a missing or corrupt model makes the detector unavailable, and the gate falls back to the energy detector with the `vad_fallback` warning (no panic)
- [ ] Test that fails without the change: a Windows CI test in `crates/voicen-whisper/tests/`

## Investigation

Tools: the Serena and Context7 tools were not available in this session. Context comes from grep and file reads, from the whisper-rs 0.16.0, whisper-rs-sys 0.15.0 (whisper.cpp 1.8.3) and tauri-build 2.7.1 sources in `.teamwright/cache/core` (the cargo registry of the core image), and from the Hugging Face API for the model metadata.

**Frame.** Observed: every speech decision is made by the energy detector. The shell passes `Err(VadError::Unavailable)` (`src-tauri/src/dictation.rs:119-121`, #62), so the first dictation of a process also writes `vad_fallback`. Expected (FR-12, requirements §8): Silero decides, with a model bundled in the installer, and the energy detector is the fallback only. The energy rule cannot tell a long cough from speech (T-001 Investigation), so FR-12's cough and keyboard rows on real audio can only be proven by Silero on real clips in Windows CI, plus the owner.

**Owner questions of the Context.** Both are answered. Q2 is #60: download in CI with a pinned SHA-256, no binary in the repository. Q3 is #59: CC0-1.0 or an explicit public-domain dedication, recorded in `licenses/manual.json`. `blocked_on` is empty. The Context sentence "Two owner questions block it" is stale; the orchestrator should drop it.

**What exists.**
- The port and the fallback are done (T-041): `SpeechDetector` (`&self`, `Send + Sync`) and `SpeechGate` (latch and exactly one `fallback_warning`).
- The pipeline emits `Warning{vad_fallback}` (`api_pipeline::vad_fallback_warns_once_across_jobs`).
- The diag log already knows `detector=silero` (`diag/event.rs` `DetectorTag::Silero`).
- `sha2` is already a core dependency.
- A CC0 speech clip exists: `crates/voicen-core/assets/connection-test-speech.s16le` (T-046, about 1 s, possibly too short for the speech case).

**What is missing.**
- The `crates/voicen-whisper` crate itself (not in `Cargo.toml` members, no whisper in `Cargo.lock`). T-017's analysis puts its creation in T-017a, pending OQ-29, and says "T-043 should depend on T-017a".
- Any pin for the model file.
- Clips of cough, keyboard and room noise.
- A CI fetch step.
- Bundling.

**Hypotheses.**
1. *The detector can be built over whisper-rs without new consent.* Confirmed. whisper-rs (#9) exposes `WhisperVadContext::new(path, params)` and `segments_from_samples(&mut self, params, &[f32])`, which returns segments with timestamps. The default params are threshold 0.5, min speech 250 ms, min silence 100 ms and pad 30 ms (`whisper_vad_default_params`). The `&mut self` means the detector holds a `Mutex`; jobs are few, and the VAD over 10 min of audio is short next to the transcription.
2. *Loading a bad model file fails cleanly.* Refuted. `whisper_vad_init_with_params` has no try/catch. It reads `str_len` from the file into `std::vector<char>(str_len + 1)` (about line 4785), so a garbage length can throw `length_error` or `bad_alloc`. It also has explicit `throw std::runtime_error` paths (about lines 4852 and 4873). Its `read` lambda ignores short reads. A C++ exception through `extern "C"` aborts the process, so no Rust `Err` is ever returned. whisper-rs also `expect`s on a NUL byte in the path. So the "corrupt model → unavailable, no panic" branch holds only if the bytes are checked against the pin before the native call. That is the invariant.
3. *The same concern is handled on a second path.* There are several gate builders:
   - `dictation.rs` (production);
   - the core tests (`api_pipeline`, `dictation_session`, `local_server`, `diag_pipeline`, `post_process_timeout`, `audio_device`);
   - `pipeline.rs` unit tests;
   - the shell tests (`tray.rs`, `hotkey.rs`).

   Only `dictation.rs` must change. The tests choose their detectors on purpose. Pinned files have one existing pattern, `local_models::catalog` with T-016's hash check while streaming. The Silero pin should follow the same rule (P-010: one source, a URL at a fixed commit, size and SHA-256), but the model is not a user-selectable `ModelId`. A separate small const avoids widening the catalog's shape tests.
4. *Bundling is a config line.* Refuted. tauri-build 2.7.1 canonicalizes every `bundle.resources` source on every shell build (`lib.rs` `copy_resources`, called at lines 760 and 762), and a missing file fails the build script. A `resources` entry in `tauri.conf.json` would therefore break the Linux gate (`check-shell-windows`) and `cargo test -p voicen` unless the model is downloaded first everywhere. The gate would need the network for every check. The fix is to add the resource only for `pnpm tauri build`, through a `--config` overlay (the CLI passes the merged config to the build). The CI fetch step must then run before `tauri build`. The Linux gate stays offline.
5. *The class was fixed before.* No. `docs/failures.md` has no `transcription-pipeline` or VAD entry, so `recurrence_of: []` is right. Risk classes this task touches:
   - `ci-toolchain` (F-001, F-002, F-011): whisper.cpp's CRT against tauri's static runtime once the shell links it; T-017's analysis covers this.
   - `ci-premise-unchecked-before-main`: the fetch, cache and bundling only run in CI, so P-016 wip runs are needed before review.
   - `guard-model`: a new cache step must be a byte-identical fragment under `scripts/ci/cache-steps/`, and its action lines must be in `action-lines.txt`.
   - The fetch is network in CI. A cache keyed by the hash and the download with its hash check are both deterministic. A failed fetch must fail the step, never skip the clip test: a skipped test would be a silent pass.

**Model choice.** `ggml-org/whisper-vad` is MIT on Hugging Face and is the conversion whisper.cpp documents. At commit `9ffd54a1e1ee413ddf265af9913beaf518d1639b` it holds:
- `ggml-silero-v5.1.2.bin`: 885 098 bytes, sha256 `29940d98d42b91fbd05ce489f3ecf7c72f0a42f027e4875919a28fb4c04ea2cf`;
- `ggml-silero-v6.2.0.bin`: 885 098 bytes, sha256 `2aa269b785eeb53a82983a20501ddf7c1d9c48e33ab63a41391ac6c9f7fb6987`.

These values come from the HF tree API (LFS oid and size), read on 2026-10-12. This is metadata only; the CI fetch is the cross-check, as in T-016 and #49. v5.1.2 is proposed. v6.2.0 is acceptable only if the clip test is green with it on whisper.cpp 1.8.3. The `licenses/manual.json` entry gains the version, the source at the commit and the hash (#60).

**Decision rule.** Speech means at least one VAD segment, with a minimum total speech duration, from `segments_from_samples` with fixed params. The constants are pinned red-then-green by the real clips. If no constant makes the real cough clip non-speech without dropping a speech clip, that is a finding for the owner. It must not be tuned away clip by clip.

**Size verdict: large.** There are two seams with different proofs, and a dependency on undecided work.
- The detector seam (core pin and verify, the native detector in `voicen-whisper`, the CI fetch, the clips) is proven in Windows CI by the crate's tests. Nothing ships.
- The shipping seam (the build overlay, the shell wiring and an install smoke assertion) changes the installer. It needs whisper.cpp linked into the shell, which brings in T-017's CRT alignment and OQ-30 (CPU baseline).

Doing both in one task would mix two CI-only proofs, the same reason T-017 was split. Options (draft OQ-34):
- **(A), recommended.** T-043a is the detector proven on real clips, as the title says. It depends on the task that creates `voicen-whisper`, T-017a under OQ-29 (A). T-043b ships it: the bundle overlay, `dictation.rs` building the gate from `SileroDetector::load(resource_dir/…)`, and an install smoke check of `detector=silero` with no `vad_fallback` on a loaded hold (ci.yml step "A hotkey hold on a loaded launch…"). It depends on T-043a and on T-017's shell link (OQ-30).
- **(B)** One task. That means several red wip runs with mixed causes.
- **(C)** T-043 as written (detector only), with bundling left unowned. FR-12 "bundled in the installer" would stay unmet with no task, and `licenses/manual.json` would keep claiming "bundled in the installer" for a model the installer does not contain.

**Recommended approach (A), T-043a, red first.**
1. Linux gate: core tests for the pin and verify. A missing file, a wrong size and a wrong hash give `Unavailable`. A fake file with its hash computed in the test passes. The pin has the right shape (64 lowercase hex, a URL at the pinned commit, the size).
2. Windows CI on `wip/T-043`: `crates/voicen-whisper/tests/silero_clips.rs`. Real speech clips give `Ok(true)`. Real silence, cough and keyboard clips give `Ok(false)`. A missing model or a truncated or flipped copy gives `Err(Unavailable)`, and the native loader is never reached. `SpeechGate::new(load(bad), EnergyDetector::new()).decide(..)` gives `detector == "energy"` and `fallback_warning`.
3. Then the fetch step, the cache fragment, the clips and their manual.json entries, and the NOTICES regeneration.

Risk: an external download in CI; the cache plus the pin make it deterministic. Rollback: remove the crate module and the CI step; the shell is untouched.

**Recommended exit**: n/a (feature task, not rca).
