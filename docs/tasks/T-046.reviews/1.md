## Verdict rationale

The core design follows the analysis seam and holds its invariant:
- The single request goes through `engine_for` → `transcribe`, with the form's timeouts through `Timeouts::from_settings` only.
- It reuses the save's `normalize`, `key_step` and `validate`, filtered to the used fields.
- The key is read once, never while `Unavailable`, with a read-only view and no write path.
- The DNS failure maps to `CannotReach` in the tester, leaving `classify` unchanged.
- The result and the log line are built only from kinds, `host_port` and an `Instant` latency.

The 35 core tests, the log-line tests and the wire pin pass, and the Windows CI run is green at the reviewed code sha. Four Medium findings remain, and Medium blocks in this project (`review.blocking: medium`):
- the shell Acceptance test is built on the released-port premise F-004 refuted (#1);
- two new timing ceilings add flake risk without bite (#2);
- the stated log-level choice has no test (#3);
- the spec task list, the plan and the diagnostics-log decision file still describe the old design (#4).

Each needs a small change. None needs a decision above the task. #5 and #6 are non-blocking follow-ups.
