## Context

FR-13 (fields, per-engine required fields per v4), FR-21 (defaults incl. v4 additions), NFR-04 (keys only in Credential Manager), spec 004 clarifications Q1 (all-or-nothing save) and Q4 (unreadable file → backup + defaults). Pure core with fakes for `CredentialStore`, `SettingsFile`, `Autostart`; the Windows Credential Manager implementation lives in `src-tauri` and is tested on Windows CI.

## Acceptance

- [ ] A fresh data folder yields exactly the FR-21 v4 defaults
- [ ] A valid save persists atomically (tmp + rename) and a reload returns the same values; keys never appear in the settings file
- [ ] `startup_action` / `blocked_actions` decide first-run, tray-only start and engine-none behaviour (spec 004 analyze HIGH fix)
- [ ] Failure branch: empty base URL for the API engine → save refused with field id `api.base_url`, nothing written, old values kept; an unreadable settings file → kept as a timestamped backup, defaults loaded, notice raised — verified by core tests on a temp dir
- [ ] Test that fails without the change: `crates/voicen-core settings tests (validation, atomic write, unreadable-file branch)`
