**Frame.** A feature: the `calls` section and its rules do not exist. Symptom-equivalent: the T012 tests cannot be written against any current symbol.

**Hypotheses checked.**
1. *Second path for loopback*: confirmed risk. `settings::url::is_insecure_remote` holds the only loopback match; a second copy for the provider host would drift (T-015's bite comments in `url::tests::is_insecure_remote_table` list exactly the near misses: `localhost.`, `foo.localhost`, `127.1.2.3`, `LOCALHOST`). Extract one `is_loopback_host(&url::Host)`.
2. *Second path for the write probe*: confirmed risk. R19 runs the probe at save (this task) and at every Record start (T-125 T022). One function, called by both.
3. *Defaults outside `defaults()`*: `docs/decisions/settings.md` forbids field-level `#[serde(default)]` and defaults built in consumers; the section follows the container-default pattern.
4. *Earlier fix of this class*: none. `docs/failures.md` has no settings/call-settings entry; class `call-settings` is new. Not a recurrence.
5. *Probe on every save*: would make every unrelated save fail while a chosen root (USB drive) is unplugged; the same reason the autostart step runs only on change (settings.md, autostart "Don't"). Probe only when the effective root changed.

**Findings the developer needs.**
- `validate` is pure by its module doc, so the probe and the earlier-roots append belong in `SettingsService::save`, after step (3) validate and before step (4) hotkey prepare (the earliest step with a side effect), so a refused root releases nothing.
- The equality rule lives in `validate` over the whole draft, so "from either side" (changing the dictation hotkey to the call hotkey, or the reverse) is one rule. `parse_hotkey` rejects non-canonical text (`hotkey::tests::rejects_non_canonical_text`), so compare parsed values; a call-hotkey grammar error is also refused on `CallHotkey` with the existing `hotkey_code` mapping.
- Edge: a release-1 file whose dictation hotkey is already `Ctrl+Alt+R` loads fine (no validation on load), but then every save is refused on the Calls tab's field until the call hotkey changes. Worth a test and a line in the decision doc; not a reason to change the default without the owner.
- **Names (decision #196).** Wire ids `calls.hotkey`, `calls.reminder`, `calls.primary_language`, `calls.storage_root` (variants `CallHotkey`, `CallReminder`, `PrimaryLanguage`, `StorageRoot`, as data-model.md and the Acceptance name them); codes `hotkey.equals_dictation` (`HotkeyEqualsDictation`), `storage.unwritable` (`StorageUnwritable`); primary language reuses `language.unsupported`. `FieldId::ALL` 27 -> 31, `ErrorCode::ALL` 15 -> 17, new arms in `as_str` and in the tests' `expected_field_id` / `expected_error_code`. contracts/ipc.md "Settings commands" still writes `callHotkey` / `storageRoot` / `primaryLanguage` and `unwritable{reason}`: the developer amends that sentence to the dotted ids and the `reason` field in the same commit (docs follow the change).
- **Primary language fill (decision #196 (1)).** The container default stays `defaults(None).calls` (`en`), because a container default cannot see `ui_language` (the limitation `settings/mod.rs` documents). The one load path, `load_or_init` (the only `from_slice::<Settings>` in non-test code, grep), calls a new `settings::parse_file`, which after deserializing checks a private presence view and fills a missing or null `calls.primary_language` from the loaded `ui_language` (`UiLanguage` en/ru are both in `WHISPER_ISO_639_1`). How it differs from the container-default rule: it is the only value derived from another field of the same file; it is applied once, after deserialization, only to a file read (FirstRun, Reset and Unavailable get it from `defaults(os_tag)`, which sets it from the resolved `ui_language`), never to a `SaveRequest` and never in a consumer. The developer adds it to docs/decisions/settings.md "Defaults come from one function" as the one named exception, with its test.
- **`reason` (decision #196 (2)).** `FieldError { field, code, reason: Option<UnwritableReason> }`, `reason` omitted from JSON when None (`skip_serializing_if`). `UnwritableReason` is Copy/Eq/Hash, so `FieldError` keeps its derives, Copy included. Variants (engineering choice inside the closed enum the owner chose, aligned with `diag::log::LogsUnwritableReason` and T-118's `missing`/`access_denied`/`other`): `missing`, `not_a_folder`, `relative`, `access_denied`, `disk_full`, `other`; never the path or OS text. Every existing wire shape is unchanged (`refused_post_processing_on_empty`, `test_connection_invalid_off_tab` stay byte-equal); `first_run_view` and `saved_insecure_api` change because the view gains `calls`; a new `refused_storage_unwritable` entry, pinned by its own core test like `e2e_settings_wire_fixture_refused_post_processing_matches_core`, gives G41 a real refusal with a reason. The log line keeps `field:code` (diag/format.rs), so T-118's log grammar is untouched. The TS `FieldError` type is not strictly decoded, so the extra key breaks nothing before G41.
- **LangCode (decision #196 (4)).** `pub struct LangCode(&'static str)` in `settings/mod.rs` next to the list, `LangCode::parse(&str) -> Option<LangCode>` through `is_lang_code`, `as_str`, Serialize as the code. `is_lang_code` replaces the inline `WHISPER_ISO_639_1.contains` in the speech_language rule, so there is one membership test. The settings field is stored as a `String` (like `speech_language`), so a bad hand-edited value is a field error, not a whole-file Reset; data-model.md's `LangCode` / `Hotkey` column is the logical type. T-123 and T-136 build on `LangCode` (both already `depends_on` T-120).
- **Probe: (A) port, recommended.** `settings::roots` (new file in the seam): `CallRoots` trait (`default_root`, `probe`), `UnwritableReason`, `FsCallRoots::new(default_root)` on std::fs, and `reason_of(io::ErrorKind)`. The settings core owns the trait, as for `CredentialStore` / `HotkeyRegistrar` (settings.md "The consumer owns the shared trait"); T-125/T-126 call `CallRoots::probe` at Record start. Reasons for (A) over (B): the delete-failure branch of the Acceptance is testable only through a fake (on the Docker gate tests run as root, so permission tricks do not fail); the default root `data_dir/calls` reaches core without a second `%LOCALAPPDATA%` resolver (J2: `load_settings_with` already gets `data_dir`, its signature does not change); the diff reaches src-tauri under (B) as well (the `FieldError` literal in src-tauri/tests/hotkey_registrar.rs), so (B) saves no P-016 run.
- **Relative, empty and missing roots — derived from the spec, not open.** Empty: `Some("")` is normalized to `None` (data-model: `None` = the default; one encoding). Relative: refused with reason `relative` (a relative path would resolve against the process working directory; R19 needs a fixed folder). Missing: a chosen root is never created and is refused with `missing` — spec FR-002 and T-126 refuse a missing root at Record start with `reason=missing`, which only exists if the probe does not create it. The default root is created by the probe (`create_dir_all`): it is the app's own folder (StorageRoot `default`, removed by the uninstaller, FR-041) and without it the first Record on a fresh install would be refused as `missing`, against spec US1 scenarios 1 and 3 ("first use ... call mode starts"). The probe file is opened with create+truncate, not create_new, so a probe left by a crash between create and delete does not block every later save. Path equality is `Path ==` (component-wise, case-sensitive); `C:\Calls` and `c:\calls` would both be kept in `earlier_roots` — harmless for listing, left as is.
- **Earlier roots and server-owned fields.** The settings window sends the whole draft (`draft.ts::saveRequest`), so `save` takes `earlier_roots`, `last_combination`, `warned_hosts` and `indicator_position` from the snapshot in force before validate. On an accepted root change it appends the old effective root (the default path included, when the old one was `None`) unless present and removes the new effective root from the list. The developer records this in docs/decisions/settings.md.
- **"A host is never logged".** The settings service logs nothing; `ProviderHost` has no Display and a Debug that does not print the value; the closed log grammar (T-118) is the structural guarantee.
- **i18n ownership (T-119 record, decisions #198).** T-120 adds `settings.field_label.calls.hotkey`, `.reminder`, `.primary_language`, `.storage_root`, `error.hotkey.equals_dictation` and `error.storage.unwritable` in EN and RU (forced by `every_field_id_has_label_text` / `every_error_code_has_catalog_text`). `error.storage.unwritable` has no `{reason}` placeholder, because `FieldMessage.svelte` renders `t(id)` without arguments. The per-reason texts and the "...: {reason}" composition belong to the Calls tab (T-155, G41), the only consumer of `reason`.
