## Context

Option 5 of #360. `tw-gate` already keys results by tree (`.teamwright/logs/gate/<area>.json`, `key` = tree) and returns a cached pass in the same checkout, but the contour's fresh checkout per hop loses it, and the review hop re-runs the full gate (T-157 review: 54 min). Wanted: the implement hop's gate stamp (or the green `ci.yml` `make check` on `wip/<ID>` at the same tree sha) is accepted by the review hop's gate when the tree is identical. This changes the gate's trust rule: the analysis names exactly what is trusted (stamp carried how, produced by what, tree compared how), and the owner confirms it in decisions before code.

Measured 2026-11-24 (decisions #360): local `make check` 18 min in CI, 50-54 min on the shared host (`.teamwright/logs/gate/runs.jsonl`).

Guard paths (`scripts/tw-gate`, `scripts/ci/`, workflows) change with their pins; `checker: true`, `analysis.decides_on` (P-020).

## Acceptance

- [ ] A review hop on a tree whose green gate stamp (same tree key) exists from the implement hop, or a green full `ci.yml` on that sha, takes the gate as passed in seconds and records which evidence it reused
- [ ] Failure branch: any byte of the tree outside `docs/tasks/**` differs (rebase, an extra commit, an uncommitted file), or the evidence is missing / red / unreadable / from another command or tree → the full gate runs (decisions #363)
- [ ] A pass of the same gate command and key under another record name (`core`, `ui`, `_top`) is reused (decisions #363)
- [ ] Test that fails without the change: a `scripts/ci/*.test.sh` case for each reuse and refusal branch, red on today's tree

## Investigation

Problem investigator, 2026-11-24. Tools: Serena loaded but not needed (all seams are shell or YAML, read with Read/grep); context7 `/actions/checkout/v5` for `clean`; local `.teamwright/logs/gate/runs.jsonl` (main tree only; the runner host's `RUNS_DIR` is not reachable from here, so no contour gate record was inspected).

**Frame.** Observed: a contour review hop runs the full `make check` again (T-157 review: 54 min), although the implement hop ran it on code that has not changed since. Expected: the review hop takes the gate as passed when trusted evidence of a green `make check` on the same content exists. Symptom vs guess: "the record is lost by the fresh checkout" is only half of it. The other half is shown below: even in one checkout, the record could not hit.

**Hypotheses.**
1. *The fresh checkout loses the record*: **confirmed.** `actions/checkout@v5` keeps `clean: true` (git clean -ffdx). `.teamwright/logs/` is gitignored. `rec lookup` reads only `$RECORD`. The hop's logs are kept write-only, in `RUNS_DIR/<run id>/logs` and in the artifact.
2. *Even a carried record misses, because the key is the whole tree*: **confirmed.** The voicen areas have no `gate_command`, so `_tw_py` sets `kind=top` and leaves the scope empty, and `scope_key` returns the whole tree. That tree includes `docs/tasks/**`. Between the implement gate and the reviewer's gate call, the tree always changes under `docs/tasks/`: the `NEEDS_REVIEW` commit (status, `implemented_by`, `## Tests`) and the reviewer's own record, written first. The technical-writer's commit may also change `docs/**` outside `docs/tasks/`. Local proof that the class exists: 28 of 61 reruns after a PASS differ from it only under `docs/tasks/**`, which is 11.6 h of gate time.
3. *The same concern is handled on a second path*: **confirmed, twice.** (a) Gate records are per name (`core.json`, `ui.json`, `_top.json`), and each name runs the same `make check` on the same key. 43 keys ran it more than once; F-027 saw two of these runs overlap. (b) ci.yml's Gate job runs the same `make check` at the exact sha of the review head (wip/<ID> = task/<ID> head after implement), and tw-gate has no input for it.
4. *The review gate requires a gate stamp*: **refuted.** `review-gate.sh` never checks a gate run. `reviews/<n>.gate.json` is the reviewer-identity stamp of the review record. Gate runs are T1: only the role text asks for one. The kit template says `scripts/tw-gate --for-task` / `scripts/tw-gate <area>`; the local `code-reviewer.md` says `make check`, which the test guard turns into `tw-gate`.
5. *This class was fixed before*: no earlier task or F-entry for gate reuse across checkouts. Related: F-027 (duplicate overlapping runs, filed as kit feedback), #144 / T-083 (CI skips `docs/tasks/**`-only pushes), gates.md › Gate stamps (the same problem for review records, solved with committed stamps).

**What each evidence source proves (the trust question for the owner).**

| Evidence | Produced by | Carried how | Tree compared | Can the session forge it? | Extra |
|---|---|---|---|---|---|
| E1: implement hop's tw-gate record | tw-gate in the implement session's tree, on the self-hosted runner, with the runner's cached image tags (preflight does not rebuild an existing tag, so a Dockerfile change in the task is not exercised) | restore `RUNS_DIR/<implement run id>/logs/gate/` (host-local, writable by any session as the same OS user) or download the artifact (GitHub-kept, but its content was written by that session) in a pre-session step; the run id must be found (the dispatcher has no input for it today); `root` must equal, and the log file must exist (lookup checks `-f log`) | its `tree` was taken **before** the status and docs commits → hits only with a key that leaves those out; technical-writer edits outside `docs/tasks/` miss | yes: it is a JSON file in a gitignored directory, as today in one checkout | works without T-249 |
| E2: green ci.yml run on `wip/<ID>` | GitHub-hosted job, clean checkout of the sha, images built from that tree, the same `make check` | T-249's `ci-read` job result file (headSha, conclusion, run url; no token in the session, #350), or T-263's `workflow_run` input | `headSha^{tree}` against the working tree: an exact commit match at the review head; only the reviewer's own record differs (`docs/tasks/`) | the file sits in the workspace before the session and can be overwritten, but the same run is what P-016's `CI:` line must cite before `CODE_COMPLETE` (checked in the main tree by the orchestrator's plain `gh`), so a forgery is caught by a check that already exists | today the review hop starts while CI runs: it waits for the run either way (P-016) |

**Which tree comparison.** Strict whole-tree identity (the Acceptance wording "any byte differs") never hits in the review hop: the reviewer's record is in the tree before its gate call, and the status commit is in it after the implement gate. A key without `docs/tasks/**` hits. It changes what the gate's key covers. Two existing owner rules already treat that set as outside `make check`: ci.yml `paths-ignore: ["docs/tasks/**"]` (#144) and P-016's "only `docs/**` changed after the cited sha". I searched the `check` closure (Makefile recipes and the non-comment lines of `scripts/ci/*.sh` and `scripts/licenses/*`) for a runtime read under `docs/` and found none. That is a text search, not proof. `docs/tasks/<ID>.mutants/` and `.checks/` are used by tw-mutants and tasks, not by `make check`. If the owner takes the exclusion, the Acceptance failure branch reads "any byte outside `docs/tasks/**` differs".

**Kit vs this repository.**
- Kit (not editable here; ask upstream in `docs/kit-feedback.md`): the review and implement SKILL order (gate before docs and the status commit; reviewer spawned without an earlier edit), the `code-reviewer` template (record written first), `review-gate.sh` (no gate check), and the tw-gate design (per-name records, whole-tree key for top-level gates).
- Repository: `scripts/tw-gate` is kit-rendered (`installed.json` hash equals the file; the template differs only by `{{GATE_COMMAND}}`). A change here is a local edit with precedent (#145, #304, #325), and `/teamwright:update` would overwrite it, so the feedback item is needed. Also in this repository: `teamwright-agent.yml` (job body before the session; the header, contour-push and tail fragments stay as they are), `scripts/ci/tw-gate.test.sh` and the Makefile target (guard paths: `checker: true`), `docs/process/gates.md` › Gate runs, and the `docs/decisions/ci-toolchain.md` guard table.

**Options.**
- **A (recommended): A1 + A2 (+ A3).** A1: the whole-tree key leaves out `docs/tasks/**` (one literal prefix in `scope_key`). This alone also removes the 28 local docs-only reruns on the shared host, and `tw-test --_key` inherits it. A2: step 3 accepts a ci.yml result file (path in an env var set by the stage step), but only for a gate whose command is the top-level `gate_command` with no `generate_command`. Conditions: `conclusion == success`, the headSha exists locally, and its filtered key equals the current key. The answer is `PASS (reused: ci.yml <url> @ <sha>)` plus a runs.jsonl record with `cached_from`. A3: the lookup also takes another name's record with the same command and key. Why it removes the cause: the evidence sits at the review sha, and the key ignores exactly the record writes. Red first: cases 1–6 of `approach`. Risk: a future `make check` target that reads `docs/tasks/` would get a false reuse; a tripwire in the test (a grep of the `check` closure for `docs/tasks`) is a candidate, but it is a text model, so the owner decides it under P-020. Depends on T-249 (or T-263) for the evidence; until then A1 + A3 still help locally. Rollback: revert tw-gate; the records stay compatible (same JSON fields, `cached_from` already exists).
- **B: A1 + carry E1.** A pre-session step restores the implement hop's `logs/gate/` (from `RUNS_DIR` or the artifact). It needs no T-249, but it trusts a file the implement session could write, depends on one runner host and on the run id, misses whenever the technical-writer edited `docs/**` outside `docs/tasks/` after the gate, and its local gate never rebuilt the images. Red first: the same tests 1 and 6, plus a workflow-step test.
- **S: strict identity + E2.** The Acceptance holds word for word. The reviewer must run tw-gate before it writes its record: an order change in the kit-managed role file and against the kit template. Any docs/tasks touch before the call misses. It is fragile, and every local docs-only rerun stays.
- **C (rejected):** give `core`/`ui` their own `gate_command` to get scoped keys. `make check` checks `scripts/ci/`, workflows, the Makefile and the licenses, which lie outside the area dirs, so a scoped key would reuse a PASS that does not cover the change.

**Owner questions (before code).** Q1: the trust rule: E2 only (A), E1 too (B), or strict (S). Q2: may the key leave out `docs/tasks/**` (A1); if so, the Acceptance failure branch changes as above. Q3: A3 (cross-name reuse) here, or as its own task. Q4: `depends_on: [T-249]` (or T-263) for the CI path.
