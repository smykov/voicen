## Context

FR-16 (default on, N = 20, range 1–100), NFR-06.

## Acceptance

- [ ] 25 dictations with N = 20 → the 20 latest shown, copy puts the text in the clipboard
- [ ] Failure branch: history turned off → stored entries deleted, nothing more written; Clear → list empty and file deleted; failed/empty/cancelled dictations create no entry — verified by core tests and Playwright
- [ ] Test that fails without the change: `crates/voicen-core history tests; e2e/history.spec.ts`

## Investigation

Investigator, 2026-11-18. Tools: Serena (`find_referencing_symbols` on `delivery::deliver`, which returned nothing, so not proof of absence) and grep and file reads for Rust, TS, markdown, YAML. `make check` not run (shared tree).

**Frame.** This is a feature task from spec 005, not a defect. Expected (FR-16, NFR-06): the last N delivered final texts are kept locally, can be copied again and cleared, and turning history off deletes them and stops writing. Observed: only the settings side exists.

**What exists already (from T-004 and others):**
- `settings::HistorySettings` (`enabled` default true, `size` default 20), `settings::validate` range 1..=100, `FieldId::HistoryEnabled/HistorySize`, `ErrorCode::HistorySizeRange`, the Settings History tab (`src/lib/settings/tabs/History.svelte`), and `SettingsTab::History`, so 004's open-settings request can already target the tab (`ShellRequests::open_settings`).
- `SettingsService::subscribe()`: the published apply channel. The tray language follower (`src-tauri/src/tray.rs`) is the precedent for a follower.
- `clock::Clock`: the wall-clock port. Its module doc already names history.
- One clipboard writer: `platform::Clipboard::set_text_excluded_from_history`, with the process's single `Arc<dyn Clipboard>` (`docs/decisions/calls-window.md` I4).
- `paths::data_dir()`: the single data-directory resolver.
- `test_support::TempDir` in core, so spec T001's `tempfile` dev-dependency is not needed.
- `serde_json` is already a voicen-core dependency.

**What is missing:**
- `crates/voicen-core/src/history/`.
- A history hook at delivery.
- `TrayAction::OpenHistory`. `tray::tests` currently asserts `"history"` is an unknown menu id; that assertion changes in this task.
- `src-tauri/src/history.rs`, a `history` capability, and the `history_*` commands in `APP_COMMANDS`.
- `src/routes/history`, `src/lib/history/`, `e2e/history.spec.ts`.
- The `docs/architecture.md` data-dir row ("later history") and a `docs/decisions/history.md` area file.

**Where delivery is decided.** It happens in core, not in the shell. `Pipeline::release` calls `delivery::deliver` once. Its `Ok(result)` branch is the only place a text counts as delivered (outcomes `Pasted` / `CopiedOnly` / `CopyManual`). Failed, NoSpeech and `ClipboardUnavailable` jobs leave by other branches. Retries pass through the same `release`. So spec T013's alternative ("if 001 places the delivery outcome in voicen-core, these run on the Linux host at that seam") applies. The record hook goes into core and is tested on Linux, not in the shell.

**Hypotheses checked:**
1. *A second delivery path exists.*
   - Call mode's `calls_copy_markdown` writes the clipboard too. But it copies a stored call transcript, not a dictation result, and spec 005 is scoped to "final transcripts" of dictation. So it must not record.
   - No other `deliver` caller was found (grep over `crates/` and `src-tauri/`).
2. *Recording via `PipelineObserver`/`DictationEvent` would be simpler.* Refuted as a design: the observer feeds `diag::LogObserver`, and `DictationEvent::Delivered` deliberately carries no text (FR-20). The text must travel on a separate port that never reaches the log.
3. *This class was fixed before.* No: `class: history` has no earlier tasks, and `recurrence_of` is empty.

**Design points for the developer (inside the spec, no product change):**
- **Port.** A `TranscriptSink` trait (`fn delivered(&self, text: &str, engine: EngineLabel)`) as a required field of `PipelineDeps`. It is called once in the `Ok` branch after `deliver`, with the same `text` that was delivered: the post-processed text, or the raw text when post-processing was skipped.
  - Required, not defaulted: a defaulted no-op would let the shell forget the wiring silently (P-013).
  - Cost: ~13 `PipelineDeps { .. }` constructors in core tests, shell tests and `src-tauri/src/dictation.rs` get a no-op or fake sink.
- **Recorder.** The production sink is a core recorder that holds:
  - `Mutex<History<FileHistoryStore>>` and `Arc<dyn Clock>`, for `ready_at_ms`;
  - a change callback, which the shell uses to `emit_to("history", ..)`.

  It never fails the job (NFR-07, SC-004). Errors go to the log as op + `io::ErrorKind`/Corrupt + counts, through a new `diag` warning kind, never text.
- **Engine label.** Mapped from the job's `settings::EngineKind` (`Api`/`BuiltinLocal`/`LocalServer` → wire `"api"`/`"local"`/`"server"`) plus that engine's model name from the job's settings snapshot. Reuse the settings enum rather than a second engine enum (P-010; the contract allows it).
- **Settings follower.** In core: a function that reads `SettingsService::subscribe()` and calls `apply_settings(enabled, size)`. The shell only spawns its thread. Tested through the real `SettingsService` save path (P-013, spec T022).
- **Window.**
  - One `history` window built only on its own opener thread, the `call::open_calls` pattern (`calls-window.md` I2). A second open focuses the existing window; closing destroys it.
  - Grants: label `history` gets exactly `history_get`, `history_copy`, `history_clear`, event listen, `settings_get` (UI language) and 004's open-settings command (`docs/decisions/ipc-acl.md`; `src-tauri/tests/app_acl.rs` pins it).
- **Event name.** The ipc contract says `history-changed`. Every other app event uses `scheme://name` (`settings://changed`, `calls://changed`, `overlay://state`). Rename it to `history://changed` in `specs/005-transcript-history/contracts/ipc.md` in the same commit. This is a naming consistency fix, not a product decision. Keeping `history-changed` also works.
- **Tray position.** Calls, Settings, History, Open logs, (Retry), Exit. This follows spec 001 FR-001's "Settings, History, Open logs" inside decisions #197's order, so no owner decision is needed.

**Options:**
- **A (recommended).** Implement as above: core module + sink port in `PipelineDeps` + core follower; the shell is thin; UI per spec.
  - Red first: `history::tests` C1 (25 records with N = 20) and the pipeline sink test.
  - Rollback: revert the commit. The data file is only `history.json*` in the data dir, and 006's uninstall removes it.
- **B.** The shell records from the `JobReport` returned to `dictation.rs`. Rejected: `JobReport` carries no text, so adding it there would put text into a type that flows to the controller and log. It would also make the record path Windows-CI-only.
- **C.** Split T-022 into three teamwright tasks (core / shell / ui) along spec phases. Same design, smaller reviews; it is the orchestrator's call. Otherwise one task in the order core → shell → ui, with the Acceptance tests as listed.

**Privacy (FR-20, NFR-04, NFR-06).**
- What is stored: text, `ready_at_ms` and the engine label only; no audio. Storage is unencrypted in `%LOCALAPPDATA%\Voicen\history.json`.
- `HistoryError` holds only op + kind (contract C8). The sweep test is spec T023.
- `history_copy` errors carry only `not_found` / `clipboard_unavailable`.
- No HTTP in the module (C12).

**Not a guard change.** No path under `scripts/ci/` or `scripts/licenses/`, no `Makefile` or `*.mk`, and no new dependency (so `THIRD-PARTY-NOTICES.txt` is unchanged), so `checker: false`. If the developer ends up adding a `make check` tripwire, the task needs `checker: true` and `decides_on` first.

**Owner questions:** none. Spec 005 settles the product behaviour, including the off-state window confirmed 2026-10-02. Clipboard failure creating no entry follows spec 005 T013 ("outcome delivered or copied-only").
