## Context

From T-043 review 2 finding #1. In CI run 39375257460 (wip/T-043 @ b5b82e6, windows job), `crates/voicen-whisper/tests/transcribe_wav.rs` took 265.55 s for 10 tests. In run 39366493906 it took 236.81 s. `WhisperModel` asks for min(available parallelism, 8) ggml threads (`crates/voicen-whisper/src/lib.rs:36`, `:169`), and libtest runs the tests in parallel on a 4-vCPU runner. T-043 found that ggml-cpu's barrier is a pure spin wait, so oversubscribed threads cost far more than they add: Silero went from minutes to 10.7 ms per decision at one thread. Whisper's graphs are large and may gain from several threads in a single run, so the Silero answer does not carry over. One transcription has to be measured alone and under the harness's parallelism. Then choose the engine's thread count, the test binary's concurrency, or both. The production case, one transcription with a VAD decision next to it on a user's machine, feeds T-102 and NFR-01.

**Abort assertion without a clock (Acceptance 5, T-099 v3#N2).**

*Why the current test does not bite.* It has two checks. (1) `clock reads >= 1`: `WhisperModel::transcribe` calls `abort.requested()` itself after `state.full` returns, so with limit zero that one read happens even when neither stop callback is installed. The check is always met. (2) `aborted * 4 <= baseline`: the only real check, a ratio of two wall-clock readings, which load can push either way. That is the F-013/F-021 shape: the clock decides the verdict.

*What cannot carry a clock-free check (searched, with source):*
- The test's own clock. `Abort::requested` latches (`speech_model.rs:64-72`): after the first true it returns without reading the clock, so the reads after the stop, which are exactly the work to be bounded, are not counted. A stepping clock that fires at read K counts only the reads before the stop.
- whisper.cpp's timing figures. `whisper_get_timings` (`whisper.h:445`, `src/whisper.cpp:4245`) reads `ctx->state` only. whisper-rs builds the context with `whisper_init_from_file_with_params_no_state` (`whisper_ctx.rs:55`) and transcribes on a separate `WhisperState`, so `ctx->state` is null and the call returns null (`:4246`). Its fields are also `ggml_time_us` durations, so wall-clock again. `n_encode`/`n_decode` (`:843-844`) have no public per-state accessor (`whisper.h`, searched for `timings` and `_from_state`).
- A counter inside `abort_requested` / `encoder_may_start`. It disappears with the callbacks, so the mutant from v3#N2 (both removed) would read 0 and pass.
- A progress-callback counter. whisper.cpp calls `progress_callback` once at the top of each main-loop iteration (`:7001-7006`). It would bite, but it adds a production callback only for the test. It shows nothing that the segment count misses: with only `encoder_may_start` removed it also reads 1.

*What carries it: whisper.cpp's segment count of the run.* `whisper_full_with_state` clears `result_all` at the start of every run (`:6801`). It computes the mel (`:6803-6808`), and then, at the top of the first loop iteration, asks `encoder_begin_callback` and `break`s on false (`:7012-7016`) before the first `whisper_encode_internal` (`:7020`). With a limit-zero `Abort`, `encoder_may_start` returns false at that first call, so the run ends with `whisper_full_n_segments_from_state` (`whisper.h:631`; whisper-rs `WhisperState::full_n_segments`) = 0. If both stop callbacks are removed, the aborted call is the same computation as the unaborted baseline on the same audio and model, so it ends with the baseline's segment count, which the test asserts is > 0 (60 s of the clip repeated every 2 s). That makes the assertion deterministic on any load. If only `abort_requested` is removed, `encoder_may_start` still stops before the first window (0 segments). If only `encoder_may_start` is removed, the first encoder graph runs to its end, because the sched helper passes no abort callback (`:190`, `:2406`), and the abort check after it (`:2455`) makes `whisper_full` return -6 with 0 segments. That bounds the work to one window, and the test does not tell this case apart. That is acceptable: the v3#N2 mutant is "both removed", and whisper.cpp exposes no per-state encode count that could separate it.

*What the assertion does not cover, by design:* the mel of the whole input (`:6803-6808`) runs before any callback and cannot be aborted. It is linear in the audio length and not decided by the `Abort`. This is written down in the test comment and in `docs/decisions/builtin-engine.md`, not hidden behind a time bound.

*Surface it needs.* The test holds `Box<dyn SpeechModel>`, and `transcribe` returns `Err(LocalEngineFailed)` whenever the `Abort` fired (decision #133), so the trait shows neither the segments nor the text. Under D2's rule (doc(hidden), no settings field, no env variable), it needs a concrete load that returns `WhisperModel`. `SpeechModelLoader::load` boxes that load, so there is still one load path. It also needs `WhisperModel`'s segment count of the last run (`state.full_n_segments()`). No core change: `Abort` and `SpeechModel` stay as they are.
