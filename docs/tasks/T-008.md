## Context

Narrowed by decision #64 (analysis Q3): T-008 keeps core `diag` (typed events, closed-output formatter, rotation ≤ 10 MiB total at every moment, 7-day retention, Degraded mode, `LogObserver`) and the shell start/settings/reconcile/cleanup lines, in one deploy; the one-time notice and the tray "Open logs folder" item move to T-054. Defaults taken (analysis): no model name or host in the log (spec 006 FR-005/006 — user text; bounded newtypes later); FR-20's three timings plus `duration_ms` (Acceptance reworded); `changed=<field ids>` omitted (not in SaveOutcome; noted in spec 004 R-11); the failed `.part` removal log is a release-2 follow-up. T-008's core lands before T-006 wires the session's observer (T-051 takes a `PipelineObserver`). FR-20 (rotating, 7 days / 10 MB, timings press→first frame, stop→text→paste), FR-18 start line, NFR-04. Typed `LogEvent`s only (no free text), `AppPaths` for the data folder; "Open logs folder" in the tray. Replaces the skeleton's ad-hoc start line in `src-tauri/src/lib.rs`. Also owns the settings log allowlist lines (spec 004 T035; decision #23), including that a base URL's query string is never logged (decision #30). Also logs the startup autostart reconcile result (`ReconcileAction::as_str`: none/written/removed/failed, R-11), which `settings_ipc::load_settings` currently discards (T-014 review round 1 #2); and the `settings://changed` bridge's thread-spawn error, today an `eprintln!` (T-030).

## Acceptance

- [ ] One dictation writes one line with engine and the FR-20 timings (plus duration_ms) and no transcript text
- [ ] Rotation keeps ≤ 10 MB in total and drops files older than 7 days
- [ ] The Windows CI smoke still finds `voicen <version> (<commit>) started`
- [ ] Failure branch: log folder not writable → the app keeps working and the log goes Degraded with one callback (the user-facing notice is T-054); a transcript string passed into any log API does not compile (typed events) — verified by core tests on a temp dir and a compile-fail test
- [ ] Test that fails without the change: `crates/voicen-core/tests/diag_{format,log,observer,pipeline}.rs`, `tests/settings_log.rs` and the `compile_fail` doctests in `src/diag/mod.rs` (red commit bbf683f); shell: `src-tauri/tests/diag.rs` (Windows CI)

## Investigation

Analysis 2026-10-04. Tools: Serena indexes only TypeScript (decision #3), so the Rust code was read with grep and file reads over `crates/`, `src-tauri/src`, `src-tauri/tests`, `.github/workflows/ci.yml`, specs 001/004/006 and `docs/`. Context7 was not needed, because no third-party API is used: the design is std only. Facts about the error kinds come from a probe run in `voicen-rust:1.99`.

**Frame.** FR-20 asks for a rotating log in `%LOCALAPPDATA%\Voicen\logs` (7 days, ≤ 10 MB) holding version, commit, engine, the timings and errors. It must never hold transcript text, audio or keys (NFR-04, P-009). Today the app has one append of a free-form start line (`lib.rs:67-79`) and four facts that are dropped or sent to stderr (`settings_ipc.rs:62`, `:90`; `lib.rs:145`, `:170`). `DictationEvent` exists but nothing in the release app consumes it. This is a need, not a defect.

**Hypotheses.**
1. *A logger already exists or a crate is needed.* Refuted. No `log`/`tracing` logger is set (grep `set_logger|subscriber|tracing|log::` in `crates`, `src-tauri/src`). The crates come in only through tauri (Cargo.lock), and without a logger their output is dropped. A crate would not help: `tracing-appender` has no size or total cap, and every logging facade accepts formatted strings, which is the P-009 leak class (spec 006 R1). Std only is enough, so this is **not an owner question**. For local time, `chrono` is on the #9 consent list and already in Cargo.lock (0.4.45), but core does not need it. Core formats the time std-only with `clock.rs`'s `civil_from_days` and takes the UTC offset from a port. The shell fills the port from `chrono::Local` or Win32 time-zone info (only a `windows` feature flag).
2. *The events already make the log safe.* Partly true. `DictationEvent` is `Copy` (guarded by `dictation_event_is_copy`), and `no_event_or_failure_carries_key_query_or_transcript` (`tests/api_pipeline.rs:1012`) proves that no event's `Debug` carries the key, the query or the transcript. But `engine`, `detector` and `failure` are `&'static str`. `Engine::kind` is an open trait method (`engine/mod.rs:22`; T-017 and T-018 implement it in other crates), and `String::leak` yields a `&'static str`. So echoing those strings does not give a closed allowlist. The fix: diag maps them through its own literal tables, and an unknown value becomes `other`.
3. *One line per dictation can be joined from the events.* Not as they are. `JobFinished`/`Delivered` carry `seq`, `SpeechGate` carries `recording`, and `RecordingStarted` (press → first frame, emitted by T-006) carries `recording` (`events.rs:41-82`, `pipeline.rs:207-292`). A join by event order holds only while `process` is serial. `pipeline.rs:64-69` allows it to run concurrently, and T-011 will run it that way. Adding `recording: RecordingId` to `JobFinished` (still `Copy`) plus `RecordingId::get()` (asked for in T-001 Notes) makes the join exact. Closing rules: `Delivered` for a text outcome, which always follows `JobFinished{Text}` in `release`; `JobFinished` for no-speech or failed; `RecordingEnded{TooShort}` for a discarded recording. The map of open records is bounded.
4. *A second path writes the log.* Confirmed, and it is to be removed. `log_start` is used by `run()` and by the shell test `src-tauri/tests/settings_ipc.rs:442`, which scans the log dir for the canary key. The four stderr lines are listed above. `remove_part` (`local_models/download.rs:483`) swallows its error inside core, where no log port exists.
5. *This class was fixed before.* No. `docs/failures.md` F-001..F-005 are about CI, guards and test timing, so nothing belongs to `diagnostics-log` and `recurrence_of: []` stands. The closest history is T-003 review 2 #2, a contract overclaim about the base-URL query that was found in review, not an incident. Its rule "no code path logs a base URL until T-008" is in `docs/decisions/settings.md:43`. This design never logs a URL, host or model name at all (Q1).

**Spec gap found.** In spec 006 data-model "LogWriter", retention runs after a roll and deletes while the total of `voicen*.log` exceeds 10 MB. At that moment the active file is near 0, so the rolled files may keep up to 10 MB, and the active file then grows to 2 MB: 12 MB on disk, which breaks FR-20. The invariant has to be rolled total ≤ `total_bytes − roll_bytes`, with the roll done before a line would cross `roll_bytes`. Fix the data-model wording in the same commit.

**Failure branches on the Linux gate.** The core container runs as uid 0, so a read-only directory cannot be tested there: root ignores the mode bits. Probed instead in `voicen-rust:1.99`:
- a file at the logs path: `create_dir_all` returns `AlreadyExists`, and opening under it returns `NotADirectory`. Map both to `NotADirectory` by checking the metadata.
- `voicen.log` as a symlink to `/dev/full`: the write returns `StorageFull`, which maps to `DiskFull`.

`PermissionDenied` is proven in Windows CI with an ACL-denied directory.

**Root cause / invariant / seam / approach:** see the `analysis` block. Rejected options:
- *B, one line per event, correlated by `rec=`/`seq=`.* No state and nothing lost on a crash, but it breaks FR-20's acceptance ("a line with the engine and the three timings"), so it needs a requirements change by the owner.
- *C, a summary event `DictationFinished` from the pipeline.* `FinishedRecording` would carry press → first frame, which changes T-042's controller and T-001's event contract. A too-short recording still needs its own line.

Option A changes one field in `events.rs` and keeps all logic in core.

**Red tests.** Listed in `analysis.approach`. They go in `crates/voicen-core/src/diag/*` unit tests plus `crates/voicen-core/tests/diag_pipeline.rs` (the redaction run reuses the `api_pipeline` harness and `common::refused_timeouts()`, F-005) and `tests/settings_log.rs` (spec 004 T035). Each must fail before the code exists.

**Size verdict: large.** It spans two seams: core `diag` (about 8 red-test groups) and the shell wiring with its Windows tests. It also has hooks into T-006. The recommended split is Q3.

**Questions** (none blocks the owner; defaults apply unless the owner says otherwise):
- **Q1 (non-blocking, owner):** spec 006 FR-005/FR-006 want the model name and the host in the log. Both are user-entered text. Default: T-008 logs neither, so no user string can reach the file. Bounded `ModelName`/`HostName` newtypes can be added later if wanted. R-11 already says "no hosts" for settings lines.
- **Q2 (non-blocking):** the Acceptance says "four timings", but FR-20 and spec 006 say three. Default: log FR-20's three plus the recording's `duration_ms`, and reword the Acceptance.
- **Q3 (non-blocking, orchestrator):** split. T-008 keeps core `diag` plus the shell start and the wiring of the facts that exist today. Both stay in one deploy because the smoke must keep finding `(<commit>) started`. A new P1 task, depending on T-006 and T-008, takes:
  - the one-time `notice.logs_unwritable` through T-006's notifier (EN and RU keys);
  - the tray "Open logs folder" (`tauri-plugin-opener`, #9);
  - the Windows test where an ACL-denied logs dir still delivers a dictation.

  Order: T-008's core lands before T-006 wires `PipelineDeps`, so no placeholder observer ever ships. Without the split, the Acceptance line "shows a one-time notice" cannot be met before T-006.
- **Q4 (non-blocking):** R-11's `settings save … changed=<field ids>` is not in `SaveOutcome`. Default: omit it and log the outcome, errors and warnings; note the change in spec 004 R-11.
- **Q5 (non-blocking):** the failed `.part` removal inside `Downloader` needs a log port in core, and local models are release 2 (#62). Default: a P3 follow-up. T-008 logs only the cleanup failure at start (`lib.rs:145`), as a typed warning with no path and no OS text.
- **Proposed T3 guard (non-blocking):** `make check` fails when Cargo.lock names a logger backend (`tauri-plugin-log`, `env_logger`, `tracing-subscriber`, `log4rs`, `flexi_logger`, `simplelog`). It decides on raw lockfile names, which no tool reinterprets (F-003 rule).

**Touch points with T-006** (analysed in parallel):
- `PipelineDeps.observer` and T-006's capture/hotkey worker use the same `Arc<LogObserver>`. There is no second observer and no no-op observer in release.
- The worker emits `RecordingStarted{hotkey_to_first_frame_ms}` and `RecordingEnded` on it.
- A capture failure at press has no event today (`recording/mod.rs:271`). T-006 adds a `Copy` variant carrying `MicCause`, never `CaptureError::Other(String)`. The exhaustive match in `LogObserver` makes a variant without a log mapping a compile error.
- T-006 must not use `eprintln!` or direct file writes for diagnostics.
- `Log::open` and the Started line come after T-006's single-instance check, so only the primary writes. Otherwise two processes would share `voicen.log` and race on the roll rename.
- Both tasks edit `run()`. T-008 changes `log_start` → `diag::start`, `load_settings` (also returns the `ReconcileAction`) and `build_app`/`spawn_change_bridge` (they take the `Arc<Log>`). Whichever task lands second converts the `lib.rs:170` stderr line.
- CI: `Get-StartCount` (`ci.yml:158`) reads only `voicen.log`. A run that crosses local midnight would roll the file, so it should count across `voicen*.log`.
