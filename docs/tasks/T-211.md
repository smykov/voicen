## Context

Part 4 of the T-007 split (decision #274). From T-051 review round 1 (#2): the dictation session's FIFO worker can die on a panic in `Pipeline::run_job` (unwind builds: tests, dev); `dictation.rs` then drops every later job (`let _ = queue.send(job)` in `stop_recording`), the overlay stays on Processing and nothing is shown or logged. Detection seams named by the T-007 analysis: a drop guard in `run_worker` (like `StopInFlight`) that marks the worker dead under the lock, clears `queued`, shows the notice and writes a log line; and the `send` result in `stop_recording`. Depends on T-007, which adds the `Notifier` the notice reaches.

Owner decisions (#274): Q1 (a) — new catalog id `failure.internal` (en "Dictation stopped because of an internal error. Restart Voicen.", ru "Диктовка остановилась из-за внутренней ошибки. Перезапустите Voicen."), on the overlay and as a toast; the tray Error state stays until restart (the menu-open rule does not clear it); every later press is blocked with the same notice, so no audio is recorded only to be dropped; one `warning kind=dictation_worker_stopped` line. It is not a `FailureReason`: it belongs to no job and cannot be retried. Q2 (a) — release builds keep `panic = "abort"`: a `run_job` panic ends the process; the crash file and the next start's previous-session verdict are the trace; no crash notice, no watchdog.

## Investigation

Investigator, 2026-11-16. Tools: Serena `get_symbols_overview` on `dictation.rs`; reads of `dictation.rs`, `recording/mod.rs`, `recording/indicator.rs`, `src-tauri/src/win/toast.rs`, `src-tauri/src/dictation.rs`; grep for warning-kind wiring, `catch_unwind`, `is_toast_surface`, catalog ids and failures (text and config the language server does not index).

**Frame.** Observed (T-051 r1 #2, Open line in `docs/decisions/dictation-session.md`): a panic in `run_job` in an unwind build ends the worker; later jobs are dropped at the queue, overlay stays Processing, nothing shown or logged. Expected (#274 Q1 a): `failure.internal` once (overlay + toast), tray Error until restart, later presses blocked with the same notice and record nothing, one `warning kind=dictation_worker_stopped`. Release builds abort (Q2 a), so the visible branch exists only in unwind builds (tests, dev).

**Hypotheses.**
1. No exit guard in `run_worker` — confirmed: the loop returns only on `recv` Err or `shutdown`; an unwind leaves state untouched.
2. A second path handles the same concern — checked: `stop_recording` (`let _ = queue.send`) and `retry` (`send` Err → `retry_dropped`, silent) both see the dead channel but neither reports it; `hotkey_pressed` never asks. So three inputs, one missing state.
3. Tray Error can be made sticky with the existing `error` flag — refuted: `tray_menu_opened` and `end_job(Delivered)` clear it; a separate controller input is needed.
4. Class fixed before — `docs/failures.md` searched (panic, worker, silent, hang, Processing): no F-entry for this class. Nearest: the `StopInFlight` guard (T-051, a panic in the release path freezing publication; invariant in `docs/decisions/dictation-session.md`, no F-entry) — same pattern, other thread. F-024 (`error-fake-masks-origin`) is relevant only to test design: `let _ = queue.send` is a swallowed error, and each failure-branch mutant must go red at its own site.
5. T-007 dependency missing — refuted: T-007 `DONE` (bcfddaad), `SessionDeps::notifier` / `Locked` drain present; T-210 `ShellNotifier` toasts every id except `notice.logs_unwritable`.

**Ordering detail the developer must keep.** `jobs` (the `Receiver`) is owned by the worker closure and dropped after `run_worker` unwinds; a guard local to `run_worker` drops first. Setting `State::queue = None` and the stopped flag in that guard's single lock section closes the window in which `stop_recording` (which sends under the lock) could still send into a receiver about to drop. `finish(Ok)` counts the job before the send, so the stopped check must come before `finish` (or the refusal must remove the entry), not after it.

**Testing an unwind panic in core.** Tests build with unwind. A `Reply` closure for the Rig's `engine_factory` that `panic!`s runs inside `FnEngine::transcribe` → `Pipeline::run_job` on `dictation-worker`; the test thread is not affected (the panic message goes to stderr), and `DictationSession::drop` ignores the join error. Observe through `FakeNotifier::calls()`, `FakeIndicator` and the observer's events with the Rig's existing waits; for the queued-job branch, gate the engine (block job 1 until job 2 is queued, then panic).

**Recurrence:** none (no F-entry of this class).

**Recommended scope:** one seam (dictation session worker exit, with the controller state it consults), area `core` only; the i18n, contract and warning-kind additions are rows on existing tables. Small; no Spec Kit needed. src-tauri unchanged.

**Small points settled by the invariant rather than by the decision text (flag for review, not blocking):** (i) a Retry click after the worker ended shows `failure.internal` (today: silent `retry_dropped`); (ii) blocked presses emit no `PressBlocked` event (`Blocked` is a settings gate reason, and #274 asks for one log line); (iii) `retry_available` should go `false` at the transition so the tray Retry row is not offered for work that cannot run; (iv) tray HotkeyError still outranks Error (indicator priority unchanged). If the owner wants otherwise on (i) or (iii), it is a one-line change within the same seam.
