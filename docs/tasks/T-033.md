## Context

Found by the T-030 analysis (decision #34). The `windows` job of `.github/workflows/ci.yml` has been red since T-003: runs 37147276182 (c0e2113) and 37151218166 (fcc04be). `cargo test --workspace` (ci.yml:57) stops at the voicen-core doctest `secrets.rs:16`, which fails to link on windows-latest (LNK2001 `mainCRTStartup`, `memcpy`, `__CxxFrameHandler3`). The last green run, 37044674209 (0e73b52), had no runnable doctest, so no doctest has ever linked on this runner; unit, integration and `voicen_lib` test binaries link fine. Because the job stops there, `pnpm tauri build`, the silent install and the smoke never run, so no `deploys: true` task can be verified (T-030 waits on this task). Investigator's candidate, unproven: `cargo test --workspace --all-targets` on Windows (skips doctests; they keep running on the Linux gate) — the analysis must find the cause before choosing it.

## Acceptance

- [ ] The `windows` job of the CI run for this task's commit is green end to end: tests, `pnpm tauri build`, silent install, launch and the commit check in the start log line
- [ ] Every voicen-core doctest still runs in some gate (the Linux gate at least) — none is silently dropped; if Windows skips doctests, that is written down with the reason in the docs the analysis names
- [ ] Failure branch: a doctest that fails (not one that fails to link) still turns a gate red
- [ ] Test that fails without the change: the CI run of the parent commit (red, run 37151218166) vs this task's run (green)
