## Context

Found by T-078's investigation (`docs/tasks/T-078.md` ## Investigation, evidence and draft options). reqwest 0.13.5's `connect_timeout` wraps the system lookup. When the resolver does not answer, the error carries connect+timeout and no dns flag, and `failure::classify` returns `CannotReach{host}`. The client drop then blocks until getaddrinfo returns: about 20 s in total on Linux with a blackholed resolver (`TW_DOCKER_ARGS="--dns 192.0.2.1"`). That is past FR-24's 5 s connect limit. `local_models::download` builds its own client with the same behaviour. Which reason is right is OQ-22 (owner).

## Acceptance

- [ ] A lookup that gets no answer within the connect timeout maps to the reason the owner picks in OQ-22, pinned by a `failure::classify_table` row and the `contracts/openai-transcription.md` row (moved here from T-078 Acceptance line 4)

- [ ] Test that fails without the change: the never-answering-resolver test above
