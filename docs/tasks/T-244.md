## Context

This task comes from a T-239 review follow-up: r1, Medium, toothless-test (`docs/tasks/T-239.follow-ups/r1.md`). The owner decided on 2026-11-22 to give it its own task (/teamwright:sprint §1b, decisions #337).

T-239 turned `drained()` (`crates/voicen-core/tests/call_session.rs:1987`) into a progress wait. It calls `common::timing::eventually_progressing(BUDGET, count, done)`. The wait fails only when the consumer's summed sample counts stop growing for `BUDGET`. The helper `eventually_progressing` has its own tests. The call site and its `count` closure have none. If the closure is wrong (it returns a constant, counts the wrong tracks, or ignores the consumer), the wait becomes a plain `BUDGET` ceiling again. That brings back the 20 s timeout that T-239 removed, and no test would show it.

## Acceptance

- [ ] A call-site test drives `drained()` over a `FakeSubtitles` that delivers samples with a delay, while the writer is held so that the backlog drains for longer than `BUDGET` in total but keeps progressing. `drained()` returns without failing.
- [ ] Failure branch: the same rig with the consumer stalled (no sample-count growth for `BUDGET`) → `drained()` fails with its "the writer stopped consuming" message, not by hanging. The test checks the panic.
- [ ] Test that fails without the change: the new call-site test goes red when the `count` closure in `drained()` is replaced with a constant (bite check, cited under `## Tests`).
