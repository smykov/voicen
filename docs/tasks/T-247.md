## Investigation

2026-11-23 investigator (ANALYZE). Tools: Serena loaded, but the shell crate is `cfg(windows)` and line-1 pinned, so symbols were read with grep and file reads (said per the task prompt); tao source read from `.teamwright/cache/core/_usr_local_cargo_registry/.../tao-0.37.1`. No build or test run.

**Frame.** Observed: two copies of the overlay-class executor and of the restyle + no-activate show; only the indicator clears `WS_CAPTION`. Expected: one helper, one decision. No user-visible overlay defect is shown: tao's `WM_NCCALCSIZE` (event_loop.rs, flags without `MARKER_DECORATIONS`) removes the visible frame, so the overlay's caption bit is a style fact, not a drawn frame (T-130 review 2 #1 says the same).

**Hypotheses.**
1. Copy instead of extraction in T-130 (confirmed: same arms, same comments, same error helpers in both files; `git log` shows the indicator added in b0d05cf8 / 0ae53189 after the overlay's b38997cf, 26035b7e).
2. The overlay really has `WS_CAPTION` (confirmed by source: `to_window_styles` sets it unconditionally; same builder flags made the indicator's S2 red). Not observed on the overlay window itself; the red test below is that observation.
3. A third path shows an overlay-class window (refuted by grep of src-tauri/src for `SW_SHOWNOACTIVATE`, `SetWindowLongPtrW`, `catch_unwind`; Serena does not index this crate, so grep is the evidence).
4. This class was fixed before (refuted: no `docs/failures.md` entry of class `overlay` or a copy-drift class; the only earlier sighting is T-130 r1#1, which predicted this drift).

**Differences the helper must keep.** Overlay: ex +`WS_EX_TRANSPARENT | WS_EX_LAYERED | WS_EX_TOOLWINDOW`, -`WS_EX_APPWINDOW`, no pre-show placement, returns bool. Indicator: ex +`WS_EX_TOOLWINDOW`, -`WS_EX_APPWINDOW`, pre-show placement (`place_indicator` + `SetWindowPos(SWP_NOACTIVATE | SWP_NOSIZE | SWP_NOZORDER)`) that runs only after a successful restyle, returns the placement. Executor: indicator's Destroy also resets `placed` and closes the webview after a successful destroy; its post-destroyed goes through `Shared::post`, the overlay's through `Shared::destroyed`.

**Size.** One seam (one new shell module), two callers, one doc section; not spec-tool work. Proof is Windows CI only (P-016 `wip/T-247` run); no owner machine needed. Advice: `surface: none`, `deploys: false` stay (internal shell refactor plus one style bit; the shell tests are the proof).
