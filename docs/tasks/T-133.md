## Investigation

**Tools.** Serena loaded via ToolSearch: `get_symbols_overview` and `find_symbol` on `crates/voicen-core/src/settings/gate.rs` (`second_launch_action` body; `LaunchArgs` not found in `crates/voicen-core/src`). Text search (grep/find) for README files, README checkers in `Makefile`/`scripts/ci`/workflows, and spec/decision text. context7 not needed (no library API involved).

**Frame.** Observed: `README.md` is English-only and says nothing about call recording, consent, call storage or `--call record`; no Russian readme exists. Expected (spec 007 FR-021, FR-045; US1 #14; tasks.md T037; requirements §3 1a row; #165, #184): a recording-consent section in EN and RU with a sample opening phrase, the unencrypted-storage statement, and the `--call record` trade-off. Not trivial: four degrees of freedom (placement, timing vs unshipped feature, legal wording, CI evidence), so `skipped:trivial` does not apply.

**Findings.**
1. No RU readme anywhere (find outside caches: only `README.md`, a licence fixture, the call-mode brief). The Acceptance says "`README.md` has ... in English and Russian", which reads as one file with two blocks.
2. FR-045 says "the README **and the help**"; requirements §3 says "a README / help section". There are no help docs in the repo, and spec Assumptions say "Consent help lives in the README and the project's help docs; no in-app link is required". No task owns "the help". The requirement (the higher source) is met by the README alone; the spec's "and" is stricter wording. See D5.
3. The feature is not built yet: `settings::gate::second_launch_action` still takes `launched_by_autostart: bool`; `LaunchArgs` / `--call` exist nowhere (T-121 in ANALYSIS, the effect is T-128). Call storage (T-116 and later), the reminder (FR-035) and `/PURGECALLS` (T-156) are also not shipped. A README that describes them as present would be ahead of the code (D2).
4. Facts the section should carry, with their source: consent is the user's (#165); recording always visible, no secret mode, start reminder on by default and can be turned off (#165, FR-035); unencrypted, readable by the Windows user (FR-021, NFR-16); default root `%LOCALAPPDATA%\Voicen\calls` (plan Storage); kept on uninstall, removed only by an explicit "yes" or `/PURGECALLS`, a moved root never deleted (FR-041, #197); `voicen.exe --call record` to the running instance, any same-user process can start a recording, indicator always shown (#184). Optional, outside the Acceptance: the other party's audio goes to the API provider when the engine is not local (FR-031 provider notice); see D6.
5. Gate: nothing in `make check` reads `README.md` (no doc-sync, link or markdown lint; `check-ui` = svelte-check, eslint, vitest, e2e). No test can fail without the change; the proof is review against the Acceptance and EN/RU parity.
6. P-016 applies literally: `README.md` is outside `docs/**`, so the task needs a `CI:` line from a green `wip/T-133` run. The task's Context ("Docs only: no CI evidence needed (P-016)") contradicts that. ci.yml `paths-ignore` is only `docs/tasks/**`, so a README push runs full CI anyway.

**Recurrence check.** `docs/failures.md` F-001..F-022 and its Classes section: no entry or class about README, user docs, or docs ahead of code (all are CI premises, flakes, guard gaps, an overlay flicker). `git log -- README.md`: one commit (`d37f0080 docs: add README`). Not a recurrence; no class.

**Owner decision points** (recommendation first):
- **D1 Placement of the Russian text.** Recommended: one `## Recording calls` section in `README.md` with an English block and a `### Русский` block, as the Acceptance says. Alternative: `README.ru.md` linked from the top of `README.md` (whole readme translated or only this section).
- **D2 Timing against the unshipped feature.** Recommended: land now, independent as planned, with one line saying call mode is in development and not in a release yet (the README already has a Status line); the line goes when 1a ships. Alternative: `depends_on: [T-128, T-156]` so the README describes only shipped behaviour.
- **D3 Consent wording and the sample opening phrase (owner's, legal).** Recommended draft facts: "You are responsible for getting the other party's consent; the rules differ by country. Voicen cannot notify them." Sample phrase EN: "Just so you know, I'm recording this call to keep notes. Is that OK with you?"; RU: «Предупреждаю: я записываю этот разговор, чтобы не потерять детали. Вы не против?» The owner approves or replaces both; no legal advice is implied.
- **D4 CI evidence.** Recommended: follow P-016 as written (diff outside `docs/**` → push `wip/T-133`, cite `CI:`), and fix the Context line. Alternative: the owner rules README-only diffs exempt, which is a P-016 amendment (decisions row + PRINCIPLES change), not a task-level choice.
- **D5 "and the help" in FR-045.** Recommended: the README is the help for 1a (requirements say "README / help"); align spec FR-045 wording to "README (the project's help)" in a spec-only edit. Alternative: open a task for in-app or separate help docs.
- **D6 Provider note.** Recommended: add one sentence that with an API engine the other party's audio goes to the chosen provider (FR-031) — relevant to consent. Alternative: keep strictly to the three Acceptance facts.
