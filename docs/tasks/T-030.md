## Context

Split from T-003 by the re-plan (decisions #20, #21). The single Windows implementation of T-003's `CredentialStore` over Credential Manager (`CredWriteW` / `CredReadW` / `CredDeleteW`, generic, `CRED_PERSIST_LOCAL_MACHINE`, absent = Ok, targets per `KeySlot`); it replaces spec 001 T028. Also the IPC commands `settings_get` / `settings_save` over T-003's `SettingsService`, the event `settings://changed`, the data directory passed to `SettingsService` (one resolver in the shell, P-010), and the shell wiring of `subscribe` (tray rebuild, notifier). Subscribers that need other tasks' implementations (001 hotkey registrar, 002 model store, 005 history) are wired by those tasks. `src-tauri` is built and tested only on Windows CI (decision #5), so this task deploys.

## Acceptance

- [ ] Windows CI: a key written to each `KeySlot` reads back equal, delete makes it absent, a missing target reads as absent (Ok), and the key bytes never appear in `settings.json` or the log
- [ ] Windows CI: `settings_save` twice over an existing `settings.json` replaces it (rename over an existing file on Windows, unverified on Linux — T-003 investigation)
- [ ] `settings_get` returns T-003's `SettingsView` (keys as presence only); `settings_save` returns `Saved` / `Refused(field errors)` and emits `settings://changed` only on `Saved`
- [ ] Failure branch: Credential Manager write refused → `settings_save` returns `Refused(key_store_failed)`, the settings file is unchanged and no other storage is used (NFR-04, no fallback) — verified by a Windows CI test with an injected failing store
- [ ] Test that fails without the change: `src-tauri/tests/credentials.rs and src-tauri/tests/settings_ipc.rs (Windows CI)`
