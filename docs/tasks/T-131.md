## Investigation

Investigator, 2026-11-10, on main at c333b775. Serena was loaded but code was read with grep/sed and file reads (TS/Svelte routes and JSON fixtures are not Rust symbols; the core facts were confirmed by reading `call/indicator.rs` and `call/session.rs`). No test run: the task is a new page, red is "route missing". Context7 not needed (no new library API; `data-tauri-drag-region` is already confirmed against pinned tauri 2.12.1 `drag.js` in T-130's evidence).

Hypotheses:

1. *Everything T-131 needs is on the wire already.* Refuted for the language: `IndicatorState` carries no `lang`, and the page's own texts (`indicator.recording`, `indicator.stop`, `indicator.dismiss`) are UI `t()` ids. Without a language source the page renders EN while `reminderText` / warnings arrive in RU, so acceptance 5 "RU renders" cannot hold. Confirmed for the rest: texts, ids, kinds, levels, elapsed time and the reminder flag are all in the fixture.
2. *The 10 s reminder and warning re-arm belong in the page.* Refuted: core owns both (`session.rs` `REMINDER`, `CallSession::tick`; `WarningList::raise` gives a dismissed kind a new id, `CallSession::dismiss_warning` republishes). A UI timer or a dismissed-kind filter would be a second owner of a core rule. The page test checks that the page renders whatever state arrives. The timing is core's test.
3. *The same concern is handled on a second path.* Yes, twice. The overlay page (listener first, then `overlay_ready`; `lang` in the payload; no expiry timer) is the pattern to copy. The Calls page (settings_get for the language; `formatDuration`) is the alternative source and the timer form to reuse. The indicator must not add a third elapsed-time formatter.
4. *Reply/event race.* IndicatorState has no `seq`. If an event arrives before the `call_indicator_state` reply, the reply may be stale (for example, a warning the user already dismissed would come back). Every change emits an event, in order (T-130: `indicator://state` on each change), so "the reply applies only if no state event has arrived" is correct without a seq. Ticks have no reply, so they have no race.
5. *This class was fixed before.* No: `docs/failures.md` F-001..F-029 has no UI indicator or reply-race entry. F-017 (a mirror of native state updated by a queued event) does not apply; the page has no native dialog.

**Proposed blocker** (not written to `docs/open-questions.md`): `blocked_on: "OQ-NN: language source of the call-indicator page"`. OQ row text: *"The call indicator page renders its own labels (`indicator.recording`, `indicator.stop`, `indicator.dismiss`) with `t()`, but `IndicatorState` (contracts/ipc.md) carries no language and T-130's `call-indicator` capability grants no `settings_get`. Options: (a) `IndicatorState` gains `lang` (overlay precedent; one producer; a small core change to indicator.rs/session.rs and the fixture, before T-131); (b) the page calls `settings_get` and listens to `settings://changed` (T-130 grants them; labels can switch language mid-call while Rust texts do not); (c) Rust renders the three labels into the wire. Recommended (a)."* This is a contract/technical choice, not a product one, so the orchestrator may decide it (decisions.md row) without the owner.

**Size**: T-131 itself is one seam (area ui). Under option (a), a core change comes first (indicator.rs, session.rs, tests/call_indicator_wire.rs, fixture, contracts/ipc.md). It belongs in its own small core task or in T-130, not in T-131, so that T-131 stays one seam.
