**What holds:**
- **Rule Q is exact for one-key headers.** The name is built from the string-aware scan: code outside strings, plus each quoted key's content if it is `[A-Za-z0-9_-]*`, else a `"` marker. Brackets and blanks are then removed. Within the grammar (B balanced, K no backslash, H the header pattern, C ASCII), a quoted bare-character key is the same key as the bare one. So `["lib"]` is `[lib]`, and any other quoted one-key name is refused.
  - A `.` counts only outside strings. So `["li.b"]` is refused (probe q2), while `[ "lib" . "x" ]` reads as `lib.x`, not a target (probe o; cargo agrees).
  - Dotted headers never name a target table, so leaving their keys free is correct.
  - Other shapes tried: `[ "lib" ] # "x" ✓` passes, correctly (q1). `[lib]]` is refused by B (q3). A tab before `=` in a `path` key is caught by P (q6).
- **Rule C is exact for the line start.** `[^\t -~]` under `LC_ALL=C` is every byte outside 0x20–0x7E and tab, tested after the trailing `\r` is stripped. The BOM, a `\v` before `[lib]` (q4) and a U+00A0 before `path` under `[[bin]]` (q5) are all refused. The real manifest and every fixture pass. Because C also bars non-ASCII bare keys, a future TOML 1.1 Unicode bare key cannot slip past the header pattern either.
