Narrowed by decision #49 to the core half (analysis option A): catalog, `ModelId`, `Timeouts::download_no_data`, `ModelStore`, `Downloader`, `DiskSpace` trait, `DownloadFailure`, en/ru message ids, mock-server helpers. The shell half is T-044, the Engine-tab picker and Playwright are T-045; spec T001, T007, T018 moved to T-017. i18n catalogs: merge after T-039's catalog changes.

## Acceptance

- [ ] A download of a catalog model (test catalog entry against a mock server) reports progress and ends with the file under its final name with the pinned size and SHA-256; `ModelStore` then reports it downloaded, and settings validation accepts `builtin_local` with it (core test)
- [ ] Failure branch: interrupted download, checksum mismatch, HTTP error, refused port or no data for `download_no_data` → `Failed{reason}`, the `.part` file deleted, no final file, and a retry succeeds; cancel deletes the `.part` with no retry reason; a slow but steady download longer than `download_no_data` still succeeds — verified by core tests against a mock server
- [ ] The production catalog has five entries with the pinned commit, sizes and SHA-256 values from the Hugging Face LFS metadata (R-6)
- [ ] Test that fails without the change: `crates/voicen-core` tests `local_download`, `local_store` and the catalog/timeouts unit tests

## Investigation

**Frame.** Expected behaviour (FR-08, spec 002 US1, FR-001–FR-008): the user picks one of five models and sees progress. The model becomes selectable only after its size and pinned SHA-256 match. An interrupted, stalled (30 s without data), refused or corrupt download deletes the `.part` file and offers Retry. Cancel deletes the `.part` file and offers no retry. Downloads run one at a time, free disk space is checked first, and leftover `.part` files are deleted at start. Observed: nothing of this exists (see `analysis.root_cause`). This is a need, not a defect, so nothing needs reproducing. Recurrence: `docs/failures.md` has F-001/F-002 (ci-toolchain) and F-003 (guard-model). No earlier task or commit is in class `model-download` (`git log -- docs/tasks/T-016.md`: planning commits only). `recurrence_of: []` stands. Tools: Serena was not used (decision #3: TypeScript only; Rust is read with grep/read). context7 was not needed: the reqwest API was read from the pinned 0.13.5 source in the core cache.

**What exists.** Core: the `DownloadedModels` trait with `FakeDownloadedModels` (`models.rs`; string ids, decision #23 N2). `Settings.builtin_local.model_id: Option<String>`. `validate` refuses builtin_local without a downloaded model. `Timeouts` struct (connect 5 s; there is no download field). `FailureReason` and `classify`, written for transcription: their `retryable` means "keep the pending recording". `clock::Clock` returns `SystemTime` only. Tests reuse wiremock and raw `TcpListener` servers (`tests/openai_client.rs`). Shell: `paths::data_dir`/`log_dir`, `NoDownloadedModels`, three commands, and the `windows` 0.62 crate with feature flags only. A disk probe needs `Win32_Storage_FileSystem`, which is a flag, not a new crate. UI: the Engine tab placeholder, and the tauriMock that throws on unknown commands. There is no `src/lib/local-models/`.

**Design points the developer must follow (not owner-level; the orchestrator can confirm):**
1. *Synchronous* (decisions #22, #42): `Downloader::start` runs the blocking download on one std thread and reports `DownloadEvent`s through a callback. No tokio, no `tokio-util`. The spec's `tokio::time::timeout` per chunk is replaced by reqwest's per-read timeout: `ClientBuilder::timeout(download_no_data)` + `connect_timeout(connect)`, and **no** `RequestBuilder::timeout` (see evidence). Tests call it on a plain thread (the blocking client panics inside a runtime, T-040).
2. *Timeouts*: add the field `download_no_data: 30 s` to the existing `Timeouts` struct, with the production value checked in `defaults_are_fr24`. Contracts/core-traits.md names consts. T-040's struct is the one source, so the field is the correct form. `MODEL_IDLE_UNLOAD` belongs to T-017.
3. *Failure type*: use a separate `DownloadFailure` (codes `download_interrupted`, `checksum_mismatch`, `not_enough_disk_space{needed}`, `source_unreachable{host}`, `disk_error`, `http_status{code}`), each with a message id. Do not extend `FailureReason`: its `retryable` and the pipeline's handling are transcription semantics, and a download failure is not a dictation failure. The wire codes stay those of contracts/ipc.md. `no_local_model` goes to T-017; `model_in_use`/`delete_failed` go to T-019. data-model.md and contracts are updated in the same commit (P-014). The classification may reuse the `TransportError` facts. It must never carry the URL (reqwest errors contain it, T-040).
4. *Cancel*: a flag that is checked between reads. During a stall, the cancel takes effect when the current read returns (≤ `download_no_data`). `Cancelled` is emitted only after the `.part` is removed (Windows cannot delete an open file). Test it with an ms timeout.
5. *Progress throttle*: the decision takes `now` from an injected monotonic source, default `Instant::now`. This keeps the "≤ 4/s, ≥ 1/s" rule unit-testable without sleeps; decision #47(2) is the spirit.
6. *Catalog injection*: `Downloader` and `ModelStore` take a catalog slice, so tests serve a fake model from the mock server. The production `MODELS` const is checked only by the shape test.
7. *One store*: one `Arc<ModelStore>` built in the shell from `paths::data_dir().join("models")`. It goes into `SettingsDeps.local_models` and the IPC state, replacing `NoDownloadedModels` (P-010, P-011). `cleanup_at_start` runs before the first `states()`.
8. *Logging*: no log facility exists in core yet (T-008), so R-11 events wait for it. Never log a URL with a query, or any key.
9. *i18n*: T-039 is editing `i18n/*.json` and `src/lib/i18n/` right now. New `local_model.*`/`download.*` ids must be merged after T-039 or coordinated with it.

**Size.** Phases 1–3 as written are larger than one seam: about 18 spec tasks. They cover a new crate, catalog values, timeouts, traits, failure reasons, ids and states, the store, the downloader, shell IPC, events and the disk probe, the UI component and model picker, and a CI cache with a fetch example. Several items are not part of the download at all: T001 (`voicen-whisper` crate), T007 (`SpeechModel` traits) and T018 (CI `tiny` cache + `fetch_model` example) feed only T-017's whisper test. It replaces `NoDownloadedModels`, adds the models dir to `paths.rs`, and gets tests in `src-tauri/tests/` (F-002 rule). Proven by Windows CI. Spec T016.

**Owner questions.**
- **Q1 (blocking for the core implementation, not for the red tests):** add `sha2` 0.10 to `voicen-core`. It is MIT OR Apache-2.0, already in `Cargo.lock` 0.10.9 through tauri/wry, so no new crate enters the lock, but it is not in the #9 list. Without it, the streamed SHA-256 needs another direct crate (`ring`/`aws-lc-rs`, both also in the lock through rustls). That would equally need consent and has a larger API.
- **Q2 (blocking for the production catalog only):** the pinned repository commit, the five exact sizes and the five SHA-256 values are not recorded anywhere. Getting them needs network access to huggingface.co: the LFS metadata (`oid sha256`, `size`) of `ggerganov/whisper.cpp` at one commit, per R-6. Was not fetched here. May the developer fetch them? Is the R-6 cross-check by downloading all five files (about 1.9 GB) required? Or is the LFS metadata plus CI hashing `tiny` through the app's own downloader (R-10, T-017) enough? The values themselves need no decision: FR-08 and the approved spec fix the source and the pinning. If this stays unanswered, the catalog can land in a follow-up record; the downloader and tests do not need it.
- Not questions (already decided): the storage location (`%LOCALAPPDATA%\Voicen\models`, spec FR-008), the source (Hugging Face, requirements §8), the disk check (size + 1 %, R-9; a probe error lets the download proceed), no resume (R-2), and the system proxy (reqwest `system-proxy`, T-040).

**Recommended:** Option A with the three-way narrowing. The first red test is `tests/local_download.rs::trickle_longer_than_no_data_succeeds_and_stall_fails`, which separates the per-read timeout from a total one, followed by the failure-branch table.
