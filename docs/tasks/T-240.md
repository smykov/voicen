## Context

OQ-88, answered by the owner in decisions #332 (option a). The contour runner's preflight in `.github/workflows/teamwright-agent.yml` runs `serena project index .` on a fresh checkout, where `.serena/project.yml` is untracked (#16). Serena then autogenerates a config with only `rust`, so contour stage sessions search TypeScript, Svelte and Markdown with the built-in tools (#72, #146). T-196 fixed local worktrees only.

Decided: a tracked language list (e.g. `scripts/ci/serena-project.yml`) that the contour preflight copies into `.serena/project.yml` before indexing. #16 stays in force for local trees; this reverses it for the runner only. The workflow change touches byte-pinned regions (`scripts/ci/contour-heads/`, `contour-push.yml`, `contour-upload.yml`, `release-guard.sh`), so the task is `checker: true`.

## Acceptance

- [ ] A tracked language list exists and names at least `rust`, `typescript` and `markdown` (and `svelte` when Serena supports it), and the contour preflight copies it into `.serena/project.yml` before `serena project index`
- [ ] `make check` pins the copy step and the list (a guard case fails when the preflight indexes without the copy, or the list loses a language)
- [ ] Failure branch: the list file is missing or unreadable → the preflight fails loudly, naming the file, instead of indexing with an autogenerated config
- [ ] `docs/decisions/context-tools.md` says the runner's config comes from the tracked list (#332) and local trees keep #16
- [ ] Test that fails without the change: `<test name>`
