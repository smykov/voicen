## Context

From the T-006 analysis refresh (Q5, 2026-10-05): T-006 (hotkey, SendInput paste, clipboard), T-052 (real Wry runtime, `run_return`) and T-057 (the overlay never takes the foreground) all plan Windows CI tests that assume the windows-latest runner has an interactive desktop where a test window can become the foreground window, `SendInput` reaches it, the clipboard can be opened and written, and `RegisterHotKey` succeeds. Nobody has checked that. A red test that cannot run there reports nothing, and the pre-push DRAIN rule refuses code of an IN_PROGRESS task, so the facts must come from a small task of their own, pushed first. Probe on windows-latest, in `src-tauri/tests/runner_probe.rs` (shell tests only in src-tauri/tests — F-001/F-002): create a top-level test window and `SetForegroundWindow` it, read `GetForegroundWindow`; `SendInput` a key to it and observe `WM_KEYDOWN`/`WM_CHAR`; `OpenClipboard`/`SetClipboardData`/read back; `RegisterHotKey(MOD_CONTROL|MOD_ALT, VK_SPACE)` and a synthetic press delivering `WM_HOTKEY`; the session/desktop name. Print each fact as one line and record the results in a new `docs/decisions/windows-ci-runner.md` (what the later tasks can assert on CI and what moves to the owner's manual check). The probe asserts only what it must to be useful (it must not fail the job because a capability is missing — a missing capability is a result).

## Acceptance

- [ ] The Windows CI job runs `runner_probe.rs` and its log shows one line per capability (foreground, SendInput, clipboard, RegisterHotKey/WM_HOTKEY, desktop/session) with the observed value; `docs/decisions/windows-ci-runner.md` records them with the CI run id
- [ ] Failure branch: a capability that is missing on the runner is reported as a result (the job stays green) and the doc says which Acceptance lines of T-006 / T-052 / T-057 move to the owner's manual check because of it
- [ ] Test that fails without the change: `src-tauri/tests/runner_probe.rs` (Windows CI; it does not exist before this task)

**Design (option A, recommended).**
1. **File.** `src-tauri/tests/runner_probe.rs`.
   - `#![cfg(windows)]` (as `credentials.rs`). Only `std` and `windows`: no tauri app and no `voicen_lib`, so nothing of the app's runtime can disturb the facts.
   - Exactly one `#[test] #[ignore = "runner probe: run only by the windows job's probe step (--ignored --no-capture)"] fn runner_probe()`.
   - One test per binary serialises the global foreground, keyboard, hotkey and clipboard state by construction. The step also passes `--test-threads=1`.
   - The budgets are constants at the top, in one place: `WAIT = 3 s` per observation, `POLL = 10 ms`, clipboard `10 × 50 ms`, `WATCHDOG = 60 s`.
2. **Threads and order.**
   - The main test thread makes no Win32 call. It receives `(fact, value)` over an `mpsc` channel with `recv_timeout` until the watchdog, prints each line at once (`println!` and a flush), so partial results survive a hang. At the watchdog it prints `timeout(ms=…)` for every fact still missing, then `runner-probe: end(facts=N)`.
   - It fails only on a probe defect: a probe thread whose `join` (checked with `is_finished` first, never blocking on a hung thread) returns a panic. No `unwrap` or `expect` on OS results: every failure becomes a line.
   - Thread S (session facts, no window) runs first: `image`, `session`, `station`, `desktop`, `foreground_lock`, `taskbar`.
   - Then thread W owns one top-level `EDIT`-class window: `CreateWindowExW(0, w!("EDIT"), w!("voicen runner probe"), WS_OVERLAPPEDWINDOW | WS_VISIBLE, …, None, None, None, None)`. It runs, in order:
     - `foreground`: `GetForegroundWindow` before (class name or none), then `SetForegroundWindow` (BOOL); poll `GetForegroundWindow() == hwnd`, pumping messages; record `GetFocus() == hwnd`;
     - `sendinput`: one `SendInput` of `VK_A` down/up (inserted count); pump with `PeekMessageW(None, PM_REMOVE)`, `TranslateMessage` (which makes the `WM_CHAR`), `DispatchMessageW`; observe `WM_KEYDOWN` `VK_A` and `WM_CHAR` (the char code as seen) at `hwnd`, then the edit's `GetWindowTextW`;
     - `clipboard`: `OpenClipboard(Some(hwnd))` with retries, `EmptyClipboard`, `GlobalAlloc(GMEM_MOVEABLE)` with the UTF-16 text `voicen-probe-<pid>` plus NUL, `SetClipboardData(CF_UNICODETEXT)`, `CloseClipboard`; reopen, `GetClipboardData`, compare;
     - `clipboard_null_owner`: the same with `OpenClipboard(None)`, which answers T-006 design 3's open point by measurement;
     - `hotkey`: `RegisterHotKey(Some(hwnd), id, MOD_CONTROL | MOD_ALT | MOD_NOREPEAT, VK_SPACE)`; one `SendInput` of Ctrl↓ Alt↓ Space↓; poll for `WM_HOTKEY` with `wParam == id`;
     - `async_keys`: while those three are down, read `GetAsyncKeyState(VK_CONTROL / VK_MENU / VK_SPACE) < 0`; then the 0xE8 mask key down/up (R-2: no menu activation), then Space↑ Alt↑ Ctrl↑, then poll until all three read up;
     - cleanup: the key-ups are sent by a guard on every path after any key-down batch; `UnregisterHotKey`; empty and close the clipboard; `DestroyWindow` on the same thread.
   - The hotkey probe runs last: the combination involves Alt, and nothing after it needs the window's focus.
   - CloseClipboard runs on every path. After a successful `SetClipboardData` the memory is the system's (never `GlobalFree` it); on failure `GlobalFree` it. `GlobalUnlock`'s `Err` with code 0 is success.
3. **Facts and line grammar** (one line each; the doc interprets):
   - Format: `^runner-probe: (?<fact>[a-z_]+)=(?<status>ok|denied|lost|absent|skipped|timeout)(\((?<detail>[^()]*)\))?$`. The detail is `k=v` pairs joined by `,`; any value character outside `A-Za-z0-9_.:-` becomes `_`; OS codes are `err=0xHHHHHHHH` (`windows::core::Error::code()`). The end line is `runner-probe: end(facts=N)`.
   - Status meaning:
     - `denied`: the API reported failure;
     - `lost`: the API reported success, but the effect was not observed within `WAIT`;
     - `skipped(reason=…)`: a precondition of the probe itself is missing, for example `no_window`;
     - `absent`: an object not found.

| Fact | Raw values (detail) | Example |
|---|---|---|
| `image` | `ImageOS`, `ImageVersion` (env; `absent` when unset) | `image=ok(os=win25,version=20260925.250.1)` |
| `session` | `ProcessIdToSessionId(pid)`, `WTSGetActiveConsoleSessionId()`, `GetSystemMetrics(SM_REMOTESESSION)` | `session=ok(id=1,console=1,remote=0)` |
| `station` | `UOI_NAME` and `UOI_FLAGS & WSF_VISIBLE` of `GetProcessWindowStation()` | `station=ok(name=WinSta0,visible=1)` |
| `desktop` | `UOI_NAME` of `GetThreadDesktop(GetCurrentThreadId())`, and of `OpenInputDesktop(0, false, DESKTOP_READOBJECTS)` or its code | `desktop=ok(thread=Default,input=Default)` |
| `foreground_lock` | `SPI_GETFOREGROUNDLOCKTIMEOUT` | `foreground_lock=ok(ms=200000)` |
| `taskbar` | `FindWindowW("Shell_TrayWnd", None)` | `taskbar=ok` / `taskbar=absent` |
| `foreground` | `before` class, `set` BOOL, `ms`, `focus` (self or other class), `now` class when lost | `foreground=ok(ms=16,before=ConsoleWindowClass,focus=self)` |
| `sendinput` | `inserted`, `keydown`, `char` (hex), `text_len`, `ms`, or the code when 0 inserted | `sendinput=lost(inserted=2,keydown=0,char=none)` |
