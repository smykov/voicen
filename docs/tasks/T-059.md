## Context

From the T-006 analysis refresh (Q5, 2026-10-05): T-006 (hotkey, SendInput paste, clipboard), T-052 (real Wry runtime, `run_return`) and T-057 (the overlay never takes the foreground) all plan Windows CI tests that assume the windows-latest runner has an interactive desktop where a test window can become the foreground window, `SendInput` reaches it, the clipboard can be opened and written, and `RegisterHotKey` succeeds. Nobody has checked that. A red test that cannot run there reports nothing, and the pre-push DRAIN rule refuses code of an IN_PROGRESS task, so the facts must come from a small task of their own, pushed first. Probe on windows-latest, in `src-tauri/tests/runner_probe.rs` (shell tests only in src-tauri/tests — F-001/F-002): create a top-level test window and `SetForegroundWindow` it, read `GetForegroundWindow`; `SendInput` a key to it and observe `WM_KEYDOWN`/`WM_CHAR`; `OpenClipboard`/`SetClipboardData`/read back; `RegisterHotKey(MOD_CONTROL|MOD_ALT, VK_SPACE)` and a synthetic press delivering `WM_HOTKEY`; the session/desktop name. Print each fact as one line and record the results in a new `docs/decisions/windows-ci-runner.md` (what the later tasks can assert on CI and what moves to the owner's manual check). The probe asserts only what it must to be useful (it must not fail the job because a capability is missing — a missing capability is a result).

## Acceptance

- [ ] The Windows CI job runs `runner_probe.rs` and its log shows one line per capability (foreground, SendInput, clipboard, RegisterHotKey/WM_HOTKEY, desktop/session) with the observed value; `docs/decisions/windows-ci-runner.md` records them with the CI run id
- [ ] Failure branch: a capability that is missing on the runner is reported as a result (the job stays green) and the doc says which Acceptance lines of T-006 / T-052 / T-057 move to the owner's manual check because of it
- [ ] Test that fails without the change: `src-tauri/tests/runner_probe.rs` (Windows CI; it does not exist before this task)
