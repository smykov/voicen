## Context

US1. Spec FR-015, FR-033 (listing), FR-039; req FR-47, FR-48, FR-71, §7; data-model.md "Call". Area core, seam `crates/voicen-core/src/call/storage.rs` (`CallStore`, `DiskSpace` port; temp dirs, a fault-injecting writer, a fake `DiskSpace`). Needs the track encoder (T-116) and the call types (T-118).

## Acceptance

- [ ] A call folder `<root>\YYYY-MM-DD_HHMMSS` is created from the local start time, with `-1`, `-2` on a clash, never an overwrite (T022, T023)
- [ ] `meta.json` is written from the start with `state: recording` in the data-model.md field order, with temp + rename on every state and device change, never in place (T022)
- [ ] The default title is "Call DD.MM HH:MM"; the speakers are `me` / `s1` with "Me" / "Other party" (EN) or "Я" / "Собеседник" (RU) (T022)
- [ ] Listing covers the current and every earlier root, newest first; `ready-to-transcribe` lists as Queued (T022)
- [ ] Failure branch: an unavailable root gives one `unavailable` line; a missing or unparsable `meta.json`, an unknown schema or a missing track file lists the folder as `damaged`, never hidden (T022)
- [ ] The `.voicen-write-probe` check runs at each start (T022)
- [ ] Test that fails without the change: the `call/storage.rs` tests

## Investigation

**Context gathering.** I used Serena (`get_symbols_overview` on call/events.rs, codec.rs, transcript.rs and clock.rs; `find_symbol CallId`), then grep and sed for the spec documents, settings/roots.rs, settings/service.rs, diag/format.rs and i18n.rs. Context7 was not needed: no new external API. The work uses std::fs only (`create_dir`, `rename`, `File::sync_all`) plus serde_json 1, which is already a dependency and keeps struct field order on serialize.

**Frame.** A feature task. Expected: core creates `<root>/YYYY-MM-DD_HHMMSS[-n]`, writes `meta.json` atomically from the start, and lists every root's calls with `damaged` and `unavailable` entries. Observed: no `call::storage` module exists, so none of this happens.

**Hypotheses, with evidence.**
1. *Nothing exists yet*: confirmed (ls of call/, grep for CallStore/DiskSpace/meta.json in crates/ and src-tauri/src).
2. *The same concern already has a path elsewhere*: confirmed, several times. Each one must be reused, not copied:
   - Write probe: `settings::roots::CallRoots::probe`. Its module doc says "there is no second probe", and T-125/T-126 call it at every Record start. Its `FsCallRoots` creates the default root, which a first call needs.
   - Current root: `settings::service::effective_root` (private). The store must resolve the root the same way save does. Recommendation: move it into roots.rs as `pub fn effective_root(&CallSettings, &Path)`.
   - Local time: `diag::format::LocalTime::of(at, seconds_east)` (pub(crate)). It feeds the folder name, `calls.title_default` (two-digit day/month/hour/minute) and `started_at`. transcript.rs fixtures use `2026-10-30T14:05:09+03:00`, with no millis; follow that form, so add a seconds-only writer beside `write_timestamp`, or format from `LocalTime` in storage.rs.
   - Atomic write: `settings::file::FsSettingsFile::write_tmp_and_rename` is tied to settings.json. The call side gets its own `write_meta` in storage.rs. T-138 (transcript.*) and T-141 (export) should reuse that tmp+sync+rename helper; expose it as `pub(crate) fn write_atomic(dir, name, bytes)` in storage.rs.
   - .opus writing: only through `OpusOgg::create` (T-116 invariant).
   - Types: `CallId`, `CallState` (hyphen serde, #195), `EngineRef`, `Speaker` (#196), `EndpointId` (invalid text never kept), `StopReason` and `FailReason` already exist.
3. *This class was fixed before*: not for calls. The closest precedent is settings (`docs/decisions/settings.md`): `create_new` reservation, so no backup is ever overwritten, and tmp+sync+rename. The same shape applies here: `fs::create_dir` (atomic, AlreadyExists → next suffix) instead of `create_dir_all`.
4. *`CallId`'s `Ord` gives newest-first*: refuted. It derives `Ord` on the String, so `…_101010-10` < `…_101010-2`. Listing must sort by a parsed key `(stamp, n)` descending, ties current root first. Do not change `CallId`'s `Ord` (events.rs, DONE).
5. *`StorageKind` can carry `StorageOp::Encode`*: refuted. There is no `encode` literal in `call_storage_failed kind=`, and #195 left the mapping to T-125. See D1.

**Shape for the developer** (indicative):
- `CallStore::new(roots: Arc<dyn CallRoots>, clock/offset)`.
- `create(&self, calls: &CallSettings, NewCall { started: SystemTime, seconds_east, mic: EndpointId, system: EndpointId, lang: UiLanguage, app_version }) -> Result<ActiveCallFiles, CreateError>`.
  - Order: probe → create_dir with suffix → `meta.json` (state recording, `results` both `pending`, `engines.transcription: null`, `pass_mode: null`) → `mic.opus`, `system.opus` via `OpusOgg::create`.
  - Any failure after create_dir removes what it created (best effort), so a refusal leaves nothing.
  - `CreateError::Root(UnwritableReason)` | `CreateError::Storage(StorageError / StorageKind)`. T-126 maps Root(Missing) → `call_refused part=root reason=missing` and the rest → `unwritable`.
- `ActiveCallFiles`: `write_meta(&CallMeta)` (state and device changes) and the two `TrackEncoder`s.
- `list(&self, calls: &CallSettings) -> CallList { entries, unavailable: Vec<PathBuf> }`. `ListState` is `Recording | Queued | Transcribing | Ready | Failed(FailReason) | Recovered | Damaged`.
- `CallMeta` field order = data-model "Call": `schema, id, title, started_at, ended_at, duration_ms, state, failure, stop_reason, mode, tracks, device_changes, engines, app_version, speakers, results, pass_mode`. Pin the key sequence in a test.
- `DiskSpace { fn free_bytes(&self, root: &Path) -> Result<u64, OsCause> }`, with `OsCause { kind: io::ErrorKind, os: Option<i32> }` (the os code matches #195). Plus a `FakeDiskSpace` under `test-fakes`. Polling is T-144's job.

**Faults without root privileges** (the Docker gate runs as root, so permission faults do not bite; roots.rs tests already work around this):
- `meta.json.tmp` pre-made as a directory → the write fails, the previous `meta.json` bytes are unchanged, and no stray tmp is left.
- A pre-made `mic.opus` directory → create fails and the folder is removed.
- A generic opener so a test hands `OpusOgg` a fault-injecting `SyncWrite`, modelled on the codec tests' `Sink`.

**Owner points: decided, decision #242 (2026-11-04), all as recommended** (D1 Encode → `kind=write`; D2 non-CallId names not listed; D3 missing default root empty, missing chosen/earlier root unavailable; D4 unknown key → damaged; D5 suffix bound -99, then root `other`). Original options, kept for the record:
- **D1** `StorageOp::Encode` → `StorageKind::Write` (rec.; no log-grammar or diag change), or add an `encode` literal (touches events.rs, diag/format.rs, diag_format tests and the contract).
- **D2** Listing skips any folder or file whose name is not a `CallId` (rec.: `.voicen-write-probe`, user folders and `meta.json.tmp` are not calls, and IPC can only address grammar ids), or lists them as damaged.
- **D3** A missing **default** current root lists as empty ("No calls yet"), not unavailable, since it is created only at the first start (rec.). A missing chosen or earlier root, or any read_dir error, gives one unavailable line.
- **D4** A `meta.json` with an unknown key is `damaged` (rec., `deny_unknown_fields` as in transcript.json, T-123), or the key is ignored.
- **D5** Clash suffixes are bounded at `-1`…`-99`, and past that the start is refused as `root other` (rec.; settings bounds backups at 9), or unbounded.

A crash between create_dir and the last file of `create` leaves a folder that lists as `damaged`. The spec allows this ("never hidden"). A staging-folder rename was considered and rejected: the track files must stay open, and the codec cannot reopen in append.

**Docs in the same commit:** add a new `docs/decisions/call-storage.md` (class `call-storage`) with invariants 1–3 and the root/probe reuse. Also update the `call::storage` row of contracts/core-call.md, if the signatures differ (`OsCause`).

**Re-check after T-124 (HEAD ad615fb4, Serena `get_symbols_overview` on call/events.rs and call/capture.rs, `find_symbol` StorageKind / TrackSink; grep for effective_root, probe, LocalTime, DiskSpace, meta.json).** Still true: `settings::service::effective_root` is a private fn; `CallRoots::probe` is the only probe and its doc names T-125/T-126; `LocalTime::of` and `write_timestamp` are `pub(crate)`; `CallId` derives `Ord` on the String; `StorageKind` has no Encode. Changed: call/ now also holds `capture.rs` and `wav_source.rs` (T-124: `TrackSink`/`TrackSource` ports, `Timeline` on `CaptureStamp`). T-124 added no disk-space, clock or storage port, and nothing that writes a file, so `DiskSpace` is still new in storage.rs. Storage reuses `clock::Clock` + `clock::LocalOffset` (start time) and `clock::MonotonicClock` (required by `OpusOgg::create`), not a new clock. Wiring the `Timeline` steps into the `TrackEncoder`s is T-126/T-141, not T-125.

**Recurrence check:** `docs/failures.md` has no F-entry or class row for `call-storage`, atomic writes or folder naming; this is a first sighting. F-024 (`error-fake-masks-origin`) applies to the tests: the fault-injecting writer fails exactly one call.

**Overlap:** `call/mod.rs` (one `pub mod` line; T-124's lines have landed, T-137 still adds one); `settings/roots.rs` and `settings/service.rs` (the `effective_root` move; T-124 and T-137 do not touch them). No overlap with `call/final_pass.rs`, `capture.rs` or `wav_source.rs`.
