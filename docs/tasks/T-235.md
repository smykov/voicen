## Context

Found by the T-233 developer on 2026-11-18. CLAUDE.md recommends `make check WORKERS=1` to lower the e2e workers, but on a clean tree it exits 2: the `area-image.test.sh` case "make check-ui passes --workers=2 to the e2e run by default" runs a nested `make -n check-ui`, and the outer `WORKERS=1` reaches it through MAKEFLAGS, so the "default" case sees `--workers=1`. The same test passes 23/23 alone and inside the default `make check`. Log at the time: `/tmp/t233-make-check.log`; tree at 6bd32d02.

## Investigation

Context tool: grep and file reads (bash scripts and the Makefile; Serena has no symbols here). Searched `scripts/ci/*.test.sh`, `scripts/*.test.*`, `scripts/licenses/`, `Makefile`, `*.mk` for nested `make` calls and `MAKEFLAGS`.

**Frame.** Observed: `make check WORKERS=1` red on a clean tree, one case of `area-image.test.sh` ("passes --workers=2 ... by default") sees `--workers=1`. Expected: green; the default case proves the Makefile default regardless of how the gate was invoked. Reproduces on the host at e44799c3 with `make -s check-area-image-fixtures WORKERS=1` (no full gate needed).

**Hypotheses.**
1. The outer command-line variable reaches the nested `make -n` through MAKEFLAGS. Confirmed: an outer make with `WORKERS=1` exports `MAKEFLAGS=s -- WORKERS=1`; `MAKEFLAGS=' -- WORKERS=1' bash scripts/ci/area-image.test.sh` fails the case.
2. A plain environment `WORKERS` also leaks (`WORKERS ?= 2` accepts the environment). Confirmed: `WORKERS=1 bash scripts/ci/area-image.test.sh` fails the same case. Same mechanism class (caller state reaches the nested make), so the fix must cover both.
3. The Makefile default is wrong. Refuted: a plain run is 23/23 and `make -n check-ui` prints `--workers=2`.
4. Second path: another self-test runs a nested make with inherited state. Checked: `scripts/licenses/stale-check.sh::run_make` already clears MAKEFLAGS, MFLAGS, MAKELEVEL, MAKEOVERRIDES (T-063); clippy-lines, test-guard, release-guard, e2e-entry and the rest mention make only as text or fixture content. No other site.
5. Fixed before: the class was solved once in stale-check.sh (T-063) but not as a shared helper; area-image.test.sh (T-177) wrote its own `mk()` without it. Not a recurrence of a tracked defect (no F-entry), so no rca.

**Root cause.** `area-image.test.sh::mk()` is a bare `make -n`, so the nested make resolves `WORKERS` from the caller's MAKEFLAGS/environment; the "default" case then reads the override.

**Fix check (done, nothing committed).** Under an outer `WORKERS=1 make ... WORKERS=1`: `env -u MAKEFLAGS -u MFLAGS -u MAKELEVEL -u MAKEOVERRIDES -u WORKERS make -n check-ui` -> `--workers=2`; the same with `WORKERS=1` on its command line -> `--workers=1`; the same with `-f` a copy where `WORKERS ?= 3` -> `--workers=3` (the default case would go red: bite).

**Approach.** See `analysis.approach`: option A in `mk()`, red case with a hostile MAKEFLAGS/MAKEOVERRIDES/WORKERS first. Unsetting WORKERS for every `mk` call is safe: the only override case passes `WORKERS=1` on the command line. The developer should also update the `check-area-image-fixtures` row in `docs/decisions/ci-toolchain.md` (note the scrubbed nested make) and may name it in the `ui-e2e.md` E3 sentence about `make check WORKERS=1`.
