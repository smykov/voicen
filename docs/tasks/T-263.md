## Context

Option 3 of #360. Today the implement session blocks on `scripts/tw-wip-run` for the whole `wip/<ID>` round (50+ min, often several rounds, inside the 240-min stage limit), holding a runner slot and the session. Wanted: the stage ends after the push with an outcome that says it waits for CI; `teamwright-next.yml` reacts to `workflow_run` of `ci.yml` completed on `wip/*` (or `task/*`) and dispatches the next hop: green → the stage that follows (review, or the rest of implement), red → implement with the failed-step log (`tw-wip-run` `LOG:` lines). Touches the chain, the stage protocol's P-016 order and possibly the kit: the analysis decides whether it needs the spec tool (more than one seam).

Measured 2026-11-24 (decisions #360): implement hop 59 min (run 45316103610), of which most is the wip round; a `wip/<ID>` `ci.yml` run 52 min serial (31 after T-262); T-247 needed 4 wip rounds, T-151 3.

Guard paths (workflows, `scripts/ci/`, byte-pinned heads and fragments) change in pairs; `checker: true`, `analysis.decides_on` (P-020).

## Acceptance

- [ ] An implement hop whose code is ready pushes `wip/<ID>`, ends without waiting, and frees its runner slot; the next hop starts when that `ci.yml` run completes, with its conclusion and run id as input
- [ ] Green → the next hop records `CI: <run> @ <sha>` (P-016) and goes on; red → an implement hop with the failed log; a cancelled or stale run (sha no longer the tip of `wip/<ID>`) → no hop, one warning
- [ ] `MAX_PARALLEL` and the per-task concurrency group (`contour-busy.sh`) still count a task waiting for CI as busy, so no second chain starts for it
- [ ] Test that fails without the change: pins in the `contour-label` / `contour-busy` tests and the owned heads, red on today's tree
