## Investigation

How I looked: Serena (`get_symbols_overview`, `find_symbol`) on `src-tauri/src/tray.rs` and `crates/voicen-core/src/call/session.rs`; Serena returned "file not found" for `src-tauri/src/call.rs` (it does not exist). The rest was grep and reads on main @ 192c0dd3 and in /projects/voicen.worktrees/T-007 (read only). I did not query context7: the plan uses no new library API (std threads and mpsc, `run_on_main_thread`, `spawn_blocking`, and T-127's `CpalTrackSource`, all already in the tree).

**Frame.** Expected (FR-001/002/003/043, R13): the tray Record, Stop and Calls items and `--call record` (second or first launch) go into `CallSession::toggle_record(_, source)`. A refusal shows a notice and a log line. The tray shows CallRecording. An unknown `--call` value is logged. Observed: every one of these routes ends in a no-op (see `analysis.evidence`). This is a feature gap, not a regression.

**Hypotheses checked.**
1. *A second path already handles the concern*: refuted. No `CallSession` is built or managed anywhere in `src-tauri/src` (grep for `CallSession` finds only `tests/call_capture.rs`).
2. *This class was fixed before*: refuted. `recurrence_of` is empty. `docs/failures.md` F-001..F-031 has no call-wiring or tray-routing entry. The classes that bear on the tests: `ci-premise-unchecked-before-main` (F-001, F-002, F-005, F-007, F-008, F-009, F-011), which covers the runner's no-output-device premise (windows-ci-runner.md:204 says it was never observed). F-008, `smoke-window-predicate`: the indicator window is a product window, never a helper (G18). F-019: no wall-clock ceiling on a window build. F-031: no test infers writer progress from ticks. F-004/F-012/F-020 family: a real-endpoint test takes a serial lock.
3. *Core already maps refusals to notices*: refuted. `start` (session.rs:682-713) returns `Toggled::Refused` and calls `CallShell::notice` for nothing. `CallNotice` has no message mapping. So the mapping is new, and it goes in core (pure, P-010).

**T-007 API the notices use.** `voicen_core::platform::Notifier::notify(&self, id: MessageId, params: &[(&'static str, String)], retry: Option<PendingId>)`, at /projects/voicen.worktrees/T-007/crates/voicen-core/src/platform.rs:174-176. Call notices always pass `retry: None`. The doc's rule applies: called outside any lock, must not block. That is true for the call worker and tick thread, after the session lock. The shell's interim implementation is `NoToasts`, at /projects/voicen.worktrees/T-007/src-tauri/src/dictation.rs:214-226, built inline in `start_dictation` at :185. T-128 needs it as one shared instance (P-011): it is built once in `run()` and passed to `DictationPorts` and `CallPorts`, so T-210 swaps one constructor. **The toast part can be done in T-128 as soon as T-007 merges.** It wires the refusals and the `CallShell::notice` stops to the port, tested with a recording fake `Notifier` in `call_launch.rs`. It does not need to wait for T-210. The toast becomes visible on screen only when T-210 replaces `NoToasts`.

**Recommended exit**: not an rca task. The code change is laid out in the analysis block. The size is at the upper edge of "small": two shell seams (call.rs, tray.rs) plus a pure core helper. The design is already settled in spec 007, so no new spec is needed.

**Open items for the orchestrator / owner (not decided here):**
1. **T-130 ordering (recommend: add T-130 to `depends_on`, or an ordering rule "T-128 does not reach `main` before T-130").** FR-005 and FR-043 make the always-visible indicator the safeguard for switch-started recordings. Without T-130's `IndicatorPart`, `set_state`/`set_tick` have nowhere to go, and a build from `main` could record with only the tray icon showing. T-130's own notes expect to land first ("IndicatorControl slot for T-128").
2. **The tick driver (recommend: in T-128, with one Acceptance line added).** No task owns the shell timer that calls `CallSession::tick` at `next_deadline`. T-144 and the core-call contract assume it exists. Without it, the reminder never hides, and the 4 h, low-disk and storage-error stops never fire (FR-017/018).
3. **What a click on a checked "Record" means (recommend: stop, i.e. a toggle).** FR-001 "Turning Record off ends the call", and it is a check item. Intent is read from the session on the worker, never from muda's mark.
4. **"Calls" in T-128.** FR-003 says it opens the Calls window, and T-142 owns that window. Recommend: T-128 routes OpenCalls to `call::open_calls`, which does nothing until T-142. The Acceptance line "Calls invoke the same path" can only be proven as routing until then.
5. **Runner premise.** The real-source refusal test (`part=system reason=no_device`) runs first on `wip/T-128` (P-016). If the runner turns out to have a render endpoint, the FR-043 smoke premise becomes an owner question, together with G18.
6. **T-210 scope.** T-210's Acceptance names only dictation messages. It should say that the one shared notifier also shows call notices, or a follow-up task should.
7. **Risk until T-145 / T-147.** Before then, a tray Exit during a recording does not finalize the call: `meta.json` stays `recording`, and only a startup `CallStore::recover` (T-147) fixes it. The Calls window (T-142) is not there yet either, so the user cannot see this.
