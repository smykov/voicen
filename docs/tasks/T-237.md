## Investigation

**Tools.** I did not use Serena for code. The seam is workflow YAML, JSON and bash checkers, which the project's Serena does not index (the caller expected this). I used grep and file reads on `.github/workflows/`, `.mcp.json`, `.claude/settings.json` (and the gitignored `settings.local.json`, which never reaches the runner), `scripts/ci/role-tools.sh`, `role-tools.test.sh`, `scripts/ci/role-heads/`, `Makefile`, `docs/decisions/context-tools.md`, `docs/decisions/ci-toolchain.md` (guard table), `PRINCIPLES.md` P-020, and T-208 with its follow-ups and review. For permission-rule syntax I used context7 `/anthropics/claude-code`: `mcp__server__*` allows every tool of a server, and the permission modes include `bypassPermissions`. That is why the token check counts every `mcp__serena` occurrence rather than listing forms. I ran no CI and no `gh`.

**Frame.** Observed: T-208's two halves can each be reverted without any red check. One half is the five-tool `--allowedTools` value in `teamwright-agent.yml` (step `claude`), the other `--agent-interface tools` in `.mcp.json`. Expected: `make check` fails on either revert.

**Hypotheses.**
1. *No checker reads either file.* Confirmed. `.mcp.json` is named by no file under `scripts/ci/` or the `Makefile`. The only `allowedTools` occurrence is the claude line. release-guard pins only the contour header (R14), the upload tail (R9) and token sets (R4). contour-busy.test.sh pins the call line, the groups and the run-name. T-208's own mutant table records "not caught".
2. *A second path grants the same tools.* Partly open today. Other routes would widen the allowlist without touching the five names: the wildcard `mcp__serena__*`, a second `--allowedTools`, `--permission-mode bypassPermissions` or `--dangerously-skip-permissions`, `--settings`, and `permissions.allow` in the committed `.claude/settings.json`, which the stage session loads. Today none of these occurs (grep above), so the invariant is closed over them by raw-token absence, not by listing forms.
3. *The flag reaches the runner by another path.* Refuted. The preflight `jq` copies `.mcpServers.serena` unchanged into `$RUNNER_TEMP/mcp.json`, and `--strict-mcp-config` takes only that file. So `.mcp.json` plus that jq line is the whole path. Duplicate JSON keys resolve last-wins in jq (a second `"serena"` key would override the first), so the pin cannot be a presence check on the flag. It is either a whole-file byte compare or a token count of `"serena"`. The recommendation does both, the count on the owned copy.
4. *The class was fixed before.* The pattern is the same as the role heads (T-082, then T-113, F-022): a grant held by review is lost silently. T-113's answer, an owned byte-exact literal plus a set check, is the model here. This is not a recurrence of a fixed defect: nothing pinned this before.

**Design notes (Option A).**
- *Why not just the two tokens the follow-up names* (`mcp__serena,` and `mcp__serena"`)? They miss `mcp__serena__*`, a trailing space, a second flag, and a settings grant. Counting raw `mcp__serena` occurrences (exactly 5 across `.github/workflows/`, all inside the one joined literal) closes all forms fail-closed.
- *r1#2 (SSOT).* The check owns the five names in `scripts/ci/serena-tools.txt`. It requires the `,`-joined form once in the workflow, and the `, `-joined form once in every head that names `mcp__serena`, with exactly 5 occurrences. The workflow and the heads are then compared by the same check. `role-tools.test.sh` keeps its own `want_names` real-head pin as a second layer and is not edited, to avoid touching another guard. The remaining copy is cross-checked transitively: a drift turns one of the two checks red. If the reviewer wants one list, `want_names` can source `serena-tools.txt` later.
- *.mcp.json as a whole-file pin.* It changed twice in its history. A kit re-render (`/teamwright:reconfigure`) or a new MCP server will turn the check red visibly; that is intended, because the file and its owned copy are edited together. The test also checks that the owned copy itself holds the flag lines, so editing both files to drop the flag still fails.
- *Failure branches to bite (P-022, at most 15 mutants):* M1–M8 in `analysis.approach`, plus "cannot run" (an owned file missing → exit 3, never a pass).
