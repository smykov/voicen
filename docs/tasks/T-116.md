## Acceptance

- [ ] `opus` 0.4 and `ogg` 0.9 are dependencies of `voicen-core`; `make licenses` passes and `THIRD-PARTY-NOTICES.txt` is committed with them; `pub mod call` exists (T002)
- [ ] Page 1 is BOS with only `OpusHead` (contracts/core-call.md values, granule 0); page 2 is `OpusTags` with vendor `voicen <version>` and no comments (T003)
- [ ] Granules advance by 960 per packet; a page ends every 50 packets with a flush after each page and `sync_data` every 5 s (fake clock) (T003)
- [ ] The last page carries EOS and its granule trims the tail (T003)
- [ ] 60 min of speech-like signal on both tracks takes at most 40 MB (SC-007) (T003)
- [ ] Failure branch: `UnexpectedEof` or a CRC mismatch on the last page ends recoverable data; a mismatch earlier gives a damaged file with its readable prefix; no valid `OpusHead` → unreadable; duration = last good granule − pre-skip (T003)
- [ ] Failure branch: an `io::Error` from write, flush or sync maps to `StorageError` (T003)

## Investigation

**Frame.** A feature task, not a defect: G02 (T002–T004) of spec 007. Expected: real Ogg Opus call tracks, written and read in `voicen-core`, tested on real libopus in the core image. Observed: there is no `call` module, no `opus`/`ogg` dependency (`crates/voicen-core/Cargo.toml`, `crates/voicen-core/src/lib.rs`), and `StorageError` / `DecodeEnd` are named in contracts/core-call.md "Codec" but defined nowhere in spec 007 (searched spec.md, plan.md, data-model.md, tasks.md, contracts/). This task defines them in `call` (recommended `call/mod.rs` so that the storage task reuses them).

**Scope.** One seam (`call::codec`) under an approved spec and decision #186. This is not large work. Two details are left open by R6/R7 and settled here without changing behaviour (see Gaps). No owner question.

**Hypotheses checked.**
1. The bundled libopus does not build in the core image. Refuted for both paths that run there. A probe crate (`opus =0.4.0`, `ogg =0.9.2`, a copy of the repo's `.cargo/config.toml`) was run in `voicen-rust:1.99` with `-j2`, with the project's cargo caches mounted:
   - Native `cargo run`: opusic-sys 0.7.5 `build.rs` runs cmake-rs 0.1.58 → cmake 3.25.1, with the Unix Makefiles generator (no `ninja` in the image) and `CMAKE_BUILD_TYPE=Release` even in debug. It printed `libopus 1.6.1 lookahead=104 preskip48k=312`, and a 94-byte packet decoded to 320 samples.
   - `cargo check --target x86_64-pc-windows-gnu` (the `check-shell-windows` path, since `src-tauri` depends on `voicen-core`): CMakeCache shows `CMAKE_C_COMPILER=/usr/bin/x86_64-w64-mingw32-gcc` and `CMAKE_SYSTEM_NAME=Windows`, and `out/lib/libopus.a` was built. Exit 0. The build script emits one `cargo:warning` (no `x86_64-w64-mingw32-g++`). It is harmless (C only) and hidden for registry crates without `-vv`.
   - libopus `CMakeLists.txt:1` `cmake_minimum_required(VERSION 3.16)` is ≤ 3.25.1. That closes the open point T-115 left.
2. The forced MSVC `[env] CMAKE_*` values in `.cargo/config.toml` (T-099) leak into the opus build. Refuted. They are present in the build script's environment but inert:
   - opusic-sys never forwards env to defines; it only filters `-flto` from `CFLAGS`/`CXXFLAGS`.
   - cmake-rs reads only `CMAKE_TOOLCHAIN_FILE`, `CMAKE_GENERATOR`, `CMAKE_PREFIX_PATH` and `CMAKE` from the environment (`getenv_target_os` call sites in `cmake-0.1.58/src/lib.rs`), and its `defined()` sees only its own defines.
   - CMake itself does not read `CMAKE_C_FLAGS*` or `CMAKE_MSVC_RUNTIME_LIBRARY` from the environment. The resulting cache has `CMAKE_C_FLAGS_RELEASE=-O3 -DNDEBUG`, not the forced `/O2 …`.
   - Consequence for Windows (T-117, not here): on msvc, cmake-rs writes cc-rs's `-MD` into `CMAKE_C_FLAGS` and `CMAKE_C_FLAGS_RELEASE` (VS generator branch, `set_compiler`), and libopus `CMakeLists.txt:282-294` sets `MultiThreadedDLL` unless `OPUS_STATIC_RUNTIME`. A toolchain file that only sets `OPUS_STATIC_RUNTIME ON` may still meet the explicit `-MD` in the flags. T-117 should check the effective cl command line, not just the cache keys.
3. Adding libopus breaks the Windows CI run of this task (class `ci-toolchain`, F-001 CRT mixing). Unproven here, and judged low risk:
   - Core test exes (`cargo test --workspace --exclude voicen`) are plain `/MD` Rust plus `/MD` libopus, the same CRT.
   - `voicen.exe` already links the `/MD` C library aws-lc under tauri's static vcruntime and passes `crt-imports.sh` (ci.yml windows job). With `lto = true` and no shell caller of the codec, libopus is likely stripped from `voicen.exe` anyway, so this task's run does not prove opus-in-`voicen.exe`. T-117 does.
   - Not checked: whether the runner has `ninja` on PATH (opusic-sys then switches to Ninja with cl).
   - The P-016 run on `wip/T-116` is the proof. A red Windows step that comes from libopus is not patched here: it goes to T-117 / an F-entry.
4. A second path that writes or reads `.opus`. None. Serena `get_symbols_overview` of `lib.rs` lists no `call` module. Grep for `opus`, `ogg` and `sync_data` under `crates/` found nothing (only the `.ogg` clip source note in THIRD-PARTY-NOTICES).
5. This class was fixed before. `docs/failures.md` has no codec, Ogg, libopus, cmake or licence entry. F-001/F-002 (`ci-toolchain`) and `ci-premise-unchecked-before-main` are the nearest classes, and their existing rule (P-016 wip run) covers this. Not a recurrence.

**Library facts the implementation relies on** (read from the crate sources, not memory; context7 not needed):
- opus 0.4.0 `Encoder`: `set_bitrate(Bitrate::Bits(24000))`, `set_vbr`, `set_complexity`, `set_dtx`, `set_inband_fec`, `get_lookahead`, `encode_float`. Both `Encoder` and `Decoder` are `Send`.
- ogg 0.9.2: `PacketWriter::write_packet(data, serial, PacketWriteEndInfo, absgp)` and `inner_mut()`. The writer never flushes its inner writer.
- ogg 0.9.2 `PacketReader<T: Read + Seek>`: on `HashMismatch` the page bytes are already consumed, so the next `read_packet` continues at the following page. EOF before a complete 27-byte header gives `Ok(None)`; EOF inside a page gives `ReadError(UnexpectedEof)`; more than 150 KiB without a capture pattern gives `NoCapturePatternFound`.

**Gaps in R6/R7, settled in the invariant:**
- **Final granule.** Granule = pre-skip + 3 × input samples. `finish` encodes zero-padded frames until 960 × packets ≥ that value, so the encoder lookahead is flushed and the tail is trimmed by the granule. The "+960 per packet" granules on non-final pages therefore include the pre-skip delay, which makes "duration = last good granule − pre-skip" hold for truncated files too.
- **Read errors R7 does not name.** A zero-filled tail (a crash after the file grew but before data landed), or a garbled header, gives `Ok(None)`, `NoCapturePatternFound`, `InvalidData` or `InvalidStreamStructVer`. The invariant treats any read error after a valid `OpusHead` as the end of data. "Damaged" is decided only by whether a CRC-valid page follows the bad one, so R7's three named cases stay exactly as written.
- **Sync timing.** The 5 s `sync_data` interval is wall time through the injected `crate::clock::MonotonicClock`. `Instant::now` is banned by clippy (T-089), which matches the contract's "fake clock".

**Size and gate cost.** 300 s of a speech-like signal (two harmonics plus noise, amplitude-modulated) encodes to 914,632 B. That is 10.98 MB/h per track (R5 estimated 10.8), so two 60-minute tracks come to about 22 MB, under 40 MB. Encoding took 3.4 s per 5 min in a debug probe, so 2 × 60 min adds about 80 s of CPU to `check-core`. The developer should encode each track in its own test so they run in parallel, and generate the signal once.

**Licences.** `about.toml` already accepts BSD-3-Clause, so it needs no change. opusic-sys's `LICENSE` carries the libopus copyright, so `licenses/manual.json` is probably not needed; confirm after `make licenses`. opus is `MIT/Apache-2.0` in slash form, and cargo-about already handles that form (brotli-decompressor in THIRD-PARTY-NOTICES.txt). byteorder is already in the lock file. `make licenses` needs crates.io access.

**Guard paths.** None. The task changes `crates/voicen-core/**`, `Cargo.lock`, `THIRD-PARTY-NOTICES.txt` and possibly `licenses/manual.json` (not under `scripts/licenses/`). It also changes `docs/decisions/ci-toolchain.md` and the `docker/rust.Dockerfile` comment: cmake now has a consumer, the native and mingw libopus build. None of these is under `scripts/ci/` or `scripts/licenses/`, `Makefile` or `*.mk`, so `checker: false` holds and `decides_on` stays empty. R5's "core image gains cmake" (T-060 Low finding) is not needed by this analysis and is left as is.

**Recommended approach.** See `analysis.approach`, option A.
