Points the orchestrator asked about, with no finding:
- **Memory handling (`list`)**: the array is freed exactly once, after the loop. No early return sits between `CredEnumerateW` and `CredFree`: `continue` only skips an element and `bad_name` is checked after the free. A null `creds` returns without a free (nothing to free). Each non-null blob is zeroed in place with `write_volatile` before the free. Only `TargetName` (decoded to `String`) and `Type` leave the buffer. `CredentialEntry` and `CredentialError { os_code }` cannot carry a blob.
- **No key text in logs or output (FR-20, NFR-04)**: the branch runs in `main()` before `run()`, so `diag` is never started and no logger exists. The path has no `print`/`eprintln`/`log` call. The exit code is the only output. The CI step checks stdout and stderr are empty (redirected handles do reach a `windows_subsystem` exe) and that the log files are unchanged.
- **CI step false-green risks**: (a) single instance: every `voicen` process is stopped, and the step throws if one survives, so a missing branch cannot be absorbed by a running primary; (b) timeout: `WaitForExit(15000)` fails, kills the process and cleans up; `$p.Handle` is cached, so `ExitCode` is reliable; (c) a broken `Test-Cred` cannot pass silently, because the plant premise checks it first; (d) the outsider check catches an over-wide purge.
