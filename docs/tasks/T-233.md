## Context

Decisions #308 (owner, 2026-11-18): the contour's implement stage of T-217 (Issue #18, run 44113118038) stopped at stage-protocol §0 because the `serena` MCP server hit CONNECT_TIMEOUT (Claude Code's default 30 s) in the headless `claude -p` session. The owner chose to fix Serena for the contour and keep §0 as it is.

The monitoring session (owner of the shared gha-pool runners) looked at the run: `serena` is on the runner (the preflight did not warn "no serena"), but `.github/workflows/teamwright-agent.yml`'s "MCP servers and toolchain images" step only writes `mcp.json` and builds no index, so `serena start-mcp-server --project-from-cwd` starts cold (Python plus the Rust and TS language servers), and `MCP_TIMEOUT` is not set. The runner environment is shared by six projects and is not changed for this; the fix belongs to voicen's workflow. Proposed by monitoring:

- in the preflight, in the `command -v serena` branch after `mcp.json` is written: `timeout 600 serena project index . >/dev/null 2>&1 || echo "::warning::no Serena index built in advance"`;
- in the env of the `claude -p` step: `MCP_TIMEOUT: "120000"`.

Another project on the pool builds the index in advance and still saw two timeouts under load on 2026-11-17, so both changes are needed.

## Investigation

Tools: Serena was not used, because the scope is YAML and bash, which it does not index. I read teamwright-agent.yml, release-guard.sh (R1-R14), area-image.test.sh and contour-busy.test.sh with grep and file reads. For Serena's behaviour I read the installed serena-agent 2.1.1.dev0 source (`serena/cli.py`, `serena/config/serena_config.py`, `solidlsp/ls_config.py`). For MCP_TIMEOUT I used context7 `/anthropics/claude-code`.

- **The project config is not in the checkout.** `.serena/project.yml` is git-ignored (decisions #16). `serena project index .` auto-creates it ("Auto-creates project.yml if it doesn't exist"), together with `project.local.yml` (ignored by `.serena/.gitignore`) and `.serena/cache/` (ignored). The tree stays clean, so the commit and push steps see nothing new. `actions/checkout` cleans ignored files on each run, so every run indexes again. The 600 s bound is per run.
- **Languages on the runner.** When it auto-creates the config without a TTY, Serena enables only the top-ranked language. Markdown, YAML and other non-programming languages get priority 0, so voicen gets `rust` only. Local `.serena/project.yml` has typescript, rust, markdown and svelte (#72, #146), so on the contour TS and Svelte have no symbol tools. The cold MCP start has the same limit today, so this is not a new limit. It is listed as an owner question below and is out of scope here. The runner's serena version was not checked; the analysis assumes 2.x behaves like the host's 2.1.1.dev0.
- **MCP_TIMEOUT reaches claude.** The step's `env -u GITHUB_ENV -u GITHUB_PATH -u GITHUB_OUTPUT -u GITHUB_STATE claude -p ...` unsets only those four variables, so a step-level `MCP_TIMEOUT` reaches the CLI. `--mcp-config` and `--strict-mcp-config` choose which servers start; the startup timeout comes from that variable.
- **Guards.** The header (`diff` against `scripts/ci/contour-heads/teamwright-agent.yml`: identical today) ends at line 46. The tail starts at `- name: Stage the session for upload`. Both edits fall between them. Rules that apply to step text: R4 (no new `secrets`), R6 (no `\x`, `\u`, `\0` or trailing-backslash escapes), R8 (no `!!`), R11 (no word `uses` and no action token, comments included), R12 (lines start with a space), R13 (no `<<`; `2>&1` is fine). Monitoring's two lines pass all of them. The `make check` tests that read this file match `scripts/ci/area-image.sh` and the image-tag literals (area-image.test.sh) and teamwright-next.yml's `gh run list` line (contour-busy.test.sh). Neither touches the edited lines. **No guard file changes, `checker: false`.**

**Owner question (optional, not blocking):** should the preflight pass `--ls rust --ls typescript` to `serena project index`, so the contour also indexes TS? Recommendation: not in this task. On the runner the TS server may need an npm install, which adds a network dependency to the preflight. Do it as a follow-up once T-233's run shows Serena connecting.
