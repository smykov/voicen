## Context

T-060 carried T-076 review 3 Low #2: when post-processing fails with an HTTP error, the dictation line does not say which status the provider returned, so the owner's log cannot tell a 401 from a 429 or a 5xx. OQ-67 asked whether to add it to the closed log grammar; the owner chose (a) (decisions #205): `pp_http_status=` on the dictation line, a closed integer, no body text (FR-20, NFR-04: never transcript text, audio or keys).

## Acceptance

- [ ] A post-processing attempt that ended with an HTTP status writes `pp_http_status=<integer>` on its dictation line, next to the existing post-processing fields
- [ ] The value is the status code only: no reason phrase, no response body, no header (closed grammar, `docs/decisions/diagnostics-log.md` updated with the field and its rule)
- [ ] Failure branch: post-processing that failed without an HTTP response (timeout, connection refused) or did not run writes no `pp_http_status=` field, verified by a log-format test
- [ ] Test that fails without the change: a diag format test with a scripted 429 from post-processing
