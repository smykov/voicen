## Context

Option 1+2 of #360. Today `actions/checkout` (default `clean: true`) wipes `.teamwright/cache/` every hop, and `teamwright-agent.yml` mounts no sccache, `target/` or cargo registry, so every hop compiles core and downloads crates from zero (`docker/voicen-core-entry.sh` falls back to plain rustc when `_tw-sccache` is absent). Owner's idea: prepare the build before the session starts.

Measured 2026-11-24 (decisions #360): contour prep steps ("Task branch", "MCP servers and toolchain images") take 0 min; the time is inside the stage. Implement hop 59 min (run 45316103610); local `make check` 18 min in CI, 50-54 min on the shared host (`.teamwright/logs/gate/runs.jsonl`); a `wip/<ID>` `ci.yml` run 52 min serial (gate 21 + windows 24-31, `windows: needs: gate`; runs 45344541978, 45346473438, 45332192687); T-247 needed 4 wip rounds, T-151 3; the review hop re-runs the same gate (T-157 review: 54 min, `core.json` key = tree).

Guard paths (workflows, `scripts/ci/`, byte-pinned heads and fragments) change in pairs; `checker: true`, `analysis.decides_on` (P-020).

## Acceptance

- [ ] A contour hop's `scripts/tw-run core` uses a sccache dir and a cargo registry kept on the runner host (outside the checkout, like `RUNS_DIR`), shared by every task; a second hop of the same tree shows sccache hits in its gate log
- [ ] Before the stage step starts, a background prebuild (`cargo test --workspace --no-run` in the core image, and the UI build) runs, and the session's first gate does not recompile what it built; a failed prebuild never fails the job and is reported as a warning
- [ ] A push to `main` warms the shared cache (a job on the contour runner, or the prebuild of the next hop), without a write token
- [ ] Failure branch: a missing or unwritable host cache dir → the hop runs cold with one `::warning::`, never red
- [ ] Test that fails without the change: the pins of the new steps in `scripts/ci/*.test.sh` (byte-pinned fragment or head), red on today's tree
