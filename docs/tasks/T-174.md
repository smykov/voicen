## Investigation

Investigator 2026-11-10. Tools: Serena `get_symbols_overview` worked on `src-tauri/src/win/hotkey.rs`; `find_symbol` found `WarningKind` in core but nothing for `DictationSession/hotkey_registration` (name path missed it), so grep and file reads were used for the shell and for `dictation.rs`. Context7 not needed: no new library API (only `PostMessageW` / `recv_timeout`, already used and unchanged).

**Per line**

1. T-055 r1#4 (`finish` timeout): confirmed. `HotkeyRegistrarHandle::finish` discards `recv_timeout`. The handle has no `Log`. The cheapest path is `Link` (built in `attach` from `HotkeyThread`), which can carry the `Arc<Log>` that `HotkeyThread::start` already gets. Then `new()` and `lib.rs` stay as they are, and an unattached handle still does nothing. A timed-out commit means the save already swapped the snapshot, so "registered == snapshot" does not hold until the queued commit runs. That is why the line is worth logging. The typed kind is new (`hotkey_request_timeout`) and follows the T-006 precedent in `docs/decisions/diagnostics-log.md`.
2. T-010 r1#2 (lost `PostMessageW`): confirmed at hotkey.rs:387. The comment already admits it. The queue is the thread's own, and it fails only at the 10 000-message quota, which no test can reach deterministically while the loop drains it. Recommended: accept the loss and record it in windows-shell.md invariant 1. The log-once flag is the alternative, but it would be untested code.
3. T-010 r1#3 (SETTLE): **already done by T-108 round 2** (037884d0; T-108.reviews/2.md r1#1 "closed"). The test now calls `hotkey_round_trip`. The cited line :1021 is stale. What is left is this task's failure branch, "a reassert that never happens fails the test": it does not hold today. With the hotkey registered, a missing reassert leaves it registered, and the 1409 probe passes. `hotkey_registration(true)` while not failing changes no tray state (`publish` dedups), so nothing else can be observed. Injecting a failing report through the session's public input first makes the reassert's success report observable (HotkeyError clears).
4. T-108 r2#1: confirmed. `hotkey_round_trip`'s `TakenHotkey::take()` read-back is the first check to see an unregister with no register after it. Its message blames the round trip, and the test's Bite comment names the later probe.
5. T-009 premise: confirmed true. `cancel_key_result` reads `live_id().is_some()`. The only `hotkey_pressed` call is hotkey.rs:705 (grep over `src-tauri/src`; core has no other start input: `DictationSession`'s public fns, dictation.rs). So a later recording cannot start while the hotkey thread serves a claim. Write it on `Registrations::cancel_key` and in the module doc. Keep it in mind for T-129 (a second, call hotkey): a call recording is not a dictation `live_id`, so the premise holds, but that task must re-check it.

**Recurrence**: none. docs/failures.md has no entry for logging gaps in the hotkey thread. F-020 / class `test-probe-takes-claimed-resource` covers the probe ordering, which T-108 closed. This task keeps that ordering (round trip before the probe) and adds no new probe.

**Size**: small (one shell seam, plus a one-variant core diag addition). Not large, no spec needed. Windows CI only for the shell part. The core part (`WarningKind`, format table) runs in the Linux gate.
