Hard-link approach, checked:
- **Atomic between two writers.** `fs::hard_link` is `linkat` on Linux and `CreateHardLinkW` on Windows. Both fail with EEXIST / ERROR_ALREADY_EXISTS, which std maps to `AlreadyExists`, when the target exists. So exactly one writer claims a name and there is no exists-then-rename window. The tmp is `<stem>-<kind>.tmp`, opened `create_new`, so `begin` (abnormal_end) and the hook (panic) never share a tmp. The file handle is dropped before the link (it is moved into the `and_then` closure), so Windows links a closed file. Windows CI ran the core tests, so NTFS behaviour is covered by tests that ran.
- **Tmp cleanup.** On a write error the tmp is removed (unless it already belonged to another writer). After the loop it is always removed, whether the link was claimed, all 60 names were taken or another link error broke the loop. Removing the tmp leaves the `.txt` link intact. A kill between link and remove leaves a stale tmp, which `begin` removes (`remove_stale_tmp`, session.rs:117, run before `write_crash_file`).
- **Hard links unsupported** (FAT/exFAT, some shares): the loop's `Err(_) => break` returns `None` and leaves no file. Under the old `rename` such a folder still got a file. This is accepted: the logs folder is under `%LOCALAPPDATA%` on the system volume, which Windows requires to be NTFS. The contract states the requirement, and decisions/diagnostics-log.md lists it as not covered. It is a documented `None`, not a silent success.
- **Hook path stays lock-free and panic-free.** The only additions are `OpenOptions` / `write_all` / `hard_link` / `remove_file`, `checked_add` on the time (no overflow panic), a bounded `for 0..60` and `ErrorKind` matches. There is no `unwrap`, no indexing, no lock and no `Log`, and the crate's `deny` lints still cover the module.
- **Name and verdict.** The name returned is the one linked, and `time:` keeps the true time. Both orders (begin→panic, panic→begin) and the planted-foreign-name case are pinned. The bite list (`replace`, `skip`, `badgrammar`, `oldname`, `otherpid`, `steptime`) covers every way to get it wrong, and I confirmed by reading that each assert would turn red under its switch.
