## Context

Follow-up 3 of decision #91. The dictation log line (FR-20) gets closed fields for post-processing: `pp=applied|skipped|off`, `pp_reason=<one of the six skip reasons>` and `pp_ms=<duration>`. This touches `events.rs`, `diag/observer.rs`, the diag_format grammar and the diag_pipeline redaction run. No prompt, transcript, reply or key ever reaches the line.

## Acceptance

- [ ] Every dictation line of a post-processed job carries `pp=` and, for a skip, `pp_reason=`, plus `pp_ms=`; a job with post-processing off carries `pp=off`.
- [ ] Failure branch: a planted prompt, transcript, reply and key never appear in the log (the diag_pipeline redaction run).
- [ ] Test that fails without the change: named in `## Tests`.

## Investigation

2026-10-09, problem-investigator. Serena tools were not available in this session; context gathered with grep and file reads over `crates/voicen-core/{src,tests}`, `src-tauri`, `docs/`, `specs/003-llm-post-processing/`. No library API is involved (std `Instant` only), so no docs lookup.

**Frame.** Type `feature`. Observed: a post-processed dictation logs as `dictation rec=… engine=… outcome=delivered result=…` with no trace of post-processing; a skipped job and a job with post-processing off give the same line. Expected (spec 003 FR-014, US3-2; #91 follow-up 3; FR-20): the outcome (applied / skipped + reason category) and the step duration, and never the transcript (raw or final), prompt, key, reply or error body.

**Where the information is lost (evidence).**
- `Pipeline::process`: `self.deps.post_processor.process(&raw, &input)` is called with no clock around it; the result is folded into `Outcome::Text { skipped: Option<SkipReason> }` (`Applied` and `NotRun` both become `None`), which only `Pipeline::release` → `JobEnd::DeliveredSkipped` reads.
- `DictationEvent::JobFinished` (`events.rs`) has `seq, recording, engine, stop_to_text_ms, outcome, failure, http_status`; nothing about the stage. `DictationEvent` is `Copy`, so `SkipReason` (holds `host: String`) cannot ride on it as is — which is right: the host must not reach the log anyway (diagnostics-log invariant 1, T-008 Q1 "no hosts").
- `diag::DictationLine` / `format::write_dictation` / `observer::Record`: no pp field. `tests/diag_support::check_closed` rejects any unknown key on a `dictation` line, so the fields must be added to the grammar too.
- `tests/diag_pipeline.rs` installs `PassThrough`: the redaction run never puts a prompt into a request or a reply into the pipeline, so today it cannot prove FR-014's "no prompt, no reply".
- `ChatPostProcessor::process` returns `NotRun` exactly when `settings.enabled` is false (first step, before the URL check); `PassThrough` (tests only since T-074) also returns `NotRun`. So `NotRun` ⇔ `pp=off` in the app.

**Hypotheses (feature form).**
1. *The data exists and only the event lacks a field* — confirmed: outcome and reason are known in `process`; only the duration has to be measured.
2. *A second path calls the post-processor* — refuted by grep: `post_processor.process` is called only in `Pipeline::process`; `src-tauri` only installs `ChatPostProcessor` (`start_dictation`). The retry path (T-007) is planned as a second `Job` constructor into the same `process → release`, so it inherits the field.
3. *A second log path for post-processing* (spec 003 tasks T026 "one allowlisted log line per post-processed dictation", plan's separate `post_process outcome=… duration_ms=…` line) — rejected by the diagnostics-log invariant "one dictation is one line" (T-020 Investigation point 8 found the same).
4. *This class was fixed before* — no: class `diagnostics-log` has no `docs/failures.md` entry; the precedent for adding a closed field is T-051 (`CaptureFailed` → `mic=`) and T-006 (`PressBlocked` → `reason=`).

**Options.**

- **A — a closed field on `JobFinished` (recommended).** `events.rs`: `pub struct PostProcessTrace { pub result: PostProcessResult, pub ms: u64 }` and `pub enum PostProcessResult { Off, Applied, Skipped(SkipKind) }`, `pub enum SkipKind { Timeout, Unreachable, InvalidKey, Http, InvalidResponse, NotConfigured }` (all `Copy`; `SkipReason::kind()` an exhaustive match in `post_process`). `JobFinished` gets `post_processing: Option<PostProcessTrace>` — `None` when the stage was not called (no speech, engine not built, transcription failed or blank). `Pipeline::process` takes `Instant::now()` before and after `post_processor.process` and stores the trace in `JobOutcome`; `release` passes it to every `JobFinished` it emits (text, clipboard-failure `Failed`, post-processed-to-blank `NoSpeech`). `LogObserver` copies it into `Record` (set on `JobFinished`, read at the line close); `DictationLine` gets `post_processing: Option<PostProcessTrace>`; `write_dictation` writes `pp=<off|applied|skipped>`, `pp_reason=<…>` for skipped, `pp_ms=<n>` for applied/skipped, each from its own literal table in `format.rs` (like `mic()`), not from `SkipReason::code()`.
  *Why it closes the gap:* the one call site of the stage produces the trace; the one job-summary event carries it; the observer already reads every per-job field from `JobFinished`. *Risk:* every non-`..` `JobFinished` pattern in tests must name the new field (`pipeline.rs` tests, `api_pipeline.rs`, `post_process_timeout.rs`, `dictation_session.rs`, `diag_observer.rs` — about a dozen sites; compile errors, not silent). Exact event-sequence assertions are untouched. *Rollback:* revert the commit; no stored data or settings format changes.
- **B — a new `DictationEvent::PostProcessed { recording, result, ms }`** emitted from `process` right after the stage, joined by `RecordingId` like `SpeechGate`. Same closed types. *Against:* every exact event-sequence assertion of a successful job changes (`api_pipeline.rs`, `dictation_session.rs`, `local_server.rs`, `pipeline.rs` tests), `diag_observer.rs`'s "every variant fed" table grows, and one more event per dictation for every observer; no gain over A, since the line closes on `JobFinished`/`Delivered` anyway.
- **C — the post-processor logs its own line** (spec 003 T026's form). *Rejected:* `ChatPostProcessor` is stateless and has no observer (post-processing invariant 1); a second line per dictation breaks "one dictation is one line"; the processor would hold the outcome with its `host`.

**Recommended: A.** It is also what T-020's Investigation (follow-up 3, point 8) sketched.

**Format and grammar (for the developer).**
- Line: `dictation rec=3 engine=api outcome=delivered result=pasted detector=energy pp=skipped pp_reason=timeout press_to_frame_ms=… duration_ms=… stop_to_text_ms=… pp_ms=15004 text_to_paste_ms=…` (order is a suggestion; keep it fixed). Update the example block in `diag/format.rs`'s module doc.
- `pp_reason` values: `timeout`, `unreachable`, `invalid_key`, `http`, `invalid_response`, `not_configured` (the six `SkipReason::code()` spellings, written from format.rs's own table). No HTTP status for `http` (FR-014 asks for the reason category; a `pp_http_status=` is a possible later addition, not in this task). No host for `unreachable`.
- `diag_support`: add `PP_RESULTS`, `PP_REASONS`; `pp`/`pp_reason` closed, `pp_ms` unsigned; co-occurrence: `pp_reason` ⇔ `pp=skipped`; `pp_ms` ⇔ `pp ∈ {applied, skipped}`; `pp*` absent on `blocked`, `too_short`, `cancelled`, `capture_failed` lines. `diag_format.rs` `every_event`: dictation lines with each `PostProcessResult` (6 skip kinds) and `None`.
- `diag/mod.rs` doctests: the three `DictationLine` literals (two `compile_fail,E0308`, one positive) must get the new field, or the compile_fail blocks also fail with E0063 and no longer fail "only because of the string".
- Level: a skip stays `INFO` on a delivered line (the dictation was delivered; the overlay and tray already report the skip). Keep `log_level` keyed on `DictationOutcome` only.

**Interpretation, stated (not an owner question).** "A job with post-processing off carries `pp=off`" is read with FR-014's "for each post-processed dictation": `pp=` appears exactly on lines whose job reached the stage. A no-speech, failed-transcription or engine-not-built job has no `pp*` keys whether post-processing is on or off — nothing about the stage happened, and inventing `pp=off` from the settings there would make "off" mean two things. If the owner wants `pp=` on every job line, it is a one-line change in `release` (build `Off` from `job.settings.post_processing.enabled` when the stage was not called); no OQ opened.

**Tests to write first (red before the change).**
1. `tests/diag_pipeline.rs` — new scenarios through a real `Pipeline` with `ChatPostProcessor` (two wiremock routes: transcription and `chat/completions`), `LogObserver`, `Log` over a temp dir. Planted: prompt `PROMPT-SECRET-…`, transcript `TRANSCRIPT-SECRET-…`, chat reply `REPLY-SECRET-…`, post-processing key `sk-test-PP-SECRET`, a base-URL query secret; an error body that echoes the transcript and prompt for the HTTP 500 skip. Scenarios: applied; skipped http 500; skipped timeout (small `Timeouts` via `Pipeline::with_timeouts`); skipped not_configured (bad base URL); skipped invalid_key (401); off. Assert per scenario: its dictation line has the expected `pp`/`pp_reason`/`pp_ms` presence (red today: `pp` absent), and no planted byte (UTF-8 and UTF-16LE, `diag_support::contains`) in any file under the logs dir. Positive controls: the chat mock received the prompt, transcript and key; the clipboard got the reply (applied) or the raw transcript (skips). Use `common::timing` / `OsAnswer` per T-080; fake data only (127.0.0.1, example.com).
2. `tests/diag_observer.rs` — a `JobFinished{post_processing: Some(Skipped(Timeout), 15004)}` + `Delivered` gives one line with `pp=skipped pp_reason=timeout pp_ms=15004`; `None` gives no `pp*` key; a clipboard-failure `Failed` keeps the `pp` keys.
3. `pipeline.rs` unit — `post_processing_outcome_and_duration_reach_job_finished`: a `FixedPostProcessor` returning each outcome (with a short sleep for `ms > 0`) → `JobFinished.post_processing` matches; no-speech / failed transcription → `None`.
4. `tests/diag_format.rs` — grammar and closed-set rows above.

**Docs in the same commit.** `docs/decisions/diagnostics-log.md` (invariant 1: the pp fields and their literal tables; the one-line invariant: pp travels on `JobFinished`), `docs/decisions/post-processing.md` (Tests that pin it; "Nothing secret in a skip": the log gets the kind only, never the host), `docs/architecture.md` if it lists the dictation line keys.
