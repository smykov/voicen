## Context

Three tests fail under host load and are so far only noted in T-060: the e2e boot 5 s limit, the `local_download` trickle test, the `connection_test` 2 requests test. A green re-run under P-016 counts only if each red attempt's failure is logged as its own task or F-entry; this task is that entry. The `tw-test ui` e2e bug was seen in the same period; the investigation reproduces it and records what it does. Host limits apply: Playwright workers=2, cargo -j2, heavy runs in `agent-tests.slice`.

Owner decision #246 (2026-11-06), on the investigation's non-blocking question 1: the ui area gets a `test_select_command`, so `scripts/tw-test ui <selectors>` runs `e2e/` selectors through `pnpm e2e` and `src/` selectors through vitest. This task adds the selector router next to `scripts/ui-unit-test.mjs`: one script, taking the selectors, that sends each to its runner and exits non-zero if any selector matches no test. It sits in the same non-guard `scripts/` seam. The config change itself (`.teamwright/config.next.yml` plus `tw-install.py apply`) is the orchestrator's job after the merge, on the owner's yes, because agents cannot edit `.teamwright/config.yml`. Question 2 (teamwright feedback) goes to the owner as a draft and is outside this task.
