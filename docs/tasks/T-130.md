### API the tests pin (the developer implements exactly these)

Core (`crates/voicen-core`):
- `voicen_core::settings::service::IndicatorPositionFailed` (unit struct, `Debug, Clone, Copy, PartialEq, Eq`) and `SettingsService::remember_indicator_position(&self, IndicatorPosition) -> Result<(), IndicatorPositionFailed>`: the `remember_warned_host` pattern (`Unavailable` -> Err and no file call; same value as in force -> Ok, no write; else only `calls.indicator_position` changes, one file write, then swap + publish; a write failure keeps the snapshot and the file, Err).
- `voicen_core::call::indicator::{WorkArea { left, top, right, bottom: i32 } (right/bottom exclusive; first entry of the slice = primary), INDICATOR_DEFAULT_MARGIN: i32 = 16, place_indicator(stored: Option<IndicatorPosition>, size: (i32, i32), work_areas: &[WorkArea]) -> IndicatorPosition}`. Rules: None -> top-right of the primary inset by the margin (`x = right - width - margin`, `y = top + margin`); fully inside some area -> unchanged (negative coordinates included); else moved the least into the one area it overlaps most (by pixels), when it overlaps none the nearest (rect-to-rect gap, ties to the earlier entry); larger than the area -> pinned to the area's left/top. An empty slice is not pinned.
- `OverlayLifecycle::on_visible(&mut self, seq, visible: bool) -> WindowAction` and `on_wake_visible(&mut self, destroyed: &[u64], newest: Option<(u64, bool)>) -> WindowAction`; `on_state` / `on_wake` / `on_destroyed` / `on_build_failed` / `generation` / `phase` and `lifecycle_tests` unchanged. For the indicator `visible` = the newest `IndicatorState.recording`.

Shell (`voicen_lib`, see the header of `src-tauri/tests/call_indicator.rs`): `call_indicator::{LABEL = "call-indicator", Settled {seq, window, failed}, start(app, Arc<SettingsService>, Arc<Log>), settled(app, hang) -> Option<Settled>}` (`start` creates and manages the mailbox and spawns the thread, no window; `call::start_calls` calls it before `CallSession::new`), `ShellCallIndicator::new(app)` forwards `set_state` / `set_tick` to the part, `CallRequest::{IndicatorStop, Dismiss(u32)}`, commands `call_indicator_state` / `call_indicator_stop` / `call_indicator_dismiss(warning_id)`, `capabilities/call-indicator.json`, `APP_COMMANDS: [&str; 19]` (no `call_indicator_moved`, decisions #314).

Investigator, 2026-11-07. Serena was used for core symbols (`overlay.rs`, `call/session.rs`). The Serena index answered for Rust core; shell files were read with grep and sed. **Frame.** This is a feature, not a defect. FR-005 needs an interactive, movable, topmost window that never takes the focus from the call app (the user is talking in Zoom or Telegram; a stolen focus loses their keystrokes). Today the core publishes indicator state into a port that nothing in the shell implements.

**Hypotheses / what is open**
1. *ADR-007 primary (WS_EX_NOACTIVATE) gives clicks and drag without activation on WebView2.* Confirm: spike rows 3 and 4 green under variant N. Refute: the target loses the foreground at the click (WebView2's browser-process child calls SetFocus or activates), or the HTCAPTION move loop activates or does not move the window. No evidence either way on this machine; Windows CI only.
2. *A second webview adds a top-level helper window.* Unlikely. tao's event-target window is per event loop. single-instance is not registered in tests. WebView2 adds child windows. `helper-windows.txt` is keyed by crate@version, and T-130 adds no crate or feature (`windows` is a `binding` entry, and all needed Win32 features are present). 3. *A second path handles the same concern.* Yes: the dictation overlay (`src-tauri/src/overlay.rs`, overlay.md invariants 1-4) solves the same build/show/destroy race and the same non-activating show. The indicator must follow the same rules, not a parallel variant. Hence the shared `OverlayLifecycle` reducer and the same "built hidden, one raw SW_SHOWNOACTIVATE, no tao setter afterwards" rule. A tao setter on a raw-shown window would diff the flags and `SW_HIDE` it or `SW_SHOW` it (overlay.md §3, tao `window_state.rs:405-467`). 4. *This class was fixed before.* No `docs/failures.md` entry of class `overlay`. F-003 and F-008 (smoke predicate) apply to the census: the indicator is a product window and is never listed as a helper (R12, overlay.md §5).
