## Investigation

Tools: Serena `find_referencing_symbols` on `engine::http::client` returned nothing (the index does not resolve the free function's callers), so callers were found with grep over `crates/` and `src-tauri/` (`http::client`, `client_with_read_timeout`, `Client::builder`); src-tauri builds no reqwest client, and `make check-ban-canary` (T-089) bans any client outside `engine::http`. Context7 (`/seanmonstar/reqwest/v0.13.5`) returned only the README for the redirect API, so the behaviour below is read from the pinned sources in the core image's cargo cache (`reqwest-0.13.5`, `tower-http-0.6.11`, versions from `Cargo.lock`).

### 1. Frame

- Observed: a configured endpoint (API, local server, post-processing) that answers 307/308 with a `Location` on another host gets the same POST, body included, re-sent there; the reply of that host is used as the transcript / post-processed text. `Authorization` is dropped (pinned by `cross_host_redirect_drops_the_key`).
- Expected (acceptance): a redirect to another origin is refused, nothing is re-sent, a same-origin redirect is still followed, the refusal is a classified failure, no log line carries transcript, prompt or URL secrets.
- Symptom vs. guess: the task names prompt and transcript; the transcription path is affected the same way with the audio (see 3).

### 2. Hypotheses

1. The shared client uses reqwest's default policy, which follows any origin — confirmed (3).
2. A second path builds its own client with another policy — refuted: every client comes from `engine::http::build` (ban canary); callers are `openai.rs::send` (API, local server, Test connection through `connection_test::run` -> `transcribe`), `post_process/chat.rs::send`, and the downloader `download.rs::run` (catalog models and `vad::silero_model::fetch` through `download_pinned`) via `client_with_read_timeout`.
3. The body is not clonable, so 307/308 would not re-send it — refuted: both bodies are `Vec<u8>` (`openai.rs` buffers the multipart form, `chat.rs` `serde_json::to_vec`), which `Body::try_clone` clones.
4. Fixed before (recurrence) — refuted: `docs/failures.md` has no entry on redirects, cross-origin, Authorization or the base URL (grep `redirect|cross-host|cross-origin|re-sen|base url`); the only earlier treatment is spec 003 research R5 / T-020, which pinned the key-drop and recorded the body re-send as the residual (`docs/decisions/post-processing.md` Known residual). Recurrence: none.

### 3. Evidence: reqwest 0.13.5 behaviour

- `ClientBuilder` default `redirect_policy: Policy::default()` = `Policy::limited(10)` (`src/redirect.rs` `impl Default for Policy`; async_impl/client.rs:311): follows any origin up to 10 hops, then `TooManyRedirects` error.
- On each hop `remove_sensitive_headers` (`src/redirect.rs:239`) removes `Authorization`, `Cookie`, `Cookie2`, `Proxy-Authorization`, `WWW-Authenticate` when host, port (`port_or_known_default`) or scheme differ from the previous URL. Nothing else is removed. `referer` defaults to true: the next hop gets `Referer` = previous URL minus userinfo and fragment, i.e. the configured base URL's path and query (a URL secret in the query would leak through it).
- tower-http `FollowRedirect` (`src/follow_redirect/mod.rs:273-291`): 301/302 turn a POST into a bodiless GET; 303 into GET; 307/308 keep method and body (reqwest's `clone_body` -> `Body::try_clone`). So a cross-origin 307/308 re-sends the full audio (transcription) or prompt + transcript (chat); a cross-origin 301/302/303 sends a bodiless GET whose 2xx reply is still parsed and used.
- Policy API: `Policy::custom(Fn(Attempt) -> Action)`; `Attempt::url()` (next), `Attempt::previous()` (all URLs requested so far, the first is the initial URL), `attempt.follow()`, `attempt.stop()` ("the 30x response will be returned as the Ok result"), `attempt.error(e)` (a `reqwest::Error` with `is_redirect()`). The policy runs before the next request is built, so `stop`/`error` sends nothing to the next origin.
- Current tests pin the leak as wanted: `tests/post_process_chat.rs::cross_host_redirect_drops_the_key` asserts `followed.len() == 1` at the other origin.

### 4. Root cause

`engine::http::client` never sets a redirect policy, so reqwest's default follows redirects to any origin and only strips credential headers; the body (and Referer) still go to the new origin and its answer is used. One mechanism explains the chat leak, the same leak with audio on the transcription and Test-connection paths, and the bodiless-GET variant for 301/302/303.

### 5. What "origin" means

The web origin of the URL: (scheme, host, port), port defaulted per scheme — `url::Url::origin()` (tuple origin for http/https; `https://h` == `https://h:443`, `http://h` != `https://h`, `127.0.0.1:A` != `127.0.0.1:B`). Compare the next URL against `previous()[0]`, the URL the engine built from the configured base URL. Consequence: an `http://` base that upgrades to `https://` on the same host is refused; with a key that setup already fails today (reqwest drops Authorization on a scheme change -> 401), for a keyless local server it is a new refusal that the user fixes by entering the https URL.

### 6. Invariant and seam

- Invariant: every request from a `client()` client goes only to the origin it was built for; a redirect to another origin is never followed and nothing reaches it. The download client is outside this invariant on purpose.
- Why the downloader must keep cross-origin redirects: every catalog URL and the Silero pin are `https://huggingface.co/.../resolve/<commit>/<file>` (`local_models/catalog.rs:80-112`, `vad/silero_model.rs:41`); Hugging Face answers LFS/Xet files with a 302 to its CDN host. It sends a GET with no key and no body, and only a file of the pinned size and SHA-256 is kept, so following is safe. (Network not checked here; a pin test with two fake servers covers our side.)
- Seam: `engine::http`. `build` takes the policy as an argument; `client` passes the same-origin policy, `client_with_read_timeout` passes `Policy::default()` explicitly. No caller changes.

### 7. How a refused redirect surfaces

Existing classification (`failure::classify`): `Status(401|403)` -> `InvalidApiKey`; other `Status(s)` -> `ServerError { status }`; `Send` with no flag -> `UnexpectedResponse`.
- With `attempt.stop()` the 3xx response is returned; `HttpClient::send_capped` maps any non-2xx to `TransportError::Status(3xx)` without reading the body (P-009) -> `FailureReason::ServerError { status: 307 }`; post-processing `SkipReason::from_failure` -> `SkipReason::Http { status }` (transcript delivered raw, as for any HTTP error); Test connection `from_failure` -> `ConnectionTestResult::Http { status }`. All existing, translated, total. The status tells the user the endpoint redirects.
- With `attempt.error(..)` the send fails with `is_redirect()` and no other flag -> `send_error` gives `Send { .. }` all false -> `UnexpectedResponse`: less telling, and the same as the existing 10-hop `TooManyRedirects`.
- Recommended: `stop()` -> `ServerError { status }`. A dedicated reason ("the server redirected to another address") would need a new `TransportError`/`FailureReason`/`SkipReason`/`ConnectionTestResult` variant and i18n text in two languages: a product wording choice, not needed for this fix; can be an OQ if the owner wants it.

### 8. Logging (FR-20, NFR-04)

`engine::http` logs nothing; `send_error` keeps only flags (the `reqwest::Error` Display holds the URL, query included, and is never formatted); a `FailureReason` carries only the configured `host[:port]` and the status. With `stop()` nothing of the `Location` URL is kept anywhere. The policy closure must not log or format `Attempt` (its URLs may carry query secrets). The dictation log line already shows `ServerError` as code + status; the diag log test is the place to prove no transcript, prompt, key or Location query reaches a log file.

### 9. Approach options

- **A (recommended)**: `Policy::custom` in `engine::http` — same origin as `previous()[0]` -> `Policy::default().redirect(attempt)` (keeps the 10-hop limit), else `attempt.stop()`. Pure predicate `same_origin(next, first) -> bool` beside it for unit tests (`Attempt` cannot be built outside reqwest). Optional hardening: `.referer(false)` on the same client (Referer then never carries the base URL, even same-origin; harmless). Removes the cause: no cross-origin request is ever built. Risk: an endpoint that legitimately redirects to another origin now fails with HTTP 3xx (OpenAI-compatible APIs are called at their final URL; the user can enter it). Rollback: revert the one policy line.
- **B**: same predicate with `attempt.error(..)` plus a new classified reason end to end. Same protection, larger diff across core, i18n and UI; needs owner wording. Not recommended now.
- **C**: `Policy::none()` on `client()`. Simplest, but breaks acceptance "a same-origin redirect is still followed". Rejected.
