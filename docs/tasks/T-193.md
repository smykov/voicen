## Context

Owner decision #215 (OQ-71 (a)): an edit of `scripts/hooks/pre-commit` (its `guard_trigger`) or `scripts/hooks/_task.py` (reads `checker` and `analysis.decides_on` for it) can loosen the trigger in a task without `checker: true`, because the token (#155) covers only `scripts/ci/`, `scripts/licenses/`, `Makefile` and `*.mk`. Seam: `scripts/hooks/pre-commit` `guard_trigger`, `scripts/ci/guard-trigger.test.sh`, `docs/process/gates.md` › Guard trigger. This is a guard change: `checker: true`, and `analysis.decides_on` is required.

## Acceptance

- [ ] A staged path under `scripts/hooks/` is refused in a task without `checker: true` and `analysis.decides_on`, and passes in a task with both; `scripts/ci/guard-trigger.test.sh` covers both cases
- [ ] `docs/process/gates.md` › Guard trigger lists `scripts/hooks/` in the token and no longer names the hooks under Not caught; the CLAUDE.md line on guard changes says the same
- [ ] Failure branch: the self-test fails when `scripts/hooks/*` is dropped from the token again
- [ ] Test that fails without the change: the new `scripts/hooks/` case of `make check-guard-trigger`

## Investigation

Context tool: grep and file reads only (the seam is a git hook and bash checkers, no language-server symbols; Serena not used). Read: `scripts/hooks/pre-commit` (sections 1-4), `scripts/ci/guard-trigger.test.sh`, `docs/process/gates.md` › Guard trigger and › State guard, `PRINCIPLES.md` P-020, `docs/decisions/ci-toolchain.md` guard table, decisions #155, #215, #229, #230, #324-#326, `docs/tasks/T-189.follow-ups/r1.md`, `docs/kit-feedback.md`, `.teamwright/installed.json` (hook entries only), `git log -- scripts/hooks`.

**Frame.** Observed: a commit staging only `scripts/hooks/pre-commit` or `scripts/hooks/_task.py` passes the guard trigger in a task without `checker: true`. Expected (#215 (a)): it is refused like any other guard path. Reproduces on any host; no test covers it.

**Hypotheses.**
1. The path token has no `scripts/hooks/` form. Confirmed: `guard_trigger`'s single `case` line has four forms; no other place builds the guard list.
2. A second path decides guard changes (a CI check, a review gate). Refuted for the commit: `make check-guard-trigger` only runs the fixtures; the review gate does not read paths for P-020. Review (T1) is the only catch today, as gates.md › Not caught says.
3. Fixed before. No: #155 widened the token from a Make model to raw paths and left the hooks out on purpose (OQ-71 opened by T-185); #229 kept T-193's change.
4. The token could match but the parser import fails for hooks. Not applicable: the Python part reads only the record; the path list is passed as arguments.

**Root cause.** See `analysis.root_cause`. All symptoms in OQ-71 are explained; no contradicting evidence.

**Options.**
- **A (recommended)**: fifth `case` form `scripts/hooks/*` (bash `case` `*` matches `/`, so nested paths are covered); fixtures and an in-test mutant bite as in `approach`. Removes the cause in the one place the list is built.
- **B**: move the token to an owned list file `scripts/ci/guard-token.txt` read by the hook. The list itself would be a guard path, but it adds a file read to a hook that is self-contained today, and the hook would still need the edit. Not needed for #215.
- **C**: add only `scripts/hooks/pre-commit` and `scripts/hooks/_task.py`. Matches OQ-71's wording but not #215 ("`scripts/hooks/`"), and leaves the project-owned `wip-push-guard.sh` and the locally edited `test-guard.sh` out. Rejected.
