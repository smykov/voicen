## Context

Owner decision #215 (OQ-71 (a)): an edit of `scripts/hooks/pre-commit` (its `guard_trigger`) or `scripts/hooks/_task.py` (reads `checker` and `analysis.decides_on` for it) can loosen the trigger in a task without `checker: true`, because the token (#155) covers only `scripts/ci/`, `scripts/licenses/`, `Makefile` and `*.mk`. Seam: `scripts/hooks/pre-commit` `guard_trigger`, `scripts/ci/guard-trigger.test.sh`, `docs/process/gates.md` › Guard trigger. This is a guard change: `checker: true`, and `analysis.decides_on` is required.

## Acceptance

- [ ] A staged path under `scripts/hooks/` is refused in a task without `checker: true` and `analysis.decides_on`, and passes in a task with both; `scripts/ci/guard-trigger.test.sh` covers both cases
- [ ] `docs/process/gates.md` › Guard trigger lists `scripts/hooks/` in the token and no longer names the hooks under Not caught; the CLAUDE.md line on guard changes says the same
- [ ] Failure branch: the self-test fails when `scripts/hooks/*` is dropped from the token again
- [ ] Test that fails without the change: the new `scripts/hooks/` case of `make check-guard-trigger`
