## Investigation

Checked on branch tw/T-255 @ 3373b44f. Tools: Serena (`get_symbols_overview` src-tauri/src/call.rs, `find_referencing_symbols` `callErrorMessageId`; Serena does not index `.svelte`, so callers in `src/routes/calls/+page.svelte` were found with grep), grep over src, e2e, i18n, crates, src-tauri, specs. I ran no tests and no gate.

**Frame.** The task record (from T-119 r1#1) assumes an `ioFailed` from export, copy or open folder shows `calls.error.io`. That is out of date. T-143 (63036a51) maps every `ioFailed` to `calls.error.io.<reason>` ("Could not complete the action: <reason>"), and e2e/calls.spec.ts:266-319 already shows those texts for export, copy and open folder, with no folder named. Acceptance 3 as written (ioFailed) already holds. The defect that remains is the base text itself: `calls.error.io` is now the catch-all for everything else, and it still blames the call folder.

**Every command that returns `ioFailed`, and what the page shows today** (contract table contracts/ipc.md:42-49; shell `src-tauri/src/call.rs`; only the first five are registered, build.rs:23-27):

| Command | `ioFailed` source | `notFound` source | Text today for ioFailed | Text today for notFound / non-CallError rejection |
|---|---|---|---|---|
| `calls_list` | none (returns the wire, never a CallError) | none | — | base: "The call folder could not be read or changed." (IPC rejection only) |
| `calls_get` | damaged call, broken transcript (`CallStore::get`) | no call part (:1045), gone call, foreign root | `calls.error.io.<reason>` | base |
| `calls_copy_markdown` | `export_bytes` (no transcript = missing, damaged = other), non-UTF-8 (:1065), clipboard write (:1068, other) | `call_part` (:1000/:1003), guard in `export_bytes` | `calls.error.io.<reason>` | base |
| `calls_export` | `export_bytes`, save dialog failure (:1096), `export_to` (target, tmp, rename), join error (:1106, other) | `call_part`, guard | `calls.error.io.<reason>` | base |
| `calls_open_folder` | folder opener (:1136) | `call_part`, `CallStore::folder` (gone call) | `calls.error.io.<reason>` | base |
| `calls_rename`, `calls_rename_speaker`, `calls_transcribe`, `calls_delete` | core only (T-152, T-146); not registered in the shell, no UI caller | — | not reachable | not reachable (T-154 will add delete with `inUse` / `recordingCall`, which have their own ids) |

Texts of the reason family today (EN / RU): `missing` "Could not complete the action: the file or folder is not available" / "Не удалось выполнить действие: файл или папка недоступны"; `not_a_folder` "…: the path is not a folder" / "…: путь не является папкой"; `access_denied` "…: access denied" / "…: доступ запрещён"; `disk_full` "…: the disk is full" / "…: диск заполнен"; `other` "…: the file could not be read or written" / "…: ошибка чтения или записи файла" (i18n/en.json:18-22, ru.json:18-22). None of them names the call folder. RU base today: "Не удалось прочитать или изменить папку звонка."

**Hypotheses.**
1. The base text is shown for ioFailed on export. Refuted: view.ts:129-131 maps every ioFailed to the reason family; view.test.ts D4 and the e2e tests pin it.
2. The base text is the catch-all, and its wording comes from before T-143. Confirmed: view.ts:133; T-143's analysis says "notFound maps to `calls.error.io` for now"; calls-ui.md D4 says the same; en.json:17 was not changed by T-143 (`git log -- i18n/en.json`: 63036a51 added only the `.io.<reason>` ids).
3. A second path shows call errors with another text. Refuted for the Calls page: one `role=alert`, and every refusal goes through `callErrorMessageId` (+page.svelte:87, :102, :138). Setup failures use `error.ipc_unavailable` (:172, :177), which is correct.
4. This class was fixed before. Partly: T-143 fixed the ioFailed half of T-119 r1#1 with neutral per-reason texts. No F-entry in docs/failures.md covers a catalog text naming the wrong place (searched for catalog, wording, i18n, en.json). Not a recurrence; no rca task is needed.

**Root cause.** The one mapper's fallback id kept the text drafted for a call-folder `ioFailed`, so its real inputs (`notFound` on any command, and any rejection that is not a CallError) all show a folder-blaming text.

**Choice: one neutral base text versus per-command ids.**
- *One neutral base text (recommended).* The base id is reached only by causes that have no reason (gone call, foreign root, no call part, IPC/ACL refusal). The page is the only place that knows the action, and the user has just clicked it, so a neutral "could not complete the action" is true for all four commands and for list and detail. The change is two catalog strings, one contract row, one pinned core row and D4. The mapper and its tests keep their shape.
- *Per-command ids.* `callErrorMessageId` would have to take the action, and with the reason family that is 4 x 6 ids (or the per-reason texts would lose their neutrality). Nothing on the wire differs by command, so the extra ids would say only what the user already knows. Rejected.
- *Option C (variant of the first, owner's call).* Add `calls.error.not_found` for `notFound` ("Could not complete the action: the call is no longer available" / "Не удалось выполнить действие: звонок больше недоступен"), leaving `calls.error.io` for non-CallError rejections only. This is T-119 r1#3, which #351 put in T-154's Acceptance (T-154.md:41). It is more informative for a call deleted outside Voicen, but it moves a line between tasks. It touches the mapper, view.test.ts, the catalog, the contract, D4 and core `CALL_FIXED_IDS` (53 -> 54).

**Proposed texts (owner question, more than one wording fits):**

| | EN | RU |
|---|---|---|
| (1) recommended | Could not complete the action. | Не удалось выполнить действие. |
| (2) | Something went wrong. Try again. | Что-то пошло не так. Попробуйте ещё раз. |
| (3) | The action could not be completed. | Действие не выполнено. |

(1) repeats the reason family's prefix ("Could not complete the action: …" / "Не удалось выполнить действие: …"), so the base reads as the same message with no reason. It keeps the final period of the other full-sentence `calls.error.*` texts (`empty_name`, `recording`). EN and RU differ, so the RU-differs check holds.

**Red tests first.** (1) In `crates/voicen-core/src/i18n.rs::call_texts_the_contract_spells_out_are_exact`, the row `("calls.error.io", "<chosen EN>")` (array 25 -> 26), red on the current text. (2) In e2e/calls.spec.ts, for each of Copy, Export MD and Open folder, the command rejected with `callsError("notFound")` and with a plain non-CallError rejection (the mock's `{ reject }`): the alert has `en("calls.error.io")` and `not.toContainText(/folder/i)`, plus one RU case `not.toContainText(/папк/i)`. These are red today because the current text contains "call folder" / "папку". The mock helpers derive the error from the fixture (D7), so nothing is hand-written.

**Acceptance wording.** Acceptance 3 names `ioFailed`, which already passes (e2e :266-309). For a red-then-green test it should read "a `notFound` and a non-CallError rejection from an export, a copy and an open-folder each show a text that does not name the call folder". The orchestrator should reword it before IN_PROGRESS.
