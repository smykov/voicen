## Context

Split from T-010 by owner decision #63: the release-1 part of hotkey handling. The two-phase registrar used by settings (the hotkey step of T-032's save transaction; a refused save keeps the old hotkey registered; a saved hotkey works at once, without a restart — P-013), and the startup failure branch (a hotkey already taken at start: tray error state and the settings window opened on the Recording tab with the field focused, via T-037's `open(tab, field)`). Recovery after sleep, lock and Explorer restart stays in T-010 (P3).

## Acceptance

- [ ] Windows CI: saving a new hotkey registers it and unregisters the old one; the new one fires without a restart
- [ ] Failure branch: a hotkey taken by another process → the save is refused with the hotkey field error and the old hotkey stays registered; taken at start → tray error and settings opened on Recording with the hotkey field focused — Windows CI
- [ ] Test that fails without the change: `src-tauri/tests/hotkey_registrar.rs` (Windows CI)

## Investigation

**Frame.** Observed (owner, T-006 Refresh 5): a hotkey saved in Settings fires only after Exit and relaunch. Expected (FR-05, spec 004 R-3/R-4): the save registers the new hotkey before `Saved`, a taken one is refused with "hotkey unavailable" and the old one stays active; at startup a taken hotkey gives tray error + notification + settings on the hotkey field.

**Hypotheses.**
1. *The hotkey thread reads the codes once and nothing re-registers* — **confirmed**: `win/hotkey.rs` `HotkeyThread::start` parses the startup text once (:68), `run` registers once under the fixed `HOTKEY_ID` (:216, :232); its loop handles only `WM_HOTKEY`, `WM_TIMER`, `WM_QUIT`. `dictation.rs` `start_dictation` reads `snapshot().hotkey` once (:130-131).
2. *Second path: the save transaction's own hotkey step* — **confirmed, and it is the designed path**: `SettingsService::save` step (4) is a comment ("none until T-010", service.rs:380, :384); `SettingsDeps.hotkeys` is "held but not called" (:32-33); the shell injects `InterimHotkeyRegistrar` that always refuses (settings_ipc.rs:65, :137-149). No `subscribe()` consumer reads `hotkey` (change bridge, tray language follower, overlay).
3. *The session caches settings* — **refuted**: `DictationSession::hotkey_pressed` takes `snapshot()` per press (`saved_settings_reach_the_next_press`), so engine and mode saves are live; only the OS registration is stale.
4. *Class fixed before* — **no**: no `docs/failures.md` entry of class `hotkey`; T-006 deliberately left re-registration and the startup branch to T-055 (T-006.md :104, :202). Not a recurrence.
5. *Startup branch already complete* — **partly**: a failed registration reaches `DictationSession::hotkey_registration(false)` → tray `HotkeyError` (+ `hotkey_register_failed os_code=1409`, tests/hotkey.rs). Missing: overlay notice, settings window on Recording / `recording.hotkey` (`ShellRequests::open_settings(tab)` has no field; `SettingsRequests` posts `Tab(tab, None)`), toast (T-007, TODO).

**Root cause.** The two-phase registrar of spec 004 exists only as a trait; neither the save transaction nor the shell implements it, and the only registration is the startup one.

**Recommended approach (A).** Requests into the existing hotkey thread (Prepare under a spare id with a reply / Commit releases the old id, swaps id and poll codes after any current hold, calls `hotkey_registration(true)` / Abort releases the spare id), exposed as a late-bound `HotkeyRegistrar` handle created in `release_parts`, passed to `load_settings` and to `DictationPorts` (same instance, like `credentials`), fail-closed until `start_dictation` attaches the thread. Core: the save step per R-3 (prepare after validate, abort on every later refusal, commit after `write_atomic` and before the swap/publish), and the startup branch in `DictationSession::hotkey_registration(false)` (notice + `open_settings(Recording, Some(RecordingHotkey))` after the lock), so T-010's resume failure reuses it. Red tests and file list: analysis block. B (subscribe and re-register after `Saved`) and C (restart the thread on save) are rejected: both act after the file is written, so a taken hotkey is saved and no working hotkey remains (FR-05).

**Win32 facts.** `RegisterHotKey` must run on the thread that owns the window (MS docs, Remarks: it cannot associate a hot key with a window created by another thread; not re-read in this session) — hence requests into the hotkey thread, not calls from the save thread. Both combos can be registered at once (R-3 rationale); registering a combo the process already holds fails with 1409, so prepare is skipped when the hotkey text is unchanged (spec 004 T032).

**Open points for the orchestrator / owner.**
- Q1: first run (or Reset/Unavailable) **and** a taken hotkey: `on_ready` opens Engine after the hotkey branch posted Recording (start_dictation runs before `app.run`), so Engine wins today. Default proposed: the hotkey field wins (`startup_action` takes the registration result, or the branch is posted after `Ready`).
- Q2: after a startup failure, re-saving the **same** hotkey text never retries (unchanged → registrar not called, T032). Default proposed: keep the spec rule in T-055; retry belongs to T-010's re-register path, or the user picks another hotkey.
- Notification: T-007's notifier does not exist. T-055 delivers tray `HotkeyError`, the 3 s overlay notice and the settings window on the field; the toast is added by T-007 on the same `hotkey_registration(false)` path. Acceptance's "notification" half stays open until T-007 — record it.
- Unverified: the first `hotkey_registration` and the opener request are posted before the event loop runs (windows-shell.md T-006 note); test (10) must observe the window through the real start order.

**Tools.** Serena and Context7 were not callable in this session; code was read with grep/sed at 002a49c (`src-tauri/src/{win/hotkey,dictation,settings_ipc,settings_window,lib}.rs`, core `settings/{service,gate,mod}.rs`, `hotkey_registrar.rs`, `dictation.rs`, `platform.rs`, `recording/mod.rs`, `i18n.rs`, `i18n/en.json`, `src-tauri/tests/{hotkey.rs,win32_support/mod.rs}`, spec 004 research R-3/R-4/R-6, contracts/core-traits.md, tasks T030-T041/T067, `docs/decisions/{windows-shell,settings,dictation-session}.md`, decisions #21, #23, #63, #64, #69). Nothing was built or run; Windows was not available.
