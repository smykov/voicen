## Context

Split from T-010 by owner decision #63: the release-1 part of hotkey handling. The two-phase registrar used by settings (the hotkey step of T-032's save transaction; a refused save keeps the old hotkey registered; a saved hotkey works at once, without a restart — P-013), and the startup failure branch (a hotkey already taken at start: tray error state and the settings window opened on the Recording tab with the field focused, via T-037's `open(tab, field)`). Recovery after sleep, lock and Explorer restart stays in T-010 (P3).

## Acceptance

- [ ] Windows CI: saving a new hotkey registers it and unregisters the old one; the new one fires without a restart
- [ ] Failure branch: a hotkey taken by another process → the save is refused with the hotkey field error and the old hotkey stays registered; taken at start → tray error and settings opened on Recording with the hotkey field focused — Windows CI
- [ ] Test that fails without the change: `src-tauri/tests/hotkey_registrar.rs` (Windows CI)
