## Context

Process review 2026-10-25, proposal 1 (decisions #208). In the 2026-10-24 parallel run, 11 of 11 worktrees stopped `BLOCKED` on the P-016 `wip/<ID>` push: a headless `claude -p` stage session in a worktree may not push. The permission `Bash(git push -f origin HEAD:wip/*)` exists only in the main tree's gitignored `.claude/settings.local.json`, which worktrees do not get. `CLAUDE.md` › Rules allows the CI-only push to "the orchestrator" only. Decision #202 already allows `wip/<ID>` pushes; `main` stays the owner's.

## Acceptance

- [ ] The project `.claude/settings.json` allows the CI-only push `git push -f origin HEAD:wip/*` (and its `git -C <path>` form); no rule allows a push to `main` or a tag
- [ ] `CLAUDE.md` › Rules: a worktree's own stage session may make the CI-only `wip/<ID>` push; every other push stays forbidden from a DEV session
- [ ] `docs/process/` or `AGENTS.md` text that says only the orchestrator pushes `wip/` is updated in the same commit (or the record says none exists)
- [ ] Evidence: one headless worktree session pushed its `wip/<ID>` without an owner step (the session log cited)
