2. *`$INSTDIR` is not the data folder.* Refuted: `installMode: currentUser` plus `installer.nsi:492` gives `$INSTDIR = $LOCALAPPDATA\Voicen`, which equals `paths::data_dir`. So the program, `uninstall.exe` and user data share one folder, and `calls\` sits under `$INSTDIR`. Any recursive `$INSTDIR` delete would break FR-041.
3. *A second deletion path.* Searched `installer.nsi` and `installer-hooks.nsh` for `RMDir`, `Delete` and `ExecWait`. Everything else deletes named files only (`:764-793`, shortcuts `:810-825`). 4. *This class was fixed before.* `docs/failures.md` has no installer or uninstall entry. The installer invariant came from the T-025 analysis, not from an F-entry (`docs/decisions/installer.md`). No recurrence.
5. *The existing "files left" check breaks on kept calls.* Confirmed by reading: `:133` `${FileExists} "$LOCALAPPDATA\Voicen\*.*"` is true whenever `calls\` is kept. An interactive keep would then show `VoicenFilesLeft`, a false error. The check must exclude `calls\`.
6. *`RMDir /r` stops at a junction.* Refuted by reading, not yet on the runner. `myDelete` in NSIS 3.11 `util.c` tests only `FILE_ATTRIBUTE_DIRECTORY` before it recurses; "REPARSE" does not occur in `util.c` or `exec.c`. A junction carries that attribute, so `RMDir /r` empties the target at any depth. This also means an attribute check on top-level entries (the earlier recommendation) is not enough for #197.
7. *`/PURGECALLS` is independent of `/P`.* Refuted by reading, not yet on the runner. `GetOptionsBody` compares only the option's length after the delimiter, and `un.onInit` runs `${GetOptions} $CMDLINE "/P"` (`installer.nsi:743`). So `/PURGECALLS` also sets `$PassiveMode = 1`. With `/S` or `/P` next to it, as in the contract table, nothing changes, so CI would not show this. A bare `uninstall.exe /PURGECALLS` runs as `/P /PURGECALLS`: no pages, no question, and `$VoicenPurgeData = 1` at `:90`, so settings, models and keys go too.
