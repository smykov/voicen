## Context

Opened by decision #39's own trigger ("if a further miss appears, open an rca"). The shell-test-layout guard (T-035, hardened in T-036) tries to refuse every doc-comment line in `src-tauri/src` that rustdoc would read as a code block. Every review round found new shapes it passed: T-035 round 1 (indented blocks, block-doc fences, `#[doc]` fences, multi-line cfg), T-035 round 2 (list continuations, literals), T-036 round 1 (seven container/paragraph shapes), and the T-036 round-1 developer (b8b0b81) found eight more while implementing #39's coarse rule — tabs in the unindent, mixed `#[doc]`/`///` unindent, outer+inner docs unindented together, raw HTML before a fence, `\x60`-escaped fences, `\r` escapes, uneven `/** */` margins, an empty middle line in `/** */` — fixed in code but pinned by no fixture (probes in `target/t036probe/`, gitignored). Each fix models a little more of rustdoc's Markdown in host-side awk.

What the doc-block scan protects: since #37, `src-tauri/Cargo.toml` has `[lib] doctest = false`, so no lib doctest executable is ever built — the ci-toolchain class (a test exe linked with a partial build-script configuration) cannot arise from a doc block. A missed doc block today is only a doc example that silently never runs. The guard's other checks (test attributes in `src/`, `#[path]`, `include`, symlinks, Cargo target `path`, benches/examples) are about executables and have not leaked in review.

T-036 is deferred into this task (`absorbed_by: T-038`); its committed code (8dc6b5f fixtures, b8b0b81 scanner) is on HEAD, unpushed. Candidate exits for the investigator to weigh: (a) code — narrow the guard to what can build an exe and pin `doctest = false` itself (refuse its removal), dropping the doc-block scan, with the doc-example convention (```text) moved to the author rule only; or (a′) keep a doc scan but make it trivially fail-closed (e.g. refuse any doc code block marker and any doc line indented 4+ columns from the raw comment text, with no unindent or Markdown modelling); (b) `/arch-review`; (c) a process/PRINCIPLES amendment (e.g. rustdoc's own parser in the core image — the guard is host-only by design, so this is an owner decision).

### 1. Frame

- **Observed:** across four consecutive steps, review or implementation found doc-comment shapes that rustdoc 1.99 reads as code blocks and the guard passed:
  - T-035 r1 #1 (a)–(c);
  - T-035 r2 #1 (a false positive, which drove the list modelling);
  - the T-036 analysis (P3/P4) and T-036 r1 #1 (a)–(g);
  - eight preparation shapes the b8b0b81 developer hit while implementing #39.
- **Expected (decision #39):** "one rule an author can follow" that stops the shape-by-shape chase.
- **Symptom vs guess:** the symptom is review rounds that keep finding passes. "The rule is still not coarse enough" is a guess. The analysis below shows the rule's input cannot be computed without the parsers it imitates.

### 2. Hypotheses

1. **The guard re-implements foreign parsers; a pass is only as good as the model's completeness.** Confirms: each miss maps to an unmodelled clause of rustc's doc desugaring, rustdoc's unindent or CommonMark. Refutes: a miss independent of the model. **Confirmed** (§3).
2. **#39's coarse rule removed the modelling.** Refutes: misses after #39 in the preparation step. **Refuted:** "4+ columns" is measured *after* rustdoc's unindent and rustc's margin and escape handling. b8b0b81 had to model `beautify_doc_string` (awk:284-317), string escapes (:241-282), CR breaks (:382), and the cross-fragment, one-less unindent (:369-381). Probes a, b, c, g, h, i and j are exactly those clauses.
3. **The scan protects an exe-producing path (the ci-toolchain class).** Partly confirmed, narrowly (§4): only through an explicit `--doc`. With `doctest = false`, default `cargo test` builds no doc exe. Bins and `tests/*.rs` never do.
4. **Second path: the same concern is handled elsewhere.** The concern is "a doc block becomes a Windows test exe". It is handled at two cargo switches, the manifest flag (#37) and the invocation (`ci.yml` windows job, reviewer-checked under invariant 2 of the area file). The doc scan is a third, redundant path, and the only leaky one.
5. **This class was fixed before.** Yes, four times (T-035 cdfa9ac, T-036 b3f3cac, b8b0b81, plus the #39 rule). Each fix widened the model; none removed the need for it (§5).

### 3. Evidence: class-level cause

The guard has to answer "would rustdoc read this as a code block?". The real pipeline is:
- rustc lexes the doc forms and desugars them, with `beautify_doc_string` on `/** */` and string escapes in `#[doc]`;
- rustdoc collects an item's fragments across files (outer docs on `mod foo;` plus `//!` in foo.rs), unindents them together (one less on raw `#[doc]`), and joins them;
- pulldown-cmark parses the result with rustdoc's options.

The guard re-implements all three in POSIX awk on the host. The pass branch is the default: a line passes unless the model recognises code. So every missing clause fails open:
- T-035 r1: block-doc and `#[doc]` forms not lexed as docs; indented blocks not modelled.
- T-036 analysis and r1: container markers followed by 5+ columns; lazy continuation granted after lines that leave no paragraph open (`>`, an empty item, `---`, setext, `***`).
- b8b0b81 (probes rerun here): a tab inside the unindent (a); a `#[doc]`/`///` mix (b); outer+inner unindent (c); an HTML block swallowing a ```text fence (f); `\x60` fences (g); an escaped CR (h); uneven block margins (i); a blank middle line in `/** */` (j). rustdoc 1.99 runs each as a doctest. The HEAD guard refuses each, and no fixture pins any of them.

The fixes worked: the HEAD guard refuses every shape found so far. But "every shape" cannot be shown, because the reference is a ~650-example spec plus rustdoc's extensions and rustc's lexer. One more review round will look for one more clause, and decision #39's own trigger fired on exactly that.

Cost of the model today: about 200 of the 430 awk lines (:19-33, :216-224, :241-430), 25 of the 68 fixture dirs, and an author rule with four clauses (```text, fences on their own line, continuations below 4 columns with per-marker widths, no raw HTML).

### 4. Evidence: what the doc-block scan protects now

cargo 1.99 source (`gh api`, branch `rust-1.99.0`):
- `src/ops/cargo_compile/unit_generator.rs:397-410` (CompileFilter::Default, the plain `cargo test`) proposes a Doctest unit only for `t.is_lib() && t.doctested() && t.doctestable()`.
- `:425-440` (`--doc` becomes CompileFilter::Only with `lib`, intent Doctest) filters `Target::is_lib` and checks only `doctestable()`. **`--doc` ignores `doctest = false`.**
- `src/workspace/manifest.rs:1018-1025`: `doctestable()` is true only for `TargetKind::Lib` with an rlib, lib or proc-macro crate type. A bin, test, bench or example target is never doctestable. `:420`: metadata `doctest` = `doctested && doctestable`.
- `src/workspace/parser/targets.rs:943`: the `doctest` key is read for every target. On a non-lib it is inert.

Probe `target/t038probe/p` in voicen-rust:1.99 (lib `staticlib, cdylib, rlib` like src-tauri, `doctest = false`; `compile_error!` doctests in `src/lib.rs` (fenced and indented), in `src/main.rs`, and in `tests/it.rs`; `[[bin]] doctest = true`, `[[test]] doctest = true`):

| Command | Result |
|---|---|
| `cargo test` | lib unittests, bin unittests, `tests/it.rs` (1 passed); **no Doc-tests section** |
| `cargo test --all-targets` | same, no doctests |
| `cargo test --doc` | `Doc-tests p_lib`, running 2 tests, both FAILED (the lib's two blocks). No bin or `tests/` doctest despite `doctest = true` |
| `cargo test --doc --lib` | `error: can't mix --doc with other target selecting options` |
| `cargo metadata --no-deps` | lib, bin and test all `doctest: false` |

Answers:
- **Bins:** cargo never builds doctests for a bin, even with `doctest = true`.
- **`tests/*.rs`:** doc comments there are inert. Those exes are configured by build.rs anyway.
- **proc-macro:** a lib kind, so the same `doctest` flag applies. src-tauri has none, and becoming one is a `[lib]` edit, which the pin sees.
- **build.rs:** not a test target.

So with `doctest = false` a doc block can become an exe **only** through a cargo invocation that passes `--doc` (or `cargo rustdoc … -- --test`) for voicen. On Windows that is only `ci.yml` (`:60-61` today: neither). Everything else the scan does is cosmetic. A ```rust example and a ```text example are equally never run; the scan only forces the label. T-035.verify/1.md:26 already shows the Windows `cargo test -p voicen` with no `Doc-tests voicen_lib`, and the empty lib and bin unit-test exes start.

One correction follows from this. Decision #37 ("a lib doctest exe cannot be built") and the area file ("cargo builds no lib doctest exe at all") hold only for invocations without `--doc`.

### 5. Root cause

See `analysis.root_cause`. It explains every round: each miss is an unmodelled clause of a foreign parser on the pass branch, including the post-#39 misses, which sit in the preparation step the coarse rule depends on. Nothing contradicts it. The other guard checks have been stable since T-035 r1: test attributes, cfg, `#[path]`, include, symlink, target path, benches and examples. They decide on Rust tokens and TOML headers whose grammar the lexer covers and the fixtures pin; they do not re-implement a Markdown pipeline. **Earlier patches and why each did not hold:**
- cdfa9ac: fence and indent scan without containers;
- b3f3cac: list note and marker+5;
- the #39 rule: coarse 4+ columns, but on modelled preparation;
- b8b0b81: preparation clauses.

Each widened the model, and the model is the defect.

### 6. Invariant and seam

See `analysis.invariant` and `analysis.seam`. The invariant is closed: it names exe kinds and the switches that create them (cargo's closed set: lib/bin unit tests, lib doctests, integration tests, benches, examples), not doc shapes.

### 7. Options

- **(a) Recommended. Narrow the guard to exe-producing shapes; pin `doctest = false` and the `--doc` route.** It removes the cause: no rule depends on rustdoc's reading of text, so there is nothing left to model. Red first: the new fixtures below (v-doctest-*, v-workflow-*, c-no-workflows-dir and v-cargo-multiline-string exit 0 or 1 wrongly today; ok-doc-text exits 1 today) and the renamed c-find-fails-cfg-test. Risk: a ```rust example in shell docs is no longer refused. That example never runs either way, so it is a doc-style matter (author rule T1). Rollback: revert the commit; the guard returns to b8b0b81.
- **(a′) Raw-text fail-closed doc rule.** It would still need fence open/close state, because an HTML block or an unclosed ```text turns a later bare ``` into an opening fence. Otherwise it must ban every fence, plus every tab, every 4+ space run, `/** */` and `#[doc]`. No need shown once (a)'s pins exist. Not recommended.
- **(b) /arch-review.** One seam, one gate script, no class across services or seams. Not indicated.
- **(c) Owner-level: rustdoc's parser in the core image.** `rustdoc --test` must expand the shell crate (`#[tauri::command]`, `tauri::generate_context!`). That needs tauri's Linux deps (webkit2gtk), which the gate never builds (decisions #5). JSON doctest extraction is unstable. Costly, and it protects only cosmetics. Not recommended.

**Recommended exit**: (a) code. The class lives in one seam, and the hazard has two structural switches, both raw-text checkable. Evidence: §3–§4.
