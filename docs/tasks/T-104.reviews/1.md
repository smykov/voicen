### cpal 0.18.2 claims, checked against the source (`.teamwright/cache/.../cpal-0.18.2`)

- **Only one function calls the input stream's error callback.** In `host/wasapi`, the callback is created in `device.rs:130`, passed to `Stream::new_input` and used only inside `run_input` (`stream.rs:364`). `grep emit_error|try_emit_error` in `host/wasapi` finds only `stream.rs`.
- **Emit sites in `run_input` and its helpers:**
  - `:621` realtime boost failure. It does not stop the loop, but it sits under `#[cfg(feature = "realtime")]`. `src-tauri/Cargo.toml` has `cpal = "0.18"` with no features, cpal's `default = []`, and `audio_thread_priority` does not appear in `Cargo.lock`. The site is compiled out, so no other non-terminal emit site is missed.
  - `:747` and `:765` (command error, wait failure) return `Break`.
  - `:754` (`pending_device_changed`) and `:775` (`handle_idx >= 2`) fire only when a `DefaultDeviceMonitor` exists. `device.rs:549-553` makes it `None` for `DeviceHandle::Specific`.
  - `:650` (`process_input` returned Err) breaks.
  - `:825` `try_emit_error(Xrun)` on `AUDCLNT_BUFFERFLAGS_DATA_DISCONTINUITY` (when `device_position != 0`) continues capturing. The root cause is confirmed.
- **Opening by id gives a `Specific` device.** `open` uses `host.device_by_id`, which is the trait default (`traits.rs:67`) and iterates `devices()`. Enumerated WASAPI devices are `DeviceHandle::Specific` (`device.rs:520`).
- **None of the three kinds treated as non-terminal can end a `Specific` stream.** WASAPI never emits `RealtimeDenied` or `DeviceChanged`: `default_device_change_error` (`stream.rs:730-735`) reports `DeviceNotAvailable` or `StreamInvalidated` instead. `Xrun` is emitted only at `:825`. The HRESULT map (`wasapi/mod.rs:60-82`) never produces any of the three, so a terminal `process_input` or command error is never classified as non-terminal. A real unplug still ends the stream with `DeviceNotAvailable` or `StreamInvalidated` and is reported.
- **`try_emit_error`** (`host/error_emit.rs:25`) can drop an Xrun when the lock is contended. This is harmless now that an Xrun is ignored.
