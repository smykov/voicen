## Investigation

Investigator, 2026-10-24. Tools: Serena not used (no `call::transcript` code exists to index); grep over `crates/`, `src-tauri/src`, `specs/007-call-mode-record/`, `docs/`; `scripts/tw-req FR-63`, `FR-64`. No library API is involved (serde derive attributes already used in core; no new dependency), so no docs lookup.

**Frame.** Feature. Missing: the schema-1 types, `validate()`, `merge()` and `render_markdown()` in `call::transcript`. Nothing writes or reads `transcript.*` today.

**Hypotheses checked.**
- *Already exists on a second path*: refuted. No `transcript`, `Segment`, `LangCode`, `EngineRef`, `Track`, `Speaker`, `CallId` symbol in `crates/` or `src-tauri/src` (grep, 0 hits). `call/mod.rs` has only the codec error types.
- *Earlier class*: refuted. `docs/failures.md` (F-001…F-022) has no schema, merge or rendering class. Diagnostics invariant (no transcript text in logs) applies: `validate()` returns `(rule, index)` only.
- *Schema can be checked by typed serde alone* (option B): refuted for the acceptance as written. With `Track`/`Source` enums, `unknown_track` and `bad_source` can only fail at parse time, without an R17 rule name, so the "validate refuses each rule" acceptance and the `transcript_invalid rule=` log line cannot be met. Hence option A (wire strings + validate).

**Gaps and decisions the developer must not guess (orchestrator, please route):**
1. **Type ownership across parallel tasks.** T-123 needs `Track` and `CallId` (G04, T-118, ANALYSIS in parallel), `LangCode` (G22, T-136; also G06, T-120), and `EngineRef` and `Speaker`, which no group in tasks.md names as owner (also used by `meta.json` in G11, T-125). `depends_on` lists only T-116. Proposal: add `T-118` to `depends_on` (Track, and `TranscriptRule` if T-118's `TranscriptInvalid` log variant needs the rule enum — the enum should be defined once, in `call::transcript` or `call/mod.rs`, and used by both). Give T-123 ownership of `EngineRef` and `Speaker`/`SpeakerId` (plan.md: the speakers table lives in `transcript` until 1c) so that T-125 reuses them. For `LangCode`, either T-123 waits for T-136 or one task defines a minimal `LangCode` (ISO 639-1 over `settings::WHISPER_ISO_639_1`) that T-136 and T-120 extend. Whether LangCode's set is exactly those 97 codes is not stated (R10 says only that a table maps names and ISO codes to it) — confirm in T-136's analysis.
2. **`duration_ms` vs the longer track.** `duration_ms` is the shorter readable track (data-model "Call"; recovery R7), but merge clamps only to the chunk. A line from the tail of the longer track (crash recovery, or a `start_offset_ms` > 0 track) would break `0 ≤ start ≤ end ≤ duration_ms`, fail validation and turn a good pass into `failed: storage`. The approach clamps to `duration_ms` as well, which keeps the text. This goes beyond what the spec text says. If the owner prefers dropping such lines or decoding only up to `duration_ms` (G24), it is a spec decision, not the developer's.
3. **Engine time units and rounding.** R10 gives seconds (`start_s`, `end_s`, floats). The approach rounds to the nearest ms and treats non-finite or negative values as the chunk start. These are the developer's choices within "clamped to the chunk", and they are pinned by tests.
4. **Text with line breaks in Markdown.** The contract's one-line `**[..] name:** text` format does not say what to do with a `\n` in the engine text or the title. Recommend the renderer folds whitespace runs to one space in the line text (the JSON keeps the original). If the owner wants something else, add it to `docs/open-questions.md`. This is minor and does not block the red tests for the other items.
5. **Tie order.** "Ordered by start time" does not settle equal starts. The approach uses a stable sort by (start_ms, mic before system, input order), and validate accepts non-decreasing `start_ms`.

**Size.** One seam, one file, pure functions. The work is small, apart from the type-ownership coordination in gap 1, which is a scheduling question, not a second seam.
