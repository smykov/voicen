### Test correction (second spawn)
`call_session::a_write_failure_stops_the_call_keeps_flushed_audio_and_leaves_meta_recording` asserted `duration_48k >= 48_000` for both tracks after a 2 s feed. Measured in a copy with the implementation (scan right before `fail_next_write("mic.opus")` and after the stop): mic.opus and system.opus both 47 688 (one 1 s Ogg page = 48 000 granule minus pre-skip 312, end Truncated, 2294 / 2302 bytes) before the fault and the same after. ## Investigation

**Frame.** Expected: spec 007 FR-016, FR-017, FR-018, FR-020, FR-032; SC-005, SC-006; data-model "CallState transitions" (a `recording` folder with no owning session becomes `recovered`; `transcribing` at start becomes `ready-to-transcribe`); research R7 (recovery only reads, never rewrites audio) and R19 (DiskSpace polled every 10 s; the 4 h limit on the session's clock). Observed on main 76c49467: none of this exists. The gaps are listed in `analysis.root_cause`.

**Hypotheses checked.**
- H1, recovery already exists somewhere: refuted. There is no recover function in `call/storage.rs` (Serena overview). grep for `recover` over `crates/` and `src-tauri/src` finds only `ListState::Recovered`, the wire mapping and the log event. The contract says "Not built yet: recovery …".
- H2, a second path handles write failures: confirmed. `Writer::apply` handles it per track. `CallSession::finish` logs encoder `finish` errors and still writes `ready-to-transcribe`. Both paths change.
- H3, the disk port must be new: refuted. `local_models::download::DiskSpace` + `FakeDisk` serve the call side (call-storage.md "Reused, not copied"; the shell's `WinDiskSpace`, T-127 note).
- H4, the class was fixed before: none. Class `call-storage` has no F-entry.
- H5, the write fault can be injected with today's opener: refuted. `TrackOpener` returns `File`, and T-126 mutants 36/37 survived because of it (call-session.md). The opener must return a boxed `SyncWrite` (the storage tests already use `FaultSink` through the generic `create_with`).

**Why `tick` is the one place for the extra stops.** The writer thread cannot stop the call itself: `Captures::close` joins the writer, so the writer would join itself. The shell's timer already drives `tick` at `next_deadline` (reminder). Adding the 10 s poll to `next_deadline` gives one deadline-driven place for the storage failure, low disk and 4 h stops. The audio is already safe at the failure, because the writer drops both encoders at once. The only cost is up to 10 s before the indicator turns off. Option C in `approach` removes that delay.

**Ownership.** `CallStore` keeps the active call's folder (set at `create_with`, cleared at `finish`). This one fact answers three questions: what recovery must skip (a primary started with `--call record` may record before recovery runs), what the list shows as Recording, and what a write-failed call shows during the same run. The last is US4 #5: when the drive returns, the call is listed as recovered.
