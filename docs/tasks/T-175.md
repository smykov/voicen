## Investigation

Tools: Serena `get_symbols_overview` on `src-tauri/tests/dictation_e2e.rs` answered. The rest of `src-tauri/tests` (Windows-only, `#![cfg(windows)]`) was read with grep and sed, because the Linux index may not cover it. The I1 guard was run read-only on the shell tree: `scripts/ci/core-test-os-answer.sh src-tauri/tests`. No build or gate was run.

**1. Frame.** This is a chore, not a defect report. Six review lines from T-060 P7 (decision #201) fall on one seam, the shell test harness. One of them, the T-080 merge, is a latent instance of class `os-answer-deadline-race`, with no CI sighting. One is the F-018 audit (class `test-event-subscribed-after-trigger`).

**2. Hypotheses.**
- (H1) dictation_e2e's refused case is a stale copy of a core seam that has since moved. Confirmed. `REFUSAL_BUDGET` = 5 s comes from decision #56 (T-048). T-080 replaced it in core with `OS_ANSWER_BUDGET` = 60 s and a probe bound to the case's deadlines. The shell copy (`timing_support::refused_loopback`, moved there by T-201) still asserts `took < 2.5 s`, while windows-latest measured ~2.17 s (F-005). That leaves a 0.33 s margin, the F-005 shape.
- (H2) Second path: the same concern lives in another shell file. Checked. `settings_ipc.rs` already uses `OsAnswer::refused()`. No other `src-tauri/tests` file names an OS-answer target (the guard's run lists only dictation_e2e.rs, a settings_ipc.rs comment and timing_support).
- (H3) This class was fixed before. Yes: T-047 (#53), T-048 (#56), T-080 (I1/I2) and T-089 (the tripwire successor). T-201 closed I2 for the shell. Each fix stopped at the core tree. The guard's own header says shell tests are Not caught, and T-074 then wrote the old shape again. This is why option B adds the shell tree to the T3 check, rather than relying on review.
- (H4) A `listen_any` user subscribes after its trigger (F-018). Refuted for every user (§3).
- (H5) T-111 changed `common::os_answer` in a way that blocks the migration. Refuted. T-111 is DONE and added `in_time()` and `Unanswered` totals; `OsAnswer::refused()` and its `timeouts` are unchanged. `common/mod.rs` already builds inside a shell crate (settings_ipc.rs). The case's deadlines fit the settings bounds of decision #99: connect 60 s ≤ max 60, post-processing 120 s ≤ max 300.

**3. listen_any audit (F-018, T-096 r1#1).** Mechanism checked in the product: `settings_window::open` emits `settings://focus` synchronously on the opener thread, and the opener sends the receipt only after `open` returns (`src-tauri/src/settings_window.rs` opener loop, `done.send(result)`). The overlay thread emits `overlay://state` before `settle()` publishes the receipt (`src-tauri/src/overlay.rs`, "after the window call returned"). So for these two events, a waited receipt orders every earlier emit before it. The F-018 race came from the separate change-bridge thread for `settings://changed`.
- `overlay_ipc.rs::emitted` (one caller, `overlay_ready_returns_the_newest_published_state_as_the_last_emit_carries_it`): subscribed before the first `set_overlay`. Safe.
- `settings_window.rs::focus_events` (4 callers) and `focus_threads`: each subscribes right after the app is built, before the first `open` / `request`. Safe.
- `single_instance.rs::a_second_launch_while_open_fronts_the_one_window_on_its_tab`: subscribes after the first trigger. Safe: the first launch builds the window (a build emits no focus), its receipt is waited (`ran(..)`), and any emit is synchronous before that receipt. The assertion is negative ("no focus"), so a late event could only turn it red, never hide a defect.
- `hotkey_registrar.rs::a_taken_hotkey_at_startup_...`: subscribed before `start(rig)`. Safe.
- `tray.rs::the_settings_item_opens_one_window_and_then_fronts_it`: subscribed before the first `on_menu_event`. Safe.
- `settings_ipc.rs::changed_events` (4 callers) and `local_models.rs::changed_events`: settled by T-096. `local_models.rs::record` (7 callers, `listen`, not `listen_any`) subscribes before every download. Safe.

Result: no fix needed. The developer records this table in `## Tests` and in the `test-event-subscribed-after-trigger` row of docs/failures.md ("audited at T-175: no subscriber after its trigger"). The tier stays T1, and the class count stays 1 (no recurrence).

**4. Root cause.** See `analysis.root_cause`. It explains the T-080 line (the copy and its 5 s budget), the tripwire-scope line (the guard scans core only), and the trigger of option B (T-074 after T-080). The other lines are independent drift and are listed as such. Contradicting evidence: none. There has been no CI failure of the dictation_e2e refused test, so the 0.33 s margin is a matching shape, not a proven flake.

**5. Options for the tripwire scope** (the Acceptance's "decide whether the tripwire covers the shell tests"): B (recommended) extends the I1 token run to `src-tauri/tests`. A records it as a T1 residual. See `analysis.approach`. B is a guard change: a staged path under `scripts/ci/`, so it needs `checker: true` and `decides_on` (pre-commit). This record has `checker: false`. **The orchestrator sets `checker: true` before IN_PROGRESS if B is taken.** This is an agent decision with precedent (T-089), not an owner one. If the orchestrator wants it confirmed, it is a one-line owner question: B, or A as a residual.

**6. Size.** Not large: one seam (shell test files plus the I1 guard's self-test), no product code, no spec. Blocker: none. `blocked_on` stays empty.
