### 2. Hypotheses

1. *A stop that throws skips the restore* (T-006 r4#4). Confirmed, at four sites. The second-path hypothesis holds: the T-062 webview step and the T-102 vad failure-branch step have the same `Stop-AllVoicen` then restore order, and the T-062 comment makes the same claim.
2. *The tray pipe works by accident* (T-024 r4#4). Confirmed. It is the only pipe site, and the other steps were already fixed (T-024's comment, `crash-records.ps1` header). This was fixed before only by convention, with no F-entry and no check.
3. *W2 cannot tell whether the uninstaller ran* (T-025 r1#2). Confirmed from `installer.nsi`: `reinst_done` (taken under the installer's own `/UPDATE`) keeps everything W2 asserts.
4. *The overlay is seen but not asserted* (T-055 r2#1). Confirmed: the step's filter excludes the overlay and nothing counts it.
5. *Comment drift* (T-058 Notes). Confirmed at two places (ci.yml probe comment, `Report::out` doc). The `:7` module doc and the `#[ignore]` reason are accurate.

Class check: `docs/failures.md` has no class for any of these, and `recurrence_of` stays empty.

### 3. Evidence

See `analysis.evidence`. Facts that decide the approach:

- `Stop-AllVoicen` throws "premise: ..." in two places. Every caller's `finally` restores after it.
- `PageLeaveReinstall`: `$UpdateMode = 1` goes to `reinst_done` with no uninstaller. A passive same-version reinstall goes to `reinst_uninstall`, which runs `ExecWait '<UninstallString> /UPDATE /P _?=<dir>'`. `Section Uninstall` always deletes `HKCU ...\Uninstall\Voicen`, and `NSIS_HOOK_POSTUNINSTALL` always deletes the toast CLSID key. The install only writes values into both keys. So a planted extra value under the uninstall key proves that the old uninstaller reached its end. A `/P /UPDATE` reinstall gives the matching negative on the same runner. An `/UPDATE` install does not create shortcuts, skips WebView2 and does not launch the app without `/R`, so it leaves nothing that the following W2 `/P` run and W3-W6 depend on.
- The overlay notice lasts 3 s (core test `notice_shows_message_for_3s_and_leaves_the_tray`). The step polls once per second, and only after the start line. Latch the overlay and poll faster from `Start-Process`.

### 4. Root cause, invariant, seam

See the analysis block. In short: these are four separate local gaps plus comment drift. The invariant that matters is I1: stop-then-restore lives in one helper, its restore always runs, and the error propagates. The other three are assertions to add (I3, I4) or a convention (I2).

### 5. Approach

See `analysis.approach`. Option B is recommended. How the red and green runs are observed: every behaviour here runs only in the Windows job, so each red and green is a `ci.yml` run on `wip/T-183` (P-016). A failing step stops the job. So either make the W2 red its own commit or put it first, or mark the injected failure-branch step `continue-on-error` only in the throwaway red commit. Record each red run id under `## Tests`.
