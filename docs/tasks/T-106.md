## Context

OQ-36, owner decision #147 (option a). T-098 shipped with the built-in engine's timeout (`timeouts.builtin`, 120 s, #133) mapped to `failure.timeout`, whose text is "The server did not answer in time" / "Сервер не ответил вовремя" — wrong for a local engine. The change is texts plus one mapping (`crates/voicen-core/src/failure.rs`, `crates/voicen-core/src/i18n.rs`, `i18n/en.json`, `i18n/ru.json`, `specs/001-dictation-via-api/contracts/messages.md`). `failure.no_local_model` and `failure.local_engine` are approved as written.

- [ ] Failure branch: an API or local-server engine timeout still shows `failure.timeout` ("The server did not answer in time" / "Сервер не ответил вовремя")
- [ ] en/ru parity holds and `messages.md` lists the new id

## Investigation

How I looked: Serena tools were not exposed to this subagent, so grep and file reads over `crates/voicen-core/src`, `crates/voicen-core/tests`, `crates/voicen-whisper/src`, `src-tauri/src`, `src-tauri/tests`, `src/`, `e2e/`, `i18n/`, `specs/001-*`, `specs/002-*`, `docs/decisions/`, `docs/failures.md`. No external library API is involved (context7 not needed).

**Frame.** Observed: a built-in (whisper.cpp) transcription that runs past `timeouts.builtin` shows "The server did not answer in time" / "Сервер не ответил вовремя". Expected (decision #147): `failure.local_timeout` "Transcription took too long" / "Распознавание заняло слишком много времени"; log reason stays `Timeout`; API and local-server timeouts keep `failure.timeout`. This is a deliberate product change on top of T-098, which shipped with OQ-36 option (c) on purpose (T-098 Notes), not a regression.

**Hypotheses.**
1. The one mapping `FailureReason::message_id` cannot see the origin, because both producers build the same bare `Timeout`. Confirmed: `local_models::residency::ModelGuard::transcribe_within` returns `Err(FailureReason::Timeout)` when the abort hook fired; `failure::classify` returns the same value for `Send{timeout:true}` / `BodyRead{timeout:true}`; `message_id` maps `Timeout => i18n::FAILURE_TIMEOUT`.
2. A second path maps failures to text (UI or shell). Refuted for transcription failures: every overlay message of a failed job comes from `reason.message_id()` / `message_params()` (`recording::RecordingController::job_finished` for `JobEnd::Failed`, `RecordingController::fail`). Core renders overlay text itself (Rust `i18n::text`, contracts/ipc.md), so the overlay page does no id mapping. `src/lib/settings/connectionTest.ts` maps `ConnectionTestResult.kind` to `failure.timeout`, but only for the connection test of the API / local-server engines (`connection_test::result` maps `FailureReason::Timeout => ConnectionTestResult::Timeout`); the built-in engine has no connection test. `src-tauri` has no `FailureReason` match. The UI types `MessageId = keyof typeof en`, and the en/ru parity tests (core `i18n::tests::catalog_parity_*`, `message_ids_exist_in_both_catalogs`, UI catalog tests) pick up a new key on their own; no UI code change is needed.
3. The engine kind could be taken at render time. It is not available there: `JobEnd::Failed(FailureReason)` has no engine; the kind travels only on `DictationEvent::JobFinished.engine` to the log observer. Routing it to the controller would split the mapping (P-010).
4. This class was fixed before. Refuted: `docs/failures.md` has no entry or class for failure texts or message ids (class `failure-texts` appears only in this task); `git log` on `failure.rs` / `residency.rs` shows T-098 introducing the built-in `Timeout`, with no later patch.

**Log side (must not change).** `diag::observer` turns `JobFinished.failure` (`FailureReason::code()`) into `FailureTag::from_code`, and `diag::format` writes `failure=timeout`; the same line already carries `engine=builtin`. So as long as `code()` stays `"Timeout"` for both origins, the log reason is unchanged, and spec 002 FR-019a ("the reason stays `Timeout`") holds.

**Root cause.** `FailureReason::Timeout` carries no origin, so `FailureReason::message_id`, the only failure-to-text mapping, cannot give the built-in abort its own message.

**Invariant.** A `FailureReason` carries everything its message needs. `message_id` / `message_params` stay the only failure-to-text mapping. A `Timeout` built by the built-in engine renders `failure.local_timeout`, and every `Timeout` built by `failure::classify` renders `failure.timeout`. `code()` is `"Timeout"` for both.

**Seam.** `failure::FailureReason` (variant shape plus `message_id`). Producers: `ModelGuard::transcribe_within` (built-in) and `failure::classify` (HTTP: API transcription, local server, post-processing chat, connection test). Exhaustive matches that must keep their result for both origins: `post_process` (reason -> `SkipReason::Timeout`; it only sees the HTTP origin), `connection_test::result` (`ConnectionTestResult::Timeout`; HTTP origin only), `FailureReason::message_params` / `retryable` (no params, retryable). Catalog: `i18n.rs` `messages!` (new `FAILURE_LOCAL_TIMEOUT = "failure.local_timeout"` next to `FAILURE_LOCAL_ENGINE`), `i18n/en.json`, `i18n/ru.json`. Contract docs: `specs/001-dictation-via-api/contracts/messages.md` (table row plus the "Since T-098" sentence) and `specs/001-dictation-via-api/data-model.md` FailureReason table (the `Timeout` row already describes the built-in case; it gains the message split). The `#[error]` Display text of `Timeout` ("the server did not answer in time") should follow the origin too, or be neutral. It reaches no user or log, only test redaction checks.

**Approach.**
- **A (recommended): the origin goes into the reason.** `Timeout { source: TimeoutSource }` with a closed `TimeoutSource { Server, Builtin }`. `classify` builds `Server`, `transcribe_within` builds `Builtin`, `message_id` picks the id, `code()` stays `"Timeout"`. Why it removes the cause: the one mapping now has the fact it needs, and every renderer (overlay now, T-007's toast later) gets it for free. Risk: mechanical churn. About 45 `FailureReason::Timeout` sites (most in tests: `recording/mod.rs` 9, `failure.rs` 11, tests/*.rs ~17) become `Timeout { source: .. }` or a helper constructor. The exhaustive matches make the compiler list every site. Rollback: revert one commit; nothing persisted carries the variant (pending recordings store audio, events and the log carry the code string).
- **B: a separate variant `LocalTimeout`.** It needs either code `"LocalTimeout"`, which changes `JobFinished.failure` and needs a `FailureTag` remap to keep `failure=timeout`, so two codes for one log reason, or a shared code `"Timeout"`, which breaks the `codes_are_distinct` invariant (codes tell reasons apart). Works, but bends one of the two code rules. Not recommended.
- **C: engine-aware rendering.** `JobEnd::Failed` carries the engine kind, and `RecordingController` picks the id. This splits the failure-to-text mapping into two places (P-010), and every future renderer must repeat it. Rejected.

**Red tests (A), in this order.** (1) `tests/local_engine.rs`: the built-in abort job (the existing 10x-limit rig) gives a reason whose `i18n::text(En, message_id)` is "Transcription took too long" and Ru "Распознавание заняло слишком много времени", with `code() == "Timeout"`. This compiles and fails on today's code. (2) Failure branch: an API timeout (`openai_client`) and a local-server timeout (`local_server`) still render "The server did not answer in time" / "Сервер не ответил вовремя". (3) `failure.rs` `message_ids_per_reason` / `every_reason`: one row per origin, so `failure.local_timeout` must be declared in `messages!` and in both catalogs. (4) A diag test: a built-in timeout `JobFinished` still writes `engine=builtin outcome=failed failure=timeout`. The existing asserts `Err(FailureReason::Timeout)` in `tests/local_engine.rs` (two tests) become the `Builtin` form.

**Size.** Small: one seam (`FailureReason`), one new catalog id. No UI, shell or IPC change. Spec Kit is not needed.

**Recurrence.** None. No `docs/failures.md` entry or class covers failure texts; T-098 shipped the old text on purpose (OQ-36 option c).
