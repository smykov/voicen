### 3. Hypotheses

1. **No shell switch exists (confirmed).**
   - `src-tauri/clippy.toml` is absent, and so is a root `clippy.toml`.
   - `src-tauri/Cargo.toml` has no `[lints]`.
   - `check-shell-windows` is `cargo check` only.
   - ci.yml has no clippy (grep).
2. **A second path holds the concern.** The file-local wait helpers (§2) are that second path. A ban that exempts them would not have caught T-200, because the `Instant::now` it would hit is inside `lifecycle.rs::poll`. So the helper's signature, not only the ban, must close the shape: no duration argument on a positive wait.
3. **The class was fixed before.**
   - T-080 / T-089 / T-110 drew I2 for core, and its row lists the shell as `Not checked`.
   - T-097 (F-019) and T-173 patched sites one by one.
   - Each held only for its own site, which is the recurrence.
4. **Lint debt blocks a shell clippy run (refuted for this scope).**
   - Only `disallowed_methods` needs to fail. `[lints.clippy] disallowed_methods = "deny"` does that without `-D warnings`.
   - The known lib lints (T-173 review: type_complexity, let_underscore_future) and any test-file lints stay warnings for T-166.
   - voicen-core and voicen-whisper passed the cross run with `-D warnings` in T-173 review.
   - Residual risk: voicen-core's `cfg(windows)` code is now linted with core's deny ban for the first time. It passed in that review run.
5. **The shell lib's clock reads (16 sites in 5 files) would also be denied (confirmed).** The lint table is per package. Exempt the lib with one owned `#![allow(clippy::disallowed_methods)]` in `lib.rs` (after the line-1 cfg pin). The integration-test crates are separate crates, so they stay denied.

### 4. Where the clippy run fits

- **Gate (recommended, owner confirms; see `blocked_on`).**
  - The core image already has clippy and `x86_64-pc-windows-gnu`. T-074, T-097 and T-173 ran cross clippy on shell tests.
  - `cargo clippy --tests` replaces the existing `cargo check --tests`. clippy-driver wraps only workspace members, so dependency metadata is reused and the cost is about the same.
  - Tests have no `target_env` cfg (only `build.rs` reads it), so gnu and msvc lint the same test code.
  - The Makefile line becomes an owned `clippy-lines.txt` entry. Dropping `--tests` or appending `-A` is then refused by `check-clippy-lines`.
- **Windows job (option B in `blocked_on`).**
  - A run-only step names no action and no secret, so `action-lines.txt`, the cache fragments and `release-guard` R1-R9 accept it.
  - It costs a full msvc metadata check of tauri/wry/windows.
  - It sits outside `clippy-lines.sh`'s scanned files (ci.yml is not scanned).
- **`-D warnings` scope:** only `disallowed_methods`, through the lint table. T-166 owns all-lints.
- **Failure branch:** permanent shell probes in `ban-canary.sh`, plus the one-off planted commit on `wip/T-201`. The gate job goes red at `make check` naming `src-tauri/tests/<file>:<line>`, and the revert goes green. In-gate placement means the gate job, not the Windows job, carries the evidence.
