## Context

T-162's investigation found that `scripts/hooks/test-guard.sh` strips `nice`, `timeout`, `env` and similar prefixes but not `systemd-run` and its options. Heavy runs prefixed with `systemd-run --scope -q --slice=agent-tests.slice --` (the host-load rule) therefore bypass the test guard and the tw-gate cache. The hook is kit-owned, so the change also goes upstream as kit feedback. It is a word-model guard: `checker: true`, and `analysis.decides_on` must name the token on the stripped prefix list.

- [ ] T-114 r1#2 Low maintainability: a parallel worktree is created without `pnpm install`, so `make check` stops at `check-nsis-fork` "cannot run"; worktree preparation installs dependencies, or the gap goes into the upstream kit note (worktree setup)
- [ ] `systemd-run --scope -q --slice=agent-tests.slice -- <runner>` is judged like `<runner>` alone: a cached gate or test run goes through tw-gate / tw-test as without the prefix
- [ ] `analysis.decides_on` names the `systemd-run` token and the options it strips
- [ ] Failure branch: a direct test runner behind the prefix (e.g. `systemd-run --scope -q --slice=agent-tests.slice -- cargo test`) is still refused

## Investigation

**Frame.** Observed: any Bash command that starts with `systemd-run` passes the test guard, whatever runs behind it. Expected: the prefixed form is judged like the command it runs. Reproduced on this runner by feeding `scripts/hooks/test-guard.sh` JSON payloads in a sandbox (`CLAUDE_PROJECT_DIR` = repo for the config, `TEAMWRIGHT_LOG_DIR=/tmp/t189probe/logs`, so the repo's `.teamwright/logs` were not touched, `TW_TEST_GUARD=block`), at 2cffa410.

**Evidence (probe results).**

| Command | Today |
|---|---|
| `cargo test` / `make check` / `pnpm test` | DENY (`scripts/tw-test core` / `scripts/tw-gate --top` / `scripts/tw-test ui`) |
| `systemd-run --scope -q --slice=agent-tests.slice -- cargo test` | **ALLOW** |
| same prefix `-- make check`, `-- make -k check`, `-- pnpm test` | **ALLOW** |
| same prefix `-- scripts/tw-run core -- cargo test -p voicen-core` (DENY without the prefix) | **ALLOW** |
| same prefix `-- scripts/tw-test core foo 2>&1 \| tail -5` (cut, DENY without the prefix) | **ALLOW** |
| `systemd-run --user --scope cargo test`; `--scope --slice agent-tests.slice -- cargo test`; `--scope -p CPUQuota=50% -- cargo test` | **ALLOW** |
| `nice -n 19 make check`, `timeout 60 cargo test`, `env FOO=1 cargo test` | DENY |
| `timeout -s KILL 60 cargo test`, `env -u FOO cargo test`, `sudo -u bob cargo test`, `stdbuf -o L cargo test` | **ALLOW** (same family, below) |

So Acceptance 3 ("still refused") is not true today: it is a red test, not a regression check.

Mechanism, by symbol in `scripts/hooks/test-guard.sh`: `PREFIX` (l.78-79) has no `systemd-run`, so `strip()` returns the words unchanged; `classify()` then matches nothing (not in `WRAPPERS`, not `tw-run`, not a shell `-c`, no config matcher, `builtin()` knows no `systemd-run`, no `test_runner_patterns` configured) and its suffix fallback (l.305-311) runs only for `RUNNERS` (`docker`, `podman`, `nerdctl`, `kubectl`, `ssh`) or a word with `/`. Result: `None`, allow. The prefix is in real use: reviewers and validators ran `systemd-run --scope -q --slice=agent-tests.slice -- make check` directly, past tw-gate's cache, in T-184 reviews 1-3 and validations 1-2, T-202 reviews 1-2, T-149 reviews 1 and 3, T-166 review 1, T-139 validation 1.

Ownership: `scripts/hooks/test-guard.sh` is byte-identical to kit 0.16.2 (sha256 `deaf5b9c…` = its entry in `.teamwright/installed.json`). No repo check pins it to the kit: no `make check` target or `scripts/ci/*` test names it (grep of `Makefile`, `scripts/ci/`). Local edits of kit-managed files already exist and diverge from the manifest (`scripts/tw-run` after T-217, the role files after #145), so a local edit is not refused by any check. The kit source is not on this runner (no `~/.claude/plugins/cache/teamwright`, no other `test-guard.sh` on the filesystem), so I could not check how a kit upgrade treats a locally changed managed file. The self-test below doubles as the tripwire: an upgrade that drops the edit turns `make check` red.

systemd-run option facts: context7 `/systemd/systemd` (main, `src/run/run.c` `parse_argv`, `src/shared/options.c`) confirms `-p/--property NAME=VALUE`, `-u/--unit UNIT`, `--slice SLICE`, `-E/--setenv`, `--service-type TYPE` take values; `--scope`, `--slice-inherit`, `-q/--quiet`, `-P/--pipe`, `-G/--collect`, `--wait`, `--no-block`, `-r/--remain-after-exit` take none; a bare `--` ends the options. Not confirmed here: `--user`, `--system`, `--description` (man page names; `systemd-run` is not installed on this runner, and the host's systemd version is unknown). The design keeps only verified names in FLAGS. A name left out costs at most an over-refusal, never a pass.

**Hypotheses.**
1. *systemd-run absent from the prefix model.* Confirmed (probe and code above).
2. *A second path handles prefixes.* Refuted for systemd-run: the only other unwrapping is the tool-runner loop in `strip()` (uv/poetry/npx/pnpm exec) and the `RUNNERS` fallback in `classify()`; neither names it. The config's `test_runner_patterns` is empty, and `.teamwright/config.yml` is state-guarded, so a regex there is an owner-only edit; it would also miss the cut rule and the tw-run path.
3. *Fixed before.* `git log -- scripts/hooks/test-guard.sh`: only kit installs (f1b1d0ce and the later upgrades); no local fix of this class. Same mechanism in another hook: **F-025** (wip-push-guard.sh allowed `setsid`, `flock`, `env -S`, … shapes it did not read; closed by T-198 with a raw token). Guard-model family: F-003, F-015, F-022. P-020 does not reach this hook (#230: kit-owned `test-guard.sh` is outside its scope), and its failure mode is a missed nudge with a human override, not a security boundary. So I recommend no rca. The design is still refusal-biased where it cannot read.
4. *The generic prefix loop has the same gap for value options.* Confirmed, outside this task's acceptance: the `strip()` loop pops only dash words, numbers and assignments after a PREFIX word, so a separate option value (`timeout -s KILL`, `env -u FOO`, `sudo -u bob`, `stdbuf -o L`) becomes the command word and the test run passes. Recommended for the kit-feedback item (same fix shape: on an unread word, judge the suffixes), not fixed here.

**Root cause.** See `analysis.root_cause`. It explains every ALLOW row. No contradicting evidence.

**Approach options.**
- **(B, recommended) Owned option tables plus a suffix-scan fallback** in `classify()` (exact `decides_on` in the front matter). The known forms (all spellings found in the task records: `--scope -q --slice=… --`, `--scope --slice=…` without `--`) are judged exactly, so `-- echo cargo test` or `-- find / -name vitest` stay allowed. An unread shape (an unknown option, `-qG`, `-pX=Y`, a missing table entry) falls to the suffix scan and never passes a test run. Red then green: the self-test cases in `analysis.approach`. Risk: the only pass risk is a value option listed as a flag, so FLAGS holds only names confirmed against the host's `systemd-run --help`. Rollback: revert the branch and the self-test.
- (A) Suffix scan only (no tables): judge every suffix `w[j:]`, j ≥ 1. No grammar read at all, but `systemd-run --scope -- find / -name pytest` and `-- echo cargo test` are refused. That is a real cost, because #201 sends host-wide `find /` scans through the slice.
- (C) Add `systemd-run` to `RUNNERS` (one word). It catches `builtin()` runners only: it misses the cut of `tw-test | tail` behind the prefix, and gives the same false positives as A. Not enough for Acceptance 2 ("judged like `<runner>` alone").

**Edge cases for the test-writer** (all in `analysis.approach`): `=` vs separate value (`--slice=x` / `--slice x`, `--property=K=V` / `-p K=V`); with and without `--`; `cargo test -- --nocapture` behind the prefix with no leading `--` (the first non-dash word is the command, so the inner `--` is never taken as systemd-run's); an unknown option; nested `nice`/`sudo` and an absolute path; `bash -c`; a cut after a prefixed wrapper; `--user --scope` with no command. Known limits, to name in gates.md: `systemd-run` reached through a variable or `$(…)`, `run0`, and depth > 3 nesting (as for tw-run) are not read. The refusal's "Run instead" line drops the slice prefix (`systemd-run … -- scripts/tw-gate --top` stays allowed and keeps both the slice and the cache). The message text is unchanged and needs no change for the acceptance.
