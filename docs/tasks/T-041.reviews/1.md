#### Invariant and decisions — what holds

- **Every decision goes through `SpeechGate::decide`, and it is infallible** (`vad/mod.rs:88-111`). It cannot panic on audio. `analyse` uses `as_chunks`, `.get()`, `total_cmp` and an `i64` sum of squares. An empty level list gives `-inf`, which is clamped to -70. An all-zero frame gives `-inf`, never NaN. The `deny(unwrap_used, expect_used, indexing_slicing)` inner attribute in `vad/mod.rs` also covers `vad::energy`. There is no caller yet (T-001), and no second decision path exists.
- **Speech is true only when the detector that ran said so.** The primary's `Ok(answer)` is returned with its own name. `Err` never maps to speech, and the fallback's `detect` decides. This is pinned by `a_failing_primary_never_lets_non_speech_through` (it fails if `Err` maps to `speech: true`, or if the decider is named wrongly) and by `primary_ok_true/false_is_trusted_*` (they fail on AND/OR with the energy rule).
- **The latch.** `primary_failed` starts at `primary.is_err()` and is stored on the first runtime `Err`. `runtime_error_falls_back_for_that_recording_and_latches` asserts `calls == 1` after an `Err` with a primary that would then say `Ok(true)`. Removing the store turns it red. Workers whose primary call is already in flight when the latch is set can still finish that call. The test comment says so, and it matches R-5.
- **One warning per gate.** `!warned.swap(true, AcqRel)` is correct by reading. Sequentially, the warning sits on the first fallback decision only (`unavailable_*`, `error_after_successes_*`). The concurrent pinning is weak, see #2.
- **The gate emits nothing.** `vad/` has no `log::`, `tracing` or `print` call. `GateDecision` carries the fact for T-001's single emit path (P-011).
- **Decisions.** #12: no Silero or whisper code in core, only the port. #42: the trait is synchronous. #43: the scope matches the split, with no pipeline or event code.
- **Docs (P-014).** R-5, contracts/core-traits.md and the architecture.md row match the code: decide/GateDecision, the latch, VadError, the constants, the trade-off of the -40 cap. specs/001 tasks.md T015/T020 still name `vad/silero.rs` in core. #### Deviations

- `as_chunks::<480>()` instead of `chunks_exact`: **accepted.** The semantics are the same (full frames, remainder ignored). It is stable since Rust 1.88, so it is fine on 1.99. The typed `&[i16; 480]` removes even the possibility of indexing. The analysis text still says `chunks_exact`, and the task does not record the change (#3, Low).
- Nearest-rank 10th percentile, `ceil(0.1·n) − 1` (`energy.rs:88-97`): **accepted as a definition.** It is the standard nearest-rank method. For n < 10 it is the minimum, and for n = 0 the result is clamped to -70. R-5 now states it. No test pins it, or the percentile itself, from below (#1).
