## Verdict rationale

The change sits in the seam the analysis named (`engine::http`) and follows option A with the orchestrator's choices: no new crate, the record accepted (#113), `docs/decisions/engine-http.md`, and the tripwire.

The record is correct by reading:
- Ordering: `close` stores `dropped` before it decrements `open`. `unanswered()` reads `open` first. All SeqCst, so a reader never sees both false in between.
- Close-once: the slot's `open` flag, under the slot lock, closes each lookup exactly once, whether the answer or the drop comes first.
- Failure paths: a lookup thread that panics never closes its lookup; the future's drop closes it, so no counter leak. A failed thread spawn closes the lookup as answered and returns the error as a DNS error.
- Thread: the lookup thread is detached and logs nothing.

`send_error` takes the new `lookup_unanswered` parameter. Grep finds its only callers in `HttpClient::send` and `send_capped`, so no other path can skip it.
