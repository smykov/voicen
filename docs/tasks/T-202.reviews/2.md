Push correctness (new code, 212-238):
- **Fetches.** `git fetch "$url" "$BEFORE"` fetches by SHA a commit that GitHub has: the remote `task/<ID>` head, or the dispatched `main` commit. `git fetch "$GITHUB_WORKSPACE" "+HEAD:refs/heads/stage"` brings in the session's commits.
- **Ancestor check.** `merge-base --is-ancestor "$BEFORE" stage` refuses a HEAD that does not descend from `BEFORE`.
- **Pushes.** The `task/<ID>` push is not forced, so GitHub refuses a non-fast-forward against a moved remote, which is correct. The `wip/<ID>` push is forced and runs after implement only, as before.
- **A stage commit touching `.github/`.** GitHub refuses it, because the token has no `workflows` scope (an existing premise, already in Not caught).
- **Partial pause.** A pause between the two pushes leaves `task/<ID>` pushed and `wip/<ID>` not, and the chain stops (`PUSHED` is unset). That is acceptable.
