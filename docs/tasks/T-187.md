## Context

Seam: new shell commands `open_project_page`, `open_third_party_notices` and `open_logs_folder` (each listed in `src-tauri/build.rs` `APP_COMMANDS` and granted to the `settings` label) and the About buttons in the settings UI. Today `logs_folder::request` only logs a warning on failure. Carries T-060 line T-023 (i). How an open-logs failure reaches the UI is still the owner's call.

## Acceptance

- [ ] T-023 analysis (i): About action buttons (Project page, Third-party licenses, Open logs folder; spec 006 FR-002 / T014 remainder, FR-17, FR-33) need shell commands `open_project_page`, `open_third_party_notices`, `open_logs_folder` no task owns; settle how `open_logs_folder` reports a failure to the UI (`logs_folder::request` only logs a warning today) — new task
- [ ] Owner-confirmed: how an `open_logs_folder` failure reaches the UI (recorded in `docs/decisions.md` before implementation)
- [ ] Failure branch: when the logs folder cannot be opened, About shows the owner-confirmed failure and the log gets one typed warning line with no path or user text

## Investigation

Tools: Serena (`find_symbol` on `call.rs::calls_open_folder`); everything else by grep and file reads (catalog JSON, tauri.conf.json, decisions, specs, ci.yml are not symbols). Negative results below (no URL constant, no opener plugin, no `error.open_notices`) come from grep over `src-tauri/`, `crates/voicen-core/src`, `src/`, `i18n/`, `Cargo.toml` files. They are evidence that nothing exists, not proof.

**State today.** About exists (T-023): build line, MIT License, Close. It has no action buttons. The shell has none of the three commands. The notices file is bundled: `bundle.resources` puts it in the install root, and the Windows install smoke checks it by SHA256. The command can find it through `app.path().resource_dir()`, which `lib.rs::release_detector` already uses. The only opener is `win::shell_open::ShellOpener`, which handles directories only (verb "open" on a file runs it, so it refuses files). The notices file and the URL each need their own fixed-target adapter, or `tauri-plugin-opener` (consented in #9; T-071 replaced it for logs). There is no project-URL constant; spec 006 T001 says to fill it from the origin repository.

**Design-ref drift.** The task's "FR-17, FR-33" are spec 006's FR-017 (Open logs folder) and FR-033 (third-party notices). They are not `docs/requirements.md` FR-17 (local server) or FR-33 (call hotkey). The requirements behind this task are FR-18, NFR-12, FR-01 and FR-20.

**Owner question Q-A: is it already decided? No.**
- #201 (2026-10-24) created this task and says "how an open-logs failure reaches the UI stays owner-confirmed".
- #274 Q6 (2026-11-12) asked "where the logs-folder failure is shown" inside the T-007 split. Its options were "overlay 3 s + toast · toast only", and it gave that work to T-210. T-210 traces it to T-071 r1 #3, the tray item, and its Acceptance says only "A failed Open logs folder".
- Neither #274 nor #305 (T-210 validation) names About or the settings window. Neither of them offers an inline or IPC-error option.
- So #274 covers the tray item only, and the About path is a separate question.
- Two documents also disagree. Spec 006 `contracts/ipc.md` and tasks T012/T014 have the command return `OpenError {code:"cannot_open", reason}`, with an inline alert in About. `docs/decisions/windows-shell.md` ("Open logs folder has one path", Don't line) says the About button "goes through `logs_folder::request`", which is fire-and-forget and can only use the overlay and toast.

Options:
- **A: reuse the tray path.** `open_logs_folder` calls `logs_folder::request` and resolves `null` at once. A failure shows `error.open_logs_folder` on the overlay for 3 s and as a toast, plus one log line. About shows nothing. Pro: one path, already verified (T-210, #305), small UI change. Con: the error appears outside the window the user clicked in. The overlay may sit behind or away from the settings window. It also contradicts `contracts/ipc.md` and T012.
- **B: inline in About (recommended).** The command runs the shared open synchronously, off the main thread (`#[tauri::command(async)]`). It returns `OpenError {code:"cannot_open", reason:<logs_reason.* id>}`. About shows `role="alert"` with `error.open_logs_folder` and the reason, plus one `logs_folder_failed` line. There is no overlay and no toast. Pro: the error shows where the user acted. It matches spec 006 contracts and T012, the `calls_open_folder` → `ioFailed` precedent, and FR-033's "report" wording for notices, so all three About buttons behave the same way. Con: the windows-shell.md Don't line must be amended. The tray path's surface stays as #274 decided.
- **C: both.** Inline alert and overlay plus toast. Con: the same failure shows twice, and it is not asked for anywhere.

Recommendation: **B**, and the same rule for `open_third_party_notices` (`error.open_notices`, a new catalog id) and `open_project_page`.

These follow from B but should be confirmed in the same owner row:
- the reason id for a notices or URL failure (reuse a `logs_reason.*`-style map, or add a new `open_reason.*` set);
- whether the notices and URL failures each get a `WarningKind` line (the Acceptance asks for one only for logs);
- the opener for the file and the URL: a Win32 adapter or `tauri-plugin-opener`.

**Hypotheses checked.**
- Second path: the tray item is the existing second path for the same concern. I1 keeps one shared open function, so it does not split.
- Fixed before: there is no prior defect. T-071 and T-210 built the tray path.
- Recurrence: `docs/failures.md` has no F-entry on an opener or an About ACL. The relevant standing rules are #45 (no path or OS text in the log) and the ACL invariant in `docs/decisions/ipc-acl.md` (T-049): a new command not granted is refused on Windows only.

**Size: large.** The work spans two areas (shell and UI, plus core catalog ids). Its seams are the shared logs open, new file and URL openers, three IPC commands with ACL, and the About UI. Its behaviour is not settled (Q-A). Recommend splitting after the owner answers: a shell task (spec T014 remainder) and a UI task (T012/T013 remainder).
