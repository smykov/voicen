## Investigation

**Frame.** Observed: in the keyboard case (`e2e/about.spec.ts:198`), after the first Enter opened About and Escape closed it (`toBeHidden` and `toBeFocused` on the button passed), the second Enter left no dialog: `getByRole('dialog', { name: 'About Voicen' })` "element(s) not found" for 5 s at line 223, on the try and on retry #1, in runs 38135164500 a1 and 38288755902 a1. A closed `<dialog>` is not in the accessibility tree, so "not found" means "closed", not "rendered but hidden". Expected: Enter on the focused button reopens About. Reproduces only on CI; neither diff touched UI code.

**Context tools.** Serena and context7 are not callable in this session (no `mcp__serena__*` / `mcp__context7__*` tools offered), so I used grep and file reads. Chromium behaviour comes from a probe run in the pinned image, not from docs; Svelte behaviour comes from its source in `node_modules` (svelte 5.57.1).

**Hypotheses.**
1. *A stale `open` state in About (Esc closes the element now, the component learns it later).* Confirm: a window after Esc in which the dialog is hidden and the button is focused but `close` has not fired, plus a click in that window that does not reopen. **Confirmed** (probe below).
2. *Enter does not reach the button (focus elsewhere, key lost under load).* Refuted for the reported runs: line 220 `toBeFocused` passed just before. A lost key event is not excluded, but nothing points to it, and hypothesis 1 explains the symptom without it.
3. *IPC mock or `get_build_info` slow under load.* Refuted: the dialog shows before and independently of the answer (`result` only fills the version line); "not found" is about the dialog itself.
4. *A second path handles the same concern.* Checked every native dialog in `src/` (grep `showModal|onclose|oncancel`): only `BuiltinLocal`'s delete confirmation, which calls `preventDefault()` on `cancel` and drives its state synchronously (`keepModel`), so it has no gap. In About, the Close button, General's discard-prompt dismiss and `onDestroy` set `open` synchronously. Only the native close (Esc) goes through the queued `close` event.
5. *This class was fixed before.* `docs/failures.md` has no UI dialog or e2e timing entry. F-014 (Windows SendInput hold) and F-013 / F-005 (core clocks) are different mechanisms; F-010 (`e2e-boot-flake`) is page boot, not this. Not a recurrence; `recurrence_of` stays empty.

**Evidence.**
- CI log, run 38288755902 attempt 1 (`gh run view --attempt 1 --log-failed`): the failure text above. The run has no artifacts (the workflow uploads only the v* installer), so the `trace.zip` named in the log is gone; the same is true of 38135164500. Both runs were later green on attempt 2.
- `src/lib/about/About.svelte`: `openAbout` does `result = null; open = true; loadBuildInfo()`. Only the `$effect.pre` calls `showModal()`, and only when `open` changes. `onDialogClose` (the `onclose` handler) sets `open = false`. Svelte 5.57.1 `internal_set` returns early when `source.equals(value)`, so `open = true` while `open` is already true schedules no effect.
- Chromium semantics probe (`node` in `voicen-ui:1.63.0`, `--network none`, Chromium 153.0.8010.12, playwright-core 1.63.0 from the lockfile; a static page with one button and one `<dialog>` that copies About's state rule; the script is outside the repo):
  - over 100 rounds of Enter (open), Escape, one `page.evaluate`, Enter: in 44 the evaluate saw `dialog.open === false`, the button focused and `close` not fired. In 25 the dialog stayed closed after the second Enter. Event log of a failing round: `keydown Escape dialogOpen=true`, `keydown Enter dialogOpen=false active=b open=true`, `click open=true`, `close-event`.
  - a second probe timed `close` against `setTimeout(0)` and `requestAnimationFrame` queued in `cancel`. `close` fires at the rendering step, in the same frame as the rAF callback (cancel 220.3 ms, close 228.9, raf 228.9, timeout0 229.4), 0-4 CDP evaluate round trips after the Escape press returned. Chromium hides the dialog and restores focus synchronously (HTML dialog close steps) but delivers `close` later.
  - In the spec, only two round trips sit between Escape and Enter (`toBeHidden`, `toBeFocused`, lines 219-220). When the runner renders frames late, both can pass before the frame, and line 222's Enter lands in the gap. That is the observed failure, and it would stay failed forever (the late `close` sets `open = false` and nothing reopens), which matches "not found" for the full 5 s.
- Real spec through the entry: `pnpm e2e e2e/about.spec.ts --grep keyboard --repeat-each=40 --workers=2` → 40 passed. Through the same image entry with `TW_DOCKER_ARGS=... --cpus=0.4` (`scripts/tw-run ui -- pnpm e2e ...`) → 30 passed. The gap is too narrow to hit locally with this spec. Not measured: why the CI runner's frames are late enough. Both failing runs failed the try and the retry about 6 s apart, which fits a sustained slow period on that host but is not proven.

**Root cause.** About mirrors the native dialog's open state in `open` and updates it on Esc only through the `close` event, which Chromium queues to the next rendering step after it has already hidden the dialog and refocused the button. A button press in that gap is a no-op state write, so no `showModal()` runs, and the late event then marks About closed. This explains every symptom: line 220 passes, the dialog is "not found" for all of 5 s, there is no UI diff, and it happens only under CI timing. No evidence contradicts it. It is a product defect a user could hit (Esc then Enter within one frame on a busy machine), not only a test defect, so the test should not be weakened.

**Invariant.** The About button shows the dialog whenever the `<dialog>` element is not open, and a `close` event never closes or marks closed a showing that began after it.

**Seam.** `About.svelte`: `openAbout` (the only opening path, `docs/decisions/settings-ui.md` A) and `onDialogClose` (the only native-close path). The synchronous closers (Close button, discard-prompt dismiss, `onDestroy`) keep using `open` → `$effect.pre`.

**Approach.**
- *A (recommended).* In `openAbout`, after `open = true`, call `dialog.showModal()` when `dialog` exists and `!dialog.open`. In `onDialogClose`, return at once when `dialog.open` is true (the event belongs to a showing that has already been replaced). Why it removes the cause: the decision reads the element, not the lagging mirror, and the stale event cannot undo a reopen. Red before the fix, green after: a new e2e case that opens About, then in one `page.evaluate` calls the dialog's `close()` and the button's `click()` back to back. That is deterministic: `close` is queued to the next frame, the same path Esc takes. It expects the dialog visible, the version line shown and `get_build_info` called 2 times. Add a keyboard loop (Escape, then Enter with no assertion between, about 20 rounds, dialog visible each time; the probe failed 25 % per round). The existing case stays as is. Risk: a double `showModal()` throws `InvalidStateError` if the guard is wrong, which the red case would show. There is no double call: after a direct `showModal()` the `$effect.pre` sees `dialog.open` true and skips, and a true→true set does not run it at all. Rollback: revert the one commit.
- *B.* Handle `cancel` (`oncancel`: `preventDefault()`, `open = false`) like BuiltinLocal, so Esc goes through the synchronous state path. It removes the gap for Esc when `cancel` fires, but Chromium's close watcher skips `cancel` without history-action user activation, and then the dialog closes with only the queued `close`, so the invariant is not closed. Use it only together with A.
- *C (workaround, labelled).* In the spec, wait between Escape and Enter for a rendered frame (the file's `settle(page)`). The test goes green, but the product gap stays and the test stops covering the user's timing. Not recommended.

Docs at fix time: add the invariant to `docs/decisions/settings-ui.md` A (Don't: decide opening from a state the `close` event updates). Log an F-entry (first sighting, class candidate `native-dialog-close-lag`) in `docs/failures.md` with runs 38135164500 and 38288755902.
