## Notes

1. Low, not blocking. The wrapper exits 3 when called directly. The host entry for `make check` also exits 3 for a missing image. But when the version mismatch is found inside the container, it runs under `pnpm e2e` there, so the gate's e2e step exits 1 (pnpm ELIFECYCLE "Command failed with exit code 3"). A host `pnpm e2e` likewise exits 1. In every case the message names the image and no test runs, so the Acceptance holds ("fails the gate with a message naming the image, not as a test failure"). Only the distinct exit code 3 is lost through pnpm. E3's "exits 3 on a mismatch" is accurate for the in-image wrapper. Possible follow-up: have the host re-entry call `scripts/e2e.sh` instead of `pnpm e2e` inside tw-run, if the code should survive end to end.
2. The `.github/workflows/ci.yml` Gate change (ui image built in CI, `pnpm install` in the image, uid 1001) is proven only by the first CI run after push. The task has `deploys: false` and `surface: none`, and the developer covered uid 1001 by hand in the image. So the validator does not treat it as blocking DONE. If that first Gate run is red, it is a regression of this task.
3. A fresh worktree has no `.svelte-kit/` until `svelte-kit sync` runs (the package.json `prepare` does it on install). The validator ran it in the throwaway copy before the in-image runs. This is not a defect of the task.
