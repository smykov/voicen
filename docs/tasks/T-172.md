1. *A later task already moved the gone-rule into the reducer.* Refuted: `run` still computes it (:306-310), and `on_wake` returns only `WindowAction` (core :249-286).
2. *The same concern is handled on a second path.* There are two: the shell's copy of `gone` is exactly the r2#1 finding. The failed-`destroy()` branch (`execute`, :411-423) posts a synthetic `Destroyed` and does not re-derive `gone`, so it is unaffected. The reducer applies that synthetic `Destroyed` and would now report `window_gone`, and the handle is already `None` at that point (taken in `Destroy`), so it is harmless.
3. *A style write can be made to fail on a live window without a seam.* Not shown: T-067 review 1 #3 says it cannot be done for a window of this process. A cross-process window or the desktop window would be an untested premise on the runner, and showing either is unsafe. So a seam is needed.

Not a recurrence. r3#1 and r3#2 are F-006 (`windows-ci-external-process`) follow-ups, and F-006's rule is met. r1#2 and r1#3 are `toothless-test` review findings (untested branches), not F-024's mechanism (an error fake that fails every later call). The new tests use `timing_support` (`holds_for`, receipt) only, with no ceilings (`os-answer-deadline-race` class, F-019).

**Root cause (mechanism).** `on_wake` computes `gone` but returns only an action, so its one caller must recompute it. `reveal` and `show_click_through` take their failing inputs (the `hwnd()` result, the Win32 restyle) from tauri and Win32 directly, so no test can choose the failure.

**Seams for the untested branches (decided here).**

The window is a parameter so the test can pin "stays hidden" (a fallback `window.show()` bites). Passing only the `Result` would leave that mutation out of reach.

The fake replaces steps 1-3 together; the branch under test ("restyle failed, live window, show without activation, one line") is the same for any of the three steps.
