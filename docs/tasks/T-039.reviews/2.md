## Orchestrator's failure at settings-focus-close.spec.ts:366 (alert not found within 5 s at :374)

My judgement: a test-timing or boot stall, not a race in the page.
- **By reading:** the catch at `:204-206` sets `ipcFailed`. Only `save()` clears it (`:174`), and the test never calls `save()`. The `speechLanguages` path only sets it to true. No focus or changed handler touches it, and `settings_get` never runs because the rejection comes first. The alert block (`:224-240`) does not depend on `draft`. Nothing in the page can lose or overwrite that alert.
- **By running:** 40/40 passes with `--repeat-each=40` while all 6 cores were kept busy by spin loops, at 1.0–2.5 s each.
- **Why it can still miss:** the alert's first wait needs only hydration plus `onMount`. That is the same condition as every other test's first wait (`open()` waits for the selected tab, which comes even later, after `settings_get`). So a 5 s miss means the page had not hydrated in 5 s. That points to a stalled boot or missing assets in that run, not to this test's logic. The orchestrator can confirm from the trace in that worktree's `test-results/` (kept by `trace: retain-on-failure`). If no `plugin:event|listen` call was recorded and no `/_app/immutable` chunk loaded, the page never booted.
- **One thing to rule out:** `playwright.config.ts` uses `reuseExistingServer: !CI` with a fixed port 4173 unless `BASE_URL` is set. If that run did not export `BASE_URL` for port 4273, it reused the preview server my `make check` was running from /projects/voicen. That server's `build/` gets rewritten by licenses-bundle's `pnpm build`, which is the shared-`build/` mechanism already known to cause flaky boots. Not a finding against T-039.
