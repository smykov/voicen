**Round-1 findings, checked:**
- **#1 is closed.** `open_bounded` (`src-tauri/src/win/capture.rs:122-148`) takes the old mechanism unchanged, and `CpalSource::start` now has one line, `open_bounded(OPEN_BUDGET, move || open(sink))` (`:152`). The new tests bite:
  - (a) `an_opener_blocking_past_the_budget_...`: if the opener runs inline, or `recv()` replaces `recv_timeout`, the call blocks for OPENER_WAIT = 10 s and then returns `Ok`. That fails both the `Ok` panic and the `budget + MARGIN` = 2.3 s bound. The thread-id check also catches an inline opener. A zero budget fails the `>= budget/2` check.
  - (b) `a_value_produced_after_the_timeout_...`: if there is no thread or no timeout, the value is handed out. If a late value is kept alive, the drop count stays 0. A double drop is caught as well.
  - (c) An error from the opener comes back unchanged, and quickly. A panicking opener gives `Other(<literal>)`: not `TIMED_OUT`, no `PLANTED` text in it, and no unwind into the caller.

  What remains untested is the one-line wiring in `start` itself. It needs a device, so I accept it by reading.
- **#2 is closed.** `asked + HOLD` is a lower bound on when the hold ends, because the holder opens after `asked` and `recv_timeout(hold)` runs from its own open. So `took + TICK >= left` is sound for a correct implementation. A single attempt gives `Err`. If the runner is too slow, the test now fails a named precondition instead of passing vacuously. The 120 ms hold is inside the retry budget (10 tries with a 20 ms pause; Windows sleep granularity makes the real budget longer).
- **#3 is closed.** When `SetTimer` returns 0, `hotkey.rs:239-246` writes `Warning{HotkeyThreadFailed, os_code}`. `Error::from_thread()` is evaluated as an argument before `log.write`, so it reads the `SetTimer` error and nothing written later (windows 0.62.2; it compiles for windows-gnu). The line carries the code only, no text. `diagnostics-log.md` documents it.
- **#4 is closed as documented.** The open gap is recorded in `windows-shell.md:104`, which the finding allowed: one leaked thread per hung press, no cap, T-012 revisits it.
- **#5 is closed as documented.** `windows-shell.md:105` records it, and owner step 5 was extended (several press/release cycles, then Exit).
