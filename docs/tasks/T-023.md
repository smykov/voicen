## Context

FR-18; About opens from the settings General tab (spec 006 Q1).

## Acceptance

- [ ] About shows `<version> (<commit>)` from `get_build_info`
- [ ] Failure branch: IPC failure → the dialog shows "cannot read build info" instead of an empty line — verified by Playwright
- [ ] Test that fails without the change: `e2e/about.spec.ts`

## Investigation

Analysis 2026-10-09 (problem-investigator). Tools: Serena was not connected in this session (no `mcp__serena__*` tools), so the context comes from grep and file reads over `src/`, `src-tauri/src`, `src-tauri/tests`, `crates/voicen-core`, `e2e/`, `.github/workflows/ci.yml` and `docs/`. No library API is new here: the dialog uses only web-platform elements, Svelte 5 template syntax already used on the settings page, and `@tauri-apps/api` `invoke` through the existing `loadBuildInfo`. Context7 was therefore not needed.

### 1. Frame

- **Expected** (FR-18; spec 006 US1 scenarios 1, 3, 4; FR-002; Clarification Q1): an "About Voicen" button on the settings window's General tab opens a modal dialog. The dialog shows `Voicen <version> (<commit>)`, the same value as the start log line. If the build info cannot be read, it shows "Cannot read build info".
- **Observed:** an installed build shows its version nowhere in the UI. The only page that renders it, `/`, is opened by no window.
- **Not a symptom:** the version value itself. Decision #98 / T-077 already make CI builds carry `MAJOR.MINOR.<run_number>`, and the Windows smoke checks the start line `voicen $VOICEN_VERSION ($VOICEN_COMMIT) started`.

### 2. Hypotheses

1. **The UI has no reachable About surface** → confirmed. `src-tauri/tauri.conf.json` `app.windows` is `[]` (T-037). `settings_window::url` builds `settings?tab=…`, and `overlay::URL` is `overlay`. `loadBuildInfo` / `formatBuildInfo` have exactly one caller, `src/routes/+page.svelte` (grep over `src/`). `tabs/General.svelte` renders the language, Start with Windows and `TimeoutsFields`, nothing else.
2. **The version or commit is wrong or empty in a real build** (a second path for the same concern) → refuted for the version: `build_info()` reads `CARGO_PKG_VERSION`. Both crates use `version.workspace = true`. `version-stamp.sh` writes the workspace version before the first compile (ci.yml "Version of this build"). The smoke asserts the start line with `$VOICEN_VERSION`, and that start line reads the same `build_info()` (`src-tauri/src/diag.rs`). For the commit: `build.rs` takes the env value if it is not blank, else `git rev-parse --short=7 HEAD`, else `unknown`, so it is never empty in practice. Residual gap, not observed: spec T010/T011 asked for the selection to be a pure, testable function. Today a padded env value is used untrimmed, and an empty `git` stdout on success would give `""`. Neither happens in CI (`git rev-parse` output). No task owns T010/T011. This is out of T-023's surface (`ui`); see the follow-ups.
3. **`get_build_info` is not callable from the settings window** → refuted for now. The settings capability lists only `core:event:*` and `core:window:allow-destroy`, and app commands are not ACL-checked yet (T-049, TODO; `docs/decisions/model-download.md` "Don't"). **Risk:** when T-049 scopes app commands, it must grant `get_build_info` to the `settings` label, or About falls into its failure branch on Windows. No Linux test can see this.
4. **This class was fixed before** → no. Class `diagnostics-log` has no F-entry. The `/` page (T-005) already had a failure branch, but it shows the rejection text (`app.build_info_error` "Cannot read build info: {reason}"). The settings window's rule is never to show a rejection text (`docs/decisions/settings-ui.md` U2), and spec 006 contracts/ipc.md gives `about.build_info_error` = "Cannot read build info" with no reason.

### 3. Build-info flow today (evidence)

| Step | Where | What |
|---|---|---|
| commit | `crates/voicen-core/build.rs` | `VOICEN_COMMIT` env (CI: ci.yml "Commit of this build", `git rev-parse --short=7 HEAD`) → else git → else `unknown`; emitted as `rustc-env` |
| version | ci.yml "Version of this build" → `scripts/ci/version-stamp.sh` (#98, `docs/decisions/ci-toolchain.md`) | stamps `<MAJOR.MINOR>.<run_number>` (or the tag's `X.Y.Z`) into `Cargo.toml` workspace, `tauri.conf.json`, `package.json`, `Cargo.lock`; local builds keep `0.1.0` |
| resolver | `voicen_core::build_info::build_info` | `BuildInfo { version: CARGO_PKG_VERSION, commit: VOICEN_COMMIT }`, `Display` = `<version> (<commit>)` |
| start line | `src-tauri/src/diag.rs` `LogEvent::Started { build: build_info() }` | asserted by the Windows smoke (ci.yml) and `src-tauri/tests/diag.rs` |
| IPC | `src-tauri/src/lib.rs` `get_build_info` (registered in `commands`) | returns `BuildInfo` as `{version, commit}` |
| UI | `src/lib/buildInfo.ts` `loadBuildInfo` / `formatBuildInfo` (`app.build_info` "Voicen {version} ({commit})") | used only by `/` |
| e2e | `e2e/build-info.spec.ts` (`/` only); `tauriMock` option `buildInfo` (value or `{reject}`; absent → "unexpected command" rejection) | |

FR-001 "one source" already holds: About reuses `get_build_info`. T-023 adds no new resolver.

### 4. Root cause

The feature is missing, not broken. The value flows correctly to `get_build_info`, but no reachable page asks for it: `/` lost its window in T-037, and the General tab has no About entry.

### 5. Invariant

Every build-info text the UI shows is `formatBuildInfo` of a `get_build_info` answer obtained for that showing of About. When that call rejects, About shows `about.build_info_error` with `role="alert"` and no version text: never an empty line, a value from an earlier opening, or the rejection text.

### 6. Seam

- `src/lib/about/About.svelte` (new): the "About Voicen" button plus the modal dialog. It is mounted only in `src/lib/settings/tabs/General.svelte`. It calls `loadBuildInfo` on every opening and clears the previous result first. Pending shows nothing; there is no timeout, since spec 006 names only the rejection branch. The dialog has `aria-labelledby` the title, closes on Close and Esc, and returns focus to the button.
- `src/routes/settings/+page.svelte`: one rule, **the discard prompt wins**. When `confirmDiscard` becomes true, About is closed before the prompt shows. Reason: with a native `<dialog>.showModal()` (the contract's `<dialog>`), the top layer makes everything outside the dialog inert, including the discard `alertdialog`. `main` is also `inert` while the prompt is open, which would make About inert as well. Either way the user could not answer the prompt.
- Catalog: UI-only ids `about.button` ("About Voicen"), `about.title`, `about.close`, `about.license` ("MIT License"), `about.build_info_error` ("Cannot read build info"), EN and RU, in `i18n/en.json` and `i18n/ru.json`. They need no `messages!` declaration (`docs/decisions/i18n.md`), and the parity tests keep them complete. The version line reuses `app.build_info`.
- Other paths: `/` keeps its own page and test, `e2e/build-info.spec.ts` stays unchanged, and `app.build_info_error` stays because core's `text_renders_from_the_embedded_catalog` uses it. Retiring `/` is a separate cleanup. `docs/decisions/settings-ui.md` gets an "About" entry (the invariant above and "the discard prompt wins") in the same commit.
- Placement detail: the General tab sits inside `<fieldset disabled={saving}>`, so the About button is disabled during a save. That is acceptable: About cannot open mid-save, and an open modal makes Save unreachable. The dialog's own buttons must not end up disabled: render the `<dialog>` so that it is not a descendant of the fieldset, or accept it and pin it with a test. The first is simpler.

That is a design point for the follow-up, not for T-023.
  - Why it removes the gap: the General tab gets the one About entry, reading the one resolver.

## Tests

Red tests (test-writer, 2026-10-09). Run: `scripts/tw-run ui -- pnpm e2e --workers=2 e2e/about.spec.ts e2e/tauri-mock.spec.ts` gives 8 failed and 25 passed. Every About case fails because the About button or the `about.*` catalog ids are missing: (1)–(4) and (6) wait for `getByRole('button', { name: 'About Voicen' })`, and (5) stops at "i18n/ru.json has no text for about.button / about.build_info_error". The two new `setBuildInfo` cases in `e2e/tauri-mock.spec.ts` pass.

Guarantee → test (`e2e/about.spec.ts`):
- (1) The button exists on General only and opens the dialog with `Voicen 0.1.0 (abc1234)`, "MIT License" and Close. `get_build_info` is called 0 times before opening and once after → "the General tab's About Voicen button opens a dialog …"
- (2) Failure branch → "failure branch: get_build_info rejects -> … alert Cannot read build info, no version text and no rejection text"
- (3) No stale value in either direction → "no stale value: open (ok), close, the IPC fails, reopen …" and "no stale error: open (IPC fails), close, the IPC recovers, reopen …" (the second uses a value that differs from every earlier answer)
- (4) Keyboard: Tab, Enter, focus moves inside, Esc returns focus, Close by Enter → "keyboard: Tab reaches the button …"
- (5) RU: the button, title, Close, license and error texts come from `i18n/ru.json` and differ from EN; the version line is unchanged → "with ui_language ru …" and "failure branch in Russian …"
- (6) The discard prompt wins → "the discard prompt wins: About open with a dirty draft …" (About is hidden, the alertdialog is visible, Keep editing is focused, Enter keeps the draft, nothing is destroyed)
- Mock: `setBuildInfo(page, value | { reject })` in `e2e/support/tauriMock.ts` → `e2e/tauri-mock.spec.ts` "setBuildInfo replaces the get_build_info answer for every later call …" and "setBuildInfo answers get_build_info on a page installed without the buildInfo option"

Bite check: a throwaway worktree held a reference About (a native `<dialog>` with `showModal`, loading on each opening, plus a page event that closes it on `confirmDiscard`). All 8 About cases passed against it. Wrong implementations:
- Build info loaded once on mount, opening only shows the dialog → red: (1) (a call before opening), (3) both cases, (4) (call count).
- The rejection text shown next to the alert → red: (2), (3) no-stale-value, (5) RU failure branch.
- The previous result kept on reopen (not cleared) → red: (3) both cases.
- The discard prompt does not close About → red: (6) (About is still visible).
- `dialog.show()` instead of `showModal()` (non-modal, so Esc does nothing) → red: (4).
- Focus lands elsewhere after close (blur) → red: (4) and (6).
- Survived: the explicit `opener.focus()` removed. Chromium's native `<dialog>` restores focus to the previously focused element by itself, so the effect stays the same and the guarantee still holds. (4) pins the effect, not the call (see the blur mutant).
- Mock: `setBuildInfo` as a no-op → both mock cases red.

Not covered: what the dialog shows while `get_build_info` is pending (the analysis says "nothing"; the mock has no hold for this command, and spec 006 names only the rejection branch).
