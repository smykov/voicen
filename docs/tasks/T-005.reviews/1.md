### What was verified

- **Identical rendering (invariant 2).**
  - Rust `tokens()` treats `{` as a placeholder only when `[a-z][a-z0-9_]*}` follows, and otherwise as a stray brace that it skips by one byte. A `}` is always stray.
  - TS `template.replace(/\{([a-z][a-z0-9_]*)\}/g, fn)` takes leftmost non-overlapping matches. A placeholder cannot contain a brace, so the two scans split every template the same way (for example `{{x}}` and `{ab{cd}`).
  - The TS replacer's return value is inserted literally, and the scan is single-pass in both languages.
  - `i18n/conformance.json` has 20 cases, and both suites iterate all of them with a `>= 15` guard. The cases cover:
    - `$&`, `$'` and `$$ $` + "`" + ` $1 $<v>`;
    - re-expansion of an earlier, a later and the same placeholder;
    - a missing argument kept verbatim and an extra argument ignored;
    - the fallback order: ru empty → en, ru missing → en, en empty → id, and an unknown id → id in both languages.
  - By reading: removing the `non_empty` filter, the en fallback or the single-pass render each turns `conformance_fixture` red.
- **Placeholder grammar.** The stray-brace and placeholder-set parity checks exist only in core `Catalog::parity_problems`, and `catalog_parity_holds_for_the_real_catalogs` runs it on the real files. The UI `catalogProblems` checks only missing and empty texts, which the Acceptance requires ("core and vitest").
- **`MESSAGE_IDS`.** `messages!` generates it from the same declaration as the constants. It is currently empty. `message_ids_exist_in_both_catalogs` gets its bite from a synthetic list. `MessageId` has a private field and derives no `Serialize`, so serialization is deferred as recorded in the contract and in `docs/decisions/i18n.md`.
- **`resolve_ui_language`.** It is the only place an OS tag becomes a language. A grep for `navigator`, `Intl.`, `toLocale` and `.language` in `src/` and `e2e/` finds only the comment and the test stub. The table covers `ru_RU`, `rus`, `-ru`, `""` and `None`.
- **The UI language store** (`language.svelte.ts`) uses the documented module pattern: a module-level `$state` behind getter and setter functions. `compileModule(..., {generate: "client"})` emits `$.state` / `$.get` / `$.set`, so it is reactive in the client build. Re-rendering is not tested; see #2.
- **Unknown literal ids.** `MessageId = keyof typeof en` turns an unknown literal id into a lint error. In the scratch copy I changed `+page.svelte` to `t("app.no_such_id")` and `svelte-check` reported 1 error.
- **`+page.svelte` / `buildInfo.ts`.** The English output is unchanged: `buildInfo.test.ts` and `e2e/build-info.spec.ts` are unmodified and green. Nothing was weakened or skipped.

- English output is unchanged, and the gate is green.
