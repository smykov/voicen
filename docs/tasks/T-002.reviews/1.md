### What was verified

- **PowerShell semantics (ci.yml:52-61)**, checked by reading. The job log of run 37035261228 shows the runner uses `pwsh.EXE -command ". '{0}'"`, so the step runs as a script file (PowerShell 7).
  - `@(@('voicen.exe', $exe), @('uninstall.exe', $uninstaller), @('Voicen.lnk', $shortcut))`: the comma list makes three 2-element arrays, and `@()` over that array adds no flattening level. The well-known flattening trap needs a single inner array. So `$p` is a 2-element array on each iteration, and `$p[0]` / `$p[1]` are the name and the path. Correct.
  - `$p[1]` in argument mode is parsed as an index expression, and `"$($p[0]) … $($p[1])"` uses subexpressions. Correct.
  - The `if {…}` / newline / `else {…}` form inside the foreach block is valid in a script file. It is only an issue at the interactive prompt.
  - `$missing = @()` followed by `+=` gives an `object[]`. `if ($missing)` is false for an empty array. For one element it takes the element's truthiness, and a non-empty string is true. For two or more elements it is always true. The messages are never empty, so the throw fires exactly when something is missing. Correct.
  - `Test-Path -LiteralPath <p> -PathType Leaf`: both parameters exist and can be combined. The paths contain no wildcard characters, and `LiteralPath` handles the spaces in `Start Menu`. With the runner's `$ErrorActionPreference = 'stop'`, a missing path returns `$false` and raises no error. A `.lnk` is a leaf. NTFS is case-insensitive, so `voicen.exe` and `Voicen.exe` would both match.
  - `Start-Process -FilePath $exe -PassThru` with a string path is equivalent to the old `$exe.FullName`. The default working directory has not changed.
  - `throw ($missing -join '; ')` matches the documented `<name> not found at <path>` text.
  - context7 was not used. The PowerShell cmdlets are standard, and the asserted paths were checked against the pinned template instead.
