## Context

Follow-up 1 of decision #91 (T-020 is the core path only). `start_dictation` in `src-tauri/src/dictation.rs` constructs `Arc::new(PassThrough)`. This task installs `ChatPostProcessor` there, so an enabled post-processing step runs in the real app. OQ-14 was answered by #90, so the wip/CI path exists.

## Acceptance

- [ ] With post-processing enabled and configured, a dictation in the installed app is post-processed through the chat endpoint (Windows CI with a mock server).
- [ ] Failure branch: when the post-processing server refuses, the raw transcript is still delivered and the skip reason reaches the session (tray Error), proven on Windows CI.
- [ ] Test that fails without the change: named in `## Tests`.

## Tests

Red tests (Windows CI only, decision #5; `src-tauri/tests/dictation_e2e.rs`, through `start_dictation` and the real hotkey thread, post-processing enabled by a `SettingsService::save` that also stores the fake key):

- `post_processing_on_through_the_real_wiring_pastes_the_chat_reply` (Acceptance line 1): a loopback raw-TCP chat mock (`ChatMock`) → the reply in the window and on the clipboard, exactly one `POST /v1/chat/completions` with `Bearer <fake key>` and `{model, messages: [system prompt, user transcript]}`, overlays Recording/Processing/Hidden, no tray Error, one `outcome=delivered result=pasted` line, no transcript/reply/prompt/key in the log.
- `post_processing_server_refusing_still_pastes_the_raw_transcript_with_tray_error` (Acceptance line 2, failure branch): base URL `http://127.0.0.1:1/v1` (`refused_loopback`, decision #53 probe; connect 5 s, post-processing 10 s per decision #56) → raw transcript pasted and on the clipboard, overlays Recording, Processing, `notice.post_processing_skipped.unreachable` host=127.0.0.1:1, tray Error last, one `outcome=delivered result=pasted` line, no canary in the log.
