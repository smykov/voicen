## Investigation

Tools: Serena `get_symbols_overview` on `src-tauri/src/call.rs` and `crates/voicen-core/src/call/final_pass.rs`; grep/sed for docs, specs, task records, `session.rs` bodies and cross-crate references (Serena does not index docs; a cross-crate text search was cheaper than per-symbol reference lookups). Branch `task/T-139` at ed75cf46.

**Frame.** Observed: after a stop the call folder is `ready-to-transcribe` and stays so; the user sees "Call saved — transcribing" and nothing follows. Expected (spec FR-022, FR-030; T048/T049): the pass runs on the dictation API engine's base URL, model and key slot, then "Transcript ready" with Open → `calls://open`, or a `pass_failed` notice.

**Dependencies.**

T-007 is DONE, so the Context's "stays open until T-007 is DONE" is met. But the toast part T-007 stood for in the spec was split since: the toast is T-210 (done, no action) and a working button needs T-213 (todo). Acceptance line 3 ("Transcript ready" → Open emits `calls://open`) cannot be met through a real toast click before T-213.

**Hypotheses.**
1. *The shell simply lacks the worker* — confirmed: no `PassQueue`/`ApiPassRunner`/`run_pass` reference in `src-tauri` (grep over `*.rs`: only `crates/voicen-core/tests/final_pass_http.rs`, `tests/wer_example.rs`, `examples/wer.rs`).
2. *The shell can learn the stopped folder* — refuted: `CallSession::finish` returns only `StopReason`; `Toggled::Stopped` has no payload; `CallShell::notice` gets `CallSavedTranscribing` / `Stopped{reason}` with no dir; `CallSession` has no public accessor for the current call. Three stop paths (`toggle_record`, `stop`, `tick`) all funnel through `stop_locked` → `finish` → `notice_stopped`, so that is the core seam for the hand-off.
3. *A second path handles the concern* — partly: `CallStore::recover` → `Recovery.queue` (T-144/T-146) would queue at the next start, which T-147 wires; it is not the stop path. A shell scan with `CallStore::list` after `Toggled::Stopped` would be a second path, and would miss tick stops.
4. *The Open action exists* — refuted: `Notifier` has no action besides `retry`; `win/toast.rs` ignores `retry`; `feedback.rs` pins `notice.transcript_ready` as a toast "with no action".
5. *This class was fixed before* — no: `docs/failures.md` has no `call-final-pass` entry (0 matches); `docs/decisions/call-final-pass.md` says first sighting. Recurrence: none.

**Size: larger than one seam.** (A) the shell pass worker in `call.rs` plus the one-Silero-load change in `vad.rs` / `lib.rs`; (B) a core stop hand-off in `call/session.rs` (needed for any stop-path enqueue); (C) the toast Open action across core `platform.rs` (Notifier), the toast codec, `win/toast.rs` and T-213's activator. (A)+(B) is a medium shell-plus-core change with settled behaviour; (C) is unsettled in scope and blocked on T-213.

**Test feasibility (Windows CI only, `src-tauri/tests/call_chain.rs`).** Feasible with existing support: `call_shell_support::CallRig` + `WavSource` (WAV-driven sessions, already used by `call_capture.rs`); a loopback mock server in the hand-rolled `TcpListener` style of `dictation_e2e.rs` (src-tauri has no wiremock dev-dependency; adding one is a dependency change with `make licenses`); the Silero model from `VOICEN_SILERO_TEST_MODEL` as `dictation_e2e.rs` already reads; the notifier and an app event listener on the tauri test runtime. Note: `tone_wav()` may not be speech for Silero; the chain test needs a speech-like WAV or must accept energy spans on one leg. Clock reads only via `tests/timing_support`.

**Owner / orchestrator questions.**
- Q1: the toast's Open. (a) Split: T-139 delivers `call::open_transcript(app, root, id)` (the one `calls://open` emitter, tested directly) and the toast keeps no button; the button goes to T-213 or a task after it. (b) Keep it here: `blocked_on: T-213` and the Notifier/codec change joins this task. Recommended (a).
- Q2: credentials. `scripts/ci/credentials.ps1` is the rule for **CI workflow steps**; Rust shell tests (`credentials.rs`, `settings_ipc.rs`) write through the product `CredentialStore` under `cred_support::serial()`. Recommended: the chain test saves the fake key through the `SettingsService`'s own store under `cred_support::serial()`, and the Context line is read as the CI-step rule. The alternative (a `ci.yml` step that plants before `cargo test`) adds a workflow step for one test.
- Q3: `calls://open {root, id}` needs a root, but `CallNotice::TranscriptReady` carries only `call: CallId`, and one `ApiPassRunner` shares one `PassEvents` for all passes. Recommended: the notice carries the folder (or the root) from core, not a guess from current settings, since the root can change between stop and pass end.

**Risks.** T-135 r1#2 (in T-197): the shared `SileroDetector` mutex is held ~1 s per 120 s scan, so a dictation decision may wait during a pass; measure in `call_chain.rs` or scan shorter windows. A pass started while the app exits: `PassQueue` drop joins the running pass; the exit path (T-145) must not block on in-flight HTTP for long.

**Recommended `blocked_on`.** For Q1 (b): `T-213 (toast Open button needs the COM activator; Notifier has no action besides retry)`. For Q1 (a): none; the task can start after the scope change, since every code dependency it then needs is DONE.
