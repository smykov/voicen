This is the only failing test across every `src-tauri/tests` binary in step 10.

The panic happens in the test's own setup: `raw_write`, called from `Planted::add` at `purge_credentials.rs:243`. Windows refused to plant the `CRED_TYPE_DOMAIN_PASSWORD` (type 2) entry, so the purge under test (`from_args`, which deletes each entry with its own type) never ran on a type-2 entry. The `CRED_TYPE_GENERIC` entry at `:242` was planted fine.

**Facts for the investigator.** These are read from `src-tauri/tests/purge_credentials.rs:49-65`; I did not test any of them. `raw_write` builds the type-2 entry exactly like a generic one:
- `UserName = "voicen"`: a bare name, not `DOMAIN\user` or a UPN.
- `CredentialBlob = FAKE_KEY.as_bytes()`: ASCII, 33 bytes. The length is odd, so it is not UTF-16.
- `Persist = CRED_PERSIST_LOCAL_MACHINE`.
- `TargetName = "voicen-test-…/Voicen/domain"`: it contains `/`, but a domain credential's target is a server name.

Each of these could cause `ERROR_INVALID_PARAMETER` on a domain-password write. Check which one against the Win32 `CREDENTIALW` / `CredWriteW` docs before choosing a fix. The test's comment says it models what `cmdkey /add:` writes. The CI step plants only `cmdkey /generic:` entries.
