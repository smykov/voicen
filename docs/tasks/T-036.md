## Context

Three Low findings from T-035 review round 2 (APPROVE), routed here:
1. **False positive:** `scripts/ci/shell-test-layout.awk:286-292` refuses a doc line indented 4+ columns after a blank doc line even when it is a list continuation or a nested list (about 20 of 24 indented-block hits in the registry cache were this). It fails closed, but the message says "doctest". Track list context, or name the case in the author rule of `docs/decisions/ci-toolchain.md`; add a fixture either way.
2. **Fixture gap:** no `ok-` fixture puts `#[test]`, a fence or `"` inside a string, raw string, char literal or block comment, and no fixture covers the "unterminated" reports; deleting those lexer parts keeps all 40 cases green. Add `ok-literals` and two unterminated fixtures.
3. **"Not caught" list incomplete:** tests in `#[path = "../x.rs"]` modules, `include!` files or symlinked `src/*.rs` pass the guard (`find -type f` skips symlinks); `[[bin]]`/`[lib] path` outside `src` likewise. List them in the script header and the area file, or refuse `#[path` / `include!(` and follow symlinks.

## Acceptance

- [ ] A list continuation or nested list in a doc comment is not reported as a doctest (or the rule names it and the message says what to do), pinned by a fixture
- [ ] `ok-literals` and two unterminated fixtures exist and pass; removing the string/comment handling from the lexer turns a fixture red
- [ ] The guard either refuses `#[path`, `include!(` and symlinked sources, or the header and `docs/decisions/ci-toolchain.md` list them as not caught
- [ ] Failure branch: every new violation fixture exits 1; tool errors still exit 3
- [ ] Test that fails without the change: the new fixtures in `scripts/ci/fixtures/shell-test-layout/`
