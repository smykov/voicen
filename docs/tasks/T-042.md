## Context

Split from T-001 by decision #43: the T-001 analysis found the core `RecordingController` (hold mode: press starts, release stops; a recording under 0.3 s is discarded, FR-02) and `IndicatorState` (what the overlay shows: idle / recording / processing / error) unowned once T-001 was narrowed to the pipeline job, and T-006 needs both before it can wire the Windows hotkey, capture and overlay. Pure state machines over a `Clock` (the existing `clock::Clock`, extended with a monotonic instant if needed — no second clock port, P-011), with fakes; capture itself (cpal) is T-006's. Toggle mode and the 10-minute maximum are T-009's; Esc cancel is T-009's.

## Acceptance

- [ ] Press then release after ≥ 0.3 s yields exactly one finished recording; after < 0.3 s it yields none and the indicator returns to idle
- [ ] The indicator state follows recording → processing → idle (or error) for one job, driven only by controller and pipeline events
- [ ] Failure branch: a release without a press, a second press while recording, or a capture error never panics and leaves the controller idle with no job (unit tests)
- [ ] Test that fails without the change: unit tests in `crates/voicen-core/src/recording/`
