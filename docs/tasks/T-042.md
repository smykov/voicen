## Context

Split from T-001 by decision #43: the T-001 analysis found the core `RecordingController` (hold mode: press starts, release stops; a recording under 0.3 s is discarded, FR-02) and `IndicatorState` (what the overlay shows: idle / recording / processing / error) unowned once T-001 was narrowed to the pipeline job, and T-006 needs both before it can wire the Windows hotkey, capture and overlay. Pure state machines over a `Clock` (the existing `clock::Clock`, extended with a monotonic instant if needed — no second clock port, P-011), with fakes; capture itself (cpal) is T-006's. Toggle mode and the 10-minute maximum are T-009's; Esc cancel is T-009's.

## Acceptance

- [ ] Press then release after ≥ 0.3 s yields exactly one finished recording; after < 0.3 s it yields none and the indicator returns to idle
- [ ] The indicator state follows recording → processing → idle (or error) for one job, driven only by controller and pipeline events
- [ ] Failure branch: a release without a press or a capture error never panics and leaves the controller idle with no job; a second press while recording is ignored as hotkey auto-repeat (still one recording; one job after release; data-model.md:53) (unit tests)
- [ ] Test that fails without the change: unit tests in `crates/voicen-core/src/recording/`

## Investigation

**Frame.** This is a feature task. Observed: core has `Clock`, `AudioBuffer`, engine, VAD and `settings::gate::dictation_gate`, but no recording state machine and no indicator state. Expected: pure core state machines that T-006 wires to the hotkey, cpal and the overlay. Proof: unit tests on the Linux gate (no Windows code).

**Recurrence.** Class `transcription-pipeline`. `docs/failures.md` lists F-001/F-002 (`ci-toolchain`) and F-003 (`guard-model`), so this is not a recurrence and `recurrence_of: []` stands. Earlier tasks of this class: none (T-001 and T-040 are features).

**Hypotheses.**
1. *It already exists under another name.* Partly true. The engine=none press check exists: `settings/gate.rs:55-62` `dictation_gate`, "called by the hotkey handler before the microphone is opened". The controller must not repeat it (P-011): T-006 calls `dictation_gate` before `press`. That covers the engine=none line of spec T014. Grep finds no recording or indicator code (Rust is not indexed by Serena; I used grep over `crates`, `src-tauri/src` and `src`).
2. *Time is handled on a second path.* The spec's `Clock { now() -> Instant }` (core-traits.md:121) would be a second clock port. **Decision: the caller passes the `Instant`; `Clock` is not extended.** Reasons:
   - (a) A press or release time belongs to the event. The hotkey thread stamps it when the event arrives. If the controller reads a clock when it processes the event, worker or lock delay gets counted in the 0.3 s hold and in `hotkey_to_first_frame_ms`.
   - (b) The Pipeline API already takes `at: Instant` (core-traits.md:132-133).
   - (c) Adding `instant()` to `Clock` would force `FakeClock` and every `SettingsService` construction (service.rs:32, settings_ipc.rs:55, tests) to deal with a method they never use.
   - (d) Tests use `t0 + Duration::from_millis(n)`: deterministic, and no fake is needed.
   - Durations use `saturating_duration_since`, so a release stamped before its press counts as a 0 s hold and is discarded, with no panic. T-009's 10-minute cap and the 3 s message expiry work the same way: `tick(at)` plus `next_deadline()`, and the shell's timer calls `tick`. T-009's "fake clock" means instants supplied by the test.
3. *The indicator is driven on a second path.* If the shell fed two separate reducers, a forgotten call would let the indicator drift away from the controller. So the controller owns `IndicatorState`. Pipeline outcomes come in only through `job_finished`.
4. *The Acceptance contradicts the design.* Line 3 says "a second press while recording ... leaves the controller idle". The data model (data-model.md:53) says a press while recording is hotkey auto-repeat and is ignored. If it ended the recording, holding the key would abort it. The data model wins. The orchestrator should reword the line to: "a second press while recording is ignored (still one recording; one job after release)". This is not an owner question.

**Settled API (hold mode only).**
- `MIN_HOLD = 300 ms`; a hold of exactly 300 ms is kept.
- `RecordingController<C>`. `C` is opaque context taken at press and returned in the result: T-006 passes `StartWindow`, which is T-001's type, so there is no dependency on it here. Methods take `&mut self`, have no threads, and the shell serialises calls.
  - `press(at, ctx) -> Press::{Start(RecordingId), Ignored}`
  - `capture_failed(id, CaptureError, at) -> Option<FailureReason>`: for the live id the controller goes Idle and returns `MicrophoneUnavailable{cause}`; a stale id returns `None`.
  - `release(at) -> Release::{Stop(StopTicket<C>), Discarded{id, held}, Ignored}`
  - `finish(ticket, Result<AudioBuffer, CaptureError>, at) -> Result<FinishedRecording<C>, FailureReason>`
  - `job_finished(id, JobEnd, at)`, `tray_menu_opened(at)`, `tick(at)`, `indicator()`
- The controller goes Idle as soon as `release` returns. A new press can start while the shell stops the stream (FR-029).
- `StopTicket` cannot be cloned and has a private constructor. `FinishedRecording { id, audio: AudioBuffer, ctx, started_at, stopped_at, end: RecordingEnd::Released }` has private fields. Together they make "at most one finished recording" hold by type.
- `RecordingEnd::{Released, TooShort}` for now; T-009 and T-006 add the other variants.
- `CaptureError` follows the contract (core-traits.md:79). It maps to `MicCause { NoDevice, AccessDenied, Busy, Other }` (messages.md:18-21). The OS text never goes into a `FailureReason`.
- New `FailureReason::MicrophoneUnavailable{cause}`: not retryable. Message ids `failure.microphone_unavailable` and `mic_reason.*` go into both catalogs (#23 N3).
- Events: the controller emits none. T-006/T-001 build `RecordingStarted`/`RecordingEnded` from the returned id, instants and `end` (`hotkey_to_first_frame_ms` comes from capture).

**IndicatorState.**
- Tray priority: `HotkeyError > Recording > Error > Idle`. Overlay priority: `Recording > Message{id, params, until = at + 3 s} > Processing (≥ 1 queued job, keyed by RecordingId) > Hidden`.
- A new recording pre-empts the message, and the message is not shown again.
- Inputs T-001/T-006 feed: `JobEnd::{Delivered{notice: Option<MessageId>}` (Pasted / CopiedOnly; clears tray `Error`), `Notice(MessageId)` (NoSpeech, CopyManual), `Failed(FailureReason)` (message + tray `Error`)`}`.
- A `job_finished` for an unknown id changes nothing; the counter cannot underflow.
- The `Indicator` render port and the IPC mapping of `until` belong to T-006.

**Red tests** (`#[cfg(test)]` in `recording/`; without the change they fail to compile):
- AC1: holds of 300, 301 and 4000 ms each give one `FinishedRecording` with the same audio and `end = Released`, and a second `release` returns `Ignored`. Holds of 0, 1 and 299 ms give `Discarded`, no ticket, tray `Idle`, overlay `Hidden`, no message.
- AC2: press gives Recording/Recording. Release and finish give overlay `Processing`. `job_finished(Delivered)` gives `Hidden`. `Failed(Timeout)` gives `Message` until +3 s and tray `Error`. `tick(+3 s)` gives `Hidden` while `Error` stays until `Delivered` or `tray_menu_opened`. Also the priority tables and the pre-emption case.
- AC3:
  - release without press gives `Ignored`, Idle.
  - a second press gives `Ignored`, the same id, and one ticket after release.
  - `capture_failed` on the live id gives Idle, `MicrophoneUnavailable`, no job, and a later release is `Ignored`.
  - `finish(Err)` gives `Err` and no queued job.
  - a stale id gives `None` and no state change.
  - a release stamped before its press gives `Discarded`.
- Lints in the module: `deny(unwrap_used, expect_used, indexing_slicing)`, as in failure.rs.

**Options.**
- (A, recommended) As above. It removes the cause: there is one owner of recording state and of what the indicator shows, and later inputs extend it. Risk: the generic `C` adds a little to the type signatures. Rollback: delete one module.
- (B) Two separate reducers wired by the shell, laid out as the spec's T012 and T019. Every shell handler must remember both calls, which is a second path for the same concern.
- (C) The controller drives an `AudioSource` port and `Clock::instant()`. That puts callback threads inside core, needs a threaded fake, and widens `Clock`. Rejected.
