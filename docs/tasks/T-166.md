## Investigation

Context gathered with grep and the core image (`scripts/tw-run core`); Serena was loaded but not needed: the seam is a Makefile recipe and the findings came from the tools' own output. All runs on main 2bf6e415, heavy runs under `systemd-run --scope --slice=agent-tests.slice`, `-j2`.

**Frame.** Observed: shell code can carry rustfmt drift and clippy warnings, and `make check` stays green. Expected (decision #201, T-060 P1): the shell is held to the same bar as core and whisper (`check-core`, `check-whisper`: `cargo fmt --check` and `clippy --all-targets -- -D warnings`).

**Hypotheses.**
1. The gate never runs fmt or all-lints clippy on `voicen` — confirmed: the `check-shell-windows` recipe has no fmt and no `-D warnings`; its T-201 comment says the other lints stay warnings and T-166 owns them.
2. A second path (Windows job) lints the shell — refuted: no `clippy` or `fmt` in `.github/workflows/ci.yml`.
3. Fixed before — partly: T-201 added clippy for `disallowed_methods` only; T-056 option B (lint both invocations, add fmt) was left as an open follow-up in `docs/decisions/ci-toolchain.md`. Three review sightings (T-055, T-071, T-009, plus T-058 for the comment) are one gap (T-060 Investigation §7), not an rca class.

**Measured today.**
- `cargo fmt --check -p voicen`: exit 1, diffs only in `src-tauri/tests/single_instance.rs` (two hunks, the `on_second_instance(...)` calls of the `--call` tests). `src-tauri/src/lib.rs` and `tests/diag.rs` from the T-009 note are clean now.
- `clippy --all-targets -- -D warnings`: exit 101 on the lib, which stops the test crates. Without `-D warnings`, the 4 warnings are:
  - `src-tauri/src/settings_window.rs` `request_with`: `type_complexity` on `Box<dyn FnOnce(&AppHandle<R>) -> tauri::Result<()> + Send>`.
  - `src-tauri/src/tray.rs` (menu-open handler): `let_underscore_future` on `let _ = tauri::async_runtime::spawn_blocking(...)`. `drop(...)` does the same thing. tauri 2.12.1's `JoinHandle::Tokio` wraps tokio 1.53.1's `JoinHandle`, which "*detaches* the associated task when it is dropped" (`tokio/src/runtime/task/join.rs`, registry source). Behaviour is unchanged.
  - `src-tauri/tests/runner_probe.rs` `is_printed`: `manual_contains`.
  - `src-tauri/tests/win32_support/mod.rs` `read_clipboard`: `chunks_exact(2)` → `as_chunks::<2>().0` (stable since 1.88; the toolchain is 1.99). The remainder is dropped either way.
- The release feature set (`cargo clippy -p voicen --target x86_64-pc-windows-gnu`) shows the same 2 lib warnings and nothing else.
- Fix these in code, not with `#[allow(clippy::...)]`. Any line holding `clippy` must be an owned entry of `scripts/ci/clippy-lines.txt`, and an allow would lower the bar the task adds.

**Root cause.** The gate's one shell compile step was scoped to a type check, plus one denied lint (T-201). Nothing else in the gate or in CI runs rustfmt or the rest of clippy on `src-tauri`.

**Invariant / seam / approach.** See the `analysis` block. Things to keep when editing:
- The recipe stays one `scripts/tw-run core` call with `DOCS_RS=1` scoped to each cargo invocation (T-102).
- `check-shell-windows` stays after `check-core` in `check:`.
- The recipe line and its `clippy-lines.txt` entry change in the same commit. Otherwise `check-clippy-lines` goes red: an unowned line and a stale entry.
- `check-ban-canary` runs its own clippy without `-D warnings` and is unaffected. Its row in `ci-toolchain.md` says "like the gate line without `-- -D warnings`"; reword it when the gate line gains it.
- Rewrap the whole `check-shell-windows` comment block to about 90 characters. Today it has 126- and 109-char lines; the 126-char one is T-058 r2#2.
- Option A costs about the same as today: clippy replaces `cargo check` on the same artifacts, and `--all-targets` adds only the bin's dev-set check. Record the measured wall time in `ci-toolchain.md` › Cost on GitHub if it moves.

**Owner decision.** None needed. Decision #201 approved this seam and scope. Option A (clippy also replaces `cargo check` in the first invocation) stays inside the "T-056 option B" follow-up text already in `ci-toolchain.md`. Option B is the literal Acceptance wording, if the orchestrator prefers it.

**Acceptance line numbers** for T-071 r1#4 are stale. Tick that line against the 4 current sites above, not against settings_window.rs:257, tray.rs:248/458 or lib.rs:172 (those no longer warn).
