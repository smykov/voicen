## Acceptance

- [ ] A `Segments` request sends `response_format=verbose_json` and `timestamp_granularities[]=segment`; an OK reply parses its segments (T042, T043)
- [ ] Failure branch: a 400 or 422 to `Segments`, or a 2xx without `segments`, is time-less; a 400 on `Plain` is `provider` (T042)
- [ ] Failure branch: 401 and 403 map to `key` and never fall back; a connect error maps to `network`; a late answer under the FR-24 timeouts maps to `timeout`; 429, other 4xx/5xx and a malformed body map to `provider` (T042)

## Investigation

**Frame.** Feature (US2, G22 T042/T043). Expected: one engine call that asks for segment times, tells "time-less" apart from failure, and maps the language. Today `OpenAiCompatibleEngine::multipart_body` always sends `response_format=json`, and `send` reads only `text`. Tools: Serena `get_symbols_overview` on `engine/openai.rs`, then grep and reads of `engine/http.rs`, `failure.rs`, `call/events.rs`, `call/transcript.rs`, `settings/mod.rs` and `tests/openai_client.rs`. Context7 `/websites/developers_openai_api_reference` for the verbose_json shape. The whisper name list comes from the `g_lang` table of whisper-rs-sys 0.15.0 in the core cargo cache (`.teamwright/cache/core/.../whisper-rs-sys-0.15.0/whisper.cpp/src/whisper.cpp`).

**Hypotheses checked.**
1. *Time-less can be decided by the caller from `FailureReason::ServerError{400|422}`* (contract signature as written). This works, but it puts the FR-024 rule in T-138's runner, and T-136's Acceptance must test it here. Rejected in favour of `TimedFailure`.
2. *A second path handles the same concern.* `post_process::chat` is the other user of `engine::http`. It neither transcribes nor parses segments, so there is no second transcription path. `transcribe` (dictation) keeps the json path. It is refactored only to share the capped send.
3. *Bans need new guards.* `Response::json()` cannot compile, because reqwest has no `json` feature in `crates/voicen-core/Cargo.toml`. `bearer_auth` is banned by review (`docs/decisions/post-processing.md`). The key goes only through `http::authorization`. A clippy entry would be a guard change. Not needed.
4. *Language table already exists.* It does not: only codes exist (`WHISPER_ISO_639_1`). The names come from `g_lang`, where the 97 codes match after dropping haw/jw/yue. A test binds the code column to `WHISPER_ISO_639_1` so the two lists cannot drift (#196(4)).
5. *Where the tests go.* T042 names `openai.rs`, but `docs/decisions/core-tests.md` forbids OS-answer targets and clock reads outside `tests/common`. So the wiremock legs (timeout, refused connect) go to `tests/openai_client.rs`. The pure tests (table, mapping, body size) go to `openai.rs` `mod tests`.

**Mapping (closed).** One function in `engine::openai` decides:
- `TransportError::Status(400|422)` with `Segments` → `Timeless`;
- otherwise `failure::classify`, then:
  - `InvalidApiKey` → `Key` (so 401/403 never fall back);
  - `NetworkUnavailable`, `CannotReach` → `Network`;
  - `Timeout` → `Timeout`;
  - `ServerError` (429 and 400 on `Plain` included), `UnexpectedResponse` (malformed body, over 1 MiB) → `Provider`;
  - `EngineNotConfigured` → `EngineNotSetUp`.

**Not touched by this task** (kept out of `analysis.seam`, which lists only changed paths):
- `engine/http.rs` and `failure.rs`;
- `call/final_pass.rs`: that is T-137; T-138 later calls `transcribe_timed`;
- `call/storage.rs` and `call/mod.rs` (T-125);
- `call/events.rs` and `call/transcript.rs`: their types are reused as is;
- `settings/mod.rs`: `LangCode` is reused;
- the `Engine` trait;
- `scripts/**` and `Makefile`: no guard change, and disjoint from T-199.

**Recommended:** option B in `analysis.approach`. No open question: the choices in `decides_on` stay within FR-024/FR-025 and R10.
