### Points the orchestrator asked about

- **Loopback rule vs the spec's closed list.** `Domain == "localhost"`, `Ipv4::is_loopback()` (127.0.0.0/8) and `Ipv6 == ::1` match FR-020 / FR-29 v4 and decision #52 exactly. The table covers both directions of every edge case in Investigation 3: shorthand IPv4 `0x7f.1` and `2130706433`, `[0:0:0:0:0:0:0:1]`, `[::ffff:127.0.0.1]`, `0.0.0.0`, `[::]`, `localhost.`, `foo.localhost`, `127.0.0.1.nip.io`, upper-case scheme and host, and https never. By reading, the table would turn red under each of these mutations:
  - `scheme == "http"` alone;
  - a text prefix or contains test;
  - `== 127.0.0.1` instead of `is_loopback`;
  - `to_ipv4()` or `is_unspecified` counted as loopback;
  - https treated like http.

  The `let Ok(..) else { return false }` cannot be reached, because a `NormalizedUrl` is only built by `check_base_url` over the same text. The comment says so.
- **`save_warnings` covers exactly the URLs in use and never unwraps.** In use means the engine's own field (`Api` / `LocalServer`; `None` and `BuiltinLocal` have no URL) plus `post_processing.base_url` only while it is enabled. `check_base_url(..).is_ok_and(..)` has no unwrap, and `save_gives_no_warning_for_an_unchecked_post_processing_url` panics on any unwrap. The function runs over the normalized `settings` after the file write. Every `Refused` return comes earlier, and `refused_save_carries_no_warning_and_writes_nothing` pins that.
