# ADR-002. Захват: микрофон и системный звук двумя раздельными дорожками

Дата: 21.10.2026 · Релиз: режим созвона 1 · Статус: **принято владельцем** — запись динамиков и микрофона; **предложено** — способ

## Контекст
Нужно записывать созвон в любом приложении без бота. На Windows системный звук устройства вывода снимается через WASAPI loopback (крейт `wasapi` или `windows`). Микрофон Voicen уже захватывает (`cpal`).

## Решение
1. Две дорожки:
   - **mic** — выбранный микрофон, после подавления эха (ADR-008);
   - **system** — loopback устройства вывода по умолчанию.
   
   Дорожки не смешиваются: раздельность даёт разметку «Я / собеседники» без диаризации (ADR-003).
2. Обе дорожки — моно 16 кГц, переводятся в формат ядра (ресемплер в ядре есть). Временные метки — от одного монотонного источника времени (QPC), у каждого буфера — время захвата. Расхождение — не больше 100 мс за час (ВФ-11).
   **Дрейф часов.** Микрофон и устройство вывода — разные устройства с разными тактовыми генераторами: ±50 ppm ≈ 180 мс за час. Поэтому одна дорожка подстраивается под другую адаптивным ресемплингом по меткам времени, иначе ВФ-11 и подавление эха (ADR-008) не выполнить.
3. При смене устройства вывода по умолчанию loopback переподключается к новому устройству. Пропуск заполняется тишиной, чтобы не сдвигать время; событие пишется в `meta.json` и лог.
4. Источник звука — трейт ядра (`AudioSource` или аналог в коде). Реализация loopback живёт в оболочке Windows, в тестах её подменяет WAV.

## Альтернативы
- **Виртуальный аудиокабель (VB-Cable)** — нужна установка драйвера, плохой опыт пользователя.
- **Бот в Zoom/Meet/Teams** — работает только на платформах с API, собеседники видят бота. Против идеи «без бота».
- **Одна смешанная дорожка** — теряется даровая разметка, эхо не подавить.

## Последствия
- Звук приложения, которое выводит не на устройство по умолчанию, не попадёт в запись (риск в ТЗ). В релизе 1 нужен индикатор уровня обеих дорожек.
- Перед проектированием нужен короткий прототип:
  - стабильность loopback при смене устройств;
  - Bluetooth-гарнитура: при включении её микрофона Windows переключает вывод в режим HFP (другое устройство «Headset»), смена устройства становится частой;
  - величина реального дрейфа на ПК владельца.
- У раннера GitHub `windows-latest` нет звуковых устройств: реальный захват проверяет только владелец (ВН-10).
