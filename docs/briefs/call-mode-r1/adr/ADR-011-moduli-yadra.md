# ADR-011. Модули ядра: границы под будущую платформу

Дата: 21.10.2026 · Релиз: режим созвона 1 · Статус: **предложено**

## Контекст
Владелец — сторонник распределённой системы и подхода «целое ядро + нишевые продукты» (исследование рынка и подходов владельца (вне репозитория)). В релизе 1 всё работает локально в одном процессе. Границы при этом должны позволять потом вынести части в сервисы и собрать другие продукты на том же ядре.

## Решение
В `voicen-core` выделяются модули с интерфейсами — ограниченные контексты:

| Модуль | Ответственность | Интерфейс |
|---|---|---|
| capture | источники звука и синхронизация дорожек | `AudioSource` (mic, loopback, файл) |
| segmentation | VAD, фразы | использует существующий VAD |
| recognition | пакетное и квазипотоковое распознавание, язык | существующий трейт движков + время фраз |
| speakers | диаризация, разметка по дорожкам | `Diarizer` |
| call session | состояние режима созвона, переключатели, события для UI | события и команды IPC |
| call storage | папки, куски, сборка, восстановление, схема JSON | `CallStore` |
| transcript | слияние, фильтр дублей, экспорт MD и JSON | чистые функции |

Модули общаются через типизированные события. Платформенное — только в оболочке.

## Последствия
- Любой модуль тестируется на Linux с подменами (ВН-10).
- Будущий сервис распознавания или диаризации — ещё одна реализация трейта, цепочка не меняется (ВН-08).
