Версия 4 от 21.10.2026:
- v2 — ответы владельца на ВВ-1…ВВ-6;
- v3 — исправления после прожарки (`prozharka-1.md`);
- v4 — ответы владельца на П-1…П-6: приняты все предложения.

**Готово к передаче агенту.** Концепт — `kontseptsiya.md`, решения — `adr/`.

**Пометки:**
- **(В)** — решение владельца;
- **(П)** — проектное предложение: агент уточняет его в своей прожарке и спецификации, решения владельца (В) не меняет;
- **(Р)** — рабочее допущение, проверяется в спецификации и проектировании.

Требования записаны в форме EARS («Когда…, система должна…»). Агент переводит их в формат `docs/requirements.md` и сохраняет связь с номерами ВФ и ВН.

## 1. Цель и критерии успеха релиза

**Цель.** На Windows-ПК владельца созвон в любом приложении:
- записывается двумя дорожками (свой микрофон и звук собеседников);
- по желанию сопровождается живыми субтитрами;
- после остановки превращается в транскрипт с говорящими, готовый для чтения и для агентов.

**Критерии успеха — все обязательны:**
1. **Реальное использование.** Владелец записал не меньше 5 реальных созвонов по 30–90 минут: рабочие и собеседования, в Telegram Desktop, Google Meet в браузере и Zoom или Teams. Ни один не потерян и не испорчен. Проверка — по разделу «Созвоны» и логу.
2. **Говорящие:**
   - роль «Я / собеседник» верна не меньше чем для 95% времени речи. Проверка — на тестовом наборе и на 2 реальных созвонах по 10 минут, размеченных владельцем вручную (П-6);
   - при 2–3 удалённых собеседниках DER на дорожке динамиков ≤ 20% на открытом корпусе реальных записей (разд. 8) (Р).
3. **Субтитры.** Задержка от конца фразы до её появления в окне — p90 ≤ 4 с через API-движок и ≤ 6 с через встроенный `small` на ПК владельца (Р, уточняется замером).
4. **Итоговый транскрипт.** Для часового созвона готов ≤ 5 мин через API и ≤ 30 мин локально (`small`, ПК владельца) (Р).
5. **Надёжность.** 2 недели ежедневного использования без падений. Сбой движка не роняет приложение и не теряет запись.

## 2. Функциональные требования

### 2.1 Режим созвона и управление

| ID | Требование | Приёмка (пример и отказ) | Приоритет |
|---|---|---|---|
| ВФ-01 | Система должна иметь режим созвона с двумя независимыми переключателями «Запись» и «Субтитры»; режим активен, если включён хотя бы один (В) | Включены оба → идёт запись и видны субтитры. Выключены оба → режим неактивен, микрофон и системный звук закрыты | Must |
| ВФ-02 | Когда пользователь меняет переключатель во время активного режима, система должна применить изменение без остановки другого переключателя | Запись идёт 10 мин, включили «Субтитры» → появилось окно, запись непрерывна (в файле нет разрыва). Выключили «Субтитры» → окно закрыто, запись продолжается | Must |
| ВФ-03 | Система должна давать управлять режимом из меню трея: «Созвон» с двумя галочками и «Остановить» (П) | Из трея включили «Запись» → индикатор записи появился за ≤ 1 с | Must |
| ВФ-04 | Когда пользователь нажимает горячую клавишу режима созвона, система должна включить режим с последним использованным сочетанием переключателей (при первом использовании — «Запись + Субтитры»), а при повторном нажатии — остановить режим (П) | Нажали → режим «Запись + Субтитры». Нажали снова → остановлен. Отказ: клавиша занята другой программой → уведомление с причиной, как для клавиши диктовки | Must |
| ВФ-05 | Пока идёт запись, система должна показывать индикатор записи с таймером поверх окон и состояние записи в трее | Индикатор «● Запись 00:12» виден над браузером в полноэкранном режиме. Индикатор можно переместить, позиция запоминается | Must |
| ВФ-06 | Когда начинается запись, система должна показать в индикаторе напоминание предупредить собеседника о записи и подсказку «лучше в наушниках»; напоминание можно отключить в настройках (ADR-010) | Каждый старт записи → напоминание видно 10 с. После отключения в настройках не показывается | Must |
| ВФ-07 | Пока режим созвона активен, диктовка должна работать как обычно; её речь попадает в дорожку микрофона и в транскрипт как «Я» (В, ВВ-4) | Во время записи продиктовали фразу в чат → текст вставлен, в транскрипте созвона эта фраза есть как «Я» | Must |

| ВФ-08 | Когда пользователь включает режим созвона, пока он уже активен, система не должна запускать второй сеанс: применяются переключатели к текущему | Второе нажатие трея «Запись» при идущей записи → один сеанс | Must |
| ВФ-09 | Когда пользователь выходит из приложения или запускается обновление во время записи, система должна запросить подтверждение и корректно остановить запись с сохранением | Выход во время записи → вопрос → «Да» → созвон сохранён и расшифруется при следующем запуске | Must |

## 7. Ограничения

- Только Windows 10/11 x64, разработка на Linux-хосте, проверка Windows-поведения в CI и на ПК владельца — как у всего Voicen.
- Без своего облачного бэкенда: ключи API пользователя или локальные движки (принцип Voicen). Свой сервис на своём сервере подключается как OpenAI-совместимый локальный или сетевой сервер (ВВ-2).
- Записи реальных созвонов **не кладутся в git**: биометрия и конфиденциальность. Тестовый набор — открытые корпуса и синтетика (разд. 8).
- У Windows-раннера CI нет звуковых устройств: реальный захват проверяет только владелец (ВН-10).

## 8. Тестовые данные

1. **Открытые корпуса реальных записей для DER и WER** (П-4). AMI Meeting Corpus и VoxConverse — CC BY 4.0 ⚠ проверить лицензию. Русский — найти открытый многоголосый набор ⚠. Хранятся вне git, подтягиваются в CI по контрольным суммам.
2. **Синтетические диалоги — для эха и синхронизации.** 10–15 диалогов по 2–10 минут, 2–4 стоковых синтетических голоса — **не клоны реальных людей**, русский и английский, со сменой языка и перебиваниями. Эталонная разметка «кто, когда, что». Пара WAV «микрофон» / «системный звук», вариант «без наушников» с подмешанным эхом, вариант с искусственным дрейфом часов.
3. **Ручной набор владельца.** Реальные созвоны, только локально. 2 созвона по 10 минут владелец размечает вручную (П-6) — для критерия 2 и чек-листа ВН-07.

## 9. Риски

| Риск | Влияние | Что делаем |
|---|---|---|
| Эхо без наушников: голос собеседника попадает в микрофон | Дубли реплик, неверное «Я» | Подавление эха (ADR-008) + фильтр дублей + рекомендация наушников в напоминании |
| Приложение созвона выводит звук не на устройство по умолчанию | Нет звука собеседника | Индикатор уровня обеих дорожек в окне записи; выбор устройства вывода в настройках (Could) |
| Одновременная речь и много собеседников | DER выше цели | Цель задана для 2–3 собеседников; узнавание по голосу — следующий релиз |
| Задержка субтитров через API при плохой сети | Субтитры отстают | Встроенный движок как альтернатива; пометки ошибок (ВФ-35) |
| Стоимость API: две дорожки × час | Расходы пользователя | Распознаются только VAD-сегменты с речью; оценка стоимости в настройках (Could) |
| Качество локальной диаризации на реальных голосах; порог кластеризации калибруют на синтетике | Ошибки разметки | Порог — в настройках для отладки; калибровка на ручном наборе владельца |
| Законы о записи разговоров (согласие собеседника) | Юридический риск пользователя | Напоминание (ВФ-06), ответственность пользователя в документации; функция «запись втайне» не делается |
| Окно субтитров: «без активации» и перетаскивание одновременно | Окно крадёт фокус или не двигается | Спайк первым; запасной вариант — окно поверх всех с возвратом фокуса |
| Дрейф часов микрофона и устройства вывода (±50 ppm ≈ 180 мс/ч) | Расхождение реплик, плохое подавление эха | Компенсация по меткам времени (ADR-002, ВФ-11) |
| Bluetooth-гарнитура переключается в режим HFP при включении микрофона, меняется устройство вывода | Частые смены устройства, пропуски | ВФ-12, индикатор уровня ВФ-16, проверка в матрице ВН-07 |
| Облачная диаризация длинных созвонов: метки говорящих в разных кусках не совпадают | Перепутаны собеседники | ADR-004: до спайка облачная диаризация только для дорожки в один кусок (П-5) |
| Встроенный движок (T-017) не готов | «Локально по умолчанию» откладывает весь релиз | Поставка по частям (П-1) |
| В CI нет звуковых устройств | Захват не проверяется автоматически | Подменные источники + ручная проверка владельца (ВН-10) |
