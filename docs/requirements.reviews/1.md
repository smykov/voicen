### Requirements roast round 1 — 2026-10-02

The draft is solid: the release-1 flow is defined end to end, every Must has acceptance, and most Musts have a failing example. There are no Blockers. Four High findings stop it being READY: an unmeasurable headline NFR, a silence requirement that the stated mechanism cannot meet, a reliability criterion that cannot be checked because there are no logs, and an undefined first run. Questions are written so the owner can answer in one line, with the recommended answer first.

## Scope against time

This cannot be judged yet. OQ-01 (date) is open and the team is not stated (#26). Release 1 is large for a small team: three engine modes, LLM post-processing, two UI languages, history, an installer, and Windows-only behaviour that cannot run on the dev host. If the date is tight, cut in this order: FR-16 (history), FR-14 (test connection), FR-19 (autostart), NFR-10, then FR-15's Russian UI (English only). FR-17 is cheap because it reuses FR-06's client, so keep it. FR-09 is a Must the owner asked for explicitly, so do not cut it without asking.

## Pre-mortem

1. Garbage text gets pasted into chats: hallucinated phrases on silence or short noise, or Ctrl+Alt+V instead of a paste. The owner stops trusting the app. Prevention is missing: #2 (VAD before sending) and #17 (wait for modifier release).
2. After sleep/resume, a headset reconnect or a microphone change, the hotkey or recording silently stops working, and there is no log to tell why. The 2-week criterion fails and nobody can diagnose it. Prevention is missing: #3 (log and crash file), #9 (survive sleep and lock), #10 (microphone fallback).
3. The unsigned installer with a keyboard hook and input simulation is blocked by SmartScreen or antivirus on a clean Windows 11, so success criterion 3 fails at release. It is partly covered by OQ-02 and the risk row in §10. Using RegisterHotKey (not a global low-level hook) wherever possible lowers antivirus heuristics; that belongs to the decision under #9.
